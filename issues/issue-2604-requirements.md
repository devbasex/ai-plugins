# #2604: 開発ループの選定が、前提の課題の実装が develop に無い課題を選び、実装のステップで失敗する

正は課題の本文（#2604）で、この文書はその写しである。`spec-copy.py write` で作り直す。手で直さない。

**解釈**: 開発ループの選定（`loop select`）が、まだ閉じていない別の課題を前提にする課題を選ばないようにする。前提の関係は、棚卸しが見積もりの記録に書いた依存（`depends_on`）と、マイルストーンの説明の並列の組の依存から取る。今の順位の算出（`upkeep.py rank`）はこの依存を並び順にだけ使い、選定は見ていない。

## 目的

- 開発ループが、前提の課題の実装がまだ届いていない課題を実装の周回に選ばず、実装のステップで失敗しないようにする
- 前提の関係で外した課題を、人が手で除外（`loop exclude`）しなくても済むようにする

## 前提

- 前提 1: 前提の関係の正本は、順位の算出が合成する依存の辺（見積もりの記録の `depends_on` と、マイルストーンの説明の `### 並列の組（見込み）` の依存）である。順位の算出は open の課題どうしの辺だけを残す（`upkeep_rank.py` の `merge_edges`）ため、前提の課題が閉じると辺は消える
- 前提 2: 前提の課題が閉じたかは、選定のたびに打つ順位の算出の時点の GitHub の状態で決める。閉じたのが前の選定の後なら、次の選定で選べるようになる
- 前提 3: #2344 の見積もりの記録（2026-11-05 の `/tmp/ndf/backlog-refinement/devbasex--ai-plugins/estimates.json`）は `depends_on` が空である。本文の前提 2 が書く #2339・#2341・#2342 は、次の棚卸しで記録へ書き足す。この変更は記録を書き換えない
- 前提 4: サブイシューの辺（子は親に依存する）は、選定から外す理由にしない。親が子の完了を待って閉じる使い方では、子を外すと親も子も選べなくなる。サブイシューの辺は今と同じく並び順にだけ効く

## 対象範囲

含む:
- 開発ループの選定が、閉じていない前提の課題を持つ課題を外し、理由を選定の行に残すこと
- 外した課題が、選定の件数の枠（`max_issues`）を使わないこと
- 順位の算出の出力が、選定の判定に要る前提の関係を選定へ渡すこと

含まない:
- 課題の本文の文章から依存の番号をスクリプトで拾うこと（棚卸しの手順 2A の担当のまま）
- #2344 の見積もりの記録の書き足し（次の棚卸しで行う。前提 3）
- 前提の課題が develop にマージ済みで、まだ閉じていない場合に前提を満たしたと見なすこと（S1）
- 選定以外の工程（順位の並び・切り出しの境界・品質の枠・大きい課題の枠）の判定を変えること

## 用語

| 用語 | 意味 |
| --- | --- |
| 前提の課題 | ある課題が依存する、別の課題。順位の算出が合成した依存の辺の先にある open の課題 |
| 選定 | 開発ループの周回で、実装する課題を選ぶ処理（`loop select`・`loop exclude` が打つ） |

## 受け入れ条件

- [ ] 1. 前提: マイルストーンの順位の 1 位の課題 A の見積もりの記録に `depends_on: [B]` があり、B が open
      操作: `loop select` を打つ
      結果: A は選ばれず（`decision` が落選）、選定の行の理由が `前提の課題の実装待ち（#B）` になる
- [ ] 2. 前提の課題が複数で open のものが 2 件あるとき、理由に open の 2 件の番号がすべて載る
- [ ] 3. 前提: 条件 1 の B が閉じている
      操作: `loop select` を打つ
      結果: A は前提を理由に外れず、順位どおりに選ばれる
- [ ] 4. マイルストーンの説明の並列の組の依存で B に依存する A も、条件 1 と同じ理由で外れる
- [ ] 5. 前提の課題が別のマイルストーン（選定の対象外のマイルストーンを含む）にあっても、条件 1 と同じ理由で外れる
- [ ] 6. 境界が無いマイルストーンで、前提で外れた課題は `max_issues` の枠を使わず、その後ろの課題が候補に上がって選ばれる
- [ ] 7. 先頭に選ぶ課題（直して出し直す・承認とマージが済んだ設計）でも、閉じていない前提の課題があれば外れる
- [ ] 8. サブイシューの辺だけで親に依存する子の課題は、前提を理由に外れない（退行しない。前提 4）
- [ ] 9. 依存の記録が無い課題の選定の結果（選ぶ課題・落選の理由・順序）は今と同じである（退行しない）
- [ ] 10. 候補がすべて前提で外れたとき、選定は今と同じく `outside_mvv` で止まり、`values.reasons` に `前提の課題の実装待ち（#B）` の件数が載る
