> ## 何が起きているか
>

> ## 求めること
>
> **エージェントの呼び出しはすべて、経路を問わず数える。帳簿はランタイムごとに分ける。** codex・kiro-cli・agy はそれぞれ別のアカウントで、料金体系も違う。1 つの帳簿に混ぜると、合計しても意味のある値にならない。
>
> | 帳簿 | 入るもの |
> | --- | --- |
> | Claude | サブエージェントと `claude -p`（同じアカウント・同じ料金体系なので 1 つにまとめる） |
> | codex | codex の呼び出し |
> | kiro | kiro-cli の呼び出し |
> | agy | agy の呼び出し |
>
> 起動するのが conductor・supervise.py・cross-review・cross-refactoring・external-ai・relay・mvv-gate のどれであっても、同じランタイムなら同じ帳簿へ入れる。**トークン削減の効果を測る主な値は Claude の帳簿の全体（サブエージェント＋`claude -p`）である。**
>

## 目的

- NDF が起動するエージェントの呼び出しを、起動の経路を問わずランタイムごとの帳簿で数え、トークン削減の施策が「処理を計測の外へ移しただけ」なのか「総量を減らした」のかを見分けられるようにする（#845 で、サブエージェント内は −86% でも `claude -p` を足すと総量が変わらなかった状態を、集計の値から読めるようにする）

## 前提

- 前提 1: 数えるのは **NDF のコードが起動した呼び出し**（Agent で起動したサブエージェント、NDF のスクリプトが起動した `claude -p`・codex・kiro-cli・agy、Jev の要求）である。利用者が自分で開いた会話（conductor の会話そのもの）は帳簿へ入れない。課題の「Claude の帳簿 = サブエージェント＋`claude -p`」の定義に合わせる
- 前提 2: 帳簿の置き場所は、既存の帳簿のディレクトリの決め方（`usage_ledger.ledger_dir`、#1142）を引き継ぐ。新しい置き場所を利用者の環境に作らない（C6 の範囲を広げない）
- 前提 3: Jev（AI Gateway）は **独自の帳簿 `jev` を持つ**。`AI_GATEWAY_API_KEY` の別アカウント・別料金で、呼び出し元の帳簿（Claude など）へ入れると「帳簿の間で単位を足し合わせない」に反するためである。承認ゲート 1 で利用者が確かめる
- 前提 4: 帳簿ができる前の期間（#827 の期間など）の値は、手元に残る会話の記録（`~/.claude/projects/` のサブエージェントと `entrypoint=sdk-cli` の会話）から集計の時に読む。帳簿の行と会話の記録が同じ呼び出しを指すときは 1 回として数える。会話の記録も帳簿の行も無い呼び出し（会話を残さない最小構成の `claude -p` の 10-03 より前の分など）は推定で埋めず、「数えられない」と集計に出す
- 前提 5: CLI ごとに返す使用量は違う。codex はトークン数、kiro はクレジット、agy は返すものを設計で実測して決める。返さない量は 0 ではなく `unknown` として残す
- 前提 6: 監査の表の「推定」とある原因（`link_external` の結び付け先・会話を残さない呼び出しの量）は、設計で再現して確かめる。確かめた結果が推定と違えば、受け入れ条件ではなく原因の記述を直す
- 前提 7: 起動の検査（受け入れ条件 10）の対象は `plugins/ndf/` の `scripts/`・`skills/`・`hooks/` のコードである。リポジトリ固有の `scripts/`（`token-usage.py` など）と、LLM を呼ばない CLI の起動（`claude plugin ...`・`claude auth login`・`codex plugin ...`・版の確認）は対象から外し、外す一覧は検査の側に明示する
- 前提 8: 集計のコマンドは NDF の配布物に置き、ai-plugins の形（リポジトリ名・`docs/metrics/` など）を既定に埋め込まない（Value 5）。閉じた課題の数は GitHub Issues から数え、課題の置き場が GitHub でないプロジェクトでは `unknown` と出す

- ランタイムごとの帳簿（Claude・codex・kiro・agy・jev）と、帳簿の行の形

| 用語 | 意味 |

| 使用量の帳簿 | 呼び出し 1 回につき 1 行を追記する jsonl。ランタイムごとに 1 つ（Claude・codex・kiro・agy・jev）。既存の `usage_ledger.py`（#1142）を広げたもの |

## 受け入れ条件

帳簿と行の形:

- [ ] 1. NDF が起動した `claude -p` 1 回につき、Claude の帳簿に 1 行が残る。呼び出し元が supervise.py・mvv-gate・`mvv_llm`・relay・cross-review・cross-refactoring・external-ai・参加者の確認（`lib/auth.py`）のどれでも同じ帳簿に入る
- [ ] 2. Agent で起動したサブエージェント 1 回につき、Claude の帳簿の集計に 1 件が入り、呼び出し元とエージェントの種類が分かる

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 運用・保守性 | 帳簿は追記だけで、既存の行を書き換えない（#1142 の I8 を引き継ぐ）。集計は帳簿と会話の記録を読むだけで、どこへも送らない |
| 移行性 | 既存の帳簿の行はそのまま読める（受け入れ条件 7）。移す手順を利用者に求めない |
| セキュリティ | 帳簿の行にプロンプト・秘密を書かない（受け入れ条件 20、C1） |
| 性能・拡張性 | 記録のために LLM の呼び出しもネットワークの通信も足さない（帳簿への 1 行の追記だけ） |

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 帳簿の行に列（ランタイムなど）が増え、帳簿のファイルがランタイムごとに分かれる。既存の行は Claude の行として読む（互換あり）。`scripts/token-usage.py --usage-root` と supervise の報告が読む形は設計で合わせる |
| データ | 利用者の手元の帳簿のディレクトリに、ランタイムごとの帳簿が増える。既存のファイルは書き換えない |
| 既存の振る舞い | 起動の共有処理・supervise.py・mvv-gate・relay・Jev・参加者の確認が帳簿へ書く。supervise の報告の「LLM の使用量」の内訳が増える |

## 検証手段

| 項目 | 手段 |

| テスト | `uv run --frozen --project . --all-extras pytest . -q -n 4` |

## 前提とする取り決め

| 項目 | 参照先 / 決めたこと |
| --- | --- |
| プロジェクト構造 | `AGENTS.md`。帳簿と集計は `plugins/ndf/scripts/lib/` に置き、Skill ごとに同じ役割の関数を分けない（Value 6、cross 系の共通ロジックは 1 つ）。実験版から既定の処理を参照しない |
| コーディング規約 | `plugins/ndf/scripts/lib/README.md` と `usage_ledger.py` の I1（ライブラリは標準ライブラリとライブラリだけを import）。`.md` の文言を照合するテストを書かない |
| テスト戦略 | 単体: 行の形・`unknown`・追記の失敗。結合: 各呼び出し元から偽の CLI を起動して帳簿に 1 行（`NDF_USAGE_DIR` を一時ディレクトリへ）。静的: 起動の共有処理を通らない起動の検出。外部 CLI の実物は呼ばない |

## 境界

| 区分 | 内容 |
| --- | --- |
| 常に行う | テストは `NDF_USAGE_DIR` を一時ディレクトリへ向ける。記録の失敗で呼び出しを落とさない。帳簿は追記だけにする |
| 確認してから行う | 帳簿の行の形・置き場所の変更（承認ゲート 1 の設計で人が見る）。Jev の帳簿の扱い（前提 3） |
| 行わない | 本物の帳簿の既存の行・ファイルの削除と書き換え。帳簿をまたぐ費用の合計。帳簿の内容の外部への送信 |
