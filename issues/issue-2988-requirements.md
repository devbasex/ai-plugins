## 目的

- **今どうなっているか**: スクリプトの import を集計すると（PR #3002 の `docs/scripts-map/README.md` の図 3、2026-11-10 の `develop` bb77113e1）、実行時に輪になる import が 1 組、import を関数の中へ逃がして避けている輪が 10 組ある。後者の 1 つは、111 ファイルが使う一番下の層 `lib/step_result.py` を含む
  - `step_result.py` は最上位で `deps.py` を読む。理由は終了コードの定数 `EXIT_DEPS_MISSING` を `deps.EXIT_DEPS_MISSING` から写すためだけである（`plugins/ndf/scripts/lib/step_result.py:34`・`:69`）
  - `deps.py` は依存の欠けで止まるとき、関数の中で `run_core` を読む（`plugins/ndf/scripts/lib/deps.py:80-90`。コメントに「run_core → step_result → deps の循環を避ける」とある）
  - `run_core.py` は最上位で `step_result` を読む
  - cross-refactoring の `refactor_lib` では `gitfacts → publish → plan → ledger → gitfacts` と `publish → ledger → gitfacts → publish` が実行時の輪になる。`ledger.py:27` は「属性は呼ぶ時点で引く」として最上位の import のまま避けている。`ledger` が `gitfacts` から使うのは `commit_trailers` の 1 つだけで（`ledger.py:312`）、`gitfacts` が `publish` を読むのは `publish` の関数を名前を変えずに引き継いで公開するためである（`gitfacts.py:42-51`）
- **誰に効くか**: NDF のスクリプトを直す人と AI。一番下の層が上の層を読むと、どこを変えても読み込みの順序で壊れうるため、#1142 の分割と重複の整理を始める前の足場になる
- **変えると何が成り立つか**: 一番下の層が上の層に依存しない（層の向きが一方向になる）。cross-refactoring の輪が消え、読み込みの順序に頼る注意書きが要らなくなる

## 前提

- 前提 1: 振る舞いは変えない。終了コードの値（`EXIT_DEPS_MISSING` = 69 を含む）・結果 JSON の形・各エントリポイントの引数と出力は、変更の前後で同じである
- 前提 2: 「輪」は、モジュールの間の import（最上位の import と、関数の中・`if TYPE_CHECKING:` の中の import・`importlib.import_module` の文字列の定数）を有向グラフにしたときの強連結成分を指す。動的に組み立てた名前の import は数えない
- 前提 3: 図 3 を作った集計のスクリプトは PR #3002 にも含まれていない（PR の変更ファイルは `docs/scripts-map/` の 4 ファイルと行数の検査の 2 ファイル）。このため受け入れ条件 5 は、図の組の数ではなく、対象のモジュールの組に輪が無いことを、リポジトリの中の検査で確かめる形にする
- 前提 4: `deps.py` は、核（`run_core`）を写さないラッパーのバージョンディレクトリ（`relay_lib/version_dir.py`）からも読まれる。依存の欠けで止まるときに核が読めない場合の扱い（結果を出さずに 69 で終える）は残してよい。残す場合は、輪を避ける理由ではなく、この理由を注意書きにする
- 前提 5: 公開している関数名（`step_result.EXIT_DEPS_MISSING`・`deps.EXIT_DEPS_MISSING`・`gitfacts` が引き継いで公開している `publish` の関数）を呼んでいる側があれば、呼び出し元を直すか名前を残すかは設計で決める。どちらでも前提 1 の振る舞いは変えない

## 対象範囲

含む:
- `plugins/ndf/scripts/lib/step_result.py`・`deps.py`・`run_core.py` の間の輪をほどく

- 上の 2 組に輪が無いことを確かめる自動の検査（テスト）

- ほかの 9 組の遅延の輪（`parallel_*`・`supervise_lib` の `engine`・`flow`・`queue` など。#2936・#2963 と重なるため別に扱う）
- 振る舞いの変更
- 重複の統合（`find_uv` など）と、#1142 のそれ以外の範囲

## 用語

| 用語 | 意味 |
| --- | --- |
| import の輪 | モジュールの import を有向グラフにしたときの強連結成分。最上位の import だけで輪になるものを「実行時の輪」、関数の中の import などを含めて初めて輪になるものを「遅延の輪」と呼ぶ |
| 一番下の層 | 他の NDF のモジュールから最も多く読まれる共通ライブラリ。ここでは結果を出す層 `step_result`（111 ファイルが利用） |
