## 目的

- 開発ループの周回が、並行するスプリントの開発版のデプロイで止まらず、プランを作り直さずに次に空いている版で開発版を出す状態にする
- conductor が周回ごとに版を決める手順を無くし、判断の要らない手順をスクリプトへ寄せる

今の開発ループは版を必須で受けるため、ループのスプリントだけが #2164 の経路を選べない。

## 前提

- 前提 1: この課題は #2344 の実装を待たず、#2164 で入った版の差し込みの上で完結する。#2344 の受け入れ条件 8（`--dev` を省いて起動でき、省いたらプランが版を参照で持ち、渡せば明示の版になる）は、この課題の受け入れ条件 1・2・5 で満たす形にそろえる。後から #2344 が差し込みを参照の部品へ寄せても、開発ループの側は「`--version` を渡さない」だけなので変更が要らない。確認: origin/develop（ac5389bae）に `plugins/ndf/scripts/lib/refs.py` は無く（`ls` で確認）、`git grep -n 2344 -- 'plugins/ndf/scripts/**/*.py'` は 0 件で、#2344 は未完了（OPEN）である
- 前提 2: `--dev` は引数として残す（任意にする）。特定の版で出す必要があるときの手段である。手順書の既定の打ち方は `--dev` を渡さない形にする
- 前提 3: 本番の版が既出のときに自動で次へ移らない #2164 の規則（同じ設計の不変条件 I4・I5）は変えない。リリース承認ゲート で判定した承認資料の版と、出す版を食い違わせないためである。したがって本番のプランまで進んだ後に別のスプリントが同じ版を本番へ出した場合は、今と同じく止まって人へ戻る
- 前提 4: 版を決める規則（`decide_dev`・`taken`・`bump` の止まり方）は変えない。開発ループがどの経路を選ぶかだけが変わるため、必ず人の承認が要る操作 P1（リリース対象の取得元・版の規則の変更）に当たらない
- 前提 5: 版がぶつかる頻度は測らない。この変更は手順を減らすもので、頻度によらず周回の止まる経路を 1 つ無くす
- 前提 6: 適用範囲は #2164 と同じく `.ndf/supervise.json` の `release.form` が `package-plugin` で、`delivery.needs_version` が真の経路である

## 対象範囲

含む:
- `sprint-state.py loop sprint` の `--dev` を任意にし、省いたら `new sprint` へ `--version` を渡さないこと
- `--dev` を省いて `--prod` だけを渡した呼び方の扱い
- 周回の記録（`loop.json`・`laps.md`）の版を、版の記録から埋めること
- 開発ループの案内の文（`loop select` と止まった後の `next`）と手順書 `references/loop.md` の打ち方
- `-- --level <上げ幅>` で上げ幅を渡せることの確認

含まない:
- 版を決める規則そのものの変更（前提 4）
- 本番の版が既出のときの自動の移動（前提 3）
- 差し込みを参照の部品へ寄せること（#2344 の範囲）
- 並行するスプリントの版の取り合いを排他にすること（#2344 の設計が「測っていない」としている項目）
- `new sprint` / `new close` を直接打つ経路の変更（#2164 で完了）
- 確定仕様 `docs/specifications/ndf-release-version-at-run-time.md` の「運用」の 289 行目の書き換え（確定仕様化の工程で行う）

## 用語

| 用語 | 意味 |
| --- | --- |
| 開発ループ | スプリントを 1 つ終えるたびに次のスプリントを選んで続けて始める進め方 |
| 周回 | 開発ループの 1 回分 |
| ループの記録 | 周回ごとの選定・判定・版・費用を持つ記録（`.ndf/loop/<名>/loop.json`。`laps.md` はそこから描画する） |

| 版の決め直し | 流し直しで記録の開発版がもう出ていたときに、次に空いている版へ取り直すこと |
| 明示の版 | 呼ぶ側が渡した版。プランの「版」の欄の `明示` に入る |
