# マイルストーン 26「17 トークン消費の削減」の MVV

2026-09-25 利用者が承認した（同日に Vision と Value 6 の汎用性を足した。2026-09-26 に Mission の目的と Value 7 を改めた）。`pace: fast` の関門 1（設計の承認）と関門 2（本番への配布の承認）は、この MVV への事前の承認として扱い、`experimental/mvv-gate.py` の判定が「従う」なら利用者の承認を待たずに進める。「従わない」か判定できないときは利用者の承認を求める。

## Mission（何のためにやるか）

NDF で開発工程を回すときの LLM のトークン消費と所要時間を、利用者へ価値を早く届けるために減らす。

## Vision（目指す姿）

判断の要らない手順（待ち・集計・検査・記録・整形・起動の組み立て）はスクリプトが決定論的に進め、LLM は判断と中身（コード・設計文書）だけを担う plugin。しかも言語・ブランチ運用・テスト・配布の手段が違うさまざまなプロジェクトで、そのまま使える汎用の plugin。

## Value（判断の基準）

1. **決定論が先**: スクリプトにできる手順を LLM に回させない。同じ手順を LLM に 2 度させたら、スクリプトにする（ただし 6 の汎用を崩さない範囲で）
2. **測って決める**: 効果は実測（費用・秒・件数）で示し、測らずに良くなったとは言わない
3. **小さく出して戻せるようにする**: 開発版のチャネル・導入の確認・自動テストで守り、早く配る。見つけた不具合は即時修正の 4 条件（原因が特定できる・既存の契約を壊さない・既存の方針の範囲・revert 1 回で戻せる）を満たせばその場で直す
4. **利用者の手を止めない**: 承認は MVV の 1 回に寄せ、再起動や告知で操作を求めない
5. **越えない線**: 秘密・認証認可・利用者のデータ・戻せない操作・他のリポジトリへの公開は、MVV があっても関門を省かない
6. **汎用を保つ**: 決定論にするのは手順の骨組みだけにする。プロジェクトごとに違うもの（テストのコマンド・起点のブランチ・配布の手段・言語・ランタイム）は宣言（`.ndf/`）か引数で受け、このリポジトリ（ai-plugins）の形を既定に埋め込まない。プロジェクトによって判断が分かれる所は、LLM の判断として残す
7. **まず届ける**: 完璧なものより、「たぶん動く」ものを早く出す。処理の改善・トークンの削減・高速化に寄与しない指摘（字句の修正、まず起きない異常処理など）は直さない
