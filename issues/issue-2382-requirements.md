## 目的

- Factory の画面を足す後続の課題（#2172 スプリントの一覧と詳細・#2173 承認と通知・#2347 ループの見え方）が、国際化・端末の幅・つながらないときの見せ方・API クライアントの差し替えを画面ごとに作り直さずに、決まった部品と地図の上へ画面を足すだけで済む状態にする（スプリント MVV の Value 2）
- 足した画面が、スマートフォン・タブレット・PC のどれでも操作でき（Value 3）、言語を足すときに画面のコードを書き換えずに済む（Value 5）

## 前提

- 前提 1: 見本の画面の 1 組は「スプリントの一覧」と「スプリントの詳細」とし、ダミーデータだけで動く。並べる項目・フェーズの名前の集合・工程の詳細パネルは #2172 が決めて置き換える。見本はその置き換えの出発点で、#2172 の受け入れ条件を先取りしない
- 前提 2: 端末の幅の代表は、スマートフォン 360 px・タブレット 768 px・PC 1280 px（CSS の px、縦向き）とする
- 前提 3: 既存の画面（`factory/web/src/pages/` の 8 画面）は、文言を翻訳のファイルへ移し、部品へ置き換える。画面の振る舞い（経路・API の呼び方・入力の検査）は変えない
- 前提 4: 翻訳のファイルは日本語の 1 言語だけを持つ。2 つ目の言語は、言語を足せることを確かめるテストの中でだけ差し込む（Value 5「まだ出ていない国のための機能を先回りして作らない」）
- 前提 5: 言語・地域・時刻帯は、利用者の設定がまだ無いため、ブラウザの言語と時刻帯から決める。ブラウザの言語に翻訳が無いときは日本語で出す。利用者ごとの設定を保存するのは後の課題
- 前提 6: ダミーの API クライアントの入出力は、既存の契約（`factory/contracts/openapi/`）がある操作はその形に合わせる。契約にまだ無い操作（スプリントの一覧と詳細）は配列で受け渡す仮の形を置き、契約は #2172・#2384 が決めたときに合わせる
- 前提 7: 画面の地図は確定仕様 `docs/specifications/ndf-factory-*.md`（7 本）の機能から起こす。モック（https://claude.ai/artifact/MYL6CPBTsm6JFTNgtiwY2J ）は設計の工程で読めれば突き合わせ、読めなければ確定仕様だけから起こす（未決 1）
- 前提 8: つながらないときについて、この課題が持つのは状態の見せ方（部品と、ダミーで状態を切り替えて見られること）だけで、端末への保存・暗号化・同期・承認の確定の保留の中身は #2383 が持つ

## 対象範囲

含む:
- 画面の地図（全画面の経路・役割ごとの主な動線・確定仕様の機能との対応）とナビゲーション
- デザインのトークン（色・文字・余白）と、一覧・詳細・状態のバッジ・承認の操作・検索・空の状態・読み込み中・失敗の表示・つながりの状態の表示の部品
- 部品の一覧と使い分けの文書
- スマートフォン・タブレット・PC の 3 つの幅で崩れない配置
- 文言の国際化の仕組み（翻訳のファイル・直に書いた文言を落とす検査）と、日時・数・金額の整形
- 画面が呼ぶ API クライアントのインタフェースと、その裏のダミーの実装（本物と差し替えられる）
- 見本の画面 1 組（スプリントの一覧と詳細）
- 既存の 8 画面の文言の移し替えと部品への置き換え（前提 3）

含まない:
- スプリントの一覧と詳細の本物の中身（項目・フェーズの集合・工程の詳細パネル）と API の中身（#2172）
- 承認の画面の中身と通知（#2173）、ループの一覧（#2347）
- 端末への保存・暗号化・同期・オフラインで押した操作の確定（#2383）
- API と MCP の契約の配列化・委任の認証・操作の記録（#2384）
- 日本語以外の翻訳、利用者ごとの言語・時刻帯の設定の保存、金額の通貨換算
- ダークモードとアクセシビリティの適合の判定（WCAG の監査）。部品は見出しとボタンの役割（role）を持つが、適合の判定はしない
- インフラ（配信・CDN）の変更（private リポジトリの持ち物）
