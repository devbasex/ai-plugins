# DBOS の記録と進行表の置き場: 別のレーンのキューを流さず、開発版が出ても途中の実行を続ける（#3344）

## 目的

- **今どうなっているか**: #1142 の作り直しの設計（決定 77）は、プランの実行の DBOS の記録を進行表と同じ 1 つの DB に置き、アプリの版を NDF の版に結びつけている。DBOS のキューの取り出しは `executor_id` で絞らないため、同じ DB を開いた別のレーンのプロセスがよそのキューを流す。加えて、開発版 `11.0.0-dev.N` が出るたびに、承認ゲートで待っていた実行が取り消される。今の NDF の記録は 2,279 ファイル・687MB まで膨らんでいる
- **誰に効くか**: C2 #3291（プランの実行）の着手を待っている lr-flow と、作り直しの NDF で複数のレーンを 1 台で同時に動かす利用者
- **変えると何が成り立つか**: レーンどうしが互いのプランを流さず、ロックの待ちと破損の影響が 1 つの実行に閉じ、置き場が日数で片付き、開発版が出ても途中の実行が続く

## 適用範囲

- **働く範囲**: `plugins/ndf-next/` の DBOS の殻（C1 の追補）・プランの実行（C2）・進行表の DB（P1）・レーンの起動（P3）・中継（M3）。今の `plugins/ndf/` は変えない
- **プロジェクトごとに違うもの**: 足さない。進行表の DB の URL（`NDF_PROGRESS_DB`）は #3092 の設計のまま環境変数で受ける
- **当たるモード**: `standard`（#1142 のまま）
