## 例: 検査の持ち場（#933）を、変えた後の形で通すと

今（ndf 10.17.8）:

1. conductor が `検査: #933` の supervisor を起動する（`general-purpose`、キャッシュの寿命 5 分）
2. supervisor が構造改善（`cross-refactoring`）を回す。段の終わりの通知で 4〜10 分おきに起き、
   そのたびに 10 万トークン超の文脈を**書き直す**（入力の 1.25 倍）
3. 同じ supervisor が、構造改善で膨らんだ文脈のまま実装レビュー（`cross-review`）へ進む。
   `bg-wait.sh wait` の 1 回が最長 540 秒で、戻るたびにまた書き直す

変えた後:

1. conductor が `検査: #933` の supervisor を **`ndf:supervisor-waits`**（寿命 1 時間）で起動する
2. 構造改善の段の間隔が 60 分以内なら、起きたときの文脈は**読み込み**（0.05 倍）で済む
3. 同じ supervisor が実装レビューへ進む。1 時間の区間では、`bg-wait.sh wait` から戻っても読み込みで
   済むので区切らない（区切ると前提を 2 倍で書き直す分だけ損になる。決定 4）
4. 設計の持ち場では、前半を寿命 5 分の supervisor が通し、`cross-review` の前で区切る（設計の文書の例）。
   区切りの後は 1 時間の supervisor が前提（約 43k）からドキュメントレビューを回す
5. 後で #870 の drive と #827 のスクリプト駆動が入ると、待ちは drive が持ち、判断の地点でだけ
   最小構成の `claude -p`（前提 約 7k）が起きる。supervisor は待たなくなる

## 依頼（原文）

次の方針を受けた（利用者の指示、2026-09-24）。

> - 候補 2「待ちの前に持ち場を切る」は候補 1 が入るまでのつなぎとして設計する
> - 候補 3 は「検査と取り込みの supervisor の定義だけに experimental.cacheTtl: 1h」を入れる。#954 本文の「候補 3 の調べ」節の結果（寿命は 1 時間にできる。試算は supervisor −5〜6%・worker +22〜28%）と、supervisor が今 general-purpose で起動されていて定義単位の設定を配れない点（定義を作る必要）を設計で扱う
> - 候補 1 と 2 を #955 の式（新しい文脈で始めるか続けるかの損得の式）で比べ、決定の記録に数値の比較を残す
> - 「どこまでスクリプトにできるか」を決定の記録に残す（利用者の方針: LLM に判断だけを残す）

## 目的

- **待ちの後の書き直しを減らす。** 書き直しの量は、待つ時点の文脈の長さ C に比例する。C を
  小さくするか（候補 2・1）、書き直しを読み込みに変える（候補 3）
- **待ちを LLM の外へ出す行き先を決める。** #827・#870 が実装するときに、誰が待ちを持ち、
  誰が判断で起きるかの契約がこの設計にある状態にする
- **切るかどうかを LLM の裁量にしない。** 切る条件は式から出した規則にし、Claude Code では
  hook が守らせる

## 前提

- 前提 1: 単価の倍率は Opus 5.5 のもの（入力 1・読み込み 0.05・書き込み 5 分 1.25・1 時間 2）。
  正本は `scripts/token-usage.py` の換算表で、この文書は値を写して計算に使うだけ
- 前提 2: 基準の実測は `docs/metrics/ndf-token-usage/2026-09-24.json` の `per_role`（10.16.0 以降の
  supervisor）を持ち場ごとに足した値（設計の「基準の実測」）
- 前提 3: サブエージェント定義の `experimental.cacheTtl` はプラグインの定義でも効く
  （#954 の「候補 3 の調べ」、公式の手引き）。実機での確認は実装の工程で行う（未確認 U1）
- 前提 4: 1 時間の寿命と hook は Claude Code だけに効く。区切るかを決めるのは hook だけで、
  hook の無いランタイムでは区切らない（今と同じ動き）
- 前提 5: 候補 1 の実装（drive・最小構成の `claude -p` の起動）は #870・#827・#760 が持つ。
  #954 はその契約と、つなぎの間の手（候補 2・3）を実装する

## 対象範囲

含む:

- supervisor のエージェント定義 2 つ（寿命 5 分と 1 時間）と、持ち場ごとの割り当て
- 持ち場の報告の `結果: 区切り` と `次の工程`、conductor の受け方、supervisor の区切りの規則
- 区切りの規則を守らせる hook（`token-guard.sh` の拡張）
- `token-usage.py` の、待ちの後の書き直しの量の列
- 候補 1 の契約（drive が待ちを持ち、判断の地点で新しい文脈を起こす）と、スクリプトにする範囲の表

含まない:

- drive の実装・pause の終了コードの表（#870）、supervisor のスクリプト駆動の実装（#827）、
  worker の CLI 化（#760）
- 損得の式を置く文書の決定（#955。この設計は式を使うだけ）
- worker の待ち（supervisor の子で、切っても待ちが残る）
- 設定 `subagentPromptCacheTtl`・環境変数での一括指定と、延命の仕掛け（#954 の調べで不採用）
