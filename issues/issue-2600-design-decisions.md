# 作業の記録の設計の決定（#2600）

設計文書は [issue-2600-design.md](issue-2600-design.md) にある。

## 決定の記録

### 決定 1: 決まりの正本を 1 か所にするため、持ち主と終わりを契約の項目へ置き、スクリプトは実行時に読む

片付けの判定は `contracts/files/*.json` を読んで動く。手順書と Python の表へ写すと、契約と食い違っても検査で分からない。契約はプラグインのディレクトリに含まれ、利用先へ届く（`.claude-plugin/marketplace.json` の取得元は `plugins/ndf`）。

`run_state_kinds.KINDS` のように Python の表を正本にする形は採らない。受け入れ条件 1 が契約の項目の欠けを検査で落とすことを求め、表を 2 つ持つことになるためである。

- 作り方: 自前で作る・標準に倣う
- 比べた候補: STD1 / LIB4

根拠: Value 5 / Value 8（MVV 版 6）

### 決定 2: 再開に要る記録を時間で失わないため、消す時点を経過時間でなく持ち主の状態で決める

周回とループは数日止まってから再開することがあり、経過時間では要るものを消す。`loop.json` と計画の状態で終わりを判定できるため、時間の窓を置かない。

件数で切る形も採らない。保留の周回と待ちの行が指す周回は、件数と無関係に残す必要がある。

- 作り方: 自前で作る
- 比べた候補: STD1 / PRD1 / PRD3 / PRD4 / PRD5

根拠: Value 5 / Value 3（MVV 版 6）

### 決定 3: 重い作業の置き場を動いているループの間に消すため、周回の締めで片付ける

162 MB の 1 プランは動いているループの中にある。ループの終わりを待つと減らない。費用・秒・結果・承認ゲートは `close_lap` が `loop.json` へコピーするため、締めの後に残す統計以外は要らない。

失敗で締めた周回も同じに扱う。失敗のキーは `loop.json` にあり、再開は新しい周回から始まるためである。

根拠: Value 3（MVV 版 6）

### 決定 4: 残すファイルを読み手が判定できるよう、残す名前をベース名の照合で持つ

`keep` はベース名の glob とし、`report.md` が深さを問わず残る。照合は標準ライブラリの `fnmatch` で足りる。依存を増やさない。

- 作り方: ライブラリやサービスを使う
- 比べた候補: LIB1 / LIB2 / LIB3

根拠: Value 3 / Value 6（MVV 版 6）

### 決定 5: 再開できるループの記録を失わないため、自動の片付けを `mvv_changed` だけに絞る

`mvv_changed` だけが `loop start` で再開しない（`_resume_mvv_changed`）。判定を当たるものだけの一覧にすると、`waiting_only` や `refused` のように止まる条件が増えても既定で消えない。再開で解けるループは `loop close` で人か conductor が閉じる。

根拠: Value 3 / C4（MVV 版 6）

### 決定 6: 答えの処理を壊さないため、答えの無い待ちの行と承認済みで未マージの待ちの行が指す周回を保留と同じに残す

`loop answer` は締めた周回のスプリント状態へ承認ゲートを書く（`sprint_loop.py:447`）。消すと答えの記録が失われる。承認済みでマージが済んでいない行も、先端が動くと問い直しで答えが外れる（`sprint_loop_gate.py` の `reask_design`）ため、同じ周回のスプリント状態を後から使う。受け入れ条件 9 の「保留でない周回」を、周回の結果が保留でなく、かつこの 2 種の行に指されていない周回と読む。答えが入ってマージまで済んだ後は次の片付けが拾う。

ループを閉じる判定（I7）は答えの無い行だけを見る。問い直しは周回の境で起きるため、再開しないループでは承認済みの行の答えが外れない。

根拠: Value 1 / Value 3（MVV 版 6）

### 決定 7: 閉じたループを再開と取り違えないため、記録の状態へ `closed` を足す

文書を消した後の `stopped` は、再開できるループと区別できない。`closed` を足し、`open_record` と `cmd_start` が 1 か所で断る。`status` が `stopped` かを見る既存の箇所へ `closed` が漏れない。

`closed_at` だけを足して `status` を `stopped` のままにする形は採らない。`user_stop` のループを閉じた後に `loop start` が再開してしまう。

根拠: Value 7（MVV 版 6）

### 決定 8: AI にプランの置き場を選ばせないため、既定をメインディレクトリに固定し、外を指す `--out` を断る

既定を `.ndf/sprints/<名>/` にし、リポジトリの中では決まった置き場だけを通す。検査は引数の解釈の最後に置き、何も作らない。リポジトリの外は通す。一時の置き場で試す使い方が残り、掃除の範囲の外である。

`--out` そのものを廃止する形は採らない。開発ループが周回の置き場を渡すために要る。

根拠: Value 5 / Value 6（MVV 版 6）

### 決定 9: 実行中のプランが自分の状態を消さないため、スプリントの片付けをキューの終わりで行う

まとめのプランは自分の状態ディレクトリへ `report.md` を書いて終わる。プランの最後のステップで消すと、実行中のファイルを消す。キューは全プランの報告の後に動くため、ここで片付ける。done は `wait` が読むので残す名前に入れ、スプリントの費用を持つ `sprint-state.json` も残す。

根拠: Value 5（MVV 版 6）

### 決定 10: 誰が打つかを工程に固定するため、承認資料の削除を本番のプランの最後のステップへ置く

`cleanup` の後は承認資料の読み手が無い。`-parallel-` の資料は `approval_path` で同じステップへ渡る。差し戻された提示の資料は持ち主のプランが最後まで流れないため、一覧が `released` の判定で拾う。

根拠: Value 5（MVV 版 6）

### 決定 11: 投稿と削除の順を守るため、実行計画を閉じる操作をコマンドにする

`records.py close-plan` が投稿して URL を確かめてから消す。投稿先は同じリポジトリの Pull Request である。測定を写す手順 1・2 は判断を含むため手順書に残す。

根拠: Value 5（MVV 版 6）

### 決定 12: `.ndf/tmp` の書き手を無くすため、テストのログを `<root>/.ndf/test-run/` へ移す

ログは流し直しで上書きされ、worktree と一緒に消えるため、終わりは `never` でよい。置き場の中へ `.gitignore` を置くのは、`tmp/` の無視の設定に頼らず、どのリポジトリでも `git status` に出さないためである。

状態の置き場（`~/.local/state`）へ移す形は採らない。#2606（リポジトリの外の置き場の寿命）の範囲へ持ち込むことになり、worktree を消しても残る。

根拠: Value 6（MVV 版 6）

### 決定 13: 契約に無いパスを落とすため、書き込みでなくパスの参照を検査する

`.ndf/`・`issues/` で始まる文字列と、`Path(".ndf") / "x"` の連結を抽出して契約のパターンと照らす。書き込みの抽出は `d / name` の形で親のパスが分からない。参照の検査なら読みも対象になり、置き場の語彙が契約に閉じる。文章の中の言及は、文字列全体がパスの形のときだけ見ることで外す。既存の違反は `contract-allow` の例外リストへ載せ、件数を増やさない。

根拠: Value 5（MVV 版 6）

### 決定 14: 手で書く文書の書き手を増やさないため、伝言とレーン用の文書は名の形と持ち主だけを定める

`notice-*`・`loop-<名>-lane.md` は `handoff.py` が名を受け、契約が持ち主を持つ。消すのは、ループの片付けと、一覧を見た AI の `handoff.py remove` である。`lroot-exclude.json` は書き手が無く、持ち主不明として一覧へ出す。

根拠: Value 3（MVV 版 6）

### 決定 15: 原因が同じ課題へ寄せるため、テスト環境は一覧に並べるところまでとする

一覧は worktree レジストリの未解放の行で worktree が無いものについて、compose のラベルでコンテナとボリュームを数える。消す手段は #2660（worktree を消した後もテスト環境の割り当てとコンテナが残る）が持つ。要求の未決 1 の推奨に沿っており、設計承認ゲートで確かめる。

根拠: Value 3 / Value 7（MVV 版 6）

### 決定 16: 周回の片付けが調査を止められなくしないため、待ち時間の調査の終わりに周回の締めを足す

調査は done の出現で止まる（`upkeep_research.py:329`）。片付けが done を消すと、間に合わなかった調査は止まらない。`--loop` と `--lap` があるときは `loop.json` の周回の締めも終わりとして読む。done を残す形は採らない。周回の片付けの結果が残す統計と一致しなくなる。

根拠: Value 7（MVV 版 6）

### 決定 17: 保存済みの状態を復元できるよう、Factory の保存の対象に `.ndf/tmp` を残す

`unpackState` は `STATE_PATHS` の外のパスを断る。外すと、保存済みの状態の復元が失敗する。`.ndf/sprints` を足し、`.ndf/tmp` は在るときだけ保存される今の動きのまま残す。

根拠: Value 6（MVV 版 6）

### 決定 18: AI のパスの打ち間違いが残骸にならないよう、スプリント状態の引数を名前で受ける

`gate p2436` は `p2436.lock` を残した。`/` を含まず `.json` で終わらない引数を決まったパスへ解決し、無ければ錠を取らずに断る。

根拠: Value 5（MVV 版 6）

### 決定 19: 棚卸しを止めないため、一覧のステップは常に 0 で返す

`list --sweep` を `refine-record` の後に置く。読めない項目は `unverified` にする。一覧を読んで消す判断は AI が持つ（`handoff.md` の手順 1〜3）。対象の列挙と消す操作はスクリプトが持つ。

根拠: Value 5 / Value 3（MVV 版 6）
