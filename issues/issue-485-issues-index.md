# #485 issues/README.md の一覧を、手で保たない形にする

## 目的

`issues/README.md` の「未完了の issue」の表が現状と食い違う。表が挙げる 29 件のうち 26 件が
既に閉じている。**この表は「次に何へ着手するか」を選ぶ入口として読まれる。** 閉じた課題が
9 割を占める一覧は、読んだ人に済んだ作業を選ばせる。

## 決めたこと

**表を無くし、課題の一覧は GitHub 側を入口にする。**

| 直し方 | 何が残るか | 採否 |
| --- | --- | --- |
| 表を現状へ書き直す | 一覧は読めるが、次の配布で再び古くなる | 採らない |
| 表を無くし、`gh issue list` と `issues/*.md` の実体を入口にする | 手で保つ対象が減る | **採る** |

**課題は GitHub 側で開閉される。** この表はその事実を受け取らないため、書き直しても同じ
食い違いが再び開く。

**索引としての役割は残す。** `issues/README.md` は「そのディレクトリに何があるか」を案内する
文書である（#498 が定めた 3 つの役割のうちの索引）。案内するのは**このディレクトリにある
ファイル**であり、GitHub 側の課題の一覧ではない。

## 受け入れ条件

- [ ] `issues/README.md` に、閉じた課題を含む手書きの一覧が無い
- [ ] open な課題を見る手段（`gh issue list`）が案内されている
- [ ] このディレクトリにファイルを作る条件と名前の付け方が、これまでどおり書かれている
- [ ] `python3 scripts/check-markdown-links.py --root .` が終了コード 0
- [ ] `python3 scripts/check-doc-line-limit.py` が終了コード 0

## 対象範囲

**含む** — `issues/README.md` の「未完了の issue」の節。

**含まない**

- `issues/old/README.md`（完了したものの索引で、閉じた課題を載せることが役割である）
- `issues/` にあるファイルそのものの整理
- 課題の本文の手入れ（`issue-upkeep` が扱う）
