## 何が起きたか

並列の計画のレーンで、supervisor が worker へ渡す報告の置き場所を用意しようとしたとき、Bash の確認ダイアログが出てレーンが人の入力を待ったまま止まった。2026-11-19 23:08 JST（計画 p8-5 のレーン lrelay）、2026-11-20 06:26 JST（同 ldocs）、2026-11-21 22:30 JST ごろ（計画 p12 のレーン lracct、NDF 11.0.13 の `ndf:supervisor-waits`）の 3 回で、どれもオーガナイザーか利用者が画面で気づいて「Yes」を送るまで進まなかった。

2026-11-23 の 22 時台（JST）には、この課題そのものを設計していた計画 p9 のレーン lsplit の `ndf:supervisor`（NDF 11.0.22）でも 2 回起きた。supervisor は課題の本文を読んで症状を知っていたが、手順書の形（`: > <置く場所>; rm -f <置く場所>.done`）を変数とループで書き、同じ確認に当たった。オーガナイザーが画面で 2 回とも Yes を返した。

## 種類

不具合（手順書が supervisor に打たせる置き場所の用意のコマンドが、人の入力を待つ確認ダイアログを出す。手順書は 2 つの承認ゲート以外を人間の入力なしで通すと約束している）。直す手段として `ndf` のサブコマンドを 1 つ足すが、足すコマンドは従の部分として「影響」の公開インタフェースの行に書く。

## 今の姿

supervisor が worker へ作業を出すとき、worker の報告のコピーを置くファイル（置く場所）と、書き終えたことを示す完了マーカー（`<置く場所>.done`）を使う。supervisor は完了マーカーができたことを見て、worker の報告を読む（待ちの手順書（`plugins/ndf/skills/development-workflow/references/waiting.md`） の「中間通知を受けたとき」）。

置き場所の用意の手順は 3 層の手順書（`plugins/ndf/skills/development-workflow/references/agent-layers.md`） の「supervisor → worker」の表の「置く場所」の欄にあり、supervisor に「自分の作業ディレクトリの下に worker ごとに新しいパスで空のファイルを作り、完了マーカーを消してから（`: > <置く場所>; rm -f <置く場所>.done`）渡す」と書く。supervisor は複数の worker の分をまとめて用意するため、この 2 つをシェルの変数とループで書く。

## 事象

`W=<作業ディレクトリ>; for n in rebuild-main rebuild-detail; do : > $W/$n.report.md; rm -f $W/$n.report.md.done $W/$n.result.json; done` を打ったとき、Claude Code が次の確認ダイアログを出し、ツールの呼び出しが結果を返さなくなった（bypass permissions の下でも出る）。

```text
Dangerous rm operation on possibly-empty variable path: $W/$n.md.done in `rm -f $W/$n.md.done $W/$n.result.json`
(rewrite it as "${W:?}"/"${n:?}".md.done or use a literal path)
Do you want to proceed?
```

ダイアログには「Bash command · from the ndf:supervisor agent」と出た。ダイアログが開いている間、そのツールの呼び出しは結果を返さず、conductor のモデルには子が終わらないことしか見えない。

## 期待する結果

supervisor が手順書のとおりに報告の置き場所を用意しても確認ダイアログが出ず、レーンが人の入力を待たずに進む。

## 再現手順

1. 並列の計画のレーンで supervisor（`ndf:supervisor` / `ndf:supervisor-waits`）を起動する
2. supervisor が `agent-layers.md` の「置く場所」の欄のとおりに、2 つ以上の worker の置き場所をシェルの変数とループで用意する
3. `rm -f $W/$n.report.md.done` の行で Claude Code の確認ダイアログが出て、ツールの呼び出しが返らない

## 環境

- NDF 11.0.9〜11.0.13（計画 p8-5 の lrelay・ldocs、計画 p12 の lracct）
- Claude Code（bypass permissions を有効にした状態でも確認ダイアログが出る）

## なぜ困るか

確認ダイアログはレーンの端末に出る画面で、モデルには届かない。ラッパーのプロセスは動いたままなので、レーンの生死の判定は「動いている」のままになり、待ちの知らせ（`lane_stalled`）にも `ndf lanes wait` の新しい止まりにも出ない。利用者かオーガナイザーが画面を見るまで誰も気づかず、その間レーンの作業が止まり続ける。

## 目的

- 報告の置き場所の用意を、AI が確認ダイアログに当たらずに 1 回の呼び出しで打てるようにし、レーンが人の入力を待って止まらないようにする

## 対象範囲

含む:

- 報告の置き場所の用意（置く場所のパスの決定・空のファイルを作ること・古い完了マーカーと前の作業の結果ファイルの始末）を `ndf` のサブコマンドにする
- 手順書（`agent-layers.md` の「置く場所」と「作業の結果ファイル」の欄、`waiting.md` の該当箇所）を、そのコマンドだけを書く形に直す
- `plugins/ndf` の中で同じ形（置き場所の用意・完了マーカーの削除）を書くほかの手順書・エージェント定義があれば、同じコマンドへ寄せる
- 空かもしれない変数を使った `rm` を PreToolUse の hook で拒否し、書き直しの形を理由として返すこと。ただし hook が Claude Code の安全確認より先に働くことを実機で確かめてからとする

含まない:

- Claude Code の安全確認そのものの振る舞いを変えること（この会話の外にある）
- worker を別プロセス（`claude -p`）で起動して画面の無い実行にすること（#3877 の本文の案 3。置き場所の用意の問題を直す手段としては採らない）
- 止まったレーンを知らせること・自動で起こすこと（#3862・#4036 が持つ）

## 前提

- 前提 1: 確認ダイアログはレーンの端末に出る画面で、サブエージェントのコマンドでも同じ画面に出る。モデルから Yes を送る手段は無い

## 受け入れ条件

- [ ] 1. 報告の置き場所の用意が `ndf` のサブコマンド 1 回の呼び出しで済み、`agent-layers.md` の「置く場所」「作業の結果ファイル」の欄と `waiting.md` がそのコマンドだけを書く。手順書に、置き場所のパスを組み立てる変数と `rm` が残らない
- [ ] 2. worker を 2 つ以上持つ supervisor が手順書のとおりに置き場所を用意しても、Claude Code の確認ダイアログの条件（空かもしれない変数を使った `rm`）に当たらない
- [ ] 3. 同じ supervisor が同じ worker の名前で 2 回目の作業を出しても、1 回目の完了マーカー（`.done`）を 2 回目の完了と読まない
- [ ] 4. コマンドが返す置く場所・完了マーカー・作業の結果ファイルのパスは、同じ作業ディレクトリの下にあり、supervisor が起動指示に書き写せる絶対パスである
- [ ] 5. 空かもしれない変数を使った `rm` を Bash で打つと、確認ダイアログの代わりに hook の拒否と書き直しの案内がツールの結果として返る。ただし hook が Claude Code の安全確認より先に働くことを実機で確かめ、先に働かないなら確かめた結果を設計文書に記録してこの条件を落とす
