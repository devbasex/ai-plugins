## 確かめた事実

2026-11-07 に、このリポジトリのコード（`develop` の d9983a9e5）の実行と、開発対象リポジトリの周回の記録の読み取りで確かめた。

1. **昇格のプランは今の版でもレーンの判定を通らない。** 本番のステージのプランをレーンの判定へ通す関数（`prod_plans`）は、テンプレートで出す経路だけが呼ぶ。テンプレートの無い経路は `route_waves` へ進み、この関数はレーンを判定しない。レーンの判定が真になる状態で昇格の経路を組むと、結果は `[('本番', ['promote'])]` だった
2. **手での置き換えは今も続いている。** 版 10.27.37 で組んだ周回 14 にも `7-promote.json.direct-promote.bak` があり、本番のステージは手書きのスクリプトでリリースの依頼を送っている
3. **まとめの古い一覧は解消済みである。** 周回 8 は版 10.27.27 で動き、設計承認ゲートの後に残った課題だけのまとめ（`close-2/1-close.json`、課題は #153 のみ）を組んでいた。ただし周回の記録の控え（`close_plans`）を更新しなかったため、リリース待ちの答えの後に 3 件のまとめ（`close/1-close.json`）が流れる状態だった。控えの更新はコミット 7784da3bf（2026-11-07 03:41 JST、10.27.37 に収録）で入り、テスト `test_gate_1_points_the_held_close_at_the_close_without_the_waiting_issue` が守っている
4. **リリースの依頼のプランの課題の一覧は、今の版でも外れない。** 外した課題を除く処理（`drop_issues`）は計画の `課題` と Pull Request の `closes` だけを書き換える。実行すると、計画の `課題` は `[153]` になり、コマンドは `--issues 153 191 117` のまま残った
5. **手で置き換えた周回は、本番へ届く前に完了で締まる。** オーガナイザーはリリースの経路が昇格のとき、リリースの組み方を「組まない」と決め、その場で `released`（`version` は `null`）と答える（`delivery.release_way`、確定仕様 `ndf-parallel-organizer.md` の不変条件 I21）。周回 8 はこの答えを 2026-11-06 16:05 JST に読み、main への昇格（carul の PR #221）のマージは 2026-11-07 08:50 JST で、差は 16 時間 45 分だった
6. **周回 6 の直接の昇格は、MVV 判定を通っている。** 置き換える前の報告の通ったステップは `verify → prepare → mvv → note → promote` で、いずれも終了コード 0 だった。落ちたのは後続の `record` で、`--prs` に `{queue_prs}` が未置換で渡った

未確認: レーンが直接流す昇格で MVV 判定が通らなかったときに、オーガナイザーへの問いとして正しく届くか（`loop.md` の表には載っていない。今の周回の記録に実例が無い）。

## 目的

- 並列の計画のレーンで、`loop sprint` が組んだプランを手で書き換えずに最後まで流せる
- 設計承認ゲートで外れた課題に、確定仕様化・閉じる判定・リリースの依頼が掛からない

## 前提

- 前提 1: リリースの経路が昇格のリポジトリのレーンは、昇格のプランを直接流す。利用者の 2026-11-07 の答えに従う。設計承認ゲートで利用者が覆したら、この要求の受け入れ条件 1・9・10・11 を書き直す（未決 1）
- 前提 2: テンプレートで出すリポジトリのレーンは、今どおりリリースの依頼を送る。このリポジトリの宣言と確定仕様が定める形である
- 前提 3: 周回の途中から始まる昇格で `{queue_prs}` が埋まらない不具合は、#2568 と親の #2663 が直す。受け入れ条件はこの解決に依存しない

## 対象範囲

含む:

- 設計承認ゲートで課題を外した周回で、リリースの依頼のプランの課題の一覧を残った課題だけにすること
- 昇格のプランとまとめのプランの課題の一覧を守る退行のテスト
- レーンの本番のステージの扱いを、リリースの経路ごとに手順書と確定仕様へ書くこと

含まない:

- 昇格のプランをリリースの依頼へ置き換えること、オーガナイザーが昇格を組むこと（前提 1・未決 1）
- `{queue_prs}` の未置換（#2568）
- 手で届ける経路のレーンの扱い。オーガナイザーは「組めない」と答える形のまま変えない
- レーンの直接の昇格に、他のレーンの `develop` の変更が入ること（未決 1 の材料）
- すでに手で置き換えた周回と、リリース待ちで保留中の周回の記録の書き直し
- 組み上がったプランの手での編集を検知する仕組み
