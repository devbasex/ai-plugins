## 何が起きたか

2026-10-13 に NDF の中で AI（LLM）を起動している箇所を調べたところ、開発工程を自動で進めるステップが、そのステップで使わない Tool の定義まで読み込んで起動していた。

NDF は、要求・設計・確定仕様化などの工程ごとに、AI を 1 回ずつ新しく起動する（`claude -p`）。この起動では、利用者の環境にある MCP（外部のサービスを AI の Tool として足す仕組み）の Tool を含め、すべての Tool の定義が文脈（AI が毎回読む入力）に載る。文脈は AI が Tool を 1 回呼んで次に進むたび（往復）に読み直されるため、使わない定義の分も往復の回数だけ費用がかかる。

2026-11-27 に利用者が、Tool と安全装置の可否は起動のたびに判断せず、設定を作る・直す Skill で承認を取る方針を示した（末尾の「リクエスト（原文）」）。この要求はその方針を含む。

## 種類

機能追加（全部の Tool を持つ起動が MCP をどう扱うかは、今のコードにも手順書にも約束が無く、新しく決めるため）

## 今の姿

この文書の「工程」は、要求・設計・実装のような開発の区切りである。工程の中の手順（ステップ）を順に並べた実行の定義を「プラン」、プランの元になる定型を「テンプレート」、あるステップの結果に応じて次のステップへ進むことを「遷移」と呼ぶ。

NDF は作業に応じて、AI の起動の仕方を 3 つ使い分けている。

- 判定だけの起動: AI に Tool を使わせず、回答だけを受け取る
- 指定した操作だけを使う起動: 設定を読み込まない最小の構成で、渡した Tool だけを使わせる
- 普段の設定を読み込む起動（以下「全部入り」）: 利用者の設定・プラグイン・hook をそのまま読み込み、Skill とサブエージェント（会話の中から別に起動する AI）が使える

今回の対象は、最後の「全部入り」である。変えるのは読み込む Tool の定義で、利用者のアクセス権限は変えない。全部入りは次の 2 つの起動が使う。2026-11-26 にコードで確かめた。

| 起動する側 | 何の起動か |
| --- | --- |
| 工程から Skill を回す起動 | 工程の定義が指す Skill を 1 回実行する |
| worker の起動 | プランのステップを 1 つ受け持って作業する（要求・設計・実装・確定仕様化・振り返り・棚卸し・リリース後テストなど） |

この起動は、許す Tool の一覧（`Read`・`Edit`・`Write`・`Bash`・`Grep`・`Glob`・`Skill`・`Agent`・`Monitor`・`SendMessage`・`ToolSearch`・`WebFetch`・`WebSearch`）を渡す。この指定は「尋ねずに使ってよい Tool」を決めるだけで、読み込む Tool の定義は絞らない。MCP の読み込みも止めない。MCP の読み込みを止めているのは、設定を読まない最小構成の起動だけである。

10 系で測った値（2026-10-13 の直近 10 日の会話の記録。全部入りで起動したステップ）:

| 会話の種類 | 会話数 | 初回の文脈（中央値、トークン） | 往復（平均） | 文脈の累計 |
| --- | ---: | ---: | ---: | ---: |
| 設計（`/ndf:design`） | 81 | 55,074 | 67.4 | 705M |
| 要求（`/ndf:requirements-design`） | 81 | 54,574 | 38.1 | 261M |

- 起動のたびに固定でかかる約 55,000 トークンが往復ごとに読み直される（設計だけで約 300M と推定）
- 2026-10-13 の実測では、引数を足さない起動は Tool 157・MCP サーバ 7・Skill 103 を読んで 35,268 トークン、Tool を 6 個に絞り MCP の読み込みを止め Skill の一覧も外した起動は 9,188 トークンだった。全部入りは Skill を使うため、そこまでは下がらない
- 全部入りの会話では、サブエージェントの Explore が 6 回、general-purpose が 3 回起動されていた

11 系では測り直していない（未確認）。起動の引数の形は 10 系と同じである。Claude Code の新しいバージョンは MCP の Tool の定義を後から読み込むことがあるため、今の初回の文脈の内訳は測るまで分からない。

**費用を前後で比べる記録も、今は残らない。** 使用量ログ（使ったトークンを 1 起動 1 行で追記する記録）には `claude -p` の行を書く関数があるが、本体のコードから呼んでいる箇所は無い（2026-11-26 に `git grep -n record_cli -- . ':(exclude)docs' ':(exclude)issues'` で検索し、定義・スキーマの説明・テストだけが当たった）。残るのは起動ごとの費用（USD）だけの別の記録で、工程とトークンの内訳を持たない。

### エンジニア向けの補足

- 3 つの起動の仕方のコード上の名前は、順に `judge`・`tools`・`full` である
- 起動の引数: `plugins/ndf/src/ndf/adapters/claude.py` の `permission_args`（282 行から）と `FULL_TOOLS`（54 行）。`full` は `--permission-mode acceptEdits --allowed-tools <FULL_TOOLS>` を渡し、`--tools`・`--strict-mcp-config` を渡さない。`--strict-mcp-config` は `minimal_args`（272 行から）だけが渡す
- 呼び手: `plugins/ndf/src/ndf/progress/invoke.py:943`（Skill のステップ）、`plugins/ndf/src/ndf/core/worker.py:398`（worker）
- 全部入りの起動が何を読むかを定めているのは、`claude.py` の起動の型 `Permission.FULL` の説明（「設定・プラグイン・hook をそのまま読み、`FULL_TOOLS` を許して編集を受ける」）だけである。MCP を読むかは書いていない
- 使用量ログ: `plugins/ndf/src/ndf/domains/records/usage.py` の `record_cli`。費用だけの記録は `plugins/ndf/src/ndf/adapters/run_log.py` の `record_cost`

## 何を足すか・変えるか

| | 今 | 足した後 |
| --- | --- | --- |
| 読み込む Tool の定義 | どの工程でも、環境にある全部（MCP を含む） | その工程が使うものだけ |
| MCP を使う工程 | 指定しなくても使える | 使うと分かった工程と、利用先が指定した工程では使える |
| MCP を使うかの根拠 | 数えていない | 工程ごとの利用回数を会話の記録から数えて残す |
| 効果の確認 | 前後を比べる記録が無い | 初回の文脈と 1 工程の費用を前後で比べて残す |
| Tool と安全装置の可否 | 手順書とコードが決め打ちする。安全装置を外す指定は条件を付けずに起動の例に書かれている | 設定を作る・直す Skill が利用者の承認を取り、承認した内容の起動は都度の承認なしで動く |

## 今の利用者への影響と互換

利用先のプロジェクトが、工程の中で自分の MCP（社内の検索やデータベースの MCP など）を使っていると、読み込みを止めた後はそのままでは使えなくなる。ai-plugins の会話の記録を数えても、利用先の使い方は分からない。そのため、利用先が必要な MCP を指定して使い続けられることを受け入れ条件にする。

相手役（レビューを頼むほかの AI）と作業の委譲で、AI の CLI の安全装置（サンドボックスと確認）を外すのは、そのマシンでサンドボックスが使えず、利用者が承認した場合だけになる。サンドボックスが使えない環境の利用先は、更新の後にそのマシンで 1 回承認する必要がある。

## なぜ困るか

使わない定義の読み直しが、工程を流すたび・往復のたびに費用になり続ける。工程を自動で流す量が増えるほど増える。

## 目的

- 全部入りで起動する工程が、使わない Tool と MCP の定義を読まずに起動する
- 工程ができることは変えずに、1 工程あたりの費用を下げ、下がった量を記録で示せる

## 対象範囲

含む:

- 工程から Skill を回す起動と、worker の起動の 2 つ
- 工程ごとの MCP の利用回数の集計
- 利用先が必要な MCP を指定する手段
- 前後比較に要る分の、起動ごとの使用量の記録
- Tool・MCP・安全装置を外す指定を作る・直す Skill と、承認の記録、起動の前の確認
- NDF のコードと手順書が、相手役と委譲の起動に付ける安全装置を外す指定

含まない:

- Skill の本文を丸ごと読む分の削減（[#1871](https://github.com/devbasex/ai-plugins/issues/1871)）
- 文脈の量を数える範囲の見直し（[#1953](https://github.com/devbasex/ai-plugins/issues/1953)、クローズ済み）
- 最小構成の起動（判定や相手役の起動）。すでに MCP を読まない
- モデルと effort の選び方（[#2944](https://github.com/devbasex/ai-plugins/issues/2944)）
- MCP の定義が呼ぶリポジトリ内のスクリプトの中身。承認の対象は MCP の定義ファイルまでである
- 作業ブランチの `.claude/settings.json` の hook と許可。Claude Code がこれまでどおり読み、NDF の承認の対象ではない
- ステータスラインの費用の表示の直し

## 前提

- 前提 1: ~~対象のランタイムは Claude Code の `claude -p` だけである。Codex の起動は扱わない~~ → Tool と MCP の絞り込みの対象は Claude Code の `claude -p` だけである。安全装置を外す指定の承認は、Codex・Kiro・agy の起動にも適用する（2026-11-27、利用者の方針）
- 前提 2: 承認した内容かどうかは、利用者のマシンに残した承認の記録で見分ける。リポジトリに置いたファイルは、承認の根拠にしない
- 前提 3: 脅威は、うっかりの書き換えと、承認していない人の変更である。AI が意図して承認者になりすます場合は扱わない
- 前提 4: MCP の定義の引数などの中身は、AI への出力に出さない。NDF が示すのは、サーバ名・コマンド名・定義ファイルの場所・内容のハッシュで、中身は利用者がファイルで読む（2026-11-27、設計の承認の回答）

## 受け入れ条件

- [ ] 1. full で起動する各工程が MCP の Tool を使っているかを、会話の記録から数えて残す。工程ごとに、数えた会話の数と、呼ばれた MCP の Tool の名前と回数（0 件ならその事実）が読める
- [ ] 2. 使っていない工程では、MCP と使わない Tool の定義を載せずに起動する。起動の最初の記録に、接続しようとする MCP が 1 つも無い。接続を待った後の応答でも、MCP の Tool が 1 件も現れない。製品に組み込みの Tool は、読み込むと決めた 16 個のうち `WebFetch` を除く 15 個（`Read`・`Edit`・`Write`・`Bash`・`Grep`・`Glob`・`Skill`・`Agent`・`Monitor`・`SendMessage`・`ToolSearch`・`WebSearch`・`TaskStop`・`NotebookEdit`・`ListAgents`）がすべて実際の起動のメインの一覧に載り、`WebFetch` はサブエージェントの側にあり、一覧から外したものは 1 つも載らない。`--tools` に `Agent` と `WebFetch` を一緒に渡すと、Claude Code は `WebFetch` をメインの一覧から外してサブエージェントの側に置く（2.1.268・2.1.332 で同じ）。直す前の起動でもメインに `WebFetch` は無く、使える範囲は変わらない
- [ ] 3. 直した後の初回の文脈と 1 工程あたりの費用を、使用量の記録で前後比較して残す
- [ ] 4. 条件 1 で MCP を使うと分かった工程では、直した後もその MCP の Tool を呼べる
- [ ] 5. 利用先のプロジェクトが指定し、利用者が承認した MCP は、指定した工程の起動で呼べる。指定が壊れている（読めない・形が違う）ときは、黙って MCP なしで起動せず、理由を示して止まる
- [ ] 6. 直した後も、全部入りで起動した工程は Skill の実行・サブエージェントの起動・ファイルの編集ができ、利用者の設定・プラグイン・hook が今と同じく読まれる
- [ ] 7. MCP を 1 つも設定していない環境でも、工程は今と同じく起動して終わる
- [ ] 8. 起動のために、利用者の設定ファイルを書き換えない
- [ ] 9. 設定を作る・直す Skill がある。読み込みに足す Tool・尋ねずに使ってよい Tool・読み込む MCP（起動されるコマンドを含む）・安全装置を外してよいランタイムを設定するとき、内容を示して利用者の承認を取り、承認の記録を残す。MCP について示すのは、サーバ名・コマンド名・定義ファイルの場所・内容のハッシュである（前提 4）。利用者が承認しなければ、起動の設定は書き換わらない
- [ ] 10. 承認した内容と一致する起動では、起動のたびの承認を求めない
- [ ] 11. 承認していない内容（承認の後の手の書き換え、NDF の起動の設定の作業ブランチだけの変更、そのマシンで承認していない設定）を使う起動は、起動せずに止まり、何が承認されていないかと直し方を示す
- [ ] 12. 読み込む Tool の指定と、尋ねずに使ってよい指定は別に書く。読み込みに足しただけでは、尋ねずに使えるようにならない。読み込む指定に許可の記法（`Bash(...)` など）や MCP の Tool の名前を書くと、起動せずに止まる
- [ ] 13. NDF のコードと手順書が起動する相手役と委譲は、そのマシンでサンドボックスが使えず、承認がある場合にだけ、安全装置を外す指定を付ける。承認は「サンドボックスが使えない環境で外してよい」を意味し、サンドボックスが使える環境ではサンドボックスを使う
- [ ] 14. NDF が起動した AI の中からは、承認の記録を書けない

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わる。利用先が MCP と Tool を指定して承認する手段（設定と Skill）が増え、指定していない MCP は工程の中で使えなくなる。安全装置を外す起動は、承認するまで使えない。互換の扱いは設計で決める |
