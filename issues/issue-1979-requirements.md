## 目的

- 使用量の帳簿と、その集計（`usage-report.py`・supervise の報告）の Claude の値を、Claude Code の会話の記録の値と一致させる。トークン削減の効果を、少なく数えた値・2 回数えた値・期間外の値で測らないようにする

## 前提

- 前提 1: 4 件の指摘は、今の develop（d51159151）で再現した（2026-11-05）。手順と結果は下の「再現の記録」にある
- 前提 2: 既に帳簿へ書かれた行（2 回数えた行を含む）は直さない。値が変わるのは、この変更が配布された後に書かれる行と、その後に行う集計だけである
- 前提 3: supervise の work（`runtime: claude`）で起動した claude の使用量は、報告の「CLI（drive・work の中）」の欄に載せる。理由: この起動は external-ai.py と起動の共有処理（`launch-cli.sh`）を通り、codex・kiro・agy の work と同じ経路で帳簿へ書かれる。「LLM の使用量」の欄は supervise 自身が受け取った `claude -p` の結果の使用量だけを持つ（`runtime` を持つ work の結果の使用量は空）
- 前提 4: 帳簿の行（サブエージェントの行を含む）は、行の時刻（`at`）で期間に入れる。1 行の中の応答を期間で分けない。期間で分けるのは、会話の記録から足す分（会話の記録だけの呼び出し）だけである
- 前提 5: サブエージェントの会話の記録は、同じ `agent_id` で続けても 1 本のファイルに追記される（SendMessage で続けた後の hook の入力の `agent_transcript_path` は同じファイルを指す）

## 対象範囲

含む:
- サブエージェントの会話の記録 1 本から使用量を読む処理（同じ `message.id` の扱い）

## 受け入れ条件

- [ ] 1. 同じ `message.id` の assistant の行が 2 行以上ある会話の記録で、帳簿へ書く使用量の 4 つの値（入力・cache read・cache write・出力）が、その id の最後の行の usage になる。同じ記録を `scripts/token-usage.py` の `scan_file` で読んだ合計と一致する
- [ ] 2. 前提: 同じ `agent_id` のサブエージェントが 2 回止まり、hook が 2 回動いた。結果: その `agent_id` の帳簿の行の使用量の和が、2 回目の停止の時点の会話の記録の合計と一致する
- [ ] 3. 前提: 受け入れ条件 2 で、1 回目の行が帳簿に無い（書けなかった）。結果: 2 回目の停止の後の帳簿の行の和が、会話の記録の合計と一致する
- [ ] 4. `usage-report.py --ledger claude` の期間（JST の日付・両端を含む）を指定したとき、会話の記録から足す分（会話の記録だけの `claude -p` の会話とサブエージェント）には、応答の時刻が期間内の応答の使用量だけが入る。最初の応答が期間より前で、後の応答が期間内の会話も、期間内の分が入る
- [ ] 5. 期間を指定しないときの Claude の帳簿の全体と会話の記録だけの値は、受け入れ条件 1 の数え方を除いて変わらない
- [ ] 6. supervise の work（`runtime: claude`）で起動した claude の使用量が、フェーズレポートの「CLI（drive・work の中）」の欄に 1 回だけ載り、「LLM の使用量」の欄には載らない
- [ ] 7. supervise 自身の `claude -p`（`runtime` を持たない work・判断・PR の呼び出し）の使用量は、「CLI（drive・work の中）」の欄に載らない（今と変わらない）
