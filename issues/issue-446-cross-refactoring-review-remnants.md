# #446 cross-refactoring からレビュー機構の残骸を取り除く

## 依頼

> **#436 でレビューをテストへ置き換えたが、レビュー機構の一部が残っている。**
> どの手順からも起動されないが、テストが依存しているため削除は別作業になる。

（issue #446 の本文より）

## 目的

**起動されない実体と、実態と合わない名前を残さない。** 残ると、次に読む人が「この経路は
生きている」と読む。テストが依存しているため、消すには「そのテストが何を確かめているか」を
読んで置き換えるか消すかを決める必要がある。

## 実測（2026-09-07）

| 残骸 | 実測 |
| --- | --- |
| `prompts/review.md` | 存在する。読む手順が 1 つも無い |
| `launch-cli.sh` の `review` フェーズ | 定義は `70` 行目と `118` 行目。**呼び出し元は同じファイルの中だけ**（他の手順・スクリプトからの起動は 0 件） |
| `refactor_lib/commands/review.py`（436 行） | 持つのは `verify-round` / `should-abandon` / `abandon-items` / `merge-fix` の 4 つ。**いずれも修正ラウンドの検証であり、レビューではない** |
| `resolved_thread_ids` の突き合わせ | `commands/review.py:238` と `gitfacts.py:304`。Step 7 の修正ループで**人と `cross-review` のスレッドに効く**ため機能としては有効 |
| `docs/03-review-viewpoints.md` | 位置づけは書き直し済み。内容は残置 |

## 受け入れ条件

**判断の 4 つは設計工程で確定する。** ここでは「確定した判断のとおりであること」と、
判断によらず満たすことを書く。

- [ ] `prompts/review.md` の扱いが決まり、そのとおりになっている
- [ ] `launch-cli.sh` の `review` フェーズの扱いが決まり、そのとおりになっている。
      **消す場合、依存するテストは「消す」か「生きているフェーズへ置き換える」かを
      1 件ずつ判断した記録がある**
- [ ] `commands/review.py` の名前が中身と一致している（`merge-fix` などの修正ラウンドの
      検証を持つ実体に、レビューの名前を付けたままにしない）
- [ ] `resolved_thread_ids` の突き合わせは**振る舞いを変えない**。人と `cross-review` の
      スレッドに効く経路が動くことをテストで示す
- [ ] `docs/03-review-viewpoints.md` の置き場所が決まり、そのとおりになっている
- [ ] **`cross-refactoring` の本番の振る舞いが変わっていない**（残骸の除去であり、
      生きている経路の挙動は変えない）
- [ ] 検査 8 本が終了コード 0
- [ ] `uv run --with pytest pytest scripts/tests plugins/ndf -q` が終了コード 0
