## 目的

- 保留の周回の締め直しの途中に出した問いが必ず周回の記録へ当たり、答えの後に止まった所から続く状態にする
- キューの続きの開始の位置が、指定と耐久の記録だけで決まり、渡し方や前の起動の残り方で変わらない状態にする
- 答えの中身を読まずに止まったプランを流す経路を無くす
- 達成したい状態: carul と ai-plugins で起きた 5 件（#2638・#2639 の 1 つ目・#2325・#2349 の 2 件・#2466）の手当て（手で締め直す・耐久ワークフローを手で取り消す）が要らない

## 前提

- 前提 1: #2342（持ち主の記録）と #2344（プランの参照）の実装を待たず、今のコード（`supervise_lib/` と `lib/sprint_loop*.py`）の上で直す。両方の設計が先行の柱のマージを待っているためである。#2342 の決定 5 と #2344 の決定 8 の形に合わせ、後の実装が同じ箇所を重ねて直さなくてよいように、この課題のマージの後に両方の課題の本文へ「この課題が先に入れた範囲」を書く
- 前提 2: `--from` の指定は人か conductor の明示の指示である。完了したプランへ `--from` を渡したときは、実行条件に当たらなければ、今と同じく指定のステップから流す
- 前提 3: 答えの `result` のうち「続けない」と機械が読むのは `rejected` と `revise` だけである。`approved` と `answered` の中身（`choice`・`note`）は持ち主の AI が読む
- 前提 4: 同じ周回の締め直しの途中の問いは、配布待ちの周回でも質問待ちの周回でも同じ扱いである。1 つの周回に問いが 2 回以上当たることがある
- 前提 5: 実行条件の評価を足すのはキューの続きで開始のステップを持つプランに限る。承認ゲート 2 の承認の後の続き（`supervise.py run <プラン> --from <ステップ>`）と質問待ちの続きは今と同じく打たない。どちらもすでに条件を通ったプランの途中で、この時点で「変更が無い」と判定されると承認した配布が飛ぶためである

## 対象範囲

含む:

- `loop hold-question` が締め直しの途中の周回を引くこと、質問待ちへ戻すこと、遅れて届いた `loop finish` を受けないこと
- 質問待ちの続きが、止まったプランを 2 度流さず、同じキューの残りとまとめを流すこと
- 周回の秒が、配布待ちと質問待ちの両方の区間を数えること
- `queue --resume --from` の照合（名前・フルパス）と、断る文
- `--from` があるときに前の途中を子ごと止めて新しい実行の回で流すこと。止めたキューの他のプランの開始の位置を保つこと
- キューの続きでの実行条件の評価、完了したプランを流さないこと、完了の後に変わったプランを知らせて止まること
- 質問待ちの答えの読み取り、答えの記録、続けないときの締め方、持ち主への渡し方（`references/loop.md` の手順 2' の契約）
- #2638・#2639・#2325・#2349・#2466 の再現の手順を 1 回ずつ通し、閉じるか残すかを記録すること

含まない:

- #2639 の 2 つ目（配布の依頼で止まったときの終了コード）。#2337 に残す
- #2349 の 3 つ目（差分の無い `pr` が終了コード 1 で止まる）。結果の契約の問題で、#2344 も範囲から外している。#2349 は開いたまま残し、残す理由を本文に書く
- プランの差し込みの値と検査の件数（#2663）、次の周回の設計の起点（#2665）
- 再開のエントリポイントの新設（`supervise.py resume`）と、持ち主の記録（#2342）
- プランの型で読んだ中身の正規化（#2344 の決定 7）。この課題の「中身が変わった」はプランのファイルの中身で判定する
- 解決した値をプランのファイルへ書き戻さないこと（#2344 の起票者の推定 S6）
- 並列の計画のオーガナイザー側の問いの一覧・答えの送り方
- レーンでない 1 スプリントの問いの扱い

## 用語

| 用語 | 意味 |
| --- | --- |
| 周回 | 開発ループの 1 回分。選定から締めるまで |
| 保留の周回 | 並列の計画のループのレーンで、答えを待たずに締めた周回（配布待ち・質問待ち） |
| 質問待ち | 作業の途中の問いをオーガナイザーへ送り、止まったプランとステップを残して締めた周回の結果 |
| 配布待ち | 配布の依頼を送り、答えを待たずに締めた周回の結果 |
| キューの続き | `supervise.py queue --resume <done>`。前の起動のステージの並びを読み、完了していないプランを終えたステップから続ける |
| 実行条件 | プランを流す前に打つコマンド。`skip_code` を返せば worktree を作らずに完了とする |
| 耐久の記録 | 1 回の起動が持つ DBOS の SQLite のファイル |
| done | キューが終わったときに書く結果の JSON |

## 受け入れ条件

### 問いの当て先

- [ ] 1. 配布待ちの周回の締め直しの途中で `loop hold-question` を打つと、受け付けて `ok` を返し、周回の結果が質問待ちになり、`question` に依頼の id・止まったプラン・ステップが入り、`release` の答えと本番の版が残る
- [ ] 2. 進行中の周回と締め直しの途中の周回が同時にあるとき、`hold-question` は `--plan` のプランが属する周回へ当たる。どの周回にも当たらないときは断り、周回の記録は変わらない（`stopped`。理由に周回が見つからないことと渡した `--plan` が出る）
- [ ] 3. 1 の問いの答えの後、止まったプランが指定のステップから 1 回だけ流れ、残りのステージとまとめが流れて周回が締め直される。止まったプランがまとめの中にあっても、頭からもう 1 度流れない
- [ ] 4. 質問待ちへ戻した周回に、戻す前に流れていた pipeline の `loop finish` が届くと断り、周回は質問待ちのままで、問いの答えを当てられる
- [ ] 5. 締め直しの途中で問いが当たった周回の秒は、配布待ちの区間と質問待ちの区間の両方を足し、答えを待っていた時間を足さない

### 再開の位置

- [ ] 6. `queue --resume <done> --from <プラン>=<ステップ>` の `<プラン>` に、一覧の `stages` に載ったフルパスと、同じファイルを指す相対パスを渡すと、ファイル名を渡したときと同じプランを同じステップから流す
- [ ] 7. どのプランにも当たらないときは何も流さずに `stopped` を返し、断る文に「名前かフルパスで渡す」ことが出る
- [ ] 8. 前の起動が強制終了で途中のまま残っていても、`--from` があれば、前の途中の耐久ワークフローを子ごと止め、指定のステップから新しい実行の回で流す。止められなければ何も流さず `stopped` を返す
- [ ] 9. 8 のとき、`--from` の対象でないプランのうち、完了したものは流れず、途中だったものは頭からでなく終えたステップから続く
- [ ] 10. キューの続きで開始のステップを持つプランの実行条件が飛ばす条件に当たると、そのプランは流れず、結果は `完了` で、理由に実行条件に当たらないことが出る
- [ ] 11. 完了したプランを含む done を `--from` なしで `--resume` すると、完了したプランは流れず、記録した結果を返す
- [ ] 12. 完了の後にプランのファイルが変わっていて `--from` が無いとき、そのプランは流れず、`queue --resume` は `gate`（終了コード 10 番台）で返り、変わったプランと、流し直す手段（`--from`）が結果に出る

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 運用・保守性 | `queue --resume` は標準エラーへ、プランごとの開始の位置と理由（`--from`・前の結果・前の起動の開始・実行条件で飛ばす・完了の後に変わった）を 1 行ずつ出す。`hold-question` の結果に当たった周回の番号が出る |
| 移行性 | 移す対象は無い。今の `loop.json`（`question` が 1 つの形）と `done.plans.json` をそのまま読める。切り戻しは PR の revert で前の形へ戻る。ただし、質問待ちへ戻した周回の記録が残っていると、前の版の `loop finish` がその周回を締める |

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わる（互換あり）。`hold-question`・`queue --resume` の引数は変わらない。`--from` が受ける値が増える。`queue --resume --from` は前の途中を止める。`queue --resume` は完了の後に変わったプランで `gate` を返す。`loop select`・`loop pending` の `metrics.answer` と、続けないときの手段が増える |
