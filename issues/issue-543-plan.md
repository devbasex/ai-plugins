## モード

`standard`。検査スクリプトの振る舞い（走査の範囲・インラインコードの扱い）と継続的統合の起動条件が変わるため。

## 目的と非目的

達成したい状態:

- `issues/` の文書の壊れた参照で、その Pull Request の継続的統合が落ちる
- いま壊れている参照がリポジトリに残らない

やらないこと:

- 走査の母集合を git の追跡から集める形へ変えること（設計の決定 5）
- 走行中の他の Pull Request のブランチにある `issues/` の参照を直すこと

## 前提

- 前提 1: 設計の「直す参照の一覧」の行番号は `91ee858` の値である。実装の起点
  （`origin/develop` の `700b1de`）で検査を実行し、出力から位置を取り直す
- 前提 2: 起点で `issues` を足して数えた失敗は 40 件である。29 件は設計の一覧と同じで、
  残る 11 件は設計文書と要求文書（`issue-543-*.md`）のインラインコードの中の記法の例である。
  11 件は決定 4 のインラインコードを除く処理で消え、記録の修正の対象にならない

## タスク分解

**コミットの順序は、参照を直す Task 1 を先に、走査を足す Task 3 を後に置く**（設計の決定 2）。

### Task 1: 記録の壊れた参照 27 件を直す

- **対象ファイル:** `issues/` の記録 10 本
- **変更内容:** `](` と `)` の間だけを、設計の「直す参照の一覧」のとおりに直す
- **満たす受け入れ条件:** 8, 9, 10
- **進め方:** テスト駆動を適用しない（記録の文字列の置換）。差分の変更行を対にし、`](…)` の中を
  空にした文字列が一致することをスクリプトで確かめる

### Task 2: インラインコードの中の記法をリンクとして読まない

- **対象ファイル:** `scripts/check-markdown-links.py`、`scripts/tests/test_check_markdown_links.py`
- **変更内容:** 1 行のインラインコードの範囲を空白 1 つへ置き換える関数を足し、`main` のリンクの
  取り出しへ渡す。見出しの読み方は変えない
- **満たす受け入れ条件:** 4, 5, 6
- **進め方:** 失敗するテスト → 通す最小実装

### Task 3: `issues/` を走査へ足す

- **対象ファイル:** `scripts/check-markdown-links.py`、`scripts/tests/test_check_markdown_links.py`、
  `.github/workflows/runtime-plugin-validate.yml`
- **変更内容:** `DEFAULT_SCAN_TARGETS` に `issues` を足す。`issues/` を対象外の例に使う既存テスト 2 件の
  例を対象外のまま残るディレクトリへ移す。`push` の `paths` に `issues/**` を足す
- **満たす受け入れ条件:** 1, 2, 3, 7, 12, 13
- **進め方:** 失敗するテスト → 通す最小実装

### Task 4: `old/` へ移すときの直し方を書く

- **対象ファイル:** `issues/README.md`
- **変更内容:** `old/` へ移すと相対パスの深さが変わって参照が壊れること、直すときは `](` と `)` の間
  だけを変えることを書く
- **満たす受け入れ条件:** 11, 14
- **進め方:** テスト駆動を適用しない（文書）。行数の検査とリンクの検査で確かめる

## リスクと対処

| リスク | 対処 |
| --- | --- |
| 触る対象はスクリプト 1 本（200 行弱）とテスト 1 本で、構造は危うくない | タスクごとにテストを通す |
