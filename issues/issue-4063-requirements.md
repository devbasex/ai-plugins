# #4063: 利用上限でアカウントを替える起動し直しが、背景の作業の残る子を止める

正は課題の本文（#4063）で、この文書はその写しである。本文から作り直す。手で直さない。

中継のラッパーが利用上限・認証の失敗のあとに子を止めて同じ会話を起動し直すとき（lracct の守り 3）、背景で動いていた supervisor・`ndf plan queue`・監視が終わったことを、起動し直した会話が知って続きから起動し直せる状態にする。背景の作業を残したまま子を待たせる案と比べて、待たずに替える形を選ぶ（比べ方は設計の決定の記録にある）。

## 何が起きたか

2026-11-22、#4049 の設計（ https://github.com/devbasex/ai-plugins/pull/4060 ）を書く中で、範囲の外として見つけた。中継のラッパーは利用上限に達した子を、別のアカウントで同じ会話を起動し直して続けさせる（`account` の手）。このとき、背景の supervisor や `ndf plan queue` が残っていても子を止めるので、背景の作業は子と一緒に終わる。#4049 は引継ぎ・止まりの判定・守り 1（上限の手前の替え）だけを扱い、上限に達した後の替え（守り 3）は「上限に達した子は動けないので待たずに替える」と決めて、その代償をこの課題に残した。

同じ日に、レーン lctx の supervisor の 1 つ目の起動が利用上限で止まり、ファイルを 1 つも書かないまま終わった。conductor は「前回の起動は利用上限で止まった」と添えて、同じフェーズの supervisor を手で起動し直した（このフェーズの起動指示）。

## 種類

機能追加（守り 3 で替えた会話に背景の作業が終わったことを伝えるのは、lracct の設計 `issues/issue-3604-3864-design.md` にも #4049 の設計にも無い約束である。lracct の替えの最初の入力 `RESUME_PROMPT` は「利用上限でアカウントを替えた。中断したところから続ける」だけを伝える）

## 今の姿

main の `9311c9a2b` で確かめた。パスは `plugins/ndf/src/ndf/domains/relay/` からの相対で書く。

- **ラッパーは上限の行を見ると、替え先があれば子を止めて同じ会話を `--resume` で起動し直す。** `switch_decide.py` の `_limit_or_auth` が `Step("account", …, prompt=RESUME_PROMPT)` を返し、`wrapper.py` の `_on_resume` が子を止めて起動し直す。背景の作業は見ない
- **lracct（#3604・#3864。実装中）は、守り 3 を 3 つの場面に広げる。** 上限の後の替え（`after_limit`）・認証の失敗の後の替え（`after_auth`、最初の入力は `AUTH_RESUME_PROMPT`）・上限が解けた今のアカウントへ戻る起動し直し（同じ認証で `--resume`）である。API キーの子で動いている間に設定が変わったとき（宛先・資格情報の変更など）も、子を止めて替え先で続ける。どれも同じ `account` の手で子を止める（`issues/issue-3604-3864-design-detail.md` の `_limit_or_auth`・`_revoked` の行と `limit` の候補の行）
- **#4049（設計は main にマージ済み、実装は #3995 と lracct の後）は、子の背景の作業の件数を記録に置く。** 記録は `<中継の保存先>/busy-<起動の ID>.json` で、作業の件数 `count` と監視の件数 `monitors` を、子の会話の起動・作業の開始・Stop の 3 つの時点で hook が書く。守り 3 はこの記録を読まない（#4049 の決定 8）
- **上限に達した子のモデルの呼び出しは失敗する。** 背景の Agent（supervisor）は子と同じアカウントで動くので、同じく進まない。背景の Bash（`ndf plan queue` など）はモデルを呼ばないので動き続け、`ndf plan` の worker の `claude -p` は上限に当たると替え先のアカウントで打ち直す（lracct の決定 9）
- **子を止めると背景の作業は終わり、起動し直した会話には終わりの知らせが届かない。** 起動し直した会話は、背景の作業がまだ動いていると読み、知らせを待ち続けうる（#4049 の決定 9 が監視について見つけた形と同じ）

## 何を足すか・変えるか

| | 今 | 足した後 |
| --- | --- | --- |
| 上限・認証の失敗のあとに替える時点に、背景に作業が残る | 子を止めて替える。起動し直した会話は背景の作業が終わったことを知らない | 待たずに替える。起動し直した会話の最初の入力が、背景の作業と監視が替えで終わったことと、続きから起動し直す方法を伝える |
| 上限が解けた今のアカウントで続ける起動し直し・認証の失敗と API キーの子の設定の変更の後の替え | 上の行と同じく子を止めて起動し直し、背景の作業が終わったことを伝えない | 上の行と同じく待たずに起動し直し、同じ入力を足す |
| 替えの記録（`log.jsonl`） | 替えた理由だけ | 替えで終わった作業と監視の件数（記録が無い・読めないときは不明）の行を足す |
| 背景に何も無い子の替え | 今のとおり | 今のとおり替える。最初の入力には同じ文が付く（子は確かめて何もしない） |

## なぜ困るか

レーンの conductor はフェーズを背景の supervisor かプランのキューへ渡して待つ。利用上限で替えた会話は、supervisor の知らせを待ち続けるか、知らせが来ないことに気づくまで進まない。気づいても、終わった作業の成果がどこまで残ったかを確かめる手がかりが無く、フェーズを頭からやり直す。今は conductor か利用者が手で気づいて起動し直している。

## 目的

- 守り 3 で替えた会話が、替えで終わった背景の作業を知り、成果の残る所から続ける状態にする
- 上限に達した子を、背景の作業のために待たせない（替え先がある限り、レーンを止めない）

## 対象範囲

含む:
- 守り 3 のすべての `account` の起動し直し（上限の後の替え・認証の失敗の後の替え・上限が解けた今のアカウントへの起動し直し・API キーの子の設定の変更か認証の失敗で止めた後の替え）で、背景の作業をどう扱うかの規則
- 起動し直した会話の最初の入力に足す文と、替えの記録に足す件数
- 手順書の直し: `plugins/ndf/skills/development-workflow/references/relay.md` の守り 3 の振る舞い
- 1〜7 を確かめるテストと、利用者の全体の設計方針（#4069）との照らし合わせ

含まない:
- 引継ぎ・止まりの判定・守り 1 の扱い（#4049 が持つ）
- 背景の作業の記録の形と書き方（#4049 が持つ。この課題は読むだけ）
- lracct の設計とコードを変えること。足し込みは lracct と #4049 の実装の後に、この課題の実装で行う
- 子を止めた後に次の会話を起動しない終わり方（`spin`・`account_unavailable`）。起動し直す会話が無いので伝える先が無い
- 上限で待つ間（`wait_reset`・`stalled`）の振る舞い。子を止めないので背景の作業は残る
- Codex（中継のラッパーは Claude Code だけを包む）

## 前提

- 前提 1: 上限に達した子と、その子の背景の Agent は、同じアカウントでモデルを呼べない（lracct の守り 3 の前提）
- 前提 2: API の失敗で終わった応答では Stop の hook が発火せず、StopFailure が発火する（Claude Code の hook の文書。設計の外部の調査）。上限に達した後は、背景の作業が終わっても #4049 の記録は Stop で減らない。そのため記録の件数は「止めた起動の最後の記録」の目安で、失った実数ではない（多めにも少なめにも出うる）
- 前提 3: 子を止めると背景の作業は子と一緒に終わる（#4049 の要求の前提 2）
- 前提 4: `ndf plan queue` は止まったプランを `--resume` で終えたステップから続ける（`development-workflow` の `waiting.md`）。supervisor の成果は作業場所のコミットと状態のファイルに残る
- 前提 5: NDF は普及のフェーズの前で、最初の入力の文と記録の行の形を変えても互換の経路を持たない（MVV Value 4）
- 前提 6: この課題の実装は #3995・lracct・#4049 の実装の後に行う

## 受け入れ条件

この節の「作業」と「監視」は #4049 の要求の用語と同じ意味である。

- [ ] 1. 上限の後に替え先があるとき、背景の作業の記録が作業 1 件以上でも、ラッパーは待たずに子を止めて替える（`wait_background` にしない）
- [ ] 2. 1 の替えで起動し直した会話の最初の入力は、lracct が選ぶ文の後に、背景の作業と監視が替えで終わったこと・終わりの知らせは届かないこと・会話の記録で替えの直前まで終わりを待っていた背景の作業と監視を確かめ（前に取り消したもの・人の答えを待つために止めたものは止めたままにする）、そのうち作業場所の成果から終わっていないと確かめたものだけを、続きから起動し直すこと（supervisor は前の起動が止まったことを添えて、`ndf plan queue` は元の呼び出しを同じ作業ディレクトリ・プランの並び・`--then`・保存先のまま、`--fresh` があれば外して `--resume` で、監視は直前のカーソルから）を足した文である。記録の作業と監視の件数を文に入れ、件数が 0 件でも会話の記録を確かめることを書く。記録が無い・読めないときは件数が分からないと書く
- [ ] 3. 認証の失敗の後の替え・上限が解けた今のアカウントへの起動し直し・API キーの子の設定の変更か認証の失敗で止めた後の替えでも、1・2 と同じく待たずに替え、同じ文を足す。API キーの子の経路の止め方は lracct の `_stop_revoked` のまま変えない（止める条件が成り立てば排他・質問で延ばさず、止めたと確かめられなければ後継を起動せずに `refused` で終え、記録を読まない）
- [ ] 4. 背景に作業も監視も無い子の替えでも 2 の文を足す（件数は 0 件と書く）。守り 1 の替え（#4049）の最初の入力は変えない
- [ ] 5. 替えの記録（`log.jsonl`）に、替えで終わった作業と監視の件数の行を、新しい子の起動の前に 1 つ書く。記録が無い・読めないときは不明と書く
- [ ] 6. 背景の作業の記録を読むのは、守り 3 の替え 1 回につき 1 回だけで、`wait_reset`・`stalled` で待つ見回りでは読まない（読み取りの回数が 0 回）
- [ ] 7. 2 の文と 5 の件数は、子が止まったと確かめた後・次の子を起動する前に読んだ、止めた起動の最後の記録から作る。替えを決めてから子が止まるまでに子が始めた作業も件数に入る
- [ ] 8. 設計文書が、利用者の全体の設計方針（#4069）との照らし合わせを決定の 1 つとして持ち、待つ費用と作業を失う費用の比べ方・プロンプトのキャッシュ・待ちを作らないことの 3 つについて、方針に合うかを書く（設計レビューで確かめる）
- [ ] 9. 1〜7 を、記録の件数（不明・0 件・1 件）と替えの種類ごとの呼び出しの回数で確かめるテストがある（時間で区切らない。時刻は差し替えた時計で進める）。.md の文言を照らすテストにはしない
