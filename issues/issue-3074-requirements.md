## 目的

- あるリポジトリの開発の途中で、別のリポジトリ（上流の NDF など）の改修が先に要ると分かったとき、今の既定は相手のリポジトリへ範囲外の課題を起票するところで終わる。起票の後に誰がいつ直すかは決まっておらず、依頼した側は相手の進みを追えず、設計は「相手の側の変更が先に要る」と書いたまま止まる
- 並列の計画には、計画の置き場と違うリポジトリでレーンを動かす仕組みがすでにある（レーンの `repo`、#2733）。これを既定の手順にし、同じオーガナイザーの下で相手のリポジトリの改修まで進む状態にする

## 前提

- 前提 1: 既定の手順の正本は `development-workflow` の並列開発の文書（`references/parallel.md` の「別のリポジトリのレーン」の節の近く）に置き、`out-of-scope` と `issue-plan-strategy` の並列の計画の文書はそこへリンクする。正本の置き場は設計で変えてよく、変えたら設計文書に理由を書く
- 前提 2: この課題は文書の変更（NDF の Skill の本文と参照の文書）で完結し、`parallel.py` などのスクリプトの振る舞いは変えない。設計で振る舞いの変更が要ると分かったら、この課題の範囲外として起票する
- 前提 3: 「クローンがある」とは、オーガナイザーと同じマシン・同じ利用者のもとに、相手のリポジトリのメインディレクトリ（worktree ではない Git のクローン）があることを指す。レーンの `repo` の検査（規則 `I20`）が通る状態と同じである
- 前提 4: 依頼した側から相手のリポジトリへ課題を起票する・1 行を書く操作は、今と同じく「他のリポジトリへ公開する」（C5）として人の承認を取る。この課題はその承認を緩めない
- 前提 5: 相手のリポジトリのレーンを計画へ足す操作は、既存の「レーンを足す」の手順（`parallel.py lane p1 add`）で行う。レーン数の上限を変えるのは今と同じく人の指示を受けたときだけである

## 対象範囲

含む:

- 「別のリポジトリの改修が要ると分かったとき」の既定の手順を、NDF の文書の 1 か所に定め、ほかの文書からそこを指す
- 既定の手順: オーガナイザーが相手のリポジトリのクローン（メインディレクトリ）を `repo` にしたレーンを起動する。クローンが無いとき・並列の計画を使っていないときは、別のリポジトリへの起票に戻る
- 依頼した側の課題と、相手のレーンが直す課題を、完全な形の参照（`<所有者>/<リポジトリ>#<番号>`）で対に結ぶ書き方
- 依頼した側が相手のレーンを待つとき・待たずに進むときの手順（`after` の使い方を含む）
- 相手のレーンに相手のリポジトリの規約（課題・設計承認ゲート・リリース承認ゲート・漏れの検査）が掛かることの明記

含まない:

- #2653 の宣言（構成リポジトリの一覧）・スプリントをまたぐ閉じる条件・重なりの判定の作り替え（#2653 の段階 3・4 で進める）
- 公開範囲の境界の検査の追加
- `parallel.py`・`relay.py` など並列の計画のスクリプトの振る舞いの変更（前提 2）
- 相手のリポジトリへの起票・1 行の書き込みに掛かる人の承認（C5）の省略（前提 4）

## 受け入れ条件

- [ ] 1. NDF の文書（`plugins/ndf/skills/` の配下）に「別のリポジトリの改修が要るとき」の既定の手順が 1 か所だけあり、`out-of-scope` と `issue-plan-strategy` の並列の計画の文書は手順を写さずに、その箇所へのリンクを持つ（確かめ方: 手順の見出しの語で `plugins/ndf/skills/` を検索し、手順の本文が 1 か所、ほかはリンクだけであることを示す）
- [ ] 2. 既定の手順は「オーガナイザーが、相手のリポジトリのクローン（メインディレクトリ）を `repo` にしたレーンを足して起動する」形であり、クローンが無いとき・並列の計画を使っていないとき・`I20` で断られたときの 3 つに、代わりの手順（別のリポジトリへの起票）が書かれている
- [ ] 3. 依頼した側の課題と相手の課題を対に結ぶ書き方が、完全な形の参照で両方の課題に書く形として定まっており、書く場所（本文の節か由来の節か）が 1 つに決まっている
- [ ] 4. 相手のレーンに相手のリポジトリの規約（課題・設計承認ゲート・リリース承認ゲート・漏れの検査）が掛かり、依頼した側の規約や情報（インフラの値など）を相手のリポジトリへ持ち込まないことが、既定の手順の箇所に書かれている
- [ ] 5. 依頼した側が相手のレーンを待つときと待たずに進むときの手順が書かれており、待つときの `after` の使い方が、`after` の今の意味（「始める条件」。並べたレーンがすべて止まってから起動する）と食い違わない
- [ ] 6. 依頼した側から相手のリポジトリへの起票・1 行の書き込みには、今と同じく人の承認（C5）が要ると書かれており、既定の手順のどの段もその承認を省いていない
- [ ] 7. 変更した Skill と文書が、リポジトリの既存の検査（`python3 scripts/check-skill-frontmatter.py`・`python3 scripts/check-markdown-links.py`・`python3 scripts/check-doc-line-limit.py`・`python3 plugins/ndf/scripts/instructions-check.py --root .`）を通る
- [ ] 8. 退行しない: 並列の計画を使っていないセッションの範囲外の課題の手順（`out-of-scope` の手順 3〜5）は、代わりの手順として今と同じ振る舞いのまま残る。`.md` の文言を照合するテストを足さない
