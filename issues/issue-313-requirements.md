# #313: wt_extract_write_target がリダイレクトより後ろの被演算子を書き込み先として出さない

設計は [issue-313-design.md](issue-313-design.md) にある。この文書は「何を満たすか」だけを扱う。

## 依頼（原文）

> `wt_extract_write_target` は、リダイレクトより後ろに置かれた被演算子を書き込み先として
> 出さない。リダイレクトを読んだ時点で、その命令の被演算子の走査が終わる。
>
> ```console
> $ source plugins/ndf/scripts/lib/worktree-common.sh
> $ wt_extract_write_target "sed -i 's/a/b/' x.md >log y.md"
> x.md
> log
> $ wt_extract_write_target "sed -i 's/a/b/' x.md y.md"
> x.md
> y.md
> ```
>
> 同じ `y.md` が、リダイレクトを挟むと出なくなる。**bash は `y.md` も被演算子として扱う**
> ため、実際には書き換えられる。
>
> この課題は被演算子の走査そのものの終わり方にあり、**リダイレクトを読み飛ばして走査を
> 続ける形へ変える**必要がある。

（issue #313 の本文から「何を見つけたか」と「なぜこの変更の範囲外なのか」の一部を引いた。
モードは `standard`）

## 解釈

**被演算子を走査する枝（`sed -i` / `cp` / `mv` / `tee`）が、リダイレクトの語とその被演算子を読み飛ばし、
命令の区切りまで走査を続ける状態にする。** bash はリダイレクトを引数の並びから取り除いてから命令を
実行するため、リダイレクトの前後の被演算子は同じ並びに属する。

読み飛ばす対象には入力側のリダイレクト（`<` `<<<` `<<` `<>`）も含める。現状はこれらの語を被演算子として
読み、`cp a b <in` の宛先を `<in` と出す。出力側だけを読み飛ばす形にすると、同じ走査の中で入力側の
語が宛先の位置を奪ったまま残る。範囲を広げた理由は設計文書の「決定の記録」にある。

## 目的

- リダイレクトを挟んだ命令でも、bash が書き換えるファイルを書き込み先として出す
- リダイレクトの被演算子（`log` や `in`）を、命令の被演算子と取り違えない

## 前提

- 前提 1: リダイレクトの書き込み先（`>log` の `log`）は、これまでどおり主の走査の `__WT_REDIR__` の枝が
  出す。被演算子を走査する枝は読み飛ばすだけで、出さない
- 前提 2: 出力の順序は契約に含めない。呼び出し側（`worktree-guard.sh`）は結果を集合として扱う
- 前提 3: 引用符で囲んだ `<` で始まる名前（`cp a "<b"`）は扱わない。字句解析が引用符を落とした後の
  語はリダイレクトと区別できない。この形の名前が使われる頻度は無視できるものとして置く
- 前提 4: `>|` の取りこぼしは #625 が扱う。印への置き換えの段で起き、この変更の走査の直しでは変わらない

## 用語

| 用語 | 意味 |
| --- | --- |
| 抽出関数 | `plugins/ndf/scripts/lib/worktree-common.sh` の `wt_extract_write_target` |
| 被演算子を走査する枝 | 抽出関数の中で `sed` / `cp` / `mv` / `tee` の後ろの語を読むループ（`_wt_extract_sed_targets`・`_wt_extract_cp_mv_target`・`tee` の枝） |
| 出力側のリダイレクト | `>` `>>` `&>` `&>>` `>&` と、記述子の番号を前置した形。字句解析の前に印 `__WT_REDIR__` / `__WT_APPEND__` へ置き換わる |
| 入力側のリダイレクト | `<` `<<<` `<<` `<<-` `<&` `<>` と、記述子の番号を前置した形。印へ置き換わらず、語のまま残る |
| リダイレクトの被演算子 | リダイレクトが開くファイル・記述子・終端の語・行の入力（`>log` の `log`、`<<<word` の `word`） |

## 受け入れ条件

リダイレクトの後ろの被演算子を出す:

- [ ] AC1: `sed -i 's/a/b/' x.md >log y.md` から、`x.md` と `y.md` と `log` の 3 件が出る
- [ ] AC2: `sed -i` の後ろに `2>&1`・`2>/dev/null`・`&>log`・`>&log`・`>& log`・`>>log` のどれを挟んでも、
  後ろの `y.md` が出る。`/dev/null` と記述子の番号は出ない
- [ ] AC3: `cp a b >log c` の宛先として `c` が出て、`b` は出ない。`mv` も同じである
- [ ] AC4: `tee a >log b` から `a` と `b` と `log` が出る
- [ ] AC5: 命令名と被演算子の間のリダイレクトを読み飛ばす。`sed -i >log 's/a/b/' x.md` から `x.md` が出る。
  `cp -t >log dir a b` と `cp a >log -t dir b` の宛先は `dir` である

入力側のリダイレクトを被演算子と取り違えない:

- [ ] AC6: `sed -i s/a/b/ x.md` の後ろに `<in`・`< in`・`<<<word`・`<<< word`・`2<in`・`<&0` のどれを挟んでも、
  出るのは `x.md` と `y.md` だけである
- [ ] AC7: ヒアドキュメントの開始（`<<EOF` と `<< EOF`）を挟んでも、出るのは `x.md` と `y.md` だけである
- [ ] AC8: `cp a b <in` と `cp a b < in` の宛先は `b` である
- [ ] AC9: `sed -i s/a/b/ x.md <>rw y.md` から `x.md` と `y.md` と `rw` が出る（`<>` は読み書きで開き、無ければ作る）

退行しない:

- [ ] AC10: 起点を渡した呼び方で、`cd sub && sed -i s/a/b/ x.md >log y.md` の 3 件が `sub` の下の絶対パスで出る
- [ ] AC11: 区切り（`|` `||` `&&` `;` 改行 `)`）で被演算子の走査が止まる。`cp a b 2>&1 || echo c` の宛先は `b` だけで、
  `c` は出ない
- [ ] AC12: プロセス置換（`cp <(echo) dest`）の宛先は `dest` である
- [ ] AC13: `uv run --with pytest pytest scripts/tests plugins/ndf -q` が通る。既存の `test_write_target.py` の
  期待値を変えない

## 対象範囲

含む:

- 抽出関数の、被演算子を走査する 3 つの枝（`sed` / `cp`・`mv` / `tee`）
- リダイレクトの語が読み終える位置を決める補助関数（新設）
- `plugins/ndf/skills/worktree/tests/test_write_target.py` への受け入れ条件のテスト

含まない:

- `>|` の取りこぼし（#625）
- `cd` の枝の入力側のリダイレクト（`cd <in sub`）。出力側は既に読み飛ばしている。入力を与えた `cd` を書く
  場面が無いため、起票もしない
- 命令名より前の入力側のリダイレクト（`<in cd x` の `cd` を命令として数えること）。出力側は #201 が扱った
- 引用符で囲んだ `<` で始まる名前の区別（前提 3）
- 字句解析（`_wt_tokenize`）と、印への置き換えの段の変更
- 対象の 4 形式（直接の書き換え・出力の付け替え・標準入力からの書き出し・複製と移動）を増やすこと
- クラス図とデータ構造の成果物。bash の関数だけを変え、型も永続データも持たない。変わるのは抽出関数の
  内側の走査の順序で、処理の流れの図が持つ

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 性能・拡張性 | 走査は語の数に対して線形のままである。語 1 つあたりの追加は、補助関数の呼び出し 1 回に収まる |

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わらない。抽出関数の引数・終了コード・1 行 1 件の出力の形は同じである |
| 既存の振る舞い | リダイレクトを挟んだ命令で、書き込み先が増える（取りこぼしが減る）。入力側のリダイレクトの語が書き込み先から消える |
| 主ディレクトリの編集の案内 | 案内が出る場面が増える。案内は編集を止めない |
| 利用者の手順 | 変わらない |

## 検証手段

| 項目 | 手段 |
| --- | --- |
| テスト | `uv run --with pytest pytest plugins/ndf/skills/worktree/tests/test_write_target.py -q`、仕上げに `uv run --with pytest pytest scripts/tests plugins/ndf -q` |
| 静的解析 | `shellcheck plugins/ndf/scripts/lib/worktree-common.sh`（導入されていれば） |
| 挙動の突き合わせ | AC1〜AC9 の命令を bash で実際に走らせ、書き換わるファイルと抽出関数の出力を比べる（設計文書の「実測」） |

## 前提とする取り決め

| 項目 | 参照先 / 決めたこと |
| --- | --- |
| プロジェクト構造 | 抽出関数は `plugins/ndf/scripts/lib/worktree-common.sh` の中に閉じる。補助関数も関数の内側に定義し、末尾の `unset -f` へ足す（既存の `_redir_target` と同じ扱い） |
| コーディング規約 | `AGENTS.md` の「最小限のコード実装」。コメントは日本語で、なぜその形かを書く（既存の枝と同じ） |
| テスト戦略 | 抽出関数の単体テスト（`test_write_target.py` の `extract`）で受け入れ条件を 1 件ずつ確かめる。guard を通した結合は既存のテストに任せる |

## 境界

| 区分 | 内容 |
| --- | --- |
| 常に行う | 既存テストの実行、変更した枝への理由のコメント |
| 確認してから行う | 字句解析と印への置き換えの段の変更 |
| 行わない | `>|` の修正（#625）、`cd` の枝の変更、対象の形式を増やすこと |
