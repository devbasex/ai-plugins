## 目的

- 「スプリントを閉じる」（`plugins/ndf/scripts/sprint-close.py`）が、スプリントの Pull Request が触れたのに閉じる語も `--issues` も無い課題を、結果 JSON の `items` に載せる。漏れた課題を、報告を読むだけで見つけられる状態にする
- 閉じる語を集めた結果が 0 件のまま「失敗 0 件」で終わる経路（PR #1825 の事例）を無くす

## 前提

- 前提 1: **突き合わせの相手はマイルストーンの課題ではなく、スプリントの Pull Request の題と本文が `#<番号>` で参照する課題にする。** このリポジトリではスプリントはマイルストーンから切り出す（`development-workflow` の用語集の「マイルストーン」）。マイルストーン 26 には 2026-10-08 時点で開いた課題が 53 件あり、スプリントが扱うのはその一部である。マイルストーンの開いた課題を全部 `kept_open` に載せると、別のスプリントの課題が毎回数十件並び、漏れが埋もれる。観測した 2 件の事例（PR #766 の `Refs #554`・`関連 #550`、PR #1825 の `- 課題: #1743 #1491 …`）は、どちらも Pull Request が番号で参照していた。マイルストーンで絞り込む選択肢を足すかは未決に置く
- 前提 2: 突き合わせで見つけた課題は**閉じない**。`kept_open` で返し、理由に「閉じる語も `--issues` も無い参照」と書く。参照だけでは、スプリントで終えた課題か、関連として挙げただけの課題かを決められない
- 前提 3: **Pull Request を作る側の検査（課題の「直し方」の 2）はこの変更で扱わない。** スプリントの Pull Request は supervise.py の `pr` のステップが `supervise_lib/pr_materials.py` で組み、`## 閉じる課題` の節に `Closes #<番号>` を書く。PR #1825 で閉じる語が落ちたのは、作った後に本文を手で書き直したためで、`pr-steps.py` を通らない。閉じる側の突き合わせは、本文がどの経路で書かれても効く（Value 6: 根本原因の場所で直す）
- 前提 4: 参照として読むのは、記録のリポジトリの `#<番号>` と、記録のリポジトリの課題の URL（`https://github.com/<所有者>/<リポジトリ>/issues/<番号>`）だけにする。他のリポジトリの参照（`<所有者>/<リポジトリ>#<番号>`）は読まない
- 前提 5: 参照した番号のうち、Pull Request（`gh issue view` の `url` が `/pull/` を含む）と、既に閉じた課題は結果に載せない

## 対象範囲

含む:
- `sprint-close.py` の課題の収集: スプリントの Pull Request の題と本文の参照を読み、収集した課題（閉じる語 ∪ `--issues`）に無い開いた課題を `kept_open` で返す
- `sprint-close.py` の停止: スプリントの Pull Request を読めたのに収集した課題が 0 件のとき、何も閉じずに止まる
- 振る舞いの変化に合わせた文書の更新: `progress-tracking` の「スプリントを閉じる」（`kept_open` の理由と終了コード 2 の行）、`development-workflow` の用語集の「スプリント課題」（今の定義は閉じる語だけで、`--issues` を含まない）

含まない:
- マイルストーンの課題との突き合わせ（前提 1）
- `pr-steps.py` の `plan` / `create` / `update` での閉じる語の検査（前提 3）
- 参照だけの課題を閉じること（前提 2）
- 他のリポジトリの課題の参照（前提 4）
- `supervise_lib/sprint.py` の `close` のステップの引数の変更（`new close --issue` の全課題を既に `--issues` で渡している）
