# #543: issues/ の Markdown をリンクの検査の走査へ入れる — 要求と受け入れ条件

設計は [issue-543-design.md](issue-543-design.md) にある。この文書は「何を満たすか」だけを扱う。

## 目的

- `issues/` に置く設計文書と計画で参照が壊れたとき、その Pull Request の継続的統合で落ちる
- `issues/old/` へ移したことで壊れた参照を、移した Pull Request の中で見つけられる
- いま壊れている参照が、リポジトリに 1 件も残らない

## 対象範囲

含む:

- `scripts/check-markdown-links.py` の走査の対象へ `issues/`（`issues/old/` を含む）を足すこと
- インラインコードの中の記法をリンクとして読まないこと
- いま壊れている参照 27 件を直すこと
- `issues/old/` へ移すときの参照の直し方を `issues/README.md` に書くこと
- 継続的統合の push の起動条件へ `issues/**` を足すこと

含まない:

- 走査の母集合を git の追跡から集める形へ変えること（設計の決定 5）
- 複数行にまたがるインラインコード。走査の対象に 0 件である
- `.github/` など、`issues/` 以外の走査していないディレクトリ
- `issues/old/` の文書の本文・リンクの文言・版数の書き換え
- リンクの記法になっていないパスの表記（`` `issues/old/...` ``）の検査
- 文書を移すときに参照を自動で書き換える道具
- ruleset の必須の検査の変更
- クラス図・データ構造・入出力の契約の節。触る型も永続データも呼び出しの約束も無い

## 依頼（原文）

> **`issues/` の Markdown がリンクの検査を素通りしている。** 走査の対象に入っていない。
>
> **`issues/` に置く設計文書と計画は、分割や移設のたびに参照が壊れうる。** 検査が見ていない
> ため、壊れたことに気づく手がかりが無い。
>
> **`docs/` へ移った後は検査される**（`plan-to-spec` が移す）。**問題は移す前の期間である。**

（issue #543 の本文から抜粋。考えられる形の 3 案は設計の工程で扱う）

## 現状の確認

`origin/develop`（`91ee858`、#445 の見出しの照合が入った後）で数え直した。`08c370a` でも同じ値だった。`git archive` で
追跡しているファイルだけを取り出し、走査の対象へ `issues` を 1 つ足して検査を実行した。

| 観点 | 実測 |
| --- | --- |
| いまの走査での失敗 | 0 件（終了コード 0） |
| `issues/` を足したときの失敗 | **29 件**（すべて `missing link target`。`missing heading anchor` は 0 件） |
| うち `issues/old/` の文書 | 27 件（9 本） |
| うち `issues/` 直下の文書 | 2 件（2 本） |
| `issues/` の文書の数 | `old/` 133 本 / 直下 26 本 |
| `issues/` の相対リンクの数 | `old/` 383 件 / 直下 25 件 |
| 他の文書から `issues/` の見出しを指す参照 | 0 件 |
| 実行時間 | 0.07 秒 → 0.11 秒 |

**起票時の 31 件から 2 件減った。** 起票の後に直した分である。主ディレクトリ（未追跡の
`issues/issue-500-readme-apply.md` を含む）で実行しても 29 件で変わらない。

**29 件は壊れ方で 3 つに分かれる。** 一覧は設計文書の「直す参照の一覧」にある。

| 壊れ方 | 件数 |
| --- | ---: |
| 文書を `issues/old/` へ移し、相対パスの深さが変わった | 23 |
| 指す先の文書が `issues/old/` へ移った、または分割された | 4 |
| インラインコードの中の記法の例を、検査がリンクとして読んだ | 2 |

## 前提

- 前提 1: 検査を呼ぶのは、継続的統合の `markdown-link-check` ジョブと
  `scripts/validate-runtime-plugins.sh` である。どちらも引数は `--root` だけで、
  走査の対象はスクリプトの中の `DEFAULT_SCAN_TARGETS` が決める
- 前提 2: GitHub はインラインコードの中の `[文言](参照先)` をリンクとして描画しない
- 前提 3: `issues/old/` の文書は起きたことの記録であり、当時の判断と記述を後から変えない。
  根拠は `AGENTS.md` の「すべての版数を機械的に置換しない」と、`check-doc-line-limit.py` の記録の扱いである

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わらない。`check-markdown-links.py` の引数と出力の形は同じ |
| データ | 無し |
| 既存の振る舞い | `issues/` の変更で継続的統合が落ちうる。インラインコードの中の記法が照合から外れる（いまの走査の対象では外部の URL 1 件だけで、結果は変わらない） |
| 並行する作業 | `issues/` に解決できない参照を持つ Pull Request は、この変更がマージされた後の再実行で落ちる |

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 性能・拡張性 | 検査 1 回の実行時間が 1 秒を超えない（実測 0.11 秒） |

## 前提とする取り決め

| 項目 | 参照先 / 決めたこと |
| --- | --- |
| プロジェクト構造 | 検査は `scripts/`、テストは `scripts/tests/` に置く（既存の配置） |
| コーディング規約 | `AGENTS.md` の「最小限のコード実装」。#445 の決定（見出しの読み方）を崩さない |
| テスト戦略 | 一時ディレクトリへ文書を作り、検査を別プロセスで実行して終了コードと出力を見る（既存のテストと同じ形）。27 件の修正は差分を読むスクリプトで確かめる |

## 境界

| 区分 | 内容 |
| --- | --- |
| 常に行う | 記録のリンクは `](` と `)` の間だけを直す。測れなかった件数を 0 件と書かない |
| 確認してから行う | ruleset の必須の検査の変更 |
| 行わない | `issues/old/` の本文の書き換え。除外の一覧の新設 |

## 検証手段

| 項目 | 手段 |
| --- | --- |
| テスト | `uv run --with pytest pytest scripts/tests/test_check_markdown_links.py -q` |
| 静的解析 | `python3 scripts/check-markdown-links.py --root .` / `python3 scripts/check-doc-line-limit.py --root .` |
| 差分の確認 | 受け入れ条件 8〜10 を、`git diff origin/develop` の変更行を比べて確かめる |

## 受け入れ条件

### 走査の範囲

- [ ] 1. `issues/` 直下の文書に解決できない相対リンクがあると、`check-markdown-links.py` が
      終了コード 1 で落ちる。出力に `- issues/<文書>: missing link target: <参照先>` の行が出る
- [ ] 2. `issues/old/` の下の文書（入れ子のディレクトリを含む）でも、1 と同じく落ちる
- [ ] 3. 他の文書から `issues/` の文書の無い見出しを指す参照（`../issues/x.md#無い見出し`）が、
      `missing heading anchor` で落ちる

### インラインコード

- [ ] 4. インラインコードの中の `[文言](参照先)` と `<a href="参照先">` は、参照先が無くても落ちない
- [ ] 5. 4 と同じ行でも、インラインコードの外にある解決できないリンクは落ちる
- [ ] 6. インラインコードを含む見出しを指す参照が、これまでどおり解決できる

### 既存の参照

- [ ] 7. 実装の Pull Request の head で、リポジトリ全体への検査が終了コード 0 で終わる
- [ ] 8. 直した 27 件のどの行も、変わったのは `](` と `)` の間だけで、角括弧の中の文言と行の他の部分は変わらない
- [ ] 9. 直した 27 件のうち 26 件は、壊れる前に指していた文書（またはディレクトリ）と同じものを指す。残る 1 件
      （`ndf-skill-inventory.md`）は、その文書を分割した先のディレクトリを指す
- [ ] 10. `issues/old/issue-81-evidence-link-rewrite.md` の差分が無い

### 手順と継続的統合

- [ ] 11. `issues/README.md` に、`old/` へ移すと相対パスが壊れること、直すときは `](` と `)` の間だけを変えることが書かれている
- [ ] 12. `runtime-plugin-validate.yml` の `push` の `paths` に `issues/**` がある

### 退行しないこと

- [ ] 13. `scripts/tests/test_check_markdown_links.py` がすべて通る。走査の対象外の例として
      `issues/` を使っていた 2 件は、対象外のまま残るディレクトリへ例を移して意図を保つ
- [ ] 14. `python3 scripts/check-doc-line-limit.py --root .` が終了コード 0 で終わる

## 用語

| 用語 | 意味 |
| --- | --- |
| 走査の対象 | `check-markdown-links.py` がリンクを取り出す文書の集合。`DEFAULT_SCAN_TARGETS` が決める |
| 参照先 | リンクの `](` と `)` の間に書かれた値 |
| 文言 | リンクの `[` と `]` の間に書かれた値 |
| インラインコード | 1 行の中で、同じ本数のバッククォートの列に挟まれた範囲 |
