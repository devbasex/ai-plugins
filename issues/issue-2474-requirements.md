## 目的

周回の途中で開発ループを止めて後から再開したとき、止める指示が再開で解け、止めていた時間がループの予算を使わない状態にする。利用者がセッションを切ってループを休ませても、再開した後に余分な止まりが 1 回挟まらず、予算の残りが休ませる前と同じに保たれる。

実際に起きた値（`.ndf/loop/lfactory2/loop.json` の記録、時刻は UTC）:

| 項目 | 値 |
| --- | --- |
| 周回 4 の開始 | 2026-11-02 13:04:20 |
| 止める指示のファイルの中身（置いた時刻） | 2026-11-02 13:08:53 |
| 周回 4 を締めた時刻（`user_stop` の止まりの時刻） | 2026-11-04 06:01:43 |
| 周回 4 の秒（計画の行の秒の和） | 0 |
| 消費の hours（周回 4 の前 → 後） | 6.19 → 47.14 |

周回 4 の区間（開始から締めるまで、約 40.95 時間）がそのまま経過時間に入った。止める指示の時刻から締めた時刻までの約 40.88 時間は、止まりの記録（`stops`）のどの行にも重ならないため引かれなかった（`user_stop` の行は締めた時刻 06:01:43 に始まり 06:02:11 に解けている）。

## 前提

- 前提 1: 止まっていた区間の始まりは、止める指示のファイルに書かれた時刻（`loop stop` を打った時刻）とする。止める指示を置いた後もセッションが周回を進めていた場合、その時間も経過時間から外れる。セッションがいつ止まったかを記録する仕組みが今は無く、止める指示の時刻が手に入る最も近い値であるため、この扱いを採る
- 前提 2: 止める指示のファイルの中身が時刻として読めない（空・壊れている）ときは、ファイルの更新時刻を区間の始まりとする
- 前提 3: 止まっていた区間の終わりは、`loop start` で再開した時刻とする
- 前提 4: 周回の途中でない（進行中の周回が無い）ときに `loop start` が止める指示を見つけた場合も、止める指示を解く。`loop start` を打つこと自体が、利用者が再開を求めた印であるため。この場合、止まっていた区間は周回の区間の外にあるため、経過時間は変わらない
- 前提 5: 既に止まっている記録（`status` が `stopped`）の再開は、今の再開の表のとおりに動く。この課題では変えない

## 対象範囲

含む:
- `loop start` が、止まっていない記録（進行中の周回がある・無いの両方）で止める指示を見つけたときに、止める指示を解く振る舞い
- 周回の途中で止める指示を置いてから再開するまでの区間を、止まりの記録へ残し、ループの予算の経過時間から外すこと
- 確定仕様 `docs/specifications/ndf-workflow-development-loop.md` の、再開の表と不変条件 I3・I8 の記述を振る舞いに合わせること

含まない:
- 既存のループの記録（lfactory2 など）の値を直すこと。lfactory2 は `mvv_changed` で止まっており再開しない
- 周回の秒（計画の行の秒の和）の数え方。止めていた時間は入っていない（起票者の推定 S4）
- 止める指示が周回の途中で効く（周回の途中で止まる）ようにすること。止める指示は今のとおり次の周回の境で効く
- 境の判定の順（`user_stop` を `mvv_changed` より先に見ること）を変えること。止める指示が再開で解ければ、次の境で `mvv_changed` が出る
- セッションが止まった時刻を記録する仕組み（前提 1）

## 用語

| 用語 | 意味 |
| --- | --- |
| 開発ループ | スプリントを 1 つ終えるたびに次のスプリントを選んで続けて始める進め方（用語集） |
| 周回 | 開発ループの 1 回分（用語集） |
| ループの予算 | 開発ループが使ってよい量の上限。周回の数・費用・経過時間で数える（用語集）。この文書の「経過時間」は、確定仕様の I8 の「動いていた時間」（終わった周回の区間の和から、止まりの記録と重なる部分を引いたもの。結果の `consumed.hours`）を指す |
| 止まる条件 | 開発ループを止める、機械で判定できる条件（用語集）。止める指示は `user_stop` に当たる |
| ループの記録 | `.ndf/loop/<名>/loop.json`（用語集）。止まりの記録は、その中の解けた止まりの一覧（`stops`）を指す |

## 受け入れ条件

- [ ] 1. 前提: 進行中の周回があり、止める指示のファイルがある。操作: `loop start <名>`。結果: 終了コード 0、`status` が `in_lap`、止める指示のファイルが消えている、結果に止める指示を解いたことが出る
- [ ] 2. 前提: 1 の再開の後。操作: その周回を `loop lap <名>`（`--failed` の有無を問わない）で締める。結果: 境の判定で `user_stop` に当たらない。ほかの止まる条件（`mvv_changed` など）に当たればそれで止まり、当たらなければ次の周回へ進む
- [ ] 3. 前提: 進行中の周回が無く、止まっていない記録に止める指示のファイルがある。操作: `loop start <名>`。結果: 終了コード 0、`status` が `resumed`、止める指示のファイルが消えている。続く `loop select` が `user_stop` で止まらない
- [ ] 4. 前提: 周回を始めた時刻 T0、止める指示を置いた時刻 T1、再開した時刻 T2、周回を締めた時刻 T3（T0 < T1 < T2 < T3）。結果: 締めた後の経過時間（`consumed.hours`）の、この周回の分が (T1 − T0) + (T3 − T2) になる。T2 − T1 は入らない
- [ ] 5. 4 の止まっていた区間（T1〜T2）が、ループの記録の止まりの記録に、周回の番号・始まり T1・終わり T2 つきで 1 行残る。`laps.md` の周回の行の止まりの欄に `user_stop` が出る
- [ ] 6. 止める指示のファイルの中身が時刻として読めないとき、1 と 4 の振る舞いは、ファイルの更新時刻を T1 として成り立つ
- [ ] 7. 止める指示のファイルが無いときの `loop start` の結果（`in_lap` / `resumed`）と、ループの記録の中身は変わらない
- [ ] 8. 既に止まっている記録（`stopped`）の再開は、止まった理由ごとに今と同じ結果になる。既存のテスト（`plugins/ndf/scripts/tests/test_sprint_loop.py`）が通る
- [ ] 9. 確定仕様 `docs/specifications/ndf-workflow-development-loop.md` の再開の表と I3・I8 が、受け入れ条件 1〜5 の振る舞いを書いている
