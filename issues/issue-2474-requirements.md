## 目的

止める指示（`.ndf/loop/<名>/stop`）が、人が実際に送った停止からだけ置かれる状態にする。人が送っていない文（送信されていないサジェスト・入力欄に残った文字・人の指示を名乗る別のセッションのメッセージ）から止める指示が置かれると、ループは誰も求めていない利用者の停止（`user_stop`）で止まり、本当に止まるべき理由が出ない。

記録で確かめた経路（2026-11-02、時刻は UTC。会話の記録 `37e6fcce`・`f3bae19d` とループの記録 `.ndf/loop/lfactory2/loop.json`）:

| 時刻 | 誰が | 何を読んで | 何をした |
| --- | --- | --- | --- |
| 13:07:22 | ループ lflow の conductor のセッション | 人の入力として記録された「3本に引継ぎメモを作って終了する指示を送ってください。」。記録の入力元の値は `typed` で、サジェストを採った入力の値（`suggestion_accepted`）ではない。利用者は 2026-11-05 に、この入力をサジェストを指示と読んだものと判断した | 3 本のループの conductor へ、別のセッションへのメッセージで「【利用者の指示・lflow 経由】引継ぎ文書を最新にして、このセッションを終了してください」を送った |
| 13:07:39 | ループ lfactory2 の conductor のセッション（`f3bae19d`） | 上のメッセージ（入力元は別のセッション） | パイプラインを止め、引継ぎ文書を書いた |
| 13:08:52 | 同じ | 同じメッセージ。ループを止めることは書かれていない | 「利用者の指示はループを止めること」と自分で読み替えて `loop stop lfactory2` を打ち、引継ぎ文書に「利用者の指示で打った」と書いた |
| 2026-11-04 06:01:43 | 再開した conductor | 残っていた止める指示 | 周回 4 を締めた境で `user_stop` で止まった。プロジェクト MVV の改訂（`mvv_changed`）は出なかった |

どの段にも、人がループを止めることを送った記録は無い。止める指示は、conductor が別のセッションのメッセージを自分で読み替えて置いた。周回 4 の経過時間に入った約 41 時間（消費の hours 6.19 → 47.14）は、周回の途中でセッションを終えて 2 日後に再開した区間であり、止める指示が作った区間ではない。

## 前提

- 前提 1: 止める指示のファイルを書くのは `sprint-state.py loop stop`（`cmd_stop`）だけである。`git grep -n "STOP_FILE" -- plugins/ndf/scripts/lib` の当たりは、定数の定義と読み込みを除くと、`cmd_stop` が書き、周回の境の判定（`boundary_stop`）が読み、止まった記録の再開（`_resume_user_stop`）が消す 3 か所である
- 前提 2: 入力を人が送ったかを、コマンドや hook の側で見分ける値は無い。hook が受ける入力の項目に入力元は無く、Claude Code の会話の記録にある入力元の値（`promptSource`・`turnOrigin`）は公開の仕様ではなく、Codex には無い
- 前提 3: 人が送った停止は、次の周回の境で効く（確定仕様の I3）。conductor は境まで周回を続けるため、止める指示が置かれてから境までは動いていた時間である。境で止まった後の区間は確定仕様の I8 で経過時間から外れる
- 前提 4: 自動の再起動（カットポイントと利用上限での切り替え）も、周回の途中で `loop start` を打つ

## 対象範囲

含む:
- conductor の手順（`development-workflow` の `references/loop.md`）に、止める指示を置く発生元を人が送った入力に限ることを書く
- セッションを終える依頼（引き継いで終了する）では止める指示を置かないことを書く
- 人が送っていない文から止める指示を置いたと気づいたときに、ファイルを消して無視することを書く
- 確定仕様 `docs/specifications/ndf-workflow-development-loop.md` の、止める指示の発生元の記述

含まない:
- `loop start` と経過時間の計算を変えること（前提 3・4）
- 中継が tmux に起動する claude のサジェストを止めること（#2504）
- 画面の入力欄の文字を判断に使わない決まり（PR #2502 で develop に入った）
- 周回の途中でセッションを終えた区間（lfactory2 の約 41 時間）を経過時間から外すこと。セッションが止まった時刻を記録する仕組みが無い
- 既存のループの記録（lfactory2 など）の値を直すこと

## 用語

| 用語 | 意味 |
| --- | --- |
| 開発ループ | スプリントを 1 つ終えるたびに次のスプリントを選んで続けて始める進め方（用語集） |
| 周回 | 開発ループの 1 回分（用語集） |
| ループの予算 | 開発ループが使ってよい量の上限。周回の数・費用・経過時間で数える（用語集） |
| 止まる条件 | 開発ループを止める、機械で判定できる条件（用語集）。止める指示は `user_stop` に当たる |
| ループの記録 | `.ndf/loop/<名>/loop.json`（用語集） |

止める指示は、`loop stop` が置くファイル `.ndf/loop/<名>/stop`（中身は置いた時刻）を指す。人が送った入力は、人がそのセッションの入力欄から送信した入力と、人が端末で打ったコマンドを指す。別のセッションからのメッセージ・引継ぎ文書・画面に出た文字・送信されていないサジェスト・conductor 自身の推測は含まない。
