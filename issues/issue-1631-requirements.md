## 目的

- テストを足すスプリントで、全体テストの所要が `.ndf/project.json` の `test_duration` の記録より長くなっても、後のフェーズの全体テストと範囲テストが上限で止まらないようにする
- 利用者か conductor が `test_duration` を手で直してプランを作り直す手当てを要らなくする（Value 2・Value 4）
- 記録が実測に近いときの上限は今と同じに保ち、ハングしたテストを見つけるまでの時間を延ばさない

## 前提

- 前提 1: 対象は予算を持たない呼び出し（`limits` の `budget_minutes is None` の枝。supervise.py のプランと `test-run.py`）だけである。cross-refactoring のように予算（`--budget-minutes`）を持つ呼び出しの上限の決め方は変えない
- 前提 2: 実測は「同じリポジトリで先に走った全体テストの壁時計の秒」とする。範囲テストの秒は全体テストの実測として使わない（範囲が変わると所要が変わる）
- 前提 3: 絶対値の下限を足すかは設計が決める。足す場合も受け入れ条件 6 の値を超えない。下限だけで直す形（実測を使わない）は採らない。テストの所要が下限の 1/3 を超えて伸びると同じ時間切れが再び起きるため（Value 6）
- 前提 4: 実測の置き場（ファイルの場所と形）は設計が決める。`.ndf/project.json` などの利用者の設定は書き換えない（C7）。`.ndf/tmp/` か状態ディレクトリなど、設定でない置き場に置く
- 前提 5: 実測が記録より短いときは、上限を記録の 3 倍より小さくしない（記録より速くなったことを理由に上限を詰めない）
- 前提 6: 宣言の `test_duration` が無いか不明のとき（`unknown_duration`）の上限（`test_timeout` 900 秒・`whole_timeout` 1800 秒）は、実測があっても小さくしない。実測で詰めるかは扱わない

## 対象範囲

含む:
- 予算なしの上限（`init_test_timeout`・`test_timeout`・`whole_timeout`）を、記録に加えて先に走った全体テストの実測から決めること
- 全体テストを走らせたときに、その秒を後のプランと `test-run.py` が読める形で残すこと
- プランのステップの `timeout`（`with_margin(上限)`）と、`test-run.py` が実行の時点で決める上限を食い違わせないこと
- プランの「テストの時間」の `basis` に、上限を決めた実測とその出所が出ること

含まない:
- `.ndf/project.json` の `test_duration` を自動で書き換えること（C7。記録を直すのは今どおり `/ndf:development-workflow` の手順 0 の解析）
- 予算を持つ呼び出し（cross-refactoring の `init_test_timeout` など）の上限の決め方
- CI の待ちの上限（`ci_wait_timeout`）の決め方
- `with_margin` の式（10%・最低 30 秒）と `TEST_FACTOR`（3.0）の値
- 実装の上限（`impl_timeout_estimate`）の決め方

## 用語

| 用語 | 意味 |
| --- | --- |
| 所要の記録 | `.ndf/project.json` の `test_duration.measured` の値（`w`。出所は `ndf-record` → `ci-junit` → `ci-steps`） |
| 全体テストの実測 | 先に走った全体テストの壁時計の秒。この変更で残すもの |
| テストの上限 | `limits` が返す `init_test_timeout`・`test_timeout`・`whole_timeout`（秒）。ステップの `timeout` はこれに `with_margin` の余裕を足した値 |

本文の「記録」は所要の記録を、「実測」は全体テストの実測を、「上限」はテストの上限を指す。

- [ ] 3. `test-run.py whole` / `scope` が実行の時点で使う上限は、そのステップの `timeout` 以下になる（ステップの `timeout` が `test-run.py` の上限より先に打ち切らない）。プランを作った後に残った実測で上限が広がる場合も同じ
- [ ] 4. プランの「テストの時間」の `basis` に、上限を決めた実測の秒と出所（記録だけで決めたときはその旨）が出る
- [ ] 5. 実測が無いときと、直近の実測が記録以下のときの上限は、今の `limits` と同じ値になる（例: 記録 2.7 秒・実測 2.5 秒なら `whole_timeout` は 9 秒のまま。下限を足した場合は受け入れ条件 6 の値）。実測が記録より大きいときは受け入れ条件 2 に従う（2026-10-30 の承認ゲート 1 で、条件 2 と食い違う「記録の 3 倍以下」から直した）
- [ ] 6. 絶対値の下限を足す場合、その値は 60 秒以下で、記録の 3 倍が下限を超えるときは記録の 3 倍がそのまま上限になる
- [ ] 7. ステップの `timeout` は今どおり `with_margin(上限)` で、上限を広げた分に別の余裕を重ねない（上限にも余裕の係数・定数を足さない）
- [ ] 8. 実測を残せないとき（置き場が書けない・壊れている）も、全体テストの合否と終了コードは今と同じで、上限は記録だけで決まる
- [ ] 9. 予算を持つ呼び出し（`budget_minutes` を渡す `limits`）の返す値が変わらない（既存のテストが通る）
