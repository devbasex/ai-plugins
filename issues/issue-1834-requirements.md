## 目的

- 承認ゲート 2 で差し戻して同じ版の開発版を出し直しても、承認資料の手で足した節（未検証・残る危険の中身・指示書の変更など）が消えず、CHANGELOG と承認資料に置き換えられた古い箇条が戻らない状態にする
- conductor の 2 つの手当て（承認資料の控えからの書き戻し・マージ済みの PR の本文の手直し）を要らなくする（Value 4）

## 前提

- 前提 1: 「承認資料」は配布のプランの `facts` ステップが `presentation_to` で写す `issues/approval-<plugin>-v<版>.md` を指す。今は `approval-facts` が承認資料を丸ごと書き出し、写しがそのファイルを上書きするため、手で足した節が消える（`release-steps.py` の `cmd_approval_facts`・`lib/step_result.py` の `approval_present`・`supervise_lib/engine.py` の `presentation_to`）
- 前提 2: 「生成する節」は、配布のステップ（`approval-facts`・`notes --approval`・`changed-plugins --approval`）が書く次の節とする: `1. 対象を開くためのもの`・`2. 承認の判断に使うもの`・`未検証・残る危険`・`指示書の変更`（この課題で足す）・`移行の手順`・`版を上げる他のプラグイン`・`同意を求めること`・`戻し方`。これ以外の `## ` の見出しの節を「手で足した節」とする。生成する節の中の手の書き換え（表のセルなど）は作り直しで生成の値に戻ってよい。ただし `未検証・残る危険` は今の `notes` と同じく、既にある中身を差し替えない（中身を集める仕組みは #1488 が持つ）
- 前提 3: 「指示書」は `.ndf/instructions.json` の `files` に並ぶファイルとする（ai-plugins では `AGENTS.md`・`CLAUDE.md`・`KIRO.md`）。設定が無いリポジトリでは `AGENTS.md` と `CLAUDE.md` のうち在るものとする（Value 5。ai-plugins の形を既定に埋め込まない）
- 前提 4: 「指示書の変更」の範囲は、承認資料の「含む PR」と同じ範囲（前のタグから承認するコミットまで）とする
- 前提 5: 後の PR が前の PR の箇条を置き換えることは、**後の PR の本文**で表す（マージ済みの前の PR の本文には触れない）。本文の中の書き方（節の名前・書式）は設計で決める
- 前提 6: CHANGELOG の版の節は今どおり `notes` が PR の本文の「利用者向けの変化」から作り直す（手で直した CHANGELOG の行を残す仕組みは作らない）。古い箇条を載せないのは前提 5 の置き換えで行う

## 対象範囲

含む:
- `approval-facts` が承認資料を書き直すとき、既にある承認資料の手で足した節を残す
- `approval-facts`（または承認資料を書く配布のステップ）が「指示書の変更」の節を生成する
- 後の PR の本文で置き換えを表した前の PR の箇条を、`notes` が CHANGELOG の版の節と承認資料の「配る中身」から除く
- 置き換えの書き方を PR の本文の書き方の案内（`release` の参照）へ書く

含まない:
- 「未検証・残る危険」の中身を集める仕組み（#1488）
- 実装の PR とスプリント PR に同じ箇条が並ぶ重複（#1637。やらないと判断済み）
- 手で直した CHANGELOG の行そのものを作り直しの後も残す仕組み（前提 6）
- 生成する節の中の手の書き換えを残す仕組み（前提 2）
- conductor のプランの外の手当て全般（#1426）
- 既に出した版（10.17.66 ほか）の CHANGELOG・承認資料の書き直し

## 受け入れ条件

- [ ] 1. 承認資料に手で足した節（例: `## 補足`）がある状態で、同じ版の `approval-facts` を 2 回続けて走らせると、2 回目の後の承認資料にその節の見出しと中身がそのまま残る
- [ ] 2. 手で足した節は、作り直しの前と同じ相対の位置（直前にあった生成する節の後）に置かれる。直前の生成する節が無くなったときは `## 同意を求めること` の前に置かれる
- [ ] 3. 承認資料が無い状態で `approval-facts` を走らせると、今と同じ節の構成（と「指示書の変更」）で承認資料が作られる（退行しない）
- [ ] 4. 前の PR の箇条を後の PR の本文で置き換えると表した版で `notes` を走らせると、CHANGELOG の版の節と承認資料の「配る中身」に前の PR の箇条が並ばず、後の PR の箇条が並ぶ
- [ ] 5. 受け入れ条件 4 は、前の PR の本文を変えずに成り立つ（`gh pr edit` を前の PR に打たない）
- [ ] 6. 前のタグから承認するコミットまでに指示書のどれかが変わった版で `approval-facts` を走らせると、承認資料に `## 指示書の変更` の節が生成され、変わったファイル・その変更のコミット（短い SHA と PR 番号）・差分を見るコマンド（`git diff <前のタグ> <承認するコミット> -- <ファイル>`）が並ぶ
- [ ] 7. 指示書が変わっていない版では、`## 指示書の変更` の節は「- 無し」と書かれる
- [ ] 8. `.ndf/instructions.json` が無いリポジトリでは、`AGENTS.md` と `CLAUDE.md` の差分だけを指示書の変更として扱う
- [ ] 9. 置き換えの指す箇条が見つからないとき、`notes` は箇条を除かずに終わり、結果 JSON の items に見つからなかった置き換えが載る
- [ ] 10. 置き換えを書かない PR だけの版では、`notes`・`changelog` の出力（CHANGELOG の版の節・承認資料の欄）が今と同じになる（退行しない）

## 非機能の条件

| 大項目 | 条件 |

| 移行性 | 既にある承認資料（置き換えの節・指示書の変更の節を持たないもの）を、そのまま作り直しに渡せる |
