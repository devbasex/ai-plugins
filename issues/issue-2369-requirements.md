## 目的

- 呼ばれない関数とエントリポイントを NDF のスクリプトから消し、柱 P1〜P8（マイルストーン 29・30）が実行の核へ移す対象を、実際に使われるものだけにする

## 前提

- 前提 1: エントリポイントの呼び手は、#2336 で入れた構造チェック（`python3 scripts/check-ndf-contracts.py`）が `callers` / `external` で既に確かめている（2026-11-04 の実行で `violations: 0`、エントリポイント 79 本、`external` を持つ項目 1 件）。この課題は、構造チェックが違反 0 を返し続けることで受け入れ条件 1 のエントリポイントの部分を満たす
- 前提 2: 「最上位の関数」は、`plugins/ndf/scripts` と `plugins/ndf/skills/*/scripts` の下の `.py` のうち、テスト（`tests/`）と実験版（`experimental/`）を除くファイルで、モジュールの最上位に定義された関数とクラスのメソッドを指す。棚卸しは `uvx vulture <対象> --exclude '*/tests/*,*/experimental/*' --min-confidence 60` で行う（確定仕様の「呼び手の無いもの」）。2026-11-04 の試行で `unused function` は 51 件（例: `plugins/ndf/scripts/lib/md.py:81` の `fences`）。数は参考値で、受け入れ条件は棚卸しのコマンドの結果で判定する
- 前提 3: 呼び手はテストを除いて数える（確定仕様の「呼び手の無いもの」と同じ）。テストだけが呼ぶ関数は呼び手 0 とし、消すときはその関数だけを確かめるテストも消す。残す関数は、理由を 1 行ずつ持つ vulture の残す関数の一覧（`--make-whitelist` の形）に載せる。置き場は設計が決める
- 前提 4: vulture が拾わない呼ばれ方（`getattr`・副命令の辞書引き・hook の JSON からの文字列の指定・別のプラグインからの import）は、候補ごとに名前でリポジトリを検索して確かめ、呼び手が見つかった候補は残す関数の一覧へ理由つきで載せる
- 前提 5: 子の課題の「再現の手順」は、各課題の本文にある手順を使う。本文に手順が無い課題は、本文の現象を起こすコマンドを起こしてから通す。起こせない課題は、理由を添えて残す
- 前提 6: 判断待ちの課題（#1512・#1968）は、再現の手順を通した結果だけを書き、判断を待つ理由で残す。この課題で判断を代わりに下さない
- 前提 7: 既に閉じている子の課題（#1709。2026-11-04 に閉じ、コメント 0 件）も判定の行を書き、閉じた理由のコメントが無ければ足す。判定で再現した課題は開き直す
- 前提 8: 「全体テストが変更の前と同じく通る」の変更の前は、作業の起点の develop の CI のジョブ `Python tests` の結果を指す（2026-11-04 14:21 UTC の develop 62553bdf4 で success）
