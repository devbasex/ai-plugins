## 何が起きたか

11.0.0 の作り直し（#1142）で、NDF の事実と方針は契約のファイル（`plugins/ndf/contracts/` の上限の設定 `limits.json`・止まった理由の表 `causes.json`・事実の表 `facts/`・`domains/`）に置くと決めた。11.0 を出した後の設計（#3388）の振り返りで、その契約の表と、表を守る検査に欠けが残ったまま配られていると分かった（[11.x の対応表](https://github.com/devbasex/ai-plugins/blob/main/issues/issue-3388-design-routing.md) の 3367-6・3367-9・3382-8・3395-2・3395-4 と、要求 306・324・325・326・332・333）。

2026-11-23 に 11 系のコード（`plugins/ndf/`）で確かめたところ、6 行のうち 2 行（3367-9・3382-8）は既に直っており、残る欠けは次の 3 つだった。

- 上限の設定に、どのコードからも引かれない方針が残る（実例: `supervise.worker-step`。`plugins/ndf/src` に読み手が 1 つも無く、worker のステップの上限は実際には効いていない）
- AI が陥りやすい作りの 7 種類のうち、6 番目（コピーで生まれた重複。2 つ以上のファイルの同じ名前の関数と、4 つ以上のファイルに出る 8〜80 字の文字列）だけ検査が無い
- 結果 JSON の `items` の要素が「オブジェクトであること」しか定めておらず、観点・分類・重さ・受け入れ条件の欄が無い

## 種類

機能追加（契約の表と検査はあるが、「引かれない方針を落とす」「コピーの重複を数える」の決まりは今の SSOT に無い）

## 何を足すか・変えるか

| | 今 | 足した後 |
| --- | --- | --- |
| 上限の設定の方針 | 引かれない方針が残り、見分ける手段が無い | 方針が読み手を指定し、検査が指定と実際の読み手の食い違いを落とす |
| コピーで生まれた重複（7 種類の 6 番目） | 検査が無い | 規則があり、前の数を基準にしたラチェットが数を増やした PR を落とす |
| 要求 332 の一覧の箇所 | 1 か所へ移したか理由が残らない | 箇所ごとに移したか理由が残る |
| 3395-2 の 1〜3 巡目の項目 | 行き先が無い項目がある | 行き先が表から生成され、行き先の無い項目が 0 件になる |
| 結果 JSON の `items` | 要素はオブジェクトとだけ定める | `lens`・`category`・`severity`・`acceptance` を任意の欄として持つ（#3685 が使う） |

## なぜ困るか

- 引かれない方針は、読む人に「この上限が効いている」と誤って思わせる。実例の `supervise.worker-step`（1,800 秒）は読み手が無く、worker の上限は実際には `plugins/ndf/src/ndf/core/worker.py:79` の `WORK_TIMEOUT`（3,600 秒）が決めている。上限を変えようとした人が効かない値を直す
- コピーで生まれた重複を数えていないので、AI が自動で開発を続けると同じ名前の関数と同じ文字列が増え続け、減らす機会が来ない（MVV の Value 10・11）
- `items` の欄が定まっていないと、観点ごとのレビュー（#3685）が結果 JSON から観点と重さを読めない

## 目的

- 上限の設定が「読み手のある方針だけ」を持ち、AI が陥りやすい作りの 7 種類すべてを CI が数え、数を増やした PR が落ちる状態にする

## 対象範囲

含む:
- 上限の設定の方針に読み手を指定させ、指定と実際の読み手の食い違いを落とす検査（3367-6・要求 332）
- 引かれない方針の始末（読み手を足すか、消すか。実例の `supervise.worker-step`（1,800 秒）は読み手が無いので消す。worker 全体の上限は #3667 が `WORK_TIMEOUT` を新しい方針 `supervise.worker-run`（3,600 秒）へ移して持つ）と、旧い名前の改名
- AI が陥りやすい作りの 6 番目（コピーで生まれた重複）の規則（要求 306・324 の欠け）
- 0 件にできない規則のための、前の数を基準にしたラチェット（要求 325 のラチェットの分）
- 1〜3 巡目の項目の行き先を表から生成する規則の残り（3395-2）
- 結果 JSON のスキーマの `items` の任意の欄 `lens`・`category`・`severity`・`acceptance`

含まない:
- `const-fact` の照合の範囲を広げること（スキーマの `enum`・上限の設定の値・辞書の値）は #3667 が持つ。要求 333 はその拡張が満たす
- 内部データの型と版、名前の対応表は #2339 が持つ
- 入れ替えの後の測り直し（要求 325 の測り直しの分・要求 298）は #3412 が持つ
- `items` の新しい欄を使う側（#3685）
- 既に直っている 2 行（3367-9 の契約の読み手の検証・3382-8 の説明の生成）の作り直し。退行しないことだけを受け入れ条件 2・3 で縛る
- 兆候の 1〜5・7 番目を 0 件から緩めること（ラチェットを当てるのは新しく足す 6 番目だけ）

## 前提

- 前提 1: 3395-4（マージ済みの ndf-next が要求の構造の条件を破る）は、11.0.0 の入れ替えで構造の規則（`lines`・`layer`・`cycle`）が `plugins/ndf/` に当たるようになり、`ndf check` が違反 0 件で通る状態で解消している。受け入れ条件 8 がこの状態を保つ

## 受け入れ条件

- [ ] 1. 上限の設定の方針が読み手を指定し、指定と実際の読み手が食い違う方針（指定した読み手が引いていない・指定の無い方針を引いている）を 1 つ作ると、`ndf check` がその方針の名前を挙げて落ちる
- [ ] 2. 契約の読み手は、同じ契約を 1 プロセスで 3 回読んでも検証の関数を 1 回だけ呼ぶ（テストで呼び出しの回数を数える。今の振る舞いを縛って退行を止める）
- [ ] 3. `plugins/ndf/docs/contracts/` の生成物を 1 文字でも手で直すと `ndf check` が落ちる（今の振る舞いを縛って退行を止める）
- [ ] 4. AI が陥りやすい作りの 7 種類すべてに検査の規則があり、6 番目（コピーで生まれた重複）を 1 件足した PR はラチェットの基準の数を超えて落ち、減らした PR は基準の数が下がって通る
- [ ] 5. 結果 JSON のスキーマの `items` が `lens`・`category`・`severity`・`acceptance` を任意の欄として持ち、欄を持たない今の結果 JSON もそのまま検証を通る。欄に知らない値を入れた結果 JSON は検証を通らない
- [ ] 6. 上限の設定から引かれない方針が 0 件になる。方針ごとに、読み手を足したか消したかが実装の PR の本文に残る
- [ ] 7. 1〜3 巡目の項目（3395-2）の行き先が表から生成され、行き先の無い項目が 0 件になる
- [ ] 8. 変えた後に `ndf check` が `plugins/ndf/` で違反 0 件（6 番目のラチェットの基準の数を超えない）
