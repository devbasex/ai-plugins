### 決定 18: 写しと alias を Claude Code の設定の親の下（`${CLAUDE_CONFIG_DIR:-~/.claude}/ndf/`）に置く

**devbase で永続化されているのは、各 AI CLI の設定の親だけである。** 2026-09-23 に devbase の
コンテナで確かめた。`~/.claude`・`~/.claude.json`・`~/.gemini` は `/persistent/group` へ、`~/.codex`・
`~/.kiro`・`~/.serena`・`~/.ssh` は `/persistent/ai` へ symlink され、この 2 つが名前付きボリュームの
mount である（`findmnt`）。今の置き場所 `~/.local/share` と、`~/.local/state`・`~/.bashrc`・`~/.zshrc` は
コンテナの層の中の普通のファイルで、作り直しで消える。

| 置き場所 | 採否 | 理由 |
| --- | --- | --- |
| `${CLAUDE_CONFIG_DIR:-~/.claude}/ndf/`（写し `relay.py`・中継の rc `shellrc`） | 採る | devbase で永続化される。中継は Claude Code だけのものなので、Claude Code の設定の親に置くのが自然である。`statusline` の `~/.claude/ndf-statusline.sh` と同じ親 |
| `~/.local/share/ndf/relay.py`（今のまま） | 採らない | devbase のコンテナの作り直しで消え、alias が指す先が無くなる |
| `/persistent/...` を直接指す | 採らない | devbase の内部の配置に依る。devbase 以外の環境に無い |

**`claude` の定義は中継の rc に書き、シェルの設定には中継の rc を読む 1 行だけを置く**（利用者の判断。
2026-09-23）。定義の形が変わっても、書き換えるのは ndf が持つ中継の rc だけで済む。**定義は alias ではなく
関数にし、呼んだ時点で写しが無ければ素の `claude` を起こす。** alias の形は写しの有無をシェルの起動時に
しか見ないため、別のコンテナの `uninstall` が写しを消すと、開いたままのシェルの `claude` が失敗する
（レビューの指摘）。読み込みの行も、中継の rc が無ければ何もしない。関数にすると 10.17.4 の囲みと
形が変わるが、定義は ndf だけが持つ中継の rc にあるので、囲みの形とは関わらない。

**パスは `install` の時点で決め、`${CLAUDE_CONFIG_DIR:-...}` を残さない。** 残すと、隔離した
`CLAUDE_CONFIG_DIR` で `claude` を打ったときに写しを見失う。

**10.17.4 の旧い写しは動かさない。** 10.17.4 の囲みの alias は旧い写しを指しており、hook が写しを
移すと alias が壊れる。hook は旧い写しを在る場所で置き直すだけにし、囲みの中を読み込みの行へ
置き換えるのは明示の `install`（E5）だけにする（決定 4 の「黙った書き換えをしない」を保つ）。

**状態の親（`~/.local/state/ndf/relay/`）は動かさない。** 記録（`rc-added` など）はこのコンテナの
`~/.bashrc` のパスを持つ。共有される親へ置くと、別のコンテナの記録がこのコンテナの判定を変える。
シェルの設定と同じく作り直しで消える場所に置けば、記録とシェルの設定が同時に消え、食い違わない。

### 決定 19: devbase では、devbase が読み込む永続化の場所へ読み込みの 1 行を置く。読み込みは devbase に依頼する（devbasex/devbase#253）

**利用者の判断（2026-09-23）で、alias を永続化される rc ファイルへ書き、devbase がそれを読み込む形に
決めた。** devbase の `~/.bashrc` と `~/.zshrc` はイメージの層にあり、作り直しで Dockerfile の中身へ
戻る。ndf の側だけでは、作り直しで消えない読み込みを置けない。

**devbase に依頼する読み込みは汎用にする。** 依頼したのは「`~/.shellrc.d/`（`/persistent/group` へ張る）の
`*.sh` を `~/.bashrc` と `~/.zshrc` が読み、そのパスを `DEVBASE_SHELLRC_DIR` で示す」である。ndf はそこへ
`ndf-relay.sh`（中継の rc を読む 1 行）を置く。

| 読み込みの形 | 採否 | 理由 |
| --- | --- | --- |
| 汎用のディレクトリの `*.sh` を読む。ndf はそこへ 1 ファイルを置く | 採る | devbase は 4 つの AI CLI と利用者自身の設定を載せる。ndf のパスを devbase に書かないので、ndf の置き場所が変わっても devbase を直さない。ほかのツールも同じ場所を使える |
| devbase が `~/.claude/ndf/shellrc` を直に読む | 採らない | devbase が ndf の内部のパスに依る |
| 汎用の rc ファイルを 1 つだけ読む | 採らない | 複数のツールが同じファイルを書き換え合う。ndf は自分のファイルだけを置いて消したい |

**読み込み先は環境変数 `DEVBASE_SHELLRC_DIR` で見つける。** 変数があり在るディレクトリを指せば、
`install` はそこへ置き、`~/.bashrc` を書かない。rc ではなくコンテナの環境に置くよう依頼したのは、
Claude Code の中の Bash（対話シェルでない）からも見えるためである。**名前は依頼の中の案で、devbase が
別の名前を選べば実装の持ち場が合わせる。**

**devbase 以外の環境（変数が無い）では、`install` が `~/.bashrc` か `.zshrc` へ読み込みの 1 行の囲みを
足す。** 案内だけにしない。`/ndf:install-wrapper` は利用者がシェルの設定を書かせるために打つ明示の
操作で、書く前にバックアップを取り、`uninstall` で戻せる（決定 3）。#253 が入る前の devbase も同じで、
作り直しで囲みは消える。

**再導入の案内は採らない。** 「写しはあるが alias が無い」を SessionStart の hook が知らせる案である。

| 扱い | 採否 | 理由 |
| --- | --- | --- |
| 永続化される場所へ読み込みを置く（devbase に依頼） | 採る | 利用者の判断。作り直しの後も打ち直さずに中継が残る |
| 作り直しのたびに再導入を知らせる | 採らない | 利用者の判断で不採用。作り直すたびに打ち直しを求める。`uninstall` した利用者にも、作り直しの後に知らせが出る（「外した」印が作り直しで消える。レビューの指摘） |
| hook が alias を足し直す | 採らない | この課題が無くそうとする、シェルの設定の黙った書き換えそのものである |

### 決定 20: `uninstall` は写しと中継の rc も消す

**中継の rc の関数は呼んだ時点で写しを見て、無ければ素の `claude` を起こす。読み込みの行は中継の rc が
無ければ何もしない**（決定 18）。そのため、同じ `/persistent/group` を共有する別のコンテナでは、開いた
ままのシェルでも次に開くシェルでも `claude` は失敗しない。外したコンテナの開いたままのシェルには
関数が残るので、報告に `unset -f claude` を示す。

| 扱い | 採否 | 理由 |
| --- | --- | --- |
| 写しと中継の rc も消す | 採る | 呼んだ時点で写しを見る形なので、共有する別のコンテナの `claude` を壊さない。使わない利用者の手元にファイルを残さない |
| 写しを残す | 採らない | 呼んだ時点で写しを見る形では残す理由が無い。残すと `startup` が使われない写しを置き直し続ける |

**devbase では、`install` と `uninstall` の効果が同じアカウントグループの全コンテナに及ぶ。** 写し・
中継の rc・読み込み先のファイルがどれも `/persistent/group` にあるためである。`uninstall` の報告に
そのことを示す。

### 決定 21: 共有される写しは、古い版のプラグインから置き直さない

**写しの親はコンテナの間で共有される。** 版の違うプラグインを使うコンテナが順に起動すると、
「中身が違えば置き直す」だけでは、古い版のコンテナが写しを古い中身へ戻す。戻った写しは、守り
（G1〜G3）を持たない中継を別のコンテナの `claude` にも起こさせる（レビューの指摘）。

| 扱い | 採否 | 理由 |
| --- | --- | --- |
| 写しの横に版（`relay.version`）を書き、新しい版の写しは古い版の hook が置き直さない | 採る | 版はプラグインの `plugin.json` が既に持つ。比べる処理は `startup` の中に閉じる |
| `relay.py` に版の定数を持たせる | 採らない | 版を持つ場所が `plugin.json` と 2 つになり、配布のたびに合わせる箇所が増える |
| 版を見ずに置き直す（今の案） | 採らない | 共有された写しが起動の順で行き来する |

**明示の `install` は版を比べずに置く。** 利用者が過去の版へ戻す（`docs/versioning-and-distribution.md`）のは、
新しい版の不具合から逃げるためである。`startup` の後退防止だけだと、中継の写しは新しい版のまま残る。
戻した利用者は `/ndf:install-wrapper` を打ち直せば写しも戻る（レビューの指摘）。この Skill を持たない
10.17.4 以前へ戻すときは、戻す前に `/ndf:install-wrapper uninstall` を打つ。戻した後なら、囲みと
`~/.claude/ndf/` を手で消す。

**旧い写しには版を持たせない。** `~/.local/share` はコンテナごとで共有されない。

### 決定 22: 2 つ目以降の区間へ、最初の区間の起動の方針の引数を引き継ぐ（#936）

**2 つ目以降の区間は、最初の区間の引数から「会話ごと・区間ごとに変わるもの」を除いた残りを
先頭に付けて `[*引き継ぐ引数, ブロックの中身]` で起動する。** devbase は
`/etc/devbase/ai-cli-aliases.sh` で `alias claude='claude --dangerously-skip-permissions'` を定義し、
alias の展開でシェルの関数 `claude` → `relay.py run --dangerously-skip-permissions` と渡る。
最初の区間には付くが、ブロックの中身だけで起動していた 2 つ目以降の区間では落ちていた。

**区切りは `claude` の CLI（commander）と同じ規則で読む。** `--help` の表で値を取らない選択肢を
集合として持ち、それ以外の `-` で始まる選択肢は次の語が `-` で始まらなければ値として取る。
可変長（`<x...>`）の選択肢は後続の `-` で始まらない語をすべて取る。`--opt=value` は 1 語、`--` の
後はすべて位置引数である。

**引き継がないのは、位置引数（最初のプロンプト）と `--` 以後、`-c`/`--continue`・`-r`/`--resume`・
`--session-id`・`--fork-session`・`--from-pr`・`--teleport`・`--cloud`・`-n`/`--name`・
`--bg`/`--background`・`--tmux`・`-w`/`--worktree` である（値ごと）。** 次の区間は `next` の塊が指す新しい会話を
始める。前の会話を指す・会話に名前を付ける・起動の形を変えるものを付けると、前の会話へ戻るか、
同じ ID を 2 度使うか、区間の起動が端末に出ない。`-w` は区間ごとに作業ツリーを作り直し、前の区間の
作業ツリーの中にもう 1 つ作る。**残りはすべて引き継ぐ。** 利用者の起動の方針
（`--dangerously-skip-permissions`・`--model`・`--permission-mode`・`--settings`・`--add-dir` など）を
表すためである。**知らない選択肢も値を取る規則のまま引き継ぐ。** 落とすより付けるほうが、devbase の
`--dangerously-skip-permissions` のような方針を失わない。起動の記録（`log.jsonl` の `start`）には、
2 つ目以降の区間で付けた引数を `carried` に残す。

| 扱い | 採否 | 理由 |
| --- | --- | --- |
| 区間ごとのものを除いて引き継ぐ | 採る | 方針はすべての区間に効き、前の会話へは戻らない |
| 全部引き継ぐ | 採らない | `--resume` や最初のプロンプトまで付き、前の会話へ戻るか同じ指示を繰り返す |
| 何も引き継がない（これまで） | 採らない | devbase の alias の `--dangerously-skip-permissions` が 2 つ目の区間で落ちる（#936） |
| 対話シェルに `alias claude` を聞いて付け直す | 採らない | 中継はシェルの外で子を起こす。対話シェルを起こすと利用者の rc が走り、alias 以外の定義や手で付けた引数は拾えない |

### 決定 1: 導入の Skill の名前を `install-wrapper` にする（関門で最終決定）

利用者の指示の `install_wrapper` はアンダースコアを含み、Skill の名前の規約に合わない。Agent Skills
仕様は `name` を「小文字英数とハイフンのみ・64 文字まで」と定める（`plugins/ndf/skills/AUTHORING.md` の
「上限値」）。`scripts/check-skill-frontmatter.py` がこれを検査する。4 ランタイムがこの仕様を土台に
するため、1 つのランタイムだけのために外すと、配布の検査が落ちる。**指示の語をそのまま残し、区切りだけを
ハイフンへ替えた `install-wrapper` が、利用者が覚えた名前から最も遠くない。**

| 名前 | 採否 | 理由 |
| --- | --- | --- |
| `install-wrapper` | 推奨 | 指示の語のまま。`/install` まで打てば候補に出る |
| `install_wrapper` | 採らない | 規約（名前はハイフンのみ）と検査に反する |
| `relay` | 採らない | 短いが、何をするかが名前から読めない。中継の文書の語（中継）を利用者は知らない |
| `relay-setup` | 次点 | 中継の語でそろう。利用者の指示の語から離れる |

### 決定 4: 10.17.4 が足した囲みは残し、1 度だけ知らせる（関門で最終決定）

**知らせずに残すことも、知らせずに消すこともしない。** 10.17.4 の利用者の中には中継を使い始めた人が
いる。新しい版の hook が消すと、それはまた利用者の設定の黙った書き換えで、この課題が無くそうとする
ものである。何もしなければ、利用者は alias が自動で足されたことを知らないまま残る。

| 扱い | 採否 | 理由 |
| --- | --- | --- |
| 残して 1 度だけ知らせる（`startup`） | 推奨 | 利用者が知って選べる。hook はシェルの設定を読むだけで、書くのは状態の親の記録と、在る写しの置き直しだけ |
| 新しい版の hook が 1 度だけ自動で外す | 採らない | 黙った書き換えをもう 1 度行う。中継を使っている利用者の `claude` の振る舞いが版の更新で変わる |
| 何もしない（リリースノートだけ） | 採らない | リリースノートを読まない利用者は知る手段が無い |

**自動の囲みは、`rc-added` に載り `rc-user` に載らないパスの囲みである。** `rc-added` は 10.17.4 の `install` が
足した先のパスを持ち、新しい版の明示の `install`・`uninstall` も足す（決定 12）。明示に触れたパスは `rc-user` にも
載るので除く。囲みを利用者が手で写した場合は `rc-added` に記録が無く、知らせない。

**知らせには入れ直しの案内も書く（#936）。** 10.17.4 の囲みの alias は、別のファイルが定義した
`alias claude`（devbase の `--dangerously-skip-permissions` など）を上書きしている。
`/ndf:install-wrapper` で入れ直せば、`install` が囲みの中を読み込みの 1 行へ置き換え、その alias が戻る。囲みを hook が勝手に書き換える動きは足さない。

### 決定 6: 送り込み（項目 3）は実測と不変条件までをこの課題で決め、実装は別の課題に分ける（関門で最終決定）

項目 1 は 10.17.4 の利用者の手元で今も働いており、早い 10.17.x で出したい（課題の本文）。送り込みの
実装は、許可の一覧・関門を越えない判定・モデルからの要求の形を持ち、項目 1・2 と独立に作って確かめられる。
同じ Pull Request に入れると、項目 1 の配布が送り込みのレビューと実機の確かめを待つ。実測の結果と
不変条件は [issue-928-design-injection.md](issue-928-design-injection.md) に残し、別の課題はそれを入力にする。
**不変条件のうち G1〜G3（関門を越えない守り）だけは、既存の `/exit` に当たるためこの課題で入れる**（決定 13）。

### 決定 13: 関門を越えない守り（G1〜G3）は、送り込みを待たずにこの課題で既存の `/exit` に入れる

実測で、質問の表示中に中継が書いた `\r` が選択肢 1 を決めると分かった（[issue-928-design-injection.md](issue-928-design-injection.md)
の「例」）。10.17.4 の切れ目の `/exit` と `\r` にも、印の後に応答が再開して質問が出る経路がある。
`/ndf:restart` はこの経路をそのまま使うので、守りが無いまま再起動を足すと、関門を越える経路を
利用者が自分で打てる形で増やすことになる。送り込みの課題へ回すと、配布済みの経路が残る。

守りは「質問の印」と「印より後の応答の行」の 2 つで作る。**画面の文言から質問を読む形は採らない。**
#895 の決定（Claude Code の版で文言が変わると読み違える）と同じ理由である。`Notification` hook は
表示から約 6 秒後に来て、2 秒で答えると来ないので、表示の始まりを知る手段にならない。`PreToolUse`
は表示と同時に来る。

### 決定 14: 切れ目の `/exit` と改行を 1 回の write にする

10.17.4 は `/exit` と `\r` を 1 秒あけて書いた。あいだに質問が出ると、`/exit` の文字は捨てられ、
`\r` が選択肢を決める。確かめ直しから書くまでの間を短くするため、1 回の write にする。実測で、
短い入力は 1 回でも間ありでも同じに働いた（`/clear`・`/compact`・`/cost`・`/status`・`/plugin`）。
`NDF_RELAY_EXIT_GAP` は使わなくなるので文書から外す。**長い入力は 1 回の write で送られないことがある**
（635 バイトは送られず、125 バイトは送られた。境界は測っていない）。`/exit` は 5 バイトで当たらない。

### 決定 15: 質問の印は `mark`（Stop）でも消す

`Esc` で質問を取り消すと `PostToolUse` が来ず、印が残る。残ったままだと中継は切り替えない（安全な
側に倒れる）が、切り替えが永久に止まる。Stop が起きたなら質問は表示されていないので、`mark` が消す。
取り消しの後は人が入力し、その応答の Stop で消える。

### 決定 2: 導入・取り外し・状態の表示を 1 つの Skill の引数で分ける

`statusline` が `status | set | restore` を 1 つの Skill で持つ前例に合わせる。導入と取り外しを別の
Skill にすると、同じ状態の親と囲みを 2 つの Skill の本文が説明し、片方だけが古くなる（AUTHORING と
既存の Skill へ統合してから新設を考える方針）。

### 決定 3: `install-wrapper` は明示指示専用にする。`restart` はモデルも起動できる

`install-wrapper` は利用者のシェルの設定を書き換える。AUTHORING の「実行前確認の要否を決める 3 つの
問い」の 1 に当たる。利用者が `/ndf:<名前>` で打つ運用なので、`statusline` と同じ明示指示専用
（`disable-model-invocation: true`）にする。これが要求の目的「シェル設定を書き換えるのを利用者の明示の
操作だけにする」を frontmatter で担保する。

`restart` は利用者の指示に「利用者（またはモデル）が呼ぶ」とある。中継の下で起きることは、conductor が
既に出している `ndf-next` のブロックと同じで、新しい権限を足さない。

### 決定 5: 写しの置き直しは SessionStart の hook で、写しが在るときだけ行う

hook から写しを置かなくなると、写しは導入した時点の版のまま止まる。**10.17.4 が置いた写しは、新しい
版の追従の処理を持たない**ので、写しの側（`run`）に追従を置いても 10.17.4 の利用者には届かない。守り
（G1〜G3）も届かない。新しい版の処理を確実に走らせられるのは、新しい版のプラグインから呼ばれる hook
である。

| 場所 | 採否 | 理由 |
| --- | --- | --- |
| SessionStart の hook（写しが在るときだけ） | 採る | 10.17.4 の写しにも届く。写しが無い利用者には何も作らず、シェルの設定も変えない |
| `run` の開始時 | 採らない | 10.17.4 の写しの `run` はこの処理を持たず、写しが永久に 10.17.4 のまま残る |
| 利用者が `/ndf:install-wrapper` を打ち直す | 採らない | 打ち直さない利用者の写しが古いまま残る。打ち直せば置き直るので、補助としては残る（E3） |

**要求の AC1 をこの決定に合わせて書き換えた**（写しが既に在るときだけ置き直しを許す）。利用者の指示は
シェルの設定の自動の書き換えをやめることで、利用者が導入した写しを今の版に保つことはそれに当たらない。
alias をプラグインのキャッシュのパスへ直接向ける案は、#895 の決定（版つきのキャッシュを指すと古い版に
固定され、古い版のディレクトリが消えると alias が壊れる）のとおり採らない。

### 決定 7: 再起動は `ndf-next` のブロックと既存の中継の経路で行う。中継に新しい副命令を足さない

`/ndf:restart` の中継の下の振る舞いは、conductor が区間の切れ目で行うことと同じ（ブロックを出して
応答を終える）である。同じ経路を使えば、`AskUserQuestion` の答え待ち・背景の処理・目標の判定・静まり・
上限・空回りの判定がすべてそのまま効く。**Skill の中の Bash から中継へ直接「今すぐ再起動」を送る形は
採らない。** 応答の途中で送ることになり、Stop を待つ判定を迂回する。子の claude が応答を終える前に
`/exit` が入る。

### 決定 8: `uninstall` は `$SHELL` に依らず bash と zsh の両方の設定を見る

10.17.4 の `install` は、起動した時点の `$SHELL` で足す先を決めた。利用者がその後にシェルを替えて
いると、今の `$SHELL` だけを見る `uninstall` は自動の囲みを見落とす。囲みの行は固有の印を持つので、
両方を見ても関係の無い行を外さない。

### 決定 9: `NDF_RELAY_AUTO` は廃止する

この変数は hook の自動の導入を止めるためにあった。hook が導入しなくなるので意味が無い。明示の
`install` に効かせると、置いたままの利用者が `/ndf:install-wrapper` を打っても何も起きず、理由が
分からない。置いたままでも害は無いので、読むのをやめて文書から外す。

### 決定 10: クラス図を作らない

`relay.py` は関数の集まりで型を定義しない。足す副命令も関数で、変える型が無い。#895 の設計と同じ
理由である。

### 決定 11: 中継の下かは `relay.py is-child` で判定する。`NDF_RELAY_DIR` の有無だけでは決めない

conductor が Bash から起こした `claude -p`（worker・外部 AI の委譲）も `NDF_RELAY_DIR` を継ぐ。その
中で `/ndf:restart` が働いてブロックを出しても、`mark` は直接の子でないとして印を書かない。
判定を `is-child` にそろえると、ブロックを出したのに切り替わらない状態が起きない。

### 決定 12: 明示の `install` は「利用者が消したら足し直さない」「案内は 1 度だけ」を持たない

10.17.4 の I5・I6 は、自動の導入が利用者の意図に反して繰り返さないための規則だった。明示の起動は
利用者の意図そのものなので、打たれるたびに同じ判定をして同じ行を出す。`rc-added` の記録があっても
足す。**足した先は `rc-added` から除かず（無ければ足し）、`rc-user` に足して自動の囲みの知らせから外す。**
`rc-added` から除くと、10.17.4 へ戻した利用者が囲みを手で消したとき、10.17.4 の hook（I5）が足し直す。
自動か明示かの区別を `rc-added` の有無に持たせず、`rc-user` に分けるのはこのためである。

### 決定 16: 中継の外の `/ndf:restart` は、シェルの 1 行ではなく貼り付ける中身を示す

再開用のコマンドは会話から作る文字列で、引用符・`$(...)`・改行を含みうる。`claude "<中身>"` の形で
示すと、利用者がシェルへ貼ったときに引用が壊れ、別のコマンドが実行されうる。起動した claude の入力欄へ
貼る中身だけを示せば、シェルを通らない。今の `ndf-next` のブロックの運用（人が中身を貼り付ける）とも
同じ形になる。中身をシェルの形へ引用し直して示す案は、Skill の中で任意の文字列を Bash へ渡す段で
同じ引用の問題が起きるため採らない。

### 決定 17: 確かめ直しと write を、質問の hook と同じロックで排他にする

確かめ直しから write までの間に質問が描かれると、G1 が破れる。質問は `PreToolUse` の hook が終わる
まで描かれないので、hook に同じロックを取らせれば、中継が書き終えるまで質問の始まりを止められる。
世代番号で後から検出する案は、書いた後に分かっても取り消せないため採らない。**中継がロックを持つ
時間は、hook が待つ 3 秒より短くする。** 超えても質問は描かれない（hook が拒否する）が、モデルが質問を
呼び直す手間が増える。そのため会話の記録を全行読む処理はロックの前に済ませ、ロックの中では
`stat` で記録が変わっていないことだけを見る。持つ時間は 1 秒と数ミリ秒で、記録の長さに依らない。**ロックが取れない hook は、印を作らず質問そのものを拒否する**（`PreToolUse` の `permissionDecision: deny`）。
印を作って質問を描かせると、ロックを持つ中継の `/exit\r` が質問に届く。拒否ならモデルが呼び直すだけで、
関門は越えない。中継が落ちれば OS がロックを放すので、拒否が起きるのは中継が 3 秒を超えて持つときだけである。
