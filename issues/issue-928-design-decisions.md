送り込みの実測と不変条件は [issue-928-design-injection.md](issue-928-design-injection.md) にある。

**関門で利用者に決めてもらう決定は 3 つある**（決定 1・4・6）。決定 5 は要求の AC1 を書き換えたので、あわせて確かめてもらう。最初の章に置き、推奨を結論に書く。
**課題の本文に無い範囲を足した決定は 13〜15 である。** 配布済みの経路で関門を越えうると、実測で

## 決定の記録

**並びは読み手の問いの順である。** 関門で決める決定（1・4・6）、範囲を足した決定（13〜15）、
そのほかの決定の順に置く。

### 決定 1: 導入の Skill の名前を `install-wrapper` にする（関門で最終決定）

利用者の指示の `install_wrapper` はアンダースコアを含み、Skill の名前の規約に合わない。Agent Skills
仕様は `name` を「小文字英数とハイフンのみ・64 文字まで」と定める（`plugins/ndf/skills/AUTHORING.md` の
「上限値」）。`scripts/check-skill-frontmatter.py` がこれを検査する。4 ランタイムがこの仕様を土台に
するため、1 つのランタイムだけのために外すと、配布の検査が落ちる。**指示の語をそのまま残し、区切りだけを
ハイフンへ替えた `install-wrapper` が、利用者が覚えた名前から最も遠くない。**

| 名前 | 採否 | 理由 |
| --- | --- | --- |
| `install-wrapper` | 推奨 | 指示の語のまま。`/install` まで打てば候補に出る |
| `install_wrapper` | 採らない | 規約（名前はハイフンのみ）と検査に反する |
| `relay` | 採らない | 短いが、何をするかが名前から読めない。中継の文書の語（中継）を利用者は知らない |
| `relay-setup` | 次点 | 中継の語でそろう。利用者の指示の語から離れる |

### 決定 4: 10.17.4 が足した囲みは残し、1 度だけ知らせる（関門で最終決定）

**知らせずに残すことも、知らせずに消すこともしない。** 10.17.4 の利用者の中には中継を使い始めた人が
いる。新しい版の hook が消すと、それはまた利用者の設定の黙った書き換えで、この課題が無くそうとする
ものである。何もしなければ、利用者は alias が自動で足されたことを知らないまま残る。

| 扱い | 採否 | 理由 |
| --- | --- | --- |
| 残して 1 度だけ知らせる（`startup`） | 推奨 | 利用者が知って選べる。hook はシェルの設定を読むだけで、書くのは状態の親の記録と、在る写しの置き直しだけ |
| 新しい版の hook が 1 度だけ自動で外す | 採らない | 黙った書き換えをもう 1 度行う。中継を使っている利用者の `claude` の振る舞いが版の更新で変わる |
| 何もしない（リリースノートだけ） | 採らない | リリースノートを読まない利用者は知る手段が無い |

**自動の囲みの見分けは `rc-added` の記録と囲みの存在の両方で行う。** 記録は 10.17.4 の `install` が
足した先のパスを持つ。囲みを利用者が手で写した場合は記録が無く、知らせない。

### 決定 6: 送り込み（項目 3）は実測と不変条件までをこの課題で決め、実装は別の課題に分ける（関門で最終決定）

項目 1 は 10.17.4 の利用者の手元で今も働いており、早い 10.17.x で出したい（課題の本文）。送り込みの
実装は、許可の一覧・関門を越えない判定・モデルからの要求の形を持ち、項目 1・2 と独立に作って確かめられる。
同じ Pull Request に入れると、項目 1 の配布が送り込みのレビューと実機の確かめを待つ。実測の結果と
不変条件は [issue-928-design-injection.md](issue-928-design-injection.md) に残し、別の課題はそれを入力にする。
**不変条件のうち G1〜G3（関門を越えない守り）だけは、既存の `/exit` に当たるためこの課題で入れる**（決定 13）。

### 決定 13: 関門を越えない守り（G1〜G3）は、送り込みを待たずにこの課題で既存の `/exit` に入れる

実測で、質問の表示中に中継が書いた `\r` が選択肢 1 を決めると分かった（[issue-928-design-injection.md](issue-928-design-injection.md)
の「例」）。10.17.4 の切れ目の `/exit` と `\r` にも、印の後に応答が再開して質問が出る経路がある。
`/ndf:restart` はこの経路をそのまま使うので、守りが無いまま再起動を足すと、関門を越える経路を
利用者が自分で打てる形で増やすことになる。送り込みの課題へ回すと、配布済みの経路が残る。

守りは「質問の印」と「印より後の応答の行」の 2 つで作る。**画面の文言から質問を読む形は採らない。**
#895 の決定（Claude Code の版で文言が変わると読み違える）と同じ理由である。`Notification` hook は
表示から約 6 秒後に来て、2 秒で答えると来ないので、表示の始まりを知る手段にならない。`PreToolUse`
は表示と同時に来る。

### 決定 14: 切れ目の `/exit` と改行を 1 回の write にする

10.17.4 は `/exit` と `\r` を 1 秒あけて書いた。あいだに質問が出ると、`/exit` の文字は捨てられ、
`\r` が選択肢を決める。確かめ直しから書くまでの間を短くするため、1 回の write にする。実測で、
短い入力は 1 回でも間ありでも同じに働いた（`/clear`・`/compact`・`/cost`・`/status`・`/plugin`）。
`NDF_RELAY_EXIT_GAP` は使わなくなるので文書から外す。**長い入力は 1 回の write で送られないことがある**
（635 バイトは送られず、125 バイトは送られた。境界は測っていない）。`/exit` は 5 バイトで当たらない。

### 決定 15: 質問の印は `mark`（Stop）でも消す

`Esc` で質問を取り消すと `PostToolUse` が来ず、印が残る。残ったままだと中継は切り替えない（安全な
側に倒れる）が、切り替えが永久に止まる。Stop が起きたなら質問は表示されていないので、`mark` が消す。
取り消しの後は人が入力し、その応答の Stop で消える。

### 決定 2: 導入・取り外し・状態の表示を 1 つの Skill の引数で分ける

`statusline` が `status | set | restore` を 1 つの Skill で持つ前例に合わせる。導入と取り外しを別の
Skill にすると、同じ状態の親と囲みを 2 つの Skill の本文が説明し、片方だけが古くなる（AUTHORING と
既存の Skill へ統合してから新設を考える方針）。

### 決定 3: `install-wrapper` は明示指示専用にする。`restart` はモデルも起動できる

`install-wrapper` は利用者のシェルの設定を書き換える。AUTHORING の「実行前確認の要否を決める 3 つの
問い」の 1 に当たる。利用者が `/ndf:<名前>` で打つ運用なので、`statusline` と同じ明示指示専用
（`disable-model-invocation: true`）にする。これが要求の目的「シェル設定を書き換えるのを利用者の明示の
操作だけにする」を frontmatter で担保する。

`restart` は利用者の指示に「利用者（またはモデル）が呼ぶ」とある。中継の下で起きることは、conductor が
既に出している `ndf-next` のブロックと同じで、新しい権限を足さない。

### 決定 5: 写しの置き直しは SessionStart の hook で、写しが在るときだけ行う

hook から写しを置かなくなると、写しは導入した時点の版のまま止まる。**10.17.4 が置いた写しは、新しい
版の追従の処理を持たない**ので、写しの側（`run`）に追従を置いても 10.17.4 の利用者には届かない。守り
（G1〜G3）も届かない。新しい版の処理を確実に走らせられるのは、新しい版のプラグインから呼ばれる hook
である。

| 場所 | 採否 | 理由 |
| --- | --- | --- |
| SessionStart の hook（写しが在るときだけ） | 採る | 10.17.4 の写しにも届く。写しが無い利用者には何も作らず、シェルの設定も変えない |
| `run` の開始時 | 採らない | 10.17.4 の写しの `run` はこの処理を持たず、写しが永久に 10.17.4 のまま残る |
| 利用者が `/ndf:install-wrapper` を打ち直す | 採らない | 打ち直さない利用者の写しが古いまま残る。打ち直せば置き直るので、補助としては残る（E3） |

**要求の AC1 をこの決定に合わせて書き換えた**（写しが既に在るときだけ置き直しを許す）。利用者の指示は
シェルの設定の自動の書き換えをやめることで、利用者が導入した写しを今の版に保つことはそれに当たらない。
alias をプラグインのキャッシュのパスへ直接向ける案は、#895 の決定（版つきのキャッシュを指すと古い版に
固定され、古い版のディレクトリが消えると alias が壊れる）のとおり採らない。

### 決定 7: 再起動は `ndf-next` のブロックと既存の中継の経路で行う。中継に新しい副命令を足さない

`/ndf:restart` の中継の下の振る舞いは、conductor が区間の切れ目で行うことと同じ（ブロックを出して
応答を終える）である。同じ経路を使えば、`AskUserQuestion` の答え待ち・背景の処理・目標の判定・静まり・
上限・空回りの判定がすべてそのまま効く。**Skill の中の Bash から中継へ直接「今すぐ再起動」を送る形は
採らない。** 応答の途中で送ることになり、Stop を待つ判定を迂回する。子の claude が応答を終える前に
`/exit` が入る。

### 決定 8: `uninstall` は `$SHELL` に依らず bash と zsh の両方の設定を見る

10.17.4 の `install` は、起動した時点の `$SHELL` で足す先を決めた。利用者がその後にシェルを替えて
いると、今の `$SHELL` だけを見る `uninstall` は自動の囲みを見落とす。囲みの行は固有の印を持つので、
両方を見ても関係の無い行を外さない。

### 決定 9: `NDF_RELAY_AUTO` は廃止する

この変数は hook の自動の導入を止めるためにあった。hook が導入しなくなるので意味が無い。明示の
`install` に効かせると、置いたままの利用者が `/ndf:install-wrapper` を打っても何も起きず、理由が
分からない。置いたままでも害は無いので、読むのをやめて文書から外す。

### 決定 10: クラス図を作らない

`relay.py` は関数の集まりで型を定義しない。足す副命令も関数で、変える型が無い。#895 の設計と同じ
理由である。

### 決定 11: 中継の下かは `relay.py is-child` で判定する。`NDF_RELAY_DIR` の有無だけでは決めない

conductor が Bash から起こした `claude -p`（worker・外部 AI の委譲）も `NDF_RELAY_DIR` を継ぐ。その
中で `/ndf:restart` が働いてブロックを出しても、`mark` は直接の子でないとして印を書かない。
判定を `is-child` にそろえると、ブロックを出したのに切り替わらない状態が起きない。

### 決定 12: 明示の `install` は「利用者が消したら足し直さない」「案内は 1 度だけ」を持たない

10.17.4 の I5・I6 は、自動の導入が利用者の意図に反して繰り返さないための規則だった。明示の起動は
利用者の意図そのものなので、打たれるたびに同じ判定をして同じ行を出す。`rc-added` の記録があっても
足し、足した先を `rc-added` から除いて、自動の囲みの知らせの対象から外す。

### 決定 16: 中継の外の `/ndf:restart` は、シェルの 1 行ではなく貼り付ける中身を示す

再開用のコマンドは会話から作る文字列で、引用符・`$(...)`・改行を含みうる。`claude "<中身>"` の形で
示すと、利用者がシェルへ貼ったときに引用が壊れ、別のコマンドが実行されうる。起動した claude の入力欄へ
貼る中身だけを示せば、シェルを通らない。今の `ndf-next` のブロックの運用（人が中身を貼り付ける）とも
同じ形になる。中身をシェルの形へ引用し直して示す案は、Skill の中で任意の文字列を Bash へ渡す段で
同じ引用の問題が起きるため採らない。

### 決定 17: 確かめ直しと write を、質問の hook と同じロックで排他にする

確かめ直しから write までの間に質問が描かれると、G1 が破れる。質問は `PreToolUse` の hook が終わる
まで描かれないので、hook に同じロックを取らせれば、中継が書き終えるまで質問の始まりを止められる。
世代番号で後から検出する案は、書いた後に分かっても取り消せないため採らない。**中継がロックを持つ
時間は、hook が待つ 3 秒より短くなければならない。** 超えると hook は印を作って質問を描かせ、中継の
`/exit\r` が質問に届く。そのため会話の記録を全行読む処理はロックの前に済ませ、ロックの中では
`stat` で記録が変わっていないことだけを見る。持つ時間は 1 秒と数ミリ秒で、記録の長さに依らない。ロックが取れない hook は印を作って続ける
（中継が落ちてロックを持ったままでも、質問を止めない）。
