## 目的

NDF が人の承認を求める 2 つの点を、番号でなく中身の分かる名前で呼ぶ。承認を求められた人が、どちらの承認か（設計を承認するのか、本番へのリリースを承認するのか）を名前だけで分かる状態にする。あわせて、同じ点を「承認ゲート」「ゲート」`関門`の 3 つの語で呼んでいる状態を、1 語 1 意味にそろえる（プロジェクト MVV の Value 8「語をそろえる」・Vision「番号でなく中身の分かる語」）。

## 用語

| 用語 | 意味 |
| --- | --- |
| 設計承認ゲート | 設計 Pull Request のマージの前に人の承認を求める点。documentation モードでは企画承認に当たる。今の `承認ゲート 1`・`ゲート 1`・`関門 1` |
| リリース承認ゲート | 本番系へ届く操作（本番へのリリース・`operation` の実行・自動反映の本番チャネルへのマージ）の前に人の承認を求める点。documentation モードでは制作物承認に当たる。今の `承認ゲート 2`・`ゲート 2`・`関門 2` |
| 承認ゲート | 上の 2 つの総称 |
| 人へ出す文 | Skill・references・エージェントの定義の本文と、スクリプト・hook が人へ見せる文（問い・承認資料・報告・案内・エラーの文） |
| 機械が読む識別子 | スクリプトが値の一致で読む文字列。問いの区分 `ndf-gate:1` / `ndf-gate:2`、並列の依頼と Factory の契約の種類 `gate1` / `gate2`、スプリント状態ファイルとループの記録に書く承認ゲートの記録の名前（`関門 1` / `関門 2`）、承認ラベル `design-approved` |

## 前提

- 前提 1: 新しい呼び名は「設計承認ゲート」「リリース承認ゲート」の 2 つで、利用者が決めた。総称は「承認ゲート」とし、`関門`は語として使わない（用語集が既に`関門`を「承認ゲート」の廃止した語に置いているため）
- 前提 2: 「リリース承認ゲート」の「リリース」は、#2620 が定める「リリース」（本番へのデプロイ）を指す。承認ゲートが掛かる操作は今のゲート 2 から変えない
- 前提 3: #2620（「配布」を「デプロイ」「リリース」に分ける）と同じ開発ループ lflow2（マイルストーン 35）で、同じ周回か続く周回で進める。2 つの課題が同じ行を書き換えるときの順序は、実装計画で決める
- 前提 4: 承認ゲートの数・置き場所・掛かる操作・承認の判定は変えない。変えるのは呼び名だけである

## 受け入れ条件

- [ ] 1. 対象範囲の人へ出す文で、2 つの承認ゲートが「設計承認ゲート」「リリース承認ゲート」と呼ばれる。対象範囲の `git grep -nE '(承認ゲート|ゲート|関門) ?[12]'` のヒットは、未決 1 で残すと決めた機械が読む識別子・互換のために旧い値を読むコード・そのテストだけになり、残した箇所とその理由が設計文書に一覧で載る
- [ ] 2. 対象範囲の人へ出す文で、`関門`が承認ゲートの意味で使われない（`git grep -n '関門'` のヒットは受け入れ条件 1 と同じ例外だけ）
- [ ] 3. 用語集（`docs/glossary/glossary.json`）に「設計承認ゲート」「リリース承認ゲート」の 2 語が載り、それぞれの廃止した語に「承認ゲート 1」「ゲート 1」`関門 1`／「承認ゲート 2」「ゲート 2」`関門 2`が載る。「ゲート 1」「ゲート 2」の独立した語は用語集から消える。`glossary.py render` で作り直した `docs/glossary.md` と、`development-workflow/references/glossary.md` の表が同じ内容を持つ
- [ ] 4. 名前の変更で、旧い版が書いた記録が新しい版で同じ意味に読める。具体的には、承認ゲートの記録の名前が `関門 1` / `関門 2` の既存のスプリント状態ファイルとループの記録を新しい版の読む側（承認済みの判定・ループの記録の集計・MVV の改訂の兆候の集計）に通したとき、変更の前と同じ判定・件数になる。機械が読む識別子を変えた場合は、旧い値と新しい値の両方を入力にしたテストがある
- [ ] 5. 承認ゲートで出す問いが、hook（問い合わせの区分の検査）に拒否されない。問いの区分を変えた場合は、旧い区分の問いも拒否されない
- [ ] 6. Factory の承認の依頼が、API・ランナー・画面で同じ種類の値を使う。画面の表示は「設計承認ゲート」「リリース承認ゲート」になる
- [ ] 7. 全体テスト（`uv run --frozen --project . --all-extras pytest . -q -n 4`）と Factory のテストと CI が通る
- [ ] 8. 用語チェック（`python3 plugins/ndf/scripts/glossary.py check --file <変更した文書>`）が、変更した文書で廃止した語の当たりを 0 件にする（受け入れ条件 1 の例外を除く）

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 移行性 | 旧い版が書いた記録（承認ゲートの記録の名前・問いの区分・並列の依頼の種類）を、新しい版が移行の操作なしで読める。利用者に記録の書き換えを求めない |
| 運用・保守性 | 承認ゲートの名前を表す文字列は、スクリプトの中で 1 か所の定数から読む（今は `gate_answer.py` と `sprint_loop_record.py` が同じ定数を別々に持つ。Value 7 の「同じ役割の定数・関数を分けない」） |

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 人へ出す文が変わる。機械が読む識別子は未決 1 で決める。変える場合は旧い値も読む互換の経路を持つ |
| データ | 既存の記録は書き換えない。新しい版が書く記録の名前を変えるかは未決 1 で決める |
