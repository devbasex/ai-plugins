## 候補 A（推奨）: 「利用者へ届ける速さ」を軸

マイルストーン 26 の MVV の延長で、プロジェクト全体へ広げた形。ミッションの目的を「トークン消費の削減」から「価値が届くまでの時間」へ持ち上げ、汎用と OSS を Vision に入れる。

### Mission（何のためにやるか）

Claude Code / Codex / Kiro / agy のどれを使うチームにも、要求から本番の配布までの開発工程を「人の判断が要る所だけで止まる」形で届け、開発者が価値を利用者へ届けるまでの時間と費用を減らす。

### Vision（目指す姿）

開発者が課題を 1 つ指せば、設計・実装・レビュー・検査・配布までを NDF が回し、人が手を止めるのは設計の承認と本番への配布の承認の 2 回だけになる。言語・テスト・ブランチ運用・配布の手段が違うどのリポジトリでも、宣言（`.ndf/`）を 1 つ置けば同じ工程がそのまま通る。効果は版ごとの実測（費用・秒・件数）で示され、チームの内外の誰もがその数値を見て版を選べる。

### Value（判断の基準）

1. **まず届ける**: 完璧なものより「たぶん動く」ものを早く出す。開発版のチャネル・導入の確認・自動テストで守り、見つけた不具合は即時修正の 4 条件（原因が特定できる・既存の契約を壊さない・既存の方針の範囲・revert 1 回で戻せる）を満たせばその場で直す。処理の改善・削減・高速化に寄与しない指摘は直さない（J6、`mvv-milestone26.md:21`）
2. **利用者の手を止めない**: 承認は設計と本番への配布の 2 つの関門に寄せ、再起動・告知・確認で操作を求めない。実行前確認の要否は「取り消せるか・他者が読む内容を外へ出すか・判断を問うか」の 3 問で決める（J5）
3. **測って決める**: 効果は実測で示し、測らずに良くなったとは言わない。手順やコードに書くコマンドは書く前に実行し、外部コマンドの一致範囲・終了コード・解決の順序を確かめる（J2）
4. **決定論が先**: 判断の要らない手順（待ち・集計・検査・記録・整形・起動の組み立て）はスクリプトが進め、LLM は判断と中身（コード・設計文書）だけを担う。同じ手順を LLM に 2 度させたらスクリプトにする（J1）
5. **汎用を保つ**: 決定論にするのは手順の骨組みだけにし、プロジェクトごとに違うもの（テストのコマンド・起点のブランチ・配布の手段・言語・ランタイム・課題の正本）は宣言か引数で受ける。ai-plugins の形を既定に埋め込まない（J3）
6. **根本原因の場所で直す**: 現象ごとに直さず、修正レイヤーが現象レイヤーと違うときは共通層へ寄せてから設計する。同じ役割の定数・関数を Skill ごとに分けない（J7）
7. **判断の理由を残す**: 変更点の列挙とは別に「何を決め、なぜそう決めたか」を版・設計文書・振り返りに残し、同じ判断を繰り返さない。正本は 1 か所に置き、写さずに指す（J9、J8）
8. **語は 1 語 1 意味の日本語**: やり取り・文書・コミット・PR は日本語で書き、業界に流通している語を用語集で 1 語 1 意味に揃える（J4）

## 候補 B: 「工程の決定論と汎用」を軸

NDF を「どのプロジェクトでも同じ結果で通る工程の基盤」として捉える形。速さは結果であって目的にしない。マイルストーン 23「汎用性の回復」以降の関心と、#1142（スクリプト全体の設計のやり直し）・ライブラリへの置き換えの流れに合う。

### Mission（何のためにやるか）

開発工程のうち判断の要らない部分を決定論的な仕組みへ移し、言語・ランタイム・リポジトリの運用が違っても同じ工程が同じ結果で通る plugin を、判断の理由の記録とともに保つ。

### Vision（目指す姿）

NDF を入れたどのリポジトリでも、解析が宣言を作り、宣言が工程（作業ツリー・テスト・レビュー・構造改善・配布）の形を決め、LLM が触るのはコード・設計文書・判断だけになる。仕組みは規定の文言でなく hook・CI・定義で守られ、振る舞いはテストが、判断の理由は版ごとの記録が保つ。4 つのランタイムのどれから起動しても同じ Skill・同じスクリプト・同じ結果になる。

### Value（判断の基準）

1. **決定論が先**: スクリプトにできる手順を LLM に回させない。計画の後で LLM が動くのは作業の CLI だけにし、時間に関わる数値は予算から算術で出す（J1、v10.17.8）
2. **汎用を保つ**: プロジェクトごとに違うものは宣言（`.ndf/`）か引数で受け、ai-plugins の形を既定に埋め込まない。宣言が無いリポジトリでも止まらず、既定の判定だけで動く（J3、v10.15.0 #554）
3. **正本は 1 か所、写さずに指す**: Skill の実体・配布の基準・用語・判定の表は 1 か所に置き、他は参照する。文書に写した値は写した側だけが古くなる（J8）
4. **規定で守られなければ仕組みで止める**: 守られなかった規定は hook・CI・エージェント定義で塞ぐ。文面だけの規則を増やさない（J11）
5. **文言でなく振る舞いを守る**: `.md` の文言を照合するテストを書かず、スクリプトが実行時に読むものだけをテストで固定する。照合の表へ足す文言は実物に出所を持つものだけにする（J12）
6. **既存ライブラリを使う**: 汎用で車輪の再発明になる処理は外部ライブラリへ置き換え（サーバーは立てない）、判断が要る箇所は「最終的に一番綺麗になるやり方」で決める（J13）
7. **測って決める**: 候補は試行（実験版）で成り立ちを確かめ、効果は実測で比べてから本体へ移す。使われなかった実験版は消す（J2、J14）
8. **判断の理由を残す**: 版・設計・振り返りに「何を決め、なぜそう決めたか」を書く。同じ判断を繰り返しそうなときに読める形にする（J9）
