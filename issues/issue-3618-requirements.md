# #3618: NDF 自身の開発の事情を汎用の振る舞いへ持ち込まない: 製品の約束を MVV から分け、汎用性の後退（代表のリポジトリの種類を扱えなくする変更）をレッドライン・設計の型・レビュー・CI・代表のリポジトリでの試験で止める

正は課題の本文（#3618）で、この文書はその写しである。`spec-copy.py write` で作り直す。手で直さない。

## 目的

NDF を使う利用者のリポジトリ（言語・テストのツール・ブランチの運用・リリースの方法がそれぞれ違う）で、NDF の設計の変更が「ある種類のリポジトリを NDF で扱えなくする」こと（汎用性の後退）を、設計承認の前に機械と人が気づける状態にする。

- ai-plugins（NDF 自身を開発するリポジトリ）の運用の事情が、汎用の振る舞いとして NDF に入り込む事例が続いている（#3119・#3121・#3156・#3309・#3379、2026-11-16 の #3572 の設計 PR #3596）
- 判断の基準はすでにある（ai-plugins の MVV `.ndf/mvv.md` の Value 4「どのプロジェクトでもそのまま使える」「ai-plugins の流儀を、使う側のプロジェクトに持ち込まない」）。足りないのは、基準を当てる工程と手段である
- 防ぐのは汎用性の後退であって、後方互換の崩れではない。普及のフェーズに入るまで、NDF は後方互換を求めない。設定のキーの改名・値の作り直し・旧い形のサポートの打ち切り・既定の変更は、互換を残さずに行ってよい（利用者の方針、2026-11-16）
- 達成したい状態: 代表のリポジトリの種類のどれかを扱えなくする設計は、(1) 設計を書く時点で代表のリポジトリでの振る舞いの表の「この種類で扱えなくなること」の列に現れ、(2) 設計の検査と MVV 判定が人へ戻し、(3) 設計承認ゲートの「人へ残す判断」の表に載る。値の改名・既定の変更・代わりの形のある値の削除だけの設計は、人へ戻さない

## 前提

- 前提 1: 混入の原因は、基準（Value 4）が工程のどこでも名指しで当たっていないことである（S1）。設計は「基準を当てる時点」を足す形で直し、基準の文言だけを直す形にはしない。当てる基準は「代表のリポジトリの種類をどれも扱えることを保つ」（汎用性）であり、「設定で選べる値を減らさない」（後方互換）ではない
- 前提 2: 承認ゲートは増やさない。MVV と共通原則の文言の改訂は、この課題の設計承認ゲートで利用者が承認し、改訂の文は実装の Pull Request でコミットしてリリース承認ゲートで人が見る（共通原則の「承認は既存の承認ゲートで取り」、C7）
- 前提 3: 案 F（CI の検査）の実装は #3617（レーン lgeneric）が持つ。この課題は、F が検査する対象（代表のリポジトリの種類に要る選択肢）の定義を設計で参照し、F の検査の実装・許可リスト・CI のジョブを持たない。両者の境は設計の「適用範囲」に書く
- 前提 4: 案 G（代表のリポジトリでの試験）の試走の実行は T2 #3411（レーン lr-t2）が持つ。この課題が持つのは、試走に加える代表のリポジトリの選び方と、そのリポジトリで確かめる項目（汎用性の後退が起きていないこと）の定義までである。#3411 の試走の範囲を変えるときは #3411 の本文の改訂として扱い、レーン lr-t2 へリクエストで送る
- 前提 5: モバイルアプリ（Flutter か Swift）の実物のリポジトリは手元に無い（2026-11-15 に `find /work -maxdepth 4 \( -name pubspec.yaml -o -name "*.xcodeproj" -o -name Package.swift \)` が 0 件）。モバイルアプリの行は、Flutter・`flutter test`・TestFlight への手動のリリースを設定した仮のリポジトリとして書く
- 前提 6: 代表のリポジトリの実物として、次の設定を材料に使う（2026-11-15 に各リポジトリの `.ndf/` を読んだ）

## 用語

| 用語 | 意味 |
| --- | --- |
| 設定 | 利用者のリポジトリが `.ndf/` に置く JSON とその中身。ndf-next の文書では「宣言」と呼んできた語で、#3613 の対応表 W3 が「設定」へそろえる |
| 代表のリポジトリの種類 | NDF が扱えることを保つリポジトリの種類。この課題では Web サービス（develop を経て本番へ出す運用を含む）・モバイルアプリ・業務文書だけ の 3 種を最低限とする |
| 代表のリポジトリ | 代表のリポジトリの種類ごとに、設計の振る舞いを確かめる ai-plugins 以外のリポジトリ（実物か、設定を仮に置いたもの） |
| 汎用性の後退 | NDF の変更の後に、代表のリポジトリの種類のどれかを NDF で扱えなくなること。その種類に要る選択肢（運用・リリースの形・テストのツール・CI など）を、代わりの形なしに無くすことで起きる。値の改名・作り直し・既定の変更・代わりの形のある値の削除は当たらない |
