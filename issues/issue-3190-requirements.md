## 目的

- **今どうなっているか**: 用語集（`docs/glossary/glossary.json`・`docs/glossary.md`、1,063 項目・20 コンテキスト）の見出しの語は今の語にそろっている（廃止した語を持つ項目は 138、廃止した語は 154 語）。崩れているのは意味の説明の文で、古い語が残る
- **原因**: 用語チェック（`glossary.py check`）は、設計の文書の追加した行の廃止した語を落とすが、用語集の意味の説明に廃止した語があっても落とさない（意味の説明で見るのは禁止語だけ）。語を改名しても説明の文に古い語が残り、そこから新しい文書へ写る。#1142 の設計文書（PR #3179）に「継続的統合」が 31 か所、直訳調の「字で持ち」（→ 文字列で持ち）が残ったのも同じ流れである
- **変えると何が成り立つか**: 用語集の意味の説明が今の語で書かれ、廃止した語と避ける語が用語集にも新しい設計の文書にも入らない

意味の説明に残る古い語（2026-11-13、`develop` の先頭 25f96ab28 で数えた）:

数えた手順: `docs/glossary/glossary.json` の `terms[].meaning` を読み、語ごとに部分一致の出現を数えた。廃止した語は、どこかのコンテキストの生きた語と同じものと、生きた語の出現の内側に現れるものを除いた（用語チェックの `deprecated` の規則と同じ除き方）。コンテキストの意味の説明（`contexts[].meaning`）には 4 語とも出現が無い。

## 前提

- 前提 1: 「段」と「字」は 1 文字のため、今の用語集の形では廃止した語に登録できない（1 文字の廃止した語は `schema` に当たる）。登録する形（2 文字以上の形にする・別の規則を足すなど）は設計が決める。どの形でも「段階」「手段」「文字」「字数」を当てない
- 前提 2: 誤った当たり（`インライン` の一部の `ライン` など）は、意味の説明を言い換えるか、照合の規則で除くかを設計が決める。どちらでも受け入れ条件 1 を満たす
- 前提 3: 意味の説明の検査は、`--rules structure` の検査に含める。CI では設計のブランチ以外の Pull Request でも走る。NDF を使うほかのプロジェクトでも、意味の説明に廃止した語がある用語集は、NDF の版を上げた後に落ちる
- 前提 4: 本文の起票の時点の数（「段」34・「継続的統合」4）と上の実測が違う。直す対象は実測の表である

## 対象範囲

含む:

- 用語集の意味の説明（`terms[].meaning`・`contexts[].meaning`）の、廃止した語と避ける語の直し
- 用語チェックの構造の検査を、用語集自身の意味の説明の廃止した語にも掛けること
- 避ける語 4 つ（継続的統合・入口・段・字で持つ）の登録と、置き換え先の語（CI・エントリポイント・ステップ / ステージ・文字列で持つ）の用語集への登録
- 人が読む文書（`docs/glossary.md`）の作り直し

含まない:

- コンテキストの分割などの再編（ndf-workflow に 578 語）
- #1142 の設計文書の直し（PR #3179 でレーン lrebuild が直す）
- 用語集の外の既存の文書（確定仕様・Skill の本文）に残る避ける語の直し
- 4 つ以外の直訳の和語の登録
- 廃止した語の欄（`terms[].deprecated`）に避ける語が載ること自体の検査

## 用語

| 用語 | 意味 |
| --- | --- |
| 廃止した語 | 用語集で別の語へ置き換えた語。この要求では、避ける語もここへ登録する |
| 禁止語 | 用語集の設定が、検査する範囲で新しく書くことを禁じた語。この要求では使わない |
| 用語チェック | `glossary.py check`。用語集の形と、文書の追加した行の語を見る |
| 用語集の設定 | `.ndf/glossary.json`。用語集の置き場・形式・チェックの対象を持つ |
| エントリポイント | 「入口」の置き換え先 |
| ステップ | 「段」の置き換え先（工程の 1 つ分） |
| ステージ | 「段」の置き換え先（パイプラインの 1 つ分） |

本文で使う「意味の説明」は、用語集の各項目の意味の欄（`terms[].meaning`）とコンテキストの意味の欄（`contexts[].meaning`）を指す。「避ける語」は、用語集にまだ登録されていない古い語・直訳調の語で、この要求が廃止した語として登録する 4 つを指す。
