今（ndf 10.17.70）:

1. 利用者のプロジェクトが `works/novel-a/chapters/011/text.md` 〜 `020/text.md` を 1 つの PR にまとめ、`/ndf:cross-review <PR>` を打つ

3. レビュー担当への「指摘の基準」は基準 1（誤動作・停止・データ破壊）・2（秘密・認証）・4（設計文書の食い違い）で、「書かないもの: 字句や言い回し…」が付く。レビュー担当は文の不自然さ・口調のずれを書かない

1. 利用者のプロジェクトが `.ndf/review.json` にプロファイル（基準・書かないもの・見送りの種類・返信・自動観点）を書く
2. 同じ PR で、自動観点は `manuscript`（プロファイルの観点）だけになる（`replace_auto_categories: true`）
3. 「指摘の基準」はプロファイルの基準（設定との食い違い・不自然な文・口調のずれ）になり、「字句や言い回し」は「書かないもの」に出ない
4. 修正担当は原稿のファイルを直すか、プロファイルの見送りの種類（`preference` など）で見送り、プロファイルの返信の文で返す

## 目的

- cross-review の枠組み（別の文脈の 2 者がレビューし、1 者が直し、新しい指摘が出なくなるまで回す・PR へ投稿する・状態ファイルで再開する）を、システム開発以外の成果物（例: Markdown の小説の原稿）のレビューにも使えるようにする
- そのために、プロジェクトの側から「指摘の基準」「書かないもの」「見送りの種類と返信」「自動レビュー観点」を差し替えられるようにする。今はどれも NDF の定数で、足すことしかできない

## 前提

- 前提 1: プロファイルは `.ndf/review.json` の `profile` の鍵に書く。`version: 1` の宣言（`focus` だけ）は今と同じに読み、`profile` は `version: 2` の宣言でだけ読む。`version: 2` でも `focus` は今と同じ基準 3 として働く
- 前提 2: プロファイルの鍵は個別に効く。書いた鍵だけが既定を差し替え、書かなかった鍵は既定の値のまま（例: `criteria` だけを書けば、「書かないもの」は既定の「字句や言い回し…」のまま出る）
- 前提 3: プロファイルが壊れている（形が違う・`reply` に `{inner}` が無い・基準の番号が `focus` の基準 3 と重なる など）ときは、今の重点の宣言が読めないときと同じく止めずに既定の基準で続け、理由を標準エラーと cross-review の報告に出す
- 前提 4: `replace_auto_categories` が真のときは、既定の自動カテゴリ（`common`・`docs_only` を含むすべて）の観点を渡さない。PR を設計 / コードへ分ける判定（`review_kind`）とラウンドの段（モデルレビュー・詳細レビュー）は、観点の差し替えと関わりなく今の分類から出す
- 前提 5: プロファイルは、今の重点の宣言と同じく PR の head のworktreeから読み、状態ファイルへ写す。`/ndf:fix` を cross-review の外で単独に使うときは `--root`（省けば今のworktree）から読む
- 前提 6: プロファイルで変えるのは、レビュー担当と修正担当へ渡す文と、見送りの返信だけである。収束の判定・投稿の形・状態ファイルでの再開・レビュー担当の選び方は変えない

## 対象範囲

含む:
- `.ndf/review.json` のプロファイル（基準・書かないもの・見送りの種類・返信・自動観点・既定の自動カテゴリを外す指定）の読み取り
- レビュー担当への「指摘の基準」の節、修正担当への「指摘の基準」の節、見送りの返信を、プロファイルから組むこと
- 修正担当の振り分けの検査（`waive_kind` と `criterion` の許す値）をプロファイルに合わせること
- 自動レビュー観点の追加と、既定の自動カテゴリを外すこと
- 修正担当への文（`review_criteria.py fixer`・`fix-steps.py context`・`/ndf:fix` の手順）で「コード」を前提にした語を、プロファイルがあれば成果物を指す語にすること
- 状態ファイルへの写しと、再開のときの読み直し
- 宣言の書き方の文書（cross-review の契約の文書と `/ndf:fix` の文書）

含まない:
- 小説の原稿に向けた既定のプロファイルを NDF に同梱すること（プロファイルは使う側のプロジェクトが書く）
- プロファイルを書く・作る手段（`init` の雛形・対話の生成）
- `cross-refactoring` の提案の基準の差し替え（`cross-refactoring` は最終ゲートとして cross-review を呼ぶので、その中では本課題の振る舞いがそのまま効く）
- `pr-review`（単発のレビュー）の基準の差し替え
- 収束の判定・ラウンドの数・参加者の選び方の変更

| 自動レビュー観点（`docs/04-contracts.md` の自動カテゴリ） | `code`・`db_migration`・`api_contract` などファイルの種類で決まる | 変えられない |

小説の原稿では、言い回し・文の自然さ・人物の口調・設定との食い違い・章の面白さが主な指摘になる。今の基準では、レビュー担当は「字句や言い回し」を書かないよう指示され、修正担当は wording として見送る。`--extra-instructions-file` で観点を足しても、「書かないもの」と食い違う指示が同じプロンプトに並ぶ。

### 提案

`.ndf/review.json` に、基準の組（プロファイル）を差し替える鍵を足す。例:

```json
{
  "version": 2,
  "profile": {
    "criteria": {"1": "設定（人物・世界観・年表）と本文が食い違う", "2": "文が日本語として不自然で読み手が引っかかる", "4": "人物の口調・呼び方が設定とずれる"},
    "not_written": ["好みの文体", "設定に無い新しい案"],
    "waive_kinds": {"preference": "好みの文体", "out_of_scope": "設定を変える提案"},
    "reply": "直しません。{inner}に当たるためです。",
    "categories": {"manuscript": {"paths": ["works/*/chapters/*/text.md"], "instructions": "..."}},
    "replace_auto_categories": true
  }
}
```

- `profile` が無ければ今の振る舞いのまま（後方互換）
- `criteria`・`not_written`・`waive_kinds`・`reply` は `reviewer_block` と `fixer_block` と `waiver_reply` が読む
- `categories` はパスの glob で自動観点を足し、`replace_auto_categories` が真なら既定の自動カテゴリを外す
- 修正担当（`/ndf:fix`・`fix-steps.py`）の「コードを変えずに」などの文言も、プロファイルがあれば「対象のファイル」に読み替える

### 受け入れ条件

- [ ] 1. `profile` の無いリポジトリで、`review_criteria.py reviewer` / `fixer` の出力が今と同じ
- [ ] 2. `profile` を書いたリポジトリで、レビュー担当への節に既定の基準 1・2・4 と「字句や言い回し」が出ず、プロファイルの基準が出る
- [ ] 3. 見送りの返信がプロファイルの `reply` と `waive_kinds` から組まれる
- [ ] 4. 自動観点が `categories` で足され、`replace_auto_categories` で既定のものが外れる
- [ ] 5. `profile` を書いたリポジトリで、修正担当への節（`review_criteria.py fixer`・`/ndf:fix`・`fix-steps.py`）の「コード」を前提にした文言が「対象のファイル」に読み替わる
- [ ] 6. 既存のテスト（`uv run --frozen --project . --all-extras pytest . -q -n 4`）が通る

### 背景

利用者のプロジェクトで、小説の原稿を 10 話ごとに PR にまとめて cross-review したいという求めが出た。今はつなぎとして、プロジェクトの Skill で同じ形のループを別に組む。
