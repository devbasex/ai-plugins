## 今の姿

guard `stop-wait`（#2324）は、Stop の hook で最後の応答の本文を読み、AskUserQuestion を使わずに本文で人の回答を待って終えた応答に変更を要求する。変更を要求すると AI は AskUserQuestion で質問し直すか、問わずに進む。AskUserQuestion なら中継とオーガナイザーへ質問が届き、待ち通知も送られる。変更要求の上限（利用者の入力ごとに 2 回、`hook.pushback`）の後は通して待ち通知を書く。

判定は `plugins/ndf/src/ndf/domains/hooks/context.py` の `classify_reply` が文字列で行う。

- 決まった言い回しの列（`_WAIT_RE`。「よろしいですか」「指示をください」など 14 個）か、行末の `?`・`？` に当たれば待ち（`prose_wait`）
- 見るのは本文の末尾 4 行（`_TAIL_LINES = 4`）だけ。コードブロックの中は見ない
- 別の場所（ほかのセッション・レーン）の待ちを報告する言い回し（`_ELSEWHERE_RE`）は待ちにしない（`elsewhere_wait`）

Stop の hook は登録の timeout が 6 秒、予算の締め切りが 3.5 秒（`plugins/ndf/contracts/limits.json` の `hook.budget.stop`）で、guard の判定は文字列だけなので数ミリ秒で終わる。

## 現象

```bash
uv run python -c 'from ndf.domains.hooks.context import classify_reply; print(classify_reply("どちらにするか決めていただければ進めます。"))'
# → report（期待は prose_wait）
```

「何が起きたか」の表の 1〜4 回目の 5 文はどれも `report`、誤検出の引用の文は `prose_wait` を返す（11.0.19 で確かめた）。

## 期待する結果

人の判断・選択・承認を求めて、その回答を待って終えた応答には、言い回しと位置によらず変更を要求する。引用・別の場所の待ちの報告・待ちを伴わない報告は通す。

## なぜ困るか

本文で質問を書いて終えた会話は、AskUserQuestion と違って中継にもオーガナイザーにも質問として届かず、待ち通知も出ない。人が画面を見に来るまで、レーンは止まったまま時間を失う。言い回しを列へ足して直しても、応答を書く側の言い回しの数だけ漏れ続け（4 回とも別の言い回し）、列を広げるほど引用を誤って止める。

## 目的

- 人の判断を本文で求めて終えた応答を、言い回しと位置によらず止め、AskUserQuestion へ寄せる
- 判定を軽いモデルに任せ、言い回しの列を足し続ける保守をやめる

## 対象範囲

含む:
- **見ればわかる質問は、軽いモデルを呼ばずにルールで止める**（2026-11-23 の利用者の決定「これぐらいは LLM 使わずに止めて欲しい」）。ルールは **10 系の判定（`ndf--v10.27.77` の `plugins/ndf/scripts/lib/wait_notice.py` の `classify_reply_wait`。文に分けて文の終わりの形・依頼の語・条件の添え書き・操作の案内を見る）を 11 系へ移したもの**にする。今の 11 系の判定（言い回しの列と末尾 4 行）は 10 系から退行している（下の「10 系との比較」）。ルールに当たらない本文だけを軽いモデルへ渡す
- guard `stop-wait` の判定を、ルールに当たらない本文を軽いモデル（最小構成の `claude -p`）に渡して決める形に変える
- 軽いモデルを呼ばない条件（呼ぶ回数と費用を抑える）と、軽いモデルが回答しないときのフォールバック、起動できない環境で呼び続けない仕組み
- 呼ぶモデル・時間の上限・本文の字数の上限の設定と、Stop の hook の時間の予算の見直し
- 判定の例の組（応答の例と期待）と、実際のモデルでその組を確かめるコマンド

含まない:
- guard `stop-wait` 以外の Stop の guard（`relay-marker`・`unattended`・`ask-closed`）の判定。`unattended` は応答の形を別のコントラクトで見ており、本文の待ちの判定を使わない
- 変更要求の文面・変更要求の上限（`hook.pushback`）・上限の後の待ち通知の振る舞い
- SubagentStop（worker・supervisor の応答）への同じ判定の適用。サブエージェントは人へ問えず、待ちを伴う終え方は上の層の報告の規約が受け止める

## 受け入れ条件

- [ ] 0. 10 系の判定（`classify_reply_wait`）を 11 系へ移し、軽いモデルの前に置く。待ちと判定した本文は軽いモデルを呼ばずに変更を要求する。10 系の例の組（`ndf--v10.27.77` の `plugins/ndf/scripts/tests/fixtures/wait_notice_corpus.json`、225 件）を 11 系のテストへ移し、10 系と同じ正誤（待ち 79 件のうち 74 件を拾う・待ちでない 146 件のうち誤検出 5 件以下）を下回らない。「何が起きたか」の表の 1〜5 はルールだけで止まる
- [ ] 1. ルールに当たらず、軽いモデルが回答を返すとき、`stop-wait` の判定は、コードブロックを除いた本文（字数の上限まで。上限は下の条件 7 の設定が持つ）をモデルへ渡した回答で決まる。回答が「人の回答を待って終えている」なら変更を要求し、それ以外なら通す。**末尾の行数で範囲を切らない**（質問の後に報告の行が 9 行続く本文でも、モデルには質問の行が渡る）
- [ ] 2. 判定の例の組を 1 つのファイルに置く。組は「何が起きたか」の表の 5 文（期待は待ち）・誤検出の引用の文（期待は待ちでない）・別の場所の待ちの報告（期待は待ちでない）・待ちを伴わない作業の報告（期待は待ちでない）を少なくとも含む
- [ ] 3. 実際の軽いモデルで判定の例の組を確かめるコマンドがある。コマンドは各例を決められた周の数（設定。既定 3 周）だけ打ち、1 周でも外れた例があれば外れとして出して 0 以外で終わる。マージの前に打ち、外れが 0 件であることと、その出力を Pull Request に貼る
- [ ] 4. 次の Stop では軽いモデルを呼ばない: 条件 0 のルールで止めた・本文が空・最後の利用者の入力の後に AskUserQuestion を使った・背景の作業（`background_tasks`）が残る・その入力の後の変更要求が上限に達した
- [ ] 5. 軽いモデルが回答しない（起動できない・時間の上限を超えた・認証などで失敗した・回答の形が違う）とき、判定は今の文字列の判定（言い回しの列と末尾 4 行）で決まり、hook は登録の timeout の中で終わる
- [ ] 6. hook の計測の記録に、判定の出所（軽いモデル／フォールバックと、その失敗の種類）と軽いモデルの所要の秒が残る
- [ ] 6a. 軽いモデルを起動できない失敗（起動の失敗・学習に使わない設定の確かめの拒否・利用上限）の後は、決められた間（設定）だけ軽いモデルを呼ばず、文字列の判定で決める。間が過ぎたら呼び直す。時間切れと起動のスロットの空き待ちでは、この間を置かない
- [ ] 7. 呼ぶモデル・時間の上限・本文の字数の上限は `plugins/ndf/contracts/limits.json` の 1 か所にあり、コードはそこから読む
- [ ] 8. Stop の予算と登録の timeout が軽いモデルの時間の上限を収め、hook の予算の順序の検査（guard の部品の上限 ≤ 締め切り − 余白 ≤ 登録の timeout）が通る
- [ ] 9. 軽いモデルの起動は最小構成（設定・MCP・スラッシュコマンド・Tool を読まない）で、その起動の中で NDF の hook が動かない
- [ ] 10. 退行しない: 既存の hook のテスト（`plugins/ndf/tests/domains/hooks/`）が通る

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 性能・拡張性 | 軽いモデルを呼ぶ Stop の待ちは、時間の上限（設定の値）を超えない。2026-11-23 の実測は、思考を切った haiku の最小構成で 1 回 0.71〜1.51 秒、子のプロセスの起動を含めて約 1〜1.7 秒（思考を切らないと 17〜33 秒かかる回があった） |
| 運用・保守性 | 判定を変えるときに直すのは、軽いモデルへの質問と判定の例の組の 2 つで、言い回しの列を足さない |
| セキュリティ | 本文を送る先は、セッション自身が使う Claude の API と同じ。`claude -p` の既存の起動（`adapters/claude.py` の `call_claude`）が確かめる学習に使わない設定を通らない起動はしない |
