## 目的

- Factory の利用者が開発ループの予算の欄を空にして保存したとき、次の周回から NDF がそのリポジトリの既定の予算で止まる条件を判定する状態にする
- 画面に出る予算と、NDF が止まる条件の判定に使う予算を食い違わせない

## 前提

- 前提 1: 今の食い違いの仕組みは次のとおりである。サービスは実行ジョブの指示に、値のある単位だけを `LOOP_BUDGET` として並べる（`factory/api/src/runs/control.ts` の `buildInstruction`）。NDF の予算の上書き（`plugins/ndf/scripts/lib/sprint_loop.py` の `apply_budget`）は渡された単位だけを上書きする。そのため、一度 `usd=10` を渡したループの費用の欄を空にしても、ループの記録の費用の予算は 10 のまま残る
- 前提 2: リポジトリの既定の予算は、既定へ戻す時点のメインディレクトリの `.ndf/pace.json` の `loop.budget` の値である。宣言が無い単位は NDF の組み込みの既定（周回 3・費用 60 USD・時間 24 時間。`plugins/ndf/scripts/lib/pace.py` の `LOOP_DEFAULTS`）である。ループを始めた時点の値を覚えておくのではない
- 前提 3: 予算の変更の API（`factory/api/src/runs/loops.ts` の `updateBudget`）は、3 つの単位をまとめて置き換える。送らない単位と `null` の単位は「空」として扱う。この契約は変えない
- 前提 4: #2405（再開のジョブへ変えた予算を届ける）の実装が、この課題の実装より先にマージされる。#2405 は、NDF に予算だけを反映する副命令（`sprint-state.py loop budget`）を足し、再開のジョブにも `LOOP_BUDGET` を載せる（`issues/issue-2405-design.md`）。#2405 が先にマージされないときは、受け入れ条件 4 を再開のジョブの経路ができた時点へ持ち越す
- 前提 5: Factory は NDF の版ごとの対応を版の比較で判定する前例を持つ（`factory/api/src/runs/version.ts` の `isLegacyVersion` と、並行の実行を許す最小の版の設定）。受け入れ条件 7 の判定も同じ考え方で作れる
- 前提 6: 既定へ戻す指示を、記録が既に既定の値である単位へ出しても、予算の履歴に行は足さない。サービスは前の値を覚えずに、空の単位を毎回「既定へ戻す」として渡してよい

## 対象範囲

含む:
- NDF の開発ループの予算の上書きに、単位ごとに「リポジトリの既定へ戻す」指示を足すこと（`loop start` と、#2405 の `loop budget` の両方）
- サービスが実行ジョブの指示に空の単位を「既定へ戻す」として載せ、ランナーが NDF へ渡すこと（周回のジョブと再開のジョブ）
- 実行ジョブの指示の契約（`factory/contracts/schemas/run-job-instruction.schema.json` の `LOOP_BUDGET`）の変更
- 予算の単位が空のときの画面の表示（一覧と詳細の「予算の残り」、予算の欄）
- 既定へ戻す手段を持たない NDF の版で動くループで、空にする変更を断ること
- 確定仕様（`docs/specifications/ndf-factory-dev-loops*.md`・`docs/specifications/ndf-factory-contracts-and-progress.md`・`docs/specifications/ndf-workflow-development-loop.md`）と NDF の手順（`plugins/ndf/skills/development-workflow/references/loop.md`）の予算の記述

含まない:
- Factory が各リポジトリの既定の予算の値を読んで画面に出すこと。既定の値の正本は各リポジトリの `.ndf/pace.json` に置いたままにする
- 再開のジョブへ予算を届ける経路そのもの（#2405 が持つ）
- 動いているジョブ（`running`）の途中で予算を届けること
- 止まった（`stopped`）・取り消した（`cancelled`）ループの予算の変更
- 予算を「掛けない」（上限を外す）状態を新しく作ること。NDF のループの予算は 3 単位とも常に正の数を持つ

## ドメインイベント

| # | イベント | 引き金 | 失敗したとき | 順序の前提 |
| --- | --- | --- | --- | --- |
| E1 | 利用者がループの予算の単位を空にして保存した | 画面か API の予算の変更 | 終わりの状態のループは既存のとおり断る。既定へ戻す手段を持たない版のループで、値のあった単位を空にする変更は断り、理由を返す（受け入れ条件 7） | ループが `running`・`between_laps`・`awaiting_approval` のいずれか |
| E2 | サービスが次のジョブの指示に、空の単位を「既定へ戻す」として載せた | 次の周回のジョブか再開のジョブを作る | 既存の断りの理由でジョブを作らない | E1 の後に作られたジョブに、E1 の予算が載る |
| E3 | ランナーが NDF へ「既定へ戻す」指示を渡した | 周回のジョブでは conductor の起動の指示、再開のジョブでは予算の反映（#2405） | 再開のジョブの扱いは #2405 の決定に従う。周回のジョブでは NDF が引数を断り、ループを始めない | E2 |
| E4 | NDF がループの記録の予算の単位を、リポジトリの既定の値へ戻した | E3 | `.ndf/pace.json` を読めないときは既存のとおりループを始めない・反映しない | E3 の時点の `.ndf/pace.json` を読む（前提 2） |
| E5 | NDF が周回を締め、既定の値で止まる条件を判定した | conductor が周回を締めるコマンドを打つ | 既存のとおり | E4 |

## 用語

| 用語 | 意味 |
| --- | --- |
| ループの予算 | 開発ループが使ってよい周回の数・費用（USD）・時間の上限。Factory のループの行と NDF のループの記録の両方が持つ |
| 予算の既定 | ループの予算の単位ごとの既定の値。リポジトリの `.ndf/pace.json` の `loop.budget` の値で、宣言が無い単位は NDF の組み込みの値 |
| 予算の反映 | 開発ループの記録の予算を、渡した単位の値で上書きすること |
| 予算の履歴 | 開発ループの記録が持つ、予算の上書きの記録 |
| 再開のジョブ | `START=resume` の実行ジョブ。承認の答えで起こすものと、利用上限のリセット時刻の後に起こすものがある |
| ループの記録 | NDF が開発ループごとに持つ `.ndf/loop/<名>/loop.json` |

## 受け入れ条件

- [ ] 1. 費用の予算 10 USD で始めたループの費用の欄を空にして保存すると、次の周回のジョブの後、NDF のループの記録の費用の予算がリポジトリの `.ndf/pace.json` の `loop.budget.usd` の値になる（サービス・ランナー・NDF のテストで、指示・NDF へ渡す引数・記録の予算をそれぞれ確かめる）
- [ ] 2. 受け入れ条件 1 のループで、締めた周回の費用の和が 15 USD（古い予算 10 以上、既定の予算未満）のとき、NDF は `budget_usd` の止まる条件を記録しない（NDF のテストで確かめる）
- [ ] 3. `.ndf/pace.json` に `loop.budget` の宣言が無い単位を既定へ戻すと、NDF の組み込みの既定（周回 3・費用 60・時間 24）になる
- [ ] 4. 承認待ちのループの予算の単位を空にした後、承認の答えで作られた再開のジョブでも、受け入れ条件 1 と同じくループの記録の予算が既定の値になる（前提 4）
- [ ] 5. 既定へ戻す指示で予算が変わったときは予算の履歴に 1 行だけ足し、変わらないとき（既に既定の値のとき・新しいループを始めるとき）は足さない
- [ ] 6. 予算の単位が空のループでは、一覧と詳細の予算の残りに、その単位がリポジトリの既定に従うことが分かる文言を出す。「掛けない」（上限が無い）とは出さない。文言は翻訳のファイルに置く
- [ ] 7. 既定へ戻す手段を持たない NDF の版で動くループで、値のあった単位を空にする変更は、画面と API の両方で断る。理由（その版では既定へ戻せないこと）を返し、画面はその理由を出す。値を入れる変更と、もともと空の単位を空のままにする変更は断らない
- [ ] 8. 3 つの単位すべてに値のあるループの周回と再開は、指示・NDF へ渡す引数・ループの記録の予算がこれまでと変わらない
- [ ] 9. 予算の欄をすべて空にして始めたループは、これまでどおり NDF の既定の予算で動く
- [ ] 10. 「既定へ戻す」を表す値が数でも既定へ戻す指示でもないとき、NDF はループの記録を変えずに引数の誤りとして断る

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 運用・保守性 | 既定の値を決める規則（`.ndf/pace.json` の読み方と組み込みの既定）は NDF の 1 か所に置き、Factory に写さない |
| 移行性 | 既に動いているループと保存済みのループの行は、データの移行なしで次のジョブから新しい規則に乗る。Factory のループの行の予算の形（単位ごとに数か `null`）は変えない |

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わる（互換あり）。NDF の `sprint-state.py loop start`（と #2405 の `loop budget`）の `--budget-*` が「既定へ戻す」指示を受けるようになる。数を渡す既存の使い方は変わらない。実行ジョブの指示の契約の `LOOP_BUDGET` の形が広がる。予算の変更の API は、版によって空にする変更を断る理由が 1 つ増える |
| データ | スキーマの変更は無い。ループの記録の予算の履歴に、既定へ戻した変更が 1 行ずつ足される |
| 既存の振る舞い | 空の単位のある周回・再開のジョブで、NDF の予算がその単位の既定へ戻る。画面の空の単位の表示が変わる |
