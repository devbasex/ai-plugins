## 何が起きたか

2026-11-22 の計画 p12 のレーン lracct で、conductor が 04:26 JST に「U1 の PR #4018 の CI と、設計の直しの PR #4022 の cross-review を待っている。そろったら設計承認を求める」と書いて、背景の supervisor-waits の完了の通知を待った。待っていた作業は 04:50 JST までにどちらも終わったが、通知が届かず conductor は動かないままだった。07:20 JST にオーガナイザーが画面を見て気づき、入力欄から再開を伝えると、conductor は直後に動き出して 07:24 JST に設計承認の質問を出した。

| 時刻（JST） | 起きたこと |
| --- | --- |
| 04:26 | conductor が待ちに入る（画面の最終行「Sautéed for 3s · done 19:26」） |
| 04:50 | PR #4022 の cross-review が 3 ラウンドの上限で終わる（保存先の `summary.json`） |
| 04:50 ごろ以後 | PR #4018 はマージ済み。画面の状態行から背景の作業の表示が消える |
| 07:20 | オーガナイザーが画面を見て気づき、入力欄から再開を伝える |
| 07:24 | conductor が設計承認の質問を出す |

この約 3 時間、生死の判定は `alive` のままで、`lane_stalled` のリクエストも `ndf lanes wait` の新しい止まりも出なかった。

## 種類

機能追加（生死の判定が今約束しているのは「conductor のラッパーのプロセスが動いているか」で、「何もしていない conductor を止まりとする」条件は今の SSOT に無い。判定の条件を 1 つ足す）。

## 今の姿

並列の計画のレーンの生死は `ndf.progress.lane.liveness` が判定し、`lane_stalled` のリクエストと `ndf lanes wait` の新しい止まりが、オーガナイザーに手を打つきっかけを渡す。判定はラッパーのプロセスが動いているかで決まるため、conductor が背景の作業を持たないまま来ない通知を待っていても `alive` になる。

## 何を足すか・変えるか

| | 今 | 足した後 |
| --- | --- | --- |
| 生死の判定の条件 | ラッパーのプロセスが動いていれば `alive` | 加えて、conductor の会話の最後の動きから一定の時間が過ぎ、背景の作業（シェル・サブエージェント）が無ければ止まりとする |
| `lane_stalled` の中身 | 止まりの種類と、そのレーンの情報 | 加えて、最後に動いた時刻と、背景の作業が無いこと |
| 閾値 | 無し | `plugins/ndf/contracts/limits.json` の値で変えられる |

## 今の利用者への影響と互換

止まりの判定が 1 つ増えるため、これまで `alive` と出ていた行が `lane_stalled` のリクエストになることがある。承認ゲートや質問の回答を待つ行は、今までどおり止まりにしない。

## 事象

2026-11-22 04:26〜07:20 JST の約 3 時間、lracct の conductor は背景の作業を持たず何もしていなかったが、生死の判定は `alive` のままで、`lane_stalled` のリクエストも `ndf lanes wait` の新しい止まりも出なかった。

## 期待する結果

背景の作業を持たず、一定の時間何もしていない conductor の行が止まりとして `ndf lanes wait` に出て、オーガナイザーが時間をおかずに手を打てる。

## 再現手順

1. 並列の計画のレーンで conductor を起動し、背景の作業の完了の通知を待たせる
2. 背景の作業がすべて終わった後、conductor に通知が届かない状態にする（conductor が応答を終えており、子のプロセスも残っていない）
3. 閾値を超える時間が過ぎても、`ndf lanes wait` に新しい止まりが出ない

## 環境

- NDF 11.0.13（計画 p12 の lracct、2026-11-22）

## なぜ困るか

レーンが何もしないまま時間が過ぎても、オーガナイザーにも利用者にも知らせが届かない。気づく手段は人が画面を見ることだけで、lracct では約 3 時間が失われた。並列の計画のすべてのレーンで同じことが起きうる。

## 目的

- 背景の作業を持たず一定の時間何もしていない conductor を止まりとして知らせ、オーガナイザーが時間をおかずに手を打てるようにする

## 対象範囲

含む:

- 生死の判定（`ndf.progress.lane.liveness`）に「conductor の会話の最後の動きから一定の時間が過ぎ、背景の作業（シェル・サブエージェント）が無い」場合を止まりとして足すこと。何で測るか（会話の記録の最後の行の時刻・中継が持つ状態・画面の状態行）と時間の閾値は設計で決める
- 止まりとして出したときの `lane_stalled` の中身に、最後に動いた時刻と、背景の作業が無いことを載せること

含まない:

- 止まった conductor を自動で起こすこと（まず知らせる。起こし方は知らせの実績を見てから決める）
- 入力待ちのダイアログで止まったレーンを知らせること（#3862・#3877）

## 受け入れ条件

- [ ] 1. 背景の作業が無く、最後の動きから閾値を過ぎた実行中の行が、`lane_stalled` のリクエストになる（テスト）
- [ ] 2. 背景の作業がある行は止まりにならない（テスト）
- [ ] 3. 承認ゲートや質問の回答を待つ行は止まりにならない（テスト）
- [ ] 4. 止まりとして出した `lane_stalled` のリクエストに、最後に動いた時刻と、背景の作業が無いことが載る（テスト）
- [ ] 5. 閾値は `plugins/ndf/contracts/limits.json` の値で変えられ、コードに同じ値を書かない（テスト）

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わる。`lane_stalled` のリクエストに項目が増え、生死の判定が返す止まりの種類が 1 つ増える。既存の項目は消さない |
| 重さ | 何もしていないレーンに誰も気づかない。回避の手段は人が画面を見ることだけで、実測で約 3 時間が失われた |
| データ | 無し（`contracts/limits.json` に閾値を 1 つ足す） |
| 既存の振る舞い | これまで `alive` と出ていた行の一部が止まりになる |
