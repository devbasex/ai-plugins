## 処理の手順

`突き合わせ 2` の行き先ごとの判定（行き先の値の形と、`gh` の結果の組み合わせ）:

| 関数 | 条件の組み合わせ | 結果 |
| --- | --- | --- |
| `突き合わせ 2` | `#<番号>` で、`gh issue view` が失敗した | `状態を取れない: #<番号>` |
| `突き合わせ 2` | `#<番号>` で、状態が `OPEN` | 出力しない |
| `突き合わせ 2` | `#<番号>` で、状態が `OPEN` 以外 | `閉じた行き先: #<番号> <状態>` |
| `突き合わせ 2` | `Z<数>` で、子の表の見出しにある | 出力しない |
| `突き合わせ 2` | `Z<数>` で、子の表の見出しに無い | `子の表に無い記号: Z<数>` |
| `突き合わせ 2` | `作らない` | 出力しない（理由の有無は対応表のレビューで見る） |
| `突き合わせ 2` | 上のどれでもない | `形の違う行き先: <値>` |

`子を起票する` の子ごとの判定（再実行のとき、同じ子を 2 本作らないための判定）:

| 関数 | 条件の組み合わせ | 結果 |
| --- | --- | --- |
| `子を起票する` | 子の題と完全に一致する Issue が無い | 起票する |
| `子を起票する` | 一致する Issue が 1 本あり、親が #3388 | 飛ばす |
| `子を起票する` | 一致する Issue が 1 本あり、親が空 | 起票せず `gh issue edit <番号> --parent 3388` だけを打つ |
| `子を起票する` | 一致する Issue が 1 本あり、親が #3388 以外 | 止めて人へ戻す（ほかの作業が同じ題で起票した） |
| `子を起票する` | 一致する Issue が 2 本以上 | 止めて人へ戻す（どれを残すかは中身を読まないと決まらない） |

題の一致は `題の照合` と同じく、全 Issue の題を取って `grep -Fx` で比べる。`gh issue list --search` は語の一致で引くため、完全な一致の判定に使わない。

- 繰り返しの終わる条件: `突き合わせ 2` は異なる行き先の数（14）だけ回る。`子を起票する` は子の表の 13 本で終わる。`子を起票する` の再試行は 1 本につき 1 回までとし、2 回目も失敗したら止める
- 計算量の注意: `突き合わせ 2` は行き先の Issue ごとに API を 1 回呼ぶ（2026-11-15 は #3412・#3492 の 2 回）。`題の照合` と `子を起票する` の判定は、全 Issue の題の取得を 1 回だけ行い、子ごとに取り直さない

## 内部のデータと定数

| 名前 | 種類 | 置き場 | 既定値 |
| --- | --- | --- | --- |
| 11.x の行の選び方 | 定数 | 対応表の `突き合わせ 1` のコマンド | 行き先の表は 7 列目が `11.x` の行、要求の表は 4 列目が `11.x` の行 |
| 行の識別子の形 | 定数 | 対応表の `突き合わせ 1`・`2`・`3` のコマンド（3 つとも同じ正規表現） | `<4 桁>-<連番>` か `要求 <3 桁>` |
| 子の記号の一覧 | 型 | 子の表の `### Z<数>` の見出し（`突き合わせ 2` が読む） | `Z1`〜`Z13` |
| 子の題 | 型 | 子の表の `**題**:` の行（`題の照合` と `子を起票する` が読む） | 13 行 |
| 一時ファイル | 定数 | 各コマンド | `/tmp/3388-routing.txt`・`map`・`dest`・`children`・`titles`・`drafts` |
| 親の Issue | 定数 | 子の表の節「表の読み方」と決定 6 | `#3388` |
| 種類のラベル | 定数 | 子の表の節「表の読み方」 | `enhancement`（`rebuild-1142` は付けない） |
| `題の照合` の取得の上限 | 設定値 | 設計文書の節「テスト設計」のコマンド | `--limit 4000` |
| 閉じる前のサブ Issue の数 | 定数 | この文書の `#3388 を閉じる` | 15（子 13 本・#3412・#3492）。子の表の一覧の行の数から決まる値で、子の表を変えたら合わせて変える |

**同じ事実を 2 か所に持たない。** 子の記号・題・順番・レーンは子の表だけが持ち、この文書は写さない。行き先は対応表だけが持つ。
記号と Issue の番号の対応は GitHub のサブ Issue の関係と、子の本文の先頭の 1 行だけが持つ（決定 6）。

## 並行と排他

| 同時に走りうる処理 | 共有する資源 | 排他の取り方 | 冪等性と中断からの再開 |
| --- | --- | --- | --- |
| 同じマシンで 2 人が突き合わせのコマンドを打つ | `/tmp/3388-*.txt` | 取らない。打つのは設計者とレビュアーで、同じマシンで同時に打つ場面は設計 PR の間に無い | どのコマンドも一時ファイルを読む前に上書きするため、打ち直せば正しい結果になる |
| 起票の作業と、ほかのレーンの起票 | GitHub の Issue の題 | 取らない。起票の前の題の判定（「処理の手順」）が、同じ題の Issue を見つけたら止める | 判定により、中断の後に打ち直しても同じ子を 2 本作らない |

## 単体テストの観点

このスプリントはテストのファイルを足さない（要求の「前提とする取り決め」）。下の観点は、設計 PR の間にコマンドを打って確かめる。

| 関数 | 正常 | 境界値 | 異常 |
| --- | --- | --- | --- |
| `突き合わせ 1` | worktree の振り分け表と `origin/develop` の振り分け表のどちらを入れても 72 行で差分が無い（行き先の列を書き換えても選ぶ行が変わらない。2026-11-15 に両方で 72 行） | 要求の表の `509〜512`（版は `作らない`）が選ばれない | 対応表から 1 行消すと `>` ではなく `<` の行が 1 行出る / 取得できないときは `git` のエラーの行が出る |
| `突き合わせ 2` | 出力が `検査した行き先: 14` の 1 行だけ | `作らない` の行が指摘を出さない | 行き先を `#3295` にすると `閉じた行き先` が出る / `Z99` にすると `子の表に無い記号` が出る / `gh` が失敗すると `状態を取れない` が出て、`閉じた行き先` は出ない / `X2` にすると `形の違う行き先` が出る |
| `突き合わせ 3` | 出力が件数の表の 14 行と一致する | 1 行だけの行き先（`Z11`・`作らない`）が `1` で出る | 対応表の行を 1 つ足すと、その行き先の数が 1 つ増える |

| `本文を組む` | 先頭の 1 行と 3 節がそろい、hook を通る | 対象範囲の対応表の行が 0 行の子（Z12）でも、対象範囲の節に含むものと含まないものがある | 節を 1 つ欠くと hook が拒む |
