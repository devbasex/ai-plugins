# #880 / #883 / #494 / #723 / #885: cross-refactoring を是正して、構造改善の工程を戻せる状態にする — 要求と受け入れ条件

設計は [issue-880-885-design.md](issue-880-885-design.md)、決定の理由は
[issue-880-885-design-decisions.md](issue-880-885-design-decisions.md) にある。この文書は「何を満たすか」だけを扱う。

マイルストーンは「17 トークン消費の削減」。版は 10.17.x（PATCH）で出す。5 つの課題は、どれも
「構造改善（`cross-refactoring`）を当面通さない」という利用者の指示（2026-09-23）を解く条件にあたる。
そのため 1 本の設計 Pull Request にまとめ、**戻してよいと判断する受け入れ条件**（AC20〜AC23）を同じ文書に置く。

## 例: PR #844 の検査の持ち場を、この変更の後にやり直すと

PR #844（#829 #830）の `--scope` は 6 ファイルだった。`--baseline-test` にはリポジトリの全体テスト
（5090 件）が渡された。

| 項目 | 今（実測） | 変更の後 |
| --- | --- | --- |
| 群 1 つの検証で走るテスト | 全体テスト（1 群あたり約 8 分） | `--round-test` に渡した範囲のテスト（`plugins/ndf/scripts/tests/test_token_guard.py`。数秒） |
| 全体テストを走らせる回数 | 着手前 1 回 ＋ 群ごと ＋ 修正コミットごと | 着手前 1 回 ＋ 最終ゲート 1 回 |
| 現状固定テスト 10 項目にかかった時間 | 約 90 分（構造改善のラウンドへ入れず打ち切り） | テストの時間は 10 項目で 1 分未満。残りは参加 CLI の提案と適用の時間 |
| テストが打ち切られたとき | 子がすぐ終わっても猶予の 5 秒を待ち切る | 子が終わった時点で戻る |
| テスト整備ラウンドが `.md` を読むテストを足したとき | そのまま採る。後の文書の整理が「期待する振る舞いの変更」で取り消される | 提案の時点で外し、適用の検証でも弾く |

文書だけを変える Pull Request（例: #489 のうち本番コードが 1 行、#520 / #521 の Markdown だけの変更）では、
`refactor.py assess` が「飛ばしてよい」を返す。検査の持ち場は構造改善を通さず、飛ばした理由を
記録と Pull Request の本文に残す。

## 目的

- **群ごとの検証を範囲のテストで行う（#880）。** 全体テストは着手前と最終ゲートの 2 回に限る
- **テストの打ち切りが猶予を待ち切らないようにする（#883）**
- **構造改善を飛ばしてよい条件を決め、差分から機械で判定する（#494）。** 飛ばしたことが通し忘れと区別できる形で残る
- **テスト整備ラウンドが `.md` の文言を固定するテストを足さないようにする（#723）**
- **リポジトリにある `.md` の文言固定テストを削り、置かない方針を規約にする（#885）**
- **上の 5 つが済んだ後に、構造改善を戻してよいかを判断できる条件を持つ**

## 対象範囲

含む:

- `cross-refactoring` に、群と修正コミットの検証に使うテストの引数 `--round-test` を足す。全体テストの実行を着手前と最終ゲートへ寄せる（#880）
- `--round-test` を渡さずに、`--baseline-test` の実行集合が範囲より広いときの案内（#880）
- 検証の記録に所要の秒数を足す（#880。AC21 の測定に使う）
- `development-workflow` の検査の持ち場が `--round-test` と `--baseline-test` を決める基準（#880）
- `run_with_timeout` の打ち切りの修正と、打ち切りの 3 つのテストの待ちの短縮（#883）
- 構造改善を飛ばしてよい条件の判定（`refactor.py assess`）と、`workflow-modes.md`「構造改善の退避先」の書き換え（#494）
- テスト整備ラウンドの提案の基準（`propose-tests.md`）、提案の取り込みでの除外、適用の検証での除外（#723）
- `.md` の文言を照合する pytest の削除と、参照切れの検査の検査スクリプトへの移し替え（#885）
- テストを書く規約（`tdd-cycle`・`quality-gates`・`AGENTS.md`）への方針の追記（#885）
- 構造改善を戻してよいかの判断の条件と、判断する場所（AC20〜AC23）

含まない:

- 適用を並列にすること（#755 #754）、cross-refactoring の駆動を `scripts/` へ寄せること（#560 #870）
- テストの一般的な高速化（#390 #884 の残り）
- cross-review の母集合・待ち方（#892 #901。別の supervisor が実装中）と区間の再起動（#895）
- `projects-sync.sh` の引数の形（飛ばした理由は既存の工程の記録と Pull Request の本文で残す。決定 6）
- `--scope` をファイルより細かく絞ること（#622）
- 設計の成果物のうちクラス図・画面・データの図: 足すのは既存のモジュールへの関数と引数 1 つ、状態ファイルの欄 2 つ（`round_test`・`seconds`）で、新しい型も画面も永続データの構造も持たないため対象が無い。状態ファイルの欄は設計文書の「入出力の契約」に書く

## 受け入れ条件

- [ ] AC2: `verify-round`（群の検証）と、修正ラウンド・最終ゲートの修正のコミットの検証が、`round_test` のコマンドを実行する。`baseline_test` のコマンドを実行しない

## 前提

- 前提 1: 全体テストは並列実行で約 1 分（#882 の後。5356 件で約 53 秒）。群ごとの全体テストの費用は #880 の実測（約 8 分）より小さいが、群と修正コミットの数だけ積み上がる。範囲のテストなら数秒で終わる
- 前提 2: 範囲の外の振る舞いは、群ごとの検証では変わらない。範囲外を触ったコミットは今も失敗になる（`SKILL.md` の「範囲の扱い」）。範囲の外への波及は最終ゲートの全体テストが見る
- 前提 3: 構造改善の所要の中央値は 1 本の Pull Request あたり 75.9 分で、cross-review の約 5 倍（#494 の 2026-09-01〜09-15 の実測）
- 前提 4: `.md` の文言を照合するテストは、プロンプトの振る舞いを保証しない。同じ文面から同じ結果が返るわけではない（#885 の方針。利用者の判断 2026-09-23）

## 非機能の条件

| 項目 | 条件 |
| --- | --- |
| 互換 | `--round-test` を渡さない起動と、変更の前の状態ファイルの再開は、今と同じ検証をする（AC1・AC7） |
| 費用 | 全体テストの実行は 1 回の cross-refactoring あたり 2 回（AC3） |
| 安全 | 範囲の外への波及を見落とさない。最終ゲートで全体テストを 1 回通す（AC3） |
| 止まり方 | 打ち切りの後に子が残らない（AC10） |

## 依頼（原文）

#880:

> `cross-refactoring` が、変更範囲の広さに関係なく、1 項目を適用するたびに `--baseline-test` のテストを丸ごと回している。範囲が狭い変更でも、1 項目あたりの待ち時間がリポジトリ全体のテスト時間で決まる。

#883:

> `run_with_timeout` がテストを打ち切ると、子がすぐ終わっても毎回 `kill_grace`（既定 5 秒）を待ち切る。

#494:

> `cross-refactoring` を飛ばしてよい条件が、どの Skill にも書かれていない。

#723:

> `.md` の文言を固定するテストは、変更の種類にかかわらず原則として置かない。`cross-refactoring` のテスト整備ラウンドも同じ扱いにする。

#885:

> `.md`（`SKILL.md`・`references/`・`prompts/`・`docs/` など）の文言を固定するテストは、原則として置かない。

## 用語

| 用語 | 意味 |
| --- | --- |
| 範囲のテスト | `--scope` のテストの置き場所だけを走らせるテストのコマンド。`--round-test` に渡す |
| 全体テスト | リポジトリのテストの全体。`--baseline-test` に渡す |
| 群 | 適用ラウンド。書き換えるファイルが重ならない項目の集まりで、1 コミットにまとめて検証する |
| 本番コード | コードの拡張子を持ち、テストの置き場所でないファイル（決定 5） |
| 文言固定テスト | リポジトリで追跡している `.md` を読み、その文字列・見出し・表の並びを照合するテスト |
| 飛ばす / 退避する | 飛ばす: 構造改善の工程で何も起動しない。退避する: `cross-refactoring` の代わりに `refactoring` 単独で進める |
