# #550 / #657: 工程を president / supervisor / worker の 3 層で通し、context window を測る

設計は [issue-550-657-design.md](issue-550-657-design.md) にある。この文書は「何を満たすか」だけを扱う。

**2 つの課題を 1 本の設計 Pull Request で決め、実装は 3 本に分ける**（分け方と順序は設計文書が持つ）。
受け入れ条件は主題ごとに並べ、どの実装 Pull Request が満たすかは設計文書の表が対応を持つ。

| 主題 | 課題 | 中身 |
| --- | --- | --- |
| A 無人の運転 | #550 | `/goal` の工程を 3 層（president / supervisor / worker）へ出し、2 つの関門以外を人間の入力なしで通す |
| B context window の測定 | #550 | 層ごとの固定費・最大充填・実作業を会話の記録から測り、振り返りへ集計を出す |
| C 中断と再開 | #657 | 利用上限（429）で落ちた層を上の層が見分け、解除を待って再開する |

## 目的

- `/goal /ndf:development-workflow <指示>` が、**2 つの関門以外は人間の入力なしで**、複数の課題を設計から振り返りまで通す
- 1 つの context window が劣化の域へ入る前に工程の境で区切り、後の工程の判断を悪くしない
- 粒度とモデルの割り当てを、導入したリポジトリの実測で決められる。**層を増やすと固定費の合計が増える**ことを、測った値で見える形にする
- 利用上限で落ちても、人が「続けて」と指示しなくても工程が再開する

## 3 層の役割

| 層 | 何者か | 人間へ問えるか | 起動する相手 |
| --- | --- | --- | --- |
| president | 人間と対話しているセッション。`/goal` を受ける | **問える**（`AskUserQuestion`） | supervisor |
| supervisor | 1 つの持ち場（連続する工程の束）を通すサブエージェント | 問えない | worker |
| worker | 1 つの作業（調査・読解・修正・テストの実行・集計）を行うサブエージェント | 問えない | 起動しない |

## 実測（要求の根拠）

**#550 の本文の実測に、#657 のための実測を足した。** 走査したのは
`~/.claude/projects/-work-ai-plugins/` の記録である（2026-09-17 時点）。**記録を取った時点の運転は
2 層（人間と対話するセッションと、その下のサブエージェント）だった。** 下の実測の「上の層」は
いまの president、「下の層」は supervisor と worker の両方に当たる。

### 下の層が利用上限で落ちたとき、上の層に何が届くか

**上の層には失敗の通知が届く。** 本文に種別と解除時刻が入っている（2026-09-01、Claude Code 2.1.252）。

```text
<task-notification>
<task-id>aad4dc48e9699f55e</task-id>
<status>failed</status>
<summary>Agent "Fix PR 213 round 2" failed: Agent terminated early due to an API error:
You've hit your session limit · resets 3:40pm (UTC) (error type rate_limit, HTTP 429, ...)</summary>
<note>... The user can send it another message and resume it, so the same task-id may notify more than once.</note>
```

**落ちた側の記録にも同じ中断が残る。** 最後の行は合成の応答で、解除時刻を数値で持つ。

| キー | 値の例 | 意味 |
| --- | --- | --- |
| `isApiErrorMessage` | `true` | API の失敗を表す合成の応答 |
| `error` / `apiErrorStatus` | `rate_limit` / `429` | 種別（他に `server_error` / `authentication_failed` を観測） |
| `message.model` | `<synthetic>` | 合成の応答。`usage` はすべて 0 |
| `quotaLimits.rateLimitType` | `five_hour` / `seven_day` | 上限の種類 |
| `quotaLimits.resetsAt` | `1789452000` | 解除時刻（UNIX 秒） |

### 上の層も同じ上限に当たる

**通知を受けた上の層の応答も、同じ上限で失敗する。** 同じアカウントの割り当てを使うためである。
2026-09-14 の進行（2.1.265）では、3 本の失敗の通知を受けた上の層の 3 回の応答が、いずれも
1 秒以内に `You've hit your session limit` で終わった。**上限の間、上の層は何もできない。**
**層を 3 つにしても、割り当ては 1 つである。**

### 解除の後に Claude Code が自動で続けた例が 1 つある

**週次の上限の解除時刻ちょうどに、人間と対話しているセッションへ入力が積まれた**（2026-09-15 06:00:41、2.1.265）。

```text
system: Usage limit reset · continuing automatically
user（origin: auto-continuation）: Your claude.ai usage limit has reset. Continue the task you were
working on when the limit was reached; do not repeat work that is already complete.
```

そのセッションはこの入力で目を覚まし、中断した相手を `SendMessage` で再開した（`Resuming agent`）。
**再開の手順は会話の場で組み立てたもので、規約には無い。** 同じ日のセッション上限では、
利用者がアカウントを切り替えて「続けて」と送っていた（11:54）。**自動の継続を観測したのは
全記録でこの 1 回（ai-plugins）と別リポジトリの 1 回だけである。**

### `/goal` の見回りは止まる

背景の作業を待つ間、`/goal` は「Goal check-in」を積む。間隔は 30 分 → 61 分 → 120 分と
伸び、**120 分の後は `idle check-ins paused until your next message` で止まった**。
見回りに頼って再開を待つと、長い上限の間に見回りが尽きる。

### 記録は応答を複数行に分けて持つ

**同じ `message.id` の行が並ぶ。** 1 本のサブエージェントで assistant の行が 212 行、固有の応答は 126 件だった。
行の数を応答数として数えると 7 割近く多く出る。起動時の `description` は
`subagents/agent-<id>.meta.json` にそのまま残り（28 件で一致）、`spawnDepth` が層の深さを持つ。

## 用語

| 語 | この文書での意味 |
| --- | --- |
| セッション | 会話を保持しているプロセス。1 つのセッションが 1 つの context window を持つ |
| president | 人間と対話しているセッション。`/goal` を受け、supervisor を起動し、報告を受け取り、関門で人間に問う |
| supervisor | 1 つの持ち場（連続する工程の束）を通すサブエージェント。工程の Skill を起動し、進行を記録し、worker を起動する |
| worker | 1 つの作業を行うサブエージェント。終われば消え、supervisor には作業の報告だけが残る。別のサブエージェントを起動しない |
| 持ち場 | supervisor 1 つが通す工程の束。`設計` / `実装` / `検査` / `取り込み` / `仕上げ` の 5 つを初期値にする |
| 作業の種類 | worker 1 つが行う作業の分類。`調査` / `修正` / `検証` / `集計` / `その他` |
| context window | セッションが保持している内容の全体と、その量。捨てると前の内容は残らない |
| 固定費 | context window が作業を始める前に既に埋まっている量。**初回の応答の入力トークン**（`input_tokens` + `cache_read_input_tokens` + `cache_creation_input_tokens`） |
| 最大充填 | 応答ごとの同じ合計の最大 |
| 実作業 | 最大充填 − 固定費 |
| 合成の応答 | API を呼ばずに Claude Code が記録へ書いた応答。`message.model` が `<synthetic>` |
| 中断 | 層が API の失敗で途中で終わること。利用上限（429）による中断を**上限の中断**と呼ぶ |
| 解除時刻 | 上限が解ける時刻。通知の文言と記録の `quotaLimits.resetsAt` が持つ |
| 自動の継続 | 解除時刻に Claude Code が president へ積む入力（`origin.kind` が `auto-continuation`） |
| 報告 | 下の層が最後に返す、項目の決まった結果。supervisor と worker で形が違う |

**この用語は実装で触る規約の文書にも当てる**（AC16）。層の語は `president` / `supervisor` / `worker`、
量を指す語は `context window` と書く。`monitor.py` の文脈窓や窓口のように別のものを指す語は対象外である。
