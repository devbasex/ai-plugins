# #3503 の詳細設計: cherry-pick-pr の手順 3・5・6 と、原則 3・使い分けの表の書き直し

設計文書 [issues/issue-3503-design.md](issue-3503-design.md) の「構成要素」と「処理の流れ」を、ファイルと手順の粒度へ下ろした文書である。

この変更が触るのは Skill の本文（Markdown）だけで、プログラムのコードを持たない。**この文書の「関数」は、Skill の本文の手順（`### <番号>. <見出し>` の 1 節と、その中のコマンドのブロック）を指す。** 手順を実行するのは Skill を読んだ AI で、コマンドは利用者の作業ディレクトリの bash で打たれる。

## 用語の対応

| この文書の語 | 本文の書き方 | 意味 |
| --- | --- | --- |
| 環境ブランチ | `<base-branch>`（手順 4・7 の既存の置き場の名前を引き継ぐ） | 引数で受けた宛先。`qa/staging` など |
| 開発のベースブランチ | `$dev_base`（手順 1 が決める） | `.ndf/worktree.json` の `base_branch` か、origin の HEAD が指す先 |
| 短命ブランチ | `<current-branch>-for-<base-short-name>`（手順 4 が作る） | 環境ブランチの先端から切ったブランチ |
| 選んだコミット | 手順 3 で利用者が決めたハッシュの列 | 古い順に並べ直したもの |
| 飛ばしたコミットの列 | 報告に並べるハッシュの列 | 手順 5 で空になったものと、手順 6 の rebase で落ちたもの。元のコミットのハッシュで並べる |

## 処理の手順

手順 3・5・6 の書き直した本文のコマンドの全文を置く。プレースホルダーの形は今の本文（`<base-branch>`・`$dev_base`）に合わせる。

**手順 3（コミット一覧の確認）**

```bash
# 1 つ目: feature ブランチにあって開発のベースブランチに無いコミット（今の一覧）
git fetch origin "$dev_base" <base-branch> || exit 1
git log --oneline "origin/$dev_base"..HEAD
# 1 つ目が空のときだけ 2 つ目: HEAD にあって環境ブランチに無い変更のコミット
# （ベースブランチへマージ済みの修正を選ぶため。--cherry-pick で同じ変更が環境ブランチにあるものを除く）
git log --oneline --no-merges --cherry-pick --right-only "origin/<base-branch>...HEAD"
```

| 関数 | 条件の組み合わせ | 結果 |
| --- | --- | --- |
| `手順3 コミット一覧の確認` | 1 つ目が 1 件以上 | 1 つ目だけを出し、利用者が選ぶ（今の使い方） |
| `手順3 コミット一覧の確認` | 1 つ目が 0 件、2 つ目が 1 件以上 | 2 つ目を出し、利用者が選ぶ |
| `手順3 コミット一覧の確認` | 1 つ目も 2 つ目も 0 件 | 利用者にハッシュを求める。受けるまで手順 4 へ進まない |
| `手順3 コミット一覧の確認` | 選んだコミットが決まった | `git log` の出力は新しい順なので、古い順へ並べ直して手順 5 へ渡す |

**手順 5（cherry-pick 実行）**: 選んだコミットを古い順に 1 件ずつ、次のブロックで打つ。

```bash
h=<コミットのハッシュ>
git cherry-pick -x "$h" || {
  if ! git rev-parse -q --verify CHERRY_PICK_HEAD >/dev/null; then
    # 始まらなかった（merge のコミット・ハッシュの誤り）。空と取り違えない
    echo "❌ $h を cherry-pick できません。選び直してください" >&2; exit 1
  elif [ -z "$(git diff --name-only --diff-filter=U)" ] && git diff --cached --quiet; then
    # 空になった（同じ変更がすでに環境ブランチにある）
    git cherry-pick --skip && echo "SKIPPED $h"
  else
    # 衝突。解消して git add し、git cherry-pick --continue で続ける
    git diff --name-only --diff-filter=U
  fi
}
```

| 関数 | 条件の組み合わせ | 結果 |
| --- | --- | --- |
| `手順5 cherry-pick 実行` | 終了コード 0 | 当たった。次のコミットへ |
| `手順5 cherry-pick 実行` | 失敗・`CHERRY_PICK_HEAD` が無い | 止める。そのハッシュを選び直す |
| `手順5 cherry-pick 実行` | 失敗・`CHERRY_PICK_HEAD` がある・未解決のファイルが無い・索引に差分が無い | 空。`--skip` して `SKIPPED` を出し、列に載せる |
| `手順5 cherry-pick 実行` | 失敗・`CHERRY_PICK_HEAD` がある・未解決のファイルがある | 衝突。解消して `--continue`。解消の内容を報告に書く |

- 繰り返しの終わる条件: 選んだコミットをすべて打ち終えたとき。始まらなかったコミットがあれば、そこで止まる
- 計算量の注意: 無し（選ぶコミットは利用者が数件を選ぶ）

**手順 6（宛先の最新の取り込み）**

```bash
git fetch origin <base-branch> || exit 1
# -x の行（元のコミットのハッシュ）を rebase の前後で比べ、rebase で落ちたコミットを見つける
pick='s/^(cherry picked from commit \([0-9a-f][0-9a-f]*\))$/\1/p'
before=$(git log --format=%B "origin/<base-branch>"..HEAD | sed -n "$pick" | sort -u)
git rebase "origin/<base-branch>" || {
  git diff --name-only --diff-filter=U
  git rebase --abort
  echo "❌ 宛先の環境ブランチと衝突したため push しません" >&2; exit 1
}
after=$(git log --format=%B "origin/<base-branch>"..HEAD | sed -n "$pick" | sort -u)
# rebase で落ちたコミット（飛ばしたコミットの列に足す）
comm -23 <(printf '%s\n' "$before") <(printf '%s\n' "$after")
[ "$(git rev-list --count "origin/<base-branch>"..HEAD)" -gt 0 ] ||
  echo "NO_COMMITS: 環境ブランチへ足すコミットがありません。push と Pull Request の作成をしません"
```

| 関数 | 条件の組み合わせ | 結果 |
| --- | --- | --- |
| `手順6 宛先の最新の取り込み` | 取得に失敗 | 止める。push しない |
| `手順6 宛先の最新の取り込み` | 環境ブランチが手順 4 から進んでいない | rebase は何もしない。足すコミットは手順 5 のまま。手順 7 へ |
| `手順6 宛先の最新の取り込み` | 進んでいて、衝突しない | 先端へ付け直す。落ちたコミットを列に足す。足すコミットが 1 件以上なら手順 7 へ |
| `手順6 宛先の最新の取り込み` | 進んでいて、衝突する | `--abort` して止まる。手順 8 へ |
| `手順6 宛先の最新の取り込み` | 足すコミットが 0 件 | `NO_COMMITS` を出し、手順 7 を飛ばして手順 8 へ |

- 繰り返しの終わる条件: 繰り返しは無い。手順 6 は 1 回だけ打つ（push の直前に 1 回）
- 計算量の注意: 無し

上の 3 つのブロックの形は、使い捨てのリポジトリ（git 2.53.0、2026-11-14）で次を確かめた。

| 確かめたこと | 結果 |
| --- | --- |
| 環境ブランチにすでにある修正を cherry-pick | 終了コード 1、`CHERRY_PICK_HEAD` がある、未解決のファイルが無い、索引に差分が無い。`--skip` は終了コード 0 |
| merge のコミットを `-m` 無しで cherry-pick | 終了コード 128、`CHERRY_PICK_HEAD` が無い、未解決のファイルが無い、索引に差分が無い（`CHERRY_PICK_HEAD` を見ないと空と取り違える） |
| 存在しないハッシュを cherry-pick | 上と同じ（終了コード 128、`CHERRY_PICK_HEAD` が無い） |
| 手順 5 の後に環境ブランチへ同じ修正が入ってから手順 6 | rebase は終了コード 0、`comm -23` が落ちた元のハッシュを 1 件出す、`git rev-list --count` は 0、`git merge-base --is-ancestor` は 0 |
| 手順 6 の rebase で衝突 | rebase は終了コード 1、未解決のファイルが出る。`--abort` は終了コード 0 で、`git status --short` は空 |

## 内部のデータと定数

| 名前 | 種類 | 置き場 | 既定値 |
| --- | --- | --- | --- |
| 選んだコミットの列 | 型（ハッシュの並び、古い順） | 手順 3 で決まり、AI が手順 5 まで持つ（シェルの変数は呼び出しをまたいで残らない） | 無し（利用者が決める） |
| 飛ばしたコミットの列 | 型（元のコミットのハッシュの並び） | 手順 5 の `SKIPPED` の行と、手順 6 の `comm -23` の出力から AI が組み、報告に載せる | 空 |
| `pick` | 定数（`-x` の行から元のハッシュを抜く `sed` の式） | 手順 6 のブロックの中だけ | `s/^(cherry picked from commit \([0-9a-f][0-9a-f]*\))$/\1/p` |
| `before` / `after` | 型（元のハッシュの並び、整列して重複を除いたもの） | 手順 6 のブロックの中だけ | 無し |

`-x` の行の形（`(cherry picked from commit <ハッシュ>)`）は git が決める。NDF の中に同じ形を持つ定数は無く、`pick` を唯一の置き場にする。ハッシュの桁数を固定しないのは、SHA-256 のリポジトリ（64 桁）でも同じ式で抜けるようにするためである。

## 並行と排他

| 同時に走りうる処理 | 共有する資源 | 排他の取り方 | 冪等性と中断からの再開 |
| --- | --- | --- | --- |
| 手順 4〜6 の間に、ほかの利用者が環境ブランチへマージする | origin の環境ブランチ | 取らない。手順 6 で push の直前に取得し直して rebase する（I2）。手順 6 と手順 7 の間に入ったマージは、Pull Request の側で「最新にする」の検査が知らせる | 手順 6 は打ち直せる（rebase 済みならもう一度打っても付け直すだけ） |
| 同じ作業ディレクトリでの別の git 操作（ほかのセッション・hook） | 作業ツリー・索引・HEAD | 取らない。手順 4 から 8 は 1 つの作業ディレクトリで 1 回ずつ走る前提（今と同じ）。worktree を分けていれば重ならない | 手順 5 の途中で止まったら `git cherry-pick --abort` で手順 5 の前へ戻せる。手順 6 は失敗した時点で `--abort` 済み |
| 同じ短命ブランチの名前を使う別の実行 | origin の短命ブランチ | 手順 2 のマージ済みの確認と、作り直しの側の手順 4 の止まり方（今と同じ。この変更で触らない） | 変えない |

## 単体テストの観点

`.md` の文言を照合するテストは書かない（`AGENTS.md`）。観点は、使い捨てのリポジトリで状態を作り、書き直した本文のブロックをそのまま打って確かめる（設計文書の「テスト設計」、受け入れ条件 9）。

| 関数 | 正常 | 境界値 | 異常 |
| --- | --- | --- | --- |
| `手順3 コミット一覧の確認` | feature ブランチに未マージのコミットがあると、1 つ目の一覧に出る | 修正がベースブランチへマージ済みで 1 つ目が 0 件のとき、2 つ目に出る。2 つ目は同じ変更が環境ブランチにあるものを出さない | 取得の失敗で止まる。2 つとも 0 件ならハッシュを求め、手順 4 へ進まない |
| `手順5 cherry-pick 実行` | 選んだ 1 件が当たり、`-x` の行を持つ。`origin/<base-branch>..HEAD` がその 1 件だけ | 選んだ全件が空で飛ばされる（短命ブランチは環境ブランチの先端のまま）。空のコミットができない | 空は `SKIPPED` で飛ばす。衝突は未解決のファイルを出して止まる。merge のコミットと誤ったハッシュは飛ばさずに止まる |
| `手順6 宛先の最新の取り込み` | 環境ブランチが手順 4 から進んでいなくても通り、足すコミットが手順 5 のまま | 手順 4 の後に環境ブランチへ別のコミットが入ると、`git merge-base --is-ancestor` が 0。選んだ 2 件のうち 1 件が宛先に入ると、その元のハッシュだけが `comm -23` に出る。全件が落ちると `NO_COMMITS` | 取得の失敗で止まる。衝突すると `--abort` され、`git status --short` が空で、push に進まない |
