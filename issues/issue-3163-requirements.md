## 目的

- **今どうなっているか**: ndf v10.27.61 のブランチ運用の宣言（`.ndf/worktree.json` の `branch_flow`。#3121）は、スプリントの起点（`start`）・ベースブランチへ入れる時点（`integrate`）・文書の PR の宛先（`doc_prs`）・本番への取り込み方（`promotion`）の 4 項目だけを持つ。どの PR で何をレビューするかを書く項目は無く、プランの雛形に決め打ちである（前提 1 の表）
- **困っていること**: ai-plugins はブランチ運用の切り替え（#3119）で「実装 PR → スプリントブランチ → ベースブランチ / リリースブランチ → 本番チャネル」と PR が分かれる。どの PR で何をレビューするかを決めないと、同じ差分を何度もレビューするか、どこでもレビューされない差分が出る。リリースブランチの PR に何を掛けるかは、今は決まっていない
- **変えると何が成り立つか**: リポジトリが宣言で、PR の種類ごとに掛けるレビューと対象の差分を選べる。宣言の無いリポジトリは今と同じに動く。#3119 はその宣言の値として ai-plugins のルールを書ける

## 前提

- 前提 1: 宣言が無いときの今の振る舞い（ndf v10.27.61 のコードで確かめた。`plugins/ndf/scripts/supervise_lib/` の `templates.py`・`sprint_bundles.py`・`sprint_waves.py`・`sprint_close_steps.py`・`release_templates.py`）を既定値とする

  | PR の種類 | cross-review | cross-refactoring | 振る舞いの確認 | 対象の差分 |
  | --- | --- | --- | --- | --- |
  | 実装 PR | 課題のまとまりの記録があるときだけ掛ける（#3081） | 掛けない | 掛けない | PR の差分全体 |
  | スプリントの PR | まとまりの記録が無いときだけ掛ける | 掛ける（リファクタリングを止める条件に当たれば外す） | 掛ける | PR の差分全体。pace `fast` の検査は未検査の差分、最後の検査はそのスプリントの PR に絞る（#3126） |
  | リリースブランチの PR | 掛けない | 掛けない | 掛けない | — |
  | 設計 PR | 掛ける（上限 3 ラウンド） | 掛けない | 掛けない | PR の差分全体 |
  | 確定仕様化の PR | 掛けない | 掛けない | 掛けない | — |

- 前提 2: リファクタリングを止める条件（`refactor_suspended`。CI テストの宣言の無いリポジトリなど）は、宣言より先に効く。宣言が cross-refactoring を選んでも、条件に当たれば今と同じく外す
- 前提 3: 宣言は「レビューを掛けるか・どの差分に掛けるか」だけを持つ。cross-review のラウンドの上限・レビューの組・観点は今の値のまま変えない
- 前提 4: レビューの単位は `branch_flow` の中に置き、この課題の版を #3119 より先に出す。#3119 はこの課題の版で、ブランチの流れとレビューの単位をまとめて宣言する
- 前提 5: 宣言を読むのはメインディレクトリの設定からで、Pull Request の変更だけでは効かない（`branch_flow` の既存の扱いと同じ）

## 対象範囲

含む:
- `branch_flow` へレビューの単位の項目を足すスキーマ・許す値・既定値・組み合わせの検査
- 宣言を読んでレビューのステップを組むプランの雛形（実装・検査・最後の検査・リリース・設計・確定仕様化）
- `plugins/ndf/skills/worktree/references/declaration.md` の書き方と例
- `project-decl.py measure`・`drift` の対象への追加
- 目録（`sprint.json` の `ブランチ運用`）への書き込みと、そこからの読み直し

含まない:
- ai-plugins の宣言の値そのもの（#3119）
- cross-review・cross-refactoring・振る舞いの確認の中身（ラウンドの上限・観点・予算）の変更
- 既存のリポジトリの宣言の書き換え

## 用語

| 用語 | 意味 |
| --- | --- |
| レビューの単位 | PR の種類ごとに、掛けるレビューと対象の差分を決めた組。ブランチ運用の宣言の中に書く |
| PR の種類 | NDF のプランが出す PR の分け方。実装 PR・スプリントの PR・リリースブランチの PR・設計 PR・確定仕様化の PR の 5 つ |
| スプリントの PR | スプリントブランチからベースブランチへ出す、検査のプランの PR |
| リリースブランチの PR | 選んで集める取り込み方（`promotion: selected`）で、リリースブランチから本番チャネルへ出す PR |
| 対象の差分 | レビューに渡す差分の取り方。PR の差分全体・未検査の差分・衝突の解消の差分・掛けないの 4 つ |
| 未検査の差分 | 前回の検査の後に入った差分。最後の検査の範囲（#3126）と同じ取り方 |
| 衝突の解消の差分 | スプリントブランチをリリースブランチへ集めるマージのコミットが、親のどちらにも無い形で持つ差分（衝突の解消と組み合わせで生じた変更） |
| 振る舞いの確認 | 検査のプランが cross-review の後に通す、振る舞いの対象を確かめるステップ |

## 受け入れ条件

- [ ] 1. `branch_flow` のレビューの単位の項目で、PR の種類 5 つのそれぞれに、掛けるレビュー（cross-review・cross-refactoring・振る舞いの確認の組）と対象の差分（PR の差分全体 / 未検査の差分 / 衝突の解消の差分 / 掛けない）を書ける。書いた値は `branch_flow` の読み分け（`plugins/ndf/scripts/lib/branch_flow.py`）が返す値に現れる
- [ ] 2. 書いた値のとおりに、プランの雛形がレビューのステップを置く・外す。PR の種類ごとに、宣言で選んだレビューのステップだけがプランの `steps` に現れ、選ばなかったレビューのステップは現れない
- [ ] 3. 宣言の無いリポジトリと、`branch_flow` にレビューの単位の項目を書かない宣言は、前提 1 の表と同じレビューのステップを組む（退行しない）。比べる対象は、実装（まとまりの記録あり / 無し）・検査・pace `fast` の検査と最後の検査・リリース・設計・確定仕様化の各プランの `steps` の `id` と `drive` の並び
      前提の確認: 今の振る舞いはコードを読んで確かめた（`sprint_bundles.with_review`・`without_review`、`templates._inspect_steps`、`sprint_waves` の設計のレビューのまとまり、`sprint_close_steps` の確定仕様化、`release_templates` のリリース）。既存のテストでは `test_bundled_sprint_has_one_reviewed_impl_plan_per_bundle`・`test_bundled_impl_plan_reviews_before_ready_on_the_ci_route` が実装と検査の側を固定している。手元のテストは CI テストの宣言で止められるため、CI で確かめる
- [ ] 4. 対象の差分に「衝突の解消の差分」を選んだリリースブランチの PR では、レビューに渡す差分が、スプリントブランチを集めたマージのコミットのうち衝突の解消と組み合わせで生じた変更だけになる。衝突の無いマージだけで組んだリリースブランチでは、渡す差分が空になり、レビューを打たずに次のステップへ進む
- [ ] 5. 実装の差分（課題の変更）が、実装 PR・スプリントの PR・リリースブランチの PR のどれでも cross-review されない宣言は、読む側（`supervise.py new sprint` など）が直すキーとその理由を出して終了コード 2 で止まり、プランを作らない
- [ ] 6. PR の種類に合わない対象の差分（「衝突の解消の差分」をリリースブランチの PR 以外へ書く、`promotion: whole` でリリースブランチの PR の値を書く、など）は、直すキーと許す値を出して終了コード 2 で止まる。既定値の行へは倒さない
- [ ] 7. 知らないキー・表に無い値は、`branch_flow` の既存の 4 項目と同じく、直すキーと許す値を出して終了コード 2 で止まる
- [ ] 8. `declaration.md` に、レビューの単位の項目の表（キー・値・既定・意味）と、成り立たない組み合わせの規則と、宣言の例が 1 つ以上ある。例をスキーマ（`plugins/ndf/skills/worktree/schemas/worktree.schema.json`）と読み分けの検査に通すと、どちらも通る
- [ ] 9. 動いているスプリントは、開始時に目録（`sprint.json` の `ブランチ運用`）へ書いたレビューの単位のまま進む。開始の後にメインディレクトリの宣言を変えても、同じスプリントのプランの打ち直しで組むレビューのステップは変わらない
- [ ] 10. `project-decl.py measure` の結果に、PR の種類ごとのレビューの単位の推定（測れなければ「不明」）が載る
- [ ] 11. `project-decl.py drift` が、宣言（無ければ既定値）と measure の結果のレビューの単位のずれを、PR の種類ごとに出す

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 性能・拡張性 | 宣言の無いリポジトリでは、1 スプリントで起動するレビュー（cross-review・cross-refactoring の起動の回数）が変わらない（受け入れ条件 3 のプランの比較で確かめる） |
| 運用・保守性 | 組み合わせの誤りの出力は、直すキー（`branch_flow.<キー>` の形）と理由を 1 件 1 行で出す（`branch_flow` の既存の `FlowError` の形にそろえる） |
| 移行性 | 既存の宣言はそのまま通る（項目を足すだけで、既存の 4 項目の値と意味を変えない）。移行の手順は要らない |
