## 原因（2026-11-15、要求の作成のときにコードを読んで確かめた）

### 事象 1

設計承認の依頼（`kind: gate1`）を組む関数 `request_gate1`（`plugins/ndf/scripts/lib/parallel_lane.py:425`）を呼ぶのは、開発ループのレーンの `lane_gate1`（`plugins/ndf/scripts/lib/sprint_loop_gate.py:422`）だけである。

```text
$ grep -rn "request_gate1" plugins/ndf/scripts --include=*.py | grep -v /tests/
plugins/ndf/scripts/lib/parallel_lane.py:425:def request_gate1(
plugins/ndf/scripts/lib/sprint_loop_gate.py:422:        rid = parallel_lane.request_gate1(
```

1 スプリントのレーンは設計承認ゲートで `AskUserQuestion`（`metadata.source: ndf-gate:1`）を出す。問いの hook（`plugins/ndf/scripts/hook_lib/ask_guard.py` の `forward_to_organizer`）は、通す問いを区分によらず `parallel.py request-ask` へ渡し、`request_ask`（`parallel_lane.py:404`）が `kind: ask` の依頼を組む。`answer` の設計 PR のマージ（`parallel_answer.py` の `merge_design`）・MVV 判定（`mvv_mark`）・古い依頼の整理（`after_items` の `drop`）は、どれも `kind: gate1` の依頼だけに掛かる。そのため 1 スプリントのレーンの設計承認には働かない。

起票者の推定 S3（hook が `ndf-gate:1` を ask として転送している）は、この読みと一致する。

### 事象 2

#3597 の「原因」の事象 2 と同じ。前の答えを今の問いへ当てる判定に要る問いの対象（ブランチ名と先端、または `#<番号>`）が、`AskUserQuestion` の入力から hook へ届く経路が無い。

## 前提

- 前提 1: 事象 1 の対象は、並列の計画の 1 スプリントのレーンが設計承認ゲートで出す設計 PR の承認の問いである。開発ループのレーンの設計承認の依頼は、今の `lane_gate1` の経路のまま変えない
- 前提 2: 区分 `ndf-gate:1` でも設計 PR を特定できない問い（依頼 `lfix-rel-qb045f34bd845` のような、実装の途中で設計の前提が崩れたときの判断）は、今どおり `kind: ask` で送る。設計承認の依頼として扱える条件（設計 PR が決まる）を設計で決める
- 前提 3: 「同じ問い」は、同じ一時レーンの名前・同じ区分・同じ対象の問いを指す。対象は #3597 の決定 6 の形（`<ブランチ名>@<先端のコミットの 40 桁>` か `#<課題か PR の番号>`）を引き継ぎ、先端は問いを受けた時点に NDF のスクリプトが求める（一時レーンに先端を書き写させない）
- 前提 4: 答えの引き継ぎは、同じ名前の一時レーン（`<計画名>-rel<連番>`）の中に限る
- 前提 5: 1 スプリントのレーンが答えを読んで続ける仕組み（耐久ワークフローの `relay.py restart` と、答えの読み取り）は、今のものを使う。この課題で読み方を変えるのは、答えが `gate1` の答えになることへ合わせる部分だけである

## 対象範囲

含む:

- 1 スプリントのレーンの設計承認の問いを、設計承認の依頼（`kind: gate1`）としてオーガナイザーへ送ること
- その依頼への `answer --approved` が設計 PR をマージし、MVV 判定と古い依頼の整理が掛かること
- 1 スプリントのレーンが `gate1` の答え（承認・直して出し直す・やらない）を読んで続けること
- 一時レーンの区分つきの問いの対象を、`AskUserQuestion` の入力の検証を通る形で `request-ask` へ届けること（#3608）
- 起き直した一時レーンが、同じ問いの前の答えを使い、答え待ちの問いを引き継ぐこと（#3608 の受け入れ条件 1〜4）
- 手順書（`development-workflow` の `references/asking.md` の「並列の計画のレーン」と `references/parallel.md`）を振る舞いに合わせること

含まない:

- 開発ループのレーンの設計承認の依頼の組み方（前提 1）
- 計画の外（並列の計画のレーンでない）の設計承認ゲートの問い。今どおり人へ通る
- リリース承認ゲートの依頼（`gate2`）。#3597 の決定 8 で、答えのある `gate2` はすでに出し直さない
- 台帳の依頼 `lrel-lock-q`（判定の記録の id が空のまま組まれた依頼の id）の扱い。手で打った `request-ask` の可能性があり、原因を確かめていない。この課題では直さない
- ndf-next の側へ同じ決まりを移すこと

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 性能・拡張性 | 問いの hook がオーガナイザーへ送る処理（設計承認の依頼の組み立てと同じ問いの判定を含む）は、hook の上限の秒（`limits` の `hook.ask-forward`）の中に収まる。過ぎたときは今どおり問いを通す |
| セキュリティ | 戻せない操作（C4）の前の答えを、対象の違う問い・対象の分からない問い・別の一時レーンの問いへ当てない（受け入れ条件 14・16・18）。設計 PR の承認を、設計 PR を特定できない問いへ当てない（受け入れ条件 9） |
| 運用・保守性 | 一時レーンが前の答えを使ったときと、答え待ちの問いを引き継いだときは、台帳に記録が残り、後から追える |

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わる。台帳の設計承認の依頼（`kind: gate1`）の送り手に 1 スプリントのレーンが加わる。区分つきの問いに対象を添える形（受け入れ条件 17）が加わる。既存の形（`kind: ask`・開発ループのレーンの `gate1`）は今と同じに読める |
| データ | 台帳の `kind: ask` の行の `target` に値が入る。スキーマの移行は無い |
| 既存の振る舞い | 1 スプリントのレーンの設計承認で、オーガナイザーの手でのマージが要らなくなる。起き直した一時レーンが答えのある問いを人へ送り直さなくなる |
