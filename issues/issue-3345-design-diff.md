# hook の基盤の契約: hook が増えても Claude Code を遅くせず、止め続けず、会話を埋めない（#3345）

## 目的

- **今どうなっているか**: #1142 の作り直しの設計には hook の契約が無く、前の設計の決定 20・I13 も引き継いでいない。今の NDF の hook は、登録・起動の形・失敗の扱い・回数の数え方が guard ごとに別々である。Stop の差し戻しは 3 か所で別々に数えられ、1 セッションで 35 分に 12 回止められた。`hook.py` の所要は p99 9.1 秒で、拒否の文は最大 8,439 字ある。新しいプラグインの `limits.json` も、締め切りより長い部品の上限を写している
- **誰に効くか**: hook の判定を作る M3 #3297 と、入口と登録を作る S1 #3303。入れ替えの後に、作り直した NDF を使う利用者
- **変えると何が成り立つか**: 新しいプラグインの hook が増えても、事象ごとの所要と会話へ入れる量が予算の中に収まる。止められ続けて進まない状態が起きず、失敗しても作業を止めない。破れは CI と計測の記録で見つかる

## 適用範囲

- **働く範囲**: `plugins/ndf-next/` の hook（M3 の `domains/hooks/` と契約表、S1 の `hooks/` の入口と登録）。今の `plugins/ndf/` は変えない
- **プロジェクトごとに違うもの**: 足さない。guard を止める指定は環境変数 `NDF_HOOK_OFF` の 1 つで受ける
- **当たるモード**: `standard`（#1142 のまま）
