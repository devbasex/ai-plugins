## 目的

- 打ち切り・例外・シグナル・強制終了で終わった実行の記録が、次の実行を「使用中」で止めない状態にする（今は #2321 のように、終わった時刻の無い持ち主の記録が寿命の窓の 24 時間だけ次の実行を断る）
- 2 つの conductor が同じ開発ループ・同じキューを同時に流さず、後から来た側が止まって持ち主を結果で知る状態にする（今は #2316 のように、互いに気づく手段が無い）
- キューの再開で、`--from` の指定が前の起動の途中の位置より常に優先される状態にする（今は #2325 のように、前の起動が途中で残っていると `--from` が無視される）

| 用語 | 意味 |

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 性能・拡張性 | 持ち主の記録を取って返す段が、1 入口の起動に足す時間は、#2335 の上限 150 ms（核全体）の内側に収まる。柱の Pull Request で `--help` ではなく持ち主の鍵を宣言した入口の起動を前後で 10 回ずつ測り、差の中央値を本文に書く |
| 可用性 | 生きた持ち主がいる実行は待たずに `stopped` で返る（受け入れ条件 3） |
| 運用・保守性 | 取った・引き取った・断った・返したを、結果の JSON の `lease` に出す |
| 移行性 | 移す対象: 持ち主の記録の置き場（状態ディレクトリの横 → `leases/`）。旧い置き場の記録は読まない（前提 6）。切り戻し: 持ち主の段の Pull Request と入口を移す Pull Request を、それぞれ revert すれば前の形へ戻る |
| セキュリティ | 受け入れ条件 11。認証・認可（C2）と秘密の扱い（C1）は変えない |
| システム環境 | 排他は既存の optional extras の `filelock`（`lib/locks.py`）を使う。extras が無い環境では、核が `stopped`（終了コード 69）と足りない extras の名前を返す（#2335 の受け入れ条件 15） |

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わる。持ち主がいるときの断りは `stopped`・終了コード 3 になる。`queue --resume --from` は前の途中を止めて指定のステップから流す。新しい入口は増えない |
| データ | 変わる。持ち主の記録の置き場が `${NDF_STATE_DIR:-~/.local/state/ndf}/leases/` へ移る。旧い置き場の記録は読まない。利用者の `.ndf/` は変えない |
| 既存の振る舞い | 変わる。打ち切りの後の流し直しが止まらなくなる。並行する conductor の後から来た側が、続きとして流さずに止まる |

## 前提とする取り決め

| 項目 | 参照先 / 決めたこと |
| --- | --- |
| プロジェクト構造 | 持ち主の部品は `plugins/ndf/scripts/lib/` に置く。既定で働くため `experimental/` に置かない（`AGENTS.md` の「安定版と実験版」）。`factory/` を参照しない |
| コーディング規約 | `AGENTS.md` の「最小限のコード実装」と、外部コマンド（`ps`・シグナル）の挙動を書く前に実行して確かめる決まり |
| テスト戦略 | 持ち主の部品は単体テストで終わり方と取り合いを担保し、入口は契約のテストで担保する。子の課題は再現の手順で確かめる。`.md` の文言を照合するテストは書かない |

## 境界

| 区分 | 内容 |
| --- | --- |
| 常に行う | #2335 の設計を正として変更する（前提 1 の再開の入口を除く）。全体テストと構造の検査を通す。持ち主の部品へ移した入口から自前の持ち主の扱いを消す |
| 確認してから行う（承認ゲート 1・2 で人が見る） | 持ち主の記録の置き場の移動。`queue --resume --from` の振る舞いの変更（公開インタフェース） |
| 行わない | 子の課題を 1 件ずつ直す Pull Request（「含まない」の例外を除く）。対象範囲の「含まない」に挙げたもの。利用者の `.ndf/` を書き換える。`-D` / `--force` が要る片付け（止めて人へ戻す） |
