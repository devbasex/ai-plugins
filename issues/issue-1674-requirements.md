# #1674: supervise.py queue --max 1 でも他のプランの触るファイルを「並行して変えない」として実装の担当へ渡す

正は課題の本文（#1674）で、この文書はその写しである。`spec-copy.py write` で作り直す。手で直さない。

## 何が起きたか

`supervise.py queue <実装のプラン 4 本> --max 1` で直列に流したのに、1 本目の実装の担当へ「並行して別のプランが次を触る。それらは変えない: …」が渡った。並べたのは、残り 3 本が触るファイルである。担当は、課題の対象の大半（テスト・確定仕様・用語集・CHANGELOG・Dockerfile）が「変えない」に当たるとして作業せずに止まった。

キューはそのまま 2 本目を始めた。2 本目は 1 本目の結果を前提にした課題で、conductor が止めた。

## 原因の見当

`supervise_lib/flow.py` の `admission.others(files, grouped)` が、`--max` と重なりの組（同時に流さない組）を見ずに、ほかのすべてのプランの `触るファイル` を `others` に入れている。`worker_steps.concurrent_rule` は、それを実装の指示文へ足す。

同じ Dockerfile を触る組は、キューが「重なる組 … を同時には流さない」と判定していた。それでも除外の行は渡っていた。

## 期待する振る舞い

- 除外の行に入れるのは、実際に同時に流れるプランが触るファイルだけにする。`--max 1` や、同時に流さない組の中では空にする
- 1 本が止まったときに、後ろの本が前の本の結果を前提にしているなら、続けて流さない（少なくとも、止まった本があることを `--then` 以外でも止める理由にできる）

## 目的

- `supervise.py queue` で流した実装の担当が、同時には走っていないプランのファイルを「変えない」と言われて、受け入れ条件の作業をせずに止まることを無くす（3 回の再発で、conductor が単独で流し直す手当てを毎回していた）
- 前のプランの結果を前提にするプランが、前のプランが止まったまま流れ出すことを無くす

## 前提

- 前提 1: 「同時に流れるプラン」は、実装の担当を起動する時点で走っている（始まって終わっていない）他のプランを指す。後から始まるプランは、その側の除外の行に先に走っているプランの `触るファイル` が入るため、組のどちらか一方へ必ず知らされる
- 前提 2: プランどうしの「前の結果を前提にする」関係は、queue が推して決めない。プランか queue の引数に明示した依存だけを見る（明示の形は設計が決める。`--then` のステージは今の振る舞いのまま残す）
- 前提 3: #1811（重なりの判定でテストのディレクトリの包含を重なりとしない）は未着手のまま。この課題は除外の行の広さだけを直し、重なりの判定（直列にするかどうか）は変えない。#1811 が判定を変えたときも、除外の行は同じ規則で狭まる形にする（同じ役割の関数を 2 つ持たない。Value 6）

## 対象範囲

含む:
- 実装の指示文へ足す除外の行（`supervise_lib/worker_steps.py` の `concurrent_rule`）に入れるファイルの決め方
- ディレクトリの `触るファイル` を除外の行へ入れるときの扱い
- queue の中で、依存を明示したプランの前のプランが完了でなかったときに、後ろのプランを流さないこと、その理由を結果に残すこと

含まない:
- 重なりの判定（`admission.overlaps` / `groups`）の変更。#1811 が扱う
- 課題の本文やスプリントの表から依存を自動で推すこと
- 設計の置き場所の書き方（ディレクトリかファイルか）の規約の変更。#1811 が扱う
- 担当が止まったときの別の理由（受け入れ条件が無い）。#1767 が扱う

## 用語

| 用語 | 意味 |
| --- | --- |
| 除外の行 | 実装の指示文の末尾に足す「並行して別のプランが次を触る。それらは変えない: …」の 1 行 |
| 重なりの組 | 同じステージの 2 本のプランで、触るファイルが包含で重なるか同じ共有の一覧に当たるもの。同時には流さない（用語集のとおり） |

## 受け入れ条件

- [ ] 1. `supervise.py queue <プラン 2 本以上> --max 1` で流したとき、どの実装の担当の指示文にも除外の行が無い
- [ ] 2. 重なりの組でつながり直列に流すプランどうしでは、実装の指示文に互いの `触るファイル` が入らない（今の振る舞いを保つ）
- [ ] 3. `--max 2` 以上で、実装の担当を起動する時点で走っている他のプランがあるときは、そのプランの `触るファイル` が除外の行に入り、走っていない（まだ始まっていない・既に終わった）プランの `触るファイル` は入らない。走っている他のプランが無ければ除外の行は無い
- [ ] 4. 除外の行に入る他のプランの `触るファイル` がディレクトリ（例 `plugins/ndf/scripts/tests/`）のとき、指示文はそのディレクトリの中のすべてを変えないとは書かない。担当がそのディレクトリへ自分のテストのファイルを足すことは、除外の行に反しない
- [ ] 5. プランが依存を明示した前のプランが完了でなく終わったとき、queue はその後ろのプランを始めない（担当の CLI を起動しない）
- [ ] 6. 5 で流さなかったプランは、queue の結果の JSON に「流さなかった」ことと、理由（どの依存先が完了でなかったか）とともに載る
- [ ] 7. 依存を明示していないプランは、同じステージの他のプランが完了でなくても今までどおり流れる（`--then` のステージの振る舞いも変わらない）
- [ ] 8. 既存のテスト（`plugins/ndf/scripts/tests/`）がすべて通る

## 非機能の条件

| 大項目 | 条件 |

| 移行性 | 依存を明示していない既存のプランの JSON は、書き直さずにそのまま流れる |
