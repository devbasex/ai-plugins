## 決定 1: 工程の 1 つとして起動したときの最終ゲートの打ち切りは、案 A を主にし、通らないときだけ案 B へ落とす（#1669）

**状態: 推奨（設計の承認で人が採るかを決める）**

### 経緯

今の方針（`plugins/ndf/skills/cross-refactoring/docs/04-verify-and-report.md` の「最終ゲート修正は想定最大時間の終わりで打ち切る」）は、
最終ゲートは push 済みの地点なので打ち切っても取り消さず、取り消しの判断を Pull Request の読み手に任せる。

スプリント m725 の検査（Pull Request https://github.com/devbasex/ai-plugins/pull/1663 ）では、この方針のために次のことが起きた。

| 起きたこと | 数 |
| --- | --- |
| 結果 | `items 23 / adopted 0 / reverted 7 / unconfirmed 16 / final_gate failing` |
| 全体テストを落としたまま `sprint/m725` に残った未確認のコミット | 16 件（うち原因は 3 ファイルを触った 8 件） |
| conductor の手作業（原因の調査・`git revert`・全体テスト・`--from review` での流し直し） | 約 15 分 |

工程の 1 つとして起動したとき（`--workflow-step`）の読み手は人ではなく、プランと conductor である。プランは refactor の失敗で
`abort` へ進むだけで、判断の材料（どの項目が落ちたテストに関わるか）はスクリプトの手元にあるのに使われない。

### 比べた案

| | 案 A: 未確認の項目を取り消し、落ちたテストが通った時点で止める | 案 B: 着手前の HEAD の木へ戻すコミットを 1 本積む |
| --- | --- | --- |
| 残る改善 | 原因でない項目は残る（#1663 なら 16 件中 8 件、原因の項目の決め方（#1649）が効けばさらに多い） | 0 件。予算（30 分）と提案者の費用をすべて捨てる |
| 所要 | 取り消し 1 件ごとに落ちたテストを走らせ直す（#1663 の構造検査は 1 回約 3 秒）。件数に比例する | コミット 1 本。走らせ直しは要らない |
| 失敗の経路 | 積み直しの衝突・取り消し尽くしても通らない・時間切れがありうる | ほぼ無い（着手前の木は着手前の全体テストを通っている。既存失敗は既に除いてある） |
| 実装 | 既存の取り消し（`undo.drop`）と、検証の中の危険フラグの取り消し（新しい順・通ったら止める）と同じ形。#1649 の原因の項目の決め方を共有できる | 新しい操作（木を戻すコミット）が要る。取り消しの台帳（`ledger`）に項目ごとの理由が残らない |
| 記録 | 項目ごとに `reverted` と理由が残り、振り返りで原因の項目が分かる | 「全件を戻した」1 行だけ |

### 決めたこと（推奨）

**案 A を主にし、案 A で通らないとき（積み直しの衝突・候補を取り消し尽くしても通らない・時間の上限を使い切った）だけ案 B へ落とす。**
単独で起動したときは今の方針（取り消さずに報告）のまま残す。

### 理由

- **テストを壊していない改善を残す。** 案 B だけにすると、原因でない改善まで毎回 0 件にする。Mission（価値を届けるまでの時間と費用を減らす）と
  Value 1（まず届ける）に反する。案 A は #1663 で 8 件を残せた
- **同じ役割の処理を 2 つ作らない。** 案 A は検証の中の危険フラグの取り消しと、#1649 で直す原因の項目の決め方をそのまま使える（Value 6）。
  最終ゲート専用の取り消しを作らない
- **止まらずに終わることは案 B が保証する。** 案 A だけでは失敗の経路（衝突・時間切れ）でまたプランが止まる。案 B はコミット 1 本で
  走らせ直しを伴わないので、案 A の失敗の受け皿にすると、工程の 1 つとして起動した cross-refactoring はどの経路でも
  「全体テストが通る状態で完了」か「判断が要る（終了コード 4）」のどちらかで終わる
- **conductor の手当てをスクリプトへ移す。** 同じ手当て（原因の項目の手での取り消し）は #1634 と #1663 で 2 度起きている（Value 4）
- **単独の起動を変えない理由。** 単独では人が Pull Request を読み、取り消すかを人が決められる。読み手が判断を持つ場面で
  機械が先に取り消すと、人の判断の材料（落ちたままのコミット）が消える

### 守ること

- 取り消しはすべて `git revert` か、着手前の木へ戻す新しいコミットで行う。push 済みの履歴を書き換えず、強制 push はしない（共通原則 C4）
- 案 B の後の最終ゲートでも落ちたら、取り消しを重ねずに終了コード 4（判断が要る）で止まる
- 打ち切りの後の取り消しにかける時間の上限は `--budget-minutes` から算術で出す（式は設計で決める）

### 根拠にした項目
