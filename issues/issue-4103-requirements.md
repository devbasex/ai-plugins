# #4103: 並列の計画: 取り直しの起動の結果が不明なとき・手動の再起動・期限を越えて生きる手で、席を数え落とすか取り直しが止まる（#4091 から分けた）

正は課題の本文（#4103）で、この文書はその写しである。本文から作り直す。手で直さない。

## 目的

- **今どうなっているか**: #4091（待つ行の席を返し・取り直す仕組み）の設計 PR #4096 の cross-review は、3 ラウンドの上限まで、席の段階とリレーハブ・既存の期限の仕組みとの境で毎回新しい重い穴を出した（ラウンド 1 の r1-13・r1-14・r1-15、ラウンド 2 の r2-1・r2-2・r2-3・r2-5、ラウンド 3 の r3-1〜r3-5）。#4091 の本体（4 つの段階・数える規則・返却と取り直しの遷移の表）から、この境を分ける
- **誰に効くか**: #4091 を実装する人と、並列の計画を流すすべての利用者
- **変えると何が成り立つか**: 取り直しの起動の結果が分からないとき・手動の再起動が割り込んだとき・起動した conductor が期限を越えても生きているときに、席を数え落とさず、取り直し中の行が止まったままにならない

## 種類

機能追加（#4091 の席の返却を安全に有効にする前提。今のリレーハブは、起動の結果が分からないときにそれを確定させる手段を持たない）

## 今の姿

パスは `plugins/ndf/` からの相対で書く。#4091・#4044・#4050 は設計がマージ済みで、実装はまだである。

- **起動の要求は頼む側が生きていなくても処理される。** `ndf relay spawn`・`restart`・`stop` は要求のファイルを `relay/hub/requests-v2/` へ書いてから、自分の `drain` でハブの排他（`hub.lock`）を取りにいく。頼む側が書いた後に落ちると、要求は残り、次に誰かが `drain` したときに、書いた時点の `held` のまま処理される（`src/ndf/domains/relay/hub.py` の `submit`・`drain`）
- **起動の確かめが失敗しても、作った tmux のセッションは残る。** `_confirm` はラッパーが錠を取るのを `relay.started`（15 秒）だけ待ち、取れなければ失敗を返すが、セッションを止めない。セッションの中のラッパーは後から錠を取りうる（`hub.py` の `_launch`・`_confirm`）
- **tmux の照会は不在と失敗を区別しない。** `Tmux.has` は `has-session` の終了コードが 0 かだけを返し、tmux を打てない・時間切れ・ソケットの権限の誤りも「無い」になる（`src/ndf/domains/relay/tmux.py`）
- **手動の再起動の上限の判定は、頼む側がハブの排他の前に読んだ `held` を使う**（#4044 の設計）。読んでから処理されるまでに別のレーンが席を取ると、古い値で判定される
- **期限を越えた続きの手は、ラッパーが生きていても失敗に数えて置き換える**（`src/ndf/progress/plan/run_decide.py` の `_expire_launched`）

## 対象範囲

含む（PR #4096 の版の `issues/issue-4091-design.md`・`issue-4091-design-detail.md` の、決定 8 で印を付けた箇所）:
- 取り直しの起動の結果が不明なときの確定: ハブに溜まった未処理の起動の要求（`hub.submit` と `drain` の間の中断）、起動の確かめ（`_confirm`）の期限切れの後に残る tmux のセッション、tmux の照会の失敗を「不在」と「不明」に分けること（`quiet`・`probe`。r2-1・r3-1・r3-3）
- ハブの上限の断りの後の生存の確かめ（r2-2）
- 手動の `ndf relay restart` と席の返却・取り直しの直列化（r1-14・r2-3・r3-4。#4044 の `held` の読み取りの時点との関係を含む）
- 起動したまま待つ続きの手が期限を越えても生きているときの扱い（置き換えない・止まりを知らせる・`/goal` の入れ直しとの関係。r1-15・r2-5・r3-5）と、確かめの手（`Settle`）を打ち切らないこと（r3-2）

含まない:
- 席の 4 つの段階・数える規則・返却と取り直しの遷移の表・承認の回答の結び方（#4091）
- 通常の `ndf relay spawn`・`restart` の数え方そのもの（#4044）

## 受け入れ条件

- [ ] 1. 取り直しの起動の要求がハブに残ったまま耐久ステップが中断しても、後続のリレー操作なしで席が確定し、確定までの間は数え続ける（テスト）
- [ ] 2. tmux の照会が失敗したときは不在とみなさず、席を返さない（テスト）
- [ ] 3. 手動の `ndf relay restart` が席の返却・取り直しと同時に起きても、上限を超えて 2 本が動かない（テスト）
- [ ] 4. 期限を越えた続きの手のラッパーが生きている間は置き換えず、止まったままなら止まりとして知らせる。取り直し中の行の確かめは期限で打ち切らない（テスト）
- [ ] 5. 起動の確かめが失敗した後に残った tmux のセッションが後から錠を取っても、上限を超えて 2 本が動かない（テスト）
