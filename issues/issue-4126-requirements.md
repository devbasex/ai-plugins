# #4126: 中継の 3 つの環境変数の名前を契約の 1 か所に持ち、コードは契約から名前を引く

中継は、NDF が claude の会話を包み、文脈が尽きる前に次の会話へ切り替えるラッパーである。中継が子の会話へ渡す 3 つの環境変数（`NDF_RELAY_DIR`・`NDF_RELAY_LAUNCH`・`NDF_RELAY_SESSION`）の名前を、環境変数の契約 `plugins/ndf/contracts/domains/env.json` の 1 か所にだけ持つ。コード（hook の経路を含む）は名前を文字列リテラルで書かず、契約から引く。あわせて、#4049 と #4062 の実装の PR が `ndf check` を通るようにする。

## 何が起きたか

#4061・#4062・#4064 の設計（PR #4095、`issues/issue-4061-4062-4064-design.md` の決定 4）は、`NDF_RELAY_LAUNCH` の名前を `signals` の定数 `LAUNCH_ENV` に持つと書く。一方で、`env.json` に `NDF_RELAY_LAUNCH` の行を足すと、検査 `const-fact` の `table-str`（契約の表の `id` と同じ字を最上位の定数に写すことを禁じる）がその定数を落とす。#4101 の設計（PR #4125）の中で、一時のコピーで見つかった。

この課題の設計で確かめ直すと、同じ形がほかに 2 つある。

- #4049 の詳細設計は、`NDF_RELAY_SESSION` の行を足し、定数 `SESSION_ENV` を `signals` に置く。#4049 の実装は #4062 より先なので、最初に落ちるのは #4049 の実装の PR である
- #4062 の詳細設計は、定数 `DIR_ENV`（`"NDF_RELAY_DIR"`）を `signals` に置く。`NDF_RELAY_DIR` の行は今の `env.json` に既にあるので、定数を足した時点で落ちる

最初の設計（2026-11-22）は、名前を使う所に文字列リテラルで書き、契約との一致をテストで確かめる形にした。利用者は設計承認ゲートでこれを差し戻し、名前を設定ファイル（契約）の 1 か所にまとめ、コードはそこから名前を得る形を求めた（2026-11-23）。

## 種類

不具合（設計どうしの食い違い）。`ndf check` が通ることは、実装の PR を取り込む約束として今の SSOT（`plugins/ndf/src/ndf/checks/README.md` の検査の規則の表と CI のジョブ）にある。環境変数の契約の表も、要約に「コードは名前をこの表から引き、表に無い名前を読まない」と約束している。設計の書いた形のまま実装すると、その約束を破る。

## 事象

`origin/main`（`ec8340675`）の取り出した作業ツリーで、#4049・#4062 の設計の形を当てて `ndf check --only const-fact` を打つと、次のとおり落ちる（2026-11-22）。

| 当てた形 | 結果 |
| --- | --- |
| `env.json` に `NDF_RELAY_LAUNCH`・`NDF_RELAY_SESSION` の行を足す（#4049・#4062） | 違反 1 件: `signals.py:39: table-str: LAUNCH_ENV が表 env の id を写す` |
| 上に加えて `SESSION_ENV = "NDF_RELAY_SESSION"` を足す（#4049 の詳細設計） | 違反 2 件: `LAUNCH_ENV` と `SESSION_ENV` |
| 行は今のまま、`DIR_ENV = "NDF_RELAY_DIR"` を足す（#4062 の詳細設計） | 違反 1 件: `table-str: DIR_ENV が表 env の id を写す` |

## 期待する結果

中継の 3 つの名前は `env.json` の 1 か所にだけあり、コード（hook の経路を含む）は名前を契約から引く。名前を変えるときに直すのは `env.json` の 1 行だけで、コードの文字列リテラルや定数を追いかけて直すことが無い。#4049 と #4062 の実装の PR は、それぞれの時点の契約の状態で `ndf check` を通る。

| PR | `env.json` の中継の行 | コードの名前の持ち方 |
| --- | --- | --- |
| #4049 の実装 | `NDF_RELAY_DIR`（今のまま）と、足す `NDF_RELAY_SESSION` の行が契約から引ける | 2 つの名前を契約から引く。`SESSION_ENV` を置かない。`LAUNCH_ENV` はまだ残る（`NDF_RELAY_LAUNCH` の行が無い） |
| #4061・#4062 の実装 | `NDF_RELAY_LAUNCH` の行を足して契約から引け、3 行を `child: drop`（子へは受け継いだ値を渡さない）にする | `LAUNCH_ENV` を消し、3 つとも契約から引く |

## 再現手順

1. `git archive origin/main plugins/ndf | tar -x -C <一時のディレクトリ>` でコピーを作り、`git init` と最初のコミットをする（`ndf check` は git の作業ツリーで打つ）
2. `env.json` の `NDF_RELAY_DIR` の行の直後に `NDF_RELAY_LAUNCH` の行を足す
3. 写しの `plugins/ndf` で `./bin/ndf check --only const-fact` を打つ
4. 終了コード 1 で、`table-str: LAUNCH_ENV が表 env の id を写す` が出る

## なぜ困るか

#4049 の実装の PR は CI の `ndf check` で落ち、#4062 の実装の PR も落ちる。実装の途中で気付くと、設計を直す工程に戻り、設計承認ゲートを通し直す手戻りになる。#4049・#4062 は並列開発の計画 p12 で順に待たれている（#4049 → #4061・#4062 → #4101）ので、1 本が止まると後ろの 2 本も止まる。

名前をコードの文字列リテラルにすると、名前の事実が契約とコードの 2 か所に分かれる。一致をテストで縛っても、事実が 2 か所にあることは変わらない。

## 目的

中継の 3 つの名前の正本を契約の 1 か所にし、コードはそこから名前を得る。#4049・#4062・#4101 の実装の PR が、設計の書いたとおりに作って `ndf check` を通る状態にする。

## 対象範囲

含む:

- 中継の 3 つの名前を契約から引く仕組み（契約の列と、hook の経路からも呼べる読み手）
- `plugins/ndf/src` の中で 3 つの名前を使う所すべて（`relay/signals.py`・`adapters/claude.py`・`relay/account_login.py`）
- #4049・#4062・#4101 の設計の、食い違う記述の読み替え（この課題の設計に書く。3 つの設計文書そのものは書き換えない）
- 実装の置き場（どの実装の PR に入れるか）と、#4101 との順

含まない:

- 検査 `const-fact` の振る舞いの変更
- 中継の 3 行の値（`area`・`set_by`・`type`・`child`・`meaning`）。#4062 の設計の「データ構造」のとおりにする
- 中継の 3 つ以外の環境変数の名前の持ち方の直し（#4101 が持つ。この課題は読み替えの行で方向だけを書く）
- hook の見分け（`relay_role`）・締め切りの出力など、#4061・#4064 の振る舞い
