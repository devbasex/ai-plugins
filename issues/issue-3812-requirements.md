## 目的

- ラッパー（`ndf relay`）の下で動く開発のループが、バージョンを出した後のカットポイントで、新しいバージョンの NDF で次のセグメントを始める
- バージョンの直しが「誰かが手でプラグインを更新したセッション」でしか効かない状態をなくし、リリースした直しが動いているレーンへ利用者の操作なしで届く

## 事象

`plugins/ndf/skills/development-workflow/references/relay.md` は、カットポイント（`ndf-next` のブロック）と最初の起動で、ラッパーが**プラグインを更新してから**次のセッションを起動すると書いている（「好きな時点で切り替える」「カットポイントの引継ぎ文書と ndf-next はスクリプトで作る」のセクション）。

11 系の中継のコードには、プラグインを更新する処理が無い。`plugins/ndf/src/ndf/domains/relay/` で `plugin` と `update` を探しても 0 件だった。

その結果、バージョンを出しても、ラッパーの下のセッションは古いバージョンのまま続く。#3807 の SessionStart での向け直しは、誰かがプラグインを更新した後でしか効かない。

## 期待する結果

マーケットプレイスに新しいバージョンが出た後のカットポイントで、ラッパーが次のセグメントを起動する前にプラグインを更新し、次のセグメントの claude が新しいバージョンの hook と Skill で動く。

## 再現手順

1. バージョン N の NDF を入れた状態で `claude`（ラッパーを挟む）を起動する
2. マーケットプレイスへバージョン N+1 を出す（`main` へのマージ）
3. ラッパーの下の会話で `ndf-next` のブロックを出して応答を終える
4. 次のセグメントの claude で `claude plugin list --json` の `ndf@ai-plugins` の `version` を見ると N のまま（`~/.claude/plugins/cache/ai-plugins/ndf/` の下に N+1 のディレクトリができない）

## 環境

- NDF 11.0.7（`ndf@ai-plugins`、user スコープ）・Claude Code 2.1.328・Linux

## 共通の背景

11.0.0 の作り直し（#3304）で、中継の手順書 `plugins/ndf/skills/development-workflow/references/relay.md` は 10 系の仕組みを写したまま残った。11 系の中継（`plugins/ndf/src/ndf/domains/relay/`）では作らなかった部分がある。2026-11-18 の洗い出しで見つけた。#3807 で直したのは、「ラッパーを挟まない起動」「セッションをまたいで設定を保つ」と、SessionStart での向け直しだけである。

**直し方は利用者の方針に従う。** 方針は「10 系の課題を引きずらず、11 系の設計思想に合わせる」である。11 系で要る振る舞いなら作り、要らなければ手順書から消す。

## 決めたこと

- **作る。** ラッパーが、最初のセグメントを起動する前と、カットポイントで次のセグメントを新しいセッションで始める前に、プラグインを更新してから claude を起動する（S1）
- ラッパー自身のコードの入れ替えは作らない。ラッパーのコードの変更は、利用者が次に `claude` を打ち直したときに効く（子の SessionStart が `relay.root` を更新後のバージョンへ向け直すため）（S3）

## 前提

- 前提 1: 更新は `claude plugin marketplace update <マーケットプレイス>` と `claude plugin update ndf@<マーケットプレイス> -y` の 2 つのコマンドで行える（Claude Code 2.1.328 で、出力の形と失敗の終了コード 1 を確かめた。2026-11-19）
- 前提 2: プラグインを更新しても、旧いバージョンの導入先（`~/.claude/plugins/cache/<マーケットプレイス>/ndf/<旧いバージョン>`）は消えず、動いているラッパーのプロセスはそのまま動き続ける（手順書の「始め方」の既存の記述）
- 前提 3: ラッパーと hook のあいだのファイルの形（シグナルファイル・マーカー・`wrapper.json`）は、同じメジャーバージョンの中では古いラッパーが読める形のまま変える（キーを足すだけにする）。読めない形へ変えるときはメジャーバージョンを上げる

## 対象範囲

含む:
- ラッパー（`plugins/ndf/src/ndf/domains/relay/wrapper.py`）が、最初のセグメントの起動の前とカットポイントの切り替え（`switch`）で、プラグインを更新してから claude を起動する
- 更新の結果を `log.jsonl` へ 1 行で残し、失敗したら端末へ `ndf-relay:` の 1 行を出す
- 11 系どうしでバージョンが違うラッパーの並びを断らないように、バージョンの混ざりの判定（`hub_decide.mixed`）を変える
- 手順書 `relay.md` と `relay-accounts.md` のうち、プラグインの更新とラッパーの入れ替えと記録に関わる記述を 11 系の振る舞いへ直す（冒頭の例・「好きな時点で切り替える」・「ラッパーの入れ替え」・「承認ゲートを越えない守り」の最後の箇条・「落ちたときの続け方」・「記録の読み方」。#3813 と #3816 の受け入れ条件をこの変更で満たす）

含まない:
- ラッパー自身のコードの入れ替え（10 系の reexec と `handover.json`）
- 手順書の「上限」（#3815）・「承認ゲートを越えない守り」の本体（#3814）・リレーハブ（#3818）の食い違い
- 子の claude の起動の例外の扱い（#3842）
- 上限・認証の失敗・子の終了から同じ会話を `--resume` で続けるときの更新（S5）
- Codex のプラグインの更新（中継は Claude Code だけ）

## 受け入れ条件

- [ ] 1. バージョン N を入れた状態のラッパーで、マーケットプレイスにバージョン N+1 が出た後のカットポイント（`switch`）では、次のセグメントの claude を起動する前に、マーケットプレイスの更新と NDF の更新のコマンドがこの順で 1 回ずつ走り、その後に次のセグメントの claude が起動する（次のセグメントの claude はバージョン N+1 の導入先を読む）
- [ ] 2. 新しいセッションで始める最初のセグメントの claude を起動する前にも、受け入れ条件 1 と同じ更新が走る。利用者が `claude --resume <ID>` で始めた最初のセグメント（同じ会話の続き）では走らない
- [ ] 3. 更新のどれかが失敗（終了コードが 0 でない・時間切れ・起動できない・出力が読めない）しても、ラッパーは止まらず今のバージョンのまま次のセグメントを起動し、`log.jsonl` に失敗の理由を持つ 1 行を残し、端末へ `ndf-relay:` で始まる 1 行を出す
- [ ] 4. 上限でアカウントを替えて再開する手（`account`）と、子の終了・止まりから起動し直す手（`restart`）では、更新のコマンドを走らせない
- [ ] 5. 11 系どうしでバージョンの違うラッパーが動いていても、ラッパーの起動（`ndf relay run`）・`ndf relay spawn`・`ndf relay restart` はバージョンの違いを理由に断らない。旧い NDF（10 系。登録したバージョンが無い）とメジャーバージョンの違うラッパーが動いていれば、今と同じく断る
- [ ] 6. ラッパーがプラグインのキャッシュの導入先から動いていない（`--plugin-dir` や開発のチェックアウトの `bin/ndf relay run`）ときは、更新のコマンドを走らせず、理由を `log.jsonl` へ 1 行残す
- [ ] 7. 手順書 `relay.md` と `relay-accounts.md` から、ラッパーの入れ替え（`relay.current`・`handover.json`・`os.execve`・`reexec`・`reexec_skipped`・`relay_version_dir`・`NDF_RELAY_PREPARE_TIMEOUT`）の記述が無くなり、代わりに「ラッパー自身のコードの変更は、`/exit` で抜けて `claude` を打ち直した後に効く。hook と Skill の変更は、次のセグメントから効く」と書かれている。読み手の無い上限 `relay.handover-prepare`・`relay.runtime-install` が `plugins/ndf/contracts/limits.json` から無くなっている（#3813）
- [ ] 8. `relay.md` の「記録の読み方」の表と例が、ラッパーが書く `log.jsonl` の保存先・行の種類のキー（`kind`）・種類ごとのキーと一致し、`plugin_update` の行を含む。載せた `jq` の例を実物の記録に打つと行が返る（#3816）
- [ ] 9. `relay.md` の冒頭の例・「好きな時点で切り替える」・「落ちたときの続け方」のプラグインの更新の記述が、受け入れ条件 1〜3 の振る舞い（更新に失敗しても止まらない）と一致する
- [ ] 10. 退行しない: 既存の中継のテスト（`plugins/ndf/tests/domains/relay/`）がすべて通る
- [ ] 11. 次の子が読む導入のメジャーバージョンがラッパーのメジャーバージョンと違うとき（例: 11.0.7 のラッパーで導入が 12.0.0 へ上がった。別のラッパーが上げた場合と、更新しない手の場合を含む）は、次のセグメントを起動せず、`relay.root` を起動先へ向け直し、端末へ `claude` を打ち直す案内の 1 行を出してラッパーを終える。同じメジャーバージョンの中では起動する
