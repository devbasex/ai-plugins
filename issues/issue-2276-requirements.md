## 目的

- Factory の API（`factory/api`）で、Secrets Manager から秘密を読んで保持する規則を 1 か所で持つ。規則を変えるときに直す場所を 1 つにし、秘密を読む Lambda を足す変更が同じ処理をもう一度書かずに済む状態にする

## 前提

- 前提 1: 共通の仕組みは、読み込みの関数を受けてその結果を保持する汎用の形（値の型を問わない）と、ARN の環境変数の名前から秘密の文字列を読む形の 2 層で足りる。署名の鍵の組は前者で扱う
- 前提 2: 共通の仕組みは `factory/api/src` の中に置く。`factory/runner` は別のパッケージで、起動時に 1 回読むだけで保持の規則を持たないため、共有の対象にしない
- 前提 3: 読めなかったときの例外の文言は、呼ぶ側の応答へ出ない（受け口は 503 の誤りに置き換え、仲立ちは鍵を読めないときに例外を返す）。文言を共通の形にそろえても、HTTP の応答の状態コードと本文は変わらない
- 前提 4: 秘密の値・鍵の中身・検証の規則は変えない。変えるのは、読んだ値を保持して読み直すコードの置き場だけである

## 対象範囲

含む:
- 実行の制御の依存（`runs/deps.ts`）の秘密の読み込み 3 件（GitHub App のクライアントの秘密・秘密鍵・実行ジョブの token の発行の鍵）
- 進捗の受け口（`handlers/ingest.ts`）の GitHub App の Webhook の秘密の読み込み
- GitHub の仲立ち（`handlers/github-oidc.ts`）の署名の鍵の組の読み込み
- 共通の仕組みの単体テスト

含まない:
- 実行ジョブの token の公開鍵の集合を時間ごとに読み直す検証（`progress/run-job-token.ts` の `createCachedRunJobTokenVerifier`）。失敗で捨てるのでなく一定時間ごとに読み直す規則で、役割が違う
- `factory/runner` の秘密の読み込み
- #2173（通知）・#2174（決済）の Lambda の実装
- 秘密の値・ARN・環境変数の名前・インフラの定義の変更

## ドメインイベント

| # | イベント | 引き金 | 失敗したとき | 順序の前提 |
| --- | --- | --- | --- | --- |
| E1 | 秘密の読み込みを求めた | Lambda の処理が秘密か鍵を初めて要る時点（起動時ではない） | — | — |
| E2 | Secrets Manager から秘密を読んだ | E1 で保持している値が無い | 環境変数が無い・読めない・値が空のとき、例外を呼ぶ側へ返し、保持を捨てる（E4） | E1 |
| E3 | 読んだ値を保持し、以後の要求へ同じ値を返した | E2 の成功 | — | E2 |
| E4 | 失敗した読み込みの保持を捨てた | E2 の失敗 | — | E2 |
| E5 | 次の要求で読み直した | E4 の後の E1 | E2 と同じ | E4 |

E2 が終わる前に E1 が重なったときは、同じ読み込みの結果を待つ（Secrets Manager を 2 回呼ばない）。受け入れ条件 7 に移した。

## 用語

| 用語 | 意味 |
| --- | --- |
| 秘密のキャッシュ | Secrets Manager から読んだ値を Lambda の実行環境の中で保持し、成功した値は以後も同じ値を返し、失敗した読み込みは捨てて次の要求で読み直す仕組み |
| GitHub の仲立ち | GitHub の OAuth を Cognito が受け取れる OIDC の形へ変える `factory/api/` のプログラム（`/oidc/github`）。署名の鍵の組を Secrets Manager から読む |

## 受け入れ条件

- [ ] 1. 秘密のキャッシュ（成功した値を保持し、失敗したら捨てて読み直す処理）の定義が `factory/api/src` のテスト以外のコードに 1 か所だけある。実行の制御の依存・進捗の受け口・GitHub の仲立ちの 3 か所はそれを呼ぶ
- [ ] 2. `factory/api/src/handlers/` の `.ts` に `GetSecretValueCommand` が現れない（`grep -n GetSecretValueCommand factory/api/src/handlers/*.ts` が 0 件）
- [ ] 3. `factory/api/src/handlers/ingest.ts` と `factory/api/src/handlers/github-oidc.ts` に、秘密か鍵の読み込みの結果を保持するモジュールの変数が無い
- [ ] 4. 共通の仕組みは、文字列の秘密と、文字列以外の値（署名の鍵の組など）の両方を同じ規則で保持できる
- [ ] 5. GitHub の仲立ちの署名の鍵の組は、共通の仕組みを通して読まれる
- [ ] 6. 読み込みが成功した後に何回求めても、Secrets Manager（または渡した読み込みの関数）は 1 回だけ呼ばれ、同じ値が返る（単体テスト）
- [ ] 7. 1 回目の読み込みが終わる前に 2 回目を求めたとき、読み込みの関数は 1 回だけ呼ばれ、両方が同じ結果を受け取る（単体テスト）
- [ ] 8. 読み込みが失敗したとき、その要求には例外が返り、次の要求で読み込みの関数がもう一度呼ばれる。2 回目が成功すればその値が返る（単体テスト）。環境変数が無いとき・`SecretString` が空のときも同じく読み直す
- [ ] 9. 失敗したときの例外の文言に、秘密の値が含まれない。文言には環境変数の名前か読む対象の名前だけが入る（単体テスト）
- [ ] 10. 失敗した読み込みを呼ぶ側が受け取った後、処理されない Promise の拒否が残らない（単体テストで `unhandledRejection` が起きない）
- [ ] 11. 環境変数の値（ARN）は、最初に秘密を求めた時点で読む。依存を組み立てる時点では読まない（今の振る舞いのまま）
- [ ] 12. 退行しない: `cd factory && npm ci && npm run check -w api` が終了コード 0 で終わり、既存のテストがすべて通る

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 性能・拡張性 | Lambda の 1 つの実行環境あたりの Secrets Manager の呼び出しの回数は、成功した後は秘密ごとに 1 回のまま変わらない（受け入れ条件 6・7） |
| 運用・保守性 | 秘密を読む Lambda を足すとき、共通の仕組みを呼ぶだけで同じ規則が効く（受け入れ条件 1・4） |
| セキュリティ | 秘密の値をログ・例外の文言・応答に出さない（受け入れ条件 9）。認証と認可の振る舞いを変えない（前提 4） |
