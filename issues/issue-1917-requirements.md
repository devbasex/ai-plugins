## 目的

- ベースブランチ（PR の宛先。スプリントの実装ならスプリントブランチ、スプリントの検査なら `.ndf/worktree.json` の `base_branch`）が検査の途中やマージの直前に進んでも、プランが自分で取り込み・衝突の解消・検査のやり直しをしてマージまで進む。conductor の手当て（取り込み・衝突の解消・全体テスト・`--from` での流し直し）を無くす
- 検査（sync・範囲テスト・doc-lint・全体テスト）を、ブランチ単独ではなくベースブランチとの合成の上で走らせ、合成で初めて落ちるチェック（行数の上限・用語集・配布物の同期）を PR の CI より前に見つける

今の作り（2026-10-16 の develop、c609cc236）:

- `plugins/ndf/scripts/supervise_lib/sprint_waves.py` の `plan_sprint_check`: 先頭の `collect` は `git pull -q --ff-only origin <スプリントブランチ>` で、ベースブランチを取り込まない
- `plugins/ndf/scripts/supervise_lib/templates.py` の `plan_check`: `test-all` は `git pull -q --rebase && <全体テスト>`（自分のブランチの追従だけ）。`merge_steps(a, on_fail="abort", next="record")` でマージが落ちると中断する
- `templates.py` の `plan_to_merge`（実装のプラン）: 作業の後に起点を取り込むステップが無く、sync・範囲テスト・doc-lint・全体テストはブランチ単独を見る
- `templates.py` の `plan_check_since`（差分の検査）だけが、`test-all` のコマンドの中で `git merge origin/<base>` を打ち、衝突を judge → fix へ回している
- `plugins/ndf/scripts/merged_lib/checks.py:82` の `PR_FIELDS` は `mergeStateStatus` を取るが、判定に使う箇所が無い。`merge-when-green` は `gh pr merge` の拒否（`not mergeable: the merge commit cannot be cleanly created`）を終了コード 1 で返し、プランは `abort`（検査）か judge（実装）へ進む

## 前提

- 前提 1: プランの `上限` は #1909（と #1676）の「上限を経路から決める」形が先に入り、ベースブランチの取り込みで増えたステップと戻りの経路は、その計算に入る。この主題はプランの `"上限"` の値を手で書き換えない。#1909 の形が入る前にこの主題を実装に入れるときは、実装の計画で上限の扱いを決め直す
- 前提 2: 戻りの回数の上限は、1 回のプランの実行で 3 回とする（4 回目の `DIRTY` で中断する）。並行のスプリントの本番リリースで起点が進む頻度（セッション 26 で 3 回）から置いた値で、誤っても定数 1 つで直せる
- 前提 3: ベースブランチの名前は今の引数（`a.base`）から読み、ai-plugins の `develop` を埋め込まない
- 前提 4: `mergeStateStatus` の `UNKNOWN`（GitHub が計算中）は衝突と扱わず、今の待ちを続ける。`BEHIND`（最新化を必須にする保護）は扱わない
- 前提 5: ベースブランチの取り込みはマージのコミットで行い、rebase や強制 push をしない（共通原則 C4 に当たる操作を足さない）

## 対象範囲

含む:
- ベースブランチの取り込みのステップ（取り込み → 用語集の自動解消 → 残った衝突は修正の worker）を 1 つの部品にし、実装のプラン・スプリントの検査のプラン（と単発の `new check --pr`）・差分の検査で共有する
- `merge-when-green` が衝突（`DIRTY` か、マージのコミットを作れない拒否）を、ほかの失敗と分けた終了コードで返す
- 実装のプランと検査のプランの `merge` / `merge-approved` が、その終了コードでベースブランチの取り込みへ戻る経路と、戻りの回数の上限
- テスト（一時リポジトリと `gh` のスタブ）

含まない:
- プランの `上限` の計算（#1909・#1676 の主題）
- 衝突の無い合成で、ベースブランチの取り込みの後（`merge` の直前）に起点が進んだときの検査のやり直し。スプリントの実装 PR では、合成の結果はスプリントの検査のプランがスプリントブランチの全体で検査する
- `BEHIND` の扱い、自動の rebase
- リリースのプラン・`promote` の `merge` の戻り（呼び手の振る舞いは変えない）
- 実装の worker の指示文（`impl_prompt`・`IMPL_RULES`・`FIX_PROMPT`。#1651 の主題）
