## 何が起きたか

利用者や AI が、中継（`ndf relay`）で claude のアカウントを 2 つ以上登録し、手順書 `relay-accounts.md` のとおりに「利用上限や認証の失敗で別のアカウントへ替わって続く」と期待して開発を流す。11 系のラッパーは、手順書が書く選び方・切り替え・API キーへの退避の多くを持たない。上限に当たったレーンは同じアカウントのまま止まり、利用者は手順書を信じて気づかない。

2026-11-19 に `main`（d16aa39d0）で手順書の主張を 1 つずつ `grep -rn` でコードと照らして見つけた（#3846 の設計の工程）。2026-11-21 の要求の工程（設計のフェーズ、スプリント p12-lracct-r1）で、手順書の 44 の主張を 11 系のコードと照らし直し、要求仕様の形へ書き直した。

## 種類

不具合（手順書 `relay-accounts.md` が既に約束している切り替えを 11 系で回復し、11 系に要らない約束は手順書から消して、手順書とコードを一致させる）

- 切り替えの判断は 2 つの純粋な関数が持つ（`account_decide.py`）

## なぜ困るか

手順書のとおりに複数のアカウントや API キーを登録した利用者が、上限・認証の失敗で切り替わると期待して、同じアカウントのまま止まったレーンに気づかない。AI も手順書から 11 系の振る舞いを読み誤る。使用率が記録されない限り、11 系のアカウントの切り替えは、#3604 で認証を替えても一度も働かない。

## 目的

- 2 つ以上のアカウントを登録した利用者のレーンが、利用上限・認証の失敗で止まらずに別のアカウントで続く
- 手順書を読んだ利用者と AI が、11 系の中継の振る舞いを正しく読める（書いてあることがコードにあり、コードの振る舞いが書いてある）

## 対象範囲

含む:
- 使用率の記録: 登録済みアカウントの使用率を、使用率の API ですべての登録済みアカウントから取り、使用率のキャッシュへ書く仕組み。取れないときと形が変わったときは、NDF の status line が受け取る `rate_limits` で今のアカウントの分を書く
- 上限の後の切り替え: 使用率が分からないアカウントも、使えるなら替え先の候補にする
- 認証の失敗（401）での切り替え: そのアカウントを一定の間候補から外し、ほかの候補で同じ会話を続ける。候補が無ければ直し方の 1 行を出して子を残す
- 指定（`account use`）を、動いているラッパーの次のセグメントの起動から効かせる
- 従量の接続への退避: 替え先のアカウントが無く、従量の接続の設定があれば、それで同じ会話を続け、上限でない登録済みアカウントが現れたらカットポイントを待たずに止めてよい時点でアカウントへ戻る
- 手順書 `relay-accounts.md` を 11 系の振る舞いだけにする（上の振る舞いを書き、11 系に無い振る舞いを消し、11 系にあって書いていない振る舞いを足す）。手順書が指す確定仕様・用語集の語の食い違いも合わせて直す

含まない:
- 子の起動の環境（設定ディレクトリ・symlink・`.claude.json` の同期・使えないアカウントを飛ばす判定）。#3604 が持つ
- 記録の行とキー（`account_dir`・`rule`・`account_rule`・`evidence`・`to_key`）の記述。#3846 で直した
- 閾値の値の見直し（#2588）
- `ndf plan` の worker を API キーで動かす近い上限の規則（#3991）
- `StopFailure` hook の `limit.json`・バックグラウンドの作業を待つ振る舞い・`NDF_ACCOUNT_CHECK_INTERVAL`（11 系の作りに合わないため、作らずに手順書から消す）

## 前提

- 前提 1: 使用率は、使用率の API（`api/oauth/usage`）ですべての登録済みアカウント（動いていないアカウントを含む）から取る。Claude Code が status line へ渡す入力の `rate_limits`（5 時間と 7 日の使用率とリセットの時刻）は、使用率の API が取れないときと形が変わったときの代わりに使う（2026-11-22 の利用者の決定）
- 前提 2: NDF の status line が設定されていない利用者のアカウントと、`ndf plan` の worker の `claude -p` のアカウントも、使用率の API で使用率が取れる
