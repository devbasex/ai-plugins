# #4211: 並列の計画: 検証と棚卸しをレーンから切り離し、オーガナイザーが環境・リポジトリごとにまとめて 1 本ずつ処理する（#4050 から分けた）

正は課題の本文（#4211）で、この文書はその写しである。本文から作り直す。手で直さない。

## 目的

- **今どうなっているか**: 並列の計画の検証（体裁レビュー・リリース後テスト）と棚卸しは、レーンの conductor が行ごとに流し、ほかのレーンとの排他を持たない。#4050 の本文は、検証を「環境ごとに 1 本」、棚卸しを「リポジトリで 1 本ずつ」とし、どちらも文脈の依存が薄いのでレーンから切り離してまとめて処理してよいと決めた（「コンテキストの依存と担い手」）。#4050 の設計（PR #4198）は、行がオーガナイザーへ委ねのリクエストを書き、オーガナイザーがまとめて空いたレーンか単発のレーンへ割り当てる形にしたが（2026-11-23 の利用者の決定で、担い手は `ndf:supervisor` でなくレーンにした）、cross-review でこの仕組みにだけ毎ラウンド新しい重い穴が出た
- **誰に効くか**: 並列の計画を流すすべての利用者
- **変えると何が成り立つか**: 同じ版の検証を行の数だけ繰り返さず、同じ環境での検証と棚卸しが 1 本ずつになる。検証と棚卸しは、それを求めた行のレーンでなく、空いたレーンか単発のレーンの conductor が流す

## 対象範囲

含む:
- 委ねのリクエスト（`lane-verify`・`lane-backlog`）と、委ねた回答の消費（`delegate_answered`）
- `ndf lanes batch claim / assign / close / abort`（取りかかりと放棄・`done` と `failed` の遷移・再実行）
- まとめた検証・棚卸しを 1 行（種類 `batch`）として、空いたレーン（同じリポジトリで行がすべて終わったレーン）へ足すか、無ければ単発のレーン（まとめ 1 つのために足し、`touches`・`after` は空）を足して置くこと。その行の起動の入力（`launch.py` の種類 `batch`）と、そのレーンの conductor が `batch close` を打って行を終える流れ
- 検証の環境の宣言（`verify.environment`）と、環境・版の排他（別の計画を含む）・リリースとの相互排他・版の不一致の扱い

含まない:
- 同じ行の中で回答の待ちを越えて工程を流すこと（#4210）
- レーンの本数の数え（#4171 の領域）。単発のレーンは今の行の起動（マシン全体の上限の判定）をそのまま通る
- オーガナイザーの会話から単発の担い手（`ndf:supervisor`）を起動する形（利用者がレーンへ任せる形を選んだ）

## 受け入れ条件

- [ ] 1. 計画の行の検証は委ねのリクエストを 1 回だけ書いて回答を待ち、同じ環境のリクエストは 1 本のまとめで処理される（テスト）
- [ ] 2. 同じ環境の取りかかりは 1 つだけで、別の計画からの取りかかりも断る。放棄した取りかかりは空く（テスト）
- [ ] 3. 棚卸しは委ねた時点で行の工程を終え、`failed` のまとめは計画を完了させない（テスト）
- [ ] 4. `batch assign` が、名指した空いたレーンへ種類 `batch` の行を足すか、名指さなければ単発のレーンを足し、耐久ワークフローが今の行の起動でその行を始める。そのレーンの conductor の `batch close` が各行へ回答を書いて行を終える。名指したレーンに未着手か実行中の行があれば断る（テスト）
