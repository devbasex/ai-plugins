# #4068: 中継の下で背景の作業を長く待つ子の、プロンプトのキャッシュの扱いを決める（起こす・引継ぎへ切り替える）

正は課題の本文（#4068）で、この文書はその写しである。本文から作り直す。手で直さない。

中継の下で背景の作業か監視を待つ子（オーガナイザー・レーンの conductor）が、プロンプトのキャッシュの寿命（1 時間）を越えて待っても、待ちが明けた最初の応答で文脈の全体を書き直さない状態にする。寿命の手前で NDF の hook が子を起こしてキャッシュを保ち、起こす費用が 1 回の書き直しを上回る長さになったら起こすのをやめる。監視だけを待つ子は、そこで待機を終えて引継ぎへ切り替えられる。

## 具体例

2026-10-24〜11-22 の会話の記録（このマシンの `~/.claude/projects/` の全 810 本余りと、その下のサブエージェントの記録）を数えた。直前の文脈が 20,000 token 以上の主の会話で、応答の間が 1 時間を超えたのは 263 回あり、263 回とも次の応答でキャッシュが当たらず、文脈を書き直した（書き直した合計は 44,641,212 token）。間の中央は 1.9 時間、文脈の中央は 172,812 token で、250,000 以上が 64 回あった。

| 応答の間 | キャッシュが当たった | 当たらなかった |
| --- | --- | --- |
| 5 分〜30 分 | 2,704 | 42 |
| 30 分〜55 分 | 493 | 28 |
| 55 分〜60 分 | 106 | 14 |
| 60 分〜65 分 | 12 | 15 |
| 65 分〜2 時間 | 1 | 144 |
| 2 時間超 | 0 | 104 |

モデルは主に Claude Opus 5.5 で、書き直しは入力の 2 倍、読み出しは 0.05 倍の値段である。172,812 token の文脈なら、書き直し 1 回は 345,624 token 相当、50 分ごとに起こして読み出す 1 回は約 8,600 token 相当（起こす入力と返事を除く）になる。263 回の待ちの全部を 50 分ごとに起こしていれば、費用は書き直しの約 1 割で済んだ（設計の「測った結果」に式と内訳がある）。

## なぜ困るか

#4049 で、背景の supervisor や `ndf plan queue` を待つ子は止められずに待つようになる。待ちは supervisor の 1 フェーズ・CI・承認の取り次ぎに及び、1 時間を越えることが多い（上の 263 回の間の中央は 1.9 時間）。待ちが明けた最初の応答は、文脈の全体を入力の 2 倍の値段で書き直す。運用上限（500,000）近くの文脈では、その 1 回が約 1,000,000 token 相当になり、読み出し 1 回（約 25,000 token 相当）の 40 回分にあたる。定額のプランでは週の利用上限を早く使い、上限に当たれば全レーンが止まる（#4069 の配慮する事項 2）。

## 目的

- 中継の下で待つ子のプロンプトのキャッシュが、寿命の内に起こされて保たれ、待ちが明けた応答で文脈の全体を書き直さない状態にする
- 起こす費用が書き直し 1 回を上回る長さの待ちでは、起こし続けず、監視だけの子は待機を終えて引継ぎへ切り替わる状態にする
- 起こす間隔と上限を決める値が `limits.json` の 1 か所にあり、記録から測った値で見直せる状態にする

## 前提

- 前提 1: キャッシュの寿命は、キャッシュを書くか読む要求の始まりから数え、読むたびに追加の費用なしで延びる（公式の文書）。子を起こして文脈を読ませれば、寿命はその時点から延びる
- 前提 2: 背景で動く hook（`asyncRewake`）は、終了コード 2 で終わると入力を待つ会話をすぐに起こし、標準エラーの文を system reminder としてモデルへ渡す。Claude Code は `asyncRewake` の hook にも `timeout` を課す（公式の文書と 2026-11-22 の実測）。長い `timeout`・起こす鎖の続行の上限・会話の終わりで眠る hook が終わるか・質問の表示中の振る舞いは、実装の最初に測り、通った版でだけ働かせる
- 前提 3: 子を起こす応答は、子の会話へ目印つきの入力 1 件と 1 行の返事を足す（1 回に数百 token）。起こす回数の上限が子の文脈を運用上限まで押し上げることは無い
- 前提 4: 費用の比べは、従量の接続の値段の比（入力に対する書き込みと読み出しの倍率）で行う。定額のプランが週の利用上限に書き込みと読み出しをどの比で数えるかは公開されておらず、同じ比で近似する（確かめ方は設計の「未確認のまま残ること」）
- 前提 5: 起きた応答の前に UserPromptSubmit が発火する（実測）。その入力を中継の入力として見分ける形（起こす文の頭か中継のマーカー）は、前提 2 の実測で決める
- 前提 6: この課題の実装は #3995 → lracct（#3604・#3864）→ #4049 の実装の後に行う。#4049 の背景の作業の記録（作業と監視の件数）を読む
- 前提 7: NDF は普及のフェーズの前で、記録の行と上限の設定の形を変えても互換の経路を持たない（MVV Value 4）

## 受け入れ条件

この節で「待つ子」は、中継の下の子のうち、直前の Stop の入力の背景の作業の列（`background_tasks`。#4049 の作業と監視の分け方で数える）に作業か監視が 1 件以上あり、回答待ちの質問が無い子を指す。「最後の応答の時刻」は、子の会話の記録の最後の応答（`assistant` の行）の時刻を指す。「起こす hook」は、子の Stop で背景に起動し（`asyncRewake`）、起こすときに終了コード 2 で終わる NDF の hook を指す。

- [ ] 1. 待つ子の最後の応答の時刻から起こす間隔（キャッシュの寿命 − 余白。1 時間の寿命の既定で 3,000 秒）が過ぎたとき、起こす hook は終了コード 2 で終わって子を 1 回起こす。起こす間隔の 1 秒手前では起こさない。起こす間隔が 0 以下になる寿命（5 分）では起こさない
- [ ] 2. 起こす hook は、その hook を起動した Stop の後に同じ会話で新しい Stop か利用者の入力（UserPromptSubmit）があったとき・ラッパーの今の起動がその hook の起動と違うとき・回答待ちの質問があるときは、起こさずに終了コード 0 で終わる。遅れて動いた古い Stop の hook も起こさない。1 つの会話を同じ時点に起こす hook は 1 つだけになる
- [ ] 3. 起こす hook は、ラッパーが渡す環境変数（`asyncRewake` に対応すると確かめた Claude Code の版でだけ渡す）が無ければ、眠らずにすぐ終了コード 0 で終わる。中継の外の会話と、Stop が背景で動かない版では、応答の終わりを待たせない
- [ ] 4. 今の待ちで起こした回数が起こす回数の上限 `n_max = floor((w − r) × S / (r × S + d))` に達したら、作業の子をそれ以上起こさない（`S` は文脈の量、`w` は寿命の書き込みの倍率、`r` はモデルの読み出しの倍率、`d` は起こす応答 1 回の費用）。上限は Opus 5.5・1 時間の寿命・`S` = 400,000・`d` = 2,000 で 35 になり、値を差し替えると差し替えた値で決まる
- [ ] 5. 監視だけを待つ子で、文脈の量が判断開始の値（#3995 が返す値。`NDF_CONTEXT_LIMIT` で下がった値を含む）以上なら、上限の内の最後の 1 回を、待機を終えて引継ぎ文書を書き次のセグメントへ切り替えるよう求める文にする。求めた後はその会話で起こさない。判断開始の値未満なら、最後の 1 回も起こす文にして上限でやめる。作業が残る子には引継ぎを求めない
- [ ] 6. 寿命はその子の最後の応答の `usage` の寿命ごとの書き込みで決める（1 時間の書き込みがあれば 1 時間、5 分だけなら 5 分）。読み出しの倍率は記録のモデルで決め、上限の設定に無いモデルは既定の倍率を使う
- [ ] 7. 子の会話の記録が読めない・最後の応答に `usage`・時刻・寿命の項目が無い・形が違うときは、前の応答へさかのぼらずに起こさない（何もしない側へ落ちる）。その会話で 1 度だけ理由を記録に残す
- [ ] 8. 起こす文から始まった応答の `usage` の読み出しが、起こす前の文脈の量の 9 割未満なら（キャッシュが当たらなかった）、その会話では起こすのをやめ、理由を記録に残す。別の入力が先に応答したときは当たりを判じない

- [ ] 10. 起きた応答（起こす文と引継ぎへ切り替える文の両方）で、#3995 の数え手が利用者の入力として数え直さない
- [ ] 11. 待ちの始まり・起こした・起きた応答の結果・待ちの終わり（当たったか書き直したか）・やめた、のそれぞれで、起こす記録に 1 行を書く。行は待ちの ID でつながり、文脈の量・寿命・モデル・起こした回数・上限と、応答の行は読み出しと書き込みと出力の token を持つ

## 用語

| 用語 | 意味 |
| --- | --- |
| キャッシュの寿命 | プロンプトのキャッシュが、書くか読む要求の始まりから保たれる時間。Claude Code の主の会話は 1 時間、サブエージェントは主に 5 分（実測） |
| キャッシュを起こす | 寿命の内に待つ子を起こして短く応答させ、文脈を読み出しの値段で読ませてキャッシュの寿命を延ばすこと |
| 起こす hook | 子の Stop で背景に起動し（`asyncRewake`）、起こす時点に確かめ直して、起こすなら終了コード 2 で終わる NDF の hook |

| 起こす間隔 | 最後の応答の時刻から起こすまでの秒。寿命から余白を引いた値 |
| 起こす回数の上限 | 起こした費用の合計が、書き直し 1 回の費用を上回らない最大の回数 |
| 書き直し | キャッシュが切れた後の応答で、文脈の全体をキャッシュへ書き込むこと（入力の 1.25 倍か 2 倍の値段） |
