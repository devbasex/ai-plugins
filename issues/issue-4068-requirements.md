中継（`ndf relay` のラッパー）の下でバックグラウンドの作業か監視を待つ子（オーガナイザー・レーンの conductor）が、プロンプトのキャッシュの寿命（1 時間）を越えて待っても、待ちが明けた最初の応答で文脈の全体をキャッシュへ書き直さない状態にする。そのために、寿命の手前で NDF の hook が子を起こしてキャッシュを保つ。起こす費用の合計が書き直し 1 回分に届いたら、起こすのをやめる。監視だけを待つ子は、そこで待機を終えて引継ぎへ切り替えられる。

## 何が起きたか

2026-10-24〜11-22 の会話の記録（このマシンの `~/.claude/projects/` の全 810 本余りと、その下のサブエージェントの記録）を数えた。直前の文脈が 20,000 token 以上のメインの会話で、応答の間が 1 時間を超えたのは 276 回あった。そのうち 263 回は次の応答でキャッシュが当たらず、文脈を書き直した（書き直した合計は 44,641,212 token）。残りの 13 回は、下の表の 60 分〜2 時間の行で当たった。書き直した 263 回では、応答の間隔の中央値が 1.9 時間、直前の文脈の量の中央値が 172,812 token で、250,000 token 以上が 64 回あった。

## 前提

## 受け入れ条件

この節で「待つ子」は、中継の下の子のうち、直前の Stop の入力のバックグラウンドの作業の列（`background_tasks`。#4049 の作業と監視の分け方で数える）に作業か監視が 1 件以上あり、回答待ちの質問が無い子を指す。「最後の応答の時刻」は、子の会話の記録の最後の応答（`assistant` の行）の時刻を指す。「起こす hook」は、子の Stop でバックグラウンドに起動し（`asyncRewake`）、起こすときに終了コード 2 で終わる NDF の hook を指す。

- [ ] 1. 待つ子の最後の応答の時刻から起こす間隔（キャッシュの寿命 − 余白。1 時間の寿命の既定で 3,000 秒）が過ぎたとき、起こす hook は終了コード 2 で終わって子を 1 回起こす。起こす間隔の 1 秒手前では起こさない。起こす間隔が 0 以下になる寿命（5 分）では起こさない
- [ ] 2. 起こす hook は、その hook を起動した Stop の後、起こす直前の確かめ（子を止めるロックの中）までに、同じ会話で新しい Stop か利用者の入力（UserPromptSubmit）があったとき・ラッパーの今の起動がその hook の起動と違うとき・回答待ちの質問があるときは、起こさずに終了コード 0 で終わる。遅れて動いた古い Stop の hook も起こさず、起こす状態と起こす記録を書き換えない。ただし、2 つの hook が同じ応答を自分の Stop の応答として取りに来て、どちらが古いかを決められないときは、後から来た hook が起こす状態の世代に取り合いの印（`contested`）だけを書き、どちらの hook も起こさない（印のほかは書き換えない。設計の決定 4）。1 つの会話を同じ時点に起こす hook は 1 つだけになる。入力の `session_id` がラッパーの渡した会話の ID と違う会話（入れ子の claude）では、起こさず、起こす状態も変えない。確かめの後に届いた入力とは競合し、その起床の当たりは判定しない（設計の決定 6）
- [ ] 3. 起こす hook は、ラッパーが渡す環境変数（`asyncRewake` に対応すると確かめた Claude Code の版でだけ渡す）が無ければ、眠らずにすぐ終了コード 0 で終わる。中継の外の会話と、Stop がバックグラウンドで動かない版では、応答の終わりを待たせない
- [ ] 4. 今の待ち（待つ子の Stop で始まり、利用者の入力かバックグラウンドの作業の知らせで始まったと確かめた応答の Stop で終わる 1 回の待ち。起こす文で始まった応答と、始めた入力の形を決められない応答では終わらない）で起こした回数が起こす回数の上限 `n_max = floor((w − r) × S / (r × S + d))` に達したら、作業の子をその待ちではそれ以上起こさない。次の待ちでは回数を 0 から数え、上限をその始まりの文脈の量で決め直す（`S` は文脈の量、`w` は寿命の書き込みの倍率、`r` はモデルの読み出しの倍率、`d` は起こす応答 1 回の費用）。上限は Opus 5.5・1 時間の寿命・`S` = 400,000・`d` = 2,000 で 35 になり、値を差し替えると差し替えた値で決まる
- [ ] 5. 監視だけを待つ子で、文脈の量が判断開始の値（#3995 が返す値。`NDF_CONTEXT_LIMIT` で下がった値を含む）以上なら、引継ぎの費用まで含めた起こす費用の合計が書き直し 1 回の追加の費用に収まる最後の起床を、待機を終えて引継ぎ文書を書き次のセグメントへ切り替えるよう求める文にする。引継ぎの費用は、引継ぎの起床の読み出し・引継ぎ文書の出力・次のセグメントの始まりの書き込みの和で、収まるかは判定の時の文脈の量で決める（設計の決定 5）。そのため、この起床は `n_max` 回目より前になることがある。どの回でも引継ぎが収まらないとき（待ちの間に文脈の量が減って収まらなくなったときを含む）は求めず、作業の子と同じく上限でやめる。求めた後はその会話で起こさない。判断開始の値未満なら引継ぎを求めず、上限でやめる。作業が残る子には引継ぎを求めない

## 用語

| 用語 | 意味 |
| --- | --- |
| キャッシュの寿命 | プロンプトのキャッシュが、書くか読む要求の始まりから保たれる時間。Claude Code のメインの会話は 1 時間、サブエージェントは主に 5 分（実測） |
| キャッシュを起こす | 寿命の内に待つ子を起こして短く応答させ、文脈を読み出しの値段で読ませてキャッシュの寿命を延ばすこと |
| 起こす hook | 子の Stop でバックグラウンドに起動し（`asyncRewake`）、起こす時点に確かめ直して、起こすなら終了コード 2 で終わる NDF の hook |
| 起こす記録 | 起こす hook が中継の保存先に書く、起こした・やめた・書き直したの行の記録 |
| 起こす間隔 | 最後の応答の時刻から起こすまでの秒。寿命から余白を引いた値 |
| 起こす回数の上限 | 起こした費用の合計が、書き直し 1 回の追加の費用 `(w − r) × S`（書き直しの値段 `w × S` から、起こして当たったときにも払う読み出しの値段 `r × S` を引いた差）を上回らない最大の回数。式は受け入れ条件 4 |
| 書き直し | キャッシュが切れた後の応答で、文脈の全体をキャッシュへ書き込むこと（キャッシュの再書き込み。入力の 1.25 倍か 2 倍の値段） |
| セグメント | 中継の下の 1 つの会話。子が引継ぎ文書と `ndf-next` のブロック（次の会話の最初の入力を書いた決まった形のコードブロック）を出すと、ラッパーが子を止め、同じ端末で新しい会話（次のセグメント）を起動する |
| 守り 1 | 中継のアカウントの切り替えの 1 つ目の守り。利用上限の閾値の手前で、同じ会話を別のアカウントで `--resume` して続ける（確定仕様 `ndf-relay-account-switching.md`） |
| lracct | #3604・#3864 の、利用上限に当たったアカウントから別のアカウントへ子を切り替えて続ける中継の仕組み |
| MVV | NDF の使命・目指す姿・価値を書いた正本（`.ndf/mvv.md`）。Value 2 は「安く使える。待機する文脈は、プロンプトのキャッシュの寿命の内に使うか、必要ならキャッシュを起こす。起こす費用が見合わなければ待機を終える」 |
