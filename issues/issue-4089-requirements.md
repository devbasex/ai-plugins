# #4089: 文脈の量を読んだ応答を返り値に持たせ、古い量と圧縮の前の量で判定しない

正は課題の本文（#4089）で、この文書はその写しである。本文から作り直す。手で直さない。

会話の記録（transcript）から文脈の量を読む関数が、どの応答の量を返したかと、その量が今の応答のものかを返すようにする。判定する側（#3995 の guard `context-limit`・中継のラッパーの引継ぎの判定・#4068 の起こす hook）は、それを見て古い量を古いと知った上で決める。会話の圧縮（compact）の前の量と、合成の応答（API の失敗の知らせ）の 0 は、文脈の量として返さない。

## 具体例

2026-11-23 06:11〜06:20 JST（UTC では 2026-11-22 21:11〜21:20）に、Claude Code 2.1.328・2.1.329・2.1.330 を Haiku 5.5 で動かした。`claude -p` で 4 回（2.1.330 は Tool 1 つの会話と 2 つの会話の 2 回）、2.1.330 の対話の形（端末で起動し、入力を送る）で 1 回である。「`start` と言って `echo hi` を打ち、`middle` と言って `echo bye` を打ち、`done` と答える」会話に、PreToolUse・PostToolUse・Stop の hook を置き、hook が動いた時点の会話の記録の末尾を残した。

| 時点 | 今の応答が記録にあったか（3 版・5 回の会話） |
| --- | --- |
| 1 つ目の Tool の PreToolUse | 5 回のうち 1 回（2.1.330 の `-p`）だけあった。4 回は最後の会話の行が利用者の入力だった |
| 2 つ目の Tool の PreToolUse | 4 回のうち 1 回（2.1.330 の対話の形）だけあった。3 回は最後の応答が 1 つ前の応答（`start` と `echo hi`）だった |
| PostToolUse | 9 回のうち 8 回あった。2.1.329 の 2 つ目の Tool の PostToolUse では無かった |
| Stop | 5 回とも無かった。Stop の入力の `last_assistant_message` は `done` だったが、記録の最後の応答は `middle` と `echo bye` の応答だった。`done` の応答は Stop の後に書かれた |

同じ版・同じ形の起動でも、有るときと無いときがある。記録を書く時点と hook の時点は競り、版の一覧では決まらない。

今の 2 つの関数（`domains/hooks/context.py` の `context_tokens` と `domains/relay/observe.py` の `context_tokens`）は、末尾から `usage` を持つ最初の行を探して、その和を返す。今の応答が無ければ前の応答の量を、前の応答も無ければ前の利用者の入力より前の応答の量を返し、どの応答の量かを返さない。

同じ探し方は、ほかに 2 つの量を返す。

- **合成の応答の 0。** 利用上限や API の失敗のとき、Claude Code は `message.model` が `<synthetic>` の `assistant` の行を書き、その `usage` は 3 つの数がすべて 0 である。このマシンの会話の記録で 32 行あった（31 行が API の失敗、1 行が `No response requested.`）。今の関数はこの行で 0 を返す
- **圧縮の前の量。** 会話の圧縮の後の記録は、`system` の `compact_boundary` の行（圧縮の前の量 `preTokens` と後の量 `postTokens` を持つ）の後に、`usage` を持たない利用者の行（要約）が続く。28 回の圧縮のすべてで、圧縮の後の最初の応答の前は `usage` を持つ行が境の後に無かった。今の関数は境を越えてさかのぼり、圧縮の前の量（23 万〜41 万）を返す。運用上限（500,000）を越えてから圧縮した会話では、圧縮の直後の Tool を guard が止める

## 種類

不具合修正（2 つの読み手の説明（`domains/hooks/guards/context_limit.py`・`domains/relay/observe.py` の docstring）と #3995 の設計は「最後の応答の文脈の量」で判定すると書くが、関数は最後の応答でない量（1 つ前の応答・圧縮の前・合成の応答の 0）を返す）

## 今の姿

main の `ec8340675` で確かめた。パスは `plugins/ndf/src/ndf/` からの相対で書く。

- **読み手は 2 つあり、同じ探し方を別々に持つ。** `domains/hooks/context.py` の `context_tokens(tail)` を guard `context-limit`（`domains/hooks/guards/context_limit.py`）が PreToolUse で使う。`domains/relay/observe.py` の `context_tokens(path, size)` を中継のラッパー（`domains/relay/wrapper.py` の `SectionState`）が見回りごとに使い、`switch_decide` が「文脈の量が上限以上で子が 5 秒静か」なら引継ぎを求める
- **どちらも量だけを返す。** 応答の ID・時刻・その量が今の応答のものかを返さない。同じ `message.id` の複数の行は同じ `usage` を持つので、量の値は変わらない
- **関わる設計（main にマージ済み・実装はこれから）**
  - #3995: guard `context-limit` が PreToolUse で 500,000 以上を止め、PostToolUse で 250,000 以上を利用者の入力ごとに 1 度知らせる。PreToolUse が読んだ量を `tool_use_id` ごとに覚え、PostToolUse はそれを使って読み直さない（設計の決定 3）
  - #4049: ラッパーの引継ぎの判定の前に、背景の作業の記録を読んで、作業が残る子を待つ
  - #4068: 起こす hook が Stop で最後の応答を読み、Stop の入力の `last_assistant_message` と文が同じときだけ今回の応答とし、違えば前の応答へさかのぼらずに起こさない（設計の決定 4）。読み方を自分で持つ（詳細設計の `keep_cache.last_turn`）

## 何を足すか・変えるか

| | 今 | 足した後 |
| --- | --- | --- |
| 読み手 | 2 つの関数が量だけを返す | 1 つの関数が、量・どの応答か（`message.id`・時刻）・今の応答のものか（`current`・`behind`・`none`）を返す |
| 今の応答の見分け | しない | 呼ぶ側が手がかりを必ず渡す。PreToolUse・PostToolUse は `tool_use_id`、Stop は `last_assistant_message`、ラッパーは手がかり無し（最後の会話の行か） |
| 合成の応答 | 0 を返す | 応答として数えない |
| 圧縮の境 | 越えてさかのぼる | 越えない。境の後に応答が無ければ量は無し |
| guard `context-limit` | 古い量でも今の量として判定する | 古い量は「ほぼこれだけはある」として上限以上の判定に使う。判定の記録に状態を残す |
| ラッパーの引継ぎの判定 | 古い量でも今の量として判定する | 同じく上限以上の判定に使う |
| #4068 の起こす hook | 自分で読み方を持つ | 同じ関数で今の応答かを確かめる |

## なぜ困るか

- **圧縮の直後に止められる。** 圧縮の前の量は運用上限を越えていることがあり（圧縮の前の量は 41 万まで見つかった）、そのとき guard は圧縮した後の会話の Tool を止め、引継ぎを求める。圧縮で減った文脈を捨てて、引継ぎの費用と時間を払う（MVV 版 11 の Value 2）
- **API の失敗の後に 0 を読む。** ラッパーは引継ぎを求めず、guard は止めない。次の応答で直るが、判定の記録に誤った 0 が残る
- **今の応答の量か分からない。** 1 つ前の応答の量は、今の応答の量より 1 応答分少ない。このマシンの会話の記録で、続く 2 つの応答の量の差は中央 1,244・上位 1% で 25,423・最大 83,623 token だった。#4068 の当たりの判定（読み出しが `S` の 9 割以上）のように量そのものを使う判定は、古さを知らずに使うと誤る。古さを知らせる手段が無いので、判定ごとに読み方を作り直している（#4068 の `last_turn`）

## 目的

- 文脈の量を読む関数が 1 つになり、どの応答の量で、今の応答のものかを返す
- 判定する側が、古い量・圧縮の前の量・合成の応答の 0 で誤って止めない・止め損なわない
- Claude Code の版が記録を書く時点を変えても、版の一覧を持たずに同じ規則で振る舞う

## 対象範囲

含む:
- 会話の記録の末尾から、最後の応答の文脈の量と、その応答の ID・時刻・今の応答かを読む 1 つの関数と、その返り値の形
- 今の応答かを見分ける手がかり（`tool_use_id`・`last_assistant_message`・手がかり無し）と、合成の応答・圧縮の境の扱い
- 古い量のときの guard `context-limit`（#3995 の PreToolUse の止めと PostToolUse の知らせ、`tool_use_id` ごとに覚える値）・ラッパーの引継ぎの判定（#3995・#4049）・#4068 の起こす hook の振る舞い
- 判定の記録（guard の `notes`）に、読んだ量が今の応答のものかを残すこと

含まない:
- 閾値の値（#3995）と、背景の作業を待つ規則（#4049）・起こす規則と費用の式（#4068）。この課題は読む量の確かさだけを変える
- #4068 の当たりの判定で、起こした応答を見分ける規則（起こす文の後の最初の呼び出し）。量の和と同じ `message.id` のまとめ方だけをこの関数から借りる
- 利用上限の行・認証の失敗・止めてよい時点（`observe.py` の `_talk`・`_pending`）の読み方
- Codex の会話（記録の形が違い、ラッパーは Claude Code だけを包む）
- 確定仕様の書き換え（確定仕様化の工程で直す）

## 前提

- 前提 1: 1 つの応答は同じ `message.id` の複数の行で記録され、どの行も同じ `usage` を持つ（実測）。Tool を呼ぶ応答は、その Tool の `tool_use` の要素（`id` が `tool_use_id`）を持つ行を含む
- 前提 2: 同じ会話の中で、圧縮の境をまたがない続く 2 つの応答の量はほとんど減らない。このマシンの会話の記録の 125,537 組で、減ったのは 14 組、減った量は最大 8,014 token（前の量の 5% 未満）だった。古い量は今の量のほぼ下限として扱える
- 前提 3: Stop の入力の `last_assistant_message` は今回の応答の文を持つ（公式の文書と実測）。Tool の入力の `tool_use_id` は呼び出しを一つに決める
- 前提 4: 会話の記録の形は Claude Code の公開の契約ではない。形が変わったときは量を返さない側へ落ちる
- 前提 5: NDF は普及のフェーズの前で、関数の名前と返り値の形を変えても互換の経路を持たない（MVV 版 11 の Value 4）
- 前提 6: この課題の実装は #3995 の実装と同じ時期かその後に行う。#3995・#4068 の実装がこの関数を使う

## 受け入れ条件

この節で「読み手」は文脈の量を読む 1 つの関数を、「応答」は同じ `message.id` の `assistant` の行のまとまり（`message.model` が `<synthetic>` の行を除く）を、「今の応答」は呼ぶ側が渡した手がかりに合う応答を指す。

- [ ] 1. 読み手は、量・応答の ID（`message.id`）・応答の時刻（その ID の最後の行の `timestamp`）・状態（`current`・`behind`・`none`）と、`current` でない理由を返す。呼ぶ側は手がかり（`tool_use_id`・`last_assistant_message`・手がかり無しのどれか）を必ず渡す。`domains/hooks/context.py` と `domains/relay/observe.py` の `context_tokens` は残らず、guard `context-limit` とラッパーがこの読み手を使う
- [ ] 2. `tool_use_id` を渡すと、その ID の `tool_use` の要素を持つ応答が読む範囲（圧縮の境より後）にあるときだけ `current` で、記録の最後の応答の量を返す（その応答か、それより後の応答）。無ければ、記録の最後の応答の量を `behind` で返す
- [ ] 3. `last_assistant_message` を渡すと、最後の応答の `text` の要素をファイルの順につないだ文がそれと同じで、その応答の後に利用者の行が無いときだけ `current` を返す。どちらかに外れる・Stop の入力に `last_assistant_message` が無いときは `behind` を返す
- [ ] 4. 手がかりを渡さないと、最後の応答の後に利用者の行（入力・Tool の結果・`isMeta` の行）が無いときだけ `current` を返す。あれば `behind` を返す。会話でない行と `isSidechain` の行は数えない（`isMeta` の行と `isSidechain` の行は「用語」の表）
- [ ] 5. 合成の応答（`message.model` が `<synthetic>`）は応答として数えない。合成の応答だけが後ろにある記録では、その前の応答の量を返し、0 を返さない
- [ ] 6. 最後の `system` の `compact_boundary` の行より前の応答の量を返さない。境の後に応答が無ければ、量は無く状態は `none` で、理由に圧縮を返す。最後の応答より新しい行に JSON として読めない行（書きかけ・壊れた行）があるとき・応答が 1 つも無いとき・記録が読めないとき・照らしを通った応答の採用行（最も新しい物理の行）の形（`usage`・`message.id`・UNIX 秒に直せる `timestamp`）が違うときも `none` を返す
- [ ] 7. guard `context-limit` の PreToolUse は、状態に関わらず量が運用上限以上なら止め、`behind` で上限未満なら止めない。運用上限は、記録から読めた量で次の判定から止める運用の閾値であり、上限をまたいだ応答の Tool の呼び出しは、その応答の量が記録から読めるまで通る（記録を待たない）。PostToolUse の知らせは #3995 の規則（判断開始の値以上・運用上限未満で、利用者の入力ごとに 1 度）のまま、量の状態を問わない。止め・知らせ・何もしないの判定の記録（`notes`）は、量（`context_tokens`）と状態（`context_state`）を持つ
- [ ] 8. #3995 の PreToolUse が `tool_use_id` ごとに覚える値は、量とともに状態を持つ。PostToolUse は覚えた値を状態ごと使い、読み直さない（読み取りの回数は #3995 の設計のまま）。状態の無い値は `behind` とみなす
- [ ] 9. ラッパーは、状態に関わらず量が運用上限以上で子が静かなら、今の引継ぎの判定（#4049 の待ちを含む）へ進む。`behind` で上限未満なら引継ぎを求めず、次の見回りで読み直す。`none` なら引継ぎを求めない。記録が読めない（権限の誤りなど）ときも見回りは止まらない
- [ ] 10. #4068 の起こす hook が今回の応答を確かめるとき、この読み手に `last_assistant_message` を渡して `current` のときだけ今回の応答とする。照らしを通った応答の採用行の形（`usage`・`message.id`・`timestamp`）の違いは「記録の形が違う」、それ以外の `current` でない結果は「今回の応答が未記録」（一時的。次の Stop で読み直す）として扱う。寿命・モデル・キャッシュと出力の量は、量と同じ採用行から読み、記録を読み直さない
- [ ] 11. 読み手は、呼ぶ側がすでに読んだ記録の末尾だけを使い、記録を読む回数を増やさない
- [ ] 12. 1〜10 を、hook の時点で今の応答が有る・無い（上の具体例の 4 つの時点の形）・合成の応答が後ろにある・圧縮の境の後に応答が無い・有る・書きかけの行がある・同じ `message.id` が複数の行にある・同じ文の応答が続く・上限をまたぐ応答が未記録の間と記録の後の記録の見本で確かめるテストがある。上限と判断開始の値の境は、値 − 1・値の量で確かめる。.md の文言を照らすテストにしない
- [ ] 13. 設計文書が、実測した Claude Code の版と、hook の時点ごとに今の応答が記録にあったかを、版と日付とともに持つ

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わらない（hook の拒否と案内の文、ラッパーの振る舞いの規則は同じ。guard の判定の記録の `notes` に状態の項目が増え、知らせの判定も `notes` を持つ） |
| データ | 無し |
| 既存の振る舞い | 圧縮の直後に、圧縮の前の量で止める・引継ぎを求めることが無くなる。API の失敗の後に 0 を読まない。今の応答が記録に無い時点の判定は、1 つ前の応答の量で「上限以上」だけを判定する（今と同じ値で同じ結果になる） |

## 用語

| 用語 | 意味 |
| --- | --- |
| 文脈の量 | 応答の `usage` の入力・キャッシュの読み出し・キャッシュの書き込みの token の和 |
| 応答 | 同じ `message.id` の `assistant` の行のまとまり。合成の応答を除く |
| 今の応答 | 呼ぶ側の時点の応答。Tool の hook ではその Tool を呼んだ応答、Stop では Stop を起こした応答、ラッパーでは記録の最後の会話の行である応答 |
| 古い量 | 今の応答より前の応答の量（状態 `behind`）。圧縮の境をまたがなければ、今の量のほぼ下限になる |
| 合成の応答 | Claude Code が API を呼ばずに書く `assistant` の行（`message.model` が `<synthetic>`）。`usage` はすべて 0 |
| 圧縮の境 | 会話の圧縮で Claude Code が書く `system` の `compact_boundary` の行 |
| `isMeta` の行 | Claude Code が利用者の入力の形で会話へ差し込む内部の行（Skill の本文・Stop の hook の差し戻しの文・画像の注記など）。`isMeta` が真の `user` の行で、次の応答の入力に含まれるので、応答の後に足された文脈として利用者の行に数える |
| `isSidechain` の行 | サブエージェントの会話の行（`isSidechain` が真）。親の会話の文脈ではなく、その `usage` は子の量なので、応答にも利用者の行にも数えない |
| 中継のラッパー | 中継（relay）の下で子の Claude Code を包んで動かし、見回りごとに子の画面と会話の記録を読む NDF のプロセス（`domains/relay/wrapper.py`） |
| 引継ぎ | 文脈が大きくなった子を止め、引継ぎ文書を書かせて新しい会話へ作業を移す手順 |
| 運用上限 | 引継ぎを始める文脈の量の運用の閾値。既定 500,000（#3995 の `context.limit`）。モデルの文脈の窓の端ではない |
| 判断開始の値 | 次の区切りで引継ぎを考え始めるよう知らせる文脈の量。既定 250,000（#3995 の `context.decide-from`） |
| 起こす hook | #4068 が置く Stop の hook。キャッシュが切れる前に待ちの会話を起こすかを、最後の応答の量と時刻で決める |
