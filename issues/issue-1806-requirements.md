## 直さないと何が起きるか

- 落ちるたびにフレーキーの判定のため落ちたテストを走らせ直す。全体テストが 5〜6.5 分のこのリポジトリでは、その分だけ待ちが延びる
- cross-refactoring の着手前のテストで落ちると「既存失敗」として固定され、その実行の間はこのテストが最終ゲートの検出から外れる（cross-refactoring 自身のテストなので、cross-refactoring の改修を検査する実行で検出力が落ちる）
- 本物の退行が同じテストに出ても、揺れと区別されにくい

## 考えられる直し方（判断は調査で）

- `-n 4` の並列で落ちるかを `pytest -p no:randomly --count` などで再現し、共有の一時ディレクトリ・git の環境変数・時刻への依存を探す
- 原因が取れるまでの間は、揺れの記録（フレーキーの件数）を検査の報告に出す

## 目的

- **揺れの原因を取り除き、このテストがフレーキーとして除かれる実行を無くす。** 走らせ直しの待ちを減らし、cross-refactoring の着手前のテストで既存失敗として固定されて検出から外れることを無くす（#1806）

## 前提

- 前提 1: 揺れの原因は、まだ特定していない。2026-10-06 に手元で単体（1.25 秒で通る）と 12 本の同時実行を試し、どちらも 12/12 で通った（再現しなかった）。原因の特定は設計の調査で行う
- 前提 2: 原因の候補は次のどれか（設計の調査で絞る）。(a) 原因の項目の判定の「外す走らせ直し」（`refactor_lib/culprit.py` の `_isolate`）の中の pytest が、上限（テストの状態の `test_timeout` = 120 秒）・JUnit を読めない（`lib/test_triage.py` の `failing_in` は読めなかった群を全部まだ落ちているとみなす）・並列の負荷のいずれかで、通るはずの ID を落ちたままと判定する、(b) テストの組み立て（`tests/crossref_helpers.py` の `build_git_flow`）が共有の一時ディレクトリ・git や pytest の環境変数・時刻に依存する、(c) どちらでもない
- 前提 3: 原因が製品の側（`culprit.py` / `test_triage.py`）にあれば、利用者の cross-refactoring の実行でも原因の項目を取りこぼしうる。その場合は製品の側を直す（Value 6。テストだけを直して症状を隠さない）
- 前提 4: 揺れの頻度は、記録の 12 回が 3 日の全体テスト・範囲テストの実行に散らばる程度で、1 回の実行では低い。受け入れ条件の繰り返しの回数（30 回）は、修正前に再現手順で 1 回以上落ちることを確かめられる回数として置く。再現手順で 30 回のうち 1 回も落ちないときは、設計で回数か条件（並列数・負荷）を上げて再現する手順を決め直す
- 前提 5: #1807 の正は `docs/specifications/cross-refactoring-failed-item-rules.md`（#1793 の確定仕様）と、今の `refactor_lib/commands/converge.py` の `_settle_scope`（`_drop_unfixed` → `scope_verdict.judge_items(pending)` → 締め切り `_give_up` の取り消しと `pending` の判定し直しを、取り消しが無くなるまで項目の数 + 1 回の内で繰り返す）である。実装は変えない
- 前提 6: モードは `standard`。どちらも共通原則の C1〜C8・固有の P1 に当たる操作を含まない

## 用語

| 用語 | 意味 |
| --- | --- |
| 原因の項目 | 全体テストか範囲テストで変更起因として落ちたテストを、その変更で落とした改善項目（#1649） |
| 原因の手がかり | 原因の項目を決めた根拠（`path` / `isolate` / `undetermined`）。この要求の「外す走らせ直し」は `isolate` の手がかりを作る走らせ直し（項目のコミットを `git revert --no-commit` で外し、落ちた ID のファイルだけを走らせ直す）を指す |
| フレーキー / 既存失敗 / 変更起因 | 落ちたテストの 3 つの分類。フレーキーは走らせ直すと通ったもの |
| 確かめ直し | 最終ゲートより前の取り消しで HEAD が変わった後、残った改善項目を新しい HEAD の範囲テストで判定し直すこと（#1793） |
| 直さなかった項目 | 修正の起動の後、修正の範囲に自分の `Item-Id` のコミットが 1 つも無い改善項目。次の検証の最初に取り消す（#1793 の R3） |
