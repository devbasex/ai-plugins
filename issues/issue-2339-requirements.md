## 何が起きたか

大方針 #2335（異常系・ログ・回復とデータ・入出力の形を 1 つの実行の核へ集める）の柱の 1 本（柱の記号 P6）として起票した。NDF が書いて読む内部のデータ（実行・プラン・状態・記録・結果）は、種類ごとに型の定義と版を持つものと持たないものが混ざり、同じ意味の値が種類ごとに別の名前で書かれている。11.0.0 の作り直しで事実の表の共通の形と jsonschema の読み手（`plugins/ndf/contracts/facts/fact.schema.json`・`plugins/ndf/src/ndf/contracts/`）は入ったが、内部データの種類ごとの型・版・移行と名前のそろえは 11.x に残した。

## 種類

機能追加（型と版を持たせる・名前をそろえる約束は今の SSOT に無い。子の課題 #1706 の「古い版が新しい項目で止まる」は不具合だが、この課題はその土台を足す）

## 今の姿

内部のデータは、種類ごとに型（スキーマ）を持つものと持たないものが混ざる（2026-11-23、`main` 33670cad1 で確かめた）。

| 種類 | 今の型 | 版 |
| --- | --- | --- |
| 結果 | `contracts/schemas/result.schema.json` と、サブコマンドごとの `contracts/schemas/io/<名前>.result.schema.json` | 無し（契約の全体の版が `contracts/version.json` にある） |
| プラン・工程の文脈・工程の出力 | `contracts/workflow/` の `progress.schema.json`・`context.schema.json`・`stage-io.schema.json`・`parallel-plan.schema.json` | 一部が `version` を持つ |
| 設定の宣言（`.ndf/*.json`） | `contracts/schemas/ndf-settings/` の 19 ファイル。`additionalProperties: false` を持ち、`project.schema.json` の `version` は `enum: [1]` | 持つ |
| 記録（`*.jsonl`） | 種類ごとにばらつく。書き手のモジュール（`src/ndf/domains/records/`・`src/ndf/domains/loop/store.py` など）が形を決める | 無し |
| 実行の状態 | 同上 | 無し |

同じ意味の値の名前も種類ごとに違う。

| 意味 | 今の名前と数（`src/` の文字列のキーとして現れた数） |
| --- | --- |
| 時刻 | `at` 40・`created_at` 5・`updated_at` 5・`started_at` 4・`ts` 1 |
| 結果・状態 | `result` 48・`status` 47・`state` 42・`outcome` 14・`verdict` 12（意味の違うものも混ざるため、どれを 1 つにそろえるかは設計で分ける） |

古い形を読む移行は、設定のキーの改名表（`contracts/data/ndf-settings-renames.json`、読み手は `src/ndf/contracts/settings_renames.py`）だけにあり、記録と実行の状態には無い。

## 何を足すか・変えるか

| | 今 | 足した後 |
| --- | --- | --- |
| 型の定義 | 種類ごとに、スキーマを持つものと持たないものが混ざる | 実行・プラン・状態・記録・結果の種類ごとにスキーマと版が 1 つある |
| 型の確かめ | 書き手・読み手ごとに確かめる所と確かめない所がある | 核が読み書きの両方で確かめ、合わなければ `stopped` にする |
| 古い形の読み込み | 読み手ごとに個別に扱うか、扱わない | 型の側の移行の関数 1 か所で受ける |
| 同じ意味の名前 | 結果・時刻などが種類ごとに別の名前 | 1 つの名前（結果は `status`、時刻は UTC の ISO 8601 の `at` など）と名前の対応表。表に無い別名を検査が落とす |

## なぜ困るか

- 型と版の無いデータは、版をまたいで読むと黙って誤るか、理由の分からないまま止まる（#1706）
- 同じ意味の値が別の名前だと、読み手ごとに名前の分岐が増え、集計と比較で取り違える（MVV の Value 8・14）

## 目的

- 内部データの種類ごとに型と版が 1 つあり、核が読み書きで確かめ、同じ意味の値が 1 つの名前で書かれている状態にする

## 対象範囲

含む:
- 実行・プラン・状態・記録・結果の種類ごとの型（スキーマと版）と、読み書きでの確かめ
- 古い形を読む移行の関数（型ごとに 1 か所）
- 名前の対応表と、表に無い別名を落とす検査
- 時刻の書き方と置き場のキーをそろえる
- 子の課題の判定（閉じたか、残したか）の記録

含まない:
- 設定の宣言（`.ndf/*.json`）の形を版をまたいで読む扱い（#1706 の直し）。この課題の仕組みで解けるかを受け入れ条件 4 で判定し、解けなければ理由を添えて残す
- 契約の表の整理と構造の検査（#3684）・定数の写しの解消（#3667）
- 型を持たせた後の既存の記録ファイルの書き換え（読み込みの移行で受ける）

## 受け入れ条件

- [ ] 1. 実行・プラン・状態・記録・結果の種類ごとに型の定義（スキーマと版）が 1 つあり、核が読み書きの両方で確かめる。型に合わない値を書こうとすると書かずに `stopped` を返し、合わないファイルを読むと `stopped` を返す
- [ ] 2. 同じ意味の値は 1 つの名前で、名前の対応表に無い別名が残らないことを検査が確かめる（別名を 1 つ足すと検査が落ちる）
- [ ] 3. 時刻の書き方（UTC の ISO 8601）と置き場のキーが 1 つにそろう
- [ ] 4. 子の課題それぞれを、閉じた（解消を確かめた）か残した（理由つき）かに分けて本文に記録する
- [ ] 5. 古い版の形のファイルは型の側の移行の関数を通して読め、移行の関数の外に古い形の分岐が無い

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 結果 JSON・記録の名前の一部が変わる。普及フェーズの前なので互換の経路を持たず、移行の関数で読む（MVV の Value 4） |
| データ | 内部データのファイルに版が入る。古い形は移行の関数で読む |
| 既存の振る舞い | 型に合わない読み書きが `stopped` になる |
