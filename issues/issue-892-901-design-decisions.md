# #892 / #901: 決定の記録

設計は [issue-892-901-design.md](issue-892-901-design.md)、要求は [issue-892-901-requirements.md](issue-892-901-requirements.md) にある。

## 決定の記録

### 決定 1: `review_pool(host)` はホストに依らず全ランタイムを返し、引数は残す

cross-refactoring と同じく、ホストも CLI プロセスとして参加させる（前提 1）。母集合から外す相手は
利用者が `--exclude` で名指しする。ホストだけを特別に扱う理由が無くなったためである（前提 2）。

引数を消す形は採らない。呼び出し側の形が変わるうえ、ホストになれない名前を弾く検査の置き場所が
無くなる。

### 決定 2: 使える者が 2 者に満たないとき、ホストを別に確かめて埋め合わせに使わない

ホストは既に母集合に入っている。使える者に居ないのは、確認を通らなかったか、利用者が
`--exclude` で外したかのどちらかである。前者は確かめ直しても通らない。後者で席へ戻すと、
利用者の指定に反する。1 者なら同じランタイムの 2 つ目で埋め、0 者なら止める。

ホストの確認と `fallback = [host]` を残す形は採らない。上の 2 つの場合のどちらでも働かず、
確認の呼び出しとその分岐だけが残る。

### 決定 3: 状態ファイルの形は変えず、`host` だけを持つ状態の再開では変更の前の母集合を式で持つ

`participants` を持つ状態は、保存された `available` と `fallback` から席を決める。関数を変えても
席は変わらない。`host` だけを持つ状態は `review_pool(host)` を呼んでいたため、関数を変えると
席が変わる。この分岐 1 つにだけ、変更の前の式（全ランタイム − ホスト）を置く。

状態ファイルに版を持たせて分岐する形は採らない。分岐が 1 か所で済むところへ、書く側と読む側の
両方に版の扱いを足すことになる。

### 決定 4: 既定の母集合から agy を外すことは、この変更に含めない

agy を外すかは #786 が扱う。この変更の後も、agy を外すには `--exclude agy` を渡す。含めると、
agy が確認を通る環境の利用者の振る舞いが、この課題の目的と別の理由で変わる。

### 決定 5: supervisor は worker の途中の通知を受けたら、自分の背景の処理で報告の写しを待つ

supervisor 自身が起動した背景の Bash は、完了すると supervisor を再開させる（前提 3、`waiting.md` の
実測）。worker そのものは supervisor の背景の子に数えられない（前提 4）。そのため supervisor が
自分で起こされる手段を持つには、worker の終わりを自分の背景の処理の終わりへ写す必要がある。
写す先として、worker が既に持つ `置き場所` のファイルを使う。supervisor は worker を起動する前に、
そのファイルを worker ごとに新しいパスで空に作る（`: > <置き場所>`）。前の worker の報告が残っていると、
途中の通知で起動した待ちがその報告に即座に反応するためである。

待ちが見るのは `## 作業の報告` の見出しではなく、worker が写しの最後に書く完了の目印の行
`<!-- 作業の報告の終わり -->` である。`置き場所` は長い出力と共用のため、見出しを待つと書きかけの写しや
長い出力の本文に現れた同じ見出しにも反応する。目印の行は写しを書き終えた後にだけ現れる。

途中の通知を受けたら worker へ `SendMessage` を送る形は採らない。worker は背景の待ちが終わるまで
報告を出せず、送っても同じく途中の通知が返る。送った後に supervisor が応答を終えたときに
起こされるかも確かめていない。

`tasks/*.output` を背景で見張る形も採らない。`waiting.md` が読むことを禁じており、パスの形も
Claude Code が約束していない。

### 決定 6: 写しの待ちの上限は 3600 秒とし、上限で起きたら既存の点検と `SendMessage` の規則へ渡す

worker が報告を書かずに落ちると、写しは現れない。上限が無いと supervisor は永久に待つ。
3600 秒は初期値で、所要時間の実測から決めた値ではない（設計の「未確認のまま残ること」）。
上限で起きても点検が 1 回挟まるだけで、作業は失われない。上限で起きた後の扱いは新しく作らない。
`agent-layers.md` の「supervisor の worker の点検」と「報告が無いまま終わったとき」をそのまま使う。

上限を置かない形は採らない。worker の失敗の通知は、応答を終えた supervisor を起こすとは
限らない（前提 4 と同じ根）。

### 決定 7: 規則の数は変えず、supervisor の規則 4 と worker の規則 5 に 1 文ずつ足す

どちらも「待ちで応答を終えない」「背景の処理を残したまま応答を終えない」という既存の規則の
中の場面である。新しい規則を立てると、起動指示へ写す規則の数が変わり、#828 の実装が書き換える
起動指示の雛形とも衝突する。
