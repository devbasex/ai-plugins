## 目的

- 子課題（#2186・#2172・#2173・#2174・#2189）が、実行ジョブの指示と進捗の事象を同じ形で読み書きできるように、確定仕様の形を機械可読な定義と TypeScript の型にして 1 か所に置く
- ランナー・GitHub・承認の API から届く進捗の事象を、出所ごとに確かめてからスプリントの実行ごとの列へ 1 度だけ残し、一覧と詳細・承認・課金がそこから導ける状態にする
- 実行ジョブの token を受け口と #2173 の両方が同じ手順で確かめられるようにし、#2186 がその形で token を発行できる状態にする

## 前提

- 前提 1: DynamoDB の表・API の入口（API Gateway）・IAM のロール・Secrets Manager の秘密はインフラであり、private リポジトリ（owner = `volare`）が作る。この課題はその定義を書かず、受け取る変数の名前（表の名前・秘密の ARN・`api` の出所として認めるロールの ARN など）を `factory/.env.example` に足すだけにする（確定仕様の「データ・設定」。値は書かない、I6）
- 前提 2: 機械可読な定義は `factory/contracts/` に置き、#2170 が置いた `factory/contracts/openapi/accounts.yaml` はパスを変えずにその形へ含める。型の生成の道具と、生成した型をコミットするか検査の中で作るかは設計で決める。どちらでも、定義と型が食い違えば `factory/` の `npm run check` が落ちる
- 前提 3: 実行ジョブの token は、この課題が形と検証を決め、#2186 がその形で発行する。token が運ぶのは実行ジョブの識別子・`sprint_run_id`・期限で、`account_id` は載せない（#2170 の約束）。「無効」は、形が違う・署名が合わない・期限が切れた・知らない鍵で作られたのどれかを指す。実行ジョブが終わった後に期限より前で token を取り消す仕組みは、実行ジョブの状態（#2186 の集約）を読む必要があるため、この課題に含めない。期限の長さは実行ジョブの打ち切りの時間（#2186 が実測で決める）から発行側が決める
- 前提 4: token の署名の形（共有の秘密か鍵の組か）と鍵の置き場は設計で決める。どちらでも、鍵は Secrets Manager の ARN（`*_SECRET_ARN`）だけで受け、値をこのリポジトリ・応答・ログに出さない
- 前提 5: `gate.answered` の照合が読む「承認の依頼の保存済みの答え」は #2173 の集約で、#2173 はまだ実装されていない。この課題は照合に要る読み出しを差し替えられる口（関数の型）として決め、テストは偽の実装で行う。本物の読み出しは #2173 が同じ口で実装する
- 前提 6: `api` の出所の認証は、API Gateway の IAM 認可（SigV4 の署名の検証）を前提にし、受け口のコードは要求の文脈に載った呼び出し元の ARN が、変数で受けた #2173 のサービスのロールの ARN と一致するかを確かめる。利用者の Cognito の token で届いた `gate.answered` は 401 か 403 で拒む
- 前提 7: `github` の出所では、受け口が GitHub の Webhook の本文（`pull_request`・`check_run`）を `pr.updated`・`ci.updated` へ翻訳する。宛先のスプリントの実行を Pull Request からどう引くかは未決（未決 1）。引けない Webhook と、扱わない種類の Webhook は 202 で受けて保存しない（GitHub は 2xx 以外を配達の失敗として記録し続けるため）
- 前提 8: 事象 1 件の大きさに上限を置き、超えたら 400 を返す。値は設計で DynamoDB の項目の上限（400 KB）より下に決める。`gate.reached` の承認資料の本文が上限を超える場合の扱い（本文を別の置き場へ移すなど）は、確定仕様の形を変えるため未決（未決 2）
- 前提 9: `payload` の鍵の名前と型は、確定仕様の表の意味を変えない詳細として設計で決め、`factory/contracts/` に置く。意味を変える・項目を足すときは、確定仕様を直す Pull Request を先に出す（確定仕様の「サービス全体の契約」の冒頭）。`phase.changed` のフェーズの名前は #2172 が集合を決めるため、この課題では列挙にせず文字列で受ける
- 前提 10: 実行の制御（#2186）は受け口を通らず進捗の記録へ直に書く（確定仕様）。この課題は、受け口と同じ重複の拒否で 1 件を追記する関数を `factory/api/src/index.ts` から公開し、#2186 はそれを `source` が `control` で呼ぶ
- 前提 11: 進捗の事象を読み出す経路（一覧と詳細の形）は #2172 が持つ。この課題は表の形（確定仕様の「進捗の正本」の列）を守って書くだけにする

## 対象範囲

含む:
- `factory/contracts/`: 確定仕様の「実行ジョブの指示」「進捗の事象の種類と受け口」「進捗の正本」の列から起こした JSON Schema と、受け口の要求と応答の OpenAPI。TypeScript の型の生成と、定義と型の食い違いを落とす検査
- 進捗の受け口（`factory/api/`）: 出所（`runner` / `api` / `github`）ごとの認証、形の検査、出所と種類と識別子の照合、GitHub の Webhook の翻訳、冪等な追記、202 / 400 / 401 / 403 の応答
- 実行ジョブの token の検証（`factory/api/`）: token から実行ジョブの識別子と `sprint_run_id` を返し、無効なら拒む関数。`factory/api/src/index.ts` から公開する
- 実行の制御が直に書くための追記の関数（前提 10）と、`gate.answered` の照合の口（前提 5）
- 受け口の handler（Lambda の入口）と、`factory/.env.example` への変数の名前の追加
- 用語集への語の追加

含まない:
- GitHub App の導入とリポジトリの登録・実行の制御・ランナー・実行ジョブの token の発行（#2186）
- 承認の依頼の保存と、答えを読む経路（#2173。前提 5）
- 進捗の事象からの一覧と詳細の派生と読み出し（#2172。前提 11）
- 使用量の台帳と請求（#2174）
- 実行ジョブの終わりで token を期限より前に取り消す仕組み（前提 3）
- インフラの定義（DynamoDB の表・API Gateway の IAM 認可の設定・ロール・秘密。private リポジトリ側。前提 1）
- 確定仕様の契約の形の変更。変えるなら設計 Pull Request で確定仕様を先に直す

## 用語

| 用語 | 意味 |
| --- | --- |
| 進捗の受け口 | ランナー・GitHub の Webhook・承認の API から進捗の事象を受け、出所ごとに認証して冪等に追記する、`factory/api/` の HTTP の経路 |
| 実行ジョブの token | 実行の制御が実行ジョブ 1 つごとに発行する、期限つきの token。そのジョブのスプリントの実行にだけ進捗の事象を書け、承認の依頼の答えを読める |
| 冪等の鍵 | 進捗の事象の重複を判定する鍵（`idempotency_key`）。形は出所ごとに決まり、同じ鍵の事象は 1 つだけ残る |

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 可用性 | 表へ書けない・保存済みの答えを読めないときは 5xx を返し、受け付けたことにしない。ランナーは同じ事象のまま送り直し、冪等の鍵で 1 件に収まる（受け入れ条件 15） |
