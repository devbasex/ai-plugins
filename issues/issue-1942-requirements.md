> ## 起きていること
>
> #1910（ndf 10.17.71）で、`.ndf/review.json` の `profile` から指摘の基準・書かないもの・見送りの種類・返信・自動観点を差し替えられるようになった。ただし `profile` はリポジトリに 1 つだけで、`criteria`・`not_written`・`waive_kinds`・`reply` は**どの PR にも同じものが効く**。`categories` だけがパスの glob で分かれる。
>
> 利用者のリポジトリは、性質の違う 2 種類の PR を同じリポジトリで回している。
>
> | PR の種類 | 変えるファイル | 合う基準 |
> | --- | --- | --- |
> | 原稿の PR（10 話ごとのまとまりなど） | `works/*/chapters/*/text.md` | 設定と本文の食い違い・不自然な文・口調のずれ・前後のつながり・面白さ。「字句や言い回し」は**書く** |
> | 仕組みの PR | `scripts/`・`tests/`・`docs/` | 既定の基準 1（誤動作）・4（設計の文書の食い違い）。「字句や言い回し」は**書かない** |
>
> プロファイルが 1 つなので、利用者は両方の基準を 1 つの `criteria` に並べ、「原稿:」「仕組み:」と文の頭で書き分けて、レビュー担当の読み分けに頼っている。そのため次のことが起きる。
>
> 1. 原稿の PR のレビュー担当にも「誤動作・設計の文書」の基準が渡り、仕組みの PR のレビュー担当にも「口調・面白さ」の基準が渡る。基準の数が倍になり、読み分けを誤ると、当たらない基準で指摘が出るか、当たる指摘が抜ける
> 2. 「書かないもの」が両立しない。原稿では言い回しの指摘が要り、仕組みでは要らない。1 つのリストに入れるために「仕組みの文書の字句や言い回し（原稿の文は基準 6 で見る）」のような条件つきの文にするしかない
> 3. 見送りの返信（`reply`）が 1 つなので、「所有者が使って困る不具合ではない」と「章を読んで困る所ではない」を 1 文に混ぜることになる
> 4. `waive_kinds` も両方の和になり、修正担当が原稿の指摘を `wording`（仕組みの字句）で見送れてしまう。振り分けの検査はそれを拒めない
>
> ## 求めること
>
> PR が変えたファイル（`changed_files`）に応じて、基準・書かないもの・見送りの種類・返信の組を選べるようにする。例えば、プロファイルを名前つきで複数持ち、パスの glob で当てる形:
>
> ```json
> {
>   "version": 3,
>   "profiles": {
>     "manuscript": {"paths": ["works/*/chapters/*/text.md"], "criteria": {...}, "not_written": [...], "waive_kinds": {...}, "reply": "...", "categories": {...}},
>     "default":    {"criteria": {...}, ...}
>   }
> }
> ```
>
> 形は設計に任せる。決めておきたい点:
>
> - 1 つの PR が 2 つのプロファイルのパスにまたがるときの扱い（変更ファイルの多い方・先に書いた方・両方の和・止めて報告 など）
> - どのプロファイルにも当たらないときは、`default` か NDF の既定に落ちる
> - 既存の `version: 2` の `profile`（1 つ）は今と同じに読む（後方互換）
> - 外せない基準 2 は、どのプロファイルでも残る（#1910 の決定 1 のまま）
> - 選んだプロファイルの名前を `init` の出力と状態ファイルに残し、再開で同じものを選ぶ
>
> ## 受け入れ条件（案）
>
> - [ ] 原稿のパスだけを変えた PR で、レビュー担当への節と修正担当への節に原稿のプロファイルの基準・書かないもの・見送りの種類だけが出て、仕組みのプロファイルの文は出ない
> - [ ] 仕組みのパスだけを変えた PR で、その逆になる
> - [ ] 原稿の PR の振り分けで、仕組みのプロファイルにしか無い見送りの種類（例: `wording`）を検査が拒む
> - [ ] 2 つにまたがる PR の扱いが、決めた規則どおりになり、選んだ名前が `init` の出力に出る
> - [ ] `version: 1`・`version: 2` の宣言の出力は変わらない
> - [ ] 既存のテストが通る
>
> ## 優先度
>

## 目的

- 1 つのリポジトリで性質の違う PR（例: 小説の原稿の PR と、それを支えるスクリプト・テスト・文書の PR）を cross-review に通すとき、PR ごとにその PR に合う指摘の基準・書かないもの・見送りの種類・見送りの返信だけをレビュー担当と修正担当へ渡す
- それにより、当たらない基準での指摘・当たる指摘の抜け・別の種類の PR の見送りの種類による見送りを無くす

## 前提

- 前提 1: 1 回の cross-review（と、その中で呼ぶ `/ndf:fix`）で効くプロファイルは 1 つである。2 つ以上のプロファイルの鍵を混ぜた組（和）は作らない。和は「起きていること」の 1〜4 をまたがる PR で再現するためである
- 前提 2: 2 つ以上のプロファイルのパスにまたがる PR でも、cross-review は止まらず、決めた規則で 1 つを選んで続ける。止めて利用者へ返すと、収束ループが人の操作を待つ（Value 2）。どの規則で選ぶかは未決 1 で設計が決める
- 前提 3: 選ぶ手がかりは PR の変更ファイルのパスだけである。PR の題・本文・ラベル・ブランチ名では選ばない
- 前提 4: パスの照らし方は #1910 の決定 2 のまま（`scripts/lib/pace.py` の `matches`。`*` と `?` は `/` をまたがず、`**` はまたぐ）
- 前提 5: レビューの重点（`focus`。基準 3）はリポジトリに 1 つのまま、どのプロファイルを選んでも効く
- 前提 6: 宣言のどれか 1 つのプロファイルでも形が壊れていれば、#1910 の決定 4（丸ごと捨てて既定で続け、終了コードを変えない）と同じ扱いにする。捨てる範囲（壊れたプロファイルだけか、宣言の全プロファイルか）は設計が決める
- 前提 7: 再開で「同じものを選ぶ」は、保存した変更ファイルと宣言が変わっていなければ同じ名前を選ぶことを指す。宣言を書き換えて再開したときは、#1910 の決定 6 のとおり保存した変更ファイルから選び直す
- 前提 8: `/ndf:fix` を cross-review の外で単独に使うとき（状態ファイルが無いとき）も、PR の変更ファイルから同じ規則でプロファイルを選ぶ。変更ファイルを取れないときは、プロファイルに当たらないときと同じ扱いにする

## 対象範囲

含む:
- `.ndf/review.json` に、パスで当てる複数のプロファイルと、どれにも当たらないときのプロファイルを書ける形を足す（形は設計が決める）
- cross-review の `init`（新規と再開）で、変更ファイルからプロファイルを 1 つ選び、その名前を `init` の出力と状態ファイルに残す
- 選んだプロファイルから、レビュー担当への節・修正担当への節・見送りの種類と返信・自動レビュー観点の分類を組む
- `fix-steps.py` の `context` と `finalize` が、選んだプロファイル（状態ファイルの写し、無ければ PR の変更ファイルから選んだもの）で節を書き、振り分けを検査する
- 宣言の鍵と規則の正本（`cross-review` の `docs/02-fix-and-rotation.md` の「レビューの宣言」）と、`review_criteria.py` の冒頭の説明の更新
- 用語集の「レビューのプロファイル」の意味の更新と、選び方の語の追加

含まない:
- 宣言の具体的な形（`version: 3`・`profiles`・`paths` の鍵の名前など）の決定。設計が決める
- レビューの重点（`focus`）をプロファイルごとに分けること（前提 5）
- PR の題・本文・ラベルによる選択（前提 3）
- `pr-review`（単発のレビュー）の基準の差し替え（#1910 の境界のまま）
- 収束の判定・投稿の形・参加者の選び方・ラウンドの数の変更
- 利用者の原稿のリポジトリの `.ndf/review.json` の書き換え（利用者が行う）

## 受け入れ条件

例として、原稿のプロファイル（パス `works/*/chapters/*/text.md`、基準に「口調のずれ」、見送りの種類に `taste`、返信に「章を読んで困る所ではない」）と、仕組みのプロファイル（当たらないときのもの。基準に「誤動作」、見送りの種類に `wording`、返信に「使って困る不具合ではない」）の 2 つを書いた宣言を使う。

- [ ] 1. 原稿のパスだけを変えた PR で、`init` が書く状態ファイルの `reviewer_block` と、`fix-steps.py context` が書く文脈のファイルの「指摘の基準」の節に、原稿のプロファイルの基準・書かないもの・見送りの種類が出て、仕組みのプロファイルにしか無い文（「誤動作」の基準・`wording`）が出ない
- [ ] 2. 仕組みのパスだけを変えた PR で、1 の逆になる（仕組みのプロファイルの文が出て、原稿のプロファイルにしか無い文が出ない）
- [ ] 3. 原稿のパスだけを変えた PR の振り分けで、`waive_kind: "wording"`（仕組みのプロファイルにしか無い種類）を `finalize` が `invalid` で拒み、`taste` は通す。原稿のプロファイルの `criteria` に無い番号も拒む
- [ ] 4. どのプロファイルを選んでも、外せない基準（基準 2）の文がレビュー担当と修正担当の両方の節に出て、振り分けで `criterion: 2` が通る
- [ ] 5. 原稿のパスだけを変えた PR の見送りの返信が、原稿のプロファイルの `reply` の `{inner}` に種類の名前を入れた文になる
- [ ] 6. 選んだプロファイルの分類（`categories`）だけが自動レビュー観点に足され、選ばなかったプロファイルの分類は、パスが当たっても足されない
- [ ] 7. 原稿のパスと仕組みのパスの両方を変えた PR で、設計が決めた規則（未決 1）どおりに 1 つのプロファイルが選ばれ、cross-review は止まらず、選んだ名前が `init` の出力に出る。2 つのプロファイルの基準・見送りの種類が混ざって出ない
- [ ] 8. どのパスのプロファイルにも当たらない PR で、当たらないときのプロファイル（宣言にあるとき）が選ばれ、その名前が `init` の出力に出る
- [ ] 9. どのパスのプロファイルにも当たらず、当たらないときのプロファイルも書いていない宣言で、レビュー担当と修正担当への節・見送りの返信が、宣言が無いときの既定（`focus` を書いていればそれを含む）と一致する
- [ ] 10. `version: 1` の宣言と、`version: 2` の `profile`（1 つ）の宣言で、`reviewer` / `fixer` の出力・見送りの返信・自動レビュー観点・状態ファイルの `review_criteria` が変更前と 1 字も変わらない
- [ ] 11. `init` の出力と状態ファイルに、選んだプロファイルの名前（選ばれなかったときはそれと分かる値）が出る。`version: 1`・`version: 2` の宣言の状態ファイルは変わらない（10）
- [ ] 12. 宣言と変更ファイルを変えずに再開すると、新規の `init` と同じ名前のプロファイルが選ばれ、状態ファイルが書き直されない。宣言を書き換えて再開すると、保存した変更ファイルから選び直す
- [ ] 13. 状態ファイルが無いまま `/ndf:fix` を単独で使うと、PR の変更ファイルから cross-review と同じ規則で選んだプロファイルの節が文脈のファイルに出て、振り分けの JSON に写る
- [ ] 14. 形の壊れたプロファイルを含む宣言で、`review_criteria.py` と `init` が終了コードを変えず、理由を標準エラー（cross-review では報告）に出し、前提 6 で設計が決めた範囲を捨てて続ける
- [ ] 15. 既存のテスト（`uv run --frozen --project . --all-extras pytest . -q -n 4`）が通る

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 性能・拡張性 | プロファイルの選択のために、cross-review の `init` と再開で GitHub の呼び出しを増やさない（新規は今取っている変更ファイル、再開は保存した `changed_files` を使う）。単独の `/ndf:fix` だけは、状態ファイルが無いとき変更ファイルの取得が 1 回増えてよい |
| 運用・保守性 | 選んだプロファイルの名前が `init` の出力と状態ファイルから読め、どのプロファイルで回したかを後から確かめられる |
| 移行性 | `version: 1`・`version: 2` の宣言を書き換えずに使える（受け入れ条件 10）。新しい形の宣言を古い NDF が読むと、宣言全体を読めないとして既定で続く（止まらない。#1910 の境界と同じ） |
| セキュリティ | プロファイルは PR の head から読むため、PR の作り手が選ばれるプロファイルを変えられる。どれを選んでも外せない基準は残る（受け入れ条件 4）。新しい危険は足さない |
