## 何が起きたか

2026-11-21、11.x の課題を並列で開発していた 2 つの作業（#3702 の設計 PR と、#3412 の設計 PR #3952 https://github.com/devbasex/ai-plugins/pull/3952 ）で、cross-review（AI 2 者に PR を読ませ、指摘がなくなるまで直す仕組み）を回した。レビュー担当の 1 つの kiro が未ログインのため差分を読めなかった。cross-review は kiro を 1 度だけ起動し直し、それでも読めなかったので止まった（止まったときの結果の形の誤りは #3953 https://github.com/devbasex/ai-plugins/issues/3953 で扱う）。

止まった後、#3702 の作業を進めていた AI は、レビュー担当を codex だけに絞って cross-review を回し直した。**その結果、レビューは codex の 1 者だけになった。** 利用者は 2026-11-21 に、この様子を見て「その場合 codex と claude になるのでは？」と問うた。

## 種類

機能追加（11 系の今の約束は「修正担当の claude はレビュー担当にしない」「欠けたレビュー担当を別の担当へ振り替えない」であり、欠けた席を claude で埋めることは今の約束に無い。約束を足すので機能追加とする。課題のラベルは不具合のまま変えない）

## 今の姿

cross-review は、PR を**読むだけのレビュー担当（相手役）**に読ませ、**修正担当**（claude）が指摘を直すか理由を添えて見送る。これを指摘がなくなるまで繰り返す。手順と引数の正は [cross-review の手順書](https://github.com/devbasex/ai-plugins/blob/main/plugins/ndf/skills/cross-review/SKILL.md) にある。

- **相手役は既定で codex と kiro の 2 者である。** claude は修正担当なので相手役にしない（[`plugins/ndf/src/ndf/core/converge/participants.py`](https://github.com/devbasex/ai-plugins/blob/main/plugins/ndf/src/ndf/core/converge/participants.py) の冒頭）
- **相手役が差分を読めなかったときは、同じラウンドで 1 度だけ起動し直す。** それでも読めなければ、一部が読めなかったときは止まり（終わり方 `incomplete_reviewers`）、全員が読めなかったときは前提の欠け（`precondition`）で止まる
- **欠けた相手役を別の担当で埋めることはしない。** 10 系から 11 系への作り直しで 10 系の振る舞いを移した課題（#3941 https://github.com/devbasex/ai-plugins/issues/3941 ）が「10 系の振り替え（別アカウント・別の参加者）は持ち込まない」と決め、claude の 2 つ目の席（`claude-2`）も移さなかった
- **リポジトリが使ってよいランタイムを `.ndf/runtimes.json` の `allowed` で絞ると、相手役はその中から選ぶ。**

10 系では、使ってよいランタイムを設定で決める課題（#1598 https://github.com/devbasex/ai-plugins/issues/1598 ）で利用者が決めたとおり、使える相手役が 1 者になると、残ったその 1 者と同じランタイムをもう 1 つ起動して 2 つ目の席を埋めていた（例: codex だけなら codex の 2 つ目。claude だけなら `claude-2`）。この課題では、残った相手役の 2 つ目ではなく、読むだけの claude で埋める（[10 系の確定仕様](https://github.com/devbasex/ai-plugins/blob/main/docs/specifications/cross-review-participants-and-seats.md)）。

## 何を足すか・変えるか

| | 今 | 足した後 |
| --- | --- | --- |
| 相手役が起動し直しても読めないとき | そのラウンドを収束に数えずに止まる | 空いた席を claude の読むだけの起動で埋め、同じラウンドを 2 者で読む |
| `allowed` が claude と codex のとき（claude は相手役にならないので、相手役になれるのは codex だけ） | codex の 1 者だけでレビューする | codex と claude の 2 者でレビューする |
| `allowed` が claude だけのとき | 選べる相手役が無いとして、引数の誤り（`invalid`）で止まる | claude の読むだけの起動 2 つ（`claude` と `claude-2`）でレビューする |
| claude の読むだけの起動 | 無い（claude は修正担当だけ） | 修正担当とは別のプロセス・別の会話で起動し、ファイルを書き換えない |

## 今の利用者への影響と互換

- 相手役が 2 者とも読めるときの振る舞いは変わらない（claude を相手役として起動しない）
- `allowed` が claude だけのリポジトリでは、今は止まっていた cross-review が回るようになる
- 相手役が欠けて止まっていた場面で、止まらずに 2 者のレビューで進むようになる。そのぶん claude の起動が増え、利用量が増える

## 事象

相手役の既定（codex・kiro）で kiro が未ログインのとき、`ndf cross-review run` は 1 ラウンド目で止まる。

```text
summary: 1 ラウンドで incomplete_reviewers（相手役が起動し直しても差分を読めなかった。理由は warnings）。指摘 12 件（直した 0・見送った 0・未解決 12）
```

`allowed` を変えたときの相手役の選び方は、次のとおりである（main `2fd9227a4` で相手役を決める関数 `participants.assign` を呼んで確かめた。2026-11-24）。

| `allowed` | 選ばれる相手役 |
| --- | --- |
| 設定なし | codex・kiro |
| claude・codex | codex だけ |
| claude だけ | 選べずに止まる（`ランタイムの設定の allowed（claude）に、既定の席の相手役が無い`） |

## 期待する結果

相手役が欠けたら、空いた席を claude の読むだけの起動で埋め、毎ラウンド 2 者のレビューを保つ。

## 再現手順

1. kiro-cli をログインしていない状態にする
2. 相手役の既定（codex・kiro）のまま、`ndf cross-review run --pr <PR> --state-dir <D> --base main --purpose design` を打つ
3. kiro が起動し直しても読めず、`incomplete_reviewers` で止まる。`--reviewer codex` で回し直すと、codex の 1 者だけでレビューする

## 環境

NDF 11.0.13・Claude Code・Linux（2026-11-21）。相手役の選び方は NDF 11.0.29（main `2fd9227a4`）でも同じであることを確かめた（2026-11-24）。

## なぜ困るか

- kiro の未ログインは常態になっている（直前の計画の引継ぎ文書に「cross-review の相手役の kiro は未ログインで回答しない。codex だけで回る」とある）。kiro か codex が使えない環境では、cross-review が止まるか、1 者のレビューになる
- 1 者のレビューでは、もう 1 者が拾うはずの見逃しが残る。#1598 の計測（2026-10-02。10 リポジトリ・PR 1,090 件・レビュー 6,842 件）では、claude が問題なしとしたラウンドで codex の重大な指摘が採用された率は 31%、逆向きは 38% で、2 者は互いの見逃しを拾い合っていた
- `allowed` を claude だけにしたリポジトリでは、cross-review をまったく使えない

## 目的

- 相手役が欠けても、cross-review が毎ラウンド 2 者のレビューで進む状態にする
- 使ってよいランタイムが claude だけのリポジトリでも、cross-review が 2 者のレビューで回る状態にする

## 対象範囲

含む:
- cross-review の相手役の席が空いたとき（起動し直しても読めない相手役がいるとき、`allowed` の中で相手役になれるランタイムが 2 つに満たないとき）に、claude の読むだけの起動で埋めること
- claude の読むだけの起動（修正担当とは別のプロセス・別の会話。ファイルを書き換えない）
- 始める前の確認（相手役のアカウントが送った内容を学習に使わない設定か。今もある確認）で使えないと分かった相手役の席を、止めずに claude で埋めること
- 埋めた席と、欠けた相手役とその理由を、状態ファイル・結果 JSON の注意（`warnings`）・PR の記録のコメントに残すこと
- cross-review の手順書と確定仕様を、足した振る舞いに合わせて直すこと

含まない:
- cross-refactoring の相手役の選び方（相手役を決める関数は cross-review と共有しているが、cross-refactoring の振る舞いは変えない）
- 止まったときの結果 JSON の形の誤り（#3953 が扱う）
- 10 系にあった、別アカウントへの振り替えと、始める前に相手役の認証とモデルを 1 回ずつ試す確認（11 系には無い。今ある「学習に使わない設定か」の確認とは別のもの）
- kiro の未ログインそのものの解消
- 同じランタイムの 2 席の組と、異なるランタイムの組のレビューの質の比較（#1598 の計測の続き）

## 前提

- 前提 1: 起動した相手役が全員読めなかったときは、今と同じく前提の欠け（`precondition`）で止まり、席を埋めない。全員が読めないのは差分や環境の側に原因があること（サンドボックスの失敗など。#3893 https://github.com/devbasex/ai-plugins/issues/3893 ）が多く、claude で埋めても同じ原因で読めないことがあるためである。始める前の確認（学習に使わない設定か）で使えないと分かった相手役は、起動していないので、この前提に当たらず claude で補う
- 前提 2: 埋めた claude の起動も読めなかったときは、今と同じく `incomplete_reviewers` で止まる。埋めた席をさらに埋め直さない
- 前提 3: あるラウンドで席を埋めたら、同じ実行の以後のラウンドは、欠けた相手役を起動せず、埋めた claude で続ける。毎ラウンド欠けた相手役を起動すると、毎回同じ失敗を待つことになるためである
- 前提 4: 利用者が `--reviewer` で相手役を 1 者だけ名指したときは、名指しのとおり 1 者で回し、席を埋めない（10 系でも 1 者で回るのは 1 者を指定したときだけだった）。2 者以上を名指して一部が起動し直しても読めないときは、既定と同じく埋める

## 受け入れ条件

- [ ] 1. 相手役が codex と kiro で、kiro だけが起動し直しても読めないとき、同じラウンドで claude の読むだけの起動が kiro の席でレビューし、そのラウンドは codex と claude の 2 者の指摘で判定される（`incomplete_reviewers` で止まらない）
- [ ] 2. 1 の実行で、指摘が出なくなれば結果は `ok` で終わり、結果 JSON の注意（`warnings`）に、欠けた相手役の名前・読めなかった理由・埋めた席が載る
- [ ] 3. 1 の実行で、状態ファイルのそのラウンドの記録と PR の記録のコメントに、レビューした相手役として codex と claude が載り、kiro の席を claude で埋めたことが分かる
- [ ] 4. 1 の実行で、2 ラウンド目以降は kiro を起動せず、codex と claude でレビューする
- [ ] 5. `allowed` が claude と codex のリポジトリで、`--reviewer` の無い cross-review が codex と claude の 2 者でレビューする
- [ ] 6. `allowed` が claude だけのリポジトリで、`--reviewer` の無い cross-review が止まらずに始まり、claude の読むだけの起動 2 つ（`claude` と `claude-2`）でレビューし、codex と kiro を起動しない
- [ ] 7. 埋めた claude の起動は、修正担当とは別のプロセスで、修正担当の会話を引き継がない
- [ ] 8. 埋めた claude の起動の引数は、ファイルを書き換える Tool（Edit・Write など）を許さない。レビューの前後で、worktree の追跡するファイルに差分が無い
- [ ] 9. 相手役が 2 者とも読めるとき、claude を相手役として起動しない（退行しない）
- [ ] 10. 相手役が全員起動し直しても読めないとき、今と同じく前提の欠け（`precondition`）で止まり、claude を相手役として起動しない（退行しない）
- [ ] 11. 埋めた claude の起動も読めないとき、そのラウンドを収束に数えず `incomplete_reviewers` で止まる
- [ ] 12. `--reviewer codex` で 1 者だけを名指したとき、codex の 1 者でレビューし、claude を相手役として起動しない
- [ ] 13. cross-refactoring の相手役の選び方は変わらない（退行しない）
- [ ] 14. cross-review の手順書（`plugins/ndf/skills/cross-review/SKILL.md`）の相手役の説明と終わり方の表が、1〜12 と 15 の振る舞いと一致している
- [ ] 15. 始める前の確認（学習に使わない設定か）で相手役が 1 者使えないときは claude 1 つで、2 者とも使えないときは claude 2 つで席を埋めてレビューし、使えない相手役を起動しない。`--reviewer` で 1 者だけを名指して、その 1 者が使えないときは、今と同じく前提の欠け（`precondition`）で止まる

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わる（互換あり）。引数と結果 JSON のキーは変えない。`allowed` が claude だけの設定は、`invalid` で止まっていたものが回るようになる。結果 JSON の注意と記録のコメントに、席を埋めたことが載る |
| 重さ | claude の起動が増え、利用量が増える。claude だけを許したリポジトリでは、各ラウンドのレビューのために claude を 2 回起動する。相手役が使えないと分かった時点ごとの扱いは、この表の下の表にある |
| データ | 状態ファイルのラウンドの記録に、埋めた席が分かる値が入る（形は設計で決める）。移行は無い |
| 既存の振る舞い | 相手役が欠けたときと、`allowed` の中で相手役になれるランタイムが 2 つに満たないときだけ変わる。claude の起動が増える |

相手役が使えないと分かった時点ごとの扱いは次のとおりである。今は、kiro か codex が使えない環境では cross-review が止まるか 1 者のレビューになり、避けるには使えない相手役をログインさせて打ち直すしかない。

| 使えないと分かった時点 | 使えない相手役 | 変更後の扱い |
| --- | --- | --- |
| レビューを始める前の確認（相手役のアカウントが、送った内容を学習に使わない設定か） | 1 者 | claude 1 つで補う |
| 同上 | 2 者とも | claude 2 つで補う（この確認で使えないのは設定のためで、環境が壊れたためではないので止めない） |
| 相手役を起動し、1 度起動し直した後 | 1 者 | claude 1 つで補う |
| 同上 | 2 者とも | 止まる（`precondition`。今と同じ） |
| `--reviewer` で 1 者だけを指定し、その 1 者が使えないと分かったとき（どちらの時点でも） | その 1 者 | claude で補わずに止まる（使えれば 1 者で回る） |

止まったときは、今と同じく相手役のログインを直して打ち直す。始める前の確認は今もある仕組みで、この課題では、確認で使えないと分かった相手役を止めずに claude で補う扱いを足す。

## 用語

| 用語 | 意味 |
| --- | --- |
| 相手役 | cross-review で PR を読むだけのレビュー担当として、CLI のプロセスで起動されるランタイム（codex・kiro など） |
| 修正担当 | 相手役の指摘を直すか理由を添えて見送り、コミットする担当（claude） |
| 席 | cross-review の 1 ラウンドの 2 つのレビュー担当のスロット。同じランタイムの 2 つ目の席は `claude-2` の形で呼ぶ |
| 振り替え | 結果を残さなかった担当の役割を、同じ実行の中で別の担当へ移すこと。この課題では、空いた席を claude の読むだけの起動で埋めることを指す |

> ## 事象
