# #2065: スライドを作る実務の手順（生成スクリプト・ページの枠組み・トーン＆マナー・構成メモ・gws での変換と確認）を Skill に取り込む

正は課題の本文（#2065）で、この文書はその写しである。`spec-copy.py write` で作り直す。手で直さない。

## 何をしたいか

スライド（発表資料・提案資料）を作る実務の手順を NDF の Skill に取り込む。手本は nyle-dx（`/work/nyle-dx` の `edp/slides`・`mdx/security/slides`・`fde/presentation`）の作り方で、次を持つ。

| 要素 | nyle-dx での形 |
| --- | --- |
| 生成 | pptxgenjs の生成スクリプト `slides/build-deck.js`。版面 10 × 5.625 インチ（16:9） |
| ページの枠組み | 共通の関数 `page` / `box` / `note` / `tbl` / `section`（見出し・罫線・ロゴ・著作権表示・ページ番号の位置を固定） |
| トーン＆マナー | 書体・色・文字サイズを定数で持ち、README に表で書く |
| 構成メモ | ページごとの見出し・役割・根拠の表（`04-presentation-notes.md`）と、読み上げの台本。スピーカーノートへ入れる |
| 変換と確認 | `gws drive +upload` → `gws drive files copy`（mimeType を Google Slides に）で変換し、`gws slides presentations pages getThumbnail` でページごとに見る |

NDF の今の Skill はスライドの原則（`design/references/layout-slide.md`・`release/references/form-slide.md`・`layout-review`）だけを持ち、上の実務の手順を持たない。

## 方針（利用者の決定 2026-10-17）

- 新しい Skill を作る前に、既存のスライドの規約（`layout-slide.md`・`form-slide.md`・`layout-review`・`document-systems` の `system-gdrive.md`）への統合を優先する
- トーン＆マナーは会社色を持たない汎用のテンプレートを既定にし、プロジェクトごとに差し替えられるようにする
- 取り込んだ手順で、発表資料「独自スキルプラグイン開発の薦め」（台本は第 7 稿 https://docs.google.com/document/d/13nNf3sLjMtrp7WZKHPFD_KW-sv-v5xv5kno2pICfP3U/edit ）を `docs/presentations/` に作る

## 目的

- AI がスライドを作るとき、毎回その場で作り方を組み立てず（python-pptx の自作など）、NDF の規約に従って、生成スクリプト・ページの枠組み・トーン＆マナー・構成メモ・台本・変換と確認の手順をそろえた形で作れるようにする
- その手順を実際に通して、発表資料「独自スキルプラグイン開発の薦め」を作り、手順が通ることを示す

## 前提

- 前提 1: 生成は pptxgenjs の生成スクリプト（Node.js）で行う。python-pptx で組む方式と、既存の Marp の経路（`docs/presentations/build.sh`）はこの課題で手を入れない
- 前提 2: 汎用テンプレートの版面（10 × 5.625 インチ）と枠組みの関数の座標は手本の値を踏襲する。書体・色・著作権表示の文言・ロゴは会社に由来しない値を既定にする（書体は配布先の環境と Google Slides で使える書体から設計で選ぶ）
- 前提 3: 台本の正本は第 7 稿の Google ドキュメントである。作成時はドキュメントから取得し、手元の写し（会話の作業ディレクトリの `script-v7.md`）と食い違えばドキュメントを採る。台本はページごとの見出しと読み上げを持つが、ページに載せる要素（図・表・箇条書き）は持たないため、ページの中身は作成時に台本から起こし、構成メモの「役割」「根拠」に書く
- 前提 4: Google Slides への変換は、利用者の Drive の非公開の場所（フォルダを指定しないアップロード、または利用者の既存の非公開フォルダ）に置く。共有・公開範囲の設定はこの課題で行わない
- 前提 5: gws は利用者のアカウントで認証済みである（引継ぎ文書）。認証が切れていれば `google-workspace` の手順で利用者に再認証を頼み、変換と確認の受け入れ条件はそれまで未達とする
- 前提 6: `docs/presentations/` は `main` へ入ると GitHub Pages で公開される（`docs/presentations/README.md`）。発表資料は社外向けで、公開されてよい内容だけを置く
- 前提 7: 規約の文言のうち、この課題で追加・変更する行は「枚」を「ページ」にする。触らない行の言い換えはこの課題の範囲外とする
