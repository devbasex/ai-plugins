## 前提

- 「消す前のコミット」は、この作業のブランチが分かれた元の `main` のコミット（分岐点）とする。分岐点は `main` の履歴に残るので、この作業がマージされた後も、そのコミットを指すリンクから消す前の 36 本を読める
- 分岐点の後に `main` で 36 本のどれかが変わったら、AI がブランチを最新の `main` の上へ載せ直して（リベースして）分岐点を取り直し、新しく付けるリンク 2 か所を書き直す。リンクが消す直前の版を見せるようにするためである

## 利用者がすること

1. 分岐点の後に `main` で 36 本のどれかが変わったと AI から知らされたら、その変更を確定仕様へ移すかを決める。AI は Pull Request の本文に、変更したコミット・変わったファイル・変更の中身の要約・移すかどうかの推奨を示す。推奨の基準は、確定仕様にまだ無い決定や仕様の変更なら「移す」、書式の直しや、既に確定仕様にある内容なら「移さない」である。利用者は、推奨に同意するか違う扱いにするかを、この作業の Pull Request へのコメントで答える。移さなくても、変更後の版は取り直した分岐点を指すリンクから読める
2. リリース承認（この作業の Pull Request を `main` へ入れてよいと承認すること）のときに、AI が Pull Request の本文に書いた確かめの結果（受け入れ条件 1〜4）を読む
