### 目的

- cross-review・cross-refactoring・merged を並行して回しても、ある実行が残した状態が別の実行を止めず、ディスクを埋めず、作業中の変更を消さない状態にする（Mission の「人の判断が要る所だけで止まる」。手で残骸を片付ける操作を無くす）

### 前提

- 前提 1: この課題は子の #2084（投稿キュー）と #2085（一時の置き場）を 1 つの設計で扱う。#1680（`rf<n>` が merged で外れない）は #2085 の受け入れ条件に含まれるため、ここで満たす。子の受け入れ条件は下の AC に取り込み、子の課題の本文は書き換えない
- 前提 2: 「実行」は、cross-review・cross-refactoring・merged の後片付け・Claude Code などのセッション（セッション開始 hook が状態ファイルを作るもの）・`worktree-deps.sh` のプロセス・テストのセッションのどれか 1 回を指す。持ち主はこの単位で記録する
- 前提 3: 自動の片付けの時点は「同じリポジトリで NDF の cross-review・cross-refactoring・merged の後片付けのどれかを実行したとき」とする。常駐のプロセスや cron は置かない。設計がこれより早い時点（セッションの終わりなど）を足すのは構わない
- 前提 4: 持ち主が終わったかを判定できない状態は、終わっていないとみなして残す（安全側）。判定の手段（プロセスの生存・PR の状態・記録の時刻）は設計が決める
- 前提 5: 片付けは `git worktree remove` と `git branch -d` のように git が拒めば止まる操作だけで行い、`--force` / `-D` を使わない（共通原則 C4）。未コミットの変更と未 push のコミットを持つ worktree は外さない（C3。作業を消さない）
- 前提 6: 一時の置き場は `NDF_WORKTREE_BASE` か `${TMPDIR:-/tmp}` のままで、場所は変えない（どのプロジェクトでも同じ。Value 5）

### 対象範囲

含む:
- NDF が実行をまたいで残す状態の一覧と、それぞれの持ち主・寿命の取り決め（AC1）
- レビュー worktree（`<NDF_WORKTREE_BASE>/<slug>/pr<n>`・`rf<n>`）、`ndf-worktree-<session>.json`、`ndf-deps.*`、`fix-pr<n>-*`、`ndf-tests-*` の片付け
- cross-review の投稿キューで、以前の実行が積んだ項目が恒久に送れないときの扱い（#2084）
- 片付けの結果（外した・残した・理由）を結果の JSON の `items` へ出すこと

含まない:
- 承認の後の別のセッションのマージで止まる件（#2221）、並行するプランの版数と触るファイルの件（#2164・#2165）
- 開発 worktree（`.worktrees/<ブランチ名>`）の片付けの規則の変更（merged の今の扱いのまま）
- relay の状態ディレクトリ（`${XDG_STATE_HOME:-~/.local/state}/ndf/relay/`）と supervise.py の状態の置き場
- 2026-10-31 時点で手元に残っている残骸を、この変更の外で手で消すこと（AC2〜AC6 の片付けを初めて回したときに片付く）

### 用語

| 用語 | 意味 |
| --- | --- |
| 残る状態 | NDF の実行が作り、その実行が終わった後もディスクに残るもの（レビュー worktree・状態ファイル・一時ファイル・投稿キューの項目）（#2229） |
| 状態の持ち主 | 残る状態を作った実行。持ち主が生きている間は、別の実行がその状態を消さない（#2229） |
| 状態の寿命 | 残る状態を片付けてよくなる条件（持ち主のプロセスの終わり・Pull Request が閉じたこと・送り終えたこと など）。状態の種類ごとに 1 つ決める（#2229） |
| 以前の実行 | 今の実行より前に同じ Pull Request・同じリポジトリで回った、終わった実行。supervise.py の `run --from` の「前の実行」とは別（#2229） |

### 受け入れ条件

持ち主と寿命:

- [ ] AC1: NDF が実行をまたいで残す状態（対象範囲の 5 種と投稿キューの項目）が 1 か所の一覧にあり、各行に置き場・持ち主・寿命・片付ける時点が書かれている。一覧に無い種類の残る状態を NDF のスクリプトが作ると、テストが落ちる

持ち主の終わった状態は自動で片付く:

- [ ] AC2: マージ済みの Pull Request `n` について `merged-steps.py cleanup` を実行すると、変更も未 push のコミットも持たない `<NDF_WORKTREE_BASE>/<slug>/rf<n>`（中の `work` を含む）が `pr<n>` と同じく外れ、`git worktree list` からもディレクトリからも消え、結果の `items` に `removed` で出る（#2085・#1680）
- [ ] AC3: merged を通らずにマージされた、または閉じられた Pull Request のレビュー worktree（`pr<n>`・`rf<n>`）で、変更も未 push のコミットも持たないものは、前提 3 の時点の後に残らない（#2085）
- [ ] AC4: 持ち主のセッションが終わった `ndf-worktree-<session>.json` は、前提 3 の時点の後に残らない（#2085）
- [ ] AC5: 持ち主のプロセスが終わった `ndf-deps.*` は、`trap` が走らずにプロセスが止められた場合も、前提 3 の時点の後に残らない（#2085）
- [ ] AC6: 持ち主の実行が終わった `fix-pr<n>-*` と `ndf-tests-*` は、AC1 の一覧の寿命を過ぎた後、前提 3 の時点かテストのセッションの終わりの後に残らない

実行中の状態を別の実行が消さない:

- [ ] AC7: open の Pull Request のレビュー worktree は、どの片付けを回しても外れない（#2085）
- [ ] AC8: 前提: 実行 A が `pr<n>`（または `rf<n>`）を使って動いている。操作: 別の実行 B が同じリポジトリで片付けを回す。結果: A の worktree と状態ファイルは残り、B の結果の `items` に `kept` と理由が出る。Pull Request `n` が既にマージ済みでも同じ
- [ ] AC9: 生きているセッション・プロセスの `ndf-worktree-<session>.json` と `ndf-deps.*` は、別の実行の片付けで消えない（#2085）
- [ ] AC10: 未コミットの変更か未 push のコミットを持つレビュー worktree は外れず、結果の `items` に `kept` と理由が出る。片付けは `--force` / `-D` を使わない（#2085。`rf1732/work` の 23 件のような作業を消さない）

以前の実行の残りが次の実行を止めない:

- [ ] AC11: 投稿キューの先頭に以前の実行が積んだ `review-post` の項目があり、GitHub がその行を 422（line could not be resolved）で拒むとき、今回の `post_review` は今回分の review を送り終え、`failed` を返さない。先頭の項目は待ち行列から外れ、`dropped/` の控えか総評のどちらかに残る。テストの偽の `gh` で確かめる（#2084）
- [ ] AC12: AC11 の後、新しいラウンドで `post_review` をもう一度呼ぶと、同じ項目の 422 で止まらない（待ち行列にその項目が積まれていない）（#2084）
- [ ] AC13: 先頭の項目が一時の失敗（429・5xx・上限）で送れないときは、今までどおり外さず、今回分も順序を保って待つ（`waitable` が真）（#2084）
- [ ] AC14: 位置エラーでない恒久の失敗（422 でも line could not be resolved を含まないもの・400・404 など）の `review-post` の項目と、別の実行が積んでまだ送りを試みていない項目は、今の扱い（飛ばさない・送る）を変えない。変えるなら設計 PR に理由を書く（#2084）
- [ ] AC15: 以前の実行が残したレビュー worktree（同じ `pr<n>`・`rf<n>`）があっても、次の cross-review / cross-refactoring の開始は失敗しない（使い直すか、外して作り直す）。未コミットの変更か未 push のコミットを持つものは消さず、開始を止めて理由を返す

退行しないこと:

- [ ] AC16: 既存のテスト（`plugins/ndf` 一式）が通る。`merged-steps.py cleanup` の結果の JSON の形（`items` の `kind`・`state`・理由）は、足す値を除いて変わらない

| 大項目 | 条件 |
| --- | --- |
| 運用・保守性 | 片付けで外したもの・残したものは、1 件ずつ置き場・`removed` / `kept`・理由が結果の JSON の `items` に出る。残したものは、人が手で外す前に理由を読める |
