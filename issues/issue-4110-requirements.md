# #4110: #4091 の設計: T2 が要る不在の確かめ（quiet）を #4103 へ移し、#4091 だけでは席を返す振る舞いが決まらない

正は課題の本文（#4110）で、この文書はその写しに、設計に要る今の姿と影響を足したものである。本文から作り直す。手で直さない。

## 何が起きたか

#4091 の設計 `issues/issue-4091-design.md` の決定 8 は `quiet` と `probe` を #4103 へ移す。一方、#4091 が実装する T2 と、その詳細手順は、`launch.quiet` の中でラッパーの不在を確かめることを必須にしている。PR #4107（#4100 の設計）の cross-review の相手役がラウンド 1 で指摘した。

## 種類

不具合（設計文書の食い違い。実装する人によって振る舞いが分かれる）

## 今の姿

パスは `plugins/ndf/` からの相対で書く。#4091・#4103 は設計がマージ済みで、実装はまだである。

- #4091 の状態と事象の表の T2・T6・T7（返却済みへ移す遷移）は、どれも「ハブの排他（`hub.lock`）の中で、一覧で動いていない・未処理の起動の要求も錠を持たない tmux のセッションも無い」ことを書く条件にしている（`issues/issue-4091-design.md` の 104・108・109 行）
- その確かめを行う `quiet`（リレーと `lane/launch.py` の 2 つ）と `probe` には「#4103。決定 8」の印が付き、決定 8 は #4103 の設計で置き換えると書く（同 150〜152 行・285 行、`issues/issue-4091-design-detail.md` の 92〜94 行）
- #4103 の設計（PR #4112）は `quiet`（ハブの排他を外から取る形）と `_drain_held` を作らず、起動の券と起動の印で一覧に「起動の途中」を載せ、返却済みは `admit.lock` の中で `launch_ticket.quiet` を読み直してから書く（`issues/issue-4103-design.md` の「#4091 の設計の置き換え」）
- #4091 の詳細設計は `lane/launch.py`（層 `ndf.progress`）が `domains/relay/hub.py`（層 `ndf.domains`）を import する形にし、その可否を「未確認のまま残ること」に置いた。層の規則（`src/ndf/checks/rules.json` の `structure.layers` が `contracts → adapters → core → progress → domains` の順、`src/ndf/checks/structure.py` の `_import_findings` が下の層から上の層の import を `layer` で落とす）により、この import は検査で落ちる

## 事象

#4091 だけを実装すると、T2 を進めずに席を返せないか、ハブの起動と排他せずに席を返すかで振る舞いが分かれる。

## 期待する結果

#4091 に含める T2 の排他と不在の確かめの実装が明記され、T6・T7 の結果の確定で #4103 へ移す部分と境界が食い違わない。

## 対象範囲

含む:
- #4091 だけを実装した状態での T2・T6・T7 の「不在」の確かめと、ハブの起動との排他
- #4091 の文書のうち、上の確かめに当たる節・遷移・決定の置き換え（置き換えは #4091 の実装の PR で行う）

含まない:
- 起動の結果が不明なときの確定・手動の再起動の直列化・期限を越えて生きる手・`Settle` を打ち切らないこと（#4103）
- リレーの版が混在する間の検出と照合（#4118）
- 席の 4 つの段階・数える規則・遷移の表そのもの（#4091）
