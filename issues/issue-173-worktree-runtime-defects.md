# issue #173: 作業ツリー運用の実機確認で見つかった不具合の修正

## 関連リンク

- 不具合の報告: https://github.com/devbasex/ai-plugins/issues/173
- 実装: #167（v9.2.0）
- 設計: `issues/issue-146-worktree-first/`
- 元の要望: #146

## モード

`standard`。プラグイン本体のシェルスクリプトの不具合修正で、対象には既存テスト
（`plugins/ndf/skills/worktree/tests/`）がある。公開インタフェース・スキーマ・認証認可は変えない。

## 用語

| 用語 | この文書での意味 |
| --- | --- |
| 主ディレクトリ | リポジトリを clone したディレクトリ。`git rev-parse --git-common-dir` の親 |
| 対象 | サブコマンドが操作する作業ツリー。引数で渡し、省略すると現在地になる |
| 実行位置 | コマンドを起動したときの作業ディレクトリ |
| 台帳 | `.git/ndf/worktree-registry.json`。スロットとポートの割り当てを記録する |
| 帯 | `testenv.port_band` が定めるホストポートの範囲 |

## 目的と非目的

達成したい状態:

- コンテナの起動と別ディレクトリからの実行を伴う経路で、単体テストが拾えていなかった
  5 件の事象が起きない
- 同じ経路が単体テストで守られ、次の版で戻らない

やらないこと:

- 起動を伴う受け入れ条件（36・37・38 など）の実施。実物のデータセットとサービス一式を要する
- `worktree-guard.sh` のシェル解析を、シェルの文法に忠実な構文解析へ作り替えること。
  今回は本文と実行される部分を分ける範囲に留める

## 前提

- 前提 1: 報告の 5 件はいずれも v9.2.0（`8747ae1`）の実装で再現する。修正の判定は、
  再現するテストが失敗から成功へ変わることで行う
- 前提 2: 事象 3 の直し方は 2 案あり、対象からの解決を採る。理由は「代替案と採否」に書く

## 受け入れ条件

| # | 条件 | 検証手段 |
| --- | --- | --- |
| 1 | `reap` が停止の対象を 1 件以上見つけたとき、`SLOT` の未定義で終了しない | `test_testenv.py` の reap のテスト |
| 2 | `reap` が渡す `NDF_SLOT` は、対象の台帳の行が持つスロットと一致する | 同上（`docker` の差し替えで環境変数を観測する） |
| 3 | `test` でテスト種類の指定を省いたとき、`--kind が要ります` が標準エラーへ出て終了コード 1 になる | `test_testenv.py` の案内のテスト |
| 4 | 別のリポジトリから対象を渡して実行しても、宣言ファイル・台帳・帯は対象側のものを使う | `test_testenv.py` / `test_localenv.py` の解決のテスト |
| 5 | 対象がリポジトリの外を指すとき、現在地の設定で黙って続けず、サブコマンド自身の案内で終了コード 1 になる | 同上 |
| 6 | `golden_tag_paths` が指す対象が 1 件も無いとき、値を出さずに終了コード 1 になる | `test_testenv.py` の tag のテスト |
| 7 | ヒアドキュメントの本文に含まれる語は、書き込み先として拾わない | `test_write_target.py` |
| 8 | 展開前の変数を含む語は、書き込み先として拾わない | 同上 |
| 9 | 既存の 348 件が通過し続ける | `python3 -m pytest plugins/ndf/skills/worktree/tests -q` |

起きてはいけないこと:

- 主ディレクトリで実行したときの既定の挙動が変わること（対象を省くと現在地が対象になる）
- 実行位置と対象が同じリポジトリに属する通常の使い方で、新たに拒否が出ること
- 書き込み先の抽出が、実行される部分の書き込みを取りこぼすこと

## 代替案と採否

### 事象 3（宣言ファイルと台帳の解決）

| 案 | 内容 | 採否 | 理由 |
| --- | --- | --- | --- |
| A | 主ディレクトリを対象から解決する | 採用 | 対象を引数で渡す約束どおりに動く。主ディレクトリの外へ置いた作業ツリー（`cross-review` が一時領域に作るもの）でも成立する |
| B | 対象が主ディレクトリの配下にあるかを確かめ、外れていれば断る | 不採用 | 主ディレクトリの外に置いた作業ツリーを一律に断ってしまう |

### 事象 3 の実装

| 案 | 内容 | 採否 | 理由 |
| --- | --- | --- | --- |
| A | `_wt_resolve` に対象のディレクトリを渡せるようにし、`wt_main_dir` / `wt_in_worktree` の引数で受ける | 採用 | 判定が共通ライブラリの 1 箇所に残る（詳細設計 06 の決定 8） |
| B | 対象から解決する関数を別に足す | 不採用 | サブモジュールの判定が 2 箇所に分かれる |

### 事象 5（書き込み先の抽出）

| 案 | 内容 | 採否 | 理由 |
| --- | --- | --- | --- |
| A | ヒアドキュメントの本文を落としてから語へ分け、展開前の変数を含む語を対象から外す | 採用 | 本文は実行される部分ではないため、落としても実際の書き込みは取りこぼさない |
| B | シェルの文法に沿った構文解析へ作り替える | 不採用 | 案内のための推定に対して規模が釣り合わない |

## 不変条件

- 宣言ファイルが無いリポジトリでは、すべてのサブコマンドが何も出力せず終了コード 0 で終わる
- 終了コードは 0 が「処理が完了した」、1 が「処理できなかった」、2 が「対象外」。
  `test` だけは実行したコマンドの終了コードをそのまま返す
- 主ディレクトリの編集は拒否しない。`worktree-guard.sh` は案内だけを出す

## 互換性

| 対象 | 変更 | 互換性の扱い |
| --- | --- | --- |
| `worktree-testenv.sh` / `worktree-localenv.sh` のサブコマンドと引数 | 変えない | 追加も削除もしない |
| `wt_main_dir` / `wt_in_worktree` | 引数を任意で受ける | 引数なしの呼び出しは今までと同じ結果を返す |
| 宣言ファイルの書式 | 変えない | 版は 1 のまま |
| 台帳の書式 | 変えない | |

## タスク分解

### Task 1: `reap` がスロットを渡す

- **対象ファイル:** `plugins/ndf/scripts/worktree-testenv.sh`、`.../tests/test_testenv.py`
- **変更内容:** 停止の対象を読む問い合わせへスロットを足し、ループの中で `SLOT` に入れる
- **満たす受け入れ条件:** 1、2
- **進め方:** 停止の対象が 1 件あるときに終了コード 0 で終わり、`NDF_SLOT` が台帳の値と
  一致することを確かめるテストを先に書く

### Task 2: テスト種類の指定を省いたときの案内

- **対象ファイル:** `plugins/ndf/scripts/worktree-testenv.sh`、`.../tests/test_testenv.py`
- **変更内容:** 書式と本文を分けて `printf` へ渡す
- **満たす受け入れ条件:** 3
- **進め方:** 標準エラーの内容と終了コードを確かめるテストを先に書く

### Task 3: 主ディレクトリを対象から解決する

- **対象ファイル:** `plugins/ndf/scripts/lib/worktree-common.sh`、
  `plugins/ndf/scripts/worktree-testenv.sh`、`plugins/ndf/scripts/worktree-localenv.sh`、
  `.../tests/test_testenv.py`、`.../tests/test_localenv.py`
- **変更内容:** `_wt_resolve` が対象のディレクトリを受け取れるようにし、入口の 2 本が
  引数の対象を渡す。対象がリポジトリの外にあるときは現在地から解決し、対象そのものの
  誤りは各サブコマンドの案内に任せる
- **満たす受け入れ条件:** 4、5
- **進め方:** 2 つのリポジトリを作り、片方から他方の作業ツリーを対象に実行して、
  対象側の台帳に記録が入ることを確かめるテストを先に書く

### Task 4: 基準のタグが対象の不在を区別する

- **対象ファイル:** `plugins/ndf/scripts/worktree-testenv.sh`、`.../tests/test_testenv.py`
- **変更内容:** 宣言したパスが 1 件も見つからないとき、値を出さずに終了コード 1
- **満たす受け入れ条件:** 6
- **進め方:** 宣言したパスを消した状態で `tag` が値を返さないことを確かめるテストを先に書く

### Task 5: 書き込み先の抽出を実行される部分へ寄せる

- **対象ファイル:** `plugins/ndf/scripts/lib/worktree-common.sh`、`.../tests/test_write_target.py`
- **変更内容:** ヒアドキュメントの本文を落としてから語へ分ける。展開前の変数を含む語を
  書き込み先として採らない
- **満たす受け入れ条件:** 7、8
- **進め方:** 報告に出た 3 つの語（`$SP/wt-test/guard.sh`・`<期待:`・`<payload`）を含む
  コマンドで、書き込み先が本文の外だけになることを確かめるテストを先に書く

### Task 6: 配布物の同期と版の更新

- **対象ファイル:** `plugins/ndf/plugin.json` ほか各ランタイムの配布物、`CLAUDE.md`
- **変更内容:** 版を v9.2.1 へ上げ、`bash scripts/build-runtime-plugins.sh` で生成物を揃える
- **満たす受け入れ条件:** 9
- **進め方:** 生成物の手編集は行わない

## 影響範囲

| 変更 | 影響を受けるもの |
| --- | --- |
| `_wt_resolve` の引数 | `worktree-guard.sh`・`worktree-session.sh`・`worktree-setup.sh`（引数なしで呼ぶため結果は変わらない） |
| 書き込み先の抽出 | `worktree-guard.sh` の案内。案内の対象が実際の書き込みへ寄る |
| `tag` の終了コード | `up` が `TAG` を空にして続ける経路。基準の記録が入らなくなるだけで、起動は続く |

## リスクと対処

| リスク | 対処 |
| --- | --- |
| ヒアドキュメントの判定が引用符の中の `<<` を拾い、以降の行を落として実際の書き込みを見逃す | 行を落とすのは終端の語が現れるまでに限る。引用符の中の `<<` を含む入力をテストへ入れる |
| `_wt_resolve` の控えが対象ごとに作り直され、hook の応答が遅くなる | 控えの鍵を解決したディレクトリにする。引数なしの呼び出しは今までどおり 1 回で済む |
| 対象からの解決により、存在しないパスを渡したときの案内が消える | 解決できないときは現在地から解決し、`aim` の「作業ツリーがありません」などの案内を残す |

## 切り戻し手順
