# #4113: 起動の許可: ほかの計画を申請する側の NDF_PROGRESS_DB で読み、計画が使う DB と別の DB の行で数える

正は課題の本文（#4113）で、この文書はその写しである。本文から作り直す。手で直さない。

## 何が起きたか

起動の許可（行を始める起動の前に、マシン全体の稼働中のレーンの数を上限と比べる判定）が、ほかの計画のステートマシンを、その計画が実際に使う DB でなく、起動を申請する側のプロセスの `NDF_PROGRESS_DB` と作業ディレクトリで解いた DB から読む。別の DB に同じ `plan_id` の古い行があれば読み取りに成功するので、読めない計画として扱われず、実行中のレーンを数え落とす。

## 種類

不具合（確定仕様 `docs/specifications/ndf-parallel-machine-plan-limit.md` の「稼働中の数の数え方」は、マシンの計画の実行中の行を持つレーンを数えると約束している。計画の行はその計画が使う DB にあるので、別の DB を読むのは約束からの外れである）

## 事象

起動の許可（`src/ndf/progress/lane/machine.py` の `admitted` → `machine_plans` → `read_lanes`）は、ほかの計画のステートマシンを、起動を申請する側のプロセスの `NDF_PROGRESS_DB` と作業ディレクトリで解いた DB から読む（`read_lanes` の `store.default_url(root)`）。計画が実際に使う DB と別の DB を開いても、そこに同じ `plan_id` の行があれば読み取りに成功する。

| 場面 | 起きること |
| --- | --- |
| チェックアウト A と B がそれぞれ `NDF_PROGRESS_DB=sqlite:///progress.db`（相対）を使い、B 側の DB に A と同じ `plan_id` の古い行がある | B の起動の許可は A の計画を B 側の DB から読み、A の実行中のレーンを数え落とす。A のラッパーが止まっていれば、上限 1 でも B を起動できる |
| A が `NDF_PROGRESS_DB` で保存先の外の DB を使い、B の環境にその変数が無い | B の起動の許可は A の計画を A のチェックアウトの既定の DB から読む（無ければ読めない計画、古い行があればその行で数える） |

## 期待する結果

起動の許可も、#4044 が索引に書く計画の実際の接続先（版 2 の `db`。#4100 の決定 1 で SQLite は絶対パス）で、ほかの計画を読む。索引の接続先を持たない計画（版 1・登録簿にだけ載る）は今のとおり `read_lanes` で読むか、読めない計画として扱う。

## なぜ困るか

マシン全体の上限（並列は 6 本まで。2026-09-25 の実測で、全体テスト 6 本の同時実行でメモリが残り 7.4 GB）を、計画ごとに別の `NDF_PROGRESS_DB` を使うマシンで超え得る。読み取りに成功するので `unreadable` にも載らず、利用者は数え落としに気づけない。

## 目的

- 起動の許可と `ndf lanes status` が、ほかの計画を、その計画が実際に使う DB から読む
- 計画が使う DB を申請する側から開けないときは、別の DB を読まずに読めない計画として扱う
- 確定仕様の既知の限界から、索引の接続先を持つ計画を別の DB で読む行を外す

## 対象範囲

| 含む | 含まない |
| --- | --- |
| 起動の許可の `machine_plans` が、索引の接続先を持つ計画（版 2）を索引の接続先で読むこと（`ndf lanes status` の `machine_waits` も同じ関数を通る） | 索引に書く値と書く時点（#4044・#4100）、索引を消す時点と条件（#4051・#4092） |
| 索引の接続先を持たない計画（版 1・登録簿にだけ載る）の読み方を決めること | 数える行の規則（`lanes_of`・`held_seats`。#4050・#4091） |
| 確定仕様の「稼働中の数の数え方」と既知の限界の行を、直した読み方に合わせること | リレーハブの判定と `ndf lanes seats`（#4044） |
| | `NDF_PROGRESS_DB` の解き方そのもの（`default_url`・`sqlite_path`） |

## 受け入れ条件

- [ ] 1. チェックアウト A と B がどちらも `NDF_PROGRESS_DB=sqlite:///progress.db` を使い、A の計画が版 2 の索引に載って実行中の行を持つレーン 1 本（ラッパーは止まっている）を持ち、B 側の DB に A と同じ `plan_id` の行（実行中の行なし）があるとき、B を作業ディレクトリにした起動の許可は A の DB の行で数え、上限 1 で B のレーンを起動せずに `machine-lanes` で待たせる（テスト）
- [ ] 2. A の計画が保存先の外の SQLite（`NDF_PROGRESS_DB`）を使って版 2 の索引に載り、B の環境に `NDF_PROGRESS_DB` が無いとき、B の起動の許可は A の DB の行で数える（テスト）
- [ ] 3. 索引の接続先を申請する側から開けない計画（パスワードつきの接続先で、申請する側に同じ `NDF_PROGRESS_DB` が無い・SQLite の DB が無い）は、起動の許可で `unreadable` に載り、申請する側の DB から読み直さない。その計画が登録簿の conductor の行（別の作業ディレクトリを含む）にも載っていても同じである（テスト）
- [ ] 4. 索引の接続先を持たない計画（版 1 の索引・登録簿にだけ載る）は、今のとおり起動の許可で数える（テスト）
- [ ] 5. 起動の許可が版 2 の索引の計画を読む間、Git の子プロセスを起こさない（テスト）
- [ ] 6. 確定仕様の「稼働中の数の数え方」が、ほかの計画をどの接続先で読むかを書き、既知の限界の「起動の許可が計画の使う DB と別の DB を読めてしまう計画」の行が、索引の接続先を持たない計画だけの行になる（文書の読み合わせ）
