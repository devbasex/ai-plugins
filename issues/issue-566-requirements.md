# #566: 次に出す版を指す例が現行版を指す形へ崩れても、検査が止めない

設計は [issue-566-design.md](issue-566-design.md) にある。この文書は「何を満たすか」だけを扱う。

## 依頼（原文）

> **版を上げるたびに手で直す箇所が、一覧に載っていない。** 版数の扱いの正本
> `docs/versioning-and-distribution.md` の章 2「版の付け方と開発版の配布」で、版数を一括で置換すると
> 壊れる記載が 2 つある。
>
> | 記載 | 置換で壊れた形 | 見つけた配布 |
> | --- | --- | --- |
> | 章 2 の箇条書き「接尾辞は次に出す正式版の版数へ付ける」の例 | 「`10.10.0` の次を開発するなら `10.10.0-dev.1`」。次に出す版を指すはずの右側が現行版を指す | v10.10.0（配布前に直した） |
> | 章 2 の版の形の表の「開発版」の行 | 値が `10.10.0`。**接尾辞が消え、正式版の行と同じ値になった** | v10.10.1（PR #569 で `10.11.0-dev.1` に直した。v10.10.0 では壊れたまま配布された） |
>
> **どちらも検査は素通りした。**

（issue #566 の本文。場所は #499 の移設に合わせて 2026-09-13 に正本の章 2・章 7 へ書き直した。
直し方の 3 案は本文の「考えられる直し方」にある）

## 解釈

**版数を一括で置換したときに、章 2 の「次に出す版を指す例」が崩れたら、配布の前に機械で止まる
状態にする。** 3 案の中から検査に規則を足す案を選ぶ。選んだ理由と、他の 2 案を最新の `develop` で
確かめた結果は設計文書の「決定の記録」にある。

## 目的

- 章 2 の版の形の表と「次を開発するなら」の例が崩れたとき、`scripts/check-doc-staleness.py` が
  行番号を付けて失敗する
- 崩れた形を見つける手がかりを、人の読み直しから継続的統合へ移す

## 前提

- 前提 1: 例は**例どうし**で比べる。`develop` の `plugin.json` は接尾辞付きの版（`10.11.0-dev.1`）に
  なりうるため、例を現行版と一致させる規則は開発版の配布のたびに落ちる
- 前提 2: 既存の検査 J の規則（章に並ぶ版数の基底が現行版の基底より小さければ落ちる）は変えない。
  正式版の行を現行版へ結び付けるのは、この既存の規則である
- 前提 3: 章 2 の例の値（`10.10.1` / `10.11.0-dev.1` / `10.11.0-rc.1`）は、新しい規則をそのまま通る。
  この変更で例の値を書き換えない
- 前提 4: #500 は、この変更が `develop` へ入った後に章 2・章 7 を触る（#499 の設計の申し送り）

## 用語

| 用語 | 意味 |
| --- | --- |
| 正本 | `docs/versioning-and-distribution.md` |
| 章 2 | 正本の `## 版の付け方と開発版の配布` から、次の同位以上の見出しの直前まで |
| 版の形の表 | 章 2 の、1 列目が `正式版` / `開発版` / `公開前の確認版` の 3 行を持つ表 |
| 次の開発の例 | 章 2 の「`X` の次を開発するなら `Y`」の形の記載 |
| 基底 | 版数から接尾辞を除いた数字 3 つ |
| 検査 | `python3 scripts/check-doc-staleness.py --root <木>` |

## 受け入れ条件

崩れた形を止める:

- [ ] AC1: 版の形の表の開発版の行に `-dev.<連番>` が無い（例: `10.10.1`）とき、検査が終了コード 1 で
  終わり、出力に開発版の行の行番号が入る。公開前の確認版の行に `-rc.<連番>` が無いとき、正式版の行に
  接尾辞が付いているときも同じである
- [ ] AC2: 開発版の行か公開前の確認版の行の基底が、正式版の行の基底以下のとき、検査が終了コード 1 で終わる
- [ ] AC3: 次の開発の例で、`Y` の基底が `X` の基底以下のとき、または `Y` に `-dev.<連番>` が無いとき、
  検査が終了コード 1 で終わる
- [ ] AC4: issue の 2 つの崩れた形を再現した木で、AC1〜AC3 の失敗が出る。1 つは現行版 `10.10.1` のまま
  右側と表の行が現行版を指す形、もう 1 つは `10.10.1` を `10.11.0` へ一括で置換した形である

記載を消して通さない:

- [ ] AC5: 版の形の表の 3 行のどれかが無いとき、同じ 1 列目の行が 2 つ以上あるとき、次の開発の例が
  1 つも無いとき、検査が「読み取れない」ことを報告して終了コード 1 で終わる

誤って止めない:

- [ ] AC6: 現行版が接尾辞付き（`X.Y.Z-dev.N` / `X.Y.Z-rc.N`）の木で、例どうしが AC1〜AC3 を満たして
  いれば検査が通る
- [ ] AC7: 最新の `develop` の木で、検査と `bash scripts/validate-runtime-plugins.sh` が終了コード 0 で終わる
- [ ] AC8: `uv run --with pytest pytest scripts/tests plugins/ndf -q` が通る。既存の検査 J のテスト
  （現行版と同じ基底の接尾辞付きの版数を例として足しても通る、など）の期待値を変えない。例外は、
  テスト用の雛形へ公開前の確認版の行を足したことでずれる行番号（`L17` → `L18`）の 1 件だけである

文書:

- [ ] AC9: 正本の章 6 が、新しい規則と、版の形の表の 1 列目と「の次を開発するなら」が位置を決める語で
  あることを書く。章 7 の前置きが挙げる件数が、直下の表の行数と一致する

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 運用・保守性 | 失敗の出力 1 件ごとに、崩れた記載の値と行番号と、比べた相手の値が入る。出力だけで直す行を開ける |

## 対象範囲

含む:

- `scripts/check-doc-staleness.py` の検査 J に、版の形の表と次の開発の例の規則を足す
- `scripts/tests/` の検査 J のテストと、テスト用の章の雛形
- 正本の章 6（検査 J の説明）と章 7（前置きの件数）

含まない:

- 章 2 の箇条書きの 3・4 つ目（「`-dev.3` の次は」「順序は semver に従い」）の検査。一括置換の後も、
  例の中では整合したまま残る
- 章 2 の例の値の書き換え（前提 3）
- `AGENTS.md`。版数の例を置かない（#499）
- 根の `README.md` の記述を正本へ移すこと（#500）
- 正本の章 6 の重複段落と敬体の段落（#603）
- クラス図とデータ構造の成果物。型も永続データも足さない。変わるのは検査の関数と、検査の失敗の
  出力の文言である（文言は設計文書の「入出力の契約」が持つ）
- `CHANGELOG.md`。版の節は配布の工程が書く

## 影響

| 対象 | 影響 |
| --- | --- |
| 継続的統合 | 章 2 の例が崩れた Pull Request が、`validate-runtime-plugins.sh` 経由で落ちる |
| 配布の手順 | 版を上げる人は、一括置換の後に検査が指す章 2 の行を直す。手順そのものは変わらない |
| 章 2 を書く人 | 版の形の表の 1 列目の 3 語と「の次を開発するなら」を消せない。言い換えると検査が落ちる |
| 利用者 | 変わらない。配布物（`plugins/`）を触らない |
