# #928: 中継の導入を明示の操作にし、再起動のコマンドを足し、親から子へ入力を送れるかを確かめる — 要求と受け入れ条件

設計は [issue-928-design.md](issue-928-design.md)、決定の理由は
[issue-928-design-decisions.md](issue-928-design-decisions.md) にある。この文書は「何を満たすか」だけを扱う。
土台は #895 の確定仕様 `docs/specifications/ndf-relay-segment-restart.md`（v10.17.4 で配布済み）である。

マイルストーンは「17 トークン消費の削減」。版はマイルストーン 26 の 10.17.x（PATCH）で、版数は配布の工程が決める（`release`）。

## 例: 10.17.4 を入れた利用者が次の版へ上げる

今（v10.17.4）:

1. 利用者が Claude Code を起動すると、SessionStart hook の `relay.py install` が `~/.bashrc` の末尾へ `alias claude=...` を黙って足す。足すのは囲み（`# >>> ndf relay >>>` 〜 `# <<< ndf relay <<<`）の中である。同時に `~/.local/share/ndf/relay.py` へ中継を写す
2. 版を 10.17.3 へ戻しても囲みは残る。10.17.3 の hook は囲みを知らず、外さないためである
3. プラグインの更新を反映したいとき・文脈を切りたいときは、人が `/exit` → `claude` → コマンドの貼り付けを行う

変更の後:

1. Claude Code を起動しても、hook は `~/.bashrc` / `~/.zshrc` と `~/.local/share/ndf/` へ何も書かない。**10.17.4 が足した囲みが残っている利用者には、それが自動で足されたものであることと、残す・外すの方法を 1 度だけ知らせる**
2. 中継を使いたい利用者は `/ndf:install-wrapper` を 1 度打つ。外すときは `/ndf:install-wrapper uninstall`（10.17.4 が足した囲みも同じ手順で外れる）
3. 中継の下で `/ndf:restart` を打つと、claude が終了→プラグインの更新→起動し直し、再開用のコマンドが人の入力なしで送られる。中継の外では、手順の 1 行と、貼り付ける中身を囲みで示して終わる

## 依頼（原文）

> (1) 中継 relay.py の自動インストール（SessionStart hook の `relay.py install` が ~/.bashrc / ~/.zshrc へ alias を足す）を廃止し、スラッシュコマンド `/ndf:install_wrapper` で導入する (2) 自動再起動に加え、スラッシュコマンド `/ndf:restart` でランタイム再起動→再開用のコマンドの自動送信 (3) 親（relay.py）が子（claude）へ任意のコマンドを送り込めるかを調査し、できればモデルから叩けなかったコマンドを実行できるようにする。（2026-09-23 利用者の指示）

> 既に 10.17.4 を取得した利用者の手元で足された alias の囲み（`# >>> ndf relay >>>` 〜 `# <<< ndf relay <<<`）の扱い（取り外しの経路・移行）も設計に含める。関門（AskUserQuestion の承認）への答えを中継が代わりに送れてはならない。（起動指示）

## 目的

- **利用者のシェル設定を書き換えるのを、利用者の明示の操作だけにする。** 導入・更新・取り外しを 1 つのコマンドが持つ
- **10.17.4 が黙って足した囲みを、利用者が知って選べる状態にする。** 知らせずに残すことも、知らせずに消すこともしない
- **再起動を 1 つのコマンドに畳む。** プラグインの更新の反映・文脈を切りたいときにも、`/goal` の区間の切れ目と同じ経路で切り替える
- **親から子へ入力を送る経路の可否と条件を事実で残す。** 送れるなら、どの範囲なら関門を越えずに送れるかを決める

## 対象範囲

含む:

- SessionStart hook から `relay.py install` を外すこと
- 導入・取り外し・状態の表示を持つ Skill（`/ndf:install-wrapper`。命名は決定 1）と、それが呼ぶ `relay.py` の副命令
- 10.17.4 が足した囲みの扱い（知らせる・外す経路・写しの更新）
- 写しが既に在る利用者の写しを、SessionStart の hook が今の版で置き直すこと（10.17.4 が置いた写しは、新しい版の処理を自分では持たないため）
- 再起動の Skill（`/ndf:restart`）と、再開用のコマンドの作り方
- 項目 3 の実測（擬似端末の子への入力が TUI にどう受け付けられるか）と、その結果・送ってよい範囲・関門を越えないための不変条件の記録
- **関門を越えない守りを、既存の `/exit` の入力に入れること。** 実測で、質問（`AskUserQuestion`）の表示中に中継が書いた `\r` が選択肢 1 を決めると分かった。10.17.4 の切れ目の `/exit` と `\r` にも同じ経路がある（[issue-928-design-injection.md](issue-928-design-injection.md) の「例」）
- `development-workflow/references/relay.md` と確定仕様の改訂（実装の持ち場で行う）

含まない:

- **項目 3 の送り込みの実装。** 実測と不変条件はこの課題で決め、実装は別の課題に分ける（決定 6）
- Codex / Kiro / agy での中継・再起動。中継は Claude Code だけで、これらには Skill も hook も配らない（`/ndf:restart` の案内の 1 行も Claude Code だけ）
- 中継の本体の振る舞い（静まりの秒数・上限・空回り・素通し・`mark` のブロックの判定）の変更。再起動は既存の `ndf-next` の経路をそのまま使う。変えるのは `/exit` を書く前の守り（AC23〜AC25）、`/exit` の後の待ちで質問の印がある間は SIGTERM までの秒を数えないこと（AC25b）、`mark` が質問の印を消すことだけである
- bash / zsh 以外のシェル（fish など）への導入
- 既存の `claude` の alias / 関数を上書きすること

## 用語

| 用語 | 意味 |
| --- | --- |
| 囲み | シェルの設定の `# >>> ndf relay >>>` から `# <<< ndf relay <<<` までの行。中の `alias claude=...` が中継を挟む |
| 自動の囲み | 10.17.4 の SessionStart hook が足した囲み。状態の親の記録 `rc-added` に足した先のパスが載る |
| 写し | `${XDG_DATA_HOME:-~/.local/share}/ndf/relay.py`。alias が指す中継の本体 |
| 再開用のコマンド | 再起動した claude へ最初の入力として渡す中身（`ndf-next` のブロックの中身と同じ扱い） |
| 送り込み | 中継が子の擬似端末へ、`/exit` 以外の入力を書くこと（項目 3） |

その他（区間・切れ目・印・静まり・素通し・落ちる）は確定仕様 `ndf-relay-segment-restart.md` の用語のとおり。

## 受け入れ条件

### 1. 自動の導入をやめる

- [ ] AC1: `plugins/ndf/hooks/claude.json` の SessionStart に `relay.py install` が無い。Claude Code を起動しても、`~/.bashrc`・`~/.zshrc` の中身と更新時刻が変わらない。`${XDG_DATA_HOME:-~/.local/share}/ndf/` に写しが無ければ、何も作られない（一時の HOME で起動の前後を比べる）
  - ~~`${XDG_DATA_HOME:-~/.local/share}/ndf/` の中身と更新時刻も変わらない~~ → 写しが既に在るときだけ、その中身の置き直しを許す（2026-09-23、設計レビューの指摘。10.17.4 の写しは新しい版の処理を持たず、hook が置き直さないと 10.17.4 のまま残る。AC11）
- [ ] AC2: Codex / Kiro / agy の hook の定義に差分が無い

### 2. 明示の導入と取り外し（`/ndf:install-wrapper`）

- [ ] AC3: `/ndf:install-wrapper`（引数なしか `install`）で、写しを置き、`$SHELL` の設定（bash は `~/.bashrc`、zsh は `${ZDOTDIR:-~}/.zshrc`）の末尾へ囲みを足す。書く前にバックアップ（`<設定>.ndf-bak-<UTC>`）を取り、足した先・バックアップ・次に開いたシェルから効くことを報告する
- [ ] AC4: 既に囲みがあれば囲みは足さず、写しだけを今の版で置き直す（更新）。10.17.4 の `rc-added` の記録があっても、明示の導入は足す（利用者が消した後でも、打てば足る）
- [ ] AC5: 既存の `claude` の alias / 関数（bash では `~/.bash_aliases` も）があれば足さず、自分で置く 1 行を示す。bash / zsh 以外のシェルでは足さず、置く 1 行を示す
- [ ] AC6: `/ndf:install-wrapper uninstall` で、足す先（と、もう一方のシェルの設定）の囲みを行ごと外す（外す前にバックアップ）。囲みの外の行は 1 バイトも変えない。写しを消す。`rc-added` には外したパスを残す（10.17.4 へ戻した利用者の hook が足し直さない）。**10.17.4 が足した自動の囲みも同じ手順で外れる**
- [ ] AC7: `/ndf:install-wrapper status` で、囲みの有無（どのファイルか・自動の囲みか）・写しの有無と、写しの中身が今のプラグインの `relay.py` と同じかを示し、何も書かない
- [ ] AC8: この Skill は Claude Code にだけ配られ、明示指示でだけ起動する（モデルが自分の判断で利用者のシェル設定を書き換えない）

### 3. 10.17.4 の自動の囲みの移行

- [ ] AC9: 自動の囲みが残っている利用者が次の版の Claude Code を起動すると、「10.17.4 が自動で足した alias が残っている。使い続けるなら何もしなくてよい。外すなら `/ndf:install-wrapper uninstall`」の 1 行が 1 度だけ出る。2 回目以降の起動では出ない。同じ HOME で 2 つの起動が同時に来ても 1 度だけである。このとき hook はシェルの設定を読むだけで書かない（知らせた記録は状態の親 `${XDG_STATE_HOME:-~/.local/state}/ndf/relay/` にだけ書く）
- [ ] AC10: 自動の囲みを残した利用者の中継は、次の版でもそのまま動く（alias の形・写しの置き場所・`NDF_RELAY_*` の意味を変えない）
- [ ] AC11: 写しが在る利用者では、Claude Code の起動ごとに SessionStart の hook が写しを今の版の `relay.py` と比べ、違えば置き直す。写しが無ければ作らない。シェルの設定は変えない。10.17.4 の写しで動く中継でも、区間の切り替えで起動した claude の hook が置き直し、次に `claude` と打ったときから新しい版で動く

### 4. 再起動（`/ndf:restart`）

- [ ] AC12: 中継の下で `/ndf:restart <再開用のコマンド>` を呼ぶと、claude はその応答の最後に `ndf-next` のブロック（中身は引数）を出して応答を終える。中継は既存の切れ目と同じ手順（静まり → `/exit` → プラグインの更新 → 区切りの 1 行 → 起動）で、再開用のコマンドを最初の入力にした claude を起動する。人の入力は `/ndf:restart` の 1 回だけ
- [ ] AC13: 引数なしで呼ぶと、今の会話から再開用のコマンドを作る。`/goal` の目標がある会話ではその目標のコマンド（`/goal ...` の形のまま）、無ければ課題番号・作業ツリー・Pull Request など会話の外に残った記録を指す 1 段落で、承認・同意を表す文を含めない。どちらも作れなければ、引数を求める 1 行を示してブロックを出さずに終える
- [ ] AC14: 中継の外（`NDF_RELAY_DIR` が無いか、`relay.py is-child` が 0 でない）で呼ぶと、ブロックは出さず、手順の 1 行と再開用のコマンドを示して終わる。手順は「`/exit` してから `claude` を起動し、下の中身を最初の入力として貼り付ける（`/ndf:install-wrapper` で中継を入れると自動になる）」で、再開用のコマンドは情報文字列 `text` の囲みで示す。**シェルへ貼る 1 行（`claude "..."`）は示さない**
- [ ] AC15: 背景の処理が動いているあいだ・`AskUserQuestion` の答えを待っているあいだは切り替わらない（既存の `mark` の判定のとおり）。`/goal` の判定が応答を続けさせたときは、続いた応答の最後に同じブロックを出し直す
- [ ] AC16: この Skill は Claude Code にだけ配られ、利用者もモデルも起動できる

### 5. 親から子への送り込みの調査（項目 3）

- [ ] AC17: 擬似端末のマスタへ書いた入力が、入力待ち・応答の途中・`AskUserQuestion` の表示中のそれぞれで TUI にどう受け付けられるか（スラッシュコマンドとして働くか・待ち行列に入るか・質問の答えに入るか）を、本物の Claude Code（版を記す）で実測し、設計の文書に表で残す
- [ ] AC18: 送り込みを実装するときに守る不変条件を設計の文書に残す。少なくとも「関門（`AskUserQuestion`）の答えを中継が送れない」「利用者の入力を装える自由な文を送らない」「対話の UI を開くコマンドを送らない」を含み、それぞれを実測のどの事実で担保するかを書く
- [x] AC19: 送り込みの実装を別の課題として起票し、この課題の本文から参照する（`/ndf:out-of-scope`）。#931 として起票した

### 6. 関門を越えない守り（既存の `/exit` の入力）

- [ ] AC23: 中継の直接の子で質問（`AskUserQuestion`）が表示されているあいだは、印があって静まっても、中継は子の端末へ何も書かない。質問に答えるか取り消した後、次の Stop が印を書き直せば、そこから今までどおり切り替わる
- [ ] AC24: 印の後に応答が再開した（会話の記録に印より後の応答の行がある）ときは、その印では `/exit` を書かない。次の Stop が印を書き直すか消すまで待つ
- [ ] AC25: `/exit` と改行は 1 回の write で書く。確かめ直し（AC23・AC24）と write は、質問の hook と同じロックの中で行い、書いた後も 1 秒ロックを持つ。質問の hook はこのロックを取ってから質問の印を作る。確かめ直しで外れたら書かずに待ちへ戻る
- [ ] AC25b: `/exit` を書いた後に質問の印が現れたら、印が消えるまで SIGTERM までの秒を数えない（書いた `/exit` が応答の待ち行列に入り、質問の答えの後に働く場合に、質問を強制終了で消さない）
- [ ] AC26: 中継の外・中継の直接の子でない claude では、質問の hook は何も書かず、何も出力せず終了コード 0 で終わる

### 7. 通しの確かめと退行

- [ ] AC20: 擬似端末の上の単体テスト（`test_relay.py`）で、`install` / `uninstall` / `status` / 知らせの 1 度だけ / 写しの置き直しを、一時の HOME と `XDG_*` の下で確かめる。本物の `~/.bashrc` を変えない
- [ ] AC21: 本物の Claude Code（一時の HOME・隔離した `CLAUDE_CONFIG_DIR`）の上で、中継の下の `/ndf:restart` が人の入力なしで次の区間を起動することを 1 度通す。記録を実装の Pull Request に残す
- [ ] AC22: 既存の中継の単体テストと全体テストが通る。`claude plugin validate .` と `python3 scripts/check-skill-frontmatter.py` が終了コード 0

## 前提

- 前提 1: 10.17.4 の自動の囲みは、`rc-added` の記録（足した先のパス）と囲みの存在の両方で見分けられる。記録が無い囲み（利用者が自分で写した）は自動の囲みとして扱わない
- 前提 2: Claude Code の Skill の中の Bash は、中継が子に置いた環境変数（`NDF_RELAY_DIR`）を継ぐ。`relay.py is-child` を Bash から呼ぶと、親をたどって最初に当たる claude が中継の子になる（`mark` と同じたどり）
- 前提 3: `ndf-next` のブロックは `/goal` の無い会話でも印になる（確定仕様の `mark` の判定は `/goal` を条件にしない）

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 可用性 | hook と Skill の失敗で SessionStart と会話を止めない（知らせの hook は常に終了コード 0）。写しの置き直しに失敗しても中継は古い写しのまま始まる |
| 運用・保守性 | 導入・取り外し・状態の入口は `/ndf:install-wrapper` の 1 つ。手で戻す方法（囲みを消す）も文書に残す |
| 移行性 | 10.17.4 の囲み・写し・`NDF_RELAY_*` をそのまま使える。版を戻しても（10.17.4 へ）新しい版で足した囲みは同じ形なので壊れない |
| セキュリティ | シェルの設定を書くのは明示の起動だけ。囲みの外を書き換えない。書く前にバックアップを取る。再開用のコマンドに承認を表す文を入れない。質問の表示中と応答の再開の後は中継が子の端末へ書かない（AC23〜AC25）。送り込みの不変条件（AC18） |
| システム環境 | Claude Code 2.1.281 以降・Linux / macOS・bash / zsh・Python 3 の標準ライブラリだけ |

## 影響

| 対象 | 変わること |
| --- | --- |
| 新しく ndf を入れる利用者 | シェルの設定が変わらない。中継を使うなら `/ndf:install-wrapper` を打つ |
| 10.17.4 で自動の囲みが足された利用者 | 1 度だけ知らせが出る。何もしなければ今までどおり中継が動く（写しは次の起動の hook で置き直される） |
| 10.17.4 で囲みを消した利用者 | 変わらない（知らせも出ない） |
| `NDF_RELAY_AUTO=0` を置いていた利用者 | 変数は意味を失う（hook が導入しないため）。置いたままでも害は無い |
| 中継の下の利用者 | `/ndf:restart` で好きな時点に切り替えられる。質問の表示中と応答の再開の後は切り替わらない（今までは切り替わりえた） |
| Codex / Kiro / agy | 変わらない |
