# #4013: cross-review: 修正担当をラウンドごとに新しく起動せず会話を続け、ファイルの探し直しを減らす

正は課題の本文（#4013）で、この文書はその写しである。本文から作り直す。手で直さない。

## 何が起きたか

2026-11-21 20:49 JST から 21:28 JST の PR #3994（lracct の設計）の cross-review の 3 ラウンドで、相手役のレビューと修正担当の修正にかかった時間は次のとおりだった（状態の保存先のファイルの更新時刻から）。

| ラウンド | レビュー（codex） | 修正（claude） |
| ---: | ---: | ---: |
| 1 | 2.6 分 | 12.3 分 |
| 2 | 1.7 分 | 8.0 分 |
| 3 | 1.6 分 | 8.4 分 |

修正担当はラウンドごとに新しい `claude -p` として起動される（`--no-session-persistence`）。毎回、同じ設計文書とコードを `grep`・`sed -n` で探し直してから直している。

## 種類

機能追加（今の SSOT は修正担当をラウンドごとに新しく起動すると定めており、実装はそのとおりに動いている。会話を続ける約束は今の SSOT に無い）

## 今の姿

cross-review の駆動（`plugins/ndf/src/ndf/domains/crossreview/drive.py`）は、ラウンドごとに相手役（codex・kiro）を並べて起動し、収束の妨げになる指摘が残れば修正担当（claude）を起動する（`_fix`・`_fixer_launch`）。修正担当は最小構成の `claude -p`（`plugins/ndf/src/ndf/adapters/claude.py` の `minimal_args`。`--no-session-persistence` つき）で、Tool は `Read,Edit,Write,Bash,Grep,Glob`、指摘の一覧と結果ファイルのパスをプロンプトで受け、直した・見送ったを結果ファイルへ書く。会話は残らないので、2 ラウンド目の修正担当は 1 ラウンド目に読んだ内容を持たない。

SSOT: `plugins/ndf/skills/cross-review/docs/02-fix-and-rotation.md`・`drive.py` の `_fixer_launch`。

2026-11-22 の実測（このマシンの 55 回の実行・225 ラウンド）:

| 項目 | 値 |
| --- | --- |
| 合計 | レビュー 243 分・修正 802 分（修正が 77%） |
| 1 ラウンドのレビュー（最も遅い相手役） | 中央値 0.9 分 |
| 1 ラウンドの修正 | 中央値 3.3 分・最大 20 分 |
| 修正 1 回の tool 呼び出し | 平均 14.4 回。Bash 1,930 回のうち `python3 -` 363・`grep -n` 282・`sed -n` 245・`grep -rn` 90 |

集計は scratchpad の状態の保存先（`round<n>.diff`・`round<n>-<相手役>.out`・`round<n>-fix.err.log`・`round<n>-fix.out`）の更新時刻と、`round<n>-fix.out` の stream-json の `tool_use` を数えた。時間は更新時刻から出したので目安である。

## 何を足すか・変えるか

| | 今 | 足した後 |
| --- | --- | --- |
| 同じ `run` の 1 ラウンド目の修正担当 | 会話を残さない新しい `claude -p` | 会話を残す新しい `claude -p`（NDF が会話の ID を決めて始める） |
| 2 ラウンド目からの修正担当 | 会話を残さない新しい `claude -p` | 前のラウンドの修正担当の会話を続ける。続けない条件（前提 2）に当たれば、新しい会話で始める |
| 相手役の起動 | 毎ラウンド独立 | 変えない |
| 修正の結果ファイルと状態ファイル | 今の形 | 変えない |

## なぜ困るか

cross-review の時間の 77% が修正担当に使われ、その多くが前のラウンドで読んだファイルの探し直しである。設計・実装・リファクタリングのどの PR も cross-review を通るので、スプリント全体の時間に効く。

## 目的

- 2 ラウンド目からは、前のラウンドの文脈を持った修正担当が指摘を直すだけになり、1 回の修正が短くなる状態にする

## 対象範囲

含む:
- 修正担当の起動（`_fixer_launch`）を、同じ `run` の中で会話を続ける形にすること（会話の始め方・続け方の形は設計で決める）
- 会話を続けない条件と、そのときに今のとおり新しい会話で起動すること（前提 2）
- 続けようとした会話が見つからない（起動が会話の欠けで失敗した）ときに、同じラウンドの中で新しい会話で起動し直すこと
- 手順書（`plugins/ndf/skills/cross-review/docs/02-fix-and-rotation.md`）の説明

含まない:
- 相手役（codex・kiro）の起動。相手役は毎ラウンド独立に読むことで、修正担当の思い込みを拾う役を持つので変えない
- 修正担当の並列化（#4015）
- 別の起動（`ndf cross-review run` を打ち直した・中断から再開した）の間で会話を引き継ぐこと
- 修正担当への指示の文と Tool の範囲の変更

## 前提

- 前提 1: 「同じ `run`」は、1 回の `ndf cross-review run` の起動（`drive` の 1 回の呼び出し）とする。会話の ID はその起動の中だけで持ち、状態ファイルには書かない（受け入れ条件 4）
- 前提 2: 会話を続けない条件は次の 3 つとする
  - 前のラウンドの修正担当が、正常に終わらなかった（タイムアウト・誤り）か、結果ファイルを書かなかった・読み込めなかった
  - 前のラウンドの修正担当の会話の文脈が、上限の設定（`plugins/ndf/contracts/limits.json` に足す値。値は設計で決める）を超えた
  - その起動で修正担当を起動するのが初めて（1 ラウンド目・別の起動からの再開の最初のラウンド）
- 前提 3: 続けた会話の修正担当にも、今と同じプロンプト（その回の指摘の一覧・結果ファイルのパス・指摘の基準）を毎回渡す。前のラウンドの指示を覚えていることを当てにしない
- 前提 4: `claude -p` は `--session-id <ID>` で会話を始め、`--resume <ID>` で続けられ、無い ID への `--resume` は終了コード 1 と `No conversation found with session ID` で終わる（2026-11-21 に claude 2.1.330 で確かめた）
- 前提 5: 会話を残すと、会話の記録が claude の設定の保存先（作業場所のパスごとのディレクトリ）に残る。今の `--no-session-persistence` はこれを残さない
- 前提 6: 会話を残して続けるのは、実行者のメインディレクトリの `.ndf/review.json` に `"fixer_sessions": true` を書いたリポジトリだけとする。書かないリポジトリは今のとおり会話を残さない（前提 5 の記録に未公開の指摘と読んだファイルの中身が平文で残るため、利用者が選ぶ）。ai-plugins は自分の `.ndf/review.json` に真を書く（2026-11-21、設計 PR #4017 の cross-review の指摘 r1-3・r2-1 で足した）

## 受け入れ条件

- [ ] 1. `fixer_sessions` が真のリポジトリで、同じ `run` の 2 ラウンド目からの修正担当が、前のラウンドの修正担当の会話を続けて起動される（起動の引数で確かめるテスト）
- [ ] 7. `fixer_sessions` を書かない・偽のリポジトリでは、修正担当はどのラウンドでも今と同じ `--no-session-persistence` で起動される（起動の引数で確かめるテスト。2026-11-21、前提 6 とともに足した）
- [ ] 2. 前提 2 の 3 つの条件のどれかに当たると、修正担当は新しい会話で起動される（条件ごとのテスト）
- [ ] 3. 続けようとした会話が見つからず起動が失敗したら、同じラウンドの中で新しい会話で 1 度だけ起動し直し、そのラウンドの修正を失わない（テスト）
- [ ] 4. 修正の結果ファイルの形と、状態ファイルへの記録（`rounds`・`findings` の形）は変わらない（既存のテストが通る）
- [ ] 5. 相手役の起動の引数は変わらない（テスト）
- [ ] 6. 入れた後の 5 回以上の実行で、2 ラウンド目からの修正 1 回の tool 呼び出しの数と時間を上の実測と比べた結果がこの Issue にある
