## 何が起きたか

2026-11-18、スプリントの Pull Request（ https://github.com/devbasex/ai-plugins/pull/3779 、67 ファイル）の cross-review（複数の AI がレビューし、指摘が無くなるまで直しを繰り返す機能）が終わらなかった。1〜3 ラウンドがどれも差分の全体（64〜67 ファイル）を読み直した。全体を読み直したラウンドでは、直した箇所と関係の無い細部の指摘が重い扱い（major）で新しく出る。利用者の指摘は「とか細かいことまで気にしてたら一生終らなくないですか」である。

2・3 ラウンドで全体を読み直した原因は未確認である（起票が挙げた状態ファイルは、2026-11-27 には残っていない）。

## 種類

機能追加（今の手順書は、下の条件で全体を読み直すことと、critical・major が残れば次のラウンドへ進むことを定めていて、実装はそのとおりに動いている）

## 今の姿

- 1 ラウンド目は差分の全体を読む。2 ラウンド目以降は、相手の AI 全員が読めた最後のラウンドからの差分だけを読む
- 次のどれかに当たると、2 ラウンド目以降も差分の全体を読み直す

| 全体を読み直す条件 | 読み直す理由 |
| --- | --- |
| 全員が読めたラウンドが無い | 差分の起点が無い |
| 起点のコミットが今の履歴に無い（Pull Request を作り直した） | 起点からの差分が正しく作れない |
| 比較先のブランチとの分かれ目が変わった | Pull Request の差分そのものが変わった |
| 今回の相手の AI に、そのラウンドを読んでいない者がいる | その AI は全体を一度も読んでいない |
| 重点（プロジェクトが指定するレビューの観点）・レビューの単位の指示（作業を分けて出す Pull Request の担当範囲の指示）・対象の Pull Request・プロジェクトの判断基準（MVV）が変わった | 新しい観点で一度も読んでいない |
| 承認済みの MVV があり、Pull Request が足した「根拠: Value …」の行が MVV と合うかを NDF が機械で確かめ終えていない | 確認が残っている |

- 設計の Pull Request は、変わったセクションがすべて詳しいレビューを通るまで全体を読む
- 次のラウンドへ進むのは、未解決の critical・major があるときで、変えていない行への指摘でも進む。minor・nit は修正へ回さず記録に残し、Issue は起票しない
- ただし文書の読みにくさの指摘は、2 ラウンド目以降は書き換わった文などに限って major にするよう、AI へ指示している
- ラウンドの上限の既定は 3 で、`--max-rounds` を渡せばその値になる
- SSOT: [手順書の「範囲」と「判定」](https://github.com/devbasex/ai-plugins/blob/main/plugins/ndf/skills/cross-review/docs/01-state-and-review.md)

## 何を足すか・変えるか

| | 今 | 足した後 |
| --- | --- | --- |
| 2 ラウンド目以降の範囲 | 上の条件に当たると全体 | 実装の Pull Request は、相手の AI 全員が読めた最後のラウンドからの差分（受け入れ条件 1 の例外では全体） |
| 次のラウンドへ進む指摘 | 未解決の critical・major のすべて | 2 ラウンド目以降は、critical と、変えた行（相手の AI 全員が読めた最後のラウンドの後に変えた行）への major。秘密・認証認可・利用者のデータ・戻せない操作・人の安全の major は行を問わない |
| それ以外の指摘 | major は修正へ回す。minor は記録に残す | 直さない。起票は「起票する指摘」（受け入れ条件の下の表）だけにし、ほかは Pull Request の記録のコメントに残す |
| 実装の Pull Request の上限の既定 | 3 | 設計で決めた値 |

## なぜ困るか

直しと関係の無い指摘でラウンドが伸びると、スプリントの検査が終わらず、リリースまでの時間と AI の利用料が増える。

## 目的

1 ラウンド目で全体を見て、2 ラウンド目以降は直した箇所が正しいかを確かめる。細部の指摘では止まらず、検査が数ラウンドで終わる。

## 対象範囲

含む:
- cross-review（`ndf cross-review run`）の 2 ラウンド目以降の範囲
- 2 ラウンド目以降に次のラウンドへ進む指摘の線引きと、進まない指摘の残し方
- 実装の Pull Request の上限の既定

含まない:
- 1 ラウンド目の範囲
- 重要度を下げる条件（ https://github.com/devbasex/ai-plugins/issues/4363 が持つ）
- 設計の Pull Request の範囲の決まり
- 再開をまたいだラウンドの合計と、費用・時間の上限（ https://github.com/devbasex/ai-plugins/issues/2468 が持つ）

## 受け入れ条件

- [ ] 1. 実装 PR の 2 ラウンド目以降の `review_scope.range` が、比較先との分かれ目の変化、重点・指示・MVV の変化、MVV の根拠の確認の未了のときも、前のラウンドからの差分になる。全員が読めたラウンドが無い、起点のコミットが履歴に無い、対象の Pull Request が変わった、読んでいない AI がいる場合は全体のままにする（テスト）
- [ ] 2. 2 ラウンド目以降、minor と、変えていない行への major では次のラウンドへ進まない（条件 5 の major を除く）。起票は下の「起票する指摘」に当たる指摘だけにし、ほかは Pull Request の記録のコメントに残す（テスト）
- [ ] 3. 実装 PR の既定の上限が設計で決めた値になり、`--max-rounds` を渡せばその値が勝つ
- [ ] 4. 1 ラウンド目は今と同じく差分の全体を見る
- [ ] 5. 2 ラウンド目以降も、critical と、相手の AI 全員が読めた最後のラウンドの後に変えた行への major が未解決なら、修正へ回して次のラウンドへ進む。秘密・認証認可・利用者のデータ・戻せない操作・人の安全の major は、変えていない行でも同じ扱いにする（テスト）

起票するのは、次のどれかに関わる指摘だけである。それ以外は記録のコメントに残す。

| 起票する指摘 | 例 |
| --- | --- |
| 利用者に届いた不具合 | 配ったバージョンのコマンドが、普段の使い方で失敗する |
| 人の安全 | 画面の案内に従うと、人に危害が及ぶ |
| 秘密 | トークンがログや Pull Request のコメントに出る |
| 利用者のデータ | 利用者のデータが書き換わる・失われる |
| 戻せない操作 | 確認なしにブランチや記録を消す |
| 承認資料の正しさ | 承認する人へ見せる説明が事実と違う |

MVV の Value 6 は、利用者の Issue の一覧を作業の残りで膨らませず、増やすのを大事な指摘に限る決まりである。上の表は Value 6 が挙げる種類である。認証・認可の指摘は、上の表のどれかにも当たるときだけ起票し、当たらなければ記録のコメントに残す。

エンジニア向けの補足: 指摘の種類を表す項目 `tracks`（定義は #4363 の設計書）の値との対応は、上の行の順に `delivered`・`safety`・`secret`・`user_data`・`irreversible`・`approval` である。認証・認可は `authz` で、`authz` にしか当てはまらない指摘は起票しない。

条件 4 と、条件 3 の「`--max-rounds` を渡せばその値になる」の今の振る舞いは、2026-11-27 に `origin/main`（ndf 11.0.45）のコードを読んで確かめた。同じコミットで cross-review のテスト 660 件が通る。
