## 何が起きたか

2026-11-25、利用者が `/work/ai-plugins` で `git pull` を打つと、手元の `.ndf/project.json` に未コミットの変更があるため止まった。`.ndf/project.json` は、NDF がリポジトリの形（言語・テスト・CI など）を書いておく設定のファイルである。git で追跡し、チームで共有する。

止めた差分は 84 行あった。中身は次の 2 つだけで、設定の値は何も変わっていなかった。

- 言語ごとのファイル数の更新（Python のファイル数 885 → 1064）
- 解析した時刻・入力のファイルのハッシュ・ブランチの構成の書き直し

NDF は、開発の作業を始めるたびに設定が古くなっていないかを確かめ、古ければリポジトリを調べ直して（解析して）設定へ書き出す（`ndf project write`）。そのたびに、こうした実行ごとに変わる値も、git で追跡するファイルへ書かれる。

## 種類

機能追加（`.ndf/project.json` の形と、実行ごとに変わる値の置き場を変える。NDF が書くファイルの置き場の一覧の行も書き換える）

## 今の姿

- 解析の書き出し（`ndf project write`。[`write.py`](https://github.com/devbasex/ai-plugins/blob/main/plugins/ndf/src/ndf/domains/project/write.py)）は、測った値と回答を `.ndf/project.json` へ書く。同じファイルのキー `analysis` に、次の 2 種類の値も毎回書く
  - 解析の記録: 解析器のバージョン・解析した時刻・入力のファイルのハッシュ・ブランチの構成。設定が古くなっていないかを確かめる仕組み（`ndf project check`）が、入力のファイルのハッシュとブランチの構成を今のリポジトリと比べる。入力のファイルは、解析が読むファイル（CI のワークフローの定義・`pyproject.toml` などの依存とテストの設定・`AGENTS.md` などの指示書）である。ブランチの構成は、リモートの既定ブランチと、`main`・`develop` などの決まった名前のブランチがリモートにあるかである
  - 書いた値の指紋（`analysis.written`）: 解析が書いた設定の値のハッシュで、項目（`languages`・`ci` など）ごとに 1 つある。書き出しはこれで、人が手で直した値か解析が書いた値かを見分け、人が直した値を書き換えない（[project-analysis.md の「書き出しの規則」](https://github.com/devbasex/ai-plugins/blob/main/plugins/ndf/skills/development-workflow/references/project-analysis.md#書き出しの規則)）
- 設定の項目の中にも、実行ごとに変わる計測値が入っている。言語ごとのファイル数（`languages[].files`）と、CI のワークフローごとの直近の実行時間（`ci.workflows[].wall_seconds`）である。CI のワークフローごとのジョブ数（`ci.workflows[].jobs`）も、ワークフローの定義から数えた数と直近の実行のジョブ数の大きい方なので、動的なマトリクスでは実行ごとに変わる。書き出しのほかに、この 3 つを使う仕組みは無い（`plugins/ndf/src`・`scripts`・`experimental` を `grep` で確かめた）
- テストの所要時間（`test_duration`）は、設定のスキーマで非推奨になっていて、書き出しはもう書かない。古い書き出しが書いた値が、このリポジトリの `.ndf/project.json` に残っている
- NDF が書くファイルの置き場の一覧（[`ndf-files.json`](https://github.com/devbasex/ai-plugins/blob/main/plugins/ndf/contracts/domains/ndf-files.json)）は、「実行で変わる計測値は追跡する設定へ書き戻さず、状態の保存先へ書く」と定めている。状態の保存先は、リポジトリの外にある、NDF が状態を置くディレクトリ（既定は `~/.local/state/ndf/`）である。一覧にはその置き場の行（`project-measured`）もあるが、そこへ書くコードはまだ無い

## 何を足すか・変えるか

| | 今 | 足した後 |
| --- | --- | --- |
| `.ndf/project.json` に載るもの | 設定の値・書いた値の指紋・解析の記録・計測値 | 設定の値と書いた値の指紋（`analysis.written`）だけ。どちらも設定の値が変わったときだけ変わる |
| 解析の記録と計測値の置き場 | `.ndf/project.json` の中 | `.ndf/measured/project.json`。git で追跡しない |
| 書いた値の指紋の作り方 | 計測値を含めた項目の値から作る | 計測値を取り除いた項目の値から作る。そのため計測値が変わっても指紋は変わらない |
| 置き場を git から外す方法 | 無い | 書き出しが `.ndf/measured/` に中身 `*` の `.gitignore` を置き、そのディレクトリ全体（この `.gitignore` 自身を含む）を git から外す。`.ndf/.gitignore` とリポジトリの根の `.gitignore` は変えない |
| 置き場の一覧 | 計測値の置き場はリポジトリの外 | 計測値と解析の記録の置き場を `.ndf/measured/` に直す |
| 解析をやり直したときの、追跡するファイルの差分 | 時刻・ハッシュ・ファイル数が変わるだけで出る | 設定の値が変わったときだけ出る |

## 今の利用者への影響と互換

- 既存の `.ndf/project.json` に残る値は、次の書き出しで `.ndf/project.json` から無くなる。解析の記録と計測値は `.ndf/measured/project.json` へ移り、テストの所要時間は捨てる。次の書き出しは、NDF を新しいバージョンへ上げた後、最初に開発の作業を始めたときに NDF が自動で打つ。利用者は、そのときに出る `.ndf/project.json` の差分を 1 回コミットする
- 新しく clone した場所には `.ndf/measured/` が無い。そのため、最初に開発の作業を始めたとき、NDF が自動で解析を 1 回やり直す。利用者の操作は要らない。解析は既定で 120 秒のタイムアウトで打ち切るので、それより長くはかからない
- 新しい NDF は、既存の設定に残る古い項目を見つけると、次の書き出しで新しい形式へ移行する。利用者が手で直す作業は要らない
- チームで新しい形式の `.ndf/project.json` を共有する前に、開発に使う NDF を新しいバージョンへ更新する。古い NDF は新しい形式の設定を受け付けない（普及のフェーズまで後方互換を求めない、というリポジトリの方針）。新しい形式がコミットされた後に古い NDF を使うメンバーは、開発の作業を始めた時点で「設定が壊れている」と判定されて止まり、NDF を更新すれば直る
- NDF 自身のリポジトリ（このリポジトリ）では、設定の形の検査（`ndf check`）が追跡している `.ndf/project.json` を新しいスキーマで確かめる。そのため、実装の Pull Request は、スキーマの変更と同じコミットで、追跡している `.ndf/project.json` を新しい形式へ移す（[設計書](./issue-4516-design.md) の決定 4）

## なぜ困るか

- 設定を変えていないのに追跡するファイルに差分が出て、`git pull`・ブランチの切り替え・worktree（作業用に分けたディレクトリ）の後片付けが止まる
- 差分をコミットすると、設定の変更に、意味の無い時刻やファイル数の変更が混ざる。`.ndf/` の変更は、取り込む前に人が確かめるものであり（NDF の共通原則の C7）、確かめる量が増える
- 書いた値の指紋はファイル数や実行時間を含めた値から作るため、計測値が変わるたびに指紋の行も書き換わり、差分がさらに増える

## 目的

- `.ndf/project.json` を、push してよい設定の値だけを持つファイルにする
- 解析をやり直しても、追跡するファイルに差分が出るのは設定の値が変わったときだけにする

## 対象範囲

含む:
- 解析の記録と計測値を `.ndf/measured/project.json` へ書くこと
- `.ndf/measured/` を git から外すこと
- 設定が古くなっていないかの確かめと、人が直した値を書き換えない決まりを、新しい置き場の上で今までどおり働かせること
- 既存の `.ndf/project.json` に残る解析の記録・計測値・テストの所要時間を、次の書き出しで取り除くこと
- 設定の形の定義（スキーマ）・置き場の一覧・`project-analysis.md`・設定とファイルの説明の文書（`ndf-settings.md`・`files.md`）を、新しい置き場と形に合わせること

含まない:
- 計測値を使う新しい仕組み（計測値から何かを決めること）
- ブランチ戦略の設定（`branch_strategy`）を書くコマンド（`ndf project branch-strategy`）の変更
- このリポジトリの `.ndf/project.json` にある利用者の未コミットの変更を、この課題の中で扱うこと。実装のリリースの後、利用者が書き出しをやり直せば片付く

## 前提

- 前提 1: `.ndf/measured/` は、設定と同じく clone したディレクトリ（メインディレクトリ）の `.ndf/` の下に置く。作業用に分けたディレクトリ（worktree）から書き出しても、メインディレクトリへ書く（今の `.ndf/project.json` と同じ）
- 前提 2: `.ndf/measured/project.json` は人が書かない。壊れていても、書き出しが作り直してよい

## 受け入れ条件

- [ ] 1. 設定の値が変わらない入力で `ndf project write` を 2 回続けて打つと、2 回目は `.ndf/project.json` を変えない。間に解析した時刻・入力のファイルのハッシュ・ファイル数・CI の実行時間・直近の実行のジョブ数が変わっても同じである
- [ ] 2. 書き出しの後、`.ndf/project.json` のキー `analysis` は `written`（書いた値の指紋）だけを持つ
- [ ] 3. 書き出しの後、`.ndf/project.json` に言語ごとのファイル数・CI のワークフローごとの実行時間・テストの所要時間が無い
- [ ] 4. 解析の記録と計測値は `.ndf/measured/project.json` に書かれ、このファイルに `git check-ignore` が真を返す。書き出しが `.ndf/measured/` の下へ何かを書こうとするとき、次のどれかに当たれば、既存のファイルを変えずに終了コード 1 で止まり、理由を出す: 既にある `.ndf/measured/.gitignore` が記録のパスを無視しない・記録が git に追跡されている・`.ndf/measured/.gitignore` を作り直そうとしたが、そのパスか `.ndf/measured/` の下のほかのファイルが git に追跡されている。書くものが無い書き出しは確かめずに終了コード 0 で終わる（記録を書かないので、記録が差分に混ざることは無い）
- [ ] 5. 書き出しが書く、git で追跡するファイルは `.ndf/project.json` だけである（`.ndf/.gitignore`・根の `.gitignore` を書かない）
- [ ] 6. 根の `.gitignore` に `!.ndf/measured/` のような否定のパターン（無視を打ち消す行）があっても、`.ndf/measured/project.json` は git から外れたままになる
- [ ] 7. `ndf project check` は `.ndf/measured/project.json` の解析の記録で、設定が古くなっていないかを確かめる。入力のファイルかブランチの構成が変わったら「古い」、変わらなければ「新しい」と、今と同じ判定を返す
- [ ] 8. `.ndf/measured/project.json` が無い・読めないとき、`ndf project check` は「古い」と判定し（終了コード 3）、理由に解析の記録が無いことを示す。作業を止める「壊れている」（終了コード 2）にはしない
- [ ] 9. 新しく clone した場所（`.ndf/measured/` が無い）で書き出しを打つと、人が直した値は書き換えず、前の書き出しが書いた値は新しい解析の値へ置き換える。どの項目を人が直した値とみなし、どの項目を置き換えるかは、変更の前の実装で同じリポジトリを clone して書き出しを打った場合と同じになる（比べるのは設定の値だけで、解析の記録と計測値は比べない）
- [ ] 10. 既存の `.ndf/project.json` に解析の記録・計測値・テストの所要時間が残っていると、`ndf project check` は「古い」（終了コード 3）を返し、「壊れている」にしない
- [ ] 11. 10 の状態から書き出しを打つと、それらの値が `.ndf/project.json` から消え、解析の記録と計測値は `.ndf/measured/project.json` へ書かれる
- [ ] 12. 11 の書き出しで、解析が書いたか人が直したかの見分けは、計測値を取り除く前の値と前の指紋で行う。解析が書いた項目は解析が書いた項目のまま、人が直した項目は人が直した項目のまま残る
- [ ] 13. 新しい解析で実行時間を測れなかったワークフローは、前の実行時間を残す（今の「前の値を残す」決まりを、新しい置き場の中で保つ）。前の実行時間は `.ndf/measured/project.json` から取り、そこに無ければ移行前の `.ndf/project.json` に残る数値から取る。移行前の値が `null`（未計測）なら引き継がない。CI の測定そのものが不明（GitHub の API の障害・時間切れ）だったときは、前の実行時間をすべて残す

- [ ] 15. 書き出しが設定か解析の記録を書く途中で失敗すると、次の `ndf project check` は、前の記録の入力が今と同じでも「古い」（終了コード 3）を返す
- [ ] 16. 書き出しの結果の表示では、`.ndf/project.json` の変更は今と同じく差分で示し、`.ndf/measured/` の下のファイルはファイル名と件数の要約だけを示す

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わる。`.ndf/project.json` の形（`analysis` の中身・`languages[]`・`ci.workflows[]`・`test_duration`）と、置き場の一覧の `project-measured` の置き場が変わる。`ci.workflows[].jobs` は、ワークフローの定義から数えたジョブ数だけを表すようになる。`互換なし`（旧い形を読む仕組みを持たず、前のバージョンの NDF は新しい形を「壊れている」と判定する） |

## 用語

| 用語 | 意味 |
| --- | --- |
| 解析の記録 | 解析が書く、解析をいつどの入力で行ったかの値（解析器のバージョン・解析した時刻・入力のファイルのハッシュ・ブランチの構成）。git で追跡しないファイルに置く |
| 計測値 | 解析が測る、実行ごとに変わる数（言語ごとのファイル数・CI のワークフローごとの実行時間・直近の実行のジョブ数）。解析の記録と同じファイルに置く |
| 書いた値の指紋 | 解析が書いた設定の値の SHA-256。今の値の指紋と一致すれば解析が書いた値、違えば人が直した値として扱う。設定の値が変わったときだけ変わるため、設定と一緒に追跡する |

## ドメインイベント

NDF が自動で行う順序は「古いかを確かめる → 測る → 書き出す」である。書き出しが途中で止まったときは、次の作業で必ず解析をやり直す。そのために、書き出しは設定を書く前に、解析の記録へ「書き出しの途中」の印を付ける。印は最後に記録を書き終えたときに消える。

| # | イベント | 引き金 | 失敗したとき | 順序の前提 |
| --- | --- | --- | --- | --- |
| E1 | 設定が古くなっていないかを確かめた | 開発の作業の始めの `ndf project check` | 解析の記録が無い・読めない・途中の印が付いているなら「古い」とする（受け入れ条件 8・15） | — |
| E2 | リポジトリと CI を測った | E1 が「古い」 | 測れない項目は不明として続ける（今と同じ） | E1 |
| E3 | `.ndf/measured/` を git から外す `.gitignore` を置き、記録のパスが git に無視されることを確かめた | E2 の後の書き出しで、`.ndf/measured/` の下へ何かを書くとき（書くものが無ければ E3 以降は起きない） | 書けない、記録のパスが無視されない（ほかの除外設定が効いている・記録が追跡されている）、または `.gitignore` を作り直そうとしたが `.ndf/measured/` の下が追跡されているなら、終了コード 1 で止まる。設定と記録は書かない | E2 |
| E4 | 前の記録に途中の印を付け、設定を書き出した | E3 の後 | 書けなければ終了コード 1 で止まる（今と同じ）。記録に途中の印が残るか、記録が無いので、次の E1 が「古い」とする（受け入れ条件 15）。印を付ける前に止まったときは、設定も記録も前のまま揃っている | E3 |
| E5 | 解析の記録と計測値を書き出し、途中の印を消した | E4 の後 | 書けなければ終了コード 1 で止まる。途中の印が残るので、次の E1 が「古い」とする（受け入れ条件 15） | E4 |
