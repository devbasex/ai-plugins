## 何が起きたか

2026-11-25、利用者が `/work/ai-plugins` で `git pull` を打つと、手元の `.ndf/project.json` に未コミットの変更があるため止まった。`.ndf/project.json` は、NDF がリポジトリの形（言語・テスト・CI など）を書いておく設定のファイルである。git で追跡し、チームで共有する。

止めた差分は 84 行あった。中身は次の 2 つだけで、設定の値は何も変わっていなかった。

- 言語ごとのファイル数の更新（Python のファイル数 885 → 1064）
- 解析した時刻・入力のファイルのハッシュ・ブランチの構成の書き直し

NDF は、開発の作業を始めるたびに設定が古くなっていないかを確かめ、古ければリポジトリを調べ直して（解析して）設定へ書き出す（`ndf project write`）。そのたびに、こうした実行ごとに変わる値も、git で追跡するファイルへ書かれる。

2026-11-25 の設計承認ゲートで、利用者は、どの仕組みも使っていない計測値について「使われない情報を取得・保存する必要はないです」と指摘した（https://github.com/devbasex/ai-plugins/pull/4518#issuecomment-7162632854 ）。

## 種類

機能追加（`.ndf/project.json` の形と、解析が測るものを変える。NDF が書くファイルの置き場の一覧の行も書き換える）

## 今の姿

- 解析の書き出し（`ndf project write`。[`write.py`](https://github.com/devbasex/ai-plugins/blob/main/plugins/ndf/src/ndf/domains/project/write.py)）は、測った値と回答を `.ndf/project.json` へ書く。同じファイルのキー `analysis` に、次の 2 種類の値も毎回書く
  - 解析の記録: 解析器のバージョン・解析した時刻・入力のファイルのハッシュ・ブランチの構成。設定が古くなっていないかを確かめる仕組み（`ndf project check`）が、解析器のバージョン・入力のファイルのハッシュ・ブランチの構成を今のリポジトリと比べる。解析した時刻は、どの仕組みも読まない。入力のファイルは、解析が読むファイル（CI のワークフローの定義・`pyproject.toml` などの依存とテストの設定・`AGENTS.md` などの指示書）である。ブランチの構成は、リモートの既定ブランチと、`main`・`develop` などの決まった名前のブランチがリモートにあるかである
  - 書いた値の指紋（`analysis.written`）: 解析が書いた設定の値のハッシュで、項目（`languages`・`ci` など）ごとに 1 つある。書き出しはこれで、人が手で直した値か解析が書いた値かを見分け、人が直した値を書き換えない（[project-analysis.md の「書き出しの規則」](https://github.com/devbasex/ai-plugins/blob/main/plugins/ndf/skills/development-workflow/references/project-analysis.md#書き出しの規則)）
- 設定の項目の `languages` と `ci` の中に、実行ごとに変わる計測値と、どの仕組みも読まない値が入っている。比べるために、読む仕組みのある `required_checks` も下の表に並べる（`plugins/ndf/src`・`plugins/ndf/skills`・`scripts`・`experimental` を `grep` で確かめた）

  | 値 | キー | 読む仕組み |
  | --- | --- | --- |
  | 言語ごとのファイル数 | `languages[].files` | 無い |
  | CI のワークフローごとの直近の実行時間 | `ci.workflows[].wall_seconds` | 無い |
  | CI のワークフローごとのジョブ数（定義から数えた数と直近の実行のジョブ数の大きい方） | `ci.workflows[].jobs` | 無い |
  | CI のワークフローの一覧と CI の種類 | `ci.workflows[].path`・`ci.provider` | 無い |
  | 必須のチェックの名前 | `ci.required_checks` | ある（リファクタリングの工程の最後に CI の結果を待つ処理と、マージの後片付けの手順が、待つチェックの名前として読む） |

- 解析は、ワークフローの実行時間とジョブ数のために、GitHub の API で直近の成功の実行の一覧・実行ごとのジョブ・テストの結果のファイル（成果物）を取りに行く
- テストの所要時間（`test_duration`）は、設定のスキーマで非推奨になっていて、書き出しはもう書かない。ただし解析は今も、CI の実行と NDF の実行の記録からテストの所要時間を測っている。古い書き出しが書いた値が、このリポジトリの `.ndf/project.json` に残っている
- NDF が書くファイルの置き場の一覧（[`ndf-files.json`](https://github.com/devbasex/ai-plugins/blob/main/plugins/ndf/contracts/domains/ndf-files.json)）は、「実行で変わる計測値は追跡する設定へ書き戻さず、状態の保存先へ書く」と定めている。状態の保存先は、リポジトリの外にある、NDF が状態を置くディレクトリ（既定は `~/.local/state/ndf/`）である。一覧にはその置き場の行（`project-measured`）もあるが、そこへ書くコードはまだ無い

## 何を足すか・変えるか

| | 今 | 足した後 |
| --- | --- | --- |
| `.ndf/project.json` に載るもの | 設定の値・書いた値の指紋・解析の記録・計測値 | 設定の値と書いた値の指紋（`analysis.written`）だけ。どちらも設定の値が変わったときだけ変わる |
| 計測値（ファイル数・実行時間・ジョブ数）とテストの所要時間 | 測って `.ndf/project.json` に書く | 測らず、どこにも書かない |
| CI の項目（`ci`） | ワークフローの一覧・CI の種類・必須のチェック | 必須のチェック（`required_checks`）だけ |
| 解析が呼ぶ GitHub の API | 実行の一覧・実行ごとのジョブ・成果物・必須のチェック・閉じた PR・課題 | 必須のチェック・閉じた PR・課題だけ |
| 解析の記録の置き場と中身 | `.ndf/project.json` の中。解析した時刻を含む | `.ndf/analysis/project.json`。git で追跡しない。読む仕組みのある値（解析器のバージョン・入力のファイルのハッシュ・ブランチの構成）だけ |
| 置き場を git から外す方法 | 無い | 書き出しが `.ndf/analysis/` に中身 `*` の `.gitignore` を置き、そのディレクトリ全体（この `.gitignore` 自身を含む）を git から外す。`.ndf/.gitignore` とリポジトリの根の `.gitignore` は変えない |
| 置き場の一覧 | 計測値の置き場はリポジトリの外 | 計測値の行を消し、解析の記録の置き場を `.ndf/analysis/` にする |
| 解析をやり直したときの、追跡するファイルの差分 | 時刻・ハッシュ・ファイル数が変わるだけで出る | 設定の値が変わったときだけ出る |

## 今の利用者への影響と互換

- 既存の `.ndf/project.json` に残る値は、次の書き出しで `.ndf/project.json` から無くなる。解析の記録は `.ndf/analysis/project.json` へ移り、計測値・テストの所要時間・ワークフローの一覧・CI の種類は捨てる。次の書き出しは、NDF を新しいバージョンへ上げた後、最初に開発の作業を始めたときに NDF が自動で打つ。利用者は、そのときに出る `.ndf/project.json` の差分を 1 回コミットする
- 新しく clone した場所には `.ndf/analysis/` が無い。そのため、最初に開発の作業を始めたとき、NDF が自動で解析を 1 回やり直す。利用者の操作は要らない。解析は既定で 120 秒のタイムアウトで打ち切るので、それより長くはかからない。測るものが減るので、1 回の解析は今より短くなる
- チームで新しい形式の `.ndf/project.json` を共有する前に、開発に使う NDF を新しいバージョンへ更新する。古い NDF は新しい形式の設定を受け付けない（普及のフェーズまで後方互換を求めない、というリポジトリの方針）。新しい形式がコミットされた後に古い NDF を使うメンバーは、開発の作業を始めた時点で「設定が壊れている」と判定されて止まり、NDF を更新すれば直る
- NDF 自身のリポジトリ（このリポジトリ）では、設定の形の検査（`ndf check`）が追跡している `.ndf/project.json` を新しいスキーマで確かめる。そのため、実装の Pull Request は、スキーマの変更と同じコミットで、追跡している `.ndf/project.json` を新しい形式へ移す（[設計書](./issue-4516-design.md) の決定 4）

## なぜ困るか

- 設定を変えていないのに追跡するファイルに差分が出て、`git pull`・ブランチの切り替え・worktree（作業用に分けたディレクトリ）の後片付けが止まる
- 差分をコミットすると、設定の変更に、意味の無い時刻やファイル数の変更が混ざる。`.ndf/` の変更は、取り込む前に人が確かめるものであり（NDF の共通原則の C7）、確かめる量が増える
- どの仕組みも使わない値のために、解析が GitHub の API を何度も呼び、テストの結果のファイルまで取りに行く。解析の時間と API の利用枠を使う

## 目的

- `.ndf/project.json` を、push してよい設定の値だけを持つファイルにする
- 解析をやり直しても、追跡するファイルに差分が出るのは設定の値が変わったときだけにする
- どの仕組みも使わない値は、測るのも保存するのもやめる

## 対象範囲

含む:
- 計測値（`languages[].files`・`ci.workflows[].wall_seconds`・実行から数えたジョブ数）・テストの所要時間・ワークフローの一覧（`ci.workflows`）・CI の種類（`ci.provider`）を、測るのも書くのもやめること。取得のためだけにある処理（GitHub の API の呼び出し・NDF の実行の記録の読み取り・前の実行時間の引き継ぎ。新しい解析で実行時間を測れなかったワークフローに前の値を残す処理）を消すこと
- 解析の記録のうち、読む仕組みのある値だけを `.ndf/analysis/project.json` へ書くこと。解析した時刻は書かない
- `.ndf/analysis/` を git から外すこと
- 設定が古くなっていないかの確かめと、人が直した値を書き換えない決まりを、新しい置き場の上で今までどおり働かせること
- 既存の `.ndf/project.json` に残る、上の値と解析の記録を、次の書き出しで取り除くこと
- 設定の形の定義（スキーマ）・置き場の一覧・`project-analysis.md`・設定とファイルの説明の文書（`ndf-settings.md`・`files.md`）・確定仕様を、新しい形に合わせること

含まない:
- 解析が書くほかの項目（`languages` の `name`・`frameworks`・`version`、`services`・`checks` など）について、その値を読むプログラムや手順があるかを調べ、無ければ測るのをやめること。課題 #4521（解析が書く項目を、読み手のあるものだけにする）で扱う
- ブランチ戦略の設定（`branch_strategy`）を書くコマンド（`ndf project branch-strategy`）の変更
- このリポジトリの `.ndf/project.json` にある利用者の未コミットの変更を、この課題の中で扱うこと。実装のリリースの後、利用者が書き出しをやり直せば片付く

## 前提

- 前提 1: `.ndf/analysis/` は、設定と同じく clone したディレクトリ（メインディレクトリ）の `.ndf/` の下に置く。作業用に分けたディレクトリ（worktree）から書き出しても、メインディレクトリへ書く（今の `.ndf/project.json` と同じ）
- 前提 2: `.ndf/analysis/project.json` は人が書かない。壊れていても、書き出しが作り直してよい

## 受け入れ条件

- [ ] 1. 設定の値が変わらない入力で `ndf project write` を 2 回続けて打つと、2 回目は `.ndf/project.json` を変えない。間に入力のファイルのハッシュが変わっても同じである
- [ ] 2. 書き出しの後、`.ndf/project.json` のキー `analysis` は `written`（書いた値の指紋）だけを持つ
- [ ] 3. 書き出しの後、`.ndf/project.json` に `languages[].files`・`ci.workflows`・`ci.provider`・`test_duration` が無い。`ci` は `required_checks` だけを持つ
- [ ] 4. `ndf project measure` の結果に、ファイル数・ワークフローの一覧・実行時間・ジョブ数・テストの所要時間が無い。測定の間に GitHub の API を呼ぶのは、必須のチェック（`rules/branches`）・閉じた PR（`pulls`）・課題（`issues`）の 3 か所だけで、実行の一覧・ジョブ・成果物（`actions/...`）を呼ばない
- [ ] 5. 解析の記録は `.ndf/analysis/project.json` に書かれ、このファイルに `git check-ignore` が真を返す
- [ ] 5a. 記録が持つキーは、読む仕組みのあるもの（`version`・`analyzer`・`inputs`・`branches`、記録に対応する設定の指紋 `written_digest`、書き出しの途中の印 `pending`）だけで、解析した時刻を持たない
- [ ] 5b. 書き出しが `.ndf/analysis/` の下へ何かを書こうとするとき、次のどれかに当たれば、既存のファイルを変えずに終了コード 1 で止まり、理由を出す: 記録のパスが git に無視されない・記録が git に追跡されている・`.ndf/analysis/.gitignore` を作り直そうとしたが、そのパスか `.ndf/analysis/` の下のほかのファイルが git に追跡されている・git が追跡と無視を確かめられない（索引を読めないなど）。無視されるかどうかは、`.ndf/analysis/.gitignore`・根の `.gitignore`・`.git/info/exclude`・利用者の除外の設定（`core.excludesFile`）を合わせた git の判定で決め、どの設定で無視されるかは問わない。書くものが無い書き出しは確かめずに終了コード 0 で終わる（記録を書かないので、記録が差分に混ざることは無い）
- [ ] 6. 書き出しが書く、git で追跡するファイルは `.ndf/project.json` だけである（`.ndf/.gitignore`・根の `.gitignore` を書かない）
- [ ] 7. 根の `.gitignore` に `!.ndf/analysis/` のような否定のパターン（無視を打ち消す行）があっても、`.ndf/analysis/project.json` は git から外れたままになる
- [ ] 8. `ndf project check` は `.ndf/analysis/project.json` の解析の記録で、設定が古くなっていないかを確かめる。解析器のバージョン・入力のファイル・ブランチの構成のどれかが変わったら「古い」、変わらなければ「新しい」と、今と同じ判定を返す。書き出しの後に利用者が `.ndf/project.json` を以前の状態へ戻し（`git restore` など）、解析が書いた値の指紋（`analysis.written`）から計算したハッシュが記録の `written_digest` と一致しなくなったときは、ほかの判定の条件が変わっていなくても「古い」を返す。人が手で直した値だけを戻したときなど、`analysis.written` が変わらないときは「古い」にしない（設定のファイル全体のハッシュでは比べない）
- [ ] 9. `.ndf/analysis/project.json` が無い・読めないとき、`ndf project check` は「古い」と判定し（終了コード 3）、理由に解析の記録が無いことを示す。作業を止める「壊れている」（終了コード 2）にはしない
- [ ] 10. 新しく clone した場所（`.ndf/analysis/` が無い）で書き出しを打つと、人が直した値は書き換えず、前の書き出しが書いた値は新しい解析の値へ置き換える。どの項目を人が直した値とみなし、どの項目を置き換えるかは、変更の前の実装で同じリポジトリを clone して書き出しを打った場合と同じになる（比べるのは設定の値だけで、解析の記録と取り除いた値は比べない）
- [ ] 11. 既存の `.ndf/project.json` に解析の記録・計測値・テストの所要時間・ワークフローの一覧・CI の種類が残っていると、`ndf project check` は「古い」（終了コード 3）を返し、「壊れている」にしない
- [ ] 12. 11 の状態から書き出しを打つと、それらの値が `.ndf/project.json` から消え、解析の記録（解析した時刻を除く）は `.ndf/analysis/project.json` へ書かれる
- [ ] 13. 12 の書き出しで、解析が書いたか人が直したかの見分けは、値を取り除く前の値と前の指紋で行う。解析が書いた項目は解析が書いた項目のまま、人が直した項目は人が直した項目のまま残る
- [ ] 14. スキーマ・置き場の一覧・`project-analysis.md`・`ndf-settings.md`・`files.md` が新しい置き場と形を書き、追跡している `.ndf/project.json` も新しい形式になっている。消した振る舞いだけを書いた確定仕様（`docs/specifications/project-decl-ci-representative-run.md`）は消し、索引の行も消す。新しくチェックアウトした場所（CI）で `ndf check` と `python3 scripts/check-skill-frontmatter.py` が通る
- [ ] 15. 書き出しが「書き出しの途中」の印を付けた後、設定か新しい解析の記録を書く途中で失敗すると、次の `ndf project check` は、前の記録の入力が今と同じでも「古い」（終了コード 3）を返す
- [ ] 16. 書き出しの結果の表示では、`.ndf/project.json` の変更は今と同じく差分で示し、`.ndf/analysis/` の下のファイルはファイル名と件数の要約だけを示す
- [ ] 17. 複数の worktree から同時に書き出しても、`.ndf/project.json` と `.ndf/analysis/project.json` は同じ 1 回の書き出しが書いた組み合わせになる。後から始めた書き出しは、先の書き出しが記録を書き終えるまで設定と記録を読まずに待ち、待ちの上限を超えたら何も書かずに終了コード 1 で止まる

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わる。`.ndf/project.json` の形（`analysis` の中身・`languages[]`・`ci`・`test_duration`）と、`ndf project measure` の結果の形（`ci`・`test_duration`）と、置き場の一覧の行が変わる。`互換なし`（旧い形を読む仕組みを持たず、前のバージョンの NDF は新しい形を「壊れている」と判定する） |
| データ | `.ndf/project.json` から値を取り除き、解析の記録だけを `.ndf/analysis/project.json` へ移す。移すのは次の書き出しで、別の移行のコマンドは持たない |
| 既存の振る舞い | 解析が GitHub の API を呼ぶ回数が減る。新しく clone した場所の最初の作業で、解析が自動で 1 回走る（今は、追跡している設定が新しければ走らない。費用の比べは [設計書](./issue-4516-design.md) の決定 5）。解析をやり直しても、追跡するファイルに差分が出なくなる |

## 用語

| 用語 | 意味 |
| --- | --- |
| 解析の記録 | 解析が書く、解析をどの入力で行ったかの値（解析器のバージョン・入力のファイルのハッシュ・ブランチの構成）と、その解析が書いた設定の指紋。設定が古くなっていないかの判定が読む。git で追跡しないファイルに置く |
| 書いた値の指紋 | 解析が書いた設定の値の SHA-256。今の値の指紋と一致すれば解析が書いた値、違えば人が直した値として扱う。設定の値が変わったときだけ変わるため、設定と一緒に追跡する |

## ドメインイベント

NDF が自動で行う順序は「古いかを確かめる → 測る → 書き出す」である。書き出しが途中の印を付けた後に止まったときは、次の作業で必ず解析をやり直す。そのために、書き出しは設定を書く前に、解析の記録へ「書き出しの途中」の印を付ける。印は最後に記録を書き終えたときに消える。

| # | イベント | 引き金 | 失敗したとき | 順序の前提 |
| --- | --- | --- | --- | --- |
| E1 | 設定が古くなっていないかを確かめた | 開発の作業の始めの `ndf project check` | 解析の記録が無い・読めない・途中の印があるなら「古い」とする（受け入れ条件 9・15） | — |
