## 何が起きたか

2026-11-25、利用者が `/work/ai-plugins` で `git pull` を打つと、手元の `.ndf/project.json` に未コミットの変更があるため止まった。`.ndf/project.json` は NDF がリポジトリの形（言語・テスト・CI など）を書いておく設定のファイルで、git が追跡し、チームで共有する。

止めた差分は 84 行あった。中身は 2 つだけで、設定の値は何も変わっていなかった。

- 言語ごとのファイル数の更新（Python のファイル数 885 → 1064）
- 解析の記録（解析した時刻・入力のファイルの指紋・ブランチの構成）の書き直しNDF が工程の始めに設定の解析（`ndf project write`）を打ち直すたびに、こうした値が追跡するファイルへ書かれる。

## 種類

機能追加（追跡する設定のファイルから、実行で変わる値を追跡しないファイルへ移す。NDF のファイルの表は計測値を状態の保存先へ書くと定めているが、解析の記録は設定の一部として定めており、置き場と形の約束を変える）

## 今の姿

- 解析の書き出し（`ndf project write`。[`write.py`](https://github.com/devbasex/ai-plugins/blob/main/plugins/ndf/src/ndf/domains/project/write.py)）は、測った値と回答を `.ndf/project.json` へ書く。同じファイルに、解析の記録（キー `analysis`）も毎回書く
- 解析の記録の読み手は 2 つある。設定が新しいかの判定（`ndf project check`。入力の指紋とブランチの構成を比べる）と、書き出し自身（キー `analysis.written` の指紋で、人が書いた値か解析が書いた値かを見分け、人が書いた値を書き換えない）。決まりは [project-analysis.md の「書き出しの規則」](https://github.com/devbasex/ai-plugins/blob/main/plugins/ndf/skills/development-workflow/references/project-analysis.md#書き出しの規則) にある
- 実行で変わる計測値が設定の項目の中に入っている。言語ごとのファイル数（`languages[].files`）と、CI のワークフローごとの直近の実行時間（`ci.workflows[].wall_seconds`）である。どちらも、書き出しの外に読み手は無い（`plugins/ndf/src`・`scripts`・`experimental` を `grep` で確かめた）
- テストの所要（`test_duration`）は、スキーマで非推奨になっており、書き出しはもう書かない。古い書き出しが書いた値が、このリポジトリの `.ndf/project.json` に残っている
- NDF のファイルの表（[`ndf-files.json`](https://github.com/devbasex/ai-plugins/blob/main/plugins/ndf/contracts/domains/ndf-files.json)）は「実行で変わる計測値は追跡する設定へ書き戻さず、状態の保存先へ書く」と定める。置き場として、追跡しない行 `project-measured`（状態の保存先の `measured/<リポジトリ>/project.json`）も持つ。しかし、そこへ書く実装は無い

## 何を足すか・変えるか

| | 今 | 足した後 |
| --- | --- | --- |
| `.ndf/project.json` に載るもの | 設定の値と、解析の記録・計測値 | 設定の値と、どの値を解析が書いたかの指紋だけ。どれも設定の値が変わったときだけ変わる |
| 解析の記録・計測値の置き場 | `.ndf/project.json` の中 | `.ndf/` の下の、git が追跡しない別のファイル |
| 解析を打ち直したときの追跡するファイルの差分 | 時刻・指紋・ファイル数が変わるだけで出る | 設定の値が変わったときだけ出る |
| 別のファイルを git から外す登録 | 無い | 書き出しが、別のファイルを置くディレクトリにそのディレクトリを外す `.gitignore` を置く。追跡するファイル（`.ndf/.gitignore`・根の `.gitignore`）は変えない |

## 今の利用者への影響と互換

- 既存の `.ndf/project.json` にある解析の記録と計測値は、次の書き出しで別のファイルへ移り、`.ndf/project.json` から消える。利用者はその差分を 1 回コミットする
- 新しく clone した場所には別のファイルが無いため、最初の工程で解析を 1 回打ち直す（今は、コミットされた解析の記録があれば打ち直さない）
- 旧い形を読む互換の仕組みは持たない（普及のフェーズまで後方互換を求めない、というリポジトリの方針）

## なぜ困るか

- 設定を変えていないのに追跡するファイルに差分が出て、`git pull`・ブランチの切り替え・worktree の後片付けが止まる
- 差分をコミットすると、設定の変更を見る Pull Request に、意味の無い時刻や件数の変更が混ざる。設定は承認ゲートで人が見るもの（共通原則の C7）で、見る量が増える
- 計測値が変わるたびに、計測値を含む項目の指紋も変わる。人が書いた値か解析が書いた値かの見分けが、計測値の揺れに引きずられる

## 目的

- `.ndf/project.json` を、push してよい設定の値だけを持つファイルにする
- 解析の打ち直しで追跡するファイルに差分が出るのは、設定の値が変わったときだけにする

## 対象範囲

含む:
- 解析の記録（解析器のバージョン・解析した時刻・入力のファイルの指紋・ブランチの構成）と計測値（言語ごとのファイル数・CI のワークフローごとの実行時間）を、追跡しない別のファイルへ書くこと
- 別のファイルを `.gitignore` に当てること
- 設定が新しいかの判定と、人が書いた値を書き換えない決まりを、新しい置き場の上で今までどおり働かせること
- 既存の `.ndf/project.json` に残る解析の記録・計測値・非推奨のテストの所要を、次の書き出しで取り除くこと
- スキーマ・NDF のファイルの表・`project-analysis.md`・設定の契約文書（`ndf-settings.md`）・ファイルの契約文書（`files.md`）を新しい置き場と形に合わせること

含まない:
- 計測値を読む新しい仕組み（計測値を使って何かを決めること）
- ブランチ戦略の設定（`branch_strategy`）を書く `ndf project branch-strategy` の変更
- このリポジトリの `.ndf/project.json` にある利用者の未コミットの変更を、この課題の中で扱うこと（実装のリリースの後、利用者が書き出しを打ち直して片付く）

## 前提

- 前提 1: 別のファイルは、設定と同じメインディレクトリの `.ndf/` に置く。worktree からの書き出しもメインディレクトリへ書く（今の `.ndf/project.json` と同じ）
- 前提 2: 別のファイルは人が書かない。壊れていても、書き出しが作り直してよい

## 受け入れ条件

- [ ] 1. 設定の値が変わらない入力で `ndf project write` を 2 回続けて打つと、2 回目は `.ndf/project.json` を変えない。間に解析した時刻・入力のファイルの指紋・ファイル数・CI の実行時間が変わっても同じである
- [ ] 2. 書き出しの後、`.ndf/project.json` に解析の記録（解析器のバージョン・時刻・入力の指紋・ブランチの構成）・言語ごとのファイル数・CI のワークフローごとの実行時間・テストの所要が無い
- [ ] 3. 2 の値は `.ndf/` の下の別のファイルに書かれ、そのファイルに `git check-ignore` が真を返す
- [ ] 4. 書き出しが書く、git が追跡するファイルは `.ndf/project.json` だけである（`.ndf/.gitignore`・根の `.gitignore` を書かない）。別のファイルを git から外す登録は、書き出しが別のファイルと同じディレクトリに置く。根の `.gitignore` に `!.ndf/` のような外さない行があっても、別のファイルは外れたままになる
- [ ] 5. `ndf project check` は別のファイルの解析の記録で設定の新しさを判定する。入力のファイルかブランチの構成が変わったら「古い」、変わらなければ「新しい」と、今と同じ判定を返す
- [ ] 6. 別のファイルが無い・読めないとき、`ndf project check` は「古い」と判定し（終了コード 3）、理由に解析の記録が無いことを示す。「壊れている」（終了コード 2）にはしない
- [ ] 7. 新しく clone した場所（別のファイルが無い）で書き出しを打っても、人が書いた値は書き換えず、前の書き出しが書いた値は新しい解析の値へ置き換える。今の clone した場所と同じ結果になる
- [ ] 8. 既存の `.ndf/project.json` に解析の記録・計測値・テストの所要が残っていると、`ndf project check` は「古い」（終了コード 3）を返し、「壊れている」にしない。続く書き出しでそれらが `.ndf/project.json` から消え、解析の記録と計測値は別のファイルへ移る。そのとき、移す前の値で解析が書いたと見分けられた項目は、移した後も解析が書いた項目として扱う
- [ ] 9. 新しい解析で実行時間を測れなかったワークフローは、別のファイルにある前の実行時間を残す（今の「前の値を残す」決まりを、別のファイルの中で保つ）
- [ ] 10. スキーマ・NDF のファイルの表・`project-analysis.md`・`ndf-settings.md`・`files.md` が新しい置き場と形を書き、`ndf check` と `python3 scripts/check-skill-frontmatter.py` が通る

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わる。`.ndf/project.json` の形（キー `analysis` の中身・`languages[]`・`ci.workflows[]`・`test_duration`）と、NDF のファイルの表の行 `project-measured` の置き場が変わる。`互換なし`（旧い形を読む仕組みを持たない） |

| 既存の振る舞い | 新しく clone した場所の最初の工程で、解析が 1 回走る。解析の打ち直しで追跡するファイルに差分が出なくなる |

## 用語

| 用語 | 意味 |
| --- | --- |
| 解析の記録 | 解析が書く、実行や時刻で変わる値（解析器のバージョン・解析した時刻・入力のファイルの指紋・ブランチの構成・言語ごとのファイル数・CI の実行時間）。git で追跡しないファイルに置く |
| 書いた値の指紋 | 解析が書いた設定の値の SHA-256。今の値の指紋と一致すれば解析が書いた値、違えば人が書いた値として扱う |
