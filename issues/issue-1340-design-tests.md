# #1340 の設計: テスト設計

本体は [issue-1340-design.md](issue-1340-design.md) にある。テストは `plugins/ndf/skills/cross-review/tests/` と
`plugins/ndf/scripts/tests/` に置く。`.md` の文言を照合するテストは書かない。

## 受け入れ条件

| 受け入れ条件・不変条件 | どの振る舞いで縛るか | どう壊したら落ちるべきか |
| --- | --- | --- |
| AC1 `final=approved` に 1 コミット足して手順どおり打つ | `init` の後の `start-round` が `ROUND=<前の最後 + 1>` を出し、前の `rounds` の要素が同じ値で残る | `init` が確定した状態を上書きする（今の振る舞い）・`rounds` を詰め直す |
| AC2 `error` / `oscillation` / `max_rounds` から足す | 値ごとに AC1 と同じ結果になる（3 件） | `reopen` が特定の値だけを受ける・後始末の確認が足す前のラウンドに当たる（`oscillation` と `max_rounds` で終了コード 5） |
| AC3 `drive.py` を通して打つ | 完了の記録の `head` と今の head が違えば、前回の結果を返さず `init` を打つ | `finished` が head を比べない・`finish` が head を残さない |
| AC4 上限で終わった状態から足す | 足した時点から既定の数（または `--max-rounds`）だけラウンドが回り、その次で `max_rounds` になる | 上限を `len(rounds)` で数える |
| AC5 `final=null` で入口を打つ | 今の再開と同じ出力で、`reopens` が増えない | `final=null` でも足した記録を積む |
| AC6 状態ファイルが無い・壊れている | 無ければ新規の経路。壊れていればパスと理由を出して終了コード 1、ファイルは変わらない | 壊れたファイルを新しい状態で上書きする・例外のまま落ちる |
| AC7 `final=approved` で `check-oscillation` | `final` が `approved` のまま、終了コード 2、`振動検知 —` の行が無い | `final` を見ずに判定する |
| AC8 収束したラウンドの 1 回の出力 | `drive.py` の出力と、副命令を `SKILL.md` の順に打った出力に、`収束` と `振動検知 — … 中断` が並ばない | 上と同じ |
| AC9 ホストが自分で直して `record-fix` → `start-round` | 戻り値ファイルが契約の形で書かれ、`start-round` が終了コード 5 で止まらない | `record-fix` が `merge-fix` と違う形で記録する・戻り値ファイルを書かない |
| AC10 コミットが送り先に無い・スレッドが未解決 | どちらも記録を作らず終了コード 5。一覧を取れないときも 5 | 確かめずに記録する・取れないときに通す |
| AC11 打ち切りが起きた形で上限より短く終わる | `git` を遅くした擬似のリポジトリで、`hook.py`（Claude Code と Codex の起動の形）と `worktree-guard.sh` が 3.5 秒 + 起動の時間で終わる | 締め切りを掛けない・`git` の子のプロセスが残って待つ |
| AC12 締め切りを過ぎたとき | 終了コード 0、標準出力に拒否が無い、標準エラーに判定の名前を含む 1 行 | 例外で 0 以外になる・何も出さない |
| AC13 締め切りの中で終わるとき | 既存の hook のテスト（`test_token_guard*`・`test_hook_trial_*`・worktree の guard のテスト）が通る | 判定の順序や `_merge` の規則を変える |

## 不変条件

| 不変条件 | どの振る舞いで縛るか | どう壊したら落ちるべきか |
| --- | --- | --- |
| I1 履歴を消さない | AC1・AC2 | 上と同じ |
| I2 足した記録 | 足すたびに `reopens` が 1 件増え、`from_final`・`base_round`・`ended_at`・`at` を持つ。2 回足すと 2 件 | 記録を積まない・前の記録を置き換える |
| I3 境から数える | AC4 と、`should-rotate` が境より後のラウンドだけで巻き直しを決めること | 全ラウンドで数える |
| I4 足す前のラウンドに確認を当てない | AC2 の `oscillation` と `max_rounds`（足す前の `sweep` が検証済みで未解決 0 件）。`sweep` が無い・`verified: false`・`remaining_open > 0` のときは `base_round` のラウンドに確認を当てて止まる | 確認の対象を最後のラウンドに固定する・`final` の確定だけで免除する |
| I5 確定した `final` を守る | AC7 | 上と同じ |
| I6 振動検知の比べる範囲 | `oscillation` から足した最初のラウンドで、境の前のラウンドと同じ指摘があっても中断しない | 境の前のラウンドと比べる |
| I7 記録の前の確認 | AC10 | 上と同じ |
| I8 2 回取り込まない | `record-fix` の後に `merge-fix` を打つと記録した終了コードで戻り、`rounds[-1].fix` とまとめの投稿が増えない。投稿の失敗で止まった後の打ち直しは投稿から続け、コード関連の CI 失敗（3）で終えた取り込みの打ち直しは 3 を返す。`merge` が無い記録は投稿から続け、投稿済みの返信を重ねず、終了コードは CI の分類で決まる | コミットを比べずに取り込む・コミットの一致だけで 0 を返す |
| I9 壊れた状態ファイル | AC6 | 上と同じ |
| I10 前回の結果を返す条件 | head が同じなら前回の結果を返す。`--reopen` なら返さない。`head` の無い記録は返す | 比べられないときに新しく回す・`--reopen` を見ない |
| I11 締め切り | AC11・AC12 | 上と同じ |
| I12 判定を変えない | AC13 | 上と同じ |
| I13 締め切りと上限の対応 | `hooks/claude.json`・`hooks/codex.json`・`dev.agy/hooks.json`・`dev.kiro/install.sh` の該当する hook の上限が、すべて締め切り + 余裕以上 | どちらか片方の値を変える |
