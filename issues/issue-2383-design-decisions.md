# #2383 の設計: 決定の記録

設計の本体は [issue-2383-design.md](issue-2383-design.md) にある。番号（`STD1`・`LIB1` など）は本体の「外部の調査」の表を指す。

## 決定の記録

### 決定 1: 鍵と暗号文を同じ所に置けるよう、端末の控えの置き場を IndexedDB にし、包みに idb を使う

鍵（CryptoKey）を保存できるのは、直列化できる値を保存する仕組みだけである（STD1・STD2）。`localStorage` と `sessionStorage` は文字列だけを持ち、鍵を書き出さずに置けない。IndexedDB の要求を Promise にする部分は idb（LIB3）に任せ、自分で包みを書かない。idb は画面の依存に足す唯一の実行時のパッケージで、運用の費用は増えない。

dexie（LIB4）は問い合わせとスキーマの版の管理を持ち、3 つのストアの読み書きと消去には余る。idb-keyval（LIB5）は 1 つのストアだけを持ち、3 つのストアを 1 つのトランザクションで消せない。依存を足さずに IndexedDB を直に使う形は採らない。要求と事象の包みを自分で書くことになり、idb が持つものの複製になる。

- 作り方: ライブラリやサービスを使う・標準に倣う
- 比べた候補: LIB3 / LIB4 / LIB5 / STD2

根拠: Value 5 / スプリント Value 6（MVV 版 5・スプリント MVV 44cd096d）

### 決定 2: 応答の中身も ID も平文で残さないよう、中身を AES-GCM で暗号化し、レコードの名前を HMAC で作る

受け入れ条件 9 は、書いたバイト列に実行の ID とリポジトリ名が現れないことを求める。中身だけを暗号化しても、読み出しの指し方（実行の ID など）をレコードの名前に使うと平文で残る。名前は書き出せない HMAC の鍵で作り、指し方そのものは暗号文の中に持つ。暗号はブラウザの標準の Web Crypto の AES-GCM 256 で、書くたびに 12 バイトの初期化ベクトルを乱数で作る（STD1）。

暗号のライブラリは足さない。標準の API で鍵を書き出せない形にでき（受け入れ条件 10）、ライブラリの鍵は JavaScript の値として持つため書き出せてしまう。

- 作り方: 標準に倣う
- 比べた候補: STD1 / STD2

根拠: C1 / スプリント Value 3（MVV 版 5・スプリント MVV 44cd096d）

### 決定 3: token の無いタブでもオフラインで読めるよう、鍵を端末に置き、token から導かない

起票者の推定 S9 は、通知から開いた token の無いタブで、期限の前なら控えを読めることを求める。鍵を token から導くと、token の無いタブは控えを復号できない。鍵は控えの持ち主の記録に書き出せない形で置き、利用者の ID と期限を平文で添える（前提 4）。

この形では、端末で同じブラウザを開ける人は期限までは控えを読める（未確認のまま残ること 7）。暗号化が守るのは、保存のファイル・バックアップ・ほかのアプリからの読み取りである。期限を短く保つため、ログインの延長は作らない（要求の対象範囲）。

根拠: スプリント Value 3（MVV 版 5・スプリント MVV 44cd096d）

### 決定 4: 読み出しを 1 行で足せるよう、端末の控えを画面の API を包む層と登録の表で作る

前提 2 は、#2173 が読み出しの操作を 1 行の登録で控えに足せる形を求める。控えに入れる読み出しを表に並べ、画面の API（`Api`）を包む層が表に従ってネットワークと控えを切り替える。画面のコードは、読み出しが控えから来たかを意識せずに今の API を呼ぶ。表に無い読み出しは控えの保管を呼ばない（I6）。

Service Worker の実行時のキャッシュで API の応答を控える形は採らない。応答が平文のまま Cache Storage に残り、前提 8 に反する（STD3・LIB1）。

- 作り方: 自前で作る
- 比べた候補: STD3 / LIB1

根拠: Value 7 / スプリント Value 4（MVV 版 5・スプリント MVV 44cd096d）

### 決定 5: 送る前に今の状態と照らせるよう、確定待ちの操作は画面を開いている間に自前の列で確定し、Background Sync を使わない

workbox-background-sync（LIB2）は失敗した要求を積み、Service Worker の起動時に送り直す。送る前に対象の今の状態を読んで照らす段を持たず、画面を閉じている間にも送る。前提 6 は画面を開いている間だけ確定するとし、前提 7 は送る前に今の状態と照らすとする。列は IndexedDB に暗号化して置き、照合の規則は登録の表に操作ごとに 1 行で持つ。

- 作り方: 自前で作る
- 比べた候補: LIB2 / STD3

根拠: スプリント Value 3 / スプリント Value 4（MVV 版 5・スプリント MVV 44cd096d）

### 決定 6: 同じ操作を 2 度送らないよう、同期をタブの排他の鍵の中で行い、送る前に列から外す

同じ利用者が画面を 2 つのタブで開いていると、つながりが戻ったときに 2 つのタブが同じ確定待ちの操作を取り出す。同期は Web Locks API の名前つきの鍵の中で行い、1 つのタブだけが列を読む。送る前に列から外すため、送った要求の結果が分からないまま失敗しても送り直さない（I9）。送り直しよりも、利用者が結果を見て押し直す方を選ぶ。取り消せない操作は 2 度の確定の方が害が大きいためである。

Web Locks API の無いブラウザでは排他なしで同期する（未確認のまま残ること 6）。

根拠: スプリント Value 3（MVV 版 5・スプリント MVV 44cd096d）

### 決定 7: 画面を開き直せるよう、画面の資産を vite-plugin-pwa の generateSW で事前にキャッシュする

画面の資産（HTML・JavaScript・CSS・翻訳のファイル）は、ビルドの成果物の一覧を Service Worker が事前にキャッシュし、経路の遷移には `index.html` を返す。vite-plugin-pwa（LIB1）は vite 8 を peerDependencies に持ち、ビルドの成果物から Service Worker を生成する。開発時の依存だけに入り、運用の費用は増えない。API の応答の実行時のキャッシュは設定しない（決定 4）。新しい版の Service Worker の更新を知らせる画面は作らず、開いているタブをすべて閉じた後に効く既定の振る舞いのままにする。

Service Worker を手で書く形は採らない。ビルドの成果物のファイル名がハッシュつきで変わるため、一覧を作る処理を自分で持つことになる。

- 作り方: ライブラリやサービスを使う
- 比べた候補: LIB1 / STD3

根拠: Value 5 / スプリント Value 3 / スプリント Value 6（MVV 版 5・スプリント MVV 44cd096d）

### 決定 8: 画面のコードを読み出しの出所に依らせないよう、控えから出したことを読み直しの部品が受け取った時刻として受け取る

API の戻り値の型を「値と出所」の組へ変えると、画面のすべての読み出しの型が変わる。読み直しの部品（`usePolled`）は、読み出しを呼ぶ間だけ控えつきの API の出所を集め、控えから出たときの受け取った時刻を `receivedAt` として返す。画面は `receivedAt` があれば注記を出す。集めるのは読み出しを呼んだ直後の同期の部分だけなので、読み出しの関数は最初の `await` より前に API を呼ぶ（今の 5 画面の読み出しはこの形である）。

控えが変わった（取り直し・消去）ときは、控えから出した画面だけを読み直す。

根拠: Value 7（MVV 版 5）

### 決定 9: ループの画面も同じ注記と読み直しを持つよう、ループの一覧と詳細の読み出しを読み直しの部品へ移す

ループの一覧と詳細は、今は画面ごとの読み込みの関数で読む。読み直しの部品へ移し、間隔での読み直しはしない（`poll: false`。今と同じく、開いたときと操作の後だけ読む）。受け入れ条件 17 は読み直しの部品の間隔を変えないことを求め、この移し替えはループの画面の読む回数を変えない。

根拠: Value 7 / スプリント Value 1（MVV 版 5・スプリント MVV 44cd096d）

### 決定 10: 電波が届かないのにブラウザがオンラインと言う場面を拾うよう、要求のネットワークの失敗でもオフラインにし、次の成功で戻す

ブラウザの `navigator.onLine` は、端末がネットワークにつながっていればサーバーに届かなくても真である。要求が応答を受け取れずに失敗したら（`fetch` の `TypeError`）つながりをオフラインにし、次に要求が応答を受け取ったらオンラインに戻す。戻ったときを E6 とし、同期を始める。オフラインの間も読み直しの間隔で要求を試すため、戻ったことに気づける。

根拠: スプリント Value 3（MVV 版 5・スプリント MVV 44cd096d）

### 決定 11: サーバーに届いたかもしれない操作を 2 度送らないよう、確定待ちにするのはオフラインで押したときだけにする

オンラインで送った取り消せない操作がネットワークで失敗したとき、サーバーが受け取って処理したかは分からない。確定待ちにすると、処理済みの操作を照合の後にもう 1 度送ることがある。この場合は今と同じく失敗を画面に出し、利用者が画面を読み直して決める。

根拠: スプリント Value 3（MVV 版 5・スプリント MVV 44cd096d）

### 決定 12: token の無いタブで書く操作をさせないよう、token の無いタブで描くのはオフラインで有効な控えがあるときだけにする

ログインの枠は、token が無くても、オフラインで控えの持ち主が期限の前なら画面を描く。オンラインなら今と同じくログインへ移す。token の無いタブで押した取り消せない操作は確定待ちになるが、同期は token が要るため、ログインした後のタブで確定する。

根拠: C2 / スプリント Value 3（MVV 版 5・スプリント MVV 44cd096d）

### 決定 13: 通信を切って開き直す確かめ方が成り立つよう、オフラインの E2E はダミーのビルドを配って行う

vite-plugin-pwa は開発のサーバーではエントリポイントだけをキャッシュし、モジュールをキャッシュしない（LIB1 の出典）。今の E2E はダミーの開発のサーバーで動くため、通信を切って開き直すと画面の資産が読めない。オフラインの E2E は、ダミーのモードでビルドした成果物（`dist-dummy/`）を `vite preview` で配るプロジェクトで行う。本番のビルド（`dist/`）とその検査（`check:bundle`）は変えない。ダミーの API は通信が切れているとネットワークの失敗と同じ誤りを投げ、本物の控えとつながりを使う。

根拠: Value 1 / Value 4（MVV 版 5）

### 決定 14: 端末の控えをサーバーの最後の応答のコピーに留めるよう、控えた応答は最後の応答で上書きし、履歴を持たない

端末の控えは、画面が最後に受け取った応答をオフラインで読むためのものである。過去の状態はサーバーの事象の記録が持ち、端末で履歴を持つと、利用者の端末に残るデータが増えるだけになる。同じ読み出しの指し方の応答は同じレコードへ上書きし、取り直しの応答に無い要素は消す（前提 9）。

根拠: スプリント Value 3 / スプリント Value 6（MVV 版 5・スプリント MVV 44cd096d）
