## 目的

- 中継のラッパー（`ndf relay run`）が子の claude を起動できないとき、Python のトレースバックではなく、理由の 1 行と停止理由の終了コードで終わる
- 一覧（`ndf relay ls`）と耐久ワークフローが、起動できずに終わったラッパーを `running` と読み違えない

## 事象

中継のラッパーが子の claude を起動する `Wrapper._start`（`plugins/ndf/src/ndf/domains/relay/wrapper.py` の `child = self.spawn(argv, env, self.s.cwd)`）は、起動の例外（`claude` が PATH に無い・作業ディレクトリが消えた・擬似端末を開けない）を捕まえない。呼び出し元の `_loop`・`Wrapper.run`・`cli._run` も捕まえず、`cli.py` の `main` が捕まえるのは中継の 5 種のエラーだけである。

設計の工程で、ptyprocess 0.7.0 の `PtyProcess.spawn` を打って確かめた（2026-11-19）。

| 打ったもの | 結果 |
| --- | --- |
| PATH に無いコマンド | 親で `FileNotFoundError: The command was not found or was not executable: <名前>.` |
| 実行できないファイル（`/etc/passwd`） | 親で同じ `FileNotFoundError` |
| 無い作業ディレクトリ（`cwd=/tmp/no-such-dir-xyz`） | 親では例外が出ない。fork した子の Python が `os.chdir` で失敗し、トレースバックを擬似端末へ出して終了コード 1 で終わる |

## 期待する結果

子を起動できないときは、理由を `log.jsonl` の 1 行と端末の `ndf-relay:` の 1 行で出し、停止理由の種類（causes）の終了コードでラッパーを終える。`wrapper.json` の状態を `stopped` にする（今は `running` のまま残るおそれがある）。

## 再現手順

1. PATH から `claude` を外して `ndf relay run` を打つ → `FileNotFoundError` のトレースバックで終わる見込み（親の例外は上の実測で確かめた。ラッパーを通した出力と終了コードは打っていない）
2. 作業ディレクトリを消してからカットポイント（`ndf-next`）を出す → 次のセグメントの子が終了コード 1 で終わり、ラッパーが `--resume` で起動し直し、今日の上限で `work_stopped` になる見込み

## 環境

NDF 11.0.7（`main` の 61d89d79b）・Linux。11.0.8 の後の `main`（2e43af7bc）でも `_start`（`wrapper.py` の 341 行）は起動の例外を捕まえない。ptyprocess 0.7.0・Python 3.14。

## 前提

- 前提 1: 子を起動できない原因は、`PtyProcess.spawn` が親で出す `OSError`（コマンドが無い・実行できない・擬似端末を開けない）と、作業ディレクトリが無いことの 2 つに分かれる。前者は例外を捕まえ、後者は起動の前に確かめる
- 前提 2: ラッパーを挟まない起動（`_passthrough`）は今のまま（`exec` できなければ理由の 1 行と終了コード 127）。この変更はラッパーの下の起動だけを扱う

## 対象範囲

含む:
- ラッパーが子を起動するすべての手（最初のセグメント・カットポイントの次のセグメント・`account`・`restart`）で、起動できないときに `Ended("precondition", <理由>)` で終える
- 子を起動する前に作業ディレクトリがディレクトリとして在るかを確かめる
- 手順書 `relay.md` の「落ちたときの続け方」に、起動できないときの 1 行と続け方を足す

含まない:
- 作業ディレクトリが消えたときに別のディレクトリへ逃がして起動すること（S6）
- 起動できなかったときの打ち直し（S5）
- ラッパーを挟まない起動（`_passthrough`）の振る舞い
- リレーハブ（`ndf relay spawn`）が tmux でラッパーを起動できないとき（ラッパーより前の段で、`hub.py` が持つ）
