# #4091: 並列の計画: 待つ行のラッパーを止めて席を返し、待ちが解けたら上限の判定を通して席を取り直す（#4050 から分けた）

## 何が起きたか

#4050（並列の計画で、待つレーンの枠へ別の Issue の設計を流す）の設計は、実装の待ちの行と承認ゲートの回答を待つ行のラッパーを耐久ワークフローが止めて席を返し（`row_parked`）、マシン全体の稼働中の数から外し、待ちが解けるか回答が載ったら上限の判定を通して席を取り直す（`row_seated`）と決めた。この仕組みは、#4050 の設計 PR（#4072）の後の cross-review（PR #4082 の 4 ラウンド）と、別の設計 PR のレビューから起票した #4085（3 点）・#4088（5 点のうち 1・2 点）で、毎回新しい重い穴が見つかった（再検証の条件・止められなかったときの戻し方・起動のキーと失敗の数え方・停止の中断と再開・起動途上の着席の数え方・回答の後の起動のキー）。収束しないまま #4050 に含めると #4050 の実装に入れないため、#4050 の決定 15 でこの課題へ分けた。#4085 と #4088 の 1・2 点も、この課題の設計でまとめて解く。

| 由来 | 穴 | 起きること |
| --- | --- | --- |
| #4085 の 1 | 再着席した行を数えない（`lanes_of` が `holding` の行を一律に除く） | 再着席の直後にラッパーが落ちると、別の計画が空きとして起動し上限を超える。#4051 の索引の後始末も索引を消せる |
| #4085 の 2 | 回答済みかを番号の比べだけで決める（`gate_wait`） | 同じ着席で続けて別の承認ゲートを待つと、前の回答で今の未回答のゲートを見落とし、席を返さない |
| #4085 の 3 | `row_parked` のコミットの後・停止の前の中断（`park_lane`） | 打ち直しも次の観測も停止を見送り、元のラッパーが枠を使い続ける |
| #4088 の 1 | 起動失敗の補償に通常の返席の再検証を求める（`launch_lane`） | 回答の後の再着席で起動に失敗すると、元のリクエストが閉じていて席を戻せず、席が残る |
| #4088 の 2 | 再着席後に `next` の前で落ちたラッパーの回復に一覧が無い（`judge_lanes`・`_parks`） | 対象がその 1 レーンだけの計画で、席の返却も再起動も起きない |

## 種類

機能追加（待つ行の席を返す約束は、今の SSOT（`plugins/ndf/skills/development-workflow/references/parallel.md`・`parallel-checks.md`、確定仕様 `docs/specifications/ndf-parallel-machine-plan-limit.md`）に無い。今の SSOT は、承認ゲートを待つ行を実行中として数える）

## 今の姿

パスは `plugins/ndf/` からの相対で書く。#4050 は設計がマージ済みで、実装はまだである。

- **待つ行は枠を使ったまま動く。** 承認ゲートの回答を待つ行は `running` のままで、マシン全体の稼働中の数に数える（`src/ndf/progress/lane/machine.py` の `lanes_of`・`held_seats`）。#4050 の実装の後も、実装の待ちの行は同じく数える（#4050 の詳細設計の「#4091 へ分けたもの」）
- **数え方は 1 か所にある。** 起動の許可（`admitted`）・リレーハブへ渡す席（`held_seats`。#4044 の `ndf lanes seats` も同じ）・計画の索引の後始末（#4051）は、どれも `lanes_of` の「実行中の行を持つレーン」を読む
- **続きの起動は上限を読まない。** 回答の後の next などの続きの手は、行を始めた起動の席を使い（`seated=True`）、動いているラッパーを置き換えて起動する（`src/ndf/progress/plan/run.py` の `launch_lane`）
- **起動の失敗は手のキーで数える。** 起動したまま期限（`parallel-run.launch` の秒）を過ぎても候補に残る手は、失敗の 1 回として数えて打ち直し、決まった回数で打ち切って知らせる（`src/ndf/progress/plan/run_decide.py` の `_expire_launched`・`_fail`）

## 何を足すか・変えるか

| | 今（#4050 の実装の後） | 足した後 |
| --- | --- | --- |
| 実装の待ちの行・承認ゲートの回答を待つ行のラッパー | 動いたまま枠を使う | 耐久ワークフローが止めて席を返す。承認ゲートは、その質問かリリースのリクエストが計画に開いた後だけ |
| 席を返した行の数え方 | — | ラッパーが止まったと確かめた行だけを数えない。止めている途中・取り直している途中の行は数える |
| 待ちが解けた・回答が載った・中止する行の起動 | 続きの起動（上限を読まない） | 席を返した行は、行を始める起動と同じく上限の判定を通して席を取り直す。上限なら待つ |
| 席を返した行の生死の判定 | — | 止まりとして知らせない。`ndf lanes status` は待ちの種類（実装の待ち・承認の回答の待ち）で出す |

## 今の利用者への影響と互換

- 計画の設定の形は変えない。動いている計画は、入れた後の最初の読み直しから待つ行の席を返す
- 承認の回答から conductor の再開までが、枠が埋まっていると延びる（上限で待つ）
- 互換の経路は持たない（NDF は普及のフェーズの前。MVV バージョン 11 の Value 4 は代表のリポジトリの種類を扱えることだけを守る）

## なぜ困るか

承認やほかのレーンを待つ行が枠を使い続けるので、p12 のように待つ行で全枠が埋まると、#4050 の空いた時間にやることの一覧の設計を流す空きが出ない。承認が何時間も出ない間、マシンの枠が待つレーンで埋まったままになる。利用者の全体の設計方針（#4069）は、範囲の資源を使い切り、処理待ちを作らないことを求める。

## 目的

- **今どうなっているか**: 待つ行（実装の待ち・承認ゲートの回答の待ち）は、何もしないのにマシンの枠を 1 本ずつ使う。席を返す仕組みは #4050 の設計で 4 ラウンド回しても穴が続き、分けられた
- **誰に効くか**: 並列の計画を流すすべての利用者
- **変えると何が成り立つか**: 待つ行が枠を返し、承認が何時間も出ない間も別の設計が流れ続ける。どこで落ちても、上限を超えて起動せず、返した席は次の観測で戻るか同じ手が打ち直される

## 対象範囲

含む:
- 待つ行（実装の待ち・承認ゲートの回答の待ち）のラッパーを止めて席を返す手と、席を取り直す手
- 止められなかったとき・起動できなかったとき・途中で落ちたときの扱い
- 続きの手の起動のキーと失敗の数え方
- 席を返した行のマシン全体の数え方と、生死の判定
- #4050 の受け入れ条件 3・16 と、受け入れ条件 4 のうち上限の判定と席を返し直す場合
- #4085 の 3 点と #4088 の 1・2 点
- #4050 の設計文書のうち、この課題が置き換える節の書き直し（実装の PR で行う）

含まない:
- 実装の待ちの判定と記録（`row_held`・`row_implementing`）、空いた時間にやることの一覧と割り当て、`after` の辺の規則。#4050 が持つ
- #4088 の 3〜5 点（最後の行の後の停止・書き手の判別・一覧の更新頻度）。#4050 に残る部分である
- 開発ループの行（`kind: loop`）。今のとおり動く
- 承認ゲートでない質問の待ち・背景の作業の待ち（#4049 の `waiting`）。席を返さない（背景の作業の待ちの知らせは #4070）
- リレーハブの数え方（#4044）と計画の索引の寿命（#4051）
- マシン全体の上限の値と層（#3989）

## 前提

- 前提 1: 計画ごとに耐久ワークフローは 1 本だけ動き、手を 1 つずつ打つ（`durable.session` を `run_key` で取る）。同じ計画の観測と起動の手は同時に走らない
- 前提 2: 承認ゲートの回答は、席を返したかによらず、オーガナイザーがラッパーへの打ち込みを使わずに今の手順書の経路（`ndf answer`・`ndf lanes release` と `ndf lanes answered`）で届ける。ラッパーの中の conductor は回答を受けない
- 前提 3: 止めた conductor の会話の文脈は失われ、起動し直した conductor はステートマシンから続ける（#4050 の決定 4 の代償と同じ）

## 受け入れ条件

- [ ] 1. 実装の待ちの行と、承認ゲートの質問かリリースのリクエストが計画に開いた行は、耐久ワークフローがそのレーンのラッパーを止め、止まったと確かめた後はマシン全体の稼働中の数に数えない。止まりの知らせを出さない。リクエストが載る前と、承認ゲートでない質問の待ちでは止めない（テスト）
- [ ] 2. 席を返した行の待ちが解けるか回答が載ると、起動し直しはマシン全体の上限の判定を通す（上限なら待ちに置く）。同じ待ちを 2 回起動せず、起動が続けて失敗したら決まった回数で打ち切って知らせる（テスト）
- [ ] 3. 席を返す手・取り直す手のどこで落ちても（返すと決めた記録の後・停止の後・取り直すと決めた記録の後・起動の後）、次の観測で枠が空くか同じ手が打ち直され、上限を超えて起動しない。止めている途中と取り直している途中の行は数える（テスト）
- [ ] 4. 同じ着席で 2 つ目の承認ゲート（別の質問の id）を待つ行も席を返す。回答済みかは質問の id で決める（テスト。#4085 の 2）
- [ ] 5. 席を取り直した行の起動に失敗したとき、承認のリクエストが閉じていても席が残らない（設計承認・リリース承認のそれぞれ。テスト。#4088 の 1）
- [ ] 6. 席を取り直した行の conductor が `next` の前に落ちても、対象がその 1 レーンだけの計画で、決まった期限の後に同じ手が打ち直される（テスト。#4088 の 2）
- [ ] 7. 確定仕様と手順書（`parallel.md`・`parallel-checks.md`）が、席を返す行・数え方・生死の判定を、実装と同じ規則で書く（読み合わせ）

## 用語

| 語 | 意味 |
| --- | --- |
| 席 | 行を始めた起動が上限の判定を通って得た、マシンの枠 1 本分の数え上げ（#4051 の決定 5 と同じ） |
| 席を返す | 待つ行のラッパーを止め、止まったと確かめた後にマシン全体の稼働中の数から外すこと |
| 席を取り直す | 席を返した行を、上限の判定を通して起動し直すこと |
