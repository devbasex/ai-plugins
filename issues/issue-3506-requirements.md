## 目的

リリース承認ゲートで利用者が 1 回承認すれば、本番の PR のマージまでリリースが止まらずに流れる状態にする。

- いまは、本番チャネル（`main`）の ruleset が承認レビュー 1 件を必須にし、本番の PR の作者が利用者自身のアカウントのため、GitHub は作者本人の承認を受け付けない。承認ゲートを通ったリリースが、人が手でマージするまで止まる
- リポジトリの宣言で「本番の PR は管理者の迂回（`gh pr merge --admin`）でマージする」を選べるようにする。迂回はリポジトリの決まりであり、NDF の固定の制約にしない

## 前提

- 前提 1: 迂回のマージは利用者のアカウントで打つ。`GITHUB_TOKEN` では本番チャネルへの push が CD を起動しない（確定仕様 [docs/specifications/ndf-release-approval-on-pr.md](../docs/specifications/ndf-release-approval-on-pr.md) の 42 行目）。利用者のアカウントは ruleset の迂回を許された役割（リポジトリの役割 admin）を持つ
- 前提 2: 宣言があるときは、承認ゲートの承認を PR のレビューでは確かめない（作者本人のレビューは付けられないため）。承認は、NDF が先端と照らせる形で PR の上に残す。形（`cd-no-review` と同じ証跡のコメントに寄せるか、別の記録か）は設計が決める
- 前提 3: 宣言が読めない（ファイルが壊れている・値の型が違う）ときは、宣言が無いときと同じく迂回しない。迂回へ倒すと、承認なしのマージが通る側へ誤るため
- 前提 4: 迂回のマージは、本番の PR の先端を指定して打つ。指定した先端と GitHub の上の先端が違えば、GitHub がマージを拒む

## 対象範囲

含む:
- 本番の PR を迂回でマージすることを選ぶ宣言の追加と、その読み取り
- 本番の経路の 2 つ（`release-steps.py release --channel prod` と `merged-steps.py promote`）が共有する本番の PR のマージの処理（`plugins/ndf/scripts/release_lib/reviewed.py` の `merge_on_pr_approval`）が、宣言を読んで迂回を使うこと
- 迂回してマージしたことの記録
- 作り直し（`plugins/ndf-next/`）のリリースのマージ（`plugins/ndf-next/src/ndf/domains/release/land.py`）が、同じ宣言を読むこと
- ai-plugins の宣言にこの値を書くこと
- 確定仕様（[docs/specifications/ndf-release-approval-on-pr.md](../docs/specifications/ndf-release-approval-on-pr.md)）の不変条件 I7（迂回なしでマージする）を、宣言の有無で分けて書き直すこと

含まない:
- ruleset そのものの変更（承認数を 0 にする、迂回を許す役割を変える など）
- 開発版チャネル（`develop`）へのマージ。`develop` の ruleset は承認 0 件で、迂回が要らない
- 本番の PR 以外の PR（実装の PR・設計の PR・戻しの PR）のマージの方式

## ドメインイベント

| # | イベント | 引き金 | 失敗したとき | 順序の前提 |
| --- | --- | --- | --- | --- |
| E1 | 本番の PR を開いた（か、開いている PR を引いた） | `release --channel prod` か `promote` | 既存の手順どおり 1 で止まる | — |

| E4 | 本番の PR の必須のチェックが通った | E3 の後の待ち | 落ちたら 1、上限まで終わらなければ 75 で止まる。迂回はしない | E3 |
| E5 | 本番の PR を迂回でマージした | E4（宣言があるとき） | GitHub が拒めば 1 で止まり、理由を出す。先端が動いていれば承認ゲートで止まる | E3・E4 |
| E6 | 迂回してマージしたことを記録した | E5 | 記録の失敗の扱いは設計が決める（未決） | E5 |
| E7 | CD がタグと GitHub Release を作った | E5 の push | 既存の手順どおり | E5 |

## 用語

| 用語 | 意味 |
| --- | --- |
| 本番の PR | リリースのブランチから本番チャネル（`main`）へ出す PR |
| 管理者の迂回 | ruleset が迂回を許した役割の人が、必須の承認レビューと必須のチェックを満たさずにマージすること。`gh pr merge --admin` で打つ |
| 迂回の宣言 | 本番の PR を管理者の迂回でマージすることを選ぶ、リポジトリの `.ndf/` の設定の値 |

## 受け入れ条件

- [ ] 1. 迂回の宣言があるリポジトリで、承認ゲートの承認が本番の PR の先端と一致し、必須のチェックが通ったとき、承認レビューを待たずに迂回でマージし、`release --channel prod` は 0 で終わる
- [ ] 2. 迂回の宣言があるリポジトリで、承認ゲートの承認が無いとき、マージせずに承認ゲート（終了コード 10）で止まり、本番の PR は開いたまま残る
- [ ] 3. 迂回の宣言があるリポジトリで、必須のチェックが落ちたとき、迂回でマージせずに 1 で止まる
- [ ] 4. 迂回の宣言があるリポジトリで、承認の後に本番の PR の先端が動いたとき、迂回せずに承認ゲート（終了コード 10）で止まる
- [ ] 5. `merged-steps.py promote` の本番の経路でも、条件 1〜4 と同じ判定でマージするか止まる
- [ ] 6. 迂回してマージしたとき、結果 JSON の本番の PR の行の `admin` が `true` になり、迂回したことが承認の証跡かリリース記録（どちらに置くかは設計が決める）にも残る
- [ ] 7. 迂回の宣言が無いリポジトリ・宣言が読めないリポジトリでは、今と同じく迂回なし（`--admin` を付けない）でマージし、承認レビューが無ければ承認ゲート（終了コード 10）で止まる（退行しない）
      前提の確認: `plugins/ndf/scripts/release_lib/reviewed.py` の 177 行目が `no_admin=True` を固定で渡し、132 行目が結果の行に `"admin": False` を書く（NDF 10.27.65、2026-11-14 に読んだ）。2026-11-15 07:09 JST のリリース（本番の PR #3505）は `reviewDecision` が `REVIEW_REQUIRED` のまま止まった
- [ ] 8. 作り直し（`plugins/ndf-next/`）のリリースのマージが同じ宣言を読み、宣言があるときは条件 1〜4・6 と同じ判定で迂回でマージし、宣言が無いときは今の振る舞いのまま変わらない
- [ ] 9. ai-plugins の `.ndf/` の宣言に迂回の値が書かれている

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わる。`.ndf/` の宣言に任意の値が 1 つ増える。値が無ければ今と同じ振る舞いのため、互換は保つ |

## 調べた事実

- 2026-11-15 07:09 JST、リリース 10（ndf v10.27.65、並列の計画 p6）が、本番の PR https://github.com/devbasex/ai-plugins/pull/3505 の承認レビューが無いため止まった（`gh pr view 3505 --json reviewDecision` が `REVIEW_REQUIRED`、作者は利用者のアカウント）。07:12 JST に利用者が手でマージし、CD（`release-cd.yml`）が成功してタグ `ndf--v10.27.65` ができた
- `plugins/ndf/scripts/release_lib/reviewed.py` の `merge_on_pr_approval` は `ops.wait_and_merge(..., no_admin=True)` で、迂回なしに固定している。呼び出し元は同じファイルの本番の経路（129 行目）と `plugins/ndf/scripts/release_lib/promotion.py` の 158 行目の 2 か所（`grep -rn "merge_on_pr_approval" plugins/ndf/scripts --include=*.py`、テストを除く）
- `main` の ruleset（`protect main`）は承認レビュー 1 件・必須のチェック・削除と強制 push の禁止を持ち、迂回を許すのはリポジトリの役割 admin（`actor_id` 5）で、`bypass_mode` は `pull_request`（PR のマージでだけ迂回できる）。`develop` の ruleset（`protect develop`）は承認 0 件（`gh api repos/devbasex/ai-plugins/rulesets/<id>`、2026-11-14）
- ruleset の迂回は、同じ ruleset の必須のチェックも満たさずにマージを通すと読んでいる（未確認: 迂回の範囲を規則ごとに分ける設定は ruleset の画面と API の応答に見当たらないが、チェックが落ちた PR で試してはいない）。どちらであっても、迂回の前に必須のチェックの通過を NDF が確かめる（条件 3）
- 作り直しの側のリリースのマージ（`plugins/ndf-next/src/ndf/domains/release/land.py` の `_refusal`）は、承認を PR のレビューではなく証跡（`trail.check`）で照らしている
