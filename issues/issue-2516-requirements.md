## 目的

- 名前が `test_` で始まるプロダクションコードのファイルを持つリポジトリでも、cross-refactoring の着手（`init`）がテンプレートの試走で誤って止まらないようにする
- 止まったときの案内が、正しいテンプレートを直す箇所として示さないようにする
- #2369 の Pull Request https://github.com/devbasex/ai-plugins/pull/2515 が検査のプランを通れるようにする

## 前提

- 前提 1: 中身でテストかどうかを見分ける対象は Python のファイル（拡張子 `.py`）に限る。Python の場合、テストの関数とは pytest が既定で集める形（名前が `test` で始まる関数、名前が `Test` で始まるクラスの中の `test` で始まるメソッド）を指す。ほかの言語のファイルは今の名前の形の判定のまま扱う
- 前提 2: 行数と危険度の判定（`is_test_path`）は今はパスの文字列だけで決めている。見分け方をそろえるために作業ディレクトリの中身を読む形へ変えてよい。読めないファイル（削除済み・リポジトリの外）は今の名前の判定で扱う
- 前提 3: ディレクトリの名前でテストの置き場所とみなす判定（`tests/` `spec/` など）は変えない。`tests/` の配下にあるテスト関数を持たない補助のファイル（`tests/test_helpers.py` など）も、試走の候補からは外す（受け入れ条件 1 の対象に含む）
- 前提 4: プロダクションコードのファイルの名前を変える（`test_strategy.py` を別名へ移す）ことはこの課題の直し方にしない。ほかのリポジトリにも同じ構成がありうるため、見分け方の側で直す（Value 6）

## 対象範囲

含む:
- cross-refactoring のテンプレートの試走の候補選び
- `--scope` のテストの置き場所の判定（本体と同じ場所にテストを置く構成の判定）
- プロダクションコードの行数と危険度の判定でのテストのファイルの見分け方（S4）
- 上の 3 つを確かめるテスト

含まない:
- Python 以外の言語のテストの見分け方の変更（S5）
- `plugins/ndf/scripts/lib/test_strategy.py`・`test_triage.py` の名前の変更（前提 4）
- 試走の判定の表（`template_verdict`）の作り直し。終了コード 5 の扱いは「未決」に置く
- cross-refactoring 以外の Skill のテストの見分け方
