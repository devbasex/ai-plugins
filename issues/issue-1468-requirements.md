# #1468: relay: Bedrock の登録をプロファイルの選択だけで済ませ、account の副命令を引数でも打てるようにする（AI が代わりに打てる）

正は課題の本文（#1468）で、この文書はその写しである。`spec-copy.py write` で作り直す。手で直さない。

## 依頼（原文）

> relay.py の `account` の副命令は、人が端末で打つ前提になっている。
>
> - `account add <名前>` は `sys.stdin.isatty()` が偽なら断る（`relay_lib/accounts.py` の `cmd_add`）。`claude auth login` が認可コードの貼り付けを端末で待つためである。AI（conductor・worker）が代わりに打てない
> - Bedrock（従量の接続）は `relay.py` で登録できない。利用者が AWS のプロファイルを用意し、`NDF_SUPERVISE_CLAUDE_FALLBACK='CLAUDE_CODE_USE_BEDROCK=1 AWS_PROFILE=<名前> AWS_REGION=<地域>'` をシェルの設定ファイルへ手で書き、ラッパーを起動し直す（`development-workflow/references/relay.md` の「従量の接続の宣言」）。手順が多く、書き誤りに気づく場所も無い
>
> 1. **Bedrock の登録をスクリプトにする。** 利用者は AWS のプロファイルを選ぶだけで、残り（認証が通るか・Bedrock の Claude のモデルを呼べるかの確認、地域とモデルの決定、従量の接続の宣言の保存、次の起動から効くこと）を relay.py が行う
>    - プロファイルの候補は `aws configure list-profiles` から出す。1 つなら確認だけ、複数なら選ばせる
>    - 宣言の保存先は relay の置き場（`${CLAUDE_CONFIG_DIR:-~/.claude}/ndf/`）にし、シェルの設定ファイルを書き換えない。環境変数 `NDF_SUPERVISE_CLAUDE_FALLBACK` があればそれを優先する（後方互換）
>    - 確認・一覧・外す副命令も用意する（`account list` に従量の接続の行を出す・`remove` で外せる）
> 2. **`account` の副命令をすべて、対話でも引数でも打てるようにする。** AI が代わりに打てるようにするため
>    - 対話で聞く値（名前・プロファイル・地域・モデル・確認の y/n）は、すべて引数で渡せる。引数で揃っていれば何も聞かない
>    - 端末でないときは聞かずに、足りない引数を名前で示して非 0 で終わる（待ち続けない）
>    - OAuth のアカウントの `account add` は、人のブラウザでの認可が避けられない。**認可の URL を出す段と、認可コードを引数で受け取って登録を終える段に分けられる**ようにし、AI が URL を利用者へ渡し、利用者が返したコードで登録を終えられるようにする
>    - 結果は `--json` で機械が読める形でも返す

（起票時の受け入れ条件 AC1〜AC9・範囲・進め方は、下の節へ観測できる形に直して引き継いだ。AC の番号は変えず、退行の条件 AC10 を足した）

## 目的

- AI（conductor・worker）が、人の代わりに `relay.py account` の副命令を最後まで打てる。人が要るのは OAuth のブラウザでの認可と、認可コードを AI へ返すことだけになる（Mission の「人の判断が要る所だけで止まる」）
- Bedrock（従量の接続）の登録が、AWS のプロファイルを選ぶ 1 操作で済み、書き誤りは登録の時点で分かる

## 前提

- 前提 1: 従量の接続は、登録できるのが 1 つだけである（今の `NDF_SUPERVISE_CLAUDE_FALLBACK` も 1 つの宣言しか持たない）。2 つ目を登録しようとすると、置き換えるかを確認する（`--yes` で置き換える）
- 前提 2: 保存する宣言に入るのは変数の名前と値（`CLAUDE_CODE_USE_BEDROCK`・`AWS_PROFILE`・`AWS_REGION`・モデルの指定）だけで、AWS の鍵・セッショントークンは入らない。資格情報は AWS CLI のプロファイルの置き場（`~/.aws/`）に残る
- 前提 3: 呼べるかの確認は、実際に Bedrock の Claude を 1 回呼んで行う（費用は 1 回の短い応答の分だけ掛かる）。呼ぶ手段（`aws bedrock-runtime` か `claude -p` か）は設計が決める
- 前提 4: `claude auth login`（2.1.284 で実測）には認可コードを引数で渡す選択肢が無い（`--claudeai`・`--console`・`--email`・`--sso` だけ）。2 回に分けた呼び出しをどう実現するか（1 回目の `claude auth login` の子を生かしておくか、別の手段か）は設計が決める。どの手段でも AC5 の観測できる振る舞いは同じである
- 前提 5: `capacity`（#1453 で足す副命令）は #1453 が develop へ入った時点の形を対象にする。#1453 が入る前に実装を始めない（課題の「進め方」）
- 前提 6: 宣言の保存先と環境変数の両方があるとき、効くのは環境変数だけである（2 つを混ぜない）
- 前提 7: 端末かどうかは標準入力が端末かで判定する（今の `cmd_add` と同じ）

## 対象範囲

含む:
- Bedrock の従量の接続を登録・確認・一覧・外す副命令（`relay.py account` の下）
- 登録した宣言を、ラッパーの区間と `supervise.py` の `claude -p` が読むこと（環境変数が優先）
- `account` のすべての副命令（`add`・`list`・`remove`・新しい Bedrock の副命令・#1453 の `capacity`）の引数化・`--yes`・`--json`・端末でないときの振る舞い
- OAuth の `account add` を 2 回の呼び出しに分けること
- `plugins/ndf/scripts/relay.py`・`relay_lib/`・`lib/claude_accounts.py`・`supervise_lib/claude.py` と、そのテスト・`development-workflow/references/relay.md`

含まない:
- AWS のプロファイルそのものを作ること（`aws configure sso` など）
- Vertex の登録（同じ形で後から足せる設計にはする）
- シェルの設定ファイルの書き換え（C6。宣言は relay の置き場にだけ保存する）
- アカウントの切り替えの規則（どのアカウントを選ぶか・閾値）の変更。#1453 が持つ

## 用語

| 用語 | 意味 |
| --- | --- |
| 従量の接続 | 使った量で課金される接続（Bedrock・Vertex・API キー）。サブスクリプションの上限に掛からない。relay の登録では名前 `metered` で表す |
| 従量の接続の宣言 | 従量の接続で起動する子へ足す環境変数の組（`KEY=VALUE` を空白区切り）。環境変数 `NDF_SUPERVISE_CLAUDE_FALLBACK` か、relay の置き場の保存先が持つ |
| relay の置き場 | `${CLAUDE_CONFIG_DIR:-~/.claude}/ndf/`。アカウントの置き場と、保存した従量の接続の宣言を持つ |
| 登録の途中の状態 | OAuth の `account add` の 1 回目と 2 回目の間に置き場へ残す状態。期限を過ぎたら捨てる |

## 受け入れ条件

- [ ] AC1: 前提: AWS のプロファイルが 1 つ以上あり、Bedrock の Claude を呼べる。操作: 端末で Bedrock の副命令（名前は設計で決める）を引数なしで打ち、プロファイルを 1 つ選ぶ（1 つなら確認に y）。結果: 終了コード 0 で、続けて打った `account list` に従量の接続の行（プロファイル名・地域・モデル）が出る
- [ ] AC2: 標準入力が端末でない状態で、`--profile <名前> --yes`（と必要なら `--region`・`--model`）だけを渡すと、何も聞かずに AC1 と同じ登録が終わる（終了コード 0）
- [ ] AC3: 呼べないプロファイルで登録すると、非 0 で終わり、理由が「認証切れ」「権限が無い」「地域で使えない」「モデルが有効でない」のどれかとして出て、宣言は保存されない（前の宣言があれば変わらない）
- [ ] AC4: 宣言を保存した状態で、ラッパーの区間と `supervise.py` の `claude -p` の両方が、登録アカウントがすべて上限に達したときに、その宣言の変数で起動する。環境変数 `NDF_SUPERVISE_CLAUDE_FALLBACK` があるときは、保存した宣言でなく環境変数の変数だけで起動する
- [ ] AC5: 標準入力が端末でない状態で、`account add <名前>` の 1 回目が認可の URL を出して 0 で終わり、2 回目の `account add <名前> --code <認可コード>` がアカウントを登録して 0 で終わる。1 回目と 2 回目の間の登録の途中の状態は relay の置き場に残り、期限（設計で決める）を過ぎた後の 2 回目は「期限切れ」を示して非 0 で終わり、登録の途中の状態は残らない
- [ ] AC6: `account` のすべての副命令（`add`・`list`・`remove`・Bedrock の副命令・#1453 の `capacity`）が次を満たす: 確認を求める箇所は `--yes` で飛ばせる。標準入力が端末でなく、足りない引数があるときは、何も待たずに足りない引数を名前で示して非 0 で終わる。`--json` を渡すと結果を JSON 1 つで標準出力へ返す
- [ ] AC7: トークン・認可コード・AWS の鍵とセッショントークンが、画面（標準出力と標準エラー）・`log.jsonl`・`--json` の出力・保存した宣言のどこにも出ない（テストで既知の値を入れ、出力に含まれないことを確かめる）
- [ ] AC8: `relay.md` の「従量の接続の宣言」の手順が新しい副命令に置き換わり、シェルの設定ファイルへ手で書く手順は「環境変数で上書きする場合」の 1 か所だけに残る
- [ ] AC9（リリース後テスト）: 実物の AWS のプロファイルで AC1 を行い、アカウントを上限にした状態で Bedrock に切り替わることを 1 回確かめる
- [ ] AC10（退行しない）: 端末で今までどおり `account add <名前>`・`account list`・`account remove <名前>` を打つと、今と同じ結果になる。宣言を保存していない利用者の切り替えの振る舞いは変わらない（既存のテストがすべて通る）

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 運用・保守性 | 呼べるかの確認で失敗したとき、理由の区分（AC3 の 4 つ）と、元になった AWS のエラーの種類の名前が出る。宣言の保存先が壊れていれば、起動のたびに画面と記録に 1 行出る |
| セキュリティ | AC7。保存した宣言と登録の途中の状態のファイルは所有者だけが読み書きできる（アカウントの置き場と同じ扱い）。登録の途中の状態は期限を過ぎたら捨てる |
| システム環境 | Linux で動く（macOS は今の `account add` と同じく OAuth の登録を断る。Bedrock の登録は macOS でも動くかを設計で決める）。`aws` CLI が無ければ Bedrock の副命令は理由を示して非 0 で終わる |
