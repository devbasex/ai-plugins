## あるべき姿

1. **1 事象 1 入口**: ランタイムごとに事象 1 つにつき登録 1 行・プロセス 1 本。guard は表で並べ、入力の解析（payload・会話の記録の末尾・最後の応答の分類）は 1 回だけ
2. **起動の形**: hook は `bin/ndf` を通らず軽い入口から始め、標準ライブラリと許した依存だけを import する。環境が無ければ終了コード 0 で通す（旧い設計の決定 20・I13 を不変条件にする）
3. **予算**: 事象ごとの時間（p95）と注入の字数を `limits.json` に置く。「部品の上限 ≤ 締め切り − 余白 ≤ 登録の timeout」を起動時に検査し、すべての登録に timeout を付ける。CI で退行を落とす
4. **失敗の規則**: 既定は通す（例外・時間切れ・環境が無い・知らない事象と Tool）。止める側に倒すのは宣言した hook だけ
5. **上限**: Stop の差し戻しはセッション共通の数え手で区間あたり合計 N 回まで。同じ理由の拒否は N 回で案内へ下げる。利用者の入力で数え直す
6. **I/O**: 同期の経路ではネットワークを使わない。外部コマンドは git のローカル操作だけ
7. **計測**: hook ごとの所要・判定（通した・案内した・止めた）・注入の字数を 1 行ずつ記録する
8. **ランタイムの契約表**: Claude Code と Codex の入出力の表と、本体の版ごとの入力の見本で CI の検証を回す
