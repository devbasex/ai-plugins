## タスク分解

タスクの番号はレビューの単位と同じ順に並べる。どのタスクも `tdd-cycle` で進め、テストは CI に寄せる（`.ndf/project.json` の `test.ci.only: true`）ため手元では走らせない。

### Task 1: 上限の設定の方針に読み手を指定させ、食い違いを `ndf check` で落とす

- **対象ファイル:** `contracts/limits.json`［lsplit］・`contracts/schemas/limits.schema.json`・`src/ndf/contracts/limits.py`・`src/ndf/checks/limits_readers.py`（新設）・`src/ndf/checks/rules.json`［lz2-ci］・`src/ndf/checks/run.py`［lz2-ci］・`src/ndf/checks/README.md`・`src/ndf/core/worker.py`［lsplit］・`tests/checks/test_limits_readers.py`（新設）
- **変更内容:** 詳細設計の「上限の設定の読み手の指定」のとおり。`actual` は `src/ndf/checks/imports.py` のモジュールの名前への変換を再利用する。230 個の方針すべての（#4312 が `hook.budget.stop.codex`・`hook.stop-wait.judge` を、#4325 が `parallel-run.idle` を足した） `read_by` を、`actual` の結果から下書きして読み直してから書き、`read_by` を必須にするのと同じコミットで `supervise.worker-step` を消して `supervise.worker-run` を足す（`core/worker.py` の `WORK_TIMEOUT` を `work_timeout` へ置き換える。#3667 の地図の行だが、方針の読み手を同じコミットで持たせるためここで行う）。引かれない方針は消すか読み手を足すかを決め、方針ごとの判断を実装の Pull Request の本文に一覧で残す（`3684:6`）
- **満たす受け入れ条件:** `3684:1`・`3684:6`
- **進め方:** 失敗するテスト（合成した上限の設定と `src` で `unread`・`undeclared`・`unresolved` が出る）→ 規則 → `limits.json` の書き足し → スキーマの必須化

| リスク | 対処 |

## 切り戻し手順

- 単位ごとにスプリントブランチへのマージコミットを `git revert -m 1` で戻せる。依存の向きが U1 → U2・U3 → U4 → U5 → U6・U7 → U8 なので、戻すときは後ろの単位から戻す
- 内部データの版（U5〜U7）を戻すと、版 1 で書いた記録を戻した NDF が読む。版 1 の行は `version` が整数で、戻した NDF は知らない欄として扱うか形の違いとして止める。記録のファイルは追記だけなので、戻す前に `.ndf/` の下の記録の写しを取っておけば元へ戻せる
