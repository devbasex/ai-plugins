# #443 / #444 / #442: リファクタリングの方法論と、枠組みとの境界

**3 件を 1 つの記録にする。** いずれも「方法論がどこにあるか」を扱い、同じ 2 つの Skill
（`refactoring` / `cross-refactoring`）と工程表を触る。**Pull Request は分ける**（#443 と
#444 は同じ移送の表裏、#442 は工程の話である）。

## 依頼

> `/ndf:cross-refactoring` はリファクタリングを多ランタイムでループさせる枠組み提供が目的で、
> どうリファクタリングするかは `/ndf:refactoring` が担うべき

（利用者の指摘。#444 の本文より）

> **`refactoring` と `cross-refactoring` に「テストをどこまで変えてよいか」の規約を置く。**
> いまはどちらも定めていない。その結果、**「テストを変えない」が暗黙の制約として働き、
> 構造改善を形だけにする**。（#443）

> **実装に入る前に、触る対象の構造を先に整えるべきかを判断する。**（#442）
