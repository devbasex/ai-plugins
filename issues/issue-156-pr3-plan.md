## モード

`standard`。収束の判定を変える。

## 目的と非目的

達成したい状態:

- 指摘の採否が、担当の判定（`event`）ではなく検証できる根拠で決まる

やらないこと:

- **効果の測定** — 4 本目が扱う
- **振動の閾値（0.5）の変更** — この変更の後の実測で決める
- 収束の上限（12）の変更

## 前提

- 前提 1: 実行検証の宣言（`.ndf/cross-review.json`）が無いリポジトリでは、実行検証を
  行わず従来どおり動く
- 前提 2: 指摘の記録が無いラウンドでは区分を決められない。従来の判定へ落ちる

## タスク分解

**構成要素は直列に依存する。** 前のタスクが残す項目を次のタスクが読む。

**順序は 0 → 1（1 段目）→ 2 → 3 → 1（2 段目）→ 4 → 5 である。** 統合が 2 回現れるのは、
機械の判定（1 段目）が反証より前、申告の統合（2 段目）が反証より後に来るためである。

### Task 0: 指摘の識別子を採番する

- **対象:** `state.py` の `cmd_read_result`（2 本目で入れた取り込み）/
  `tests/test_review_findings.py` へ追加
- **満たす条件:** —（1〜14 の前提）
- **変更内容:** 取り込みの時点で `finding_id`（`<agent>-r<round>-<索引>`）を採番する。
  **統合・反証・実行検証の記録が、どの指摘を指すかをこの値で結ぶ**
- **進め方:** 失敗するテスト → 実装。既存の取り込みのテストが通ること

### Task 1: 重複の統合（2 段構え）

- **対象:** `state.py` の `_merge_duplicates` / `tests/test_merge_duplicates.py`
- **満たす条件:** 1 / 2
- **変更内容:** **1 段目は機械の判定**（近傍かつ本文の一致）、**2 段目は申告の統合**
  （反証で相互に `duplicate` が付いた組）。代表は先に取り込まれた担当の指摘とし、
  `merged_from`（代表が持つ）と `merged_into`（束ねられた側が持つ）で結ぶ
- **進め方:** 失敗するテスト → 実装。**過剰統合は指摘を失うが、統合し損ねても失われる
  ものは無い**ため、1 段目は厳しい側へ倒す（取りこぼしは `duplicate_candidates` へ残す）
- **順序に注意する。** 2 段目は**反証の後・区分の前**に走る。Task 3 の後に足す

### Task 2: 実行検証

- **対象:** `state.py` の `cmd_verify_findings` / `tests/test_verify_findings.py`
- **満たす条件:** 3 / 4 / 5 / 6
- **変更内容:** 束ねた組は**代表と `merged_from` の全員**の `suggested_check` を実行する。
  **1 件でも `reproduced` があれば代表を `reproduced`** とし、出所を
  `verification.finding_id` へ残す
- **進め方:** 実行を試みるテスト → 実装。**`realpath` で作業ツリーの配下へ解決する**

### Task 3: 反証

- **対象:** `scripts/critique.sh`（新設）/ `state.py` の `cmd_collect_critiques` /
  `tests/test_critiques.py`
- **満たす条件:** 7 / 8
- **変更内容:** 反証の値へ `duplicate_of`（申告先の `finding_id`）を持たせる。
  **申告先を指せないと 2 段目の統合が実装できない**
- **進め方:** 起動の形のテスト → 実装

### Task 4: 区分と収束の判定

- **対象:** `state.py` の `_classify_finding` と `cmd_judge` /
  `tests/test_classify_findings.py`
- **満たす条件:** 9 / 10 / 11 / 12 / 13 / 14
- **進め方:** 区分ごとのテスト → 実装 → 既存の判定のテストが通ること

### Task 5: 契約と規約を書く

- **対象:** `docs/06-evidence.md` / `docs/04-contracts.md`
- **満たす条件:** —（1〜14 の裏付け）
- **進め方:** 記述 → 行数の検査

| 収束の判定 | 新規性が数える対象が変わる。**ラウンド数が動く** |

| 状態ファイル | 項目が 4 つ増える |

## リスクと対処

| リスク | 対処 |
| --- | --- |
| 判定を変えてラウンド数が読めなくなる | 母集合は 2 本目で既に広げた。**この変更では式だけを変える**（原因を切り分けられる） |
| 実行検証が任意のコマンドを走らせる | 宣言された接頭辞に当たるものだけ。`realpath` で作業ツリーの配下へ限る |
| 反証の起動でラウンドが長くなる | 同じラウンドの 2 段目として回す（新しいラウンドを足さない） |
| `state.py` が 3200 行を超えて肥大する | **Task の単位で関数を分ける。** 構造改善の工程で見直す |

前へ戻る。** 状態ファイルの移行は伴わない（項目が無ければ従来の判定へ落ちる）。
