## 目的

- エントリポイントとステップが、終わり方（正常・例外・SIGTERM・時間切れ）にかかわらず、`ok` / `gate` / `stopped` と決まった終了コードで返る状態にする。欠け・例外・判定できない状態が `ok` で返る経路を、核と検査で塞ぐ
- worker・外部 CLI・課題を閉じる処理の結果を、自由文ではなく構造化した結果で受け取り、読み違いで先へ進む不具合（原因の型 A）を型ごとに無くす
- 達成したい状態: 新しいエントリポイントを足しても、核を通らなければ構造チェックが落とすため、同じ型の不具合が生まれない

## 受け入れ条件

### 核の結果の契約

- [ ] 1. 本体が結果を返す・例外を投げる・SIGTERM を受ける・時間切れになる、の 4 つの終わり方のそれぞれで、核の結果 JSON の `status` は `ok` / `gate` / `stopped` のどれかで、終了コードは `step_result.code_matches` を満たす
- [ ] 2. 例外・SIGTERM・時間切れで終わったとき、結果は `stopped` で、`summary` に理由があり、`gaps` に `interrupted`（SIGTERM）か `timeout`（時間切れ）が入る
- [ ] 3. 本体が `gaps` の空でない結果を `ok` で返すと、核は `stopped`・終了コード 6 を返す
- [ ] 4. 本体が結果の形でないもの（`None`・型の違う値）や、`status` と終了コードが食い違う結果を返すと、核は `stopped`・終了コード 1 を返す

- [ ] 7. `core-entry` の例外リストに行を足す変更を構造チェックが落とす。この課題を閉じる時点で `core-entry` の例外リストの行は 0 である
