# #895: 決定の記録

設計は [issue-895-design.md](issue-895-design.md)、要求は [issue-895-requirements.md](issue-895-requirements.md) にある。

## 決定の記録

### 決定 1: 中継は端末の前景に常駐し、claude を擬似端末の子として起動する形だけにする。tmux を使う形は採らない

利用者の差し戻し（2026-09-23）で、tmux が無い環境でも止まらないことと、前景の子プロセスで同じことが
できないかが問われた。2 つの形を実測して比べた。

| 観点 | 前景の中継（採る） | tmux の上の中継（採らない） |
| --- | --- | --- |
| 前提 | 端末と Python 3 だけ | tmux・今のペインが tmux の中・VS Code の統合ターミナルが tmux を開く設定。設定はどのリポジトリも用意しておらず、入れる処理（`setup`）が要る |
| 前の区間を終わらせる | 擬似端末のマスタへ `/exit` と改行を書く（実測で約 1.6 秒・終了コード 0・記録は壊れない） | `send-keys` で `/exit` |
| 前の区間の画面 | 同じ端末に次の TUI が描かれる。履歴に残るかは未確認。会話の記録と区切りの 1 行は残る | ウィンドウとして残り、`Ctrl-b p` で遡れる |
| 中継が落ちたとき | 擬似端末が閉じ、子が SIGHUP で終わる。本体の例外を捕まえて防ぐ | 区間は tmux が持つので動き続ける |
| 印を書いた claude の見分け | 中継が起動した子の pid と比べる | ペインの前面のプロセスを親子でたどる |
| 中継の始め方 | `relay.py run "<最初のコマンド>"` で claude を起動する代わりに打つ | 別のウィンドウで `relay.py run` を常駐させる |

前提が端末だけになり、`setup` による利用者の設定ファイルの書き換え（Machine 設定・バックアップ・注釈の扱い）が
すべて要らなくなる。画面を遡れないことと落ちたときの巻き込みは、区切りの 1 行と例外の捕まえで補う。

前景を既定にして tmux を任意の代わりの形として残す案も採らない。2 つの形の区間の切り替え・印の見分け・
記録を両方持つことになり、使われない側が古くなる。tmux の中で使いたい利用者は、tmux のペインの中で
`relay.py run` を打てば同じに動く。

### 決定 2: 中継が使えない・止まると決めたときは、止まらずに今までどおりの運用へ落ちる

利用者の差し戻しで、前提が欠けたときに止まらないことが求められた。`run` は始められなければ `claude` を
そのまま exec する。切り替えない理由があれば、今の区間を続けさせる。どちらも `ndf-relay:` で始まる 1 行で理由を出す。
conductor は中継の有無によらず `ndf-next` のブロックを出すので、人は今までどおりその中身を貼り付けて続けられる。

終了コード 1 で止まる形は採らない。利用者は前提をそろえるまで claude を起動できず、今までより手間が増える。

### 決定 3: 区間の終わりは、最後の応答の `ndf-next` のブロックで決める

Stop hook の標準入力には `last_assistant_message` が来る（「確かめたこと」の 1）。conductor は既に切れ目で
引き継ぎの 1 行を出す規約を持つので、その 1 行を決まった囲みに入れるだけで機械が読める。情報文字列を
`text` ではなく `ndf-next` にするのは、説明のために引いたコマンドの例を印と取り違えないためである。
外側の囲みの中に引いた例も数えない。

引継ぎ文書の決まった見出しを hook が読む形は採らない。引継ぎ文書はマイルストーンを進める利用者が
任意に置くもので、置き場所も名前も決まっていない。transcript の `goal_status` で決める形も採らない。
`/goal` を使わない区間では現れない。

### 決定 4: 関門の承認は区間の中で `AskUserQuestion` のまま受け、ブロックは承認の後に出す

`AskUserQuestion` の応答待ちでは Stop が起きない（「確かめたこと」の 5）。関門を区間の切れ目にせず、
承認と取り込みを済ませてから次のコマンドを出せば、中継は関門のことを知らなくてよい。
`context-window.md` の「報告が `結果: 関門` なら、関門の承認と取り込みの後に出す」がすでにこの順である。

関門で止まっていることを中継が画面の出力から読む形は採らない。画面の文言は Claude Code の版で変わり、
読み違えると関門の前で会話を切る。

### 決定 5: `stop_hook_active` を見ず、印は最新の Stop の中身で置き換え、中継は静まってから動く

`/goal` の判定は Stop hook と並んで発火し、止めを拒むと応答が続く。標準入力だけでは最後の Stop か
分からない（「確かめたこと」の 4）。そこで hook は Stop のたびに印を書き直すか消し、中継は印と
会話の記録と利用者の入力が 15 秒止まってから `/exit` を入力する。応答が続けば記録が動くので、中継は待つ。
`/goal` の目標がある区間では、印の後の `goal_status` の記録も待つ。判定は command hook より後に記録へ
書かれるため、判定に 15 秒を超えて掛かっても、その記録が現れる前に `/exit` を入力しない。
利用者の入力を見るのは、人が打っている途中に `/exit` を混ぜないためである。

`stop_hook_active` が真の Stop を捨てる形は採らない。`/goal` が 1 度拒んだ後の Stop こそ区間の最後で
ありうる。

### 決定 6: 前の区間は子の端末へ `/exit` を入力して終わらせ、シグナルは 30 秒で終わらないときだけ使う

中継は子の擬似端末のマスタを持つので、人が打つのと同じ `/exit` を入力できる。実測で、終了コード 0・
記録は壊れず・SessionEnd の理由が人の `/exit` と同じ `prompt_input_exit` になった（「確かめたこと」の 6）。
SIGTERM でも記録は壊れないが、終了コードが 143 になり、終わり方の記録が人の終了と区別できなくなる。

Stop hook の出力で終わらせる形は採らない。`{"continue": false}` はプロセスを終わらせない（「確かめたこと」の 9）。

### 決定 7: 印を書くのは中継が起動した子の claude だけにする

conductor が Bash から起こす `claude -p`（cross-review の担当など）は `NDF_RELAY_DIR` を継ぎ、Stop hook も
走る。そのまま印を読み書きさせると、担当の応答にブロックがあれば関門の前で会話を切り、無ければ前の印を消して
静まりの待ちを崩す。hook は親をたどって最初に当たる `claude` のプロセスが `child.pid` と同じかを確かめる。

環境変数だけで見分ける形は採らない。子の claude が起こすプロセスはすべて同じ値を継ぐ。

### 決定 8: プラグインの更新は区間ごとに毎回行う

配布の直後かどうかを中継が判定するには、配布の事実をどこかから読む必要がある。毎回
`marketplace update` と `plugin update -y` を打てば、版が変わっていないときは何も変わらず、
数秒で終わる。更新の後の版を記録に残し、AC8 の確かめに使う。

更新に失敗したら次の区間を起動せず、次のコマンドを画面に出して終わる。古い版のまま次の区間を始めると、
配布した hook と Skill で進んだと記録が誤って示す。

### 決定 9: 同じコマンドを起動し直さない。印の無い終わりで中継も終わり、空回りで切り替えをやめる

子の claude が印を書かずに終わるのは、人が `/exit` した・Ctrl-C を 2 回押した・落ちたのいずれかである。
同じコマンドで起動し直しても、前者では人の意図に反し、後者では同じく落ちる。中継も終わってシェルへ戻る。

空回りは「区間が 3 つ続けて、起動から印を書くまで 120 秒未満だった」で見る。同じコマンドの繰り返しを
比べる形は採らない。3 層の入口のコマンドは区間が違っても同じ文字列になりうる（`/goal
/ndf:development-workflow <マイルストーン>`）。前景の中継では 1 つ目の区間も中継が起動するので、1 つ目から数える。

### 決定 10: 1 日の起動回数の上限は 20、静まりは 15 秒を初期値にする

切れ目の再起動は、持ち場の境（1 つのまとまりで設計・実装・検査・取り込み・仕上げの 5 つ）と
関門の後に起きる。1 日に 2〜3 のまとまりを進めても 20 には届かず、空回りの検出を抜けた暴走は 1 日で止まる。
いずれも `run` の引数で変えられる。

### 決定 11: 中継は Python の 1 ファイルで書き、hook も同じファイルの副命令にする

印の形・作業ディレクトリの場所・pid の読み方を hook と中継が共有する。2 つのファイルに分けると、
片方だけが変わって食い違う。Python にするのは、擬似端末（`pty`）・端末の属性（`termios`）・JSON・
引数の配列での起動を標準ライブラリだけで書け、単体テストで子を試験用のプログラムに差し替えやすいためである。
hook の定義の側で `NDF_RELAY_DIR` を見て、中継の下でなければ `python3` を起こさない。

bash で書く形は採らない。擬似端末の入出力の中継を書けない。

### 決定 12: 次のコマンドの中身はシェルを通さずに 1 つの引数で渡す

中身は LLM の出力であり、引用符や `$(...)` を含みうる。子の起動は `os.execvpe` に引数の配列で渡し、
シェルを介さない。Claude Code の中から継いだ環境変数（`CLAUDECODE` など）は外す。

### 決定 13: 記録は区間ごとに起動の 1 行と終わりの 1 行に分ける

版は起動の時点で、長さと終わり方は終わった後に分かる。1 行にまとめると、起動の後に落ちた区間の
行が書かれないか、行を書き直すことになる。空回りの判定（決定 9）は、直前の 2 区間を `end` の行の長さで、
今の区間を印の `written_at` とその区間の `start` の差で読む。`end` は区間が実際に終わったときだけ書き、
切り替えをやめたときは `stop` の行の理由を残す。

終わり方を次の区間の起動の行へ持たせる形は採らない。最後の区間と、印なしで終わった区間の
終わり方が残らない。

### 決定 14: 次の区間の作業ディレクトリが消えていたら、主ディレクトリか在る最も近い親で起動する

設計 Pull Request をマージした切れ目では、`merged` が設計のブランチの作業ツリーを消す。conductor が
そこにいた場合、印の `cwd` は消えている。次の区間は `development-workflow` の「新しい会話で戻す」で
作業ツリーを戻すので、主ディレクトリから始めて足りる。

起動を諦めて止まる形は採らない。切れ目 1 は毎回この形になりうる。

### 決定 15: tmux と VS Code の設定を確かめて入れる処理（`setup`）は作らない

利用者の要求（2026-09-23）で一度 `setup` を設計したが、決定 1 で tmux を前提から外したため、確かめる対象も
入れる設定も無くなった。前景の中継が要るのは端末と Python 3 だけで、`run` が始める前に自分で確かめ、
欠けていれば今までどおりの起動へ落ちる（決定 2）。利用者の設定ファイルは書き換えない。
