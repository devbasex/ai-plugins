## I68 の扱い

I68 の文は「ランナーが `NDF_FACTORY_RUN=1`・`NDF_ORGANIZER_DIR`・`NDF_ORGANIZER_LANE` を必ず渡す」を含む。受け入れ条件 16 は文を変えないことを求める。語の決定 1 の後、この「ランナー」は新しい意味（マシン）では読めない。

**I68 の行の直後に、注の 1 行を置く。** 「この行のランナーはランナーのエージェントを指す（語の決定の前に書いた不変条件の文を変えないため）」。文そのものは変えない。読み手は注で意味を引ける。`glossary.py check` は確定仕様を照合の対象にしない（`.ndf/glossary.json` の `check.paths` は `issues/` の設計の文書だけ）。そのため、旧い意味の行が検査を落とすことはない。

## 実行の形の追加

並行開発のモデルの文書の「実行の形ごとの違い」の表に列「E: Factory + 開発者ごとの手元のマシン（チーム開発）」を足す。値は nd-factory#54 の受け入れ条件の案から読んだ。

| 観点 | E: チーム開発 |
| --- | --- |
| 人への窓口 | Web の一覧と「自身のマシン」の画面。開発者は自分のマシンのレーンを見て止める |
| オーガナイザー | Factory のオーガナイザー。開発者の手元で 1 台の中のオーガナイザーを起動しない |
| レーンの入れ物 | 実行ジョブ。担当者のマシンへ優先して渡し、ランナーのエージェントが区間ごとに `claude -p` を起動する |
| 待つ間 | ジョブを終え、答えで次のジョブを起こす。次のジョブは担当者の別のマシンでもよい |
| レーンを起こす者 | 実行の制御が担当者のマシンへ渡す。担当者が `anyone` なら枠の空いたマシン |
| 同時の数 | 開発者ごとのマシンの枠の和 |
| 状態の置き場 | サービスの表。手元の置き場は実行の間だけ |
| 資源の監視の範囲 | マシンごとに見て、まとめはサービスが持つ（予定） |
| アラートの宛先 | 同じマシンの conductor だけ |
| ラインが止まるとき | Factory のオーガナイザーが処理する。開発者の 1 台の異常でラインを止めるかは C と同じく別の判断 |
| 重い処理の枠 | マシンごとに 1 つ |
| 後片付け | 手元の置き場は要る。ランナーのエージェントがジョブの終わりに行う（予定） |
| OOM のとき | 1 台の中だけに響く。ジョブを同じ開発者の別のマシンへ回せる |

オーガナイザーの定義（文書の「層はいくつあるか」の表の行）へ、次の文を足す。「チーム開発の形（E）では、開発者の操作の窓口は Web 画面で、開発者の手元で 1 台の中のオーガナイザーを起動しない（確定仕様 `ndf-factory-organizer.md` の I68 と同じ）。手元で claude を対話に使うことは妨げない」。図の「B・C」の箱に E を足し、「形が増えて変わる判断」の 3 つ目に E を含める。
