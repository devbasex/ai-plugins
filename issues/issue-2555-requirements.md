## 目的

- 正式版の変更履歴（`CHANGELOG.md` の版の節）と GitHub Release の本文が、その版のリリースタグに入っている変更だけを載せる状態にする
- 版の節を組むリリースの工程が、出す版に入っていない PR を載せない状態にする（同じ食い違いを再び作らない）

## 前提

- 前提 1: リリースタグとタグが指す中身は書き換えない（履歴の書き換えは戻せない操作に当たる）。直すのは develop の `CHANGELOG.md` と GitHub Release の本文で、正式版の利用者には次の正式版の配布で届く
- 前提 2: 版の節に並べる PR の範囲の終点は、出す版のコミット（リリースのブランチの先頭）とする。承認された版のコミットとリリースのブランチの先頭が一致することは、既存のリリースの工程が保つ
- 前提 3: 版の節を組む経路は `release-steps.py` の `changelog`・`notes`・`approval-facts` だけである。範囲の終点を正せば、この経路で作る節にタグの外の PR は載らない。版の節とタグを突き合わせる独立した検査は、同じ判定を 2 か所に持つことになるため足さない
- 前提 4: 正式版を出さなかった版の節の箇条は、次の正式版の範囲（前のリリースタグから出す版のコミットまで）に必ず含まれる。そのため、正式版を出したときに、前のリリースタグより新しくタグの無い版の節を消しても、変更の記載は失われない

## 対象範囲

含む:
- 版の節と承認資料の「含む PR」に並べる PR の範囲の終点を、出す版のコミットにする
- リリースタグのある版の節へ、別の版の工程が行を足さないようにする
- 正式版を出したとき、前のリリースタグより新しくタグの無い版の節を消す
- develop の `CHANGELOG.md` の既存の食い違い（10.27.2・10.27.21 の節の 5 組と、10.27.22・10.27.23 の節）を直す
- GitHub Release `ndf--v10.27.21` の本文から #2542・#2543 の 4 行を外す

含まない:
- リリースタグの付け替えと、タグが指すコミットの `CHANGELOG.md` の書き換え
- マージコミットから辿れない 232 組（10.9.1 以前の版など。下の「未確認・残リスク」）の検証
- タグの無い古い版の節（10.27.0・10.27.4・10.27.12・10.27.13）の整理。前のリリースタグより古いため、受け入れ条件 7 の対象にならない
- 版の節とリリースタグを突き合わせる独立した検査の追加（前提 3）
