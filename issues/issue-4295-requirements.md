## 何が起きたか

2026-11-22 から 11-24 にかけて、並列の計画（同時に進める複数のレーンの一覧）で、実際には別のファイルしか変えないレーンどうしが、触る場所の宣言（`touches`）が重なるという理由で待たされた。宣言はディレクトリ単位で書かれているためである。

- 計画 p12 では、文脈の切り替えの閾値を 2 つの値にそろえる課題（ https://github.com/devbasex/ai-plugins/issues/3995 ）の計画の工程を 11-22 11:53 JST に終えてから、実装の最初の単位の PR（ https://github.com/devbasex/ai-plugins/pull/4216 ）を出すまで、約 24 時間何もしていない。中継のアカウントの切り替えを直すレーン lracct（ https://github.com/devbasex/ai-plugins/issues/3604 ）と `relay/` で宣言が重なったためで、実装そのものは約 5 時間で終わった
- 計画 p9 では、レーン lz1-contract が `plugins/ndf/src/` 全体を宣言している。2026-11-24 に中継のラッパーを直すレーン lrelay（ https://github.com/devbasex/ai-plugins/issues/4049 ・ https://github.com/devbasex/ai-plugins/issues/4068 ）を足したときも、変えるファイルが重ならないかを確かめる手段が無く、`after`（前のレーンの終わりを待つ指定）で順序を付けるしかなかった

逆向きのことも起きた。p9 のレーン lsplit（ https://github.com/devbasex/ai-plugins/issues/3877 ・ https://github.com/devbasex/ai-plugins/issues/3908 ・ https://github.com/devbasex/ai-plugins/issues/4036 ）は `progress/`・`core/plan/`・`contracts/workflow/` などを宣言したが、マージした単位の PR は宣言の外の `domains/relay/hub.py`・`domains/hooks/guards/relay_mark.py`・`core/worker.py`・`contracts/worker/kinds.json` なども変えた。同じ時間帯に動いていたほかのレーン（p12 の lctx の `hooks/`、後から足した lrelay の `relay/`）とのこの重なりは、だれにも知らされなかった。

利用者はこの日、宣言の外のファイルを変えることを禁じる方向では解かないと決めた（2026-11-24）。重複の排除・モジュール化・ライブラリ化のために触る範囲が広がるのは、より重要な方針に沿った動きだからである。

## 種類

機能追加（今の約束は「宣言した触る場所が重なる行を同時に動かさない」だけで、宣言を詳細設計から出すことと、実際に変えたファイルで重なりを知らせることは約束に無い）

## 今の姿

並列の計画の各レーンは、触る場所（パスか glob の並び）を `touches` に持つ。書き方は [parallel-plan.md](https://github.com/devbasex/ai-plugins/blob/main/plugins/ndf/skills/issue-plan-strategy/references/parallel-plan.md) にある。

- 計画の検査（`ndf lanes init`・`start`・`set`・`lane add`）は、前後の鎖（`after` と行の並び）が無い別のレーンの行どうしで触る場所が重なれば、誤り（規則 I13）として断る（[parallel-checks.md の「レーンの間の重なり」](https://github.com/devbasex/ai-plugins/blob/main/plugins/ndf/skills/development-workflow/references/parallel-checks.md)）
- 重なりの判定は接頭辞か glob で行う。`relay/` と `relay/hub.py` は重なる（`plugins/ndf/src/ndf/progress/lane/rules.py` の `touch_hit`）
- `touches` はレーンに付き、行（スプリント）には付かない（`plugins/ndf/src/ndf/progress/lane/types.py` の `LaneSpec`）
- 宣言を直すのはオーガナイザー（並列の計画のまとめ役の conductor）で、`ndf lanes set <計画> <レーン> --touches ...` を手で打つ
- 判定が見るのは宣言だけで、単位の PR が実際に変えたファイルは見ない
- 詳細設計書は地図（ファイル配置と依存の向き）を持つ（[document-roles.md](https://github.com/devbasex/ai-plugins/blob/main/plugins/ndf/skills/requirements-design/references/document-roles.md) の「文書ごとの読み手と順序」）。今は地図を `touches` に使っていない

確かめたこと: `plugins/ndf/tests/progress/test_lane.py` の `test_touch_hit`・`test_touch_overlap_errors_as_they_are_now` が今の判定を縛っている（2026-11-24、main `ea401b56a` で通過）。

## 何を足すか・変えるか

| --- | --- | --- |
| 宣言の出所 | オーガナイザーが計画を組むときにディレクトリ単位で書き、手で直す | 設計がマージされたレーンは、設計で確定した変えるファイルの一覧に置き換わる。一覧は、設計書の「設計の結果」の触るファイルと、詳細設計書を別のファイルにしたときはその地図のファイルを合わせたものである |

## 今の利用者への影響と互換

- 宣言が狭まるので、今は I13 で断られる組の一部が同時に実装へ進めるようになる
- 宣言が広がる（宣言の外を変えた）ときは、知らせを受けたオーガナイザーが順序を決める。知らせを受けてもレーンは止まらない
- 計画の JSON の形（`touches` の並び）は変えない

## なぜ困るか

ディレクトリ単位の宣言のままでは、変えるファイルが重ならないレーンも片方が丸ごと待つ。p12 では実装 5 時間に対して 24 時間を待ちに使った。並列開発の方針（処理待ちを作らない、 https://github.com/devbasex/ai-plugins/issues/4069 ）に反する。

一方、宣言の外へ広がった変更は、ほかのレーンと重なっても知らされない。マージの順で衝突して初めて気づくことになる。

## 目的

- レーンの触る場所を、詳細設計で確定したファイルの単位で持ち、見かけの重なりでレーンを待たせない
- 実装の途中で触る範囲が広がっても止めず、広がった結果ほかのレーンと重なれば、オーガナイザーがすぐ知って順序を決められる

## 対象範囲

含む:
- 設計承認ゲートの後に、設計で確定した変えるファイル（「設計の結果」と、別のファイルにした詳細設計書の地図）でレーンの `touches` をファイル単位で置き換えること
- 単位の PR で実際に変えたファイルをレーンの行に記録し、ほかのレーンと重なればオーガナイザーへ知らせること（計画をまたぐレーンも含む）。記録は I13 の判定に入れない
- 設計の結果が無い・読めないとき、または別のファイルにした詳細設計書の地図を読めないときに、今の宣言のまま動くこと
- 行（スプリント）より細かく、レビューの単位ごとに触る場所を持つかを設計で比べること（採るなら受け入れ条件 7 を満たす）
- 先に宣言して排他を掛ける形と、衝突したら base-sync（ベースブランチの取り込み）と CI で直す形の得失を、設計で比べること

含まない:
- 設計のフェーズの排他。設計のフェーズは `touches` と I13 の外に置くと、開発計画を 7 つのフェーズに分ける課題（ https://github.com/devbasex/ai-plugins/issues/4050 ）が決める。この課題は #4050 が前提とする「実装のフェーズの手前で `touches` が確定している」の中身を受け持つ
- 待ちの種類ごとの時間の計測（ https://github.com/devbasex/ai-plugins/issues/4293 ）
- 宣言の外のファイルを変えることを禁じる・失敗にする決まり
- スプリントの中の実装のプランどうしの重なりの判定（`ndf plan queue`。 https://github.com/devbasex/ai-plugins/issues/2037 が扱う）

## 前提

- 前提 1: 本当に重なる組の順序は残す。lsplit の単位の PR（ https://github.com/devbasex/ai-plugins/pull/4289 ・ https://github.com/devbasex/ai-plugins/pull/4291 ・ https://github.com/devbasex/ai-plugins/pull/4297 ）と、#4050 を扱うレーン lphase の詳細設計の地図は 14 ファイル（`progress/plan/run.py`・`progress/lane/launch.py` など）で重なり、lphase を lsplit の後に置く順序は正しい。ファイル単位にしても順序が要る組は残り、減るのは見かけの重なりだけである
- 前提 2: 知らせを受けたオーガナイザーは、`after` で順序を付け直すか、そのまま進めて base-sync で直すかを選ぶ。どちらを選ぶかはオーガナイザーが決め、仕組みは決めない

> 1. **詳細設計の地図（変えるファイルの一覧）から、レーンと行の触る場所をファイル単位で出す。** 地図は `design` の手順「詳細設計を書く」が既に書いている。設計承認ゲートの後に、機械でレーンの touches を置き換える（今はオーガナイザーが `ndf lanes set` で手で直している）
> 2. **行（スプリント）より細かく、レビューの単位ごとに触る場所を持ち、重なる単位だけを待たせる。** 重ならない単位から実装を始められる
>
> 3. **設計のフェーズの排他は #4050 が持つ（この課題の範囲の外）。** #4050 の設計（`issues/issue-4050-design.md` の「7 つのフェーズと排他」）は、設計のフェーズを排他 `none`（`touches` と I13 の外）とし、`after` と `touches` を実装のフェーズの手前でだけ照らす。p9 の lz1-contract が設計の前から `plugins/ndf/src/` などを宣言して並行開発を事実上止めていた件（2026-11-24 の利用者の指摘）は、#4050 が入るまでオーガナイザーが手で touches を設計文書だけに狭めて回避している。**この課題が受け持つのは、#4050 の「`touches` が確定している」の中身（詳細設計の地図からファイル単位で決める）である**
> 4. **（比べる案）先に宣言して排他を掛けるのをやめ、衝突したら直す形にする。** git は行の単位で 3 方向のマージを行うので、同じディレクトリの別のファイル・同じファイルの別の箇所は衝突しない。排他は、多くのレーンが書き足すファイル（`contracts/limits.json`・`contracts/domains/*.json`・用語集など）だけに掛け、残りはスプリントブランチの base-sync と CI に任せる。得失（衝突の直しの費用・CI の待ち）を設計で比べる
>
> ## 受け入れ条件（案）
>
> 1. 設計がマージされたレーンの touches が、詳細設計の地図のファイルの一覧に置き換わる
> 1a. **地図や宣言の外のファイルを変えても、単位を落とさない・止めない。** 単位の PR の差分のファイルを機械が拾ってレーンの touches へ足し、同じ時間帯に動くほかのレーン（計画をまたぐものを含む）の touches と重なればオーガナイザーへ知らせる。知らされたオーガナイザーは、どちらを先にマージするかを `after` で付け直すか、そのまま進めて base-sync で直すかを決める
> 1b. 重複の排除・モジュール化・ライブラリ化のために範囲を広げることを、手順書・hook・検査のどれも禁じない（禁じる決まりを足さない）
> 2. 地図が無い・読めないときは、今の宣言のまま動く
> 3. 2 本のレーンの地図が重ならなければ、ディレクトリが同じでも同時に実装へ進める
> 4. （2 の案を採るなら）重なる単位だけが待ち、ほかの単位は先に進む
