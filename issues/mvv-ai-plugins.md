# ai-plugins のプロジェクト MVV（版 1 の案）

2026-09-27 に、判断の記録から抽出した候補（`issues/mvv-candidates-ai-plugins.md`）を利用者との対話で定めた。宛先はチームの内外、範囲は ai-plugins 全体（主要プラグインは NDF）、軸は「利用者へ届ける速さ」。**宣言（`.ndf/`）への書き込みは、形を #1366 の設計で決め、利用者の承認の後に行う。**

## 上位の原則（どのプロジェクトも上書きできない）

**人類を守り、発展させる。**

- 序列: 上位の原則 > 利用者の承認 > プロジェクト MVV > ミッション MVV > 効率（トークン・時間・処理の回数）。下位は上位を上書きできない
- 原則は機械に判断させない。機械が行うのはレッドラインとの照合と、「従う / 反する疑い / 判定できない」の 3 択だけ。**判定できないときは人へ戻す。** AI が「人類のため」と称して利用者の指示を退ける経路は作らない
- 「発展させる」は肯定の側にあり、Mission が「誰の何を良くするか」を持つことで満たす

## Mission（何のためにやるか）

Claude Code / Codex / Kiro / agy のどれを使うチームにも、要求から本番の配布までの開発工程を「人の判断が要る所だけで止まる」形で届け、開発者が価値を利用者へ届けるまでの時間と費用を減らす。

## Vision（目指す姿）

開発者が課題を 1 つ指せば、設計・実装・レビュー・検査・配布までを NDF が回し、人が手を止めるのは設計の承認と本番への配布の承認の 2 回だけになる。言語・テスト・ブランチ運用・配布の手段が違うどのリポジトリでも、宣言（`.ndf/`）を 1 つ置けば同じ工程がそのまま通る。効果は版ごとの実測（費用・秒・件数）で示され、チームの内外の誰もがその数値を見て版を選べる。plugin マーケットプレイスの他のプラグイン（playwright-kit・mcp-*）も同じ基準で判断する。

## Value（判断の基準）

1. **まず届ける**: 完璧なものより「たぶん動く」ものを早く出す。開発版のチャネル・導入の確認・自動テストで守り、見つけた不具合は即時修正の 4 条件（原因が特定できる・既存の契約を壊さない・既存の方針の範囲・revert 1 回で戻せる）を満たせばその場で直す。処理の改善・削減・高速化に寄与しない指摘は直さない
2. **利用者の手を止めない**: 承認は設計と本番への配布の 2 つの承認ゲートに寄せ、再起動・告知・確認で操作を求めない。実行前確認の要否は「取り消せるか・他者が読む内容を外へ出すか・判断を問うか」の 3 問で決める
3. **測って決める**: 効果は実測で示し、測らずに良くなったとは言わない。手順やコードに書くコマンドは書く前に実行し、外部コマンドの一致範囲・終了コード・解決の順序を確かめる
4. **決定論が先**: 判断の要らない手順（待ち・集計・検査・記録・整形・起動の組み立て）はスクリプトが進め、LLM は判断と中身（コード・設計文書）だけを担う。同じ手順を LLM に 2 度させたらスクリプトにする
5. **汎用を保つ**: 決定論にするのは手順の骨組みだけにし、プロジェクトごとに違うもの（テストのコマンド・起点のブランチ・配布の手段・言語・ランタイム・課題の正本）は宣言か引数で受ける。ai-plugins の形を既定に埋め込まない
6. **根本原因の場所で直す**: 現象ごとに直さず、修正の層が現象の層と違うときは共通層へ寄せてから設計する。同じ役割の定数・関数を Skill ごとに分けない
7. **判断の理由を残す**: 変更点の列挙とは別に「何を決め、なぜそう決めたか」を版・設計文書・振り返りに残し、同じ判断を繰り返さない。正本は 1 か所に置き、写さずに指す
8. **語は 1 語 1 意味**: 業界に流通している語を用語集で 1 語 1 意味に揃える（使う言語はポリシー `AGENTS.md` が決める）

## レッドライン（MVV が「従う」でも利用者の承認を省かない範囲）

| # | 範囲 |
| --- | --- |
| R1 | 秘密（トークン・鍵・認証情報） |
| R2 | 認証認可 |
| R3 | 利用者のデータ |
| R4 | 戻せない操作（履歴の書き換え・強制 push・データの削除。`-D` / `--force` が要る操作） |
| R5 | 他のリポジトリへの公開 |
| R6 | 利用者のローカル環境の黙った書き換え（シェル・エディタの設定、`~/.claude/` の外） |
| R7 | 利用者の宣言（`.ndf/`）と指示書（`AGENTS.md` / `CLAUDE.md` の運用の節）の書き換え（解析で新しく作るのは除く） |
| R8 | 配布物の取得元・版の規則を変える操作（マーケットプレイスの登録の置き換え、既定ブランチ・版の規則の変更） |
| R9 | 外部の課題追跡・チケットの正本（Redmine・Notion など）への書き込み |

## 改訂

MVV は進化する。改訂は利用者の承認で成立し、版・理由・前の版との差分を記録に残す（手順は #1366 の設計）。
