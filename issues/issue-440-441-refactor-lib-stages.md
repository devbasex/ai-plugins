# #440 / #441 refactor_lib の分割の段階 2 と段階 3

**2 件を 1 つの記録にする。** 段階 2（テストをモジュール境界へ寄せる）が終わるまで段階 3
（再エクスポートを外す）へ進めないため、受け入れ条件が連続する。**Pull Request は分ける**
（段階ごとに保証するものが違う）。

## 依頼

> **#438 の分割は「テストを変えない」ことを条件に行った。** その結果、テストがモジュール
> 境界を検証していない。（#440）
>
> **`refactor.py` の再エクスポートと `__setattr__` を外し、各モジュールが公開する名前を
> 絞る。** モジュール間の依存が一方向であることを検査で固定する。（#441）

## 目的

**分割を「名前空間が 1 つのまま」から「境界が守られる」状態へ進める。** 段階 1（#438）は
振る舞いを固定するために再エクスポートを使った。そのままでは、分けたことが構造として効かない。

## 段階ごとに保証するもの

| 段階 | 課題 | 何を変えるか | 何が保証されるか | テスト |
| --- | --- | --- | --- | --- |
| 2 | #440 | テストが読むモジュール | **境界がテストで検証される** | 変える（実装は変えない） |
| 3 | #441 | 再エクスポートと `__setattr__` | **公開 API が確定する** | 変えない |

**混ぜない。** 同じ Pull Request に入れると、テストが落ちたときに原因が実装の変更なのか
読み込みの経路の変更なのかを分けられない。

## 受け入れ条件（段階 2 / #440）

- [ ] テストがモジュールごとに分かれ、そのモジュールの公開 API を通して呼ぶ
- [ ] `conftest.py` がモジュールごとのフィクスチャを持つ
- [ ] **`assert` の中身が変わっていない**（差分で確かめ、変えた件数を 0 として示す）
- [ ] テストが通る（件数は着手の時点で数え直す）
- [ ] **モジュールをまたいで渡している非公開名のうち、テストが触るものが特定されている**
- [ ] 検査 8 本が終了コード 0

## 受け入れ条件（段階 3 / #441）

- [ ] `refactor.py` の再エクスポートが無くなり、入口が argparse と main だけになる
- [ ] **`__setattr__` の仕掛けが無くなる**
- [ ] 各モジュールの外から呼ばれない補助が `_` 始まりになっている
- [ ] **モジュールをまたいで渡している非公開名が 0 個**
- [ ] **モジュール間の依存が一方向であることを機械で確かめる検査がある**（循環が無いこと・
      モジュールをまたぐ非公開名が無いことの 2 つを見る）
- [ ] `commands` 層どうしの横の依存が解消されている
- [ ] テストが通る
- [ ] `uv run --script refactor.py` が動く
- [ ] 検査 8 本が終了コード 0

## 検査を置く理由

**人が見ている限り、次の変更でまた混ざる。** #438 で循環が見つかったのは、責務のコメントが
依存を反映していなかったためである。同じことは繰り返される。

## 範囲

| 含む | 含まない |
| --- | --- |
| テストの読み込みの経路 | テストが何を確かめるか（`assert` の中身） |
| 再エクスポートと `__setattr__` の除去 | 実装の振る舞い |
| 依存の一方向性の検査 | 語彙と方法論の移動（#443 / #444） |
