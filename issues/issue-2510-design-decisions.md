# #2510 の設計: 決定の記録

設計文書の本体は [issue-2510-design.md](issue-2510-design.md) にある。

## 決定 1: 設計のプランの入力の正本を 1 つにするため、ループの記録から周回ごとに入力ファイルを書き出して渡す

設計のプランは `supervise.py new sprint` が組み、ループの記録を読まない。記録から書き出したファイルのパスを引数で渡せば、プランの組み立ては記録の形を知らずに済み、MVV 判定と表の突き合わせも同じファイルを読める。課題の本文の履歴の節は GitHub の書き込みに失敗しうるため、入力にしない（要求の前提 5）。

プランの組み立てが課題の本文を読む形は採らない。本文の節は書き込みの失敗と人の編集で揃わなくなり、#2338 の回避で本文の節が読まれなかった経路と同じ弱さを持つ。

根拠: Value 7 / Value 5（MVV 版 5）

## 決定 2: 表の書き手を 1 つにするため、指摘への対応の表は設計のステップの worker が設計文書へ書き、突き合わせのコマンドが設計 PR の本文へ写す

pr のステップは既にある設計 PR の本文を作り直すため、worker が本文へ直接書いた表は次の pr のステップで消える。設計文書に置けば、レビューの直しでも同じ差分で直り、MVV 判定も設計文書の材料として読む。本文へのコピーは、最後の送りの後の突き合わせのステップが行う。

pr のステップの材料に表を足す形は採らない。pr のステップは設計 PR を出す時点で 1 回しか本文を作らず、レビューの直しで変わった表を拾えない。

根拠: Value 5 / Value 8（MVV 版 5）

## 決定 3: 機械が確かめられる範囲に絞るため、表の突き合わせは項目ごとの行と欄の有無だけを見て、中身が指摘を満たすかは MVV 判定に任せる

行と欄の有無は決まった手順で判定でき、スクリプトが持てる。中身の充足は判断であり、既に承認ゲート 1 の手前にある MVV 判定に指摘の全文と問いを足せば、新しい判定の工程を作らずに済む。MVV 判定が「従わない」を返せば人へ問われる。

中身を判定する AI のステップを別に足す形は採らない。MVV 判定と同じ材料で同じ問いを 2 回問うことになる。

根拠: Value 5 / Value 3（MVV 版 5）

## 決定 4: 表の欠けが MVV 判定で通らないようにするため、プランの中の突き合わせが欠けを見つけたら MVV 判定へ進まず承認ゲートで終える

MVV 判定が「従う」を返すと設計 PR はマージされ、人の判断待ちへ移す関数を通らない。#2494 はこの経路で指摘を反映しないまま通った。プランの中で欠けを見つけて承認ゲートで終えれば、周回の締めの共通の経路（人の判断待ちへ移す関数）が自動の出し直しを決める。自動で戻すかの判断は締めの 1 か所だけに置く。

プランの中で自動の出し直しまで決める形は採らない。上限の判定にループの記録が要り、プランはそれを読まない。

根拠: Value 7（MVV 版 5）

## 決定 5: 指摘を満たす設計を 1 回で揃えやすくするため、要求と設計の起動指示へすべての回の指摘の全文を埋め込む

起動指示にファイルのパスだけを書くと、worker が読まない経路が残る（#2338 の回避で本文の節が読まれなかった）。全文と項目の識別子を起動指示に置き、「この指摘を満たすように直す。満たせない項目は理由を書く」と、設計文書へ表を置く指示を添える。

最新の 1 回だけを渡す形は採らない。前の回で満たした項目を次の回で崩さないため（要求の前提 1）。

根拠: Value 2 / Value 7（MVV 版 5）

## 決定 6: 課題の本文に指摘の全文を 2 か所持たないため、判断待ちの節は履歴の節の回を指す 1 行だけを載せる

判断待ちの節は次に人の判断待ちへ移すときに書き直される。全文を履歴の節へ移し、判断待ちの節は「指摘: 節『出し直しの指摘の履歴』の開発ループ <名前> の第 N 回」と書けば、正本が本文の中でも 1 か所になる。

根拠: Value 8（MVV 版 5）

## 決定 7: 答えの種類ごとの手順の正本を 1 つにするため、表を `loop.md` に置き、`parallel.md` から指す

答えを読んで動くのはどちらの場合もループ（レーンもループである）で、`parallel.md` が持つのは答えを送る側の手順である。正本を読む側に置けば、手順の変更で直す文書が 1 つになる。

根拠: Value 8（MVV 版 5）

## 決定 8: 別のループで送った指摘も満たすため、出し直しの指摘の入力はすべてのループの記録から回を集め、回をループの名前と回数の組で識別する

要求の前提 1 は、別の開発ループで送った回も入力に含めると決めた。ループが替わると前のループの指示が届かない形は、受け入れ条件 12 と同じ根を持つ。回数はループごとに 1 から数えるため、項目の識別子にループの名前を入れて衝突を避ける。自動の出し直しの上限は、いま回っているループの記録の直前の行で数える。上限は人の出し直しの 1 回ごとに効くもので、前のループの回まで遡る必要が無いためである。

いま回っているループの回だけを集める形は採らない。前提 1 に合わず、ループを替えた直後の設計が前の指摘を読まない。

根拠: Value 7 / Value 2（MVV 版 5）

## 決定 9: 答えを捨てないため、止まったループのレーンも起こす対象に入れ、当てられない答えは区分 `unmatched` の問いにする

#2474 の原因は、止まったループのレーンを起こすことが、オーガナイザーが `metrics.next` の 1 行を打つことだけに頼っていた点にある（[「#2474 の承認が当たらなかった原因」](issue-2510-design.md#2474-の承認が当たらなかった原因)）。1 スプリントのレーンには、耐久ワークフローが起こす 1 行を以後の知らせに添え続ける仕組み（`revive`・`wake`）が既にある。ループのレーンもこの対象に入れれば、新しい経路を作らずに済む。

置き換えた id への答えは、問いの一覧の `replaced` から持ち主を引き、今の問いへの答えと同じく持ち主を起こす。問い直した後に止まったレーンへも答えが届き、前の印から取り込みだけなら当たる。当てられない答え（一覧にも `replaced` にも無い id・前の印から取り込みだけでない・今の依頼への承認を受けた後に先頭が取り込み以外で動いて問い直す・前のループへ当てられない）は、今は耐久ワークフローの受け取りか、レーンの読み取りで黙って捨てられる。区分 `unmatched` の問いにすれば、オーガナイザーが `parallel.py wait` の `questions` で知り、答えるまで計画は終わらない。答えのイベント自体は立てたまま残すため、後から同じ id の依頼が届いても当たる。

耐久ワークフローが自分でレーンを起こし直す形は採らない。今の決まりは、レーンを起こす操作をオーガナイザーの 1 行に置いている（`parallel.md` の「オーガナイザーが打つのは…終わったレーンを起こす 1 行だけ」）。この課題では起こす 1 行の届け方だけを直し、担い手は変えない。

根拠: Value 7 / Vision（MVV 版 5）

## 決定 10: 問い直しの判断と答えの当て方をそろえるため、取り込みのコミットだけかの判定を承認の依頼の部品の 1 つの関数に置く

要求の非機能の条件は、依頼を送り直すかの判断と答えを当てるかの判断が同じ関数を使うことを求める。レーンの問い直し・レーンの前の依頼への答え・耐久ワークフローの前のループへの答えの 3 か所が、この関数だけを呼ぶ。判定は git の履歴と差分で決まり、AI の判断を要らない。

判定は、設計 PR のブランチの上のコミット（`--first-parent`）だけを見る。取り込んだ起点ブランチのコミットは、親を辿ると範囲に入るため、ブランチの上だけに絞る。そのうえで、設計文書と要求のコピー（`issues/issue-<課題>-*.md`）の中身が変わらないことを確かめる。

コミットの題（`Merge branch 'develop'` など）で判定する形は採らない。題は書き換えられ、要求の前提 7 の「中身が同じ」を確かめられない。

根拠: Value 5 / Value 7（MVV 版 5）

## 決定 11: 前のループの待ちを埋もれさせず、その記録の持ち主を変えないため、耐久ワークフローとレーンが同じ関数で送り、答えは `loop answer` で当てる

要求の未決は、送る担い手と、同じ行を 2 回出さない方法を設計に委ねた。開始時は、まだレーンが周回の境を通っていないため、耐久ワークフローが送る。周回の境はレーンにしか無いため、レーンが送る。どちらも承認の依頼の部品の同じ関数で依頼を作る。依頼の id を行（ループの名前・課題・周回）から決めるため、両方から送っても、耐久ワークフローの受け取りが同じ id を 1 つにまとめる（I11）。

答えを当てるのは耐久ワークフローである。前のループにはレーンが無く、周回の境で答えを読む持ち主がいない。`loop answer` を呼べば、記録の書き込みはそのループの集約の関数のまま、要求の「答えを当てる以外は前のループの記録を書き換えない」に収まる。

前のループの待ちの問いは、計画を終えることを止めない（I12）。前のループの判断は計画の仕事の外にあり、止めると計画の終わりが計画の外の判断に縛られる。終えたときの要約に並べて、埋もれないようにする。

レーンが前のループの行を自分の記録へ写す形は採らない。要求の対象範囲が「前のループの記録を計画のレーンへ移す・合わせること」を含まないとしている。

根拠: Value 2 / Value 7（MVV 版 5）

## 決定 12: 自動で出し直す上限は、人の出し直し 1 回につき 1 回とする

利用者の決定である（2026-11-05 の承認ゲート 1）。設計の不変条件 I7 と受け入れ条件 5 の上限（1 回）はこの決定による。

根拠: 利用者の決定（2026-11-05 の承認ゲート 1）
