# #2343: 上限と再試行の方針を 1 つの宣言に集め、同じ失敗の打ち直しを止める

正は課題の本文（#2343）で、この文書はその写しである。`spec-copy.py write` で作り直す。手で直さない。

大方針 #2335（異常系・ログ・回復とデータ・入出力の形を 1 つの実行の核へ集める）の柱の 1 本。子の課題は、この柱の仕組みがそろえば解消する可能性があるものである。

## 具体例

2026-10-31 の本番の配布のプランで、`release` のステップが同じ CI の失敗（run 38353378585 の `runtime-smoke (agy)`）で落ち続けた。プランの判定役（judge）は 7 回とも「外部の待ちの揺れなので同じステップをもう一度」と返し、ステップの上限まで 366 秒、同じ失敗した run を読み直した（#1983）。打ち直しの回数は数えていたが、**原因が前回と同じかは誰も見ていなかった。**

2026-10-30 には、cross-refactoring の最終ゲートの CI の待ちが、上限 1154 秒のうち 112 秒を残して「結論を得られない」で終わった。同じコミットのチェックはすべて成功していた（#2224）。待ちの部品が、上限の時刻に最後の照会を打たずに止まるためである。

どちらも、上限と再試行の値と止め方が、それぞれの部品の中に書かれていることから起きる。この課題が終わると、上限と再試行の方針は 1 つの宣言から読まれ、同じ原因の打ち直しは決まった回数で止まり、止まった理由が結果に出る。

## 目的

- NDF のスクリプトが、上限の値と再試行の回数・間隔をそれぞれ自分で持たずに済む状態にする。値を変えるときに直す場所が 1 つになり、入口の契約から上限をたどれる
- 同じ原因の失敗を上限まで打ち直さない。打ち直しが結果を変えないと分かった時点で止まり、止まった理由（原因と回数）が結果に残るので、人へ戻ったときに追い直さずに済む
- 待ちが宣言した上限を使い切ってから止まる。上限より前に「結論を得られない」で止まらない

## 対象範囲

含む:

- 上限の宣言（`plugins/ndf/contracts/limits.json`）を作り、`limits.py` の表と、各部品の上限・再試行の回数・待ちの間隔の既定値をそこへ移す
- 構造チェック（`scripts/check-script-structure.py`）に、上限・再試行の数字のリテラルの検査と、`lib/waits.py` の外の再試行のループの検査を足す
- 再試行のループを持つ関数（2026-11-04 の時点で `supervise_lib/paths.py` の `_add_worktree_with_retry`、`lib/post_queue.py` の `retry` など）を `lib/waits.py` の呼び出しへ置き換える
- 原因の鍵を作り、同じ原因の打ち直しを宣言の回数で止める仕組み。呼び出しの再試行（`lib/waits.py`）と、プランの判定役が返すステップの打ち直しの両方に当てる
- 待ちが上限の時刻に最後の照会を打ってから止まり、止まった理由を結果に出すこと
- 子の課題 9 件の再現の手順を通し、閉じるか理由つきで残すかを本文に記録すること

含まない:

- 上限の値そのものの見直し（例: cross-refactoring の予算の配分を変える #2457）。この柱は値の置き場と当て方をそろえ、値は今の既定値のまま移す
- 上書きの経路（引数・環境変数・設定）を新しく作ること。#2341（P8）が受け持つ
- 期限で打ち切った実行の持ち主の記録と後片付け。#2342（P3）が受け持つ
- 子の課題を 1 件ずつ直すこと。仕組みを入れた後に再現の手順を通して残ったものは、理由を書いて残す
- 型 D のうちマイルストーン 30 の外にある 4 件（#1872・#1919・#2154・#2251）

## 用語

| 用語 | 意味 |
| --- | --- |
| 上限の宣言 | 上限の秒・再試行の回数・待ちの間隔・同じ原因の上限を、方針の名前ごとに持つ 1 つのファイル（`plugins/ndf/contracts/limits.json`） |
| 方針の名前 | 上限の宣言の 1 行を指す名前。入口の契約と部品の呼び出しが、値でなくこの名前で上限を引く |
| 原因の鍵 | 失敗が前回と同じ原因かを見る値。例外の型と、数字・時刻・パスを伏せた失敗の理由の文から作る |
| 再試行 | 失敗した同じ呼び出しを、同じプロセスの中で間隔を置いて打ち直すこと |
| ステップの打ち直し | プランの判定役が、失敗したステップを同じステップのまま流し直すと返すこと |

## 受け入れ条件

- [ ] 1. 上限（時間・予算・待ち）・再試行の回数・待ちの間隔の既定値は上限の宣言（`plugins/ndf/contracts/limits.json`）1 か所にあり、`limits.py` と各部品はそこから値を読む。宣言の値を 1 つ変えると、その方針の名前を使う部品の振る舞いが変わる（テストで、宣言を差し替えて部品の上限が変わることを見る）
- [ ] 2. テストと実験版を除く `plugins/ndf/` の Python のコードに、`timeout=<数字>` の直書きと、上限・再試行の回数・待ちの間隔の定数への数字のリテラルがあると、構造チェック（`python3 scripts/check-script-structure.py`）が終了コード 1 で落とす。変更の後の develop では 0 で通る
- [ ] 3. 再試行のループは `lib/waits.py` だけにある。`lib/waits.py` の外で再試行のループを書くと構造チェックが落とす。`tenacity` を import するのは `lib/waits.py` だけである
- [ ] 4. 同じ原因の鍵の失敗が上限の宣言の回数に達すると、呼び出しの再試行は止まり、待ちの合計の上限まで回らない。原因の鍵が変わった失敗は別に数える（テストで、同じ理由の失敗を続けると宣言の回数で止まり、理由の文の数字だけが違う失敗も同じ原因として数えることを見る）
- [ ] 5. 止まったときの結果は `stopped` で、理由に原因の鍵の要旨と回数が出る（例: 「同じ原因（`CI の失敗: runtime-smoke`）で 3 回失敗した」）。ステップの打ち直しにも同じ上限が効き、#1983 の再現の手順（同じ CI の失敗が続く `release` のステップ）では、宣言の回数で止まって人へ戻る
- [ ] 6. 待ちは、次の眠りが上限を超えるとき、上限の時刻に最後の照会を 1 回打ってから止まる。上限で止まったときの結果は `stopped` で、理由に待った秒・照会の回数・上限の秒が出る（#2224 の再現の手順で確かめる）
- [ ] 7. 宣言が無い・壊れている・方針の名前が宣言に無いとき、部品は組み込みの値へ黙って戻らず、終了コード 1 と理由（宣言のパスと方針の名前）で止まる
- [ ] 8. 子の課題 9 件（前提 5）のそれぞれを、閉じた（再現の手順を通して解消を確かめた）か残した（理由つき）かに分けて、この課題の本文に記録する。閉じた課題には、通した手順と結果をコメントで残す
- [ ] 9. 退行しない: 既存の全体テスト（`uv run --frozen --project . --all-extras pytest . -q -n 4`）が通る。`limits.py check` の順序のチェック（無進捗の許容 < 監視の上限 < CLI の上限）は、宣言を読んで同じ組を判定する
