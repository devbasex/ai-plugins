# #312 / #315: テスト環境の停止判定と台帳の書き込み失敗を、呼び出し元が取り違えない

設計は [issue-312-315-design.md](issue-312-315-design.md) にある。この文書は「何を満たすか」だけを扱う。

## 依頼（原文）

### #312

> ロックの保持を判定する関数は、持ち主の番号（`pid`）を持たないロックに対して 0（持ち主が
> いる）を返す。捨ててよい状態かの判定（`_ndf_lock_is_stale` が見る 5 分の規則）を通らない。
>
> （中略：空のロックディレクトリで `wt_lock_is_held` が `rc=0` を返す再現）
>
> **持ち主を書く前に落ちたロックが、生きている持ち主のロックと同じ扱いになる。**
>
> ## 直さないと何が起きるか
>
> ロックのディレクトリを作った直後に落ちたプロセスがあると、そのテスト環境は停止の対象から
> 外れ続ける。`_ndf_lock_is_stale` は 5 分の規則を持つが、`ndf_lock_is_held` はそれを見ないため、
> 時間が経っても対象へ戻らない。停止されないテスト環境はスロットとポートを握ったままになる。

### #315

> `wt_registry_update` は、排他を取れないときに終了コード 1 を返す。呼び出し元の
> `worktree-testenv.sh` は戻り値を見ずに次へ進む。**台帳へ書けなくても、そのまま処理が続く。**
>
> （中略：266 行・429 行・144 行の呼び出し、429 行を本体とする `_close_record` の呼び出し元 424 行と
> 510 行。485 行は `|| return 1` で受けているため対象に含めない）
>
> ## 直さないと何が起きるか
>
> 基準のタグ・ポートの割り当て・解放の時刻が台帳に載らないまま、テスト環境の操作が完了と
> して返る。台帳と実体が食い違い、次の採番が同じスロットを割り当てるか、解放したはずの
> 割り当てが残る。

## 解釈

**#312:** 保持の判定が、取得の側が「捨ててよい」と読むロックを「握られている」と読まないようにする。
判定の規則を 2 つ持たず、取得の側の規則（`_ndf_lock_is_stale`）1 つに揃える。

**原文の再現（作った直後の空のロックで `rc=0`）は、直した後も `rc=0` のままである。** 取得の途中の
ロックも同じ形をしており、区別できないためである（設計文書の決定 1 と実測）。直すのは「時間が
経っても対象へ戻らない」ことである。

**#315:** `worktree-testenv.sh` の中で、台帳の更新（`wt_registry_update` と、それを呼ぶ
`wt_slot_*`）の失敗を、どの呼び出しでも受け取る。原文が挙げた 144 / 266 / 424 / 429 / 510 行に
加え、同じ形の 139 / 277 / 306 / 374 / 388 行も対象にする（実測で同じ食い違いが出たため）。

## 目的

- 持ち主を書く前に落ちたプロセスのロックが残っても、5 分を過ぎればテスト環境が `reap` の停止の
  対象へ戻る
- 台帳へ書けなかったとき、`worktree-testenv.sh` のサブコマンドが完了を装わない。書けなかった事実と、
  利用者が次にすることが標準エラーに出る

## 前提

- 前提 1: 「捨ててよい」の基準は `NDF_LOCK_STALE_MINUTES`（5 分）とロックのディレクトリの更新時刻で
  決める。この値と規則は変えない
- 前提 2: 変更は排他の共通実装（`lock-common.sh`）とテスト環境の入口（`worktree-testenv.sh`）と、
  そのテストに収まる。`worktree-common.sh` の関数の戻り値の形は変えない。同じファイルの別の節を
  他の担当が設計している
- 前提 3: 台帳の更新の失敗の原因（排他の待ちの上限・jq の失敗・書き出しの失敗）は、呼び出し元から
  区別しない。どれも `wt_registry_update` の終了コード 1 として届く
- 前提 4: `last_used_at`（最後に使った時刻）を読むのは `reap` だけである。書けなくても割り当て・
  ポート・公開の記録は食い違わない

## 対象範囲

含む:

- `ndf_lock_is_held` の判定を `_ndf_lock_is_stale` の規則へ揃える
- テスト環境の入口（`worktree-testenv.sh`）で、台帳を更新する呼び出しの戻り値を受け取ること。
  対象のサブコマンドは `env` / `up` / `test` / `down` / `expose` / `unexpose` である
- 失敗を知らせる文言
- 上の 2 つを固定するテスト

含まない:

- `worktree-common.sh` の `wt_slot_acquire` が「排他を取れない」と「空きが無い」を同じ終了コードで
  返す点（`env` が前者でも「空きスロットがありません」と出す）。関数の戻り値の形を変える必要がある
  ため、#626 として起票した
- `reap` が停止の対象へ戻したテスト環境の、残ったロックのディレクトリを取り除くこと。次に `test` を
  実行したときの取得が捨てる（`ndf_lock_acquire` の既存の振る舞い）
- 485 行（`expose` の先着 1 本の関門）。原文どおり `|| return 1` で受けている
- `worktree-setup.sh` / `worktree-session.sh` など、他のスクリプトからの台帳の更新
- `pid` が別のプロセスに再利用された場合の判定
- 設計のクラス図。変更はシェルの関数と条件分岐だけで、型を追加も変更もしない

## 用語

| 用語 | 意味 |
| --- | --- |
| 実行中のロック | `test` が握るロック `<共通 git ディレクトリ>/ndf/<環境名>.inuse.d` |
| 空のロック | ディレクトリはあるが `pid` を持たないロック（`held` の有無は問わない） |
| 古い | ロックのディレクトリの更新時刻が `NDF_LOCK_STALE_MINUTES` 分より前である |
| 台帳の更新 | `wt_registry_update` と、それを呼ぶ `wt_slot_set_ports` / `wt_slot_release` / `wt_slot_touch` |
| 失敗させる | テストで、台帳の更新が終了コード 1 を返す状態を作る（jq の差し替えか、台帳のロックを握る） |

## 受け入れ条件

### #312: 保持の判定

- [ ] AC1: 古い空のロックに対して `ndf_lock_is_held` と `wt_lock_is_held` が終了コード 1 を返す
- [ ] AC2: 作った直後の空のロック（`held` の有無を問わない）に対して、両関数が終了コード 0 を返す
- [ ] AC3: 生きている `pid` を持つロックに対して、ディレクトリの更新時刻が古くても終了コード 0 を返す
- [ ] AC4: 生きていない `pid` を持つロック、存在しないパス、ディレクトリでないパス、空の引数に対して
  終了コード 1 を返す（現状と同じ）
- [ ] AC5: ディレクトリであるロックのどの状態でも、`ndf_lock_is_held` の結果が
  `_ndf_lock_is_stale "$dir" "<いまの token>"` の結果の否定と一致する
- [ ] AC6: 呼んだ後の呼び出し側のシェルの `$-` に `C` が残らず、標準出力へ何も書かない
- [ ] AC7: `reap --idle 45m` で、使われていない割り当ての実行中のロックが古い空のロックのとき、その
  テスト環境に `compose stop` が呼ばれる
- [ ] AC8: 同じ条件で実行中のロックが作った直後の空のロック、または生きている `pid` のロックのとき、
  `compose stop` が呼ばれない

### #315: 台帳の更新の失敗

- [ ] AC9: `env` でポートの記録（`wt_slot_set_ports`）が失敗すると、終了コード 1 で終わる。標準出力に
  JSON を出さず、標準エラーに台帳へ記録できなかったことが出る。この呼び出しで新しく取った割り当ては
  解放を試みる
- [ ] AC10: `env` でポートが帯を超えた後の解放（`wt_slot_release`）が失敗すると、終了コード 1 の
  まま、標準エラーにスロットを解放できなかったことが出る
- [ ] AC11: `up` で基準のタグの記録が失敗すると、終了コード 1 で終わり、`compose up` が呼ばれない
- [ ] AC12: `up` で排他を取れないとき（台帳のロックを生きている持ち主が握る）、AC11 と同じ結果になる。
  待ちは 1 回分（上限 5 秒）で終わる
- [ ] AC13: `down` で解放の記録が失敗すると、終了コード 1 で終わる。標準エラーには、破棄はしたが
  スロットの解放を記録できなかったことと、`down` を再実行すればよいことが出る
- [ ] AC14: `unexpose` で台帳を閉じられないと、終了コード 1 で終わる。標準エラーには、閉じる手段は
  実行したが台帳を閉じられなかったことが出る
- [ ] AC15: `expose` で公開の手段が失敗し、記録の巻き戻しも失敗すると、終了コード 1 で終わる。
  標準エラーに「記録を戻しました」は出ない。代わりに、記録を戻せなかったことと `unexpose` で閉じる
  ことが出る
- [ ] AC16: `up` / `test` で最後に使った時刻の記録（`wt_slot_touch`）が失敗すると、標準エラーに
  警告が出る。`up` は `compose up` を呼び、終了コード 0 で終わる。`test` は実行したコマンドの
  終了コードをそのまま返す

### 退行しないこと

- [ ] AC17: 台帳の更新が成功する場合、各サブコマンドの標準出力・終了コード・台帳の内容が変更前と
  同じである。既存の `test_testenv.py` / `test_registry.py` / `scripts/tests/test_lock_common.py` が
  すべて通ることで確かめる
- [ ] AC18: `ndf_lock_acquire` の振る舞い（2 段の関門・陳腐化したロックの奪取・待ちの上限）が変わらない

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 運用・保守性 | 台帳へ書けなかったときの文言は、どの記録（ポート・基準のタグ・解放・公開）が書けなかったかと、次の操作を 1 行で示す |
| システム環境 | `flock` を使わない。`bash` 以外に `dash` で読み込まれても `lock-common.sh` の構文が通る（`workflow-common.sh` からも読まれるため） |

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 関数名・引数は変わらない。`ndf_lock_is_held` の戻り値が、古い空のロックで 0 から 1 へ変わる。`worktree-testenv.sh` の終了コードが、台帳へ書けないときに 0 から 1 へ変わる（`env` / `up`） |
| データ | 台帳の形は変わらない |
| 既存の振る舞い | `reap` が古い空のロックを持つテスト環境を止める。台帳へ書けない `env` / `up` が先へ進まない |
