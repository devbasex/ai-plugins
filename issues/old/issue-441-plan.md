## モード

`standard`。本番コードの構造を変え、対象にテストが十分にある（576 件）。

## 目的と非目的

達成したい状態:

- **各モジュールが公開する名前が確定し、入口が argparse と `main` だけになる**
- **モジュール間の依存が一方向であることを、機械が確かめ続ける**

やらないこと:

- 実装の振る舞いの変更
- モジュールの分け方そのものの見直し（責務の再配置）

## 名前をどう決めるか

**モジュールをまたいで使う名前は公開名にする。** `_` を外し、その名前が属するモジュールを
1 つに決める。

| 判断 | 対象 |
| --- | --- |
| **公開名にする**（`_` を外す） | 他のモジュールが取り込んでいる 27 個 |
| **`_` のまま残す** | そのモジュールの中だけで使う補助 |

**改名で意味が変わる名前は、公開名にするときに名前も見直す。** `_round` / `_load` /
`_finish` は、モジュールの外から見ると何を指すのかが読めない。

## `commands` 層の横の依存をどうするか

**3 本とも、下の層へ移すことで解消する。**

| 依存 | 何を取り込んでいるか | 移す先 |
| --- | --- | --- |
| `gate → converge` | `_unassigned_fix_commits` | `verify`（検証の判定であり、コマンドではない） |
| `converge → apply` | `_phase_after_group` / `_prepare_fix_phase` / `_run_drop` / `current_group` | `rounds`（ラウンドの進行の判定） |
| `setup → report` | `_finish` | `rounds`（同上） |

**この判断は実装の過程で見直す。** 移した先が別の依存を生むなら、そこで決め直して記録する。

## タスク分解

**1 タスク = 1 コミットにし、タスクごとにテストを通す。**

### Task 1: 境界の検査を先に置く

- **対象ファイル:** `tests/test_module_boundaries.py`（新設）
- **変更内容:** 依存の循環と、モジュールをまたぐ非公開名を見る検査を書く。
  **この時点では失敗する**（27 個の非公開名が残っているため）
- **満たす受け入れ条件:** 6
- **進め方:** 失敗するテストを先に置く。以後のタスクがこの検査を緑にしていく

### Task 2: `gitfacts` と `paths` の非公開名を公開名にする

- **対象ファイル:** `refactor_lib/gitfacts.py` / `refactor_lib/paths.py` と、取り込み側
- **変更内容:** 22 個の名前から `_` を外し、取り込み側を追随させる
- **満たす受け入れ条件:** 3（一部）
- **進め方:** 改名 → テスト → 検査の残件が減ることを見る

### Task 3: `commands` 層の横の依存を解消する

- **対象ファイル:** `commands/{gate,converge,setup}.py` / `verify.py` / `rounds.py`
- **変更内容:** 3 本の依存を下の層へ移す
- **満たす受け入れ条件:** 3（残り）/ 4

### Task 4: 再エクスポートと `__setattr__` を外す

- **対象ファイル:** `refactor.py`
- **変更内容:** `_reexport` / `_Entry` / `_LIB_MODULES` を消し、入口を argparse と `main` に絞る
- **満たす受け入れ条件:** 1 / 2 / 8

### Task 5: テストの差し替えを定義元へ寄せる

- **対象ファイル:** `tests/test_*.py`
- **変更内容:** 入口経由のまま残っている 82 件を定義元へ向ける
- **満たす受け入れ条件:** 5 / 7

## 影響範囲

| 対象 | 影響 |
| --- | --- |
| `cross-refactoring` の振る舞い | 変わらない（名前の付け替えと取り込み経路の変更） |
| 配布物 | `cross-refactoring` の `scripts/` と `tests/` |
| 他の Skill | 影響しない（`refactor.py` は `cross-refactoring` の中でだけ使う） |

## リスクと対処

| リスク | 対処 |
| --- | --- |
| 改名で参照が漏れる | タスクごとにテストを実行する。`--help` の起動も確かめる |
| 横の依存を移した先が別の依存を生む | Task 1 の検査が循環を見る。移した時点で確かめる |
| 差し替えが届かない箇所が残る | Task 4 の後に Task 5 を行う。順序を入れ替えない |
| テストの件数が変わる | 増減があれば内訳を示す（#446 と #440 で同じ形を採った） |

## 切り戻し手順

コミットを戻すだけで元へ戻る。データ移行も外部の系への操作も含まない。
