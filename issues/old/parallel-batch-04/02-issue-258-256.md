# 担当 B — 版数の書式を 1 か所へ集め、配線テストの掴み方を直す（#258 / #256）

- issue: https://github.com/devbasex/ai-plugins/issues/258 / https://github.com/devbasex/ai-plugins/issues/256
- ブランチ: `fix/issue-258-version-pattern`
- モード: `standard`

この文書は仕様と設計の両方を持つ。`standard` のため設計は独立したファイルにせず、同じ
ファイルの別の節として置く（`design` の規約）。

## 用語

| 語 | この文書での意味 |
| --- | --- |
| 版数の書式 | 版数 1 つを拾う正規表現。数字 3 つと、任意の接尾辞からなる |
| 接尾辞 | 開発版の版数に付く `-dev.1` / `-rc.1` の部分 |
| 説明文書の検査 | `scripts/check-doc-staleness.py`。説明文書に書かれた版数と Skill 数を突き合わせる |
| 定義ファイルの検査 | `scripts/validate-runtime-plugins.sh` のヒアドキュメントに埋め込まれた Python |
| 配線テスト | `scripts/tests/test_validate_wiring.py`。説明文書の検査が呼ばれていることを固定する |
| 呼び出し行 | 定義ファイルの検査のスクリプトが、説明文書の検査を起動している行 |

## 何を解決するか

版数の書式が 2 か所に書かれている。同じ規則を 2 つの定義が持つため、片方だけを直すと
一方の検査だけが接尾辞を読めない状態になる。

**この食い違いは v9.7.0-dev.1 の配布で起きた。** 接尾辞を読めるようにする直しが #248
（説明文書の検査）と #254（定義ファイルの検査）の 2 件に分かれ、同じ原因の同じ直しを 2 回
行っている。どちらも接尾辞を落とすと「版数が古い」で止まるため、片方だけでは開発版を出せない。

配線テストは別の課題を持つ。呼び出しの形を確かめる目的で書かれているが、掴む行を
「対象のファイル名を含む最初の 1 行」で選ぶため、呼び出し行より前にそのファイル名を書いた
コメントを 1 行置くとテストが落ちる。#254 の修正でこの経路を踏んだ。

## 現状（実測）

### 版数の書式が 2 か所にある

```console
$ grep -Fn '\d+\.\d+\.\d+' scripts/check-doc-staleness.py scripts/validate-runtime-plugins.sh
scripts/validate-runtime-plugins.sh:110:VERSION_IN_DESCRIPTION = re.compile(r"\(v(\d+\.\d+\.\d+(?:-[0-9A-Za-z.]+)?)\)")
scripts/check-doc-staleness.py:70:VERSION = r"(\d+\.\d+\.\d+(?:-[0-9A-Za-z.]+)?)"
```

### 配線テストが掴む行

```python
# scripts/tests/test_validate_wiring.py
line = next(l for l in body.splitlines() if "check-doc-staleness.py" in l)
assert "--root" in line
```

呼び出し行は 403 行にあり、その手前 400〜402 行にこの検査を説明するコメントがある。
コメントの中にファイル名を書くと、掴む行がコメント行になる。

```console
E   AssertionError: assert '--root' in '# 版数の書式は `scripts/check-doc-staleness.py` の …'
```

### 定義ファイルの検査は、本体だけを取り出して実行される

```python
# scripts/tests/validate_manifests_helpers.py
HEREDOC_START = 'run python3 - "$ROOT_DIR" "${FAMILIES[@]}" <<\'PY\''
HEREDOC_END = "PY"
```

テストはヒアドキュメントの本文を取り出し、一時ディレクトリへ作った木を根として実行する。
**本体が根の下のファイルを読む場合、その木にも同じファイルが要る。**

## 受け入れ条件

1. 版数の書式の定義が 1 か所にある。説明文書の検査と定義ファイルの検査は、どちらも
   その 1 か所を読む
2. どちらの検査にも、版数の数字 3 つを直接書いた正規表現が残っていない
3. 接尾辞付きの版数（`9.8.0-dev.1`）と接尾辞なしの版数（`9.8.0`）を、両方の検査が
   これまでどおり拾う
4. 検査が失敗したときの出力の形が変わっていない
5. 共有する定義を読み込めないとき、検査は素通りせずに 0 以外の終了コードで終わる
6. 配線テストは、呼び出し行より前に対象のファイル名を含むコメントがあっても通る
7. 配線テストは、呼び出し行が 1 行も無いときに落ちる
8. 配線テストは、呼び出し行から `--root` を外すと落ちる
9. `uv run --with pytest pytest scripts/tests -q` が通る
10. `bash scripts/validate-runtime-plugins.sh` が終了コード 0 で終わる

## 対象範囲

### 含む

- `scripts/lib/version_pattern.py`（新設）
- `scripts/check-doc-staleness.py` の版数の書式の定義と、その読み込み
- `scripts/validate-runtime-plugins.sh` のヒアドキュメントの中の版数の書式
- `scripts/tests/` の既存テストと、新しく足すテスト

### 含まない

- `AGENTS.md` と `plugins/ndf/README.md`。担当 A が持つ
- `plugins/` と `.github/`
- 版数の書式そのものの変更。拾える版数の範囲は現状のまま
- 検査が突き合わせる箇所の増減

## 設計

### 構成要素

| 位置 | 役割 |
| --- | --- |
| `scripts/lib/version_pattern.py` | 版数の書式を持つ唯一の場所。正規表現の断片と、そこから組み立てた 2 つのコンパイル済みの形を公開する |
| `scripts/check-doc-staleness.py` | 自分の位置から `scripts/lib` を解決して読み込む |
| `scripts/validate-runtime-plugins.sh` のヒアドキュメント | 根（`$ROOT_DIR`）から `scripts/lib` を解決して読み込む |
| `scripts/tests/validate_manifests_helpers.py` | 一時ディレクトリの木へ、共有する定義を実物から複製する |

**読み込みの起点が 2 通りあるのは、実行のされ方が違うためである。** 説明文書の検査は
ファイルとして起動されるため自分の位置が分かる。定義ファイルの検査は標準入力から渡される
本体であり、自分の位置を持たない。根は引数で受け取っているため、そちらから解決する。

### 共有する定義

```python
# scripts/lib/version_pattern.py
VERSION = r"(\d+\.\d+\.\d+(?:-[0-9A-Za-z.]+)?)"
VERSION_VALUE = re.compile(VERSION)
VERSION_IN_DESCRIPTION = re.compile(r"\(v" + VERSION + r"\)")
```

公開するのは版数の書式そのものと、そこから組み立てた 2 つの形だけである。版数を扱う
処理（比較・基底の取り出し）は移さない。説明文書の検査だけが使うものであり、移すと
定義ファイルの検査から読まれない関数が共有の位置に置かれる。

### 読み込みの手順

説明文書の検査は、自分の隣のディレクトリを探索の先へ足してから読み込む。

```python
sys.path.insert(0, str(pathlib.Path(__file__).resolve().parent / "lib"))
from version_pattern import VERSION, VERSION_VALUE
```

定義ファイルの検査は、引数で受け取った根から解決する。

```python
sys.path.insert(0, str(root / "scripts" / "lib"))
from version_pattern import VERSION_IN_DESCRIPTION
```

**モジュール名は `version_pattern` とする。** `version` は他の場所でも使われる一般的な名前で、
探索の先へ `scripts/lib` を足すと、同名の別のモジュールを隠すことがある。

### 読み込めないときの扱い

読み込めないときは、その場で 0 以外の終了コードで終える。版数の書式を持たないまま検査を
続けると、突き合わせの対象がすべて素通りする。

```python
try:
    from version_pattern import VERSION_IN_DESCRIPTION
except ImportError as exc:
    raise SystemExit(f"版数の書式を読み込めない（scripts/lib/version_pattern.py）: {exc}")
```

失敗の出力の形は、既存の突き合わせの失敗とは別に扱う。突き合わせの失敗は一覧へ積んで
まとめて出すが、これは検査そのものが成立しないことを表すため、積まずに止める。

### 配線テストの掴み方

呼び出し行の候補は、対象のファイル名を含む行のうち、コメント行を除いたものとする。

```python
def invocation_lines(body: str) -> list[str]:
    return [
        line
        for line in body.splitlines()
        if "check-doc-staleness.py" in line and not line.lstrip().startswith("#")
    ]
```

候補が空のときは落とす。素通りさせると、呼び出しが外れたことを検出できない。候補が
複数あるときは、そのすべてに `--root` があることを求める。

## 決定の記録

### 共有の位置を `scripts/lib/` に置く

`scripts/` の直下ではなくディレクトリを分ける。`scripts/` の直下は実行するスクリプトの
置き場所で、拡張子とハイフンを含む名前で揃っている。読み込まれる側は名前の付け方も
役割も違う。`plugins/ndf/scripts/lib/` が同じ形を採っている。

### 版数の書式だけを共有し、処理は移さない

共有の対象を広げると、定義ファイルの検査から呼ばれない関数が共有の位置に集まる。読む側が
どこまでを前提にしてよいかが曖昧になる。移すのは、2 つの検査が同じ規則を必要としている
版数の書式に限る。

### 定義ファイルの検査は根から解決する

ヒアドキュメントの本体は標準入力から渡されるため `__file__` を持たない。位置を決められるのは
引数で受け取った根だけである。テストがこの本体を一時ディレクトリの木に対して実行するため、
テスト側の木にも共有する定義を置く必要がある。**複製の元は実物 1 つとし、テスト用の写しを
別に書かない。** 書式を 1 か所へ集める変更で、テストの側に 2 つ目の定義を作らない。

### 読み込みに失敗したら止める

代わりの書式を埋め込んで続ける形は採らない。埋め込んだ時点で定義が 2 つに戻る。読み込めない
ことは検査の前提が崩れている状態であり、突き合わせの結果を出せる状態ではない。

### 配線テストはコメント行を除く

呼び出し行を `python3` との共起で選ぶ方法もあるが、起動の書き方が変わると候補が空になる。
コメント行を除く方法は、呼び出しの書き方に依存しない。候補が空のときに落とすため、
除きすぎた場合も検出できる。

## テスト設計

| 何を確かめるか | 置き場所 |
| --- | --- |
| 共有する書式が、接尾辞なしの版数を拾う | `scripts/tests/test_version_pattern.py` |
| 共有する書式が、接尾辞付きの版数を拾う | 同上 |
| 共有する書式が、数字 2 つだけの文字列を版数として拾わない | 同上 |
| 説明文書の検査に、版数の数字を直接書いた正規表現が無い | 同上 |
| 定義ファイルの検査に、版数の数字を直接書いた正規表現が無い | 同上 |
| 共有する定義が読めないとき、定義ファイルの検査が 0 以外で終わる | 同上 |
| 説明文書の検査が、接尾辞付きの版数で通る | `scripts/tests/test_doc_staleness.py`（既存） |
| 定義ファイルの検査が、接尾辞付きの `(v…)` を拾う | `scripts/tests/test_validate_manifests_version.py`（既存） |
| 呼び出し行の前にコメントがあっても配線テストが通る | `scripts/tests/test_validate_wiring.py` |
| 呼び出し行が無いとき配線テストが落ちる | 同上 |
| 呼び出し行から `--root` を外すと配線テストが落ちる | 同上 |

**「無い」ことの確認は、実行結果で示す。** 版数の数字を直接書いた正規表現が残っていないことは、
対象のファイルを読んで数字 3 つの並びを探す形で確かめる。目視での確認は残さない。
