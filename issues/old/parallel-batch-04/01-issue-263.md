# 担当 A — 開発版チャネルの取得手順の記載を実機に合わせる（#263）

- issue: https://github.com/devbasex/ai-plugins/issues/263
- ブランチ: `docs/issue-263-install-steps`
- モード: `light`

`light` のため設計工程は通らない。この文書は受け入れ条件と、書き換える記載の対象を定める。

## 用語

| 語 | この文書での意味 |
| --- | --- |
| 取得元 | プラグインの配布元として登録するマーケットプレイス 1 つ |
| 登録 | 取得元を利用者の手元へ追加すること（`plugin marketplace add`） |
| 導入 | プラグインの実体を利用者の手元へ展開すること（`plugin add` / `plugin install`） |
| 開発版チャネル | `develop` を指す ref で登録した取得元 |
| 実体 | 導入されたプラグインのファイル一式。版ごとのディレクトリに置かれる |

**登録と導入を分ける。** この 2 つを 1 つの語で書くと、記載の食い違いそのものが説明できない。

## 何を解決するか

`AGENTS.md` と `plugins/ndf/README.md` が書いている開発版の取得手順は、3 点が実機の挙動と
食い違う。手順どおりに実行しても開発版を受け取れない経路が 1 件、手順が途中で止まる経路が
1 件、根拠として書かれた事実が片方のランタイムにしか当てはまらない箇所が 1 件である。

## 現状（実測）

### 1. 取得元の切り替えだけでは、導入済みの版は変わらない

```console
$ codex plugin marketplace add devbasex/ai-plugins --ref develop
Added marketplace `ai-plugins` from https://github.com/devbasex/ai-plugins.git#develop.

$ codex plugin list | grep ndf
ndf@ai-plugins   installed, enabled  9.6.0

$ codex plugin add ndf@ai-plugins
Installed plugin root: /home/ubuntu/.codex/plugins/cache/ai-plugins/ndf/9.7.0-dev.1
```

`AGENTS.md` の開発版の例は `marketplace add` の行だけを書いている。

Claude Code も実体を版ごとのディレクトリへ置く。手元の導入記録は版のディレクトリを直接指す。

```console
$ ls ~/.claude/plugins/cache/ai-plugins/ndf/
8.6.0  9.0.0  9.1.0  9.1.1  9.1.2  9.2.0  9.2.1  9.3.0  9.4.0  9.5.0  9.6.0  9.7.0  9.7.0-dev.1

$ python3 -c "import json;d=json.load(open('$HOME/.claude/plugins/installed_plugins.json'));print(d['plugins']['ndf@ai-plugins'][0]['installPath'])"
/home/ubuntu/.claude/plugins/cache/ai-plugins/ndf/9.7.0
```

登録を書き換えても、この導入記録が指す版は変わらない。

### 2. Codex は同名の取得元の上書きを拒む

```console
$ codex plugin marketplace add devbasex/ai-plugins --ref develop
Error: marketplace 'ai-plugins' is already added from a different source; remove it before adding this source
```

`AGENTS.md` は「同じ名前で別の取得元を追加すると、利用者の登録が置き換わる」と書いている。
この記述は Claude Code で実測したものである。

`remove` の影響もランタイムで違う。Codex の `remove` は導入の記録
（`~/.codex/config.toml` の `[plugins."ndf@ai-plugins"]`）を残すため、`add` し直せば有効な状態に
戻る。Claude Code の `marketplace remove` は clone と導入記録まで消える。

### 3. clone の取得範囲がランタイムで違う

```console
$ git -C ~/.codex/.tmp/marketplaces/ai-plugins config --get remote.origin.fetch
+refs/heads/*:refs/remotes/origin/*

$ git -C ~/.claude/plugins/marketplaces/ai-plugins config --get remote.origin.fetch
+refs/heads/main:refs/remotes/origin/main
```

`AGENTS.md` は Claude Code 側の値を、両ランタイムに当てはまる根拠として書いている。

**結論そのものは両ランタイムで変わらない。** Codex も登録時の ref を基準にするため、clone を
手で別のブランチへ切り替えても `codex plugin list` の版数は変わらない（issue #263 の実測）。

## 受け入れ条件

1. `AGENTS.md` の開発版の取得の例が、登録に続けて導入の操作を書いている。**書かれたコマンドを
   上から順に実行すると、開発版の実体が手元へ入る**
2. 取得元を切り替えても導入済みの版は変わらないことが、理由（実体が版ごとのディレクトリに
   置かれ、導入の記録がその版を指す）とともに書かれている
3. ランタイムで挙動が違う 3 点（同名の登録の上書き・`remove` が消す範囲・clone の取得範囲）
   について、**どのランタイムの挙動かが記載から読み取れる**
4. 一方のランタイムでしか実測していない記述に、他方へ当てはまるという断定が無い
5. `plugins/ndf/README.md` の更新案内が、開発版を試す利用者に対して同じ手順を示している
6. `bash scripts/validate-runtime-plugins.sh` と
   `python3 scripts/check-doc-staleness.py --root .` が終了コード 0 で終わる

## 対象範囲

### 含む

- `AGENTS.md` の「版の付け方と開発版の配布」節のうち、取得の例とその根拠の記述
- `AGENTS.md` の「ローカルのディレクトリを同じ名前でマーケットプレイスとして追加しない」の
  段落のうち、置き換えと `remove` の挙動をランタイム共通として書いている箇所
- `plugins/ndf/README.md` の更新案内のうち、開発版の取得に触れる箇所

### 含まない

- `scripts/` の検査。版数の書式は担当 B が扱う
- `plugins/ndf/skills/` と `.github/`
- チャネルの方針そのもの（`main` が正式版、`develop` が開発版）。記載の対象は手順である
- Kiro の手順。clone の checkout で切り替える形は変わらない

## 何を書き換えるか

| 対象 | 現在の記載 | 書き換えの方針 |
| --- | --- | --- |
| `AGENTS.md` 開発版の取得の例 | `marketplace add` の 2 行だけ | ランタイムごとに、登録の行と導入の行を並べる |
| `AGENTS.md` 導入の説明 | 記載なし | 実体が版ごとのディレクトリに置かれること、導入の記録がその版を指すことを 1 段落で書く |
| `AGENTS.md` 同名の登録 | 「置き換える」と共通で断定 | Claude Code は置き換え、Codex は `remove` を求める、と分けて書く |
| `AGENTS.md` `remove` の影響 | clone と導入記録まで消える | Claude Code の挙動として書き、Codex は導入の記録が残ることを添える |
| `AGENTS.md` clone の取得範囲 | refspec を共通の根拠として提示 | ランタイムごとの実測値を表で並べ、結論が両者で同じであることを別に書く |
| `plugins/ndf/README.md` 更新案内 | 開発版の取得に触れていない | 開発版を試すときの手順へ導入の操作を含める |

## 確かめ方

**利用者の登録を書き換える操作は行わない。** `AGENTS.md` 自身が、同名の取得元の追加と
`marketplace remove` が利用者の登録と導入記録に影響することを記録している。記載を直すための
確認で、その状態を壊さない。

確認は次の 3 つで行う。いずれも読み取りだけである。

| 何を確かめるか | 方法 |
| --- | --- |
| 実体が版ごとのディレクトリに置かれること | `ls ~/.claude/plugins/cache/ai-plugins/ndf/` と `~/.codex/plugins/cache/ai-plugins/ndf/` |
| 導入の記録が指す版 | `~/.claude/plugins/installed_plugins.json` と `~/.codex/config.toml` |
| clone の取得範囲 | `git -C <clone> config --get remote.origin.fetch` |

**残リスク（未確認）**: Claude Code で「取得元を `develop` へ切り替えた直後に、導入済みの版が
変わらない」ことと、「同名の取得元の追加が置き換えになる」ことは、この変更では実測していない。
どちらも利用者の登録を書き換える必要があるためである。記載は、Codex で実測した挙動と、
Claude Code の導入記録の構造から読み取れる事実に限る。断定できない部分は書かない。
