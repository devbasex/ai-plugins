# 216 / 284: 参加する 4 CLI を同じ扱いにし、実測モデル名の限界を明示する

`/ndf:cross-refactoring` が起動する 4 つの CLI のうち、適用の役割だけが 1 つを外している
（#216）。あわせて、指定した言語モデル（以後「モデル」と書く）で実際に動いたかを確かめ
られるのが 4 つのうち 1 つだけである事実を、記録と案内へ残す（#284）。

## 用語

| 語 | この文書での意味 |
| --- | --- |
| 参加 CLI | `cross-refactoring` が外部プロセスとして起動する claude / codex / agy / kiro の 4 つ |
| ホスト | 進行を制御する側のランタイム。提案とレビューには参加しない |
| 母集合 | 役割ごとの担当を選ぶ元になる参加 CLI の集合 |
| 適用 | 提案された改善項目をコードへ反映し、コミットまで行う役割 |
| 輪番 | ラウンド番号から適用担当を決める規則（`assignment.assign`） |
| 言語モデル | 参加 CLI が内部で呼び出す生成モデル。この文書で「モデル」と書くときはこれを指す |
| 実測モデル名 | CLI の出力から読み取れる、そのラウンドで実際に動いた言語モデルの名前 |
| 配布先ランタイム | NDF の Skill を配る先。現在は 4 つとも配布先である |

適用で読ませる 3 つは agy へ配っている。`cross-refactoring` 自身も配っているため、agy は
ホストにもなれる。

### 適用の母集合を 4 者にすると、同じラウンド番号の適用担当が変わる

適用担当は `pool[ラウンド番号 % 母集合の大きさ]` で決まる。母集合の大きさが 3 から 4 へ
変わるため、ラウンド 2 以降の担当が入れ替わる。ホストによらず同じ並びになる。

| ラウンド | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 現在（3 者） | codex | kiro | claude | codex | kiro | claude | codex | kiro |
| 変更後（4 者） | codex | agy | kiro | claude | codex | agy | kiro | claude |

**`ALL_RUNTIMES` の並びは変えない。** v10.0.0 で固定した並び（`claude` / `codex` / `agy` /
`kiro`）はそのまま使う。並べ替えると読み替えの手掛かりが消えるため、母集合の大きさだけを
変える。

**過去の記録との突き合わせは、ラウンド番号では成り立たなくなる。** 3 者で回した記録の
ラウンド 2 は kiro、4 者で回した記録のラウンド 2 は agy を指す。状態ファイルは
`rounds[].impl` に担当の名前を持つため、担当名で突き合わせれば読める。

### 既定の上限のままでは、claude が適用担当にならない

`--max-outer-rounds` の既定は 3 である（`refactor.py` の `add_argument`）。ラウンド番号は
Pull Request ごとに 1 から始まるため、4 者にすると `claude` の順番（ラウンド 4）へ届かない。

```console
$ grep -n 'max-outer-rounds' plugins/ndf/skills/cross-refactoring/scripts/refactor.py
3593:    init.add_argument("--max-outer-rounds", type=int, default=3)
```

現在の 3 者では、ラウンド 1〜3 に codex / kiro / claude が 1 度ずつ入る。既存のテスト
`test_host_takes_impl_turn_at_least_once` がこの性質を固定している。

## 設計

### 適用の母集合

```python
# 参加する 4 CLI。並びは固定する（輪番の読み替えの手掛かりになる）。
ALL_RUNTIMES: tuple[str, ...] = ("claude", "codex", "agy", "kiro")

# ホストになりうるランタイム。4 つとも NDF の配布先であるため全員がなれる。
HOST_RUNTIMES: tuple[str, ...] = ALL_RUNTIMES
```

`IMPL_EXCLUDED` は定数ごと外す。`impl_pool()` は `list(ALL_RUNTIMES)` を返す。関数は
残す。呼び出し側（`refactor.py` の `cmd_init`）が「提案・レビューの母集合」と「適用の
母集合」を別々に確定する構造は変えないためである。両者は依然として一致しない（適用は
ホストを含み、提案・レビューは含まない）。

`HOST_RUNTIMES` の名前は残す（決定 4）。`HOST_ENV_HINTS` へ agy の項目は足さず、agy が
ホストのときは `--host agy` を明示する（決定 3）。

### ホストごとに必要な CLI

`SKILL.md` の表へ agy の行を足す。

| ホスト | 必要な CLI |
| --- | --- |
| Claude Code | `codex` / `agy` / `kiro-cli` |
| Codex | `claude` / `agy` / `kiro-cli` |
| agy | `claude` / `codex` / `kiro-cli` |
| Kiro CLI | `claude` / `codex` / `agy` |

適用にホスト自身も参加するため、ホストのコマンドも起動できる必要がある。この点は 4 者に
しても変わらない（`launch-cli.sh` はランタイム名だけで分岐し、ホストか否かを見ない）。

### 手順書の配置の理由

配置先そのものは変えない。agy は codex と同じ `.agents/skills` を使う。書き直すのは理由で
ある。

| 現在の理由 | 変更後の理由 |
| --- | --- |
| agy は配布先ではないため標準の配置先を持たない | 担当ごとの作業ツリーの中へ置き、利用者のホームと対象リポジトリ本体へは書き込まない。4 者とも同じ扱いである |

配置先が作業ツリーの中であることは、配布先かどうかとは別の理由で決まっている
（`prepare-worktrees.sh` の 59 行に「利用者のホームと対象リポジトリ本体には一切書き込まない」
とある）。この理由は 4 者すべてに当てはまる。

### 実機確認の範囲

#216 の「4 者が輪番で適用担当になる実機確認を 1 周行う」を、次の 2 つに分ける。

| 何を確かめるか | 手段 |
| --- | --- |
| 輪番が 4 者を順に選ぶこと | 単体テスト（A3） |
| agy が適用担当として改善項目を反映し、コミットを残すこと | 実 Pull Request で 2 ラウンド走らせる |

**4 ラウンド走らせない。** 1 ラウンドは提案 3 回・適用 1 回・レビュー 2 回の CLI 起動を
含み、適用の監視の上限は 3600 秒である。4 ラウンドで CLI の起動は 24 回になる。ラウンド 1
（codex）・3（kiro）・4（claude）の適用は現在の 3 者構成ですでに実績があり、この変更で
経路が変わらない（`launch-cli.sh` はランタイム名で分岐し、母集合を見ない）。新しいのは
ラウンド 2 の agy だけである。

```bash
/ndf:cross-refactoring <PR> --scope <範囲> --baseline-test "<コマンド>" --max-outer-rounds 2
```

agy が適用担当として手順書どおりに動くことは、#216 の本文が実セッションの結果として記録
している（3 項目が 3 コミットに分かれ、各コミットが 1 ファイルだけを含む）。実 Pull Request
での確認は、その結果が `cross-refactoring` の進行の中でも成り立つかを見る。

### 実測モデル名の扱い

実測できるランタイムを 1 箇所で宣言し、判定をそこから導く。

```python
# 実際に動いた言語モデルの名前を、公開された出力から読み取れるランタイム。
OBSERVABLE_RUNTIMES: tuple[str, ...] = ("claude",)
```

集計へ入れるかの判定を、次の 3 つの状態で表す。

| 状態 | 条件 | 集計 |
| --- | --- | --- |
| 実測できる | `claude` | 入れる。実測値と指定値の食い違いを警告する |
| 指定値で代用する | 実測できないランタイムで、`--model` の指定がある（`kiro=auto` を除く） | 入れる。実測不可であることを報告へ残す |
| 何が動いたか分からない | 実測できないランタイムで、`--model` の指定が無い。または `kiro=auto` | 分離する |

`is_measurable(runtime, model)` はこの表のうち「分離する」を `False` にする。現在の実装は
`kiro` の `auto` だけを分離しており、codex と agy の既定モデルは分離していない。指定が無い
まま実測もできないラウンドは、`kiro=auto` と同じく何が動いたか分からない。

分離の理由の文言は `models.py` が持つ。現在の文言は `metrics.py` にあり「既定モデル（auto）
で動いたため」と書いている。この文言は kiro 以外にも出るようになるため、ランタイムごとの
理由を返す関数を `models.py` へ置き、`metrics.py` はそれを呼ぶ。

| 場面 | 出す文言 |
| --- | --- |
| 指定が無く実測もできない | `<runtime> はモデルを指定しておらず、実際に動いたモデルも取得できない` |
| `kiro=auto` | `kiro の auto はラウンドごとに違うモデルが動きうる` |
| 指定があり実測できない | `<runtime> は指定した <モデル> で動いた前提で数える（実測不可）` |

3 つ目は分離ではなく、報告へ残す注記である。

### 案内

`CLAUDE.md` の 231 行を 4 つの参加 CLI へ広げる。

| 現在 | 変更後 |
| --- | --- |
| モデルを比べるなら `--model kiro=<name>` を必ず指定する（既定 `auto` は実際に動いたモデルを取得できない） | モデルを比べるなら `--model <ランタイム>=<name>` を 4 つとも指定する。実際に動いたモデルを取得できるのは claude だけで、残り 3 つは指定値で代用する。指定が無いラウンドは集計から分離される |

`SKILL.md` の同じ趣旨の 2 行（74〜75 行）も同じ内容にする。

**計測の目的は保つ。** 比較そのものをやめない。`metrics.py` の
「比較として読むときの限界」に、ハーネスとモデルが交絡することと、kiro の `auto` が使えない
ことがすでに並んでいる。ここへ「実測できるのは claude だけで、残り 3 つは指定値を信じて
いる」を足す。限界を書いたうえで比べる形は、この Skill がすでに採っている形である。

## 決定の記録

### 決定 1: `IMPL_EXCLUDED` は定数ごと外す

空のまま残す選択肢がある。値が空でも `impl_pool()` の形は変わらないため、実装としては
どちらも成り立つ。

外すほうを採る。空の除外一覧は、除外の規則が現在は何も無いことを表さず、規則の置き場所
だけが残った状態になる。理由を書かないまま値を足せてしまうため、次に誰かが除外したく
なったときに、なぜ外したのかの記録を伴わずに戻せる。

参照は `assignment.py` の中の 1 箇所だけで、外部からの参照は無い。

```console
$ grep -rn 'IMPL_EXCLUDED' --include='*.py' --include='*.sh' --include='*.md' . | grep -v '^./issues/'
plugins/ndf/skills/cross-review/scripts/lib/assignment.py:27:IMPL_EXCLUDED: tuple[str, ...] = ("agy",)
plugins/ndf/skills/cross-review/scripts/lib/assignment.py:82:    return [r for r in ALL_RUNTIMES if r not in IMPL_EXCLUDED]
```

### 決定 2: `--max-outer-rounds` の既定を 3 から 4 へ上げる

上げない選択肢がある。上限は「提案が続く限り何ラウンドまで回すか」であり、全員に順番が
回ることを保証する値ではない。収束は多くの場合 1〜2 ラウンドで起きるため、上げても実行
時間は通常は変わらない。

上げるほうを採る。ラウンド番号は Pull Request ごとに 1 から始まるため、上限 3 では
`ALL_RUNTIMES` の先頭にある claude の順番（ラウンド 4）へ届かない。**除外を外したのに、
上限によって 1 者が適用担当にならない状態が残る。**

輪番の式を `pool[(ラウンド番号 - 1) % 4]` へ変える選択肢は採らない。届かない 1 者が
claude から kiro へ移るだけで、ラウンド 1 の担当も変わるため、読み替えの手掛かりが増える。

### 決定 3: `HOST_ENV_HINTS` へ agy の項目を足さない

agy が設定する環境変数を推定に使う選択肢がある。agy の実行ファイルの中には
`ANTIGRAVITY_CONVERSATION_ID` という名前が含まれる。

足さない。この名前が hook や tool の子プロセスへ渡ることは確かめていない。バッチ 05 の
実測では、agy はプラグインの位置を示す環境変数を子プロセスへ渡していない。**推定を外すと
提案・レビューの母集合が狂う**（ホストが提案側に混ざる、参加すべき者が外れる）ため、
確かめていない手掛かりを推定へ入れない。

agy がホストのときは `--host agy` を明示する。`detect_host` は推定できないとき既定値を
置かずに失敗し、案内は `HOST_RUNTIMES` を連結して出すため、agy を足した時点で案内にも
agy が並ぶ。

### 決定 4: `HOST_RUNTIMES` の名前を残す

`ALL_RUNTIMES` へ寄せて定数を 1 つにする選択肢がある。現在は 4 つとも配布先であるため、
2 つの値は一致する。

名前を残し、`ALL_RUNTIMES` を代入する。`detect_host` と `--host` の選択肢が問うているのは
「ホストになれるか」で、「参加できるか」とは別の問いである。同じ値になったことと、同じ
問いになったことは違う。配布先でない CLI が参加 CLI に加わると、2 つは再び分かれる。

### 決定 5: 実機確認は agy の 1 ラウンドに絞る

4 ラウンド走らせて 4 者すべての適用を見る選択肢がある。#216 の「やること」はこの形で
書かれている。

絞る。1 ラウンドあたりの CLI 起動は 6 回、適用フェーズの監視の上限は 3600 秒である。
4 ラウンドで 24 回になる。ラウンド 1 / 3 / 4 の担当（codex / kiro / claude）は現在の
3 者構成で適用の実績があり、この変更で通る経路が変わらない。`launch-cli.sh` はランタイム
名だけで分岐し、母集合を参照しない。

確かめる価値があるのは、これまで適用担当にならなかった agy である。上限 2 で走らせると
ラウンド 2 が agy になり、1 ラウンド分の費用で確かめられる。

### 決定 6: agy の会話の記録からモデル名を読まない

`~/.gemini/antigravity-cli/conversations/<会話の識別子>.db` の `executor_metadata` から
モデル名を取り出す選択肢がある。`--output-format json` が返す `conversation_id` が鍵に
なるため、実測値を取れるランタイムを 1 つ増やせる。

読まない。表の構造も値の形式も公開されていない。値はスキーマ定義の無い二進形式で、
位置を頼りに抜き出すことになる。agy の版が上がって形が変われば、誤った値を実測値として
記録するか、静かに `None` へ戻る。**指定値と実測値の突き合わせは、誤った実測値を出すと
指定どおりに動いた実行を食い違いとして警告する**ため、取得できないことより害が大きい。

読み取り先が作業領域の外にあることも、この Skill の方針（作業ディレクトリの外を触らない）
と合わない。

公開された手段が出た時点で `OBSERVABLE_RUNTIMES` へ足せば、判定も報告も追随する。

### 決定 7: 指定が無く実測もできないラウンドを集計から分離する

現在の扱いを保つ選択肢がある。`is_measurable("codex", None)` は現在 `True` を返し、codex の
既定モデルで走ったラウンドは集計へ入る。

分離する。指定が無く実測もできないラウンドは、何が動いたかを後から確かめる手段が無い。
これは kiro の `auto` と同じ状態である。片方だけ分離すると、報告を読む側は codex と agy の
行を「指定したモデルの成績」として読める。

分離しても比較の手段は残る。4 つとも `--model` を指定すれば、3 つは指定値で代用した形で
集計へ入る。案内（B4）がこの手順を示す。

### 着手前の想定と実測が食い違った点

| 想定 | 実測 |
| --- | --- |
| 除外を外しても輪番の再現性は保たれる | ラウンド 2 以降の適用担当が入れ替わる。担当名でしか過去の記録と突き合わせられない |
| 変えるのは `test_assignment.py` だけである | `test_init.py` の 3 件も落ちる（`test_init_emits_shell_assignments` / `test_init_records_cohorts_separately` / `test_init_rejects_agy_as_host`） |
| agy はモデル名をどこにも残さない | 会話の記録の中には残る。公開された取得手段ではないため使わない（決定 6） |
| codex は実行の記録をファイルへ残す | 実測を行った計算機では残さなかった。`~/.codex` に 30 分以内に書かれたファイルは 0 件である |
| 上限 3 のままでも 4 者に順番が回る | claude の順番はラウンド 4 で、上限 3 では届かない |
