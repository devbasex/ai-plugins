## 目的

- プラグインを更新したら、ラッパーを打ち直さなくても、次のセッションからラッパー自身のコード（`relay_lib/` と `lib/` の包み）も新しい版で動く
- 動いているラッパーの版が、利用者と AI から見える

## 前提

- 前提 1: 入れ替えの対象は、ランチャーのコピー（`~/.claude/ndf/relay.py`。シェルの管理ブロックの alias が呼ぶもの）から起動したラッパーだけとする。プラグインのキャッシュの `scripts/relay.py` を直接打って起動したラッパーは、今のまま入れ替えない（利用者の通常の起動はコピーを通る。直接の起動はテストと手での確かめに限られる）
- 前提 2: 新しい版のコードが効き始めるのは、**プラグインを更新した直後のセッション**からとする。今は `relay.current` を新しい版へ替えるのが次のセッションの SessionStart hook（`relay.py startup`）であり、切り替えの時点の `relay.current` はまだ古い版を指す。このため、更新後の版のラッパーのバージョンディレクトリを、次のセッションを起動する前に用意する（誰がどう用意するかは設計が決める）。1 セッション遅れて効く形は採らない
- 前提 3: 入れ替えの仕組みを持たない版（10.17.51 以前）で動いているラッパーは、この変更の後も自分では入れ替わらない。利用者が 1 度だけ打ち直せば、以後の更新で入れ替わる。打ち直しの案内は、下の版の表示が担う
- 前提 4: 入れ替えはプロセスを替えずに行う（PID・端末・親のシェルを保つ）。子の claude が居ない時点（前のセッションが終わり、次のセッションを起動する前）でだけ行う
- 前提 5: 「動いているラッパーの版」は、動いているプロセスが読み込んだバージョンディレクトリの名前（`relay-<版>-<digest>`）で表す。版の文字列だけでは、同じ版で中身の違うコピー（digest 違い）を見分けられないため
- 前提 6: 入れ替えるかの判定は、動いているバージョンディレクトリの名前と、更新後に使うべきバージョンディレクトリの名前が違うかで行う（版の大小は比べない。後退の防止はコピーを置く側の既存の規則（新しい版を古い版で置き直さない）が担う）

## 対象範囲

含む:
- セッションの切り替えで、更新後の版のラッパーのバージョンディレクトリを用意し、動いているものと違えばラッパーを入れ替えること
- 入れ替えの前後で、ラッパーの状態（relay の作業ディレクトリ・セッションの番号・次のセッションの起動の入力・アカウントの選び方）を引き継ぐこと
- 入れ替えられないときに今の版のまま続け、理由を画面と `log.jsonl` に残すこと
- 動いているラッパーの版を `log.jsonl`・`/ndf:install-wrapper status`・`experimental/resume.py` に出し、コピーの版と違えば打ち直すよう案内すること
- `development-workflow` の `references/relay.md` の「動いているラッパーは古い版の `run` のまま動く」の記述を、入れ替えの振る舞いに合わせて改めること

含まない:
- 10.17.51 以前の版で今動いているラッパーを、外から入れ替えること（前提 3）
- プラグインのキャッシュから直接起動したラッパーの入れ替え（前提 1）
- 動いている子の claude（セッションの途中）の入れ替え
- プラグインの更新の手順（`claude plugin marketplace update` と `claude plugin update`）と、コピーの置き直しの規則（後退させない）の変更
- Claude Code 以外のランタイム（ラッパーは Claude Code だけ）

## 受け入れ条件

入れ替えの振る舞い:

- [ ] AC1: コピーから起動したラッパーで、プラグインの更新によりラッパーのバージョンディレクトリが変わる切り替えをすると、更新直後のセッションの `log.jsonl` の `start` の行の「動いているラッパーのバージョンディレクトリ」が、更新後の版のものになる
- [ ] AC2: AC1 のとき、`log.jsonl` に入れ替えの行が 1 行あり、入れ替え前と入れ替え後のバージョンディレクトリの名前とセッションの番号を持つ。その行は前のセッションの `end` の行より後、次のセッションの `start` の行より前にある
- [ ] AC3: 入れ替えの前後で、ラッパーの PID・relay の作業ディレクトリ（`NDF_RELAY_DIR`）が変わらず、セッションの番号は続き（入れ替え前が 7 なら次は 8）になる
- [ ] AC4: 入れ替えた後の次のセッションの起動の入力（引数・cwd・退避前の cwd・起動オプション・上限の後に決めたアカウント）が、入れ替えなかった場合と同じになる
- [ ] AC5: 入れ替えた後も、1 日の起動回数・再起動ループの判定・アイドル・停止シグナルファイルの扱いが入れ替え前から続く（入れ替えで起動回数が増えない・数え直さない）
- [ ] AC6: 入れ替えた後も、ラッパーが動いていると判定される（`relay_running` が真。hook がシグナルファイルを書ける）。端末は raw のまま、入れ替えの後の子の入出力が中継される
- [ ] AC7: 入れ替えた後、入れ替え前のバージョンディレクトリにこのラッパーの使用中の印（`inuse-<pid>`）が残らず、入れ替え後のバージョンディレクトリにある
- [ ] AC8: 動いているラッパーのバージョンディレクトリと更新後に使うものが同じ名前なら、入れ替えない（入れ替えの行が無い）
- [ ] AC9: 1 回の切り替えで、入れ替えは高々 1 回である（入れ替え後のラッパーが同じ切り替えで再び入れ替えない）

入れ替えられないとき:

- [ ] AC10: 更新後の版のバージョンディレクトリを用意できない・入れ替えの呼び出しが失敗したときは、今の版のまま次のセッションを起動し、画面に 1 行と `log.jsonl` に理由を持つ 1 行を残す。次のセッションの起動は失われない
- [ ] AC11: 入れ替え後のラッパーが引き継ぎを読めないときは、次のセッションを起動せず、利用者が手で打つ次のコマンドを画面に示して止まる（既存の「次の区間を起動できない」と同じ形）
- [ ] AC12: プラグインのキャッシュから直接起動したラッパー（前提 1）と、`NDF_RELAY=0`・パススルーの経路の振る舞いは変わらない

版の表示:

- [ ] AC13: `log.jsonl` の `start` の行が、動いているラッパーのバージョンディレクトリの名前を持つ
- [ ] AC14: `/ndf:install-wrapper status` をラッパー経由のセッションで打つと、動いているラッパーのバージョンディレクトリの名前を出す。コピー（`relay.current`）が指すものと違えば、その旨と「`/exit` してから `claude` を打ち直す」の案内を出す
- [ ] AC15: `experimental/resume.py` の版の行に、動いているラッパーの版が並び、ほかの版と違えば「食い違いあり」になる
- [ ] AC16: 入れ替えの仕組みを持たない版のラッパー（`start` の行に動いているバージョンディレクトリの名前が無い）のときは、AC14・AC15 の表示を「不明」とし、打ち直すと版が見えるようになる旨を出す

文書:

- [ ] AC17: `development-workflow` の `references/relay.md` が、切り替えのたびにラッパーが更新後の版へ入れ替わること・入れ替えない場合（前提 1・前提 3・AC10）を記し、「動いているラッパーは古い版の `run` のまま動く」の記述が残らない

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 可用性 | 入れ替えのどの失敗でも、次のセッションの起動を失わない（AC10）か、手で打つコマンドを示して止まる（AC11）。ラッパーが黙って終わり、利用者のシェルへ戻ることは無い |
| 性能・拡張性 | 版が同じ切り替え（AC8）では、今の切り替えより外部コマンドの呼び出しを増やさない（足すのはファイルの読み取りだけ）。版が違う切り替えでは、環境の用意と入れ替えに掛かった秒を `log.jsonl` に残す |
| 運用・保守性 | 入れ替え・入れ替えなかった理由を `log.jsonl` の行で後から数えられる（理由は決まった語の集合） |
| 移行性 | 入れ替えの仕組みを持たない版から持つ版へは、利用者の 1 度の打ち直しで移る（前提 3）。打ち直しの後は手が要らない |
| セキュリティ | 入れ替えで引き継ぐ中身（ファイルか引数か環境変数か）に、認証情報（トークン・API キー・従量の接続の宣言の値）を新たに書き出さない。ファイルに書くなら利用者だけが読める権限にし、読んだら消す |
