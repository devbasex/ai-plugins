## 受け入れ条件

- [ ] 1. 承認を求めるときに提示する項目が表で定まっている
- [ ] 2. 提示物が、対象を開くためのものと承認の判断に使うものに分かれている

- [ ] 4. `design` が定める必須の節が埋まっていることを示す

- [ ] 6. 同じ規定を設計レビューの承認と本番への配布の承認の両方が使い、定義は 1 箇所にある
- [ ] 7. 配布の承認で、取り消しの手段とその限界を提示する
- [ ] 8. ゴール条件が Pull Request より後の工程を含むとき、着手の時点で判定する
- [ ] 9. 要るときは到達点を Pull Request の提出とレビューの収束へ置き直す
- [ ] 10. 完了報告に、止まった理由と再開する手順が書かれる
- [ ] 11. 判定できないときは、マージを試みて拒否された時点で同じ扱いへ移る
- [ ] 12. `SKILL.md` が 300 行以内である
- [ ] 13. 判定の基準（モードの定義）と工程表の内容が変わっていない
- [ ] 14. 多義語「環境」が一意な語へ言い換えられている
