# #1587: 決定の記録

設計の本体は [issue-1587-design.md](issue-1587-design.md) にある。この文書は、その設計で選んだ結論と理由と採らなかった案だけを持つ（1 ファイル 500 行の基準で分けた）。

## 決定 1: 更新後の版のバージョンディレクトリは、更新後の版の `startup` を子プロセスで呼んで用意する

バージョンディレクトリの中身（入れるファイルの一覧・環境の宣言・digest の計算）を正しく知るのは、
その版のコードである。動いている旧版のコードで新版のディレクトリを置くと、新版でファイルの一覧が
変わったときに、旧版が誤った中身を置く。`startup` は次のセッションの SessionStart hook が打つものと
同じ処理で、後退の防止の規則もそのまま効く。次のセッションの hook は、置き終えた複製を見て何もしない。

動いているラッパーが自分のコードで置く形は、上の理由で採らない。次のセッションの hook を待つ形は、
1 セッション遅れて効くため要求の前提 2 に反する。

根拠: Value 6 / Value 2（MVV 版 2）

## 決定 2: 入れ替えるかの判定は、導入先のファイルから計算した名前で先に絞り、`relay.current` で確かめる

版が同じ切り替えが大半で、そこで外部コマンドを足さないことが要求である。導入先の
`relay_lib/*.py`・`LIB_FILES`・`pyproject.toml`・`uv.lock` を読んで `VersionDir.name_for` で名前を出せば、
ファイルの読み取りだけで「同じ」と言える。違うと出たときだけ `startup` を呼び、実際に入れ替える先は
`relay.current` の値にする（新版がファイルの一覧を変えていても、置いた本人の名前を使う）。

版の文字列だけで比べる形は、同じ版で中身が違うコピー（前提 5）を見分けられないため採らない。
毎回 `startup` を呼ぶ形は、AC8 の切り替えで外部コマンドが増えるため採らない。

根拠: Value 3 / Value 2（MVV 版 2）

## 決定 3: 状態は作業ディレクトリのファイル（`handover.json`）で渡し、環境変数にはパスだけを入れる

`SectionInput` は利用者の入力の文（再開コマンド）と、上限の後の選び方（`Choice`）を持ち、
引数や環境変数に入れると長さと引用の扱いが版ごとの約束になる。作業ディレクトリは既に 0700 で、
ラッパーごとに 1 つあり、`NDF_RELAY_DIR` の形は版をまたいで変えない約束がある。ファイルを
0600 で書き、読んだら消せば、要求のセキュリティの条件を満たす。

`run` の引数に状態を足す形は、副命令と引数を変えない要求（影響の表）に反するため採らない。
環境変数に中身を入れる形は、子の claude へ継がれる経路が増えるため採らない。

根拠: Value 5 / C1（MVV 版 2）

## 決定 4: 申し送りからの起動では、`cmd_run` の起動の判定と `read_plugin` を通さない

旧版が同じ環境で既に判定を通っている。読み直すと `claude plugin list` の呼び出しが 1 回増え、
判定の結果が変わればセッションが失われる（AC10・AC11 の外の失敗が増える）。必要な値は申し送りに
入れる。

根拠: Value 2 / Value 3（MVV 版 2）

## 決定 5: `relay.lock` は exec で一度放し、新版が取り直す

`relay.lock` の排他は filelock の `flock` で取っており、fd は継がれない。exec の後に新版の
filelock が新しい fd で取り直すため、継いだ fd を持ったままにすると自分自身と競る。放れている間は
子の claude が居ないため、`relay_running` を見る hook（`mark`・`question`・`notice`）は呼ばれない。
外から `status` を打つと、その一瞬だけ「終わっている」と出るが、状態は変わらない。

継いだ fd を新版へ渡して使い続ける形は、上の理由で採らない。

実測（2026-10-01、このリポジトリの venv。`lib/locks.py` で取った後に `os.execve` した先で
`try_exclusive`）:

```text
before exec: pid 34872 took = True
after exec: pid 34872 lock free = True
```

根拠: Value 1（MVV 版 2）

## 決定 6: 端末は exec の前に入力を捨てずに戻し、新版が raw にし直す

`Terminal.set_raw` は「戻す先」の設定を控えてから raw にする。raw のまま exec すると、新版が raw を
控え、終わるときに利用者のシェルを raw のまま残す。戻すときは `TCSAFLUSH` でなく `TCSADRAIN` を使い、
入れ替えの間に打たれた入力を新版の子へ渡す。

控えた設定を申し送りで渡す形は、`termios` の値（制御文字のバイト列）を JSON の約束にすることになり、
得るものが無いため採らない。

根拠: Value 2（MVV 版 2）

## 決定 7: 使用中の印は、新版が新しい方へ置いてから古い方を消す

旧版が exec の前に自分の印を消すと、exec が失敗したときに印が無いまま動き、`startup` の片づけで
使っているディレクトリが消える。新版が消せば、どの時点でもどちらかに生きた pid の印がある
（pid は exec で変わらない）。

根拠: Value 1（MVV 版 2）

## 決定 8: 新版は `count.lock` を 5 秒まで待って取り直し、起動の上限は判定し直さない

`count.lock` は「起動の数を数えて `start` の行を書く」までを、すべてのラッパーの間で 1 つずつにする。
exec で放れるため、新版は取り直してから起動する。上限（1 日の起動回数・再起動ループ）は旧版が
判定済みで、判定し直すと同じ切り替えを 2 度数える。待ちの 5 秒と、取れないときの `count-lock` の
`give_up` は、既存の `recheck` と同じ値と形にする。

根拠: Value 6（MVV 版 2）

## 決定 9: 申し送りを読む仕組みを持たない版へは入れ替えない

入れ替え先が `relay_lib/handover.py` を持たなければ、新版の `cmd_run` は申し送りを知らずに最初の
引数で新しいラッパーを始め、セッションの番号が 1 に戻り、元の起動の引数でセッションを始める。
要求の前提 6 は版の大小を比べないとするため、ファイルの有無で受け手の能力を見る。

根拠: Value 1 / Value 6（MVV 版 2）

## 決定 10: `startup` の子プロセスの上限は 600 秒にし、超えたら今の版のまま続ける

`startup` は環境の用意（`uv sync`）を含み、その中の `uv sync` が既に 600 秒の上限を持つ。同じ値を
外側の上限にし、余白を重ねない。超えたら打ち切って今の版のまま次のセッションを起動し、次の
セッションの SessionStart hook が置き直しを続ける。`NDF_RELAY_PREPARE_TIMEOUT` で変えられる。

根拠: Value 2 / Value 3（MVV 版 2）
