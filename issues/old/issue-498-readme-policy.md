# #498 README に何を書き、何を書かないかを規約にする

## 目的

`README.md` に何を書き、何を書かないかの規約が無い。歯止めは分量の基準（501 行以上で分割）
だけで、役割の境界を定めていない。結果として、規約と手順が入口の文書へ流れ込み、他の文書と
主題が重なっている。

追跡している `README.md` は 22 本・3211 行で、上位 3 本が 1354 行（42%）を占める。

**この課題は規約を決めるところまでを扱う。** 既存の 22 本を規約へ合わせるのは #500 が扱う。

## 決めること

### 1. 3 つの役割と、名前を使う条件

「README」という名前が 3 つの役割に使われている。**開いてみるまで何が書いてあるか分からない。**

| 役割 | 何であるか | 名前 |
| --- | --- | --- |
| 入口 | そのディレクトリが何であり、どう始めるかを示す | `README.md` を使う |
| 索引 | そのディレクトリに何があるかを案内する | `README.md` を使う |
| 規約 | 書き方・作り方の基準を定め、検査が突き合わせる | **`README.md` を使わない** |

### 2. 入口に書くものと書かないもの

| 書く | 書かない |
| --- | --- |
| 何であるか（1 段落） | 規約（判断の基準） |
| 何ができるか | 手順（作り方・変え方） |
| どう始めるか（導入と最初の 1 手） | 他の文書と重なる説明 |
| どこへ行けばよいか（リンク） | 版ごとの変更点 |

**詳細はリンクで渡す。** 入口が長いほど、最初の一歩が遠くなる。

### 3. 読み手ごとの置き場所

| 読み手 | 知りたいこと | 置き場所 |
| --- | --- | --- |
| 使う人 | 何ができるか / 入れ方 / 最初の一歩 / どこへ行けばよいか | `README.md` |
| 変える人 | 規約・手順・判断の基準 | `AGENTS.md` / `docs/` |
| AI エージェント | 工程と判断の基準 | `AGENTS.md` / `CLAUDE.md` / `skills/` |

### 4. 重なっている主題の正本

根の `README.md` の「開発ガイドライン」（223 行）は、`AGENTS.md` と
`docs/plugin-development-guide.md` の 2 本と主題が重なる。

| 主題 | 正本 | 理由 |
| --- | --- | --- |
| ディレクトリ構造 | `docs/plugin-development-guide.md` | 変える人が読む手順である |
| `plugin.json` の書き方 | `docs/plugin-development-guide.md` | 同上 |
| ベストプラクティス（実施すること / してはいけないこと） | `AGENTS.md` | 判断の基準であり、定義上のポリシーに当たる |
| 検証コマンド | `docs/plugin-development-guide.md` | 手順である |

**版数の扱いの正本は #499 が決める。** この課題では扱わない。移す先が競合するためである。

### 5. 規約の置き場所

**規約は `markdown-writing` の参照ファイルへ置く。** 文書の書き方の規約を持つ場所が
すでにあり、そこが唯一の置き場所である。`AGENTS.md` へ置くと、#499 が軽くしようとしている
文書へ規約を足すことになる。

**このリポジトリの 22 本がどの役割に当たるかは書かない。** それは #500 が扱う適用の側で
あり、規約は対象のリポジトリを問わずに読めるものにする。

## 受け入れ条件

- [ ] `markdown-writing` の参照ファイルに、README の 3 つの役割と、名前を使う条件が書かれている
- [ ] 入口に書くものと書かないものが表になっている
- [ ] 読み手ごとの置き場所の対応が表になっている
- [ ] `SKILL.md` から、その参照ファイルを読む条件が示されている
- [ ] 重なっている 4 主題の正本が、この課題の記録に残っている（#500 が読む）
- [ ] `python3 scripts/check-skill-frontmatter.py` が終了コード 0
- [ ] `python3 scripts/check-doc-line-limit.py` が終了コード 0
- [ ] `bash scripts/validate-runtime-plugins.sh` が終了コード 0

## 対象範囲

**含む** — `markdown-writing` への参照ファイルの追加と、`SKILL.md` からの読み込みの条件。

**含まない**

- 既存の `README.md` 22 本を規約へ合わせること（#500）
- `AGENTS.md` の版数の扱いの移動（#499）
- 役割の境界を機械で検査する仕組みの新設（**役割は機械では決まらない**。分量の検査は
  `check-doc-line-limit.py` が現在も見ている）

## 検証手段

| 何を確かめるか | コマンド |
| --- | --- |
| Skill の書式 | `python3 scripts/check-skill-frontmatter.py` |
| 文書の分量 | `python3 scripts/check-doc-line-limit.py` |
| リンク | `python3 scripts/check-markdown-links.py --root .` |
| 配布物の整合 | `bash scripts/validate-runtime-plugins.sh` |

## 境界

| 区分 | 中身 |
| --- | --- |
| 常に行う | 既存の検査の実行、`markdown-writing` の既存の構成に合わせた採番 |
| 確認してから行う | 新しい検査スクリプトの追加、Skill の追加 |
| 行わない | 既存の README の書き直し、`AGENTS.md` の版数の扱いへの手入れ |
