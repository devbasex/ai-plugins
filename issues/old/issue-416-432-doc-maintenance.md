# #416 / #432: 説明文書の分量と、確かめる対象の記述

マイルストーン「07 設計と要求の成果物の定義」のうち、説明文書に関わる 2 件をまとめる。
どちらも本番の振る舞いも本番コードの構造も変えないため、モードは `light` である。

## 依頼（原文）

> /ndf:development-workflow https://github.com/devbasex/ai-plugins/milestone/11

マイルストーンが持つ 5 件のうち、この 2 件を 1 本の Pull Request にする。

### #416 の本文（抜粋）

> `plugins/ndf/README.md` は**配布のたびに更新案内の本文を書き直す**（`release` の手順 3）。
> その本文は版ごとに長さが変わるため、分割の基準（501 行以上）へ当たりやすい。
>
> **収めるために、配布とは関係のない節を圧縮した。** v7.0.0 の移行案内（3 メジャー前）を
> 削って行数を作っている。次の配布でも同じことが起きる。

### #432 の本文（抜粋）

> **`AGENTS.md` の DO は「コードやスクリプトが呼ぶ外部コマンド」を確かめる対象にしているが、
> 自分で書いた関数の出力形式と、その読み取り側の組み合わせは対象に入っていない。**
>
> `AGENTS.md` の DO の該当項目の対象を、「外部コマンド」から「**入力と出力の形**」へ広げる。

## 目的

| 課題 | 達成したい状態 |
| --- | --- |
| #416 | 配布のたびに更新案内へ書く分量が、残り行数ではなく中身で決まる |
| #432 | 入力の形と、内部で決めた区切りの読み書きが、確かめる対象として規約に入る |

## 前提

- 前提 1: #416 の分割で `scripts/check-doc-staleness.py` を変更しない。この検査は
  `plugins/ndf/README.md` の中で 3 つの位置を決める語（配布先の表・レイアウト図・更新案内の
  見出し）を探す。読む先を別ファイルへ向けると検査の実装が変わり、モードが `standard` へ
  上がる。**位置を決める語を `plugins/ndf/README.md` に残す形で分ける**
- 前提 2: 移す先は `plugins/ndf/docs/` とする。配布物の中に置くのは、利用者が導入した
  プラグインの中から辿れるようにするためである
- 前提 3: #432 の追記で `AGENTS.md` が分割の基準（501 行以上）へ当たらない。現在 471 行で
  あるため、追記は 29 行以内に収める

## 対象範囲

含む:

- `plugins/ndf/README.md` の節の一部を別ファイルへ移し、導線を残す
- `AGENTS.md` の DO の該当項目の対象を、入力と出力の形まで広げる

含まない:

- `scripts/check-doc-staleness.py` と `scripts/check-doc-line-limit.py` の変更
- 更新案内の本文そのものの書き換え（配布の工程が持つ）
- `README.md`（リポジトリ直下）と `CHANGELOG.md` の分量
- `AGENTS.md` の他の項目の見直し

## 用語

| 用語 | この文書での意味 |
| --- | --- |
| 位置を決める語 | `check-doc-staleness.py` が記載を見つけるために探す固定の語。見つからないと検査が落ちる |
| 更新案内 | `plugins/ndf/README.md` の `## vX.Y.Z へ更新するとき` の節。配布のたびに書き直す |
| 入力の形 | コマンドや関数へ値を渡す書き方。ヒアドキュメント・複数行の引用符・ファイル渡しなど |
