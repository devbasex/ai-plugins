# #415 Kiro のインストーラが、存在しない導入先を案内なしで落とす

## 目的

`plugins/ndf/dev.kiro/install.sh` は `--project` に存在しないパスを渡すと、シェルの裸の
エラーだけを出して終了する。何を直せばよいかが読み取れない。

```console
$ bash plugins/ndf/dev.kiro/install.sh --project /nonexistent-xyz --yes
plugins/ndf/dev.kiro/install.sh: line 40: cd: /nonexistent-xyz: No such file or directory
$ echo $?
1
```

**他の入力の誤りは案内の形が揃っている。** 引数の不足・未知の選択肢・`--scope` の誤った値は、
いずれも `ERROR:` で始まる 1 行を出して終了コード 2 で止まる。存在しないパスだけがこの形から
外れる。

導入は利用者が最初に行う操作である。ここで詰まると先へ進めない。

## 決めたこと

### 存在しないときは案内を出して止める。作らない

他の入力の誤りと形を揃える。**作る側に倒さない。** 綴りを誤ったパスを渡した利用者に対し、
誤った名前のディレクトリを作ってそこへ導入すると、誤りに気づく機会が失われる。

| 採らなかった案 | 採らなかった理由 |
| --- | --- |
| 作ってよいか尋ねてから作る | `--yes` を渡す使い方（案内が載せている形）で尋ねる相手がいない |
| `--yes` のときだけ黙って作る | 同意した覚えのない場所へ書き込むことになる |

**案内の本文へ作り方を添える。** 導入先を先に作ることを利用者が知らないと 2 手になるため、
`mkdir -p <パス>` を `HINT:` で始まる行として案内へ書く。

**案内のパスは、シェルの語 1 つとして読める形で書く。** 受け取った値をそのまま埋め込むと、
空白を含むパスが 2 つの語に割れ、案内どおりに打っても意図した導入先は作られない（実測）。
整形の手段は設計で決める。

**作り方を添えるのは、存在しないパスに限る。** ファイルを渡した場合、`mkdir -p` はそのパスが
既にあるとして失敗する（実測）。実行できない手順を案内することになるため、この入力には
`HINT:` の行を出さず、ディレクトリではないことを述べる `ERROR:` の 1 行だけを出す。

### 判定はパスの解決の前に置く

現在の実装は `cd` の失敗をそのまま外へ出している。`cd` を呼ぶ前に、存在とディレクトリで
あることを確かめる。

| 入力 | 現在 | 変更後 |
| --- | --- | --- |
| 存在しないパス | `cd` のエラー、終了コード 1 | `ERROR:` と `HINT:` の 2 行、終了コード 2 |
| ディレクトリではないパス（ファイル） | `cd` のエラー、終了コード 1 | `ERROR:` の 1 行、終了コード 2 |
| 存在するディレクトリ | 導入が進む | 変わらない |

**検査は `--scope` の解決より前に置く。** 値を受け取る分岐がパスを解決しているため、検査を
そこへ足すと `--scope global` と併用した場合も先に止まる。この併用は現在も `cd` のエラーと
終了コード 1 で終わり、`--project` を無視する警告（`WARN:`）までは到達していない（実測）。
警告が出るのは、渡したパスが存在するディレクトリだった場合である。併用の扱いは受け入れ条件で
固定する。

## 受け入れ条件

- [ ] `--project` に存在しないパスを渡すと、`ERROR:` で始まる 1 行と `HINT: mkdir -p <パス>`
      の 1 行を標準エラーへ出して終了コード 2 で止まる
- [ ] `HINT:` の行のパスは、空白などを含んでいてもシェルの語 1 つとして読める形で出る
- [ ] `--project` にディレクトリではないパス（ファイル）を渡すと、`ERROR:` で始まる 1 行を
      標準エラーへ出して終了コード 2 で止まる。`HINT:` の行は出さない
- [ ] `--scope global` と存在しないパスを併用したときも、存在しないパスと同じ形で止まる
- [ ] `cd:` で始まるシェルのエラーが出力に現れない
- [ ] 存在するディレクトリを渡したときの振る舞いが変わらない（`--dry-run` で終了コード 0）
- [ ] 上の 6 つを検査する自動テストが `scripts/tests/` にあり、
      `uv run --with pytest pytest scripts/tests -q` が通る

## 対象範囲

**含む** — `plugins/ndf/dev.kiro/install.sh` の `--project` の値の検査と、その自動テスト。
検査は選択肢を解析する時点に置くため、`--scope` の値によらず働く。

**含まない**

- 他の選択肢の検査の追加
- `--scope global` と存在するディレクトリを併用したときの警告（`WARN:`）の変更
- 導入の処理そのものの変更
- 他のランタイムのインストーラ（`dev.agy/install-hooks.sh`）の検査

## 検証手段

| 何を確かめるか | コマンド |
| --- | --- |
| 振る舞い | `uv run --with pytest pytest scripts/tests -q` |
| 手で 1 度通す | `bash plugins/ndf/dev.kiro/install.sh --project /nonexistent-xyz --yes; echo $?` |
| 併用の形 | `bash plugins/ndf/dev.kiro/install.sh --scope global --project /nonexistent-xyz --yes; echo $?` |
| 案内のパスの形 | `bash plugins/ndf/dev.kiro/install.sh --project "/tmp/no such dir" --yes` の `HINT:` の行 |
| 配布物の整合 | `bash scripts/validate-runtime-plugins.sh` |

## 境界

| 区分 | 中身 |
| --- | --- |
| 常に行う | 既存テストの実行、案内の形を既存の `ERROR:` に揃える |
| 確認してから行う | 終了コードの割り当ての変更、導入の処理への手入れ |
| 行わない | 依頼の範囲外の整理、他のインストーラの変更 |
