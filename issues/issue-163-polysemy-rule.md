# 多義語を定義せずに使わないルールを markdown-writing へ追加する

## 関連リンク

- issue #163 — 本文書の依頼元
- Pull Request #162 — 「スタック」を「テスト環境」へ改め、用語表と本文へ定義を置いた実例
- 対象 Skill — `plugins/ndf/skills/markdown-writing/`

## モード

`standard`。`markdown-writing` の指示内容を変えるため、本番の振る舞いの変更として扱う。
Skill 名とコマンド名は変えず、対象も 1 Skill に収まるため `architecture` へは上げない。

## 依頼（原文）

> 指す対象が文脈で変わる語は、次のいずれかで扱う。
>
> | 対応 | 使う場面 |
> | --- | --- |
> | 一意な語へ言い換える | **既定。** 文書の主題を表す語がこれに当たる場合 |
> | 初出で定義する | 言い換えると不自然になる場合、業界で定着した呼び方がある場合 |
>
> **言い換えを既定とする理由。** 定義は読み飛ばされる。読み手が知っている語であるほど、定義を
> 読まずに自分の解釈で読み進める。語そのものを一意にすれば、読み飛ばしても誤解が生じない。
>
> あわせて次を求める。
>
> - 同じ文書の中で、1 つの語を 2 つ以上の意味に使わない
> - 説明文で使う語と、コマンド名・設定のキー名を対応させる（説明を言い換えたら識別子も揃える）
> - 定義を置く場合は、用語表と初出の本文の両方に置く

あわせて、リリースと動作確認までを完了の範囲とする指示を受けている。

## 目的

読み手が意味を知っているが指す対象が文脈で変わる語を、書き手が無自覚に使う経路を塞ぐ。
既存のルール 1 は読み手が意味を知らない語（内部識別子・略語）だけを対象としており、この種の
語は既存の 5 種のセルフチェックのいずれにも掛からない。

## 用語

| 用語 | 意味 |
| --- | --- |
| 多義語 | 読み手が語自体は知っているが、指す対象が文脈によって変わる語。「環境」「コンテナ」など |
| 主題語 | その文書が扱う対象そのものを指す語。同一ファイル内での出現数が多い |
| 候補 | セルフチェックが出力する、定義の有無を書き手が確認すべき語とファイルの組 |

範囲であり、後から成否を判定できる。

| # | 決めること | 決定 | 理由 |

| 1 | 語の一覧の置き場所 | `02-ambiguous-terms.md`（`SKILL.md` と同階層） | 一覧と閾値は運用で増減する。`01-diagram-guide.md` と同じく、条件付きで読むガイドへ置く既存の構成に合わせる |
| 2 | 一覧の初期メンバー | 実測した 12 語 | 下の「実測」を根拠にする。プロジェクト固有の語は各リポジトリで足せる形にする |
| 3 | 既定の対応 | 言い換え | 定義は読み飛ばされる。語自体を一意にすれば読み飛ばしても誤解が生じない |
| 4 | セルフチェックの成立条件 | 同一ファイル内の出現数が 5 回以上の語だけを候補にする | 語の有無だけで拾うと 131 ファイル中 92 件（70%）が候補になり判定に使えない。閾値 5 で 30 件（22%）に絞れる |

| 6 | チェックリストの文面 | 2 項目を追加する | 「言い換えたか / 定義したか」と「同一文書で 1 語 2 意味にしていないか」は別々に判定できる |

## 実測

`docs/` と `plugins/*/skills/` の Markdown 131 ファイルを対象に数えた。

```bash
grep -rho "<語>" docs/ plugins/*/skills/ --include="*.md" | wc -l
```

| 語 | 出現数 | 指しうる対象の例 |
| --- | --- | --- |
| 環境 | 175 | 実行環境 / 検証環境 / 環境変数の集合（「環境変数」46 件を除いた数） |
| エージェント | 118 | 委譲先の AI / 常駐プロセス / 利用者の代理 |
| コンテナ | 81 | コンテナ実行系の実体 / 画面の入れ物 / データ構造 |
| モデル | 75 | データの構造 / 学習済みの資産 / 画面と処理を分ける層 |
| セッション | 65 | 対話の単位 / 通信の状態 / 保存先への接続 |
| タスク | 56 | 作業項目 / 実行単位 / 非同期の処理 |
| トークン | 41 | 認証情報 / 言語モデルが数える単位 / 字句解析の単位 |
| ポリシー | 21 | 権限の規則 / 運用の方針 / 再試行の設定 |
| サービス | 12 | コンテナ定義の単位 / 業務の機能 / 常駐プロセス |
| リソース | 12 | 計算資源 / 通信で扱う対象 / 権限の対象 |
| ジョブ | 7 | 定期実行の単位 / 実行中の処理 / 印刷の単位 |
| スタック | 7 | 技術の組み合わせ / 呼び出しの履歴 / 後入れ先出しの構造 / サービスの集合 |

閾値ごとに候補となるファイル数を測った。

| 閾値（同一ファイル内の出現数） | 候補ファイル | 割合 |
| --- | --- | --- |
| 1 回以上（語の有無だけで拾う） | 92 / 131 | 70% |
| 2 回以上 | 64 / 131 | 48% |
| 3 回以上 | 46 / 131 | 35% |
| 5 回以上 | 30 / 131 | 22% |
| 8 回以上 | 18 / 131 | 13% |

閾値 5 で浮かんだ語は、その文書の主題語と一致した。

```text
plugins/ndf/skills/docker-container-access/SKILL.md → 環境:16 コンテナ:9
plugins/ndf/skills/deploy/SKILL.md                  → 環境:12
plugins/ndf/skills/external-ai/SKILL.md             → モデル:8 タスク:13
```

出現数が多いことは候補から外す理由にならず、**その文書の主題を指す語であるほど定義が要る**
という関係になっている。閾値 5 を既定とし、ガイド側で変更できるようにする。

## 対象範囲

## タスク分解

Skill の実体は Markdown であり、実行して失敗するテストを先に書く形は取れない。代わりに
**先に検証コマンドの期待値を実測で確定させ、文書を書いたあと同じコマンドで一致を確認する**
順序で進める。期待値は「実測」の表（候補 30 ファイル / 131 中）を使う。

### Task 1: 多義語のガイドを新設する

- **対象ファイル:** `plugins/ndf/skills/markdown-writing/02-ambiguous-terms.md`
- **変更内容:** 12 語の一覧と指しうる対象の例、閾値 5 の根拠、セルフチェックのコマンド、
  候補が出たときの判断手順を書く
- **満たす受け入れ条件:** 4・5・6
- **進め方:** コマンドを先に組み立ててこのリポジトリで実行し、出力が 30 ファイルになることを
  確認してから文書へ書き写す

### Task 2: ルール 2 を追加し、既存の番号を繰り下げる

- **対象ファイル:** `plugins/ndf/skills/markdown-writing/SKILL.md`
- **変更内容:** 「重要ルール」へルール 2 を挿入し、既存の 2〜8 を 3〜9 へ繰り下げる。
  セルフチェックへ多義語の確認を追加し、チェックリストへ 2 項目、詳細ガイドの表へ 1 行を足す
- **満たす受け入れ条件:** 1・2・3・7・8・9・10
- **進め方:** 挿入と番号の繰り下げだけを行い、既存ルールの本文には触らない。
  変更後に `git diff` で本文の差分が見出し番号に限られることを確認する

### Task 3: 配布と版数を揃える

- **対象ファイル:** `plugins/ndf/.claude-plugin/plugin.json`、`.claude-plugin/marketplace.json`、`CLAUDE.md`
- **変更内容:** 版数を 9.1.0 へ繰り上げ、`CLAUDE.md` へ変更内容を追記し、生成物を同期する
- **満たす受け入れ条件:** 12・13・14
- **進め方:** `bash scripts/build-runtime-plugins.sh` を実行し、`--check` で差分が残らないことを確認する

### Task 4: 検証と動作確認

- **対象ファイル:** なし（実行のみ）
- **変更内容:** 検査スクリプトとプラグイン検証を実行し、配布物を読み込んで参照できることを確認する
- **満たす受け入れ条件:** 11・12・15
- **進め方:** `scripts/check-skill-frontmatter.py` → `scripts/check-markdown-links.py` →
  `scripts/validate-runtime-plugins.sh` → `claude plugin validate` の順に実行する

## 切り戻し手順

版数を含めて元へ戻る。データ移行は無い。
