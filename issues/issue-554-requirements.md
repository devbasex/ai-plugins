# #554: 開発の指示書に「現行版だけを残す」規則を機械で見る

設計は [issue-554-design.md](issue-554-design.md) にある。この文書は「何を満たすか」だけを扱う。語の意味は末尾の「用語」にある。

## 実例: #551 の直前の状態は、既存の検査をすべて通った

**`f56c90d9`（PR #552 のマージの直前の `develop`）の `CLAUDE.md` を、この課題の検査に通すと落ちなければならない。**

| 見るもの | `f56c90d9` の値 | 既存の検査 |
| --- | --- | --- |
| `CLAUDE.md` の行数 | 333 | 行数の検査（501 行以上で落とす）は**通る** |
| 行頭が `v<版数> で` の段落 | **7 個**（36 行目以降の `v10.0.0` 〜 `v10.5.1`） | 見ていない |
| そのときの `CHANGELOG.md` の最新の `ndf` の版 | `10.9.1` | 見ていない |
| 即時読み込みの参照（`@`） | `@AGENTS.md` と **`@docs/ndf-version-decisions.md`** | 見ていない |

7 個の段落はどれも `10.9.1` 以下の版、つまり**出た版**の段落である。2 つ目の `@` は出た版の
記録そのものを毎回読み込ませていた。**この 8 件をこの課題の検査が指摘できれば、同じ状態へ戻った
ときに継続的統合が止める。**

## 目的

- 出た版の判断が指示書へ残ったまま Pull Request を出すと、継続的統合の検査が落ちる
- 指示書へ即時読み込みの参照を足すと、許可した先でない限り同じ検査が落ちる
- 配布の Pull Request（版の節を `CHANGELOG.md` へ足すもの）で、退避を忘れると**その Pull Request の中で**落ちる

## 前提

- 前提 1: 版の判断を指示書へ書くのは `ndf` だけである（退避先の文書も `ndf` の版だけを扱う）
- 前提 2: 配布の Pull Request は、`CHANGELOG.md` へ版の節を足す Pull Request の中で退避もする。v10.12.0-dev.1 と v10.14.0-dev.1 の配布がこの形である
- 前提 3: 即時読み込みの一致範囲は Claude Code 2.1.274 で実測した範囲とする（設計文書の「実測」）

## 対象範囲

含む:

- 指示書 3 本の、出た版の段落と見出しの検出
- 版が決まる前に書く段落の書き出しの形を規約に足し、その形も検出する
- 指示書 3 本の、許可した先以外への即時読み込みの参照の検出
- 検査を継続的統合のジョブとして足すこと
- 規約（`CLAUDE.md` の「版ごとの判断の記録」）と、版を上げる手順（`docs/versioning-and-distribution.md`）へ検査を書くこと
- 規則と食い違う既存の 2 行（下の「範囲へ入れたもの」）

含まない:

| 扱わないもの | 理由 |
| --- | --- |
| 読み込みの量（トークン数）を閾値で落とすこと | 設計文書の決定 1。測るには CLI の認証と課金が要り、文字数で代用すると行数と同じ穴が残る |
| 版数を持たない書き出しで書いた段落の検出 | 機械では判別できない。規約で書き出しの形を決めて検出の側へ寄せる（決定 3） |
| 必須チェックの一覧（ruleset）へ検査を足すこと | リポジトリ設定の変更で、利用者の確認が要る。設計文書の「利用者の確認が要る事項」に書き分ける |
| `release` Skill の本文 | リポジトリに依存しない手順で、検査の名前を書けない（`check-skill-repo-assumptions.py`）。リポジトリ側の手順（`docs/versioning-and-distribution.md`）へ書く |
| 退避先の見出しが扱う版の範囲の検査 | 版の段落が無い版でも範囲を上げるかは規約が決めていない。#551 の範囲外として残る |
| `playwright-kit` と MCP プラグインの版 | 前提 1 |
| リリースタグとの突き合わせ | 決定 2。タグは `main` へ進めた後に打つため、配布の Pull Request の時点では無い |

### 範囲へ入れたもの

**規則と逆のことを書いている 2 行**（起票せず範囲内へ入れた）。どちらも「判断の理由は `CLAUDE.md` に置く」と書いており、
**#551 で決めた置き場所（`docs/ndf-version-decisions.md`）と食い違う**。検査を足す手順と同じ文書・同じ話題であり、
残すと検査が守らせる規則と手順書が逆を指す。

| 場所 | いまの記載 |
| --- | --- |
| `CHANGELOG.md` 7〜8 行目 | 「その版で決めた規約は `CLAUDE.md` の版ごとの段落に」 |
| `docs/versioning-and-distribution.md` の「バージョン更新時の手順」4 | 「判断の理由は `CLAUDE.md` の側に置く」 |

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 運用・保守性 | 指摘は `ERROR: <ファイル>:<行>: <理由>` の 1 行で、直し方（退避先・許可の一覧）を含む。外部への通信・CLI の認証を要さない |
| システム環境 | Python 3 の標準ライブラリだけで動く。`actions/checkout` の既定（浅い clone・タグなし）で動く |

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わらない。配布物（`plugins/`）は触らない |
| 既存の振る舞い | 継続的統合に検査が 1 つ増える。必須にするかは利用者が決める |

## 検証手段

| 項目 | 手段 |
| --- | --- |
| 検査 | `python3 scripts/check-instruction-files.py --root .` |
| テスト | `uv run --with pytest pytest scripts/tests/test_check_instruction_files.py -q` |
| 過去の状態での再現（AC1 / AC12） | `git archive f56c90d9 CLAUDE.md AGENTS.md KIRO.md CHANGELOG.md` を一時ディレクトリへ展開し、`--root` で渡す |
| 継続的統合 | 実装の Pull Request の checks でジョブの結果を見る |

## 境界

| 区分 | 内容 |
| --- | --- |
| 常に行う | 既存の検査とテストの実行、既存の `check-*.py` の書き方（終了コード 0/1/2、`--root`、docstring に理由）に合わせる |
| 確認してから行う | 必須チェックの一覧（ruleset）への追加 |
| 行わない | `release` Skill の本文の変更、退避先の文書の中身の変更、読み込みの量の測定 |

## 用語

| 用語 | この文書での意味 |
| --- | --- |
| 指示書 | 全セッションが毎回読むリポジトリ直下の `CLAUDE.md` / `AGENTS.md` / `KIRO.md` の 3 本 |
| 出た版 | `CHANGELOG.md` に `## [ndf X.Y.Z]` の節がある版。**その最大値以下の版**を出た版として扱う |
| 版の段落 | 行頭が `v<版数> で` で始まる段落。退避先（`docs/ndf-version-decisions.md`）と #551 以前の `CLAUDE.md` が使う書き出し |
| 即時読み込みの参照 | コードの外に書いた `@<パス>`。Claude Code は参照先の内容をそのまま読み込む |

## 依頼（原文）

> **「開発の指示書には現行版で決めたことだけを残す」という規則を、機械で見ていない。**
>
> （中略）
>
> | 何を見るか | 判定の仕方 |
> | --- | --- |
> | 出た版の見出しが指示書に残っていないか | 配布済みの版数の一覧（変更履歴の文書またはタグ）と突き合わせる |
> | 即時読み込みの記法が使われていないか | 指示書の中の `@` 参照を数え、許可した先だけに限る |
> | 指示書の分量そのもの | 行数ではなく**読み込みの量**で見る（分量の基準は文書の種類で変わる） |
>
> **分量だけで見ない。** 今回の 333 行は基準内であり、行数では捕まえられなかった。
