# #554: エージェント向け指示書を適切に保つ検査を NDF から配る

設計は [issue-554-design.md](issue-554-design.md) にある。この文書は「何を満たすか」だけを扱う。語の意味は末尾の「用語」にある。
**何を「適切」と呼ぶか**は [issue-554-design-criteria.md](issue-554-design-criteria.md) にある。
外部の一次情報から導いた 21 の観点と、検査に入れたもの・入れないものがそこにある。
調査の記録は [issue-554-instruction-research.md](issue-554-instruction-research.md) にある。

## この課題でしたいこと

**NDF を入れたリポジトリで、エージェント向けの指示書を適切に保てるようにしたい。** 指示書は
`AGENTS.md`（Codex / agy）・`CLAUDE.md`・`KIRO.md` の 3 種で、**根に置いたものは、そのランタイムの
全セッションと全サブエージェントが毎回読む**（配下に置いたものは、その場所で作業したときに読まれる）。
何を書いてもよい場所ではなく、**毎回の読み込みの量をそのまま増やす場所**である。
利用者は NDF を入れた任意のリポジトリで、`devbasex/ai-plugins` はその 1 例にすぎない。

**いま指示書を機械で見ているものは無い。** 指示書は増える一方で、次の 3 つが起きても誰も止めない。

| 起きること | いまの結果 |
| --- | --- |
| 出た版の判断が指示書へ残り続ける | 毎回の読み込みに乗り続ける。`ai-plugins` では 333 行のうち 79%（264 行）がこの状態になった（#551） |
| 即時読み込みの参照（`@<パス>`）が増える | 参照先の中身も毎回読み込まれる。**参照先が消えていても気づかない** |
| 指示書の総量が増える | 気づく手段が無い。行数の検査を持つリポジトリでも、1 本ずつの行数しか見ていない |

**何を見るべきかは、外部の一次情報から導く。** 出典 23 件（一次情報 22 件・個人ブログ 1 件）から 21 の観点が出ており、機械で判定できるかで
仕分けると、**落とせるのは 4 つ**（参照先の無い即時読み込み・許可していない即時読み込み・出た版の段落・
量の上限）、**報告だけが 2 つ**（読み込みの量・指示の数）である。**残る 15 は入れない**（意味の判定になる、
リポジトリごとに違う、助言が割れている）。

**指示書の「適切」は動く。** 1 年以内に、形式の統治の移管・読むファイルの追加・強調語の助言の反転・
自己検証の指示の削除が起きている。**観点の一覧をデータとして持ち、引き金を決めて調べ直す。**

**この課題で配るのは、その観点を見る検査である。** 配布物（`plugins/ndf/`）に置き、4 ランタイムのどれで
入れても同じ実体が動く。判定の強さは**リポジトリ側の宣言**で決まる。

| 宣言 | 動く判定 |
| --- | --- |
| 宣言が無い | 壊れた即時読み込み（参照先が無い）で落ちる。指示書の本数と読み込みの量を報告する |
| 宣言がある | それに加えて、許可していない即時読み込み・出た版の段落・読み込みの量の上限で落ちる |

目的を 3 つにまとめると次になる。

- 指示書の壊れた即時読み込みは、宣言の有無によらず落ちる
- 版の判断を指示書へ書くリポジトリでは、出た版の段落が残ったまま Pull Request を出すと落ちる
- 毎回の読み込みの量が、実行するたびに数字で出る

## 実例: この検査が捕まえるもの（`ai-plugins` の過去の状態）

**動機と、検査が何を捕まえるかは `ai-plugins` の過去の状態で示せる。** これは適用の 1 例であり、判定の前提ではない。

| 見るもの | `f56c90d9`（PR #552 の直前）の値 |
| --- | --- |
| `CLAUDE.md` の行数 | 333（行数の検査は 501 行以上で落とすため**通っていた**） |
| 行頭が出た版の版数で始まる段落 | **7 個**（`v10.0.0` 〜 `v10.5.1`。当時の最新は `10.9.1`） |
| 即時読み込みの参照 | `@AGENTS.md` と **`@docs/ndf-version-decisions.md`**（出た版の記録そのものを毎回読ませていた） |

この 8 件を退避した結果、毎回の読み込みが **19,186 トークン（30.3%）減った**（PR #552 の実測）。
**同じ状態へ戻ったときに機械が止めるのが、この課題の狙いである。**

## 前提

- 前提 1: 実行するのはリポジトリの作業ツリーの中で、`git` が使える
- 前提 2: 即時読み込みの一致範囲は Claude Code 2.1.274 で実測した範囲とする（設計文書の「実測」）。他のランタイムが同じ記法を読むかは測っていない
- 前提 3: 指示書の既定の名前は `AGENTS.md` / `CLAUDE.md` / `KIRO.md` の 3 種とする。増減はリポジトリ側の宣言で行う
- 前提 4: 宣言はリポジトリの `.ndf/` に置く（`worktree.json` / `projects.json` と同じ場所と同じ考え方）
- 前提 5: 観点の出所は 2026-09-17 に取得した外部の一次情報 23 件とする（調査の記録）。**この前提は日数で古くなる**ため、調べ直しの引き金を設計に持つ

含む:

- 配布物（`plugins/ndf/scripts/`）に置く検査 1 本と、その単体テスト

- 調べ直しの経路（`--refresh`）と、その引き金・記録の場所
- 走査するスコープ（プロジェクト / ユーザー / プラグインの配布物）と、指摘ごとの扱いの判定

- 宣言の書き方と判定の一覧を書いた参照 1 本

| 指示書どうしの重複した段落の検出 | 決定 8。同じ規約を意図して再掲する書き方があり、機械では区別できない |
| ランタイム間で内容が食い違うことの検出 | 決定 8。同じ意味かどうかの判定になる |

| 読み込みの量をトークン数で測ること | 決定 7。CLI の認証と課金が要り、読み込む設定で値が変わる。バイト数で測る |

| 観点の一覧を `--refresh` が自動で書き換えること | 決定 14。外部の読み違いがそのまま検査の基準になる。提示までにする |
| 機械で判定できない 15 の観点 | 観点の文書の表。意味の判定になる・リポジトリごとに違う・助言が割れている |
| 指摘を検査自身が直すこと・課題を立てること | 決定 17。判定と出力までを検査が持ち、書き込みと投稿は呼び出し側が行う |
| Skill の陳腐化（#743） | 別の課題。調べ直しの部品と扱いの表は共有し、観点と判定は #743 が足す |
| `.kiro/steering/` や `.claude/` の下の設定 | 指示書の名前を持たない。宣言の `files` へ書けば対象になる |
| このリポジトリの `scripts/` 側への検査の新設 | 配布物の側に置くため。このリポジトリは配布物を呼ぶ |

## 検査が落ちたときに何をするか

| 指摘 | 直し方 |
| --- | --- |
| 参照先の無い即時読み込み | 参照を消すか、実在するパスへ直す |
| 許可していない即時読み込み | `@` を外す（リンクかコードスパンにする）。毎回読ませる必要があるなら、宣言の `imports` へ理由とともに足す |
| 許可の指し先が無い | 宣言の `imports` からその行を外す |
| 出た版の段落が指示書に残っている | その段落から次の見出しまでを、宣言の `decisions` が指す退避先へ移す |
| 版が決まる前の段落が、配布を越えて残っている | 書き出しを出す版の版数へ直し、同じく退避先へ移す |
| 読み込みの量が上限を超えた | 現行でない記述を退避先へ移す。上限そのものを変えるなら宣言を直す |

**版が決まる前の段落は、宣言した印（既定は無し）で書き出す。** 版数はまとまりをマージするまで決まらないため、
書く時点では直前の正式版しか書けない。印を宣言したリポジトリでは、配布で新しい版が出た時点で検査が拾う。

## 受け入れ条件

### 走査の対象

- [ ] AC1: 宣言の無いリポジトリで実行すると、根の `AGENTS.md` / `CLAUDE.md` / `KIRO.md` と配下の同名のファイルを走査し、走査した本数を出力へ出す
- [ ] AC2: `git` が追跡していないファイルは走査に入らない
- [ ] AC3: 指示書が 1 本も無いリポジトリでは、対象が無いことを 1 行出して終了コード 0 で終わる。ただし版を取れない宣言があるときは終了コード 2 が優先する
- [ ] AC4: 宣言の `files` に値を足すと、その値と一致するファイルが走査に入る。`/` を含まない値はファイル名の一致、含む値は根からの相対パスの一致になる
- [ ] AC5: `files` を書くと既定の 3 つは対象から外れる（置き換えであって、足し込みではない）

### 走査の範囲と扱い

- [ ] AC6: 既定では、プロジェクトのスコープ（根と配下の追跡された指示書）だけを走査する
- [ ] AC7: `--scope user` / `--scope plugins` を重ねて渡すと、宣言の `scopes` が持つ位置も走査する。宣言に位置が無ければそのスコープは走査されない
- [ ] AC8: ユーザーとプラグインのスコープでは、宣言の `scopes` が挙げた位置が根になる。その中に収まる `@` 参照は存在を判定し、量にも入る
- [ ] AC9: 指摘の 1 行は `ERROR: [<扱い>] <位置>: <理由>` の形で、`<扱い>` は `直す` / `起票` / `報告` のどれかになる
- [ ] AC10: 実行しているスクリプトの実体が `--root` の下にあるとき、すべての指摘が `[直す]` になる（NDF の開発リポジトリの判定）
- [ ] AC11: そうでないとき、プロジェクトとユーザーのスコープは `[直す]`、NDF が配るものは `[起票]`、他のプラグインが配るものは `[報告]` になる
- [ ] AC12: 検査はどのファイルも書き換えず、課題も立てない（扱いの判定と出力だけを行う）

### 宣言が無くても動く判定

- [ ] AC13: 参照先の存在しない `@docs/none.md` が**即時読み込みを解釈する指示書**にあると、終了コード 1 で `ERROR: [直す] <ファイル>:<行>: …` の形の指摘が出る
- [ ] AC14: 解釈しない指示書（既定では `AGENTS.md` / `KIRO.md`）の `@docs/none.md` は指摘されず、量の集計でも参照をたどらない
- [ ] AC15: 宣言の `import_syntax` へ足した指示書では、同じ判定が働く
- [ ] AC16: `import_syntax` に無い指示書へ `imports` を書くと、効かない許可として指摘される
- [ ] AC17: 参照先は、その参照を書いた指示書のディレクトリから解決する（`docs/AGENTS.md` の `@x.md` は `docs/x.md` を指す）
- [ ] AC18: `@~/x.md` と、作業ツリーの外へ出る参照は存在を判定しない（許可の判定には掛ける）
- [ ] AC19: 追跡された symlink が根の外を指すとき、その参照先は読まず、存在も判定せず、量にも入れない
- [ ] AC20: コードスパン（`` `@openai/codex` ``）とコードブロックの中の `@` は指摘されない
- [ ] AC21: メールアドレスの形（`user@example.com`）と、括弧の直後の `@`（`(@x.md)`）は指摘されない
- [ ] AC22: 強調の中（`**@AGENTS.md**`）と空白の直後の `@AGENTS.md` は参照として読む
- [ ] AC23: 根の指示書ごとに、その本文と `@` でたどった先の合計バイト数が 1 行ずつ出る。多段の参照をたどり、同じ参照先は 1 回だけ数え、循環する参照でも止まる。`--report` を付けると内訳が出る

- [ ] AC25: 宣言が無いとき、出た版の判定と許可の判定は動かず、動かないことが出力に出る

- [ ] AC26: 指示書ごとに、箇条書きの項目と段落の文の数（指示の数）が出力に出る。箇条書きは字下げしたものも数え、段落は連結してから句点で区切る。見出しは 1 行 1 つ。表・引用・コードブロック・HTML の行は数えない
- [ ] AC27: 観点のデータ（`instruction-criteria.json`）を読めないとき、終了コード 2 で終わる
- [ ] AC28: 観点のデータから行を消すと、その判定は動かない（消した観点の指摘が出ない）
- [ ] AC29: 知らない `id` の行があるとき、終了コード 2 で終わる
- [ ] AC30: 観点のデータで `enforce` が `report` の観点は、値が大きくても終了コード 0 のまま
- [ ] AC31: 観点のデータの `checked_at` が既定の日数（90 日）より古いと、`NOTE:` が 1 行出る。終了コードは変わらない
- [ ] AC32: 宣言の `review_interval_days` を変えると、その日数で `NOTE:` の出方が変わる。`reviewed_at` を書くと、日数を数える起点がそちらになる

### 調べ直し

- [ ] AC33: `--refresh` は観点のデータの `sources[]` の URL を取得し、**出典ごとに 1 行**（名前・前回の参照日・取得の成否・前回と内容が変わったか）を標準出力へ出す
- [ ] AC34: 出典ごとの待ちは既定 10 秒で、越えたら取得の失敗として一覧へ理由付きで出る。待ちは引数 `--refresh-timeout <秒>` > 宣言の `refresh_timeout_seconds` > 既定の順で決まる
- [ ] AC35: 内容が変わったかは、前回取得時の指紋（`fingerprint`）との一致で判定する。指紋が無い出典は「前回の記録が無い」と出る
- [ ] AC36: その出典から取った主張（`claim`）を同じ一覧へ並べる。**主張が今も成り立つかは人が読む**（機械で判定しない）
- [ ] AC37: `--refresh` はどのファイルも書き換えない（実行の前後でファイルの内容とタイムスタンプが変わらない）
- [ ] AC38: 通信できない環境で `--refresh` は終了コード 2 で終わり、**`--refresh` を付けない検査は同じ環境で終了コード 0 になる**
- [ ] AC39: `--refresh` が取得に失敗した出典を、黙って落とさずに一覧へ出す
- [ ] AC40: 出典の一部だけが取得に失敗したとき、一覧は全件を出したうえで終了コード 2 を返す（成功した分を理由に 0 にしない）

### 宣言があるときの判定

- [ ] AC41: 宣言に `$schema` を書いても、書かない宣言と同じに読まれる（読み取り側は参照しない）。解決できない値でも検査の結果は変わらない
- [ ] AC42: `release` の参照が、`$schema` に**版を固定した公開の URL** を書く例を持つ（導入先がランタイムごとに違うため、相対パスにしない）
- [ ] AC43: `imports` を宣言すると、許可の外の `@` は参照先が存在しても終了コード 1 になる。キーはリポジトリの根からの相対パスで、同じ名前の別の指示書には効かない
- [ ] AC44: `"imports": {}`（許可が 1 つも無い）を書くと、参照がすべて指摘される。未指定のときは許可の判定が動かない
- [ ] AC45: `imports` の指し先が存在しないと終了コード 1 になる（宣言の陳腐化）。存在を判定しないパス（`~`・作業ツリーの外）の許可は、存在しないことを理由に指摘しない
- [ ] AC46: `released` に変更履歴の文書と見出しの形を宣言すると、最新以下の版数で書き出した段落と見出しが指摘される
- [ ] AC47: 段落の 2 行目以降が版数で始まっても指摘されない（折り返した行は段落の書き出しではない）。連続する箇条書きの 2 件目以降は段落の先頭として指摘される
- [ ] AC48: 同じ宣言で、最新より新しい版数で始まる段落は指摘されない
- [ ] AC49: `released` にタグの形を宣言すると、タグの最大値を最新として同じ判定をする
- [ ] AC50: 最大値は数字 3 つの組として決まる。`10.9.0` と `10.10.0` があるとき、最新は `10.10.0` になる
- [ ] AC51: `pattern` に名前付きの捕捉 `(?P<version>…)` が無いとき、終了コード 2 で終わる
- [ ] AC52: 捕捉した値が版数の形（数字 3 つ＋任意の接尾辞）でないとき、終了コード 2 で終わる
- [ ] AC53: `released.path` が根の外を指すとき（`../` や根の外への symlink）、終了コード 2 で終わる
- [ ] AC54: `released` の宣言から版を 1 つも取れないとき、走査の前に終了コード 2 で終わる（壊れた即時読み込みの指摘も出さずに止まる）
- [ ] AC55: `pending_marker` を宣言すると、その印で書き出した段落は基底が最新**未満**のときだけ指摘される
- [ ] AC56: 出た版の段落の指摘に、宣言の `decisions` が指す退避先が出る
- [ ] AC57: `budget.bytes` を宣言し、**根の指示書 1 本の**合計がそれを超えると終了コード 1 になる
- [ ] AC58: 宣言の構造が不正なとき、終了コード 2 で終わる。対象は JSON として読めない・`version` が無いか未対応・項目の型が違う（`files` が配列でない）・`pattern` が正規表現として読めない・`pending_marker` が空文字列の 5 つ

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 運用・保守性 | 指摘は 1 件 1 行で、直し方（退避先・宣言の項目）を含む。外部への通信・CLI の認証を要さない |
| 移行性 | 宣言が無いリポジトリでも動き、既定の判定だけが働く。既存の利用者が宣言を書くまで落ちない |
| システム環境 | Python 3 の標準ライブラリだけで動く。`actions/checkout` の既定（浅い clone・タグなし）で、タグを使う宣言以外は動く |

## 境界

| 区分 | 内容 |
| --- | --- |
| 常に行う | 既存の配布スクリプト（`plugins/ndf/scripts/`）の書き方（終了コード・`--root`・docstring に理由）に合わせる。単体テストを `plugins/ndf/scripts/tests/` へ置く |
| 確認してから行う | 必須の検査の一覧（ruleset）の変更。利用者が入れると決めたため、実行は実装 Pull Request のマージ後に進行側が行う |
| 行わない | 新しい Skill の追加、指示書の中身の自動の書き換え、このリポジトリの `scripts/` への検査の新設 |

未決の項目は無い。必須の検査へ入れるかは利用者が決めた（入れる）。

## 用語

| 用語 | この文書での意味 |
| --- | --- |
| 指示書 | エージェントが読む規約の文書。既定の名前は `AGENTS.md` / `CLAUDE.md` / `KIRO.md` |
| 根の指示書 | リポジトリの根に置かれた指示書。セッションのたびに読まれる |
| 配下の指示書 | サブディレクトリに置かれた指示書。その場所で作業したときに読まれる |
| 即時読み込みの参照 | コードの外に書いた `@<パス>`。参照先の内容がそのまま読み込まれる |
| 出た版 | リポジトリが配布済みとして宣言した版。取り出し方（変更履歴の文書・タグ）は宣言が決める |
| 宣言 | リポジトリ側に置く `.ndf/instructions.json`。無ければ既定の判定だけが動く |
| 読み込みの量 | 根の指示書と、そこから即時読み込みでたどった先の合計バイト数 |
| 観点 | 指示書がどうあるべきかの 1 項目。外部の一次情報から導き、`instruction-criteria.json` が一覧を持つ |
| 落とす / 報告する | 観点ごとの強さ。落とすものは終了コード 1、報告するものは数を出すだけ |
| 調べ直し | `--refresh`。観点の出典を読み直し、食い違いを提示する（書き換えない） |
