## 依存の更新の比較

| 観点 | X2（自前） | Dependabot（PRD2） | Renovate（PRD1） |
| --- | --- | --- | --- |
| 公開から 7 日待つ | `exclude-newer` と候補の除外 | `cooldown.default-days: 7` | `minimumReleaseAge: "7 days"` |
| `uv.lock` | 自前で `uv lock` | `package-ecosystem: "uv"` | `pep621` の manager |
| 推移的な依存 | 動かさない（3380-3） | `allow` の `dependency-type` に `indirect` がある。`uv.lock` で推移的な依存をどう上げるかは未確認 | `lockFileMaintenance` で lock ごと作り直す。`uv.lock` の推移的な依存は脆弱性の修正のときだけ上げる |
| 脆弱性 | 無い（3380-2） | security updates が警告から PR を出す。uv の推移的な依存は親の更新が要ると上げられない | 脆弱性の警告から PR を出す設定（`vulnerabilityAlerts`）がある。既定値と、警告の出所（GitHub・OSV）の扱いは未確認 |
| GitHub Actions の版 | 対象外 | このリポジトリで既に週 1 回動いている（`.github/dependabot.yml`） | SHA への固定を設定 1 つで行う |
| 導入の費用 | スクリプト・テスト・週 1 回のジョブを作って保つ | 既存の設定へ 1 項目を足す。新しい権限は要らない | GitHub App の導入（リポジトリへの書き込みの権限）かセルフホスト。AGPL-3.0 |
| 固定の理由 | `[tool.ndf.deps.hold]` の自由文 | `ignore` の版と設定のコメント | `packageRules` の `enabled: false`・`allowedVersions` |

**推奨**は Dependabot を使い、X2 を縮めることである（決定 118）。結論は利用者が設計承認ゲートで決める（#3395 の前提 6）。

**推奨が依る未確認の挙動。** 次の 2 つは「確かめられなかったこと」に挙げたもので、推奨の理由の一部はこれに依る。承認資料にこのまま載せる。

| 未確認の挙動 | 依る推奨・理由 | 外れたとき |
| --- | --- | --- |
| Dependabot が `uv.lock` の推移的な依存を version updates で上げるか | 7 点の「全 lock」と 3380-3 を 11.x へ回す理由 | 3380-3 を範囲へ戻し、行き先を X2 にする |
| Renovate の `vulnerabilityAlerts` の既定値と、警告の出所の扱い | Renovate を採らない理由のうち、脆弱性の観点 | 採らない理由は導入の費用（書き込みの権限かセルフホスト）だけになる。推奨は変わらない |

**結論ごとに書き直す行。** 利用者が推奨と別の結論を選んだら、承認の後の設計 PR で次の行を書き直す。

| 結論 | X2 の中身（「構成要素」） | 範囲の一覧の行 | 行き先の表の行 | 決定 |
| --- | --- | --- | --- | --- |
| 既存ツール（Dependabot。推奨） | 書き直さない | 書き直さない | 書き直さない（X2 の 5 行の「比較の結論まで着手しない」を外す） | 決定 118 を決定として確定する |
| 既存ツール（Renovate） | Renovate の導入（GitHub App かセルフホスト）と設定・一度の引き上げ | 3380-2・3380-3・3380-6 と 7 点の「全 lock」の理由 | X2 の 5 行（3347-10・3380-1・3380-2・3380-4・3380-9） | 決定 118 を Renovate で書き直す |
| X2（自前） | 詳細設計の X2 のまま（`plugin-deps.py`・週 1 回のジョブ）に、脆弱性の確かめを足す | 3380-2・3380-3・3380-6 と 7 点の「全 lock」の理由 | X2 の 5 行 | 決定 118 を書き直す |
