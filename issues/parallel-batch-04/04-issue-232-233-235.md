- issue: [#232](https://github.com/devbasex/ai-plugins/issues/232) / [#233](https://github.com/devbasex/ai-plugins/issues/233) / [#235](https://github.com/devbasex/ai-plugins/issues/235)

この文書は仕様と設計の両方を持つ。`standard` のため設計は独立したファイルにせず、同じ

## 用語

| 語 | この文書での意味 |
| --- | --- |
| 起点 | pytest を起動したときの根（`rootdir`）。ここでは開発のブランチを指さない |
| 束 | 1 つの `tests/` ディレクトリにまとまったテストの集まり |
| 収集 | pytest がテストを見つける段階。実行より前にある |
| 前提のコマンド | テストが子プロセスとして呼ぶ外部コマンド（`bash` / `jq` / `git`） |
| 身元 | git がコミットの作成者として記録する名前とメールアドレス |
| 継続的統合 | GitHub Actions のワークフロー |
| 実行環境 | テストを動かす計算機と、そこに入っているコマンド・設定 |

**「起点」を pytest の根の意味だけで使う。** このリポジトリでは開発の起点ブランチにも
同じ語を使うが、この文書では出てこない。

## 何を解決するか

## 設計

### 収集（#232）

`pytest_plugins` の宣言を、リポジトリの根の `conftest.py` へ移す。pytest の案内が求める
位置そのものである。

| 位置 | 変更の内容 |
| --- | --- |
| リポジトリの根の `conftest.py` | `pytest_plugins = ["pytester"]` を置く |
| `playwright-kit-ops/tests/conftest.py` | `pytest_plugins` を外す。探索の先の設定は残す |
| `playwright-kit-ops/pyproject.toml` | `addopts` へ `-p pytester` を足す |

**2 つの起点のどちらでも `pytester` が有効になるようにする。** リポジトリの根を起点に
した実行では根の `conftest.py` が読まれる。その skill のディレクトリを起点にした実行では
根の `conftest.py` は読まれないため、そのディレクトリの設定ファイルで足す。

実測では、この形でリポジトリの根から 1 回の起動で全件が通る。

```console
$ uv run --project plugins/playwright-kit/skills/playwright-kit-ops --with pytest pytest . -q
1652 passed in 50.79s
```

**依存の解決は起点を変えても要る。** `playwright-kit-ops` のテストは、その skill の
`pyproject.toml` が宣言する依存を使う。リポジトリの根から起動するときは、`--project` で
その宣言を指す。

継続的統合のジョブは 1 つにまとめ、この起動の形をそのまま使う。

テストの実行は、起点の直下へ報告書のディレクトリ（`reports/<日時>/`）を作る。追跡の対象から
外す。

### 前提のコマンド（#233）

読み飛ばしをやめ、収集の段階で不足を検出して失敗させる。判定はリポジトリの根の
`conftest.py` が持ち、束ごとの前提を対応表で宣言する。

```python
REQUIRED_COMMANDS = {
    "scripts/tests": ("bash", "jq", "git"),
    "plugins/ndf/skills/worktree/tests": ("bash", "jq", "git"),
    "plugins/ndf/skills/development-workflow/tests": ("bash", "jq", "git"),
    "plugins/ndf/skills/cross-refactoring/tests": ("git",),
}
```

収集した項目に対応表の束が含まれているときだけ、その束の前提を確かめる。束を 1 つも
収集していなければ何も確かめない。前提の一覧を 1 か所へ置きつつ、束ごとに違う前提を
保つためである。

| 状態 | 振る舞い |
| --- | --- |
| 前提が揃っている | これまでどおり |
| 不足があり、読み飛ばしの指定が無い | 不足の一覧を示して 0 以外の終了コードで終わる |
| 不足があり、読み飛ばしの指定がある | その束の項目を読み飛ばす |

読み飛ばしの指定は環境変数 1 つ（`NDF_TESTS_ALLOW_MISSING_COMMANDS=1`）とする。

束の側の `collect_ignore_glob` と、テストの `skipif` は外す。**外すことで、束だけを起点に
したときも読み飛ばしではなく失敗になる。** 収集された項目が呼ぶコマンドが無ければ、
テストはその場で落ちる。

継続的統合の「コマンドの有無を確かめる」ステップは外す。テストの側が確かめるようになるため、
同じ前提を 2 か所で持たない。

### 身元（#235）

身元を用意する責任をテストの側へ移す。

| 位置 | 変更の内容 |
| --- | --- |
| 落ちる 3 ファイル | テスト用のリポジトリを作る時点で、リポジトリの設定へ身元を書く |
| リポジトリの根の `conftest.py` | テストの実行中だけ、全体設定と system の設定を空へ向ける |

**全体設定を空へ向けるのは、依存が戻らないようにするためである。** 身元を用意し直しても、
実行した人の全体設定が残っていれば、次に同じ依存が入ったときに気づけない。空へ向けておけば、
用意していないテストはその場で落ちる。

向け先は一時ディレクトリに作った空のファイルとし、テストの実行が終われば消える。実行した人の
設定は書き換えない。

継続的統合の「git の身元を設定する」ステップは外す。

**本番の振る舞い（`refactor.py`）は変えない。** 呼び出し側が既定の身元を与える形も採れるが、
利用者がコミットの作成者を選べなくなる。

## 決定の記録

### 宣言を根へ移す

`pytest_plugins` をやめて別の手段で `pytester` を有効にする形も採れるが、その skill の
テストは `pytester` を使う自己テストを持っており、有効にする経路は必要である。pytest の
案内が示す位置へ移すのが、案内と実装が一致する形になる。

### 起点ごとに有効化の経路を分ける

根の `conftest.py` だけに置くと、その skill のディレクトリを起点にした実行で `pytester` が
読まれない。設定ファイルの `addopts` だけに置くと、リポジトリの根を起点にした実行で読まれない。
起点は 2 通りあるため、両方に置く。

### 読み飛ばしではなく失敗を既定にする

読み飛ばしが既定だと、テストの 9 割以上が消えても終了コード 0 で終わる。「通った」と読める
状態を既定にしない。読み飛ばしたい実行環境のために指定を 1 つ残すが、選ぶのは実行する側とする。

### 前提の一覧を根の 1 か所へ置く

束ごとに違う前提を全体へ課すと、必要のないコマンドを求めることになる。対応表を根へ置き、
収集した束にだけ適用する形にすれば、一覧は 1 か所のまま束ごとの違いを保てる。

### 身元はテストが用意する

呼び出し側（`refactor.py`）が既定の身元を与える形は、本番の振る舞いを変える。コミットの
作成者は利用者の設定で決まるべきもので、テストの都合で既定を置かない。

**残リスク（未確認）**: 全体設定を空へ向けたことで、git の設定に依存する別のテストが将来
書かれたときに、原因が分かりにくい形で落ちる可能性がある。根の `conftest.py` に、何を
空へ向けているかを書き残す。

## テスト設計

| 何を確かめるか | 置き場所 |
| --- | --- |
| 前提のコマンドが不足しているとき、収集が 0 以外の終了コードで終わる | 根の設定のテスト（新設） |
| 失敗の出力に不足したコマンドの名前が出る | 同上 |
| 読み飛ばしの指定があるとき、これまでどおり読み飛ばす | 同上 |
| 対応表に無い束だけを収集したとき、前提を確かめない | 同上 |
| 身元が全体設定に無くても、対象の 3 ファイルが通る | 既存の 3 ファイル（実行環境で確かめる） |
| リポジトリの根を起点にして全件が収集される | 継続的統合の実行そのもの |

前提の不足は、`PATH` を絞った子プロセスとして pytest を起動して確かめる。実行環境の
`PATH` は書き換えない。
