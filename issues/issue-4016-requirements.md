## 何が起きたか

PR #3994（lracct の設計）の cross-review が 2026-11-22 01:37 JST に終わるとき、指摘のスレッドを PR へ書いた。自分のアカウントの事象（`users/<login>/events`）を分ごとに数えると次のとおりだった。

| 時刻（JST） | 書き込み |
| --- | --- |
| 01:37 | インラインのコメント 20 件・レビュー 23 件 |
| 01:38 | インラインのコメント 10 件・レビュー 12 件 |

20 分後（01:57 JST）に Issue を起票すると、GraphQL は 200 で `createIssue.issue: null`、REST は 403 `You have exceeded a secondary rate limit and have been temporarily blocked from content creation` を返した。5 分おきの打ち直しも通らない。同じアカウントで動く並列のレーンも、その間は PR・Issue・コメントを書けない。

事象の一覧は 1 ページ（100 件）だけを読んだ。resolve（GraphQL の mutation）はこの一覧に出ないので、実際の書き込みの数はもっと多い。

## 種類

機能追加（GitHub の二次レート制限の内側に書き込みを収める約束は、今の SSOT（`contracts/limits.json` と cross-review の確定仕様）に無い。書き込みの形と間隔を新たに約束する）

## 今の姿

cross-review は終わるときに、収束の妨げになる重さの指摘 1 件ごとにスレッドを PR へ書く（#3939・#3941。実装は `plugins/ndf/src/ndf/domains/crossreview/threads.py`）。

| 書き込み | 1 件の指摘あたり | 間隔 | 二次レート制限に当たったとき |
| --- | --- | --- | --- |
| スレッドを作る（`POST /pulls/{n}/comments`） | 1 回（行を断られるとファイルに付け直して 2 回） | `cross-review.thread-spacing`（1 秒）。同じプロセスの中だけ | `cross-review.secondary-rate-limit`（3 回まで、`retry-after` が無ければ毎回 60 秒） |
| 返信する（`POST /pulls/{n}/comments/{id}/replies`） | 1 回（直した・見送った指摘） | 無し | 同上 |
| resolve（GraphQL の `resolveReviewThread`） | 1 回（直した・見送った指摘） | 無し | 同上 |

NDF のほかの書き込み（Issue の起票・PR のコメント・本文の書き換え。`adapters/publish.py`・`domains/backlog/issues_gh.py`）は、どれも `adapters/github.py` の `GitHub.rest` / `GitHub.graphql` を通るが、間隔を持たない。並列のレーンはすべて同じアカウントで書くので、プロセスごとの間隔では合計を抑えられない。

## 何を足すか・変えるか

| | 前 | 後 |
| --- | --- | --- |
| 指摘のスレッドの作り方 | 指摘ごとに 1 回 | 行に付ける指摘は、付けるコミットごとに 1 つのレビュー（`POST /pulls/{n}/reviews` の `comments[]`）にまとめる |
| 今回の実行で直した・見送った指摘 | スレッドを作り、返信し、resolve する（3 回） | 最初のコメントに直したコミットか見送りの理由を書いて作り、返信しない |
| resolve | 1 件ごとに 1 回の mutation | 書き込みの間隔を当てる（まとめ方は設計で決める） |
| 書き込みの間隔 | cross-review のスレッドを作るときだけ、プロセスの中で 1 秒 | NDF が GitHub へ書くすべての要求に、マシン全体で共有する間隔を当てる |
| 二次レート制限の待ち（`retry-after` が無いとき） | 毎回 60 秒 | 60 秒から指数的に延ばし、上限の回数で止まる |

## 今の利用者への影響と互換

- PR に残る記録の見え方が変わる。直した・見送った指摘のスレッドは、返信の無い 1 つのコメントで閉じる。前の実行が作ったスレッドへの返信は今のとおり残る
- NDF の書き込みは、マシン全体の間隔の分だけ遅くなる。内容を作る書き込みは前の内容を作る書き込みから約 7 秒を空け、並列のレーンが同時に書けば順に並ぶ（6 つなら最後は約 36 秒）。二次レート制限に当たった後は、その待ちが終わるまでどのレーンも書かない。cross-review の終わりは、まとめた分だけ要求の数が減る
- 公開インタフェース（コマンドの引数・結果 JSON の形）は変わらない

## なぜ困るか

二次レート制限に当たると、同じアカウントで動くすべてのレーンが PR・Issue・コメントを書けなくなる。ブロックが続く長さは公開されておらず、打ち続けると BAN されうる。cross-review を並列のレーンで回すたびに、ほかのレーンの起票と PR の記録が止まりうる。

## 目的

- cross-review の 1 回の終わりに作るリクエストを数件に収める
- マシン全体の書き込みの速さを、GitHub の上限（下の「前提」）の内側に保つ
- 誰に効くか: 並列の計画のすべてのレーンと、オーガナイザーの起票

## 対象範囲

含む:
- `plugins/ndf/src/ndf/domains/crossreview/threads.py` の書き込み
  - 行に付けるインラインのコメントを、付けるコミットごとに 1 つのレビューにまとめて送る
  - 今回の実行で直した・見送った指摘は、スレッドの最初のコメントに直したコミットか見送りの理由を書いて作り、返信を省く（前の実行が作ったスレッドへの返信は残す）
  - 間隔を返信と resolve にも当てる
- NDF が GitHub へ書く要求（cross-review の書き込み・Issue の起票を包むもの・PR のコメント）の間隔を、マシン全体で共有する。1 時間 500 件に収める平均の間隔（約 7 秒）を既定の目安にする
- 二次レート制限に当たったときの待ちを、`retry-after` が無ければ 1 分から指数的に延ばす形にそろえる（`cross-review.secondary-rate-limit`）

含まない:
- 読み取りの削減（条件付きのリクエスト）。別の課題で測ってから決める
- エージェントが NDF を通さずに打つ `gh` のコマンド（`gh pr create`・`gh issue comment` など）の間隔。NDF のコードを通らないので、この課題の仕組みでは数えられない

## 前提

- 前提 1: 二次レート制限は、GitHub が時間あたりの回数（一次の上限）とは別に、短い間の書き込みの多さ・同時の要求の多さで断る上限で、403 か 429 と本文の `secondary rate limit` で返る。内容を作るリクエストは、Issue・コメント・レビュー・PR など新しい内容を作る書き込みを指す。GitHub の上限は docs.github.com の rate-limits-for-the-rest-api・best-practices-for-using-the-rest-api（2026-11-22 に読んだ）のとおりとする。内容を作るリクエストはおおむね 1 分 80 件・1 時間 500 件、書き込みは並列にせず順に送り間を 1 秒以上空ける、当たったら `retry-after` → `x-ratelimit-reset` → 1 分以上の順で待ち、続けば指数的に延ばす。ブロックが続く長さと残りの量は公開されていない
- 前提 2: 「マシン全体」は、同じ OS のユーザーで動く NDF のプロセスすべてを指す。別のマシン・別のコンテナで同じアカウントが書く分は数えない
- 前提 3: レビューの作成（`POST /pulls/{n}/reviews`）の `comments[]` は `subject_type` を持たない（2026-11-22 に文書で確かめた）。ファイルに付けるスレッドはレビューにまとめられない

## 受け入れ条件

- [ ] 1. 行に付ける指摘が N 件で、付けるコミットが 1 つの cross-review の終わりに、インラインのコメントを作るリクエストが 1 件（レビュー 1 つ）になる。コミットが k 個なら k 件になる（テスト）
- [ ] 2. 今回の実行で直した・見送った指摘に、返信の書き込みが無い。前の実行が作ったスレッドの指摘を今回直したときは、返信が 1 件ある（テスト）
- [ ] 3. 返信と resolve の要求にも間隔が当たる（テスト）
- [ ] 4. 2 つのプロセスが同時に GitHub へ書いても、続く 2 つの書き込みの間がマシン全体の間隔を下回らない（テスト）
- [ ] 5. `retry-after` の無い二次レート制限の待ちが、1 分から指数的に延び、上限の回数で打ち直しをやめて失敗を返す（テスト）
- [ ] 6. 打ち直しても、同じ指摘のスレッド・返信・resolve を二重に書かない（退行しないこと。テスト）
