# #895: 区間の切れ目の再起動と次のコマンドの入力を、前景の中継で自動にする — 要求と受け入れ条件

設計は [issue-895-design.md](issue-895-design.md)、決定の理由は
[issue-895-design-decisions.md](issue-895-design-decisions.md) にある。この文書は「何を満たすか」だけを扱う。

マイルストーンは「17 トークン消費の削減」。版数は配布の工程が決める（`release`）。

## 例: 設計の関門をまたいで実装へ進む

今（マイルストーン 26 の運用）:

1. conductor が設計の関門で `AskUserQuestion` を出し、人が「承認」と答える
2. conductor が設計 Pull Request をマージし、引継ぎ文書（利用者が `issues/` に置く作業用の文書で、追跡しない）の「次に実行するコマンド」を書き換えて応答を終える
3. **人が** `/exit` で Claude Code を終え、起動し直し、引継ぎ文書のコマンドを貼り付ける

変更の後（利用者が最初に 1 度、`relay.py run "<最初のコマンド>"` で Claude Code を起動しておく）:

1. 同じ（人が「承認」と答える）
2. conductor が同じ手順の最後に、次のコマンドを決まった形のコードブロックで出して応答を終える
3. **中継が** その Claude Code へ `/exit` を入力して終え、プラグインを更新し、同じ端末で次のコマンドを入れた Claude Code を起動する。人は同じ端末の TUI を見ているだけでよい

人が行うのは 1 の回答だけになる。**中継を使わずに起動した利用者では、今までどおり 3 を人が行う**（2 のブロックの中身を貼り付ける）。

## 目的

- **切れ目ごとの手作業の転記を無くす。** 今の再起動は人の判断を含まず、終了・起動・貼り付けの 3 つの手作業だけである
- **画面の見え方と関門の答え方を変えない。** 各区間は対話の TUI のまま VS Code の統合ターミナルに見え、関門は `AskUserQuestion` で答える
- **前提を増やさない。** 中継が動けないとき（端末が無い・対応しない環境）は、止まらずに今までどおりの運用へ落ちる
- **#827 と「何が claude を起動し、状態をどこに持つか」の答えをそろえる。** #827 は supervisor の層で同じ問いを扱う

## 対象範囲

含む:

- 次のコマンドを機械が読める形で出す規約（conductor の最後の応答と、引継ぎ文書の「次に実行するコマンド」）
- 区間の終わりに印のファイルを書く Stop hook（Claude Code だけ）
- 端末の前景に常駐し、claude を擬似端末の子として起動し、印を見て終了・更新・次の起動を行う中継スクリプト（`relay.py`）
- 上限（1 日の起動回数・空回り）と止める手段（停止の印）
- 中継が動けないとき・止まったときに、今までどおりの運用へ落ちる形と、その見せ方
- 中継の記録（区間ごとの起動時刻・コマンド・プラグインの版・長さ・終わり方）
- 中継の始め方と止め方を `development-workflow` の参照に書くこと

含まない:

- tmux と VS Code の設定を前提にすること・それらを入れること。中継は端末 1 つで動く（決定 1。tmux の中で使ってもよい）
- 席を外しているときの関門の通知（Slack など）。既存の Stop hook の Slack 通知があり、足すなら別の課題にする
- Codex / Kiro / agy をホストにした中継。これらには Stop hook を置かず、今の手動の運用のまま動く
- supervisor のスクリプト駆動（#827）。この課題は conductor の層だけを扱い、起動と状態の置き場所の答えを #827 と共有する
- 区間の中身（工程の順序・関門の数）の変更。切れ目は `context-window.md` の 4 点と関門の後のまま
- Windows（擬似端末の標準ライブラリが無い）。中継は動けない環境として今までどおりの運用へ落ちる
- 設計の成果物のうち画面・永続データ・API: 画面を持たず、状態は中継の作業ディレクトリのファイルだけで、呼び出される約束はコマンドの引数と印のファイルの形である（入出力の契約の節で扱う）。クラス図は、変える型が無いため対象が無い（新しいスクリプト `relay.py` は関数の集まりで、型を定義しない）

## 受け入れ条件

### 次のコマンドの形

- [ ] AC1: `context-window.md` の「新しい会話で戻す」が、次のコマンドを情報文字列 `ndf-next` の囲みのコードブロック 1 つで出すと定める。複数行を許し、囲みの中身がそのまま次の区間の最初の入力になる。関門の承認より前には出さないことも同じ節に書く
- [ ] AC2: 引継ぎ文書の「次に実行するコマンド」の節が同じ形（`ndf-next` のブロック）で書かれる。形を定めた場所は AC1 の節 1 つである

### 印を書く Stop hook

- [ ] AC3: 中継が起動した claude の最後の応答に `ndf-next` のブロックが 1 つある Stop が起きると、hook が印のファイルを 1 つ書く。印は囲みの中身・作業ディレクトリ・セッションの ID・記録の場所を持つ
- [ ] AC4: 次のどれかに当たるとき、hook は印を書かず、何も出力せず終了コード 0 で終わる: 中継の下で動いていない / 中継がもう動いていない / ブロックが無い / ブロックが 2 つ以上 / 外側の囲みの中に引いたブロックしか無い / hook を呼んだ claude が中継の直接の子でない（conductor が Bash から起こした `claude -p` など）
- [ ] AC4b: 前の Stop が書いた印は、ブロックの無い Stop が後に起きると消える（`/goal` が応答を続けさせた後、最後の Stop の中身だけが印に残る）。中継の直接の子でない claude の Stop は印を消さない
- [ ] AC5: `AskUserQuestion` の応答待ちのあいだは印が書かれない（関門で止まった区間を中継が終わらせない）

### 中継

- [ ] AC6: 印が現れ、会話の記録と利用者の入力が 15 秒動かず、`/goal` の目標がある区間では印の後の目標の判定の記録がそろうと、中継は子の端末へ `/exit` と改行を入力する。子が終わるのを確かめてから、プラグインを更新し、区切りの 1 行を画面に出して、同じ端末で `claude "<囲みの中身>"` を子として起動する
- [ ] AC7: 利用者のキー入力（Ctrl-C を含む）はそのまま子の claude へ届き、端末の大きさの変化も子へ伝わる。中継は区間のあいだも端末を手放さない
- [ ] AC8: 中継の記録（JSON Lines）に、区間の起動ごとに 1 行（起動時刻・区間の番号・コマンド・起動の時点のプラグインの版）、区間の終わりごとに 1 行（長さ・終わり方）が残る。配布の後の区間では、記録の版が配布した版と一致する
- [ ] AC9: 印の作業ディレクトリが消えていたら（設計の作業ツリーが後片付けで消えた切れ目）、主ディレクトリか在る最も近い親で次の区間を起動し、記録に残す

### 上限と止め方

- [ ] AC10: 1 日の起動回数が上限（既定 20）に達すると、次の印を受けても `/exit` を入力せず、今の区間をそのまま続けさせる（AC14 の形で知らせる）
- [ ] AC11: 中継が起動した区間が 3 つ続けて 120 秒未満で印を書いた（空回り）とき、3 つ目の印では `/exit` を入力せず、今の区間をそのまま続けさせる（AC14 の形で知らせる）
- [ ] AC12: 子の claude が印を書かずに終わったとき（人が `/exit` した・Ctrl-C を 2 回押した・落ちた）、中継は次の区間を起動せず、子の終了コードで終わってシェルへ戻る
- [ ] AC13: `relay.py stop`（別の端末から）か停止の印のファイルで、次の印を受けても `/exit` を入力しなくなる。今の区間は人がそのまま続けられる

### 今までどおりの運用へ落ちる

- [ ] AC14: 中継が次の区間を起動しないと決めたとき（上限・空回り・停止の印・更新の失敗・起動の失敗）、`ndf-relay:` で始まる 1 行で理由と「次のコマンドは手で入力する」旨を画面に出し、記録に `stop` の行を残す。conductor の応答のブロックは画面に残っているので、人は今までどおり貼り付けて続けられる
- [ ] AC15: `relay.py run` が中継を始められないとき（標準入力か標準出力が端末でない・擬似端末を作れない・別の中継の子の中で打たれた）、`ndf-relay:` で始まる 1 行で理由を出し、中継を挟まずに `claude "<最初のコマンド>"` をそのまま起動する（今までどおりの起動と同じ）
- [ ] AC16: 中継を使わずに起動した Claude Code、Codex / Kiro / agy では、今の運用が変わらない（hook は AC4 のとおり何もしない。Codex / Kiro / agy の hook の定義に足さない）

### 通しの確かめ

- [ ] AC17: 擬似端末の上で中継を始め、印を 2 回出す区間を続けて動かすと、人が何も入力せずに 3 つ目の区間まで起動する。記録に起動の 3 行と終わりの 2 行が残る。1 つ目の区間で `AskUserQuestion` を出させ、答える前に印が無いことも見る
- [ ] AC18: 全体テストが通る

## 前提

- 前提 1: Claude Code は位置引数の最初の入力を渡した状態で対話の TUI を開く。擬似端末の中でも同じである（設計の「確かめたこと」）
- 前提 2: Stop hook は応答が終わるたびに発火し、`AskUserQuestion` の応答待ちと claude の終了では発火しない。サブエージェントの終わりは `SubagentStop` で、Stop ではない。`/goal` の判定は Stop hook と並んで発火し、目標が未達なら応答が続く（そのとき Stop hook は次の終わりにもう一度発火し、`stop_hook_active` が真になる）
- 前提 3: Stop hook の子のプロセスは claude の環境を継ぐ。conductor が Bash から起こす `claude -p` も同じ環境を継ぐ
- 前提 4: 区間をまたいで持ち越す状態は、会話の外（課題の本文・盤面・通過工程の控え・Pull Request・引継ぎ文書）にある（`context-window.md` の「新しい会話で戻す」）。会話を捨てても次の区間が戻せる
- 前提 5: 同時に動かす claude の上限（メモリの制約で 3 本）は、conductor 1 本と配下のサブエージェント・外部 CLI の合計に掛かる。中継が足すのは区間の claude 1 本だけで、前の区間の claude が終わってから起動する

## 非機能の条件

| 項目 | 条件 |
| --- | --- |
| 可用性 | 中継が動けないとき・止まると決めたときは、今までどおりの運用へ落ちる（AC14・AC15）。中継の中の例外で子の claude を巻き込んで終わらせない |
| 費用 | 中継の待ちは LLM を使わない（スクリプトの中の待ち）。hook は 1 回の Stop で 1 秒以内に終わる |
| 運用・保守性 | 止まった理由と区間ごとの版が記録に残る。記録の置き場所は 1 つである |
| セキュリティ | 印のファイルは利用者だけが読み書きできる場所に置く（権限 `0700` のディレクトリ）。中継は印の中身をシェルに解釈させずに claude の引数として渡す |
| システム環境 | Linux / macOS の端末・Python 3（標準ライブラリだけ）・Claude Code 2.1.280 以降。tmux も VS Code の設定も要らない |

## 影響

| 対象 | 変わること |
| --- | --- |
| 中継で起動した利用者 | 切れ目で自動に次の区間が始まる。関門の答えだけを入力する |
| 中継を使わない利用者 | 変わらない。conductor の最後の応答のコマンドの囲みが `text` から `ndf-next` に変わるだけで、貼り付けて使える |
| conductor | 次のコマンドを `ndf-next` のブロックで出す。関門の承認より前には出さない |
| 引継ぎ文書 | 「次に実行するコマンド」の囲みが `ndf-next` になる |

| 条件 | 手段 |

| AC3・AC4・AC4b | hook の単体テスト（標準入力の JSON を与え、印の有無と中身・出力・終了コードを見る。プロセスの親子の読み取りは差し替える） |

## 境界

```text
常に行う      … 擬似端末の上で試す（利用者の端末を乱さない）、既存テストの実行
確認してから行う … 利用者の端末で中継を始めること（利用者が自分で始める）
行わない      … 区間の中の工程の変更、Codex / Kiro / agy の hook の追加、#827 の実装の先取り、利用者の設定ファイルの書き換え
```

## 依頼（原文）

> **`/goal /ndf:development-workflow` の区間の切れ目で人が行っている「再起動と次のコマンドの入力」を、tmux の上の中継スクリプトで自動にする。** 画面の見え方（VS Code の統合ターミナルで動きが見える）と関門の承認のしかた（`AskUserQuestion`）は変えない。

利用者の差し戻し（2026-09-23、設計 Pull Request #908 の関門）:

> tmux が無ければ止まらずに中継を飛ばし、これまでどおりの挙動にする（次の /goal のコマンドを示す）。または、常駐プロセスと fg（前景の子プロセス）で、tmux 無しでも似たようにできないか。

## 用語

| 用語 | 意味 |
| --- | --- |
| 区間 | 1 つの Claude Code のプロセス（conductor の会話）が受け持つ範囲。切れ目から次の切れ目まで |
| 切れ目 | `context-window.md` の切ってよい 4 点と、関門の承認と取り込みの後 |
| 中継 | 端末の前景に常駐し、claude を擬似端末の子として起動して、印を見て区間を切り替えるスクリプト |
| 印 | Stop hook が中継へ次の区間の開始を知らせるファイル |
| 停止の印 | 利用者が中継に次の区間を起動させないために置くファイル |
| 空回り | 印を書いて終わった区間が短い時間で続くこと。同じコマンドを繰り返すなど、進まずに起動だけが重なる状態 |
| 落ちる | 中継が区間を切り替えず、人が次のコマンドを入力する今までどおりの運用に戻ること |
