# #895: 区間の切れ目の再起動と次のコマンドの入力を、tmux の上の中継で自動にする — 要求と受け入れ条件

設計は [issue-895-design.md](issue-895-design.md)、決定の理由は
[issue-895-design-decisions.md](issue-895-design-decisions.md) にある。この文書は「何を満たすか」だけを扱う。

マイルストーンは「17 トークン消費の削減」。版数は配布の工程が決める（`release`）。

## 例: 設計の関門をまたいで実装へ進む

今（マイルストーン 26 の運用）:

1. conductor が設計の関門で `AskUserQuestion` を出し、人が「承認」と答える
2. conductor が設計 Pull Request をマージし、引継ぎ文書（利用者が `issues/` に置く作業用の文書で、追跡しない）の「次に実行するコマンド」を書き換えて応答を終える
3. **人が** `/exit` で Claude Code を終え、起動し直し、引継ぎ文書のコマンドを貼り付ける

変更の後:

1. 同じ（人が「承認」と答える）
2. conductor が同じ手順の最後に、次のコマンドを決まった形のコードブロックで出して応答を終える
3. **中継が** その区間の Claude Code を `/exit` で終え、プラグインを更新し、同じ tmux の新しいウィンドウで次のコマンドを入れた Claude Code を起動する。人は新しいウィンドウの TUI を見ているだけでよい

人が行うのは 1 の回答だけになる。

## 目的

- **切れ目ごとの手作業の転記を無くす。** 今の再起動は人の判断を含まず、終了・起動・貼り付けの 3 つの手作業だけである
- **画面の見え方と関門の答え方を変えない。** 各区間は対話の TUI のまま VS Code の統合ターミナルに見え、関門は `AskUserQuestion` で答える
- **#827 と「何が claude を起動し、状態をどこに持つか」の答えをそろえる。** #827 は supervisor の層で同じ問いを扱う

## 対象範囲

含む:

- 次のコマンドを機械が読める形で出す規約（conductor の最後の応答と、引継ぎ文書の「次に実行するコマンド」）
- 区間の終わりに印のファイルを書く Stop hook（Claude Code だけ）
- 印を待ち、終了・更新・起動を行う中継スクリプト（tmux の上で常駐）
- 上限（1 日の起動回数・同時に動く区間の数・空回り）と止める手段（`Ctrl-C`・停止の印）
- 中継の記録（区間ごとの起動時刻・ウィンドウ・コマンド・プラグインの版・終わり方）
- 中継の始め方と止め方を `development-workflow` の参照に書くこと
- 中継の前提（tmux・今のペインが tmux の中・VS Code の統合ターミナルが tmux を開く設定）を確かめ、無い設定を入れ、入れた内容を示すスクリプト（`relay.py setup`。`run` も始める前に通る）

含まない:

- tmux そのものを入れること（パッケージの入れ方と権限が環境ごとに違う。無ければ案内して止まる）、手元の VS Code のユーザー設定とワークスペースの設定を書き換えること
- 席を外しているときの関門の通知（Slack など）。既存の Stop hook の Slack 通知があり、足すなら別の課題にする
- Codex / Kiro / agy をホストにした中継。これらには Stop hook を置かず、今の手動の運用のまま動く
- supervisor のスクリプト駆動（#827）。この課題は conductor の層だけを扱い、起動と状態の置き場所の答えを #827 と共有する
- 区間の中身（工程の順序・関門の数）の変更。切れ目は `context-window.md` の 4 点と関門の後のまま
- 設計の成果物のうち画面・永続データ・API: 画面を持たず、状態は中継の作業ディレクトリのファイルだけで、呼び出される約束はコマンドの引数と印のファイルの形である（入出力の契約の節で扱う）。クラス図は、変える型が無いため対象が無い（新しいスクリプト `relay.py` は関数の集まりで、型を定義しない）

## 受け入れ条件

### 次のコマンドの形

- [ ] AC1: `context-window.md` の「新しい会話で戻す」が、次のコマンドを情報文字列 `ndf-next` の囲みのコードブロック 1 つで出すと定める。複数行を許し、囲みの中身がそのまま次の区間の最初の入力になる。関門の承認より前には出さないことも同じ節に書く
- [ ] AC2: 引継ぎ文書の「次に実行するコマンド」の節が同じ形（`ndf-next` のブロック）で書かれる。形を定めた場所は AC1 の節 1 つである

### 印を書く Stop hook

- [ ] AC3: 中継が動いている tmux のセッションの中で、最後の応答に `ndf-next` のブロックが 1 つある Stop が起きると、hook が印のファイルを 1 つ書く。印は囲みの中身・ペインの ID・作業ディレクトリ・セッションの ID を持つ
- [ ] AC4: 次のどれかに当たるとき、hook は印を書かず、何も出力せず終了コード 0 で終わる: tmux の外 / 中継が動いていない / ブロックが無い / ブロックが 2 つ以上 / hook を呼んだ claude がペインの前面の claude でない（conductor が起こした `claude -p` など）
- [ ] AC4b: 同じペインの前の Stop が書いた印は、ブロックの無い Stop が後に起きると消える（`/goal` が応答を続けさせた後、最後の Stop の中身だけが印に残る）
- [ ] AC5: `AskUserQuestion` の応答待ちのあいだは印が書かれない（関門で止まった区間を中継が終わらせない）

### 中継

- [ ] AC6: 印が現れ、その会話の記録が 15 秒動かず（応答が止まっている）、`/goal` の目標がある区間では印の後の目標の判定の記録がそろうと、中継は印のペインへ `/exit` を送る。そのペインの claude が終わるのを確かめてから、プラグインを更新する。続けて同じ tmux のセッションに新しいウィンドウを開き、`claude "<囲みの中身>"` を印の作業ディレクトリで起動する。新しいウィンドウが前面になる
- [ ] AC7: 終わった区間のウィンドウは、利用者が開いた最初の区間を含めて残り、`Ctrl-b p` で前の区間の画面を遡れる。残す数の上限（既定 10）を超えたら、中継が開いた古いものから閉じる
- [ ] AC8: 中継の記録（JSON Lines）に、区間の起動ごとに 1 行（起動時刻・ウィンドウ・コマンド・起動の時点のプラグインの版）、区間の終わりごとに 1 行（長さ・終わり方）が残る。配布の後の区間では、記録の版が配布した版と一致する

### 上限と止め方

- [ ] AC9: 1 日の起動回数が上限（既定 20）に達すると、次の印を受けても新しい区間を起動せず、理由を出して中継が終わる
- [ ] AC10: 同じ tmux のセッションで中継は 1 つしか動かない（2 つ目は理由を出して終了コード 1 で終わる）。中継が追う区間の列は 1 本で、最初に受けた印のペインと、中継が開いたペインの印だけを受ける。中継は前の区間の claude が終わる前に次の区間を起動しない
- [ ] AC11: 中継が起動した区間が 3 つ続けて 120 秒未満で印を書いた（空回り）とき、3 つ目の印を受けたところで次の区間を起動せずに中継が終わる。利用者が開いた最初の区間は数えない（中継が起こした起動の繰り返しを止めるためである）
- [ ] AC12: 中継が起動した区間の claude が印を書かずに終わったとき（人が `/exit` した・落ちた）、中継は次の区間を起動せずに終わる
- [ ] AC13: 中継のウィンドウで `Ctrl-C` を押すと中継だけが終わり、区間の claude は動き続ける。停止の印のファイルを置くと、次の印を受けても `/exit` を送らず新しい区間を起動しない（今の区間は人がそのまま続けられる）

### tmux が無い環境

- [ ] AC14: tmux の外で動く Claude Code、中継を始めていない tmux の中の Claude Code、Codex / Kiro / agy では、今の運用が変わらない（hook は AC4 のとおり何もしない。Codex / Kiro / agy の hook の定義に足さない）

### 前提の確かめと導入（`relay.py setup`、2026-09-23 利用者の要求で追加）

- [ ] AC17: `setup` は VS Code のリモートの Machine 設定に、統合ターミナルが tmux を開く設定が無ければ足し、足したキー・バックアップのパス・戻し方の 1 行を示す。既にあれば何も書かない（2 回目は `ok` で、ファイルが変わらない）。既定のプロファイルが tmux でない別の値なら書き換えずに示す。注釈を含み書き戻すと失われるファイルは書かない。戻し方は、既にあったファイルならバックアップからの写し戻し、新しく作ったファイルなら削除である`--check` は書かずに、足りない設定があれば終了コード 3 で終わる
- [ ] AC18: tmux が無ければ `setup` は案内を出して終了コード 1 で終わる。`run` は始める前に `setup` と同じ確認と導入を通り、tmux の外で打たれたら中継を始めずに終了コード 1 で終わる。ワークスペースの設定が既定のプロファイルを上書きしていれば、その場所を示し書き換えない

### 次の区間の起動先

- [ ] AC19: 印の作業ディレクトリが消えていたら（設計の作業ツリーが後片付けで消えた切れ目）、主ディレクトリか在る最も近い親で次の区間を起動し、記録に残す。起動してすぐ終わった区間のウィンドウも残る

- [ ] AC20: 次の区間の起動（`new-window`）が失敗したら、中継は理由（`start-failed`）と tmux の出力を記録と標準エラーに残して終わる

### 通しの確かめ

- [ ] AC15: 別のソケットの tmux の中で中継を始め、印を 2 回出す区間を続けて動かすと、人が何も入力せずに 3 つ目の区間まで起動する。各区間のウィンドウが残り、記録に起動の 2 行（中継が起動した 2 つ目と 3 つ目の区間）と終わりの 2 行（1 つ目と 2 つ目の区間）が残る
- [ ] AC16: 全体テストが通る

## 前提

- 前提 1: Claude Code は位置引数の最初の入力を渡した状態で対話の TUI を開く（`claude --help` の `Usage: claude [options] [command] [prompt]`。#895 の「確かめたこと」）
- 前提 2: Stop hook は応答が終わるたびに発火し、`AskUserQuestion` の応答待ちでは発火しない。サブエージェントの終わりは `SubagentStop` で、Stop ではない。`/goal` の判定は Stop hook と並んで発火し、目標が未達なら応答が続く（そのとき Stop hook は次の終わりにもう一度発火し、`stop_hook_active` が真になる）
- 前提 3: Stop hook の子のプロセスは claude の環境を継ぐ。tmux の中なら `TMUX` と `TMUX_PANE` を持つ
- 前提 4: 区間をまたいで持ち越す状態は、会話の外（課題の本文・盤面・通過工程の控え・Pull Request・引継ぎ文書）にある（`context-window.md` の「新しい会話で戻す」）。会話を捨てても次の区間が戻せる
- 前提 5: 同時に動かす claude の上限（メモリの制約で 3 本）は、conductor 1 本と配下のサブエージェント・外部 CLI の合計に掛かる。中継が足すのは区間の claude 1 本だけで、前の区間の claude が終わってから起動する

前提 1〜3 は設計の時点で実測した（設計文書の「確かめたこと」）。

## 非機能の条件

| 項目 | 条件 |
| --- | --- |
| 可用性 | 中継が落ちても区間の claude は動き続ける。人は今の手動の運用へそのまま戻れる |
| 費用 | 中継の待ちは LLM を使わない（スクリプトの中の待ち）。hook は 1 回の Stop で 1 秒以内に終わる |
| 運用・保守性 | 止まった理由と区間ごとの版が記録に残る。記録の置き場所は 1 つである |
| セキュリティ | 印のファイルは利用者だけが読み書きできる場所に置く（権限 `0700` のディレクトリ）。中継は印の中身をシェルに解釈させずに claude の引数として渡す |
| システム環境 | tmux 3.x・Python 3（標準ライブラリだけ）・Claude Code 2.1.280 以降 |

## 影響

| 対象 | 変わること |
| --- | --- |
| 中継を始めた利用者 | 切れ目で自動に次の区間が始まる。関門の答えだけを入力する |
| 中継を始めていない利用者 | 変わらない。conductor の最後の応答のコマンドの囲みが `text` から `ndf-next` に変わるだけで、貼り付けて使える |
| conductor | 次のコマンドを `ndf-next` のブロックで出す。関門の承認より前には出さない |
| 引継ぎ文書 | 「次に実行するコマンド」の囲みが `ndf-next` になる |

## 境界

```text
常に行う      … 別のソケットの tmux で試す（利用者の tmux を乱さない）、既存テストの実行
確認してから行う … 利用者の tmux のセッションで中継を始めること（利用者が自分で始める）
行わない      … 区間の中の工程の変更、Codex / Kiro / agy の hook の追加、#827 の実装の先取り
```

## 依頼（原文）

> **`/goal /ndf:development-workflow` の区間の切れ目で人が行っている「再起動と次のコマンドの入力」を、tmux の上の中継スクリプトで自動にする。** 画面の見え方（VS Code の統合ターミナルで動きが見える）と関門の承認のしかた（`AskUserQuestion`）は変えない。

## 用語

| 用語 | 意味 |
| --- | --- |
| 区間 | 1 つの Claude Code のプロセス（conductor の会話）が受け持つ範囲。切れ目から次の切れ目まで |
| 切れ目 | `context-window.md` の切ってよい 4 点と、関門の承認と取り込みの後 |
| 中継 | tmux のウィンドウの 1 つで常駐し、印を見て区間を切り替えるスクリプト |
| 印 | Stop hook が中継へ次の区間の開始を知らせるファイル |
| 停止の印 | 利用者が中継に次の区間を起動させないために置くファイル |
| 空回り | 印を書いて終わった区間が短い時間で続くこと。同じコマンドを繰り返すなど、進まずに起動だけが重なる状態 |
