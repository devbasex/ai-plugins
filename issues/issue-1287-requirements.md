## 目的

- **cross-review の役割を「利用者が困る不具合と、処理を悪くする変更を、マージの前に止める」に定め直す。** 仕上げの磨き込み（minor・nit の修正）に修正の回・push・CI を使わない（MVV の Value 7「まず届ける」。2026-09-26 に利用者が改訂した `issues/mvv-milestone26.md`。メインディレクトリにあり、まだコミットされていない）
- **指摘の基準を 1 か所の定めに揃える。** レビュー担当への指示・設計原則・`/ndf:fix` の判断表・最終スイープ・`/ndf:pr-review` の重要度の表が、同じ基準から同じ扱いを導く状態にする
- **汎用を保つ。** 既定の基準は「利用者が使って困るか」だけにし、プロジェクトごとの重点は `.ndf/` の宣言から受ける（MVV の Value 6）

## 前提

- 前提 1: 重要度の語（`critical` / `major` / `minor` / `nit`）はそのまま残す。基準 1〜4 に当たるものを `major` 以上とし、`critical` と `major` の分け方は今の定め（`/ndf:pr-review` の重要度の表）を変えない
- 前提 2: `nit` は `minor` と同じ扱いにする。レビュー担当は書かず、届いたら修正担当は直さずに見送りの返信で閉じる。今の `--defer-nit` と「最後に 1 回ユーザへ問い合わせる」は、`nit` については使わなくなる
- 前提 3: 修正担当は届いた重要度ラベルを鵜呑みにしない今の定めを残す。`minor` のラベルで届いても、中身が基準 1〜4 に当たれば `major` 以上として直す。逆に `major` のラベルでも基準に当たらなければ見送る
- 前提 4: 見送りの返信を書いたスレッドは閉じる（resolve する）。今の `rejected`（誤読の指摘。閉じない）とは分ける。閉じないと最終スイープの open thread 0 の検証が通らない
- 前提 5: 基準の変更は `/ndf:fix` が単独で呼ばれたとき（bot のレビューへの対応）にも同じく働く。cross-review の中だけに限らない
- 前提 6: 重点の宣言が読めない（壊れている）ときは、基準 1・2・4 だけで続け、読めなかったことを結果に出す。レビューを止めない
- 前提 7: このリポジトリ（ai-plugins）は重点の宣言として「トークン・所要時間・処理の回数を増やす変更」を置く。宣言そのものは NDF の既定に含めない
- 前提 8: 効果の集計は、変更が開発版（`develop`）に載った日から 14 日、または `/ndf:fix` のまとめのコメントが 30 件たまった時点の早い方で行う。比べる基準は起票時の実測（2026-05-20〜09-26、PR 136 本、まとめのコメント 383 件）である
- 前提 9: 「減った」の判定は、minor の修正の割合が 10% 以下、かつ minor だけの修正の回が集計した PR の本数の 5% 以下とする（今は 40% と 35 回 / 136 本 ≒ 26%）。重要度を判定し直して `major` へ上げたものは minor に数えない

| 既存の振る舞い | cross-review のレビュー担当が minor を書かなくなる。`/ndf:fix` と最終スイープが minor・nit を直さなくなる |

## 検証手段

| 項目 | 手段 |
| --- | --- |
| テスト | `uv run --frozen --project . --all-extras pytest . -q -n 4` |
| 静的解析 | `python3 scripts/check-skill-frontmatter.py`、`claude plugin validate .` |
| 効果の集計 | 修正のまとめの集計スクリプト（置き場所は設計が決める）を前提 8 の時点で実行する |
| 手動確認 | 変更の後の最初の cross-review で、投稿された指摘に基準外のものが無く、minor のスレッドに見送りの返信が付いて閉じていることを PR の上で見る |

## 前提とする取り決め

| 項目 | 参照先 / 決めたこと |
| --- | --- |
| プロジェクト構造 | `AGENTS.md`。Skill の実体は `plugins/ndf/skills/`。既定で動くものから実験版（`plugins/ndf/scripts/experimental/`）を参照しない |
| コーディング規約 | `AGENTS.md` と `plugins/ndf/skills/AUTHORING.md`。`.md` の文言を照合するテストは書かない |
| テスト戦略 | 振る舞い（指示の組み立て・修正の結果の区分・スイープの閉じ方）をスクリプトの単体テストで固定する。文書の食い違いはテストでなくレビューで見る |

## 境界

| 区分 | 内容 |
| --- | --- |
| 常に行う | 既存テストの実行、`check-skill-frontmatter.py` と `claude plugin validate .` |
| 確認してから行う | 重要度の語の変更、収束の判定の変更、`/ndf:fix` の結果 JSON の既存の値の改名 |
| 行わない | cross-review 以外のレビュー工程の基準の変更、過去の PR のスレッドの掃除 |
