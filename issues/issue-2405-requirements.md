## 目的

- Factory の利用者が、承認待ちや利用上限待ちで止まっている開発ループの予算を画面で変えたとき、ループが再開した後に NDF がその予算で止まるかを判定する状態にする
- 画面に出る「予算の残り」と、NDF が止まる判定に使う予算を食い違わせない

## 前提

- 前提 1: 周回の間（`between_laps`）に変えた予算は、次の周回のジョブ（`START=loop`）の指示の `LOOP_BUDGET` から `--budget-*` として NDF へ渡っており、この課題では変えない。根拠: `factory/runner/src/runtime.ts` の `loopPrompt` が `LOOP_BUDGET` を `--budget-<単位> <値>` へ並べ、`factory/runner/src/loop.test.ts` の「`--budget-laps 3 --budget-usd 60`」の例がそれを確かめている
- 前提 2: NDF のループの記録（`.ndf/loop/<名>/loop.json`）は既にあるループにも `loop start <名> --budget-*` で予算を上書きでき、変わったときだけ予算の履歴（`budget_history`）に 1 行足す（`plugins/ndf/scripts/lib/sprint_loop.py` の `apply_budget`）。ただし既にあるループへの `loop start` は、止まった記録を解く手続き（承認ゲート 2 の答えの処理・周回の締め・予算超過の判定し直し）も同時に行う（同じファイルの `cmd_start`・`resume_stopped`）
- 前提 3: NDF の止まる条件の判定は、周回を締めるときにループの記録の予算と締めた周回の消費の和を比べる（`plugins/ndf/scripts/lib/sprint_loop_record.py` の予算の判定）。したがって conductor を起こす前にループの記録の予算が新しい値になっていれば、その後の判定は新しい予算で行われる
- 前提 4: 実行ジョブの指示の契約（`factory/contracts/schemas/run-job-instruction.schema.json`）は、ループの実行の `resume` に `LOOP_BUDGET` を載せることを既に許している。契約の形は変えない
- 前提 5: 予算をループの記録へ反映できなかったときは、conductor を起こさずにジョブを失敗で終える。古い予算のまま進めると、この課題が直す食い違いをそのまま残すためである。人の判断待ちへの答えを書けなかったとき（`factory/runner/src/runtime.ts` の `answerLoop`）と同じ扱いにする

## 対象範囲

含む:
- 承認の答えによる再開（`APPROVAL_REQUEST_ID` のある `START=resume`）で、Factory のループの今の予算を NDF のループの記録へ反映すること
- 利用上限の後の再開（`APPROVAL_REQUEST_ID` の無い `START=resume`）で、同じく反映すること
- 反映を確かめる自動テスト（Factory のサービスとランナー、必要なら NDF のスクリプト）
- 確定仕様（`docs/specifications/ndf-factory-dev-loops.md` ほか）の予算の変更の記述を、再開のジョブにも届くことに合わせる

含まない:
- 動いているジョブ（`running`）の途中で予算を届けること。変えた予算は次に作るジョブ（再開か次の周回）で届く
- 画面で予算の単位を空にした（制限を外した）ときに、NDF の予算を既定へ戻すこと。今の NDF の `--budget-*` は値の上書きだけを持ち、外す口が無い。周回のジョブでも同じ制約があり、別の課題で扱う
- 止まった（`stopped`）・取り消した（`cancelled`）ループの再開。決定 14 のとおり終わりの状態であり、続きは新しいループで始める
- 予算の変更の画面と API（`updateBudget`）の形の変更

## ドメインイベント

| # | イベント | 引き金 | 失敗したとき | 順序の前提 |
| --- | --- | --- | --- | --- |
| E1 | 利用者がループの予算を変えた | 画面か API の予算の変更（`updateBudget`） | 終わりの状態のループは `already_finished` で断る（既存） | ループが `running`・`between_laps`・`awaiting_approval` のいずれか |
| E2 | サービスが再開のジョブを作った | 承認の答え（`requestResume`）か、リセット時刻の経過（`resumeAfterReset`） | 既存の断りの理由（`sprint_run_busy` など）で作らない | E1 の後に作られたジョブに、E1 の予算が載る |
| E3 | ランナーが保存した状態を復元した | 再開のジョブの起動 | 既存のとおりジョブを失敗にする | E2 |
| E4 | ランナーがループの記録の予算を新しい値にした | E3 の完了 | conductor を起こさずジョブを失敗で終える（前提 5） | E3 の後、conductor の起動の前 |
| E5 | conductor が前回の続きから進めた | E4 の完了（予算を宣言していないループでは E3 の完了） | 既存のとおり | E4 |
| E6 | NDF が周回を締め、止まる条件を新しい予算で判定した | conductor が周回を締めるコマンドを打つ | 既存のとおり | E4 |

E4 と人の判断待ちへの答えの書き込み（既存）の順序は、どちらが先でも結果が同じになることを設計で確かめる（未決 2）。

## 用語

| 用語 | 意味 |
| --- | --- |
| ループの予算 | 開発ループが使ってよい周回の数・費用（USD）・時間の上限。Factory のループの行と NDF のループの記録の両方が持つ |
| 再開のジョブ | `START=resume` の実行ジョブ。承認の答えによるものと、利用上限の後のものがある |
| ループの記録 | NDF が開発ループごとに持つ `.ndf/loop/<名>/loop.json`。予算・予算の履歴・周回・止まった理由を持つ |

## 受け入れ条件

- [ ] 1. 承認待ち（`awaiting_approval`）のループの予算を変えた後に、承認の答えで作られた再開のジョブでは、conductor を起こす前に NDF のループの記録の予算が変えた値になっている（ランナーのテストで、記録の予算を読んで確かめる）
- [ ] 2. 利用上限待ち（`awaiting_reset`）の実行のループの予算を変えた後に、リセット時刻の後に作られた再開のジョブでも、受け入れ条件 1 と同じになる
- [ ] 3. 予算を下げて再開した場合、締めた周回の消費の和が新しい予算以上になった周回の締めで、NDF が `budget_<単位>` の止まる条件を記録する（例: 費用の予算を 60 から 40 へ下げ、消費の和 50 で締めると `budget_usd` で止まる）
- [ ] 4. 予算を上げて再開した場合、古い予算なら止まっていた消費の和でも NDF は止まる条件を記録しない（例: 費用の予算を 40 から 100 へ上げ、消費の和 50 で締めると止まらない）
- [ ] 5. 再開のジョブの指示に載る予算は、そのジョブを作った時点の Factory のループの予算である（サービスのテストで、`requestResume` と `resumeAfterReset` の両方の指示に `LOOP_BUDGET` が載ることを確かめる）
- [ ] 6. 予算が変わっていないときは、予算の履歴に行を足さない。変わったときは 1 行だけ足す
- [ ] 7. 予算を反映する操作は、ループの記録の予算と予算の履歴のほかを変えない。止まった記録の解除・周回の締め・承認ゲート 2 の答えの処理は、conductor が前回の続きから進めるときに既存のとおり 1 回だけ起きる
- [ ] 8. 予算をどの単位も宣言していないループの再開では、ループの記録の予算を変えない
- [ ] 9. ループに属さない実行の再開のジョブは、指示も振る舞いも変わらない（`LOOP_BUDGET` を載せない）
- [ ] 10. ループの記録へ予算を反映できなかったとき、ランナーは conductor を起こさずにジョブを失敗で終え、理由をジョブの出力に残す

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 運用・保守性 | 予算の上書きの規則（単位ごとの上書きと予算の履歴）は NDF の 1 か所に置き、ランナーとサービスに同じ規則を写さない |
| 移行性 | 既に動いているループと保存済みの状態は、そのまま次の再開のジョブで新しい規則に乗る。データの移行は要らない |

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わらない。実行ジョブの指示の契約は再開のジョブの `LOOP_BUDGET` を既に許している（前提 4）。NDF に予算だけを反映するコマンドを足すかは未決 1 |
| データ | スキーマの変更は無い。NDF のループの記録の予算の履歴に、再開のときの変更が 1 行ずつ足される |
| 既存の振る舞い | 再開のジョブで、conductor の起動の前に予算の反映が入る。周回のジョブとループに属さない実行は変わらない |
