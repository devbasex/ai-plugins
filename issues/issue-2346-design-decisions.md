# #2346 の設計: 決定の記録

設計文書の本体は `issues/issue-2346-design.md` にある。ここには決定だけを置く。

## 決定の記録

### 決定 1: 統括役を高々 1 つにするため、`hub.lock` のファイルロックを持つ前景のラッパーを統括役にする

`run` はパススルーの判定の後で `hub.lock` を待たずに取り、取れたら統括役を兼ねて今の前景の起動を続ける。ロックは OS がプロセスの終了で放すため、統括役が kill されても次に打った `claude` が取れる（AC21）。同時に 2 つの `run` が始まっても、取れるのは 1 つだけである（AC22）。名前つきのラッパー（tmux の中で起動された印 `NDF_RELAY_SPAWNED` を持つもの）は `hub.lock` を取りに行かない。取りに行くと、統括役が落ちた後に tmux の中のラッパーが統括役になり、AC21 の「次に打った `claude` が統括役になる」と食い違う。

`hub.json` の pid の生死で統括役を判定する形は採らない。pid の再利用で死んだ統括役を生きていると読み、書き換えの競合を別に守る必要がある（今の `relay_running` もロックで判定している）。

根拠: Value 6（MVV 版 4）

### 決定 2: 2 本目の環境を利用者の環境と同じにしつつ秘密をディスクに置かないため、tmux のセッションは統括役が作り、依頼には名前・作業ディレクトリ・引数だけを載せる

tmux の window の中の環境は、サーバの環境とセッションを作ったクライアントの環境から決まる。統括役が `new-session` を呼べば、統括役（利用者が打った 1 本目の `claude`）の環境がそのまま継がれ、依頼に環境変数を載せずに済む。名前と印だけを `-e` で渡す（`-e` が window へ届くことは 2026-11-02 に tmux 3.6 で確かめた）。利用者の依頼の原文「1本目のrelay.pyが2本目のclaudeを立ち上げ」とも合う。

頼む側が自分の環境を依頼のファイルに書いて渡す形は採らない。環境変数に入った token がディスクへ残る（共通原則 C1）。頼む側が自分で `tmux new-session` を呼ぶ形も採らない。登録簿の書き手が 2 つになり（I4）、サーバが既に在ると頼む側の環境が継がれない点は同じである。

根拠: C1 / Value 6（MVV 版 4）

### 決定 3: 端末ごとに別のラッパーを見られ、利用者の tmux に触れないため、名前つきのラッパー 1 本に tmux のセッション 1 つを割り当て、専用のソケット `-L ndf-relay` に置く

1 つのセッションに window を並べると、ある端末で attach して window を選ぶと、同じセッションへ結び付いたほかの端末の表示も切り替わる。セッションを名前ごとに分ければ、`attach-session -t =<名前>` で端末ごとに独立して結び付けられる。各セッションは window を 1 つだけ持つため、用語集の「tmux の 1 つの window で動く」はそのまま成り立つ。専用のソケットにすれば、利用者が自分で使う tmux のサーバ（既定のソケット）の一覧と操作に混ざらない。

根拠: Value 2 / 境界の「利用者の tmux サーバに触れない」（MVV 版 4）

### 決定 4: 登録簿の書き手を統括役 1 つにするため、依頼はファイルの受付箱で渡す

頼む側（端末の `run`・`spawn`・Stop hook・`restart`）は `hub/requests/<id>.json` を置き、統括役が 0.5 秒ごとに読んで処理し、`hub/results/<id>.json` を書く。受付箱のディレクトリは 0700・ファイルは 0600 で、同じ OS の利用者だけが送れる（非機能のセキュリティ）。統括役が居ない間に置かれた依頼は残り、次の統括役が起動の直後に処理する。

Unix ドメインソケットは採らない。統括役に受け付けの thread と接続の扱いが要り、統括役が居ない間の依頼を残せない。頼む側が登録簿のロックを取って自分で書く形も採らない。書き手が複数になり、上限と重複の判定（I2・I3）が入口ごとに分かれる。

根拠: Value 6（MVV 版 4）

### 決定 5: 上限をコンテナごとの値にするため、同時に動かす数の上限は環境変数 `NDF_RELAY_MAX_NAMED`（既定 3）で受ける

上限が守るのは同じコンテナ・同じアカウントの資源で、リポジトリごとの値ではない。`.ndf/` はリポジトリごとの設定のため、別のリポジトリから打った `claude` で値が変わる。今のラッパーの上限（`NDF_RELAY_MAX_STARTS`）と同じく環境変数で持てば、統括役の環境から 1 つに決まる。数えるのは動いているラッパーすべて（統括役のラッパーと、名前の無い今のラッパーを含む）である。要求の未決 2 への答えである。

根拠: Value 5（MVV 版 4）

### 決定 6: 起動のブロックを `ndf-next` と同じ経路で拾うため、情報文字列 `ndf-spawn <名前>` の囲みにする

Stop hook の `mark` は既に `lib/md.py` で `ndf-next` の囲みを拾っている。同じ読み方で情報文字列だけを変えれば、拾う規則が 1 つに残る。中身は最初の入力で、1 つの応答に複数置ける（3 本のループを 1 度に始める）。`ndf-spawn` は区間を終えないため、`next.json` を書かず、置いた区間は止まらない（AC5）。hook は依頼を置くだけで待たない（Stop hook の時間の上限は 5 秒）。要求の未決 3 への答えである。

JSON の囲みは採らない。conductor が手で書く形が増え、`ndf-next` と書き方が分かれる。

根拠: Value 4 / Value 6（MVV 版 4）

### 決定 7: 統括役の居ない間も承認待ちを取りこぼさないため、承認待ち通知は各ラッパーの待ち通知が名前を付けて出す

今の待ち通知（`wait-notify.py`）は各ラッパーの claude の hook として動く。`lib/wait_notice.py` の `build_locator` が `NDF_RELAY_NAME` を読み、`ラッパー: <名前>（relay.py attach <名前>）` の 1 行を足す。統括役を経由しないため、統括役が落ちて次の `claude` が来るまでの間も通知は出る。要求の未決 4 への答えである。端末が結び付いているかは見ずに常に足す。hook の中で tmux を呼ばずに済み、結び付いた利用者にも害が無い。

統括役が `ls` と同じ判定で承認待ちを見回して通知する形は採らない。統括役の居ない間に出ず、今の通知と 2 重になる。

根拠: Value 2 / Value 6（MVV 版 4）

### 決定 8: 一覧の状態を新しく書かずに導くため、状態は作業ディレクトリの今のファイルから決め、語は Factory の `awaiting_approval` に揃える

`relay.lock` が持たれていれば動いている、`question`（`AskUserQuestion` の表示中に在る質問シグナルファイル）も在れば承認待ち、どちらでもなければ止まった、と読む。ラッパーの状態機械に書き込みを足さないため、I5 を守れ、ラッパーが kill された後も正しく止まったと出る（AC20）。

状態の語は Factory のスプリントの実行の状態 `awaiting_approval` に揃える（AC26 の「対応する項目は同じ名前」）。要求の AC9 は `waiting_approval` と書いており、AC26 と食い違う。どちらに揃えるかは承認ゲート 1 で利用者が決める（本体の未確認 1）。

根拠: Value 6 / Value 8（MVV 版 4）

### 決定 9: 名前つきの `stop` で 1 本が確かに止まるよう、停止シグナルファイルを置いた上で tmux のセッションを終える

今の `stop` のシグナルファイルは「次の区間を起動しない」だけで、動いている claude は残る。名前つきの `stop` がシグナルファイルだけなら、その行は `relay.lock` が持たれたまま `running` と出て、AC11 の「その 1 本だけが止まり」を満たせない。そこでシグナルファイルを置いてから `tmux kill-session` を呼び、ラッパーへ SIGHUP を届ける（今の `_serve_terminal` が SIGHUP で端末を戻し、`close` を通って終わる）。5 秒で `relay.lock` が放されなければ、`lib/procs.py` の `stop_tree` で止める。会話の記録は残るため、`restart` で続けられる。名前を付けない `stop` は今のまま変えない（AC12）。

根拠: Value 2 / Value 6（MVV 版 4）

### 決定 10: やり直した後もループが続くよう、`restart` は最後の区間の入力で起動し直す

開発ループは区間ごとに `ndf-next` の入力（引継ぎ文書を読む `/goal …` など）で続く。最初の引数で起動し直すと、ループが始めの地点へ戻る。区間 1 なら登録簿の `args`、区間 2 以降は最後の start の行の `command` を最初の入力にする。作業ディレクトリは登録簿の値ではなく、最後の start の行の `cwd` を使う（区間の切り替えで worktree へ移っているため）。

`claude --resume <会話>` で起動し直す形は採らない。止めた理由が会話の行き詰まりであることが多く、同じ会話へ戻すと同じ所で止まる。

根拠: Value 2（MVV 版 4）

### 決定 11: 依存を増やさないため、tmux は CLI を `relay_lib/tmux.py` の 1 か所から呼び、libtmux を入れない

使う操作は `new-session`・`has-session`・`list-sessions`・`kill-session` と、`attach-session` への exec の 5 つで、どれも 1 回の呼び出しで終わる。attach は端末をそのまま渡すため、どのライブラリを使っても exec になる。libtmux を入れると、ラッパーを動かす python の環境（`runtime.enter`）の依存が増え、tmux の版ごとの差をライブラリの版でも追うことになる。外部コマンドを呼ぶモジュールを 1 つにする形は、今の `lib/` の包み（`locks.py`・`procs.py`）と同じである。

根拠: Value 6 / Value 10（MVV 版 4）

### 決定 12: 1 本目の振る舞いを変えないため、統括役の仕事は前景のラッパーの thread で行い、端末へは書かない

統括役の処理（受付箱の読み取り・tmux の起動・登録簿の更新）は `Relay` が持つ thread（`UsageWatch` と同じ持ち方）で行う。前景の端末は raw で claude の画面を中継しているため、統括役は端末に何も書かず、記録は `hub-log.jsonl` にだけ残す。統括役の thread の例外は記録に残して thread だけを終え、前景のラッパーを巻き込まない（統括役の役目は `hub.lock` を放して次の `claude` へ渡る）。

統括役を前景と別のデーモンとして起動する形は採らない。利用者の依頼「1本目のrelay.pyが2本目のclaudeを立ち上げ」と、前提 2（1 本目は今どおり前景）から外れ、止め方と寿命を別に持つ必要が出る。

根拠: Value 2 / Value 6（MVV 版 4）

### 決定 13: 名前が tmux で置き換わらないよう、名前の形を `^[a-z0-9][a-z0-9_-]{0,31}$` に限り、無いときは `t<番号>` を付ける

tmux はセッション名の `.` を `_` へ置き換え（2026-11-02 に確かめた）、`:` を対象の区切りに使う。置き換わると登録簿の名前と tmux のセッション名が食い違う。形は Factory の `JOB_ID`（`^[A-Za-z0-9_-]{1,128}$`）の部分集合で、#2189 が指示の識別子を名前へ写すときにも合う。端末から打つときの名前は環境変数 `NDF_RELAY_NAME` で受ける（`claude` の引数は claude へ渡すため、ラッパーの引数を混ぜない）。指定が無ければ、統括役が `t1`（統括役自身）・`t2`… のうち動いていない最小の番号を付ける。要求の前提 3 への答えである。

作業ディレクトリの名前（リポジトリや worktree の名前）から付ける形は採らない。同じディレクトリで 2 本を打つと重なり、区間の切り替えで作業ディレクトリが移る。

根拠: Value 8（MVV 版 4）

### 決定 14: 統括役が答えないときに利用者の手を止めないため、10 秒で結果が無ければ今の前景の起動に戻る

`hub.lock` が持たれているのに結果が来ないのは、統括役の thread が止まったときである。そのまま待つと利用者の `claude` が起動しない。`NDF_RELAY_HUB_WAIT`（既定 10 秒）で待ちを切り、理由を 1 行出して今の前景の起動（統括しない 1 本）へ戻る。tmux が無いとき（AC23）と同じ戻り方である。遅れて統括役が依頼を処理しても重複して起動しないよう、統括役は依頼を `rename` で受け取り、頼む側は待ちを切るときに依頼を消す。消せなければ統括役が受け取った後なので、もう 1 度同じ秒数だけ結果を待つ。

根拠: Value 2（MVV 版 4）
