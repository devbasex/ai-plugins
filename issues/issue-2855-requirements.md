## 目的

並列の計画で、サブスクリプションの利用上限（5 時間・週）に当たって作業が止まる回数を減らす。worker の `claude -p` を、サブスクリプションに付く月の API クレジット（利用上限と別枠）で動かせるようにし、利用上限の消費をその分だけ逃がす。

## 背景（2026-11-09 に公式の文書で確かめた）

- Max・Ultra・Team のサブスクリプションは、リンクした Console 組織へ毎月の API クレジットが付く（Ultra は $200、Max は $100）。**サブスクリプションの利用上限（週・5 時間）とは別枠**で、使っても利用上限は減らない。未使用分は請求の周期の終わりで消える
  - https://support.claude.com/en/articles/17154008-monthly-api-credits-for-max-ultra-and-team-plans
  - https://platform.claude.com/docs/en/about-claude/api-credits-for-subscribers
- クレジットで払えるのは、リンクした組織の **API キーで動かす `claude -p` と Agent SDK**・Messages API など。**対話の Claude Code（ターミナル・IDE・デスクトップ・Web）は払えない**。サブスクリプションのログインで動かす `claude -p` は利用上限から引かれる
- クレジットが尽き、組織に買ったクレジットも自動チャージも無ければ API の要求は止まる（"Your credit balance is too low to access the Anthropic API."）。サブスクリプションへは課金されない
- 今の `relay.py account` は OAuth のアカウント（`account add`）と従量の接続（`account add-bedrock`。保存した宣言の `provider` は Bedrock だけ）を持つ。Anthropic の API キーを登録する副命令は無い（`plugins/ndf/scripts/lib/claude_accounts.py` の `FOREIGN_AUTH_ENV` に `ANTHROPIC_API_KEY` があり、アカウントの子では外している）。環境変数 `NDF_SUPERVISE_CLAUDE_FALLBACK` で `ANTHROPIC_API_KEY` を従量の接続として宣言することはできるが、1 本だけで、登録済みアカウントがすべて上限のときにだけ、対話のセッションにも使われる

### Team プランの API クレジット（2026-11-09 に公式の文書で確かめた）

| 項目 | Team プラン | 個人の Max・Ultra |
| --- | --- | --- |
| 金額 | Standard の席 $20・Premium の席 $100。全席の分を 1 つの残高にまとめ、上限は月 $500（"On Team plans, credits for all seats are pooled into one monthly balance, capped at $500."） | Max $100、Ultra $200（固定） |
| 受け取る人 | Team の Primary Owner か Owner が 1 人で Console 組織をリンクして受け取る（"One owner links a Console organization and claims the pooled credit, up to $500 a month."）。Console 側は Owner・Admin・Billing | 契約者本人 |
| 使える人 | リンクした組織で API キーを持つ全員が同じ残高から使う（"Everyone with an API key in the linked organization can use the balance."）。使いすぎは workspace の spend limit で抑える | 同じ |
| 条件 | サブスクリプションが有効になって 7 日後から（"New subscribers can claim credits after 7 days on an eligible plan."） | 同じ |
| 席の増減 | 足した席は翌月の付与から数え（"Seats added to your plan count from the next billing month's credit."）、外した席は更新まで残る（"Seats you remove stay on your plan until it renews, so the credit might be lower after that."） | — |

- 例: Premium 2 席と Standard 3 席なら月 $260。Premium を 1 席足すと翌月から $360
- 利用上限とは別枠（"Separate from your plan limits."）。ただし、クレジットで使った分も組織の月の spend cap に数える
- 使える先・使えない先は個人のサブスクリプションと同じ
- 個人のサブスクリプションから Team へ移ると個人のリンクは終わり、Team の Owner が 7 日後に受け取る。1 つの Team プランにリンクできる Console 組織は 1 つで、変えるにはサポートへの連絡が要る
- 公式の文書に書かれていないこと: Standard と Premium の席の違い、席数の最低条件、API キーでクレジットの残高を読む手段

## 前提

- 前提 1: 登録する API キーは、利用者の登録済みアカウント（OAuth）のサブスクリプションにリンクした Console 組織のキーである。NDF はキーとサブスクリプションのリンクを確かめない（確かめる API が公開されていない）。結び付けは利用者が登録のときに宣言する
- 前提 2: 1 つの登録済みアカウントに結び付ける API キーは 0 本か 1 本である（1 つのサブスクリプションにリンクできる組織は 1 つ）。Team プランのアカウントも同じ扱いで登録できる
- 前提 3: 残高は API キーでは読めない。残高切れは、要求の失敗の文言（"credit balance is too low"）を受けた時点で知る
- 前提 4: 登録済み API キーと従量の接続（Bedrock・環境変数の宣言）の両方が使えるときは、登録済み API キーを先に使う。従量の接続の振る舞い（登録済みアカウントがすべて上限のときに使う）は変えない
- 前提 5: 組織に買ったクレジットか自動チャージがあると、月の API クレジットを使い切った後の要求は残高切れにならず、買ったクレジットから払われる。NDF はこれを検出できない。登録のコマンドはこのことを 1 行で表示する

## 対象範囲

含む:
- `relay.py account` に、Anthropic の API キーを名前を付けて登録する副命令・外す副命令・確かめ直す副命令を足す
- 登録済み API キーを、登録済みアカウントに結び付けて持つ
- `supervise.py` のステップなど、NDF が起動する `claude -p` の worker で、宣言に従って登録済み API キーを使う
- 残高切れと認証の失敗を受けたときの、候補からの除外と記録と起動し直し
- `account list` への状態の表示

含まない:
- ラッパーが起こす対話のセッションで API キーを使うこと（API クレジットで払えない）
- 残高を API で読むこと（Admin API が要り、利用者の通常の API キーでは読めない）
- Console 組織の作成・サブスクリプションへのリンク・API キーの発行（利用者が Console で行う）
- 環境変数 `NDF_SUPERVISE_CLAUDE_FALLBACK` と Bedrock の従量の接続の振る舞いの変更
- `relay.py ls`（ラッパーの一覧）への表示
- Codex など claude 以外の CLI

## 用語

| 用語 | 意味 |
| --- | --- |
| サブスクリプション | 利用者が Anthropic と結ぶ Claude の契約（Max・Ultra・Team）。利用上限（5 時間・週）と月の API クレジットを持つ。supervise.py の「プラン」とは別の物 |
| API クレジット | サブスクリプションにリンクした Console 組織へ毎月付く API の残高。利用上限と別枠で、未使用分は請求の周期の終わりで消える |
| 登録済み API キー | 利用者が `relay.py account` の副命令で預けた Anthropic の API キー。名前と、結び付いた登録済みアカウントを持ち、worker の `claude -p` にだけ使う |
| 残高切れ | API キーの要求が "credit balance is too low" で失敗した状態。そのキーは解除の条件を満たすまで候補から外れる |
| API キーの使い方の宣言 | 登録済み API キーを worker にいつ使うかを決める 1 つの設定。既定は「使わない」 |

## 受け入れ条件

### 登録

- [ ] 1. 登録の副命令は、名前と API キーの値と、結び付ける登録済みアカウントの名前を受け取る。値は対話の入力を待たずに渡せる（標準入力など。AI が代わりに打てる）
- [ ] 2. 登録の副命令は、保存の前に 1 回だけ API の要求を打ってキーを確かめる。認証の失敗・残高切れ・通信の失敗のときは、理由を表示して 0 以外の終了コードで終わり、何も保存しない
- [ ] 3. 登録した API キーは置き場のファイルに 0600 で保存される。キーの値は、標準出力・標準エラー・進捗ログ・判断の記録・`account list` のどれにも現れない（テストは、偽のキーの値の文字列がこれらに 0 回現れることで判定する）
- [ ] 4. 名前を変えて 2 本以上を登録でき、外す副命令で 1 本ずつ外せる。同じ名前で登録し直すと置き換わる。既存の登録済みアカウントの名前と、予約の名前（`metered`）とは衝突させない（衝突は理由を表示して拒む）

### 使う範囲

- [ ] 5. 登録済み API キーは NDF が起動する `claude -p` の worker（`supervise.py` のステップなど）の環境にだけ渡る。ラッパーが起こす対話のセッションの環境に、登録済み API キーの値が入ることは無い
- [ ] 6. API キーの使い方の宣言は 1 か所にあり、少なくとも「使わない」「常に使う」「サブスクリプションの利用上限に近づいたら使う」を選べる。宣言が無いときは「使わない」として動く
- [ ] 7. 宣言が「使わない」のとき、worker の起動の環境・アカウントの選定・上限の後の切り替えは、この変更の前と同じになる（既存のテストがそのまま通る）
- [ ] 8. 使える登録済み API キーが 2 本以上あるとき、どれを選ぶかの規則が 1 つに決まっていて、同じ状態からは同じキーを選ぶ（規則は設計で決める。未決 3）。残高切れか認証の失敗の状態のキーは選ばない

### 失敗したとき

- [ ] 9. API キーで起動した worker が残高切れで終わったら、そのキーの状態を残高切れとして記録し、次の使える API キーか、それが無ければサブスクリプションのログイン（今のアカウントの選定）で同じ呼び出しを起動し直す。ステップは止まらない
- [ ] 10. 9 と同じ扱いを認証の失敗でも行い、状態は認証の失敗として記録する。どちらも、進捗ログに、キーの名前と理由（残高切れ・認証の失敗）が 1 行残る（値は残らない）
- [ ] 11. `relay.py account list` に、登録済み API キーごとに名前・結び付いたアカウント・状態（使える・残高切れ・認証の失敗）が出る。値は出ない
- [ ] 12. 確かめ直す副命令で、指定した API キーに 1 回要求を打ち、成功すれば状態を使えるへ戻す

### 退行しない

- [ ] 13. 登録済み API キーが 0 本のとき、`relay.py account` の既存の副命令・ラッパーの区間の起動・worker の起動の振る舞いは変わらない（既存のテストがそのまま通る）
- [ ] 14. OAuth のアカウントと Bedrock の従量の接続の登録・一覧・外す・確かめる副命令の出力と終了コードが変わらない

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 可用性 | 残高切れ・認証の失敗で worker のステップを止めない（受け入れ条件 9・10）。置き場が壊れていれば、API キーを使わずに今の振る舞いで動き、壊れていることを 1 行表示する |
| セキュリティ | キーの値は 0600 のファイルにだけ置き、画面・記録・ログに出さない（受け入れ条件 3）。子の環境へ渡すのは選んだ 1 本だけで、ラッパーの対話のセッションへは渡さない（受け入れ条件 5）。秘密の検査（`python3 scripts/check-repo-secrets.py`）が通る |
| 運用・保守性 | 状態の確認（`account list`）と解除（確かめ直す副命令）が利用者のコマンドで完結する |
| 移行性 | 置き場に新しいファイルを足すだけで、既存のファイルの形を変えない。登録が無ければ移行の操作は要らない |
