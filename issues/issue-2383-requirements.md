## 具体例

## 目的

- 利用者が電波の届かない場所でも、最後に受け取ったスプリントの一覧・詳細・承認を待つ依頼を読み、承認の判断の材料をそろえられる状態にする
- オフラインの間に押した取り消せない操作が、サーバーの今の状態と食い違ったまま確定しない状態にする
- 端末に残したデータを、端末を手にした他人が読めず、ログアウトと期限切れで残らない状態にする

## 前提

- 前提 1: 端末の控え（下の「用語」）に入れるのは、この課題を実装する時点で画面が読んでいる次の応答である。スプリントの一覧（`listSprintRuns`）・スプリントの詳細（`getSprintRunDetail`）・承認を待つ依頼の一覧（`listApprovalRequests`）・ループの一覧と詳細（`listLoops`・`getLoopDetail`）。承認資料のうち今ある部分は、スプリントの詳細の承認ゲートの状態・工程・Pull Request と、承認を待つ依頼の一覧である
- 前提 2: #2173 が作る承認資料（設計文書の節・ゲート 2 の中身の行）と通知の一覧は、この課題の仕組みへ読み出しの操作を登録することで端末の控えに入る。登録とそのテストは #2173 が持つ。この課題は、読み出しの操作を 1 行の登録で控えに足せる形を用意する
- 前提 3: 端末の控えに入れない応答: アカウント・席・モデルの資格情報・委任の資格情報・リポジトリの候補・工程の中身（`getStepDetail`）。前の 4 つは秘密か個人情報に近く、工程の中身は 1 件が大きく、承認の判断に要る材料はスプリントの詳細で足りるため
- 前提 4: 端末の控えの保存の期限は、控えを作ったときのログインの token の有効期限の時刻（token の `exp`）である。期限の時刻と利用者の ID は秘密ではないため、控えとともに残す。期限の前なら、token の無いタブでもオフラインのときに控えを読める。期限を過ぎた控えは表示せずに消す。ログインの延長（refresh token）は作らない
- 前提 5: 「取り消せない操作」は、今の画面にある次の 4 つである。ループの人の判断待ちへの答え（`answerLoop`。承認と差し戻しのボタン `ApprovalActions` を使う）・ループの開始（`startLoop`）・ループを止める（`cancelLoop`）・スプリントの実行を止める（`cancelSprintRun`）。#2173 の承認ゲートの答えは、#2173 がこの仕組みへ載せる
- 前提 6: オフラインの間に取り消せない操作のボタンを押すと、操作は確定待ちの操作として端末の控えに残り、画面は「つながってから確定します」と確定待ちの数を出す。確定させるのは、画面を開いていて、つながりが戻ったときだけである。画面を閉じている間に確定することはない（Service Worker の背景の同期は使わない）
- 前提 7: つながりが戻ったとき、確定待ちの操作ごとに、操作の対象の今の状態をサーバーから読み、押したときに画面が見ていた状態と同じときだけ確定する。比べる状態は操作ごとに決め、少なくとも次を含む。判断待ちへの答えは「同じ周回の同じ課題が、まだ答えを待っている」。止める操作は「対象がまだ終わっていない」。ループの開始は「同じ名前のループが動いていない」
- 前提 8: オフラインで画面を開き直しても読めるように、画面の資産（HTML・JavaScript・CSS・翻訳のファイル）を Service Worker で端末に置く。API の応答は Service Worker の控えに置かず、暗号化した端末の控えにだけ置く
- 前提 9: 取り直しで食い違ったときは、サーバーの応答で控えを置き換える。端末の側の変更は確定待ちの操作だけで、控えの読み出しの結果を端末で書き換えることはない

## 対象範囲

含む:

- 読み出しの応答を、暗号化して端末に残す仕組み（端末の控え）と、そこへ読み出しの操作を登録する形
- オフラインの間に、前提 1 の画面を端末の控えから表示し、受け取った時刻を出すこと
- つながりの状態の「最後に受け取った時刻」と「確定待ちの数」を、実際の値で出すこと（`factory/web/src/connection.ts` の `browserConnection` は今 online だけを持つ）
- つながりが戻ったときの、控えの取り直しと、確定待ちの操作の照合と確定
- ログアウト・ログインの期限切れ・別の利用者のログインで、端末の控えと確定待ちの操作を消すこと
- 画面の資産をオフラインで読み込めるようにすること（前提 8）
- 前提 5 の 4 つの操作を、確定待ちの操作として扱うこと

含まない:

- #2173 の承認資料・通知・承認ゲートの答えを控えへ登録すること（前提 2・前提 5。#2173 が持つ）
- 前提 3 の応答を控えに入れること
- 取り消せる操作（リポジトリの登録・予算の変更など）のオフラインでの受け付け。今のとおり、オフラインでは押せない
- 画面を閉じている間の確定（前提 6）と、ブラウザの押し出しの通知
- ログインの延長（refresh token）と、ログインの仕組みの変更
- API の変更（読み出しは今の配列の入出力をそのまま使う）

## 用語

| 用語 | 意味 |
| --- | --- |
| 端末の控え | 画面が最後に受け取った読み出しの応答を、暗号化して端末に残したもの。受け取った時刻と保存の期限を持つ |
| 確定待ちの操作 | オフラインの間に押した取り消せない操作で、つながったときに今の状態と照らしてから確定するもの |

## 受け入れ条件

オフラインで読む:

- [ ] 1. スプリントの一覧・詳細・承認を待つ依頼の一覧を一度開いた後、通信を切って画面を開き直すと、最後に受け取った中身が表示される（E2E。Playwright で通信を切り、ページを読み込み直す）
- [ ] 2. ループの一覧と詳細も、1 と同じく通信を切った後に表示される（E2E）
- [ ] 3. 端末の控えから表示した画面には、その応答を受け取った時刻が利用者の時刻帯で表示され、つながりの状態の表示が「最後に受け取った時刻」を実際の値で出す
- [ ] 4. 一度も開いていない画面を通信を切って開くと、「まだ受け取っていません」の文が出て、空の一覧を「0 件」として出さない
- [ ] 5. つながりが戻ると、端末の控えにある応答を取り直し、画面とその表示がサーバーの応答と同じになる。スプリントの詳細とループの詳細は、控えにある ID をまとめた 1 回の要求で取り直す

端末の控えの守り:

- [ ] 6. 期限の時刻の前なら、token の無いタブでも、オフラインのときに同じ利用者の控えを読める。期限の時刻を過ぎた控えは表示されず、消える
- [ ] 7. ログアウトすると、端末の控えと確定待ちの操作がすべて消える
- [ ] 8. API が 401 を返したとき、または控えと別の利用者がログインしたとき、端末の控えと確定待ちの操作がすべて消える
- [ ] 9. 端末に書いたバイト列の中に、応答の平文（実行の ID・リポジトリ名など、控えた応答に含まれる文字列）と、token の値が現れないことを確かめるテストがある
- [ ] 10. 暗号化の鍵は端末から書き出せない形で持ち、書き出しを試みると失敗することを確かめるテストがある

取り消せない操作:

- [ ] 11. オフラインで前提 5 の操作のボタンを押すと、操作は確定せず（API へ要求を送らず）、画面に「つながってから確定します」と確定待ちの数が出る
- [ ] 12. 確定待ちの操作は、つながる前なら利用者が取り消せ、取り消したものは確定しない
- [ ] 13. つながりが戻ると、確定待ちの操作ごとに対象の今の状態を読み、押したときと同じなら確定する。食い違えば（例: 判断待ちがすでに答えられている・ループがすでに止まっている）確定せず、食い違いの理由を画面に出す
- [ ] 14. 今の状態の読み出しが失敗したときは確定せず、確定待ちのまま残す
- [ ] 15. オンラインのときの前提 5 の操作は、今と同じくその場で確定する（退行しない）

退行しない:

- [ ] 16. 端末の控えへの保存が失敗しても、オンラインの画面は今と同じく応答を表示する
- [ ] 17. オンラインの間、画面の表示と読み直しの間隔（`usePolled`）は今と変わらない
- [ ] 18. 前提 3 の応答（委任の資格情報の値・モデルの資格情報など）は端末の控えに入らないことを確かめるテストがある

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| セキュリティ | 端末の控えは暗号化して保存し、鍵は書き出せない形で持つ（受け入れ条件 9・10）。token・キー・資格情報の値は控えに入れない（受け入れ条件 9・18）。控えはログアウト・401・期限・別の利用者で消す（受け入れ条件 6〜8） |
| 性能・拡張性 | 取り直しは画面ごとに 1 回の配列の要求にまとめる（受け入れ条件 5）。オンラインのときの表示の速さは今と変わらない |
| システム環境 | 対象のブラウザは、e2e が使う Chromium と、スマートフォン・タブレットの幅（360・768 px）の表示。iOS の Safari の実機での確認はリリース後テストで行う |

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わらない。API と契約（`factory/contracts/`）は変えない |
