# #928: 親から子への送り込み — 実測と不変条件

設計の本体は [issue-928-design.md](issue-928-design.md)、決定は [issue-928-design-decisions.md](issue-928-design-decisions.md) にある。
この文書は項目 3（中継が子の擬似端末へ `/exit` 以外の入力を書けるか）の実測の結果と、**送り込みを
実装するときに守る不変条件**を残す。送り込みの実装は別の課題 #931 で行う（決定 6）。**不変条件のうち
関門を越えない守り（G1〜G3）は、既存の `/exit` の入力にも当たるため、この課題で入れる**（決定 13）。

## 例: 質問の表示中に届いた改行が関門を答える

`AskUserQuestion` で「A と B のどちらが好きですか」を出させ、表示から約 2 秒後に中継と同じ形で
擬似端末のマスタへ `/clear` と `\r` を書いた。**答えは `"A"` になった。** `/clear` は実行されず、
`\r` がフォーカス中の選択肢 1 を決定した。`承認します` と `\r` でも答えは `"A"` で、文は自由記述に
入らなかった。数字の `2` は `\r` なしで即座に `"B"` を決定した。

**関門の質問の選択肢 1 が「承認」なら、中継が書いた `\r` がそのまま承認になる。** 10.17.4 の中継が
切れ目で書く `/exit` と `\r` も同じ形である。印（`next.json`）は最後の Stop で書かれ、次の Stop まで
残る。**印の後に応答が再開して質問が出る経路**（`/goal` の判定が未達で応答を続けさせた、など）では、
質問の表示のあいだ会話の記録が静まり、15 秒の後に中継が `/exit` と `\r` を書く。

## 実測の条件

| 項目 | 値 |
| --- | --- |
| 日時 | 2026-09-23 |
| Claude Code | 2.1.281（`--model haiku`）。Linux の擬似端末（45×140）の子として起動した |
| 隔離 | `HOME`・`CLAUDE_CONFIG_DIR`・`XDG_{CONFIG,DATA,STATE,CACHE}_HOME` を一時ディレクトリへ、`DISABLE_AUTOUPDATER=1`。認証は複写した。利用者の `~/.local/bin/claude` の symlink・`~/.bashrc`・`~/.zshrc`・`~/.claude/settings.json` は前後で変わっていない |
| 観測 | 画面（端末の描画）・会話の記録・hook（`UserPromptSubmit` / `Stop` / `PreToolUse` と `PostToolUse` の `AskUserQuestion` / `Notification` / `PreCompact` / `SessionStart` / `SessionEnd`）の入力の記録 |
| 形 | 「1 回」= 文字列と `\r` を 1 回の write。「間あり」= 文字列の 1 秒後に `\r`（10.17.4 の `/exit` の形） |
| 試行 | 31 回（hook の実行中の 6 回を含む）。同時に動かした claude は 1 つ |

## 実測の結果

### 入力待ち（応答が終わった後）

| 送った入力 | 受け付け | 画面・記録 | hook |
| --- | --- | --- | --- |
| `/clear` | 働く | 画面が消え、新しい会話の記録が始まる | `SessionEnd`（`clear`）→ `SessionStart`（`clear`・新しい session_id） |
| `/compact` | 働く | 10〜23 秒で要約が終わる | `PreCompact`（`manual`）→ `SessionStart`（`compact`・同じ session_id） |
| `/cost` / `/status` | 働く | 設定の対話が開く。`Esc` 1 回で閉じる | 無し |
| `/plugin` | 働く | プラグインの対話が開く。`Esc` 1 回で閉じる | 無し |
| `/model sonnet` | 確認で止まる | 会話があると「Switch model?」の対話が出る。`\r` で切り替わり、**利用者の設定へ既定として保存される**。`Esc` で取り消す | 無し |
| 文 2 つを `\r` で区切って 1 回で書く | 2 つの別の入力 | 1 つ目の応答の後に 2 つ目が送られる | `UserPromptSubmit` が 2 回 |

- **スラッシュコマンドでは `UserPromptSubmit` も `Stop` も発火しない。** 送ったコマンドが終わったことを Stop hook で知ることはできない
- 短い入力では「1 回」と「間あり」に違いが無い

### 応答の生成中

`/clear` と `\r` を 1 回で書くと、**待ち行列に入った**（画面に `Press up to edit queued messages`）。
応答は割り込まれず最後まで出て、その `Stop` の直後に `/clear` が実行された。

### `AskUserQuestion` の表示中

| 送った入力 | 答え |
| --- | --- |
| `/clear` + `\r`（1 回・間あり） | `"A"`（選択肢 1）。`/clear` は実行されない |
| `承認します` + `\r`（1 回・間あり） | `"A"`。文は自由記述に入らない |
| `1` / `2` | `"A"` / `"B"`。`\r` なしで即座に決まる |
| `\r` だけ | `"A"` |
| 文字だけ（`\r` なし）の後に `Esc` | 文字は捨てられ、`Esc` で質問が取り消される（`User declined to answer questions`） |

| hook | 質問の表示との関係 |
| --- | --- |
| `PreToolUse`（`AskUserQuestion`） | **表示と同時に発火する** |
| `PostToolUse`（`AskUserQuestion`） | 答えると発火する。`Esc` で取り消すと**発火しない** |
| `Stop` | 表示中は発火しない。`Esc` で取り消した後も 20 秒発火しなかった |
| `Notification`（`permission_prompt`） | 表示から約 6 秒後。約 2 秒で答えると発火しない |

### `PreToolUse`（`AskUserQuestion`）の hook の実行中

hook を 3 秒止め、その実行中（開始の約 1 秒後）に書いた。6 試行。

| 送った入力 | 質問の対話 | 結果 |
| --- | --- | --- |
| 無し | hook の終了の 0.05〜0.11 秒後に初めて描かれる（4 試行で同じ） | hook の実行中の画面は、通常の入力欄とスピナーだけ |
| `/exit\r`（2 回） | 描かれない | 約 0.4 秒で `/exit` が実行されて claude が終わる。質問の答えは残らない |
| `\r` だけ | hook の後に描かれる | 捨てられる。質問の答えにならない |
| `1` だけ | hook の後に描かれる | 答えにならず入力欄の下書きに残る。後の `/exit\r` と合わさり `1/exit` が普通の文として送られた |
| `hello\r` | hook の後に描かれる | 待ち行列に入り、質問に答えた後に答えと一緒にモデルへ渡る |

**hook の実行中に書いた入力は、質問の答えにならない。** 質問の対話は hook が終わるまで描かれないためである。
G3 のロックはこの事実に立つ。

### 長い入力

子は起動時にブラケットペーストのモード（`\x1b[?2004h`）を入れる。

| 送った入力 | 結果 |
| --- | --- |
| 125 バイト + `\r`（1 回） | 送られる |
| 635 バイト・1,835 バイト + `\r`（1 回） | **送られない。** 後から書いた `/exit` と `\r` が、文の末尾に `\n/exit` として付いた普通の文として送られた |
| 635 バイト → 1 秒 → `\r` | 送られる |
| `\x1b[200~` + 635 バイト + `\x1b[201~` + `\r`（1 回） | 送られる |
| `\x1b[200~/clear\r\x1b[201~` | 送られない（括りの中の `\r` は送信にならない） |

## 不変条件

送り込み（別の課題）と、この課題の `/exit` の入力の両方が守る。**G1〜G3 はこの課題で入れる。**

| # | 不変条件 | 担保する実測の事実 | 実現方式 |
| --- | --- | --- | --- |
| G1 | **質問（`AskUserQuestion`）の表示中は、子の端末へ何も書かない** | 表示中の `\r` は選択肢を決め、数字は即決する。文字の中身に依らない | `PreToolUse`（`AskUserQuestion`）の hook が作業ディレクトリへ `question` を作り、`PostToolUse` と `mark`（Stop）が消す。中継は `question` がある間は書かない |
| G2 | **印の後に応答が再開していたら、その印では書かない** | 印は次の Stop まで残る。質問の表示中は Stop が起きない | 中継は、会話の記録に印の `written_at` より後の `assistant` か `user` の行（目標の判定の `attachment` は数えない）があれば、その印を古いものとして扱い、次の Stop が印を書き直すか消すまで待つ |
| G3 | **G1・G2 の確かめ直しと write を、質問の始まりと排他にする** | 質問の対話は `PreToolUse` の hook の終了の後に描かれ、hook の実行中の入力は答えにならない（「hook の実行中」の表）。短い入力は 1 回でも間ありでも同じに働く | 中継と `question open` が同じロック `question.lock` を取る。中継はロックの中で確かめ直し、`/exit` と `\r` を 1 回の write で書き、1 秒おいて放す |
| G4 | 人の入力を装える自由な文を送らない | 自由な文は `UserPromptSubmit` として人の入力と区別されない | 送ってよいのは許可の一覧のスラッシュコマンドだけ（下の「送り込みの実装の下書き」）。改行・制御文字を含む中身は捨てる |
| G5 | 対話の UI を開くコマンドを送らない | `/cost`・`/status`・`/plugin`・`/model` の確認は対話で止まり、閉じるのに `Esc` が要る。`Esc` は質問を取り消す | 許可の一覧に入れない。`/model` は既定の保存も起きる |
| G6 | 送ったコマンドの終わりを Stop で待たない | スラッシュコマンドでは Stop が発火しない | 終わりは `SessionStart`（`clear` / `compact`）の hook か、会話の記録で見る |
| G7 | 長い入力を 1 回の write で送らない | 635 バイトを 1 回で書くと送られず、後の入力と混ざった。125 バイトは送られた（境界は測っていない） | 送り込みの中身の上限を 125 バイト以下の 100 バイトにする。それを超えるものは送らない |

**G1 の `question` が `PostToolUse` で消えない場合**（`Esc` で取り消した）は、次の Stop で `mark` が消す
まで中継は書かない。**残るほうへ倒す。** 取り消しの後は人が入力するので、その応答の Stop で消える。

## 送り込みの実装の下書き（#931 の入力）

| 項目 | 下書き |
| --- | --- |
| モデルからの要求 | 最後の応答の `ndf-send` のブロック 1 つ。`mark` が `send.json` に写す（`next.json` の形は変えない） |
| 許可の一覧 | `/clear` と `/compact [指示]` から始める。`/model` は確認の対話と既定の保存があるため入れない |
| 時点 | `next.json` と同じ静まりと G1〜G3。送った後は印を消し、`SessionStart` の hook で終わりを知る |
| 失敗 | 許可に無い・長すぎる・改行を含むなら送らず、`ndf-relay:` の 1 行で知らせる |
| 未確認 | 質問の自由記述（`Type something.`）へフォーカスが移った状態での入力、質問の表示中のブラケットペースト、`/model` の会話の無い状態 |
