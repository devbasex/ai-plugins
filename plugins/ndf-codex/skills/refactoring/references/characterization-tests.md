# 現状固定テスト

**現状の振る舞いをそのまま正解として記録するテスト**である。正しさを主張しない点が通常の
テストと違う。目的は 1 つで、構造を変えたときに振る舞いが変わったことを検出することにある。

## 通常のテストとの違い

| | 通常のテスト | 現状固定テスト |
| --- | --- | --- |
| 期待値の根拠 | 仕様・受け入れ条件 | **現在の実装の出力** |
| 不具合を含むか | 含まない | **含みうる**（現状が不具合ならそれも固定される） |
| 寿命 | 仕様が変わるまで | 構造改善が終わり、仕様ベースのテストへ置き換わるまで |
| 失敗の意味 | 仕様違反 | 振る舞いが変わった（意図的か事故かを判断する） |

## 手順

### 1. 入口を決める

固定する対象は**公開された入口**にする。内部関数を固定すると、その内部構造を変えられなく
なり、構造改善の妨げになる。

### 2. 現状の出力を取る

対象を実際に動かし、出力を記録する。期待値を自分で考えて書かない（考えた値は仕様であり、
現状ではない）。

```python
# 1. まず何が返るか分からない状態でテストを書く
def test_current_behavior_of_price_calculation():
    result = calculate_price(quantity=3, unit_price=100, coupon="SUMMER")
    assert result == 0   # ← 仮の値。実行して実際の値に置き換える
```

```text
$ pytest -k test_current_behavior_of_price_calculation
E   assert 270 == 0     ← 現状の出力は 270。これを期待値にする
```

### 3. 分岐を洗い出して固定する

1 つの入力だけでは足りない。**構造改善で通る経路**を固定する。

| 固定する入力 | 理由 |
| --- | --- |
| 代表的な正常系 | 主要経路 |
| 各分岐に入る入力 | 改善で分岐を触るため |
| 境界値（0 件、空、上限） | 条件式の書き換えで壊れやすい |
| 例外・エラーになる入力 | 例外の種類とメッセージも振る舞いである |

分岐に入る入力が作れない場合、その分岐は到達不能な可能性がある。削除の候補として記録する
（削除は別の差分で行う）。

### 4. 副作用を観測できるようにする

戻り値以外の振る舞いも固定する必要がある。

| 副作用 | 固定の仕方 |
| --- | --- |
| DB への書き込み | 書き込み後の状態を読み出して比較する |
| 外部への通信 | 呼び出し内容（宛先・本文）を記録して比較する |
| ファイル出力 | 出力内容を比較する（差分が大きい場合は要点だけ） |
| ログ | 仕様として決まっているものだけ固定する |

外部依存を分離できない場合は、依存を注入できる形へ変える **最小限の変更** を先に行う。
その変更自体はテストで守れないため、差分を小さく保ち、単独のコミットにする。

### 5. 不具合を見つけたときの印

現状が明らかに誤っている場合、固定したうえで印を残す。

```python
# NOTE: 現状固定。クーポン期限切れでも割引が適用される不具合を含む。
#       修正は別の変更で行う（issues/xxx.md）。
def test_current_behavior_applies_expired_coupon():
    assert calculate_price(coupon="EXPIRED") == 270
```

印がないと、後任が「これが仕様だ」と読む。

## 出力が大きい場合

出力全体を比較すると、無関係な差分（順序・空白・時刻）で落ちる。次のどちらかにする。

- **要点だけを比較する**（件数・合計・キーの集合）
- 出力を正規化してから比較する（並べ替え、時刻の置換）

出力全体を丸ごと保存して比較する方式（承認テスト）を使う場合は、保存ファイルを差分と
一緒にレビューできる形にする。中身を読まずに更新すると、退行を承認してしまう。

## 役目を終えたら置き換える

構造改善が終わったら、固定テストを仕様ベースのテストへ置き換える。置き換えの目安:

| 状況 | 対応 |
| --- | --- |
| 仕様が確認でき、期待値の根拠が書ける | 仕様ベースのテストへ書き換える |
| 固定した振る舞いが不具合だった | 不具合を直し、テストを正しい期待値へ変える |
| 仕様が誰にも分からない | 固定テストを残す。根拠が「現状維持」であることをコメントに書く |

固定テストを残すこと自体は問題ない。**根拠を書かずに残すこと**が問題になる。
