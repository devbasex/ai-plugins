## 最終ゲート

最終ゲートは `ndf refactor run` が項目を流し終えた後に受け持つ（打つコマンドは無い）。1 周は次の順に進み、`--max-fix` の回数まで
最終ゲート修正を挟んで回す。

1. 作業ディレクトリを origin の head ブランチの先頭へ合わせて送る。衝突したら `base_conflict`、push を断られたら `push_rejected` で止まる
2. CI を待つ前に PR がベースブランチと衝突していないかを見る。衝突していれば CI は始まらないので待たずに `base_conflict` で止まる。
   GitHub がまだ計算中なら間を置いて読み直す
3. 送った head の必須のチェック（`--required`）と CI のテスト（`--ci-test`）を待つ。通れば最終ゲートを通過する
4. テストが落ちたら、落ちたテスト（CI から読めなければ落ちたチェックの名前）を渡して修正担当を起動する（最終ゲート修正）。
   テスト以外の検査の落ち・待ちの上限は、そのまま停止理由にする

**木が起点と同じでも確かめを省かない。** `--max-fix` の回数を使い切ってもテストが落ちていれば `test_failed` で止まる。

### 最終ゲート修正は対象範囲の中だけを直す

最終ゲート修正は、直しのコミットがリファクタリング計画の対象範囲（`--scope`）の外のファイルを変えていれば、マージせずに
修正の前の HEAD へ戻し、落ちたテストと範囲外のファイルを最終ゲートの記録に残して `refused` で止まる。修正担当が結果を出さずに
終わったときも、検査していない変更を修正の前へ戻して `work_stopped` で止まる（同じコマンドの再開が範囲外の変更を検査せずに
送らないためである）。

## 単独起動の終わり

**`ndf refactor run` の最終ゲートは CI の必須のチェックで判定し、cross-review を呼ばない。** 単独起動で Pull Request 全体を
承認収束にかけるなら、`run` が `ok` で終わった後に `/ndf:cross-review <PR>` を打つ。項目の妥当性は範囲テストで判定済みのため、
**項目をまたいだ整合**（複数の項目で触った箇所の重複・打ち消し・命名の揺れ、取り消した項目の残骸、生成物とリリース対象の同期）を見させる。
Draft を解除するのは、cross-review の結果 JSON の `status` が `ok` のときだけである。

## 配分の表

**配分の表は保存しない。** リファクタリング計画のたびに、次の順で組む。

| 材料 | 中身 |
| --- | --- |
| 初期値 | Skill の `data/allocation-defaults.json` の種類ごとの分 |
| 設定 | `.ndf/estimate.json` の `allocation_minutes`。書いた種類だけ初期値より先に効く。初期値に無い種類・0 以下の分は `invalid` で止める |
| 履歴 | 最終ゲートを通った実行の実測。種類ごとに、その種類を含む直近 10 行の Σ秒 ÷ Σ件数で置き換える。標本の無い手法は手法をまとめた値へ落とす |

履歴は `<記録の根>/<owner>--<repo>/cross-refactoring-allocation.jsonl` に、最終ゲートを通った実行だけが 1 行ずつ足す（記録の根は
`NDF_METRICS_DIR`）。履歴が無いか読めないときは初期値（と設定）で計画し、1 行知らせる。リモートが GitHub でなければ書かない。

## 報告

結果の出口（完了・止まった）で、`run` は次の 2 つを書く。

| 何を | どこへ | 中身 |
| --- | --- | --- |
| 完了報告 | 作業場所の `logs/report.md`（パスは `metrics.report`） | 項目の表・見送りの理由別の件数・工程別の所要・予算と安全網・成立の判定・フレーキーの直し・最終ゲートの記録 |
| リファクタリング計画のコメント | PR のコメント 1 件 | 項目の表（番号・対象・状態・理由）と予算の行 |

- **計画のコメントは前に書いた本文と同じなら書かない**（`metrics.plan_comment` が `unchanged`）。書けなくても結果は変えない（`failed`）。
  リファクタリング計画ができる前に止まった実行では作らない（`skipped`）
- `run` が終わった後に項目のコミットを `git revert` で取り消して push しても、`run` はコメントを読み直さない。コメントの該当する
  項目の状態を手で直す
- 報告と PR の文章では、項目を `<ファイル>#<シンボル>` で書き、リファクタリング計画は生の URL で書く
