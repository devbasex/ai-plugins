# 作業場所・状態ファイル・提案

[← SKILL.md](../SKILL.md)

この文書の手順は `ndf refactor run` が 1 回の実行の中で受け持つ。打つのは SKILL.md の「実行」の 1 行だけで、
対象のリポジトリの中から打つ。Skill のディレクトリへは移らない。

## 作業場所

作業場所の根は NDF の保存先の `rf<PR>` で、中に次を置く。

| パス | 中身 |
| --- | --- |
| `work/` | 書き込み用の作業ディレクトリ。修正担当が動く。PR の head から detached で作る |
| `read/<ランタイム>/` | 読み取り用ディレクトリ。提案と成立の判定の担当が動く。工程の前に `work` の HEAD へ合わせる |
| `logs/` | 担当の出力と、回収した結果ファイル。完了報告（`report.md`）もここに置く |
| `state.json` | 状態ファイル |

- 作る前に、オーナーのいない NDF の lock を片付ける。作った直後に、ホストと時刻つきの lock を掛ける
- 担当の結果ファイルの保存先（`.cross_refactoring/`）は git の除外へ足し、差分に入れない
- 片付けは `ndf refactor release --pr <PR>`（NDF の lock だけを外す）。最終ゲートまで終わった実行は `run` が片付ける

## 状態ファイル

状態ファイルは作業場所の根の `state.json` で、worktree の外に置く（差分に入らない）。一時ファイルへ書いてから置き換えるため、
途中で止まっても半端な JSON を残さない。中身は `ndf refactor state --pr <PR>` で読める。

| キー | 中身 |
| --- | --- |
| `pr`・`branch`・`base`・`args` | 対象の PR・head ブランチ・差分の起点・結果を変える引数 |
| `target_scope` | 対象範囲（`--scope`）。最終ゲート修正はこの中だけを変えてよい |
| `touched` | 課題が触る関数 |
| `phases` | 工程ごとの起点（`base_sha`）と開始の時刻 |
| `items` | 項目。項目ごとに起点 `start`・検証の記録 `history`・状態 `status`・理由 `reason` を持つ |
| `mvv` | 項目を計画したか確かめた MVV を見分ける値 |
| `skipped` | 見送った提案と理由 |
| `budget` | 予算・延ばした実効の予算 |
| `final` | 最終ゲートの記録 |
| `done` | 完了の記録（`head`・`args`・結果 JSON） |

## 再開

**止まった実行は、同じコマンドを打ち直すと終わった工程を流し直さずに続ける。**

| 状態 | 打ち直したとき |
| --- | --- |
| 完了の記録があり、PR の head と結果を変える引数（`--base` がコミットなら PR のマージ先も）が同じ | 前回の結果を返す |
| 完了の記録があり、head・引数・マージ先のどれかが違う | 新しい実行を始める |
| 未完了で、対象ブランチか結果を変える引数が前回と違う | `invalid` で止まる。前と同じ引数で打ち直すか、状態ファイルを消してから打ち直す |
| 項目の途中で止まった | その項目の起点まで戻してからやり直す |
| 計画に使った MVV と今の承認済みの MVV が違う（計画の MVV を記録していない状態も） | 未着手の項目を計画の担当に今の MVV で 1 回確かめさせ、反する項目を見送ってから続ける。担当が結果を出さなければ `work_stopped` で止まる |

安全網の上限（`--safety-net-minutes`）は結果を変える引数に入らない。大きくして打ち直すと、止まった所から続く。作業ディレクトリが
在って git の登録が消えていれば、作業を失わないよう作り直さずに止まる。

## 課題が触る関数

初めに `--base` と HEAD の分岐点からの差分（`--base...HEAD`）から、対象範囲のファイルごとに触った行を含む関数・メソッド・クラスを引いて記録する
（`--symbols` を渡せば差分から引かない）。読み方は `ndf refactor touched --base <B> --scope <範囲...>` と同じである。

- Python は構文木で関数の行の範囲を読む。構文の誤りのファイルでは止まる（ファイル単位へ倒さない）
- 構文木の読み手の無い言語のファイルは、提案をファイル単位で通す
- 関数の外の行だけを触ったファイルへの提案は範囲外になる

## テストの選び方

**項目の検証は、項目が触るモジュールに対応するテストと検査だけを打つ。** 対応は `ndf refactor tests --changed <ファイル>...` で
確かめられる（対応を引けないソースは `unmapped` に載る）。全体テストは最終ゲートが CI の必須のチェックで見る。足したテストが
全体の実行に収集されるかは `ndf refactor collected --paths <ファイル>...` と同じ確かめを `run` が行う。

## 提案

提案の参加者を順に起動し、提案をまとめる。担当は読み取り用ディレクトリで読むだけの起動をし、課題が触る関数だけを
`{"proposals": [{"path", "symbol", "title", "reason"}]}` の形で返す。

- 結果を出さない担当は数えずに続ける。形の違う提案は数えて捨てる
- 同じ関数への同じ趣旨の提案は 1 つにまとめ、提案した担当を並べる（担当の数は計画の順位に効く）
