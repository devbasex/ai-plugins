# 設計方針

| 観点 | 方針 |
| --- | --- |
| 参加者 | **全員 CLI プロセス。** 提案は参加者の全員、リファクタリング計画以降は実装担当 1 者。ホストと同じランタイムでも別プロセスで起動する |
| 実装担当 | **名指し（`--implementer`）→ ホスト（参加者にいれば）→ 参加者の先頭。** 輪番は持たない。再開しても変わらない |
| 時間 | **実装の予算（`--budget-minutes`）は選定にだけ使う。** 見積り（テストの追加と実装の和）の合計が実効の予算に収まる件数を採り、グレード high の和が予算と 2 倍の間なら予算をその和まで延ばす。テストの実行・CI の待ち・経過時間は数えない。予算から締め切りを導かず、選んだ項目を時間で打ち切らない。時間の上限は 2 つだけで、テストと CI の待ちのハングの検知（所要の記録から `3·max(w, m)`・`3·c`）と、コーディングの CLI の起動の秒の累計に置く安全網（既定で実効の予算 × 2。当たったら取り消さずに止めて人へ渡す）である |
| 検証の単位 | **項目。** HEAD で項目ごとの範囲テストを走らせる。全体テストは危険フラグが立ったときに走らせ、直した後は落ちたテストを確かめ直す。落ちたら落ちたテストだけを走らせ直してフレーキー・既存失敗を除き、変更起因なら原因の項目（落ちたテストの出力に現れるパスか、項目を外した走らせ直しで決める。危険フラグとは関係しない）を修正へ回す。原因が決まらなければ取り消さずに最終ゲート修正へ寄せる |
| 収束しない項目 | **落ちたテストの集合の履歴で決める。** 前進（件数が減る・別のテストへ移る）の間は回数の上限なく修正を続ける。停滞（同じ集合が続く）か振動（前に見た集合へ戻る）なら、実装担当と別のランタイムが成立を判定し直し、成立なら修正担当を 1 度だけ替える。成立しない項目と、替えた後も停滞か振動した項目だけを、その項目のコミットの `git revert` で打ち消す。打ち消しが衝突したら打ち消しの前の HEAD へ戻して止め、人へ渡す |
| 見積り | 配分テーブル。所要は**オーケストレーターの時計とコミットの時刻**で測り、担当の申告を使わない |
| 判断 | Jev（公開リポジトリで鍵があるとき）にグレード・同じ変更か・D5 を**リファクタリング計画の手順で**問い、確信度が足りなければ実装担当の答えを使う。リファクタリング計画の後で LLM が動くのは作業の CLI（テストの追加・実装・直し）と、**成立の判定**（実装担当と別のランタイムが、変更起因で落ちた項目と停滞か振動した項目を判定する）である。打ち消し・見送り・前進の判定・フレーキーの見分けはスクリプトが決める。機械で決まらないテストの差分はレビューへ引き継ぐ |
| 範囲の扱い | `--scope` は**案出しの対象を決めるのにだけ使う**。範囲の外の既存のファイルを変えても取り消さず、項目の `outside_scope` に残して報告とコードレビューへ引き継ぐ。分割・抽出で作る新しいファイルはどこに置いても範囲の中として扱う。**テストの置き場所を含めないと `init` が止める** |
| 手順の違反 | **差し戻す。** 計画に無いコミットはそのコミットだけを `git revert` で打ち消し、期待値の欠けと文言を固定するテストは項目を修正へ回し、記名の欠けとテストの追加のコミットの形は報告に残す。手順の違反で項目を取り消さない |
| 公開の責務 | **オーケストレーターだけが push する。** 生成物の同期は `--sync-command` として push の直前にオーケストレーターが行う |
| 検証の情報源 | **git と実際のテスト実行。** 結果ファイルの申告は検証に使わない |
| 外へ出す文章 | 項目は **`<ファイル>#<シンボル>` を併記**し、取り消しは**件数だけ**述べ、リファクタリング計画は**生の URL**で書く |
| 最終ゲート | `--ci-check` があれば継続的統合、無ければ全体テスト。単独起動はその後に `cross-review` |
| 状態の永続化 | `<work>/.cross_refactoring/cross-refactoring-rf<番号>-state.json`（版 3）。中断・再開可能 |

**push が credential helper の不全で落ちたときは、オーケストレーターが退避して 1 度だけやり直す**。退避の値は共通ライブラリ（`<プラグインルート>/scripts/lib/git-credential.sh`）が持つ。
