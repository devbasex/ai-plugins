# フレーキーなテストの直し（cross-refactoring / $RF_RUNTIME）

あなたは **$RF_RUNTIME**（モデル: $RF_MODEL）として、この実行の中でフレーキーと見分けたテストを直します。
フレーキーとは、同じコードで走らせ直すと通ったり落ちたりするテストです。後からでは再現が難しく直せないため、
見つけたこの実行の中で直します。この直しは改善項目とは別のコミットで残し、項目の合否には数えません。

$RF_SKILL_BLOCK

## 必須コンテキスト

- リポジトリ: $RF_REPO / Pull Request #$RF_PR
- 作業ディレクトリ: `$RF_WORKDIR`
- 対象範囲: `$RF_SCOPE`

## 直すテスト

```json
$RF_ITEMS
```

- `tests` が直すテストの ID、`log` が落ちたときのログの置き場、`commands` がそのテストのファイルだけを走らせ直すコマンドです
- `sendback` が空でなければ、前回の直しが手順を外れたための差し戻しです。そこに書かれた違反を直してください

## 手順

1. ログを読み、`commands` を何度か走らせて、落ちる原因（時刻・順序・乱数・共有の状態・待ち時間など）を突き止める
2. テストのファイルだけを直し、原因を取り除く（走らせ直しの回数を増やす・テストを飛ばす・期待値を緩める直し方はしない）
3. テスト 1 件ごとに 1 コミットにし、本文の末尾にトレーラー `Flaky-Fix: <直したテストの ID>` を書く
4. 直せなかったテストはコミットせず、結果に理由を書く

## 提出形式

結果を **`$RF_STEM-result.json`** に書いてください。

```json
{"tests": [{"test_id": "tests/test_foo.py::test_bar", "fixed": true, "cause": "現在時刻に依存していた", "commit": "<SHA>"}]}
```

## 守ること

- テストのファイル以外を変えない。改善項目のコミットを書き換えない
- push しない。`--no-verify` を使わない
- 作業段階が進むたびに `$RF_STEM-progress.log` へ 1 行追記する（`start` / `analyze` / `fix` / `commit` / `done`）
