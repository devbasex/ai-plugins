# 最終ゲートの失敗の修正（cross-refactoring / $RF_RUNTIME）

あなたは **$RF_RUNTIME**（モデル: $RF_MODEL）として、**最終ゲートで落ちた全体の
テストを直します**。

**これは項目の修正ではありません。** 落ちているのは Pull Request 全体の
テストで、**どの改善項目にも属しません**。項目をまたいだ組み合わせや、範囲テストの
外への波及で初めて出る失敗（片方が消した関数をもう片方が呼んでいる、など）がここに
現れます。

## 必須コンテキスト

- リポジトリ: $RF_REPO / Pull Request #$RF_PR
- 作業ディレクトリ: `$RF_WORKDIR`（**ここでだけ作業する**）
- ブランチ: `$RF_HEAD_BRANCH`
- テストコマンド: `$RF_BASELINE_TEST`

## 手順書

$RF_SKILL_BLOCK

## やること

1. `$RF_BASELINE_TEST` を実行し、**どのテストがなぜ落ちているか**を読む
2. **項目をまたいだ組み合わせと、範囲テストの外への波及を疑う。** 個々の項目は
   範囲テストを通っているため、単独の変更だけを見ても原因は出ません
3. **振る舞いを元へ戻す方向で**直す。テストの側を書き換えて通すのではありません
   （**テストを緩めた時点で、振る舞い不変を示す手段が消えます**）
4. 直してから `$RF_BASELINE_TEST` をもう 1 回実行する

**振る舞いを変えないと直せない**と判断したときは、直さずに終えてください。
最終ゲートの修正の上限に達したら、**取り消さずに失敗として報告します**。ここは既に
push した地点なので、取り消しの判断は Pull Request の読み手が持ちます。

## コミットの規約

**求めるトレーラーは 2 つだけです。** `Item-Id` は書きません。この修正は
改善項目に属さないため、書くと実在しない番号を作ることになります。

```text
Fix: 最終ゲートのテストの失敗を直す — src/foo/bar.py#BarService.handle

（何をどう直したか）

Impl-Runtime: $RF_RUNTIME
Impl-Model: $RF_MODEL
```

**コミットごとのテストの合否は見ません。** 合否は取り込みの直後に最終ゲートが
1 度だけ判定します（継続的統合で判定する実行では、手元のテストを走らせません）。

**申告から漏れたコミットがあると、この修正の範囲ごと取り消されます。** 作った
コミットは 1 件残らず結果ファイルへ書いてください。

## 作業の進み具合を残す

**作業段階が進むたびに `$RF_STEM-progress.log` へ 1 行追記してください。**
テストの実行中は何も出力されないため、追記が無いと監視が「進んでいない」と見て
打ち切ります。書くのは段階と対象だけで、内容は要りません。

```bash
echo "test src/foo.py" >> "$RF_STEM-progress.log"
```

| 段階 | いつ書くか |
| --- | --- |
| `start` | 着手した |
| `edit` | ファイルを書き換えた |
| `test` | テストを実行する直前 |
| `commit` | コミットした |
| `done` | 結果ファイルを書き終えた |

## 守ること

- **push しない。** 公開するのはオーケストレーターだけで、**検証を通した後**に行います
- **`git push --force` と `--no-verify` を使わない**
- **コミット時のフックが生成物の同期を求めても、同期はしない。**
  同期はオーケストレーターが公開の直前に行うため、ここでは生成物が古いのが正しい状態です。
  フックが原因でコミットできないときは
  `git -c core.hooksPath=/dev/null commit ...` で**そのコミットだけ**フックを外します
- **直した内容は必ずコミットする。** worktree に置いたまま終えると、
  検証を受けていない変更として捨てられます
- 作業ディレクトリの外を触らない
- **対象範囲（`$RF_SCOPE`）の外にあるファイルを 1 つも変更しない。** 範囲外を触った
  修正コミットがあると、この修正の範囲ごと取り消されます
- **生成物・配布物の同期をしない。** 同期はオーケストレーターが公開の直前に行います
- 失敗と関係の無い箇所を「ついでに」直さない
- **テストの期待値を緩めて通さない。** 振る舞いが変わっていないことを示す手段が消えます

## 提出形式

結果を **`$RF_STEM-result.json`** に次の形で書いてください。

```json
{
  "elapsed_seconds": 133,
  "commits": [
    {
      "sha": "def5678",
      "trailers": {
        "Impl-Runtime": "$RF_RUNTIME",
        "Impl-Model": "$RF_MODEL"
      }
    }
  ]
}
```

判定はオーケストレータが **git** から行います。結果ファイルに何と書いてもチェック結果は
変わりません。使うのは「どのコミットを作ったか」の申告だけです。
