# テスト整備の提案（cross-refactoring / $RF_RUNTIME / テスト整備ラウンド $RF_ROUND）

あなたは **$RF_RUNTIME**（モデル: $RF_MODEL）として、下記の範囲のうち
**テストが薄い経路**を挙げ、そこへ足す現状固定テストを提案します。
この段階では**コードもテストも 1 行も変更しません**。

**構造は変えない。** ここで足すのは、後の構造改善で振る舞いが変わっていないことを
示すためのテストだけです。

## 必須コンテキスト

- リポジトリ: $RF_REPO / Pull Request #$RF_PR
- 作業ディレクトリ: `$RF_WORKDIR`（**ここから外は読まない・書かない**）
- 対象範囲: `$RF_SCOPE`（**この範囲の外は提案しない**）
- 着手前のテスト: `$RF_BASELINE_TEST`
- 採用上限: 3 者の提案を統合したうえで、**合計 $RF_MAX_ITEMS 件までが採用**されます

## 手順書

まず次の 3 つを **順に読み**、その基準に従うこと。読まずに進めてはならない。

- `$RF_SKILL_BASE/refactoring/references/characterization-tests.md` —
  **手順書そのもの。** 現状固定テストの書き方と、`case` の語彙の出所
- `$RF_SKILL_BASE/tdd-cycle/references/testing-levels.md` —
  `level` の語彙の出所。**「上の階層へ持ち上げない」が採否の基準**
- `$RF_SKILL_BASE/tdd-cycle/references/test-quality.md` —
  **採らない提案の基準。** 実装詳細に結合したテストは提案しない

## 対象外（過去に見送った提案）

同じ提案を繰り返さないでください。

$RF_EXCLUDED

## 語彙（この値だけを使う）

`case` と `level` には**下の識別子をそのまま**書いてください。日本語の説明は
意味の対応を示すためのもので、**出力に日本語を書くと語彙外**として扱われ、
その提案は対象外になります。

### `case` に書ける値（固定する経路の種類）

$RF_VOCAB_CASES

### `level` に書ける値（どの階層で固定するか）

$RF_VOCAB_LEVELS

## やること

1. 対象範囲のコードと、既にあるテストを読む
2. **固定されていない経路**を探す。既に固定されている経路は挙げない
3. 経路ごとに `case` と `level` を決める。**分岐は単体、つなぎ目は結合、通しは
   代表シナリオだけ**を原則にする
4. その経路をどう固定するかを、順序のある手順として書く
5. テストを足す先のファイル（`path`）を決める。**`$RF_SCOPE` の中に置く**

多く出すことより、**採れる提案だけを出す**ことを優先してください。
テストが十分なら空の配列で構いません。**無理に絞り出さないでください**（採用 0 件で
このラウンドは終わり、構造改善の提案へ進みます）。

## 提出形式

結果を **`$RF_STEM-result.json`** に次の形で書いてください。

```json
{
  "items": [
    {
      "path": "tests/services/test_bar.py",
      "target": "src/foo/bar.py#BarService.handle",
      "case": "branch",
      "level": "unit",
      "rationale": "分岐 5 本のうち固定されているのは正常系 1 本だけである",
      "plan": "1. 各分岐に入る入力を作る\n2. 戻り値と保存後の状態を比較する"
    }
  ]
}
```

- `path` は**テストを足す先**のファイル（リポジトリ相対）
- `target` は**固定する入口**で、`<ファイル>#<シンボル>` の形で書く
- **`target` + `case` が同じ提案は 1 件へ統合されます。** 3 者が同じ経路を挙げる
  ため、この 2 つが重複排除の鍵になります。**他のランタイムと合意した提案ほど
  優先される**ので、独自性を狙わず素直に挙げてください
- `level` は鍵に入りません。同じ経路に複数の階層が挙がったときは**低い方**が採られます

## 守ること

- **コードもテストも変更しない。** この段階は提案だけです
- 作業ディレクトリの外を触らない
- **構造を変える提案はしない。** それは次のラウンドで扱います
- **実装詳細に結合したテストを提案しない**（内部メソッドの呼び出し回数、private な
  関数の直接呼び出し、表示文字列の完全一致）
- 既に固定されている経路を挙げない
