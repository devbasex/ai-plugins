# 書き上げた文書を章立てから組み直す

**この工程が作るのは、同じ内容を読み手が問う順に並べ直した文書と、前後の値の表である。**
内容を足すことも、書き方のルールを新しく持つこともしない。

| 作るもの | 中身 |
| --- | --- |
| 組み直した文書 | 章立てを読み手の問う順に並べ替え、長い文を分け、対比と列挙を表にしたもの |
| 前後の値の表 | 測った指標を再構成の前と後で並べたもの。目安を超えた項目は理由を添える |

## なぜ別の工程にするか

**最初に書き上がる文書は、書き手が調べた順に並んでいる。** 調査は「問題に気づく → 測る →
枠組みを当てる → 結論を出す」の順に進み、文書もその順で書かれる。読み手が最初に知りたいのは
結論であるため、並びが逆になる。

**書いた本人はこの食い違いに気づけない。** 調べた順に読むと筋が通って見える。別の工程として
切り出さないかぎり、組み直す機会が来ない。

## いつ通すか

| 場面 | 扱い |
| --- | --- |
| 工程として | 文書を作る工程の後、その文書をレビューへ出す前 |
| 明示指示として | 書き上げた文書があるとき。種類は問わない（設計文書・課題の本文・Pull Request の本文・説明文書・報告書） |

**レビューの前に置く。** 後に置くと、レビュー担当が構成の指摘と内容の指摘を同時に出すことに
なり、どちらの指摘なのかが混ざる。構成を整えてから内容を見てもらう。

## 手順

**4 段を順に通す。** 段 1 と段 4 は同じ指標を測る。

| 段 | 行うこと | 出るもの |
| --- | --- | --- |
| 1. 測る | 再構成の前の値を取る | 指標ごとの数 |
| 2. 組み直す | 章立てを読み手の問う順に並べ替える。**内容を足さない** | 並べ替えた文書 |
| 3. 整える | 長い文を分ける。対比と列挙を表にする。語を一意にする | 整えた文書 |
| 4. 測り直す | 前後の値を並べ、目安を超えた項目に理由を添える | 前後の値の表 |

### 段 1: 測る

**測る手段は対象リポジトリから探して決める。** 候補は順序ではなく一覧である。対象に実在する
ものを採る。

| 候補 |
| --- |
| そのリポジトリがすでに持つ文書の検査の仕組み（設定ファイルや継続的統合の定義から探す） |
| そのリポジトリで動く処理系を使い、その場に書く短い集計 |
| 編集に使っている道具が備える文字数・行数の表示 |
| 手で数える（結論の位置・章の数・章あたりの行数） |

**どれも見つからないときは、手で数えられる指標だけを測る。** 測れなかった指標は
「測れなかった」と段 4 の表へ残す。**測れないことを「目安に収まっている」と書かない。**

**文の区切り方と字数の数え方は言語で違う。** 対象の文書の言語に当たる
`references/lang-<言語>.md` を探して、そのファイルだけを読む。**この文書は言語の一覧を
持たない**（言語を 1 つ足すときに他のファイルを変えないため）。当たるファイルが無い言語では、
区切りの定義をその場で決めて記録へ残し、`lang-<言語>.md` を足す。

### 段 2: 組み直す

**章立てを「章立ての並び」の順に並べ替える。** 段落と文はまだ触らない。

**内容を足さない。** 組み直しと書き足しを同時に行うと、どちらが読みやすさに効いたのかが
分からなくなる。足すべき内容が見つかったら、見つけたことを控えておき、組み直した後に別の
作業として行う。

### 段 3: 整える

| 行うこと | 判断の基準 |
| --- | --- |
| 長い文を分ける | 「測る指標と目安」の平均文長と最長文 |
| 対比・列挙を表にする | 対比・列挙・分類は表、手順は順序付きの並び、原則は文章 |
| 語を一意にする | 同じ語が 2 つの対象を指していないか |

**書き方のルールはこの文書が持たない。** `markdown-writing` を呼び、そのセルフチェックを
この段で通す。同じルールを 2 か所に置くと、片方だけが更新される。

### 段 4: 測り直す

段 1 と同じ手段で測り直し、前後の値を並べる。

## 章立ての並び

**読み手が問う順に並べる。** 書き手が調べた順に並べない。

| 順 | 読み手の問い | 章の例 |
| --- | --- | --- |
| 1 | 何が決まったのか。何を作るのか | 作るもの / 結論 |
| 2 | なぜそれが要るのか | なぜ必要か |
| 3 | その判断は何に基づくのか | 枠組み / 実測 |
| 4 | 中身はどうなっているのか | 定義 / 設計 |
| 5 | どう進めるのか | 手順 |
| 6 | 何をもって終わりとするのか | 受け入れ条件 |

**調査の順序と逆になる並びがある。** 調査は 3 から始まり 1 で終わるが、文書は 1 から始める。

**この並びは章だけでなく、章の中の段落にも同じ形で当てはまる。** 文書の最初の章が最も重要で、
章の最初の段落がその章の要点を述べ、段落の最初の文がその段落の主張を述べる。読み手はどこで
読むのをやめても要点を得られる。

**当てはまらない章がある文書では、その章を並びの外へ置く。** 参照の一覧・用語表・付録が
これに当たる。**外へ置いた章は末尾へ集める。**

## 測る指標と目安

**目安であって、超えたら差し戻す値ではない。** 超える場合は理由を残す。

| 指標 | 目安 | 根拠 |
| --- | ---: | --- |
| 結論・成果物が定義される位置 | 最初の章 | 重要な順に並べる書き方（逆ピラミッド / BLUF）。実測では 1〜5 行目へ移った |
| 平均文長 | 40 字以下 | 再構成後の実測は 30.4 / 31.0 / 33.4 字 |
| 最長文 | 100 字以下 | 再構成後の実測は 73 / 75 / 105 字 |
| 章あたりの行数 | 40 行以下 | 超える章は分割の候補 |
| 対比・列挙の形 | 表 | 情報の型に合わない形で書くと、読み手が型を読み取る手間を負う |
| 1 つの語が指すもの | 文書内で 1 つ | `markdown-writing` の多義語のルール |

**目安の根拠は 3 本の文書の実測である。** 同じ内容を組み直した前後を測ったもので、
他の種類の文書での妥当性は未確認である。

### 目安を超えたときに残すもの

超えた項目ごとに、次の 3 つを段 4 の表へ書く。

| 書くもの | 例 |
| --- | --- |
| 測った値 | 最長文 138 字 |
| 超えた理由 | 分けると条件と結論の対応が読めなくなる 1 文である |
| 採らなかった直し方 | 2 文に分ける（主語が両方に要り、字数が増える） |

## 組み直しと書き足しを分ける

**内容が変わっていないことを直に確かめる手段は無い。** 章を並べ替えるついでに 1 文を足しても、
検査には何も現れない。そのため**変えた量そのものを見る**。

| 見る値 | 組み直しだけのとき | 書き足しが混ざったとき |
| --- | --- | --- |
| 行数 | 表への置き換えと章の分割の分だけ増える | それを超えて増える |
| 章の数 | 分割した分だけ増える | 新しい主題の章が増える |
| 平均文長 | 減る | 減り方が鈍る（足した文が平均へ乗る） |

**行数の増加が説明できないときは、書き足しが混ざっている。** 増えた分が「どの表への置き換え」
「どの章の分割」に対応するかを段 4 の表で言えるかどうかで見る。**言えない増加は段 2 へ戻して
外し、別の作業として行う。**

**実測では行数が 1.4 倍から 4.7 倍になった。** 増えたのは表と章の分割で、減ったのは 1 文の
長さである。**読みやすさは短さではない。**

## 報告

段 4 の表をそのまま報告に載せる。**前の値だけ、または後の値だけを載せない。**

```text
| 指標 | 前 | 後 |
| --- | ---: | ---: |
| 結論が定義される位置 | 158 行目 | 1 行目 |
| 平均文長 | 46.1 字 | 33.4 字 |
| 最長文 | 186 字 | 105 字 |
| 章の数 | 7 | 10 |
| 行数 | 188 | 263 |

目安を超えた項目: 最長文 105 字（目安 100 字）。
  理由: 条件と結論の対応が 1 文で読める形を保った。
  採らなかった直し方: 2 文に分ける（主語が両方に要り、字数が増える）。

測れなかった指標: なし
```

- **測る手段が見つからず測れなかった指標は「測れなかった」と書く。** 空欄にしない
- **段 2 で控えた「足すべき内容」は、別の作業として報告に残す。** 組み直しの中では行わない

## `markdown-writing` との境界

| Skill | 持つもの | いつ使うか |
| --- | --- | --- |
| `markdown-writing` | 何が読みやすい文書かのルール（語・表現・図表・長さ） | 書くときと、書いた後の点検 |
| この Skill | 書き上げた文書を組み直す手順（測る・並べ替える・整える・測り直す） | 書き上げた後 |

**分かれ目はルールと手順であって、書く前と後ではない。** `markdown-writing` のセルフチェックは
書いた後に走る。この Skill は段 3 でその点検を呼ぶ。

## 範囲外の課題を見つけたとき

組み直しの対象に含まれない課題（内容の誤り・別の文書の不整合）を見つけたら、**見つけたその場で
`out-of-scope` が issue にする**。組み直しの中では直さない。
