# 共通ルール

**文書形式と文書の目的に関わらず、組み直した文書が満たす決まりである。** 手順 3 で、目的別ガイドと形式別ガイドより先に当てる。

**各行は、読み手に何が成り立つか（目的）を規則として書き、手段は例として添える。** 手段だけを規則にすると、表示先や文書形式が変わったときに規則が目的を外れる。

**このファイルは決まりの本文を持たない行がある。** 「正本」の列が別のファイルを指す行は、その節を読んで当てる。同じ決まりを 2 か所に書かないためである。

| # | 共通ルール | 正本 | 当たらない目的 |
| --- | --- | --- | --- |
| K1 | 読み手が問う順に並べる。構成は目的別ガイドが決める | [SKILL.md の手順 2](../SKILL.md#手順-2-組み直す) | — |
| K2 | 内容を足さない。足すべき内容は控えて報告に残す | [SKILL.md の手順 2](../SKILL.md#手順-2-組み直す) | — |
| K3 | 別の Skill が固定した章（設計文書の承認する人が読む欄・要求のテンプレート・Pull Request の本文の形・`type-*.md` の必ず書く節・出典の節）を動かさず、消さない | 各 Skill。一覧は [related-skills.md](related-skills.md) | — |
| K4 | 読み手が抽象の説明を実物で確かめられる。例: 抽象の説明に実物の例を添え、最初の例を目的別の構成の 1 番目の章に置く | このファイル（この行） | 小説 |
| K5 | 読み手が書き手の文脈を持たずに読める。例: 説明文に内部の識別子・略語・会話でできた語・検討過程・変更履歴を持ち込まない | [markdown-writing のルール 1・3・4](../../markdown-writing/SKILL.md#重要ルール) | 小説 |
| K6 | 読み手が初めて見ても意味が通じる語で書かれている。例: 訳語や造語を作らず、読み手の業界で流通している語（カタカナ語・英語を含む）を使い、1 語 1 意味にする。key term は「鍵の語」ではなく「キーワード」。キーワードは [keyword-check.md](keyword-check.md) で確かめる | [markdown-writing のルール 2・11](../../markdown-writing/SKILL.md#重要ルール)、[keyword-check.md](keyword-check.md) | — |

| K9 | 読み手が、目安を超えた箇所とその理由を知れる。例: 目安を超えたら、測った値・理由・採らなかった直し方を残して進む | [SKILL.md の手順 4](../SKILL.md#手順-4-測り直す) | — |
| K10 | パス・URL が、表示先（Markdown・VS Code の端末・Slack・Confluence など）でリンクとして認識され、クリックで開ける。例: 直後に半角スペースを置き、全角の括弧・句読点を密着させない | [markdown-writing のルール 12](../../markdown-writing/SKILL.md#12-パスurl-は表示先でリンクとして認識される形で書く) | 小説・エッセイ（パスと URL を持たない） |

**「当たらない目的」の列は、その目的別ガイドがこの行を外すことを示す。** 外す理由は目的別ガイドの側に書く。外さない目的では、目的別ガイドの決まりと食い違っても共通ルールを外さない。

## 判断を求める文書の決まり

**判断を求める前に経緯・前提・材料を示す決まりは、共通ルールに入れない。** 判断を求めない文書（小説・手順書）には当たらないためである。決議依頼と議論用の文書の目的別ガイドが、`decision-request` を指す。
