# 運用マニュアル・手順書

**読み手がその場で手を動かす。** 読みながら操作できることが条件である。

**改訂が続く。** 実在のマニュアルは題名に更新の継続が書かれ、識別子を持つものがある。

## 必ず書く節

| 節 | 何を書くか |
| --- | --- |
| 何ができるようになるか | 手順を終えた後の状態 |
| 前提 | 権限・環境・事前に済ませておくこと |
| 手順 | **順序付きの並び。** 1 手 1 操作 |
| 確かめ方 | 各段が成功したことをどう見るか |
| うまくいかないとき | よくある失敗と、その対処 |
| 問い合わせ先 | 手順で解決しないときの窓口 |

## 書かない節

| 書かないもの | なぜ |
| --- | --- |
| 仕組みの説明 | 手を動かす人は仕組みを知らなくてよい。**必要なら別の文書へ分ける** |
| 設計の経緯 | 同上 |
| 複数のやり方の併記 | 迷わせる。**1 つに決めて書く** |

## 初版と改訂の違い

**工程は同じで、残すものが違う。**

| 版 | 追加で残すもの |
| --- | --- |
| 初版 | 識別子（対象の運用が識別子の体系を持つ場合） |
| 改訂 | **変更点**（どの手順がどう変わったか）/ **改訂の日付** / **前の版の所在** |

**古い版を消さない。** 読み手が過去の手順で作業している可能性があり、消すとどこが変わった
のかを確かめられない。

**変更点は「手順 3 の前提が変わった」のように、手順の番号で指す。**

## 読み手が最初に問うこと

**「これは自分がやる作業か、いま始められるか」。** 冒頭に「何ができるようになるか」と
「前提」を置く。

## よくある欠落

| 欠落 | 何が起きるか |
| --- | --- |
| 確かめ方が無い | 失敗したまま次の手順へ進む |
| 前提が無い | 権限が足りず途中で止まる |
| 1 手に複数の操作が入る | どこで失敗したか分からない |
| 改訂で変更点が残らない | 前の手順で作業している人が気づけない |
| 画面の名前が実物と違う | 探して止まる。**改訂のたびに実物と突き合わせる** |
