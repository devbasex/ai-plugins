# 指標定義

**何を数えるかを決める。** 値ではなく定義が本体である。

**定例報告とは別の文書である。** 報告は定義を既にあるものとして扱い、値を読んで打ち手を書く。

## 必ず書く節

| 節 | 何を書くか |
| --- | --- |
| 指標の名前 | **一意な名前**。似た指標と取り違えられない形 |
| 何を測るものか | その指標が答える問い |
| 計算式 | 分子と分母。**除外する条件も書く** |
| 取得元 | どこから取るか。`document-sources` の 4 項目と同じ粒度 |
| 更新の頻度 | いつ更新するか。**締めのタイミング** |
| 目標値の決め方 | 誰がどう決めるか。値そのものではなく決め方 |
| 見る人 | 誰がこの指標で判断するか |

**1 指標 1 行の表にする。** 指標が増えても形が変わらない。

## 書かない節

| 書かないもの | なぜ |
| --- | --- |
| 現在の値 | 定義の文書に値を書くと、値が古くなったときに定義まで信用されなくなる |
| 施策の内容 | 指標は測る道具である |
| 過去の推移 | 報告が持つ |

## 読み手が最初に問うこと

**「この数字は何を数えているのか、いつ時点のものか」。** 名前と計算式と締めの時期を
並べて置く。

## よくある欠落

| 欠落 | 何が起きるか |
| --- | --- |
| 除外の条件が無い | 同じ式でも人によって値が変わる（テスト用の行を含めるかなど） |
| 締めのタイミングが無い | 月末締めか翌月 5 日締めかで値が変わる |
| 目標値の決め方が無い | 目標が根拠なく動く |
| 似た名前の指標がある | 会議で別の指標を指したまま議論が進む |
| 取得元が「管理画面」だけ | 同じ値へ戻れない |
