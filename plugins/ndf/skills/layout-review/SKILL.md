# 体裁レビュー

**生成物を描画して、版面を見る。** ソースを読んでも分からない欠陥を拾う。

**配布（生成）の後、制作物承認の前に置く。** Markdown の時点では版面が存在しないため、
生成してはじめて描画できる。

## 内容は見ない

**内容のレビューは別の工程が済ませている。** ここで見るのは版面だけである。

| 何を | どこが見るか |
| --- | --- |
| 事実・数値・出典・表現・構成 | 実装レビュー（`cross-review`）と完了判定の事実確認 |
| 生成物と正本の内容の一致 | 配布の工程の内容照合（`document-systems` の `import.md`） |
| **版面**（文字あふれ・図の重なり・改ページ・書体） | **この Skill** |

**重なる観点を持たない。** 版面の指摘と内容の指摘が混ざると、どちらの工程へ戻すのかが
決まらない。

## 既知の失敗のリストでは足りない

**リストは生成の経路ごとに違う。** AI エージェントが組む経路では、同じソースから同じものが
出ないため、失敗を列挙できない。**だから描画して見る。**

**判定を経路に依らせないことが、この工程を置く理由である。**

## 機械で測るものと、人が見るもの

| 見方 | 項目 |
| --- | --- |
| 機械で測る | 外部への参照が残っていないか / 図の横幅 / ページ数 / 1 枚あたりの文字数 |
| **人が画像を見る** | **枠からの文字あふれ / 図の重なり / 改ページの位置 / 書体の代替** |

**機械で測るものを先に通す。** 落ちたらそこで生成へ戻す。画像を見るのはその後である。

## 描画して見る手段

**生成物の形で決まる。生成の経路では決まらない。** 何が作ったかによらず、できたものを
描画すればよい。

| 生成物の形 | 手段 |
| --- | --- |
| HTML | `playwright-kit` の `playwright-evidence`（スクリーンショット） |
| PDF | ページを画像へ変換する |
| Google スライド / ドキュメント | PDF へ書き出してから画像へ（`document-systems` の `system-gdrive.md`） |
| システムのページ | **システムごとに違う。** `system-<名前>.md` が持つ。無いシステムもある |

**手段は `document-systems` が持つ。** ここで重ねて定めない。

## 描画できない・画像を読めないときは止める

**この工程は制作物承認（取り消せない操作）の手前にある。** 判定できないまま通すと、版面を
一度も見ないまま提出へ進む。

| 状況 | どうするか |
| --- | --- |
| 描画の手段が無い | **止める。** 人が対象を開いて見る経路を提示する |
| 実行環境が画像を読めない | **止める。** 描画した画像の場所を示し、人が見て承認する |
| 描画はできたが判断が付かない | **止める。** 迷った箇所を挙げて人へ渡す |

**工程を飛ばす形は採らない。** 止めたうえで人へ渡す。

## 書体の代替は、環境を区別する

**描画の環境に書体が無いために起きる欠けは、成果物の欠陥ではない。**

```text
1. 欠けている文字を見つける
2. 配布先の環境で同じことが起きるかを確かめる
3. 起きるなら生成へ戻す。描画の環境だけなら、記録して先へ進む
```

**区別せずに生成へ戻すと、直しようのない指摘を繰り返す。**

## 差し戻し先は設計である

**版面の欠陥は、体裁設計が決めた版面か、生成の経路のどちらかに由来する。** 執筆へ戻しても
直らない。

| 原因 | 戻す先 |
| --- | --- |
| 版面の決め方（余白・文字の大きさ・1 枚あたりの情報量） | 体裁設計（`design` の `layout-<出力の形>.md`） |
| 生成の経路（変換器の設定、指示の与え方） | 配布の生成の段（`release` の `form-<出力の形>.md`） |
| 内容が多すぎて収まらない | **執筆へ戻す**（主張の数を減らす） |

## 見た結果を残す

**制作物承認の提示物になる。** 描画した画像と、見た結果を残す。

```markdown
## 体裁レビュー

- 描画の手段: <何で描画したか>
- 見た範囲: 全 12 枚 / 全 8 ページ
- 機械で測った項目: 外部への参照 0 件 / 図の横幅 上限内 / 1 枚あたりの文字数 上限内
- 人が見た結果:
  - 3 枚目: 表が枠から 1 行はみ出す → 体裁設計へ差し戻し（1 枚あたりの行数の上限を下げる）
  - 7 枚目: 図と注釈が重なる → 生成へ差し戻し
- 画像: <保存先>
```

**「問題なし」だけを書かない。** 見た範囲と手段を書く。

## 範囲外の課題を見つけたとき

版面の外の課題（内容の誤り、別の文書の不整合）に気づいたら、その場で `/ndf:out-of-scope` が
issue にする。**この工程では直さない。**

この工程に入ったら `/ndf:progress-tracking <issue番号> "体裁レビュー"` を呼ぶ（記録の手順は
その Skill が持つ）。

## 関連

- `/ndf:release` — 配布（生成と提出）。この工程はその間に入る
- `/ndf:document-systems` — 描画して見る手段（システムごと）
- `/ndf:design` — 体裁設計（`references/layout-<出力の形>.md`）
- `playwright-kit` の `playwright-evidence` — HTML のスクリーンショット
