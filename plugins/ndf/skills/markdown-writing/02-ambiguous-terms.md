# 多義語の一覧と確認手順

読み手が語自体は知っているが、**指す対象が文脈によって変わる語**をまとめる。`SKILL.md` の
ルール 2 を実行するときに読む。

この種の語は、読み手にとって知らない語ではないため読み飛ばされる。読み手は分かったつもりで
先へ進み、別の対象を思い浮かべたまま作業する。識別子や略語（ルール 1 の対象）とは、
気づかれにくさの点で異なる。

## 一覧

| 語 | 指しうる対象の例 |
| --- | --- |
| 環境 | 実行環境 / 検証用に立てた一式 / 環境変数の集合 / 開発機 |
| エージェント | 委譲先の AI / 常駐プロセス / 利用者の代理人 |
| コンテナ | コンテナ実行系の実体 / 画面の入れ物 / データ構造 |
| モデル | データの構造 / 学習済みの資産 / 画面と処理を分ける層 |
| セッション | 対話の単位 / 通信の状態 / 保存先への接続 |
| タスク | 作業項目 / 実行単位 / 非同期の処理 |
| トークン | 認証情報 / 言語モデルが数える単位 / 字句解析の単位 |
| ポリシー | 権限の規則 / 運用の方針 / 再試行の設定 |
| サービス | コンテナ定義の単位 / 業務の機能 / 常駐プロセス |
| リソース | 計算資源 / 通信で扱う対象 / 権限の対象 |
| ジョブ | 定期実行の単位 / 実行中の処理 / 印刷の単位 |
| スタック | 技術の組み合わせ / 呼び出しの履歴 / 後入れ先出しの構造 / サービスの集合 |

プロジェクト固有の語は各リポジトリで足す。**製品名・機能名と一般語が重なる語**（自社製品の
「ダッシュボード」と一般的な画面の呼び名など）が候補になる。

## 確認手順

書き終えた文書に対して実行する。同一ファイル内で **5 回以上**出現した語だけを出力する。

```bash
FILE=<対象ファイル>
for w in 環境 エージェント コンテナ モデル セッション タスク トークン ポリシー サービス リソース ジョブ スタック; do
  n=$(grep -o "$w" "$FILE" | wc -l)
  [ "$n" -ge 5 ] && echo "$w: $n 回"
done
```

改訂対象を洗い出すときは、ディレクトリ全体へ流す。

```bash
for f in $(find docs/ -name "*.md"); do
  for w in 環境 エージェント コンテナ モデル セッション タスク トークン ポリシー サービス リソース ジョブ スタック; do
    n=$(grep -o "$w" "$f" | wc -l)
    [ "$n" -ge 5 ] && echo "$f: $w:$n"
  done
done
```

## 出力された語の扱い

| 語の状態 | 対応 |
| --- | --- |
| 文書の主題を指しており、一意な語へ置き換えられる | **言い換える（既定）** |
| 業界で定着した呼び方で、言い換えると通じない | 用語表と初出の本文の両方へ定義を置く |
| 1 つの意味でしか使っておらず、指す対象が文脈から一意に決まる | そのままでよい |

言い換えたときは、コマンド名・設定のキー名・見出しも揃える。説明文だけを言い換えると、
読み手は説明と識別子を別のものとして読む。

用語表・一覧・実行結果の引用として**語そのものを挙げている箇所**は、指す対象をその場で説明して
いるため書き換えない。

**候補が出たら、まず内訳を確認する。** 数え方は部分一致であり、複合語も 1 件として数える。
「環境変数」「タスクランナー」のように、複合語になることで指す対象が一意に決まる箇所は
書き換えない。

```bash
grep -n "環境" "$FILE" | grep -v "環境変数"
```

出力は**確認の候補**であって、書き換えの確定ではない。既存の 5 種のセルフチェックと同じ扱いに
する。

## 閾値を 5 回とする根拠

このリポジトリの Markdown 130 ファイル（`docs/` と `plugins/*/skills/`）で、閾値ごとに候補と
なるファイル数を数えた。語の一覧を掲げる `SKILL.md` とこのファイルは、上の規定により対象外
なので母集団から除く。

| 閾値 | 候補ファイル | 割合 |
| --- | --- | --- |
| 1 回以上（語の有無だけで拾う） | 91 / 130 | 70% |
| 2 回以上 | 64 / 130 | 49% |
| 3 回以上 | 46 / 130 | 35% |
| **5 回以上** | **30 / 130** | **23%** |
| 8 回以上 | 18 / 130 | 14% |

語の有無だけで拾うと 7 割が候補になり、書き手は出力を読まなくなる。閾値 5 で 2 割へ絞れる。

候補 30 件には複合語による分が含まれる。`docs/specifications/runtime-plugin-container-smoke.md`
は「環境」5 回で候補になるが、うち 4 回は「環境変数」であり、内訳を確認すれば対象外と判断
できる。

**出現数が多いことは、候補から外す理由にならない。** 閾値 5 で浮かんだ語は、その文書の主題を
指す語と一致した。

```text
plugins/ndf/skills/docker-container-access/SKILL.md → 環境:16 コンテナ:9
plugins/ndf/skills/deploy/SKILL.md                  → 環境:12
plugins/ndf/skills/external-ai/SKILL.md             → モデル:8 タスク:13
```

主題を指す語ほど、読み手は自分の解釈で読み進める。**頻出する多義語こそ定義か言い換えが要る。**

短い文書（100 行未満）で候補が出ないときは、閾値を 3 へ下げる。長い文書で候補が多すぎるときは
8 へ上げる。閾値は語の一覧と同じく、リポジトリごとに調整してよい。
