# README の役割と、書くもの・書かないもの

**`README.md` は入口である。** そのディレクトリが何であり、どう始めるかを示し、詳細はリンクで
渡す。規約と手順は持たない。

## 3 つの役割と、名前を使う条件

「README」という名前は、中身の違う 3 つの文書に使われることがある。**同じ名前が 3 つの役割を
指すと、開いてみるまで何が書いてあるか分からない。**

| 役割 | 何であるか | 名前 |
| --- | --- | --- |
| 入口 | そのディレクトリが何であり、どう始めるかを示す | `README.md` を使う |
| 索引 | そのディレクトリに何があるかを案内する | `README.md` を使う |
| 規約 | 書き方・作り方の基準を定める。検査が突き合わせる先になることもある | **`README.md` を使わない** |

**規約に `README.md` の名前を使わない。** 規約は読み手が「基準を探しに来る」文書であり、
入口とは読まれ方が違う。中身を表す名前を付けるか、規約を置く場所（`docs/` など）へ移す。

**索引は `README.md` のままでよい。** そのディレクトリに何があるかを示すもので、入口と
読まれ方が同じである。

## 入口に書くものと書かないもの

| 書く | 書かない |
| --- | --- |
| 何であるか（1 段落） | 規約（判断の基準） |
| 何ができるか | 手順（作り方・変え方） |
| どう始めるか（導入と最初の 1 手） | 他の文書と重なる説明 |
| どこへ行けばよいか（リンク） | 版ごとの変更点 |

**入口が長いほど、最初の一歩が遠くなる。** 開いた人が最初に必要とするのは「何ができるか」と
「入れ方」であり、その後ろに規約や手順が続くと、必要な情報へ届くまでの距離が伸びる。

**版ごとの変更点は変更履歴の文書が持つ。** 入口へ置くと、版を重ねるたびに入口が伸びる。

## 読み手ごとの置き場所

**置き場所は読み手で決める。** 同じ主題でも、誰が読むかによって置く先が変わる。

| 読み手 | 知りたいこと | 置き場所 |
| --- | --- | --- |
| 使う人 | 何ができるか / 入れ方 / 最初の一歩 / どこへ行けばよいか | `README.md` |
| 変える人 | 規約・手順・判断の基準 | 開発の規約を持つ文書 / `docs/` |
| AI エージェント | 工程と判断の基準 | エージェント向けの規約の文書 / `skills/` |

## 主題が重なったときは正本を決める

**同じ主題が 2 つの文書にあると、片方だけが古くなる。** どちらが正かを読み手が判断できない。

見つけたときは、**消すのではなく正本を決めて残りをリンクに置き換える**。正本は「その主題を
最も詳しく持つ文書」ではなく、**その主題を読みに来る読み手が最初に開く文書**で決める。

| 主題の性質 | 正本にする文書 |
| --- | --- |
| 判断の基準（何を選ぶか） | 開発の規約を持つ文書 |
| 手順（どう作るか・どう変えるか） | `docs/` の開発向けの文書 |
| 使い方（どう始めるか） | `README.md` |

## 分量との関係

**分量の基準（501 行以上で分割）だけでは遅い。** 役割が定まっていないと、上限に当たった
ときに削る対象が「古い順」で決まり、役割から見て残すべき節が落ちることがある。

**役割の境界は機械では決まらない。** 分量は検査できるが、その節が入口に置くべきものか
どうかは読んで判断する。書くときと改訂するときに、この文書の表へ照らす。
