# 見積の段階を付ける

手順 2B で、課題ごとに 4 つの列（UBV・TC・RR/OE・Size）の段階と根拠の 1 行を付ける。順位・切り出しの境界・
前倒しと後ろ倒しの判定は、手順 2C の `upkeep.py rank` が段階から決める。**LLM は段階を付けるだけで、式を当てはめない。**

## 例: 4 件に段階を付ける

open の課題 4 件（直近のマイルストーン M1 に #1422・#1382、次の M2 に #1289、未設定に #1399）に付けた段階である。

| 課題 | 本文の要点 | UBV（区分） | TC | RR/OE | Size | 実害の観測 |
| --- | --- | --- | --- | --- | --- | --- |
| #1422 | `merge-when-green` がマージに成功しても exit 1 を返す | 3（表示） | 5 | 2 | 1 | あり |
| #1382 | 状態の表示に 1 項目が欠ける | 3（表示） | 1 | 2 | 2 | なし |
| #1289 | 承認ゲート 1 の問い直しが繰り返される。子 #772・#785 がこの課題を前提にする | 5（機能） | 3 | 5 | 3 | あり |
| #1399 | 取り消した変更を含むコミットが origin へ出た | 13（全体） | 8 | 8 | 5 | あり |

- **#1422 の UBV は 3 である。** マージの結果は正しく、終了コードだけが誤る。区分は「表示」で帯は 2〜3
- **#1399 の UBV は 13 である。** 取り消した変更が公開されるのは安全機構の欠落で、区分は「全体」、帯は 13〜20
- **#1289 の RR/OE は LLM の 5 のままでよい。** 子 2 件がこの課題に依存しているため、`rank` が被依存の数から
  8 へ上げる（表では `8（被依存）`）

`rank --capacity 3` の結果は、#1399 と #1289 が M1 への前倒し（どちらも自動）、#1382 が M2 への後ろ倒し（承認）で、
M1 の順位は #1399 → #1289 → #1422 → #1382 になる。

## 尺度

段階は宣言の尺度（既定は 1, 2, 3, 5, 8, 13, 20）の中から選ぶ。尺度に無い値・根拠の 1 行が空の段階は、`rank` が
順位から外して返す（終了コード 20）。**確信度は掛けない。** 根拠が本文に無い列は、段階を付けたうえで `needs_detail`
に列の名前を並べる（本文の書き足しが要る目印。順位には効かない）。

## 列ごとの段階の意味

| 列 | 何を比べるか | 付け方 |
| --- | --- | --- |
| UBV（実害の大きさ） | 直さずに置くと起きる害の大きさ | 実害の目安の区分で帯を選び、帯の中の値をアンカーと比べて決める |
| TC（時間的重要度） | 着手を遅らせるほど害や費用が増えるか | 期限・再発の頻度・同じ箇所の変更の多さ。期限も再発も無ければ 1 |
| RR/OE（リスク低減・他の課題を解放） | 直すと何が止まらなくなるか、何が着手できるようになるか | 止まる経路を塞ぐか、前提になる課題か。解放する数は `rank` が数えるため、LLM は本文の記述だけで付ける |
| Size（大きさ） | AI エージェントが実施したときの費用 | 下の「大きさは AI の実施の費用で付ける」 |

### 実害の目安（UBV の帯）

| 区分 | 当てはまるもの | 帯（既定） |
| --- | --- | --- |
| 全体 | 全体の停止・データの損失・安全機構の欠落 | 13〜20 |
| 機能 | 一部の機能の誤動作・手戻り | 5〜8 |
| 表示 | 表示や終了コードの誤り（結果は正しい） | 2〜3 |
| なし | 上のどれにも当たらない（体裁・好み） | 1 |

**区分を先に選び、帯の中の値だけをアンカーと比べて決める。** 課題どうしの相対だけで付けると、全体の停止と表示の
誤りが隣の段階に並ぶ。見積の入力の `ubv.impact` に区分を書くと、`rank` が段階が帯に入っているかを確かめる。
区分と帯は宣言の `harm_guide` で変えられる。

### 退避策の状態

退避策・回避策は、**実際に止まるのを防いだ記録（働いた後に止まらなかった日時とログ）があるときだけ** UBV と RR/OE を
下げる根拠になる。「一部にある」「効いたか分からない」では下げない。

| 状態（`mitigation`） | 意味 | UBV |
| --- | --- | --- |
| `防いでいる` | 働いた後に止まらなかった記録がある | 区分を 1 つだけ下げた帯の値も受け付ける（最下位の区分は下げられない） |
| `部分的` | 退避策はあるが、止まった記録が残っている | 区分の帯のまま |
| `無い` | 退避策が無い（省略したときの値） | 区分の帯のまま |

RR/OE を退避策で下げたかはスクリプトが判定できないため、下げたときは根拠の 1 行に防いだ記録を書く。

### 大きさは AI の実施の費用で付ける

**人の工数で見積らない。** 課題を実施するのは AI エージェントで、人が実施するときの大きさの感覚とは違う。

| 見るもの | 取り場所 |
| --- | --- |
| 所要時間 | 閉じた課題の supervise の記録（`~/.local/state/ndf/sv/*/**/progress.jsonl` と `report.md` の秒） |
| LLM の費用 | 同じ記録の費用 |
| 変更量 | 閉じた課題の Pull Request の差分の行数 |

- **部品が揃っていて組み合わせるだけの課題は、人の感覚で大きくても段階が下がりうる**（例: 起動・監視・統計の部品が
  揃った課題を、新しい層の新設の 13 でなく 8 とした）
- **人の判断を待つ時間（承認ゲート・`needs-decision`）は費用に数えない。** 判断を待つ課題は `waiting_decision: true`
  にする。順位の値は変わらず、表と報告に「判断待ち」の印が付き、判断を先に求める材料になる
- 根拠の 1 行には、比べた閉じた課題の番号と実績を書く

## アンカーの選び方

アンカーは、段階を比べる基準の課題である。**段階ごとに 1〜2 件、閉じた課題から選ぶ。**

- 大きさのアンカーは、supervise の記録と Pull Request の差分の実績がある課題から選ぶ
- UBV のアンカーは、実害の観測（再現の記録・起きた日時）が本文にある課題から選ぶ
- 課題番号はリポジトリに固有のため、Skill には書かず、リポジトリの宣言（`.ndf/backlog.json` の `anchors`）に置く。
  宣言にアンカーが無いときは、上の段階の意味の文だけで付ける

## 材料の取り場所

手順 2A は段階を付けずに材料を控える。手順 2B は控えた材料を列ごとに並べて段階を付ける。

| 材料 | 取り場所 | 使う列 |
| --- | --- | --- |
| 害の範囲と実害の観測 | 本文の再現手順・起きた日時とログ・関連する課題の記録 | UBV・`observed_harm` |
| 期限と再発 | 本文の期限・同じ現象の起票・同じ箇所の変更の回数（`git log --oneline -- <パス> \| wc -l`） | TC |
| 止まる経路と前提の関係 | 本文の「#N の後」「#N を前提に」・ルートコーズの親として指す番号 | RR/OE・`depends_on` |
| 退避策が防いだ記録 | 退避策が働いた後の記録 | `mitigation` |
| 実施の費用 | 閉じた課題の supervise の記録と差分の行数 | Size |
| 人の判断待ち | `needs-decision` のラベル・本文が判断を求めている箇所 | `waiting_decision` |

依存は本文の記述を抽出して `depends_on` に書くだけでよい。サブイシューとマイルストーンの説明の
`### 並列の組（見込み）` の依存は `rank` が読み、順序はスクリプトが決める。

## 見積の入力

手順 2B が書き、`rank --scores` で渡す。この回に付けた課題だけでよい（付けていない課題は記録か前回の表から採る）。

```json
{"version": 1,
 "milestones": ["01 直近の主題", "02 次の主題"],
 "issues": [{"number": 1399, "digest": "<candidates の値>",
             "ubv": {"step": 13, "why": "取り消した変更が origin へ出た（安全機構の欠落）", "impact": "全体"},
             "tc": {"step": 8, "why": "..."}, "rr_oe": {"step": 8, "why": "..."},
             "size": {"step": 5, "why": "<閉じた課題の番号>（差分 <行数>・<所要>・<費用>）と同じ程度"},
             "mitigation": "無い", "observed_harm": true, "needs_detail": [], "depends_on": [1237],
             "waiting_decision": false}]}
```

| 項目 | 必須 | 意味 |
| --- | --- | --- |
| `milestones` | いいえ | 着手の順（先頭が直近）。無ければ名前の先頭の連番の昇順。説明が別の順序を書くときに渡す |
| `issues[].digest` | はい | `candidates` の課題の要約値。次の `candidates` が本文の変化を見る |
| `ubv` / `tc` / `rr_oe` / `size` | はい | `step`（尺度の値）と `why`（根拠の 1 行）。`ubv` は `impact`（実害の目安の区分）も持つ |
| `mitigation` | いいえ | `防いでいる` / `部分的` / `無い`（既定） |
| `observed_harm` | いいえ | 本文に実害の観測があるか（既定 `false`）。自動の前倒しの条件になる |
| `needs_detail` | いいえ | 本文の書き足しが要る列 |
| `depends_on` | いいえ | 本文から抽出した依存先の番号 |
| `waiting_decision` | いいえ | 人の判断待ちか（既定 `false`） |

## 宣言の書き方

リポジトリごとの値は `.ndf/backlog.json` に置く（書き換えは利用者の承認が要る）。引数が宣言に勝ち、どちらにも無ければ
一般的な WSJF の既定値で動く。

```json
{"version": 1, "scale": [1, 2, 3, 5, 8, 13, 20], "margin_steps": 1, "auto_threshold": 8, "capacity": 13,
 "dependents_steps": [[0, 1], [1, 5], [2, 8], [3, 13], [5, 20]], "label_floor": {"<重要度のラベル>": 8},
 "size_exponent": 0.3, "large_slot_ratio": 0.5, "large_min_size": 13,
 "harm_guide": {"全体": [13, 20], "機能": [5, 8], "表示": [2, 3], "なし": [1, 1]},
 "anchors": {"ubv": {"13": [{"number": 1, "summary": "<閉じた課題の要約>"}]}}}
```

| キー | 意味 | 既定 | 引数 |
| --- | --- | --- | --- |
| `scale` | 尺度 | 1, 2, 3, 5, 8, 13, 20 | `--scale` |
| `margin_steps` | 余白（前倒しの候補にするために境界の課題を上回るべき尺度の段階の数） | 1 | `--margin-steps` |
| `auto_threshold` | 自動の閾値（前倒しを承認なしに反映するために UBV か RR/OE が届くべき段階） | 8 | `--auto-threshold` |
| `capacity` | 容量（1 つのスプリントへ切り出す Size の和の上限） | 無し（境界と候補を出さない） | `--capacity` |
| `dependents_steps` | 被依存の数（解放する数）→ RR/OE の段階の対応表 | 0→1, 1→5, 2→8, 3→13, 5→20 | `--dependents-steps` |
| `label_floor` | ラベル → UBV の下限 | 無し（下限は効かない） | `--label-floor` |
| `size_exponent` | 大きさの指数 α（1 で一般的な WSJF、0 で遅延コストだけ） | 0.3 | `--size-exponent` |
| `large_slot_ratio` | 大きい課題の枠の割合 | 0.5 | `--large-slot-ratio` |
| `large_min_size` | 大きい課題の閾値 | 尺度の上から 2 番目 | `--large-min-size` |
| `harm_guide` | 実害の目安（区分 → 帯） | 上の表 | — |
| `anchors` | 列 → 段階 → アンカーの課題 | 無し | — |

## 式と判定の置き場

式・同点の扱い・依存の順序・前倒しの判定は `scripts/upkeep_rank.py` だけが持つ。ここには写さない。

| 何か | 関数 |
| --- | --- |
| 実効の段階・遅延コスト・順位の値 | `score` |
| 同点の扱い | `row_key` |
| 依存の合成とマイルストーンの中の順序 | `merge_edges`・`topo_order` |
| 大きい課題の枠と切り出しの境界 | `large_slot`・`boundary` |
| 前倒しの閾値 | `Config.threshold`（`upkeep_rank_config.py`） |
| 前倒し・後ろ倒しの候補と扱い | `_candidates` |
| 見積の検証（尺度・根拠・実害の目安の帯・退避策） | `validate_estimate`（`upkeep_rank_config.py`） |
| `### 順位` の表の描画と前回との差分 | `render_rank_table`・`rank_changes`（`upkeep_rank_table.py`） |
