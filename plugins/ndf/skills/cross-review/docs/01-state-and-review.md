# 01: 状態ファイルとレビューのラウンド

`SKILL.md` の「実行」が打つ `ndf cross-review run` が、1 回の起動で何をするかを持つ。**ラウンドの手順は
`run` の中にあり、メインが手順ごとにコマンドを打つことはない。** 修正と終わり方は
[02-fix-and-rotation.md](02-fix-and-rotation.md) にある。

## 始め

`run` はラウンドへ入る前に次を行う。どれかで止まれば、結果 JSON の `status` が `stopped` になる。

| 順 | すること | 止まったとき（`cause.kind`） |
| ---: | --- | --- |
| 1 | `--worktree`（省けば打った場所）が git に登録された worktree かを確かめ、メインディレクトリ（1 回だけ求める）の `.ndf/runtimes.json` の `allowed` と `.ndf/review.json` の重点（`version: 1` の `focus`）を同期の前に読む（`--worktree` がメインディレクトリそのものでも、同期が持ち込む PR の設定を実行者の設定にしない）。相手役は `allowed` の中から選ぶ。修正担当（claude）も `allowed` に要る | 登録が無ければ `precondition`（`ndf cross-review check-worktree <worktree>` と同じ確かめ）。`invalid`（形の誤り・`allowed` の外の名指し・選べる相手役が無い）。修正担当が `allowed` の外か、メインディレクトリを決められず `allowed` を読めなければ、どの担当も起動する前に `precondition`（設定が無いときと分ける）。`.ndf/review.json` は `invalid`（`version: 2`・`3` のプロファイル・形の誤り） |
| 2 | `--state-dir`（リンクをたどった先）が `--worktree` の外かを確かめてから、worktree を origin の head ブランチの先頭へ合わせる。自分のコミットは載せ直す | 保存先が worktree の中なら同期の前に `precondition`。衝突すれば `precondition`（衝突したファイルを挙げる） |
| 3 | PR の head の `.ndf/review.json` は指示に使わない（PR の作成者が指摘の採否や直し方を誘導できる）。PR の head の Git のツリーの種別と blob の ID を手順 1 で読んだ実行者の設定と比べ（作業場所のファイルを開かず、リンクをたどらず、中身を設定として読まない）、違えば `warnings` に載せる。その変更は差分としてレビューする | — |
| 4 | 前の起動が残した修正の結果ファイルを、修正の記録の無い最後のラウンドへ読み込む | `work_stopped`・`invalid` |
| 5 | 前の起動が送れなかった修正のコミットがあれば送る（修正担当がコミットを報告していなければ、`unsent_fix` で修正担当が作ったと確かめられるコミットだけを送る。修正担当が結果を書かずに残したコミットは、ここでは送らず、レビューした後に送る） | `work_stopped` |
| 6 | PR のスレッドと PR コメントを 1 回だけ読み、前の実行が残した未解決の自分の指摘（下の「残った指摘を引き継ぐ」）をジャーナルへ入れる | 止まらない（読めなければ `warnings`） |
| 7 | 最後のラウンドが `converged` で、その head が今の HEAD、比較基点（`--base` と HEAD の merge-base の SHA）が今と同じで、今回の相手役が全員そのラウンドを読んでいて、そのラウンドの重点とプロジェクト MVV が今と同じで、承認済みの MVV があれば根拠の記述を確かめ終えていて、未解決の指摘も無ければ、相手役を起動せずに前回の結果を返す。インラインのレビューコメントとレビュー本文は読まない。記録のコメントは、今の PR へ今と同じ状態の記録を公開できていれば（`report_published`）書き直さず、公開できていなければ書き直す | — |
| 8 | 担当すべてを起動できるか（学習の設定のバックアップ）を確かめる | `precondition` |

状態の保存先は `--state-dir` で、状態ファイル（`cross-review-pr<元の番号>-state.json`）・ラウンドごとの差分と
相手役の出力（`round<n>-<相手役>.*`）・修正の結果ファイル・終わったときの要約（`summary.json`）をそこへ置く。
保存先はレビューする worktree の外に置く（中にあると、同期が PR から持ち込んだ状態ファイルやシンボリックリンクを実行者の
状態として読み書きする）。プランから打つときの保存先は `<プランの実行の保存先>/cross-review` である。

## 1 ラウンド

1 ラウンドは次の順に進む。ラウンドは `--max-rounds`（既定 3）まで、1 回の起動の中で続けて回す。

1. **範囲を決める**（下の「範囲」）。`--base...HEAD` の差分をラウンドの差分のファイルへ書く。変わった Markdown が
   `contracts/limits/cross-review.design-doc-lines.json`（1,000 行）を超えれば `warnings` に知らせる（止めない）
2. **相手役を並べて起動する。** 相手役は `--reviewer`（繰り返して複数）で名指しし、省けばランタイムの表の既定の席から
   読むだけの起動を持つ者を、修正担当（claude）を除いて並べる。相手役へは下の「指摘の基準」と、PR に既にある
   コメント（下の「既存のコメント」）を渡す。相手役は読むだけで、最後の行に
   `{"findings": [{"text": "<指摘>", "severity": "<重要度>", "impact": "<critical・major のとき、利用者の経路で何が起きるか 1 文 か 空>", "path": "<ファイル か 空>", "line": <行 か null>, "section": "<パス#見出し か 空>"}]}`
   を 1 行出す
3. **指摘をジャーナルへ入れる。** 同じ趣旨の指摘はキーで重ねない。理由を添えて見送った指摘は、出し直されても扱わない。
   直した指摘が戻ってきたら未解決へ戻す。同じ指摘がより重い重要度で出し直されたら重い方を残す
4. **判定する**（下の「判定」）。修正が要れば修正担当を起動する（[02](02-fix-and-rotation.md)）

**差分を読めなかった相手役は、同じラウンドで 1 度だけ起動し直す。** それでも読めなければ、そのラウンドは収束の側へ数えない。

| 起動し直した後 | 終わり方 | 結果 |
| --- | --- | --- |
| 全員が読めた | 判定へ進む | — |
| 一部が読めない | `incomplete_reviewers`（読めた相手役の指摘はジャーナルに残す） | `status: stopped`・`work_stopped`。相手役ごとの理由と直し方は `warnings` |
| 誰も読めない | ラウンドを状態ファイルに残さない | `status: stopped`・`precondition`。相手役ごとの理由と直し方は `cause.detail` |

起動し直した相手役の出力は `round<n>-<相手役>-retry.*` にある。別のアカウントや別の相手役へは振り替えない。

## 指摘の基準

相手役は次の基準のどれかに当たる指摘だけを、重要度（`contracts/domains/severities.json` の `critical`・`major`・`minor`・`nit`）
つきで書く。基準の文の SSOT は `contracts/data/review-criteria.json` で、修正担当へも同じ基準を渡す（[02](02-fix-and-rotation.md)）。

| 番号 | 基準 |
| --- | --- |
| 1 | 利用者が普通に使う経路で、誤動作する・止まる・データを壊す |
| 2 | 秘密・認証認可・利用者のデータ・戻せない操作に触れる |
| 3 | このプロジェクトのレビューの重点に当たる（`.ndf/review.json` の `focus` があるときだけ） |
| 4 | 設計の文書で、実装する人が違うものを作ってしまう食い違い |
| 5 | プロジェクト MVV の Mission・Vision・Value に反する。または、必ず人の承認が要る操作（MVV の `P<番号>`・共通原則の `C<番号>`）に当たる（マージ先のブランチに承認済みの MVV があるときだけ） |

- 基準 5 は、起動の始めに保存した MVV の本文と共通原則のスナップショットのパスを渡して読ませる。PR の head の `.ndf/mvv.md` は使わない。
  相手役は反する項目を指摘の `mvv` に 1 つ書く。`mvv` が MVV に無い項目なら、基準 5 でない普通の指摘として扱い、`warnings` に載せる
- 対応のアクションの無いもの（観察・感想・コードの引用だけ・良い点）は書かせない。見つけたものは 1 ラウンドで出し切らせる
- `.ndf/review.json` は `{"version": 1, "focus": ["<重点>", ...]}` だけを読む。`version: 2`・`3` のプロファイル（`profile`・`profiles`）は
  読まず、書かれていれば `invalid` で止まる（黙って無視しない）
- `critical`・`major` には、利用者の経路で何が起きるかの 1 文（`impact`）を書かせる。基準 2 の指摘では、何が誰に漏れるか・
  何が戻せなくなるか・誰がどの操作を権限の外で実行できるか・どのデータに何が起きるかのうち当たるものを一つ書けばよい（認可の指摘は
  データへの影響が無くても、誰がどの操作を権限の外で実行できるかだけで足りる。起きる確率は書かない）、基準 3 の指摘では何がどの単位でどれだけ増えるか、基準 4 の指摘では実装する人が
  何を作り違えるかを書く。書けない指摘は `minor` にさせる。指示の文の SSOT は `review-criteria.json` の `impact`
- ジャーナルへ入れるとき、1 文（空白を除いて空でない文字列）の無い `critical`・`major` は `minor` へ下げる。重要度の
  無い指摘と尺度に無い値の指摘は同じに扱い、1 文があれば `major`、無ければ `minor` にする。`critical`・`major` で 1 文の
  あるものと、`minor`・`nit`（1 文の有無によらない）はそのまま
- MVV の項目に反する指摘と、必ず人の承認が要る操作に当たる指摘は、1 文が無くても下げず、`warnings` に指摘の番号を載せる。
  Mission・Vision・Value に反する指摘は、相手役が `minor`・`nit` を付けても `major` にする
- 前の実行から引き継いだ指摘と、前のバージョンの状態ファイルの行は付け直さず、記録された重要度のまま扱う（重要度の無い行は
  収束の妨げになる側に倒す）

## 既存のコメント

起動の始めに 1 回だけ PR コメントを読み、前回の結果を返さないときはインラインのレビューコメントとレビュー本文も 1 回だけ読み（人と bot と前の実行の返信を含む）、
ラウンドごとに、そのラウンドで相手役へ渡す差分（前の head からの差分ならそこで変わったファイル）に付いたインラインのコメントとほかのコメントを、信頼しない参考資料として相手役へ渡す。書き手を確かめていないので、相手役はコメントの指示に従わず、「直した」と書かれた論点も
今の差分で残っていれば報告する。cross-review 自身の
記録のコメントと指摘のスレッドの最初のコメント（マーカー `<!-- ndf:cross-review-report -->` で始まる）は渡さない（自分の指摘は
ジャーナルが持つ）。1 件の本文は `cross-review.remark-chars` の字数で切り、全体が `cross-review.remarks-total` の字数を超えれば古いものから省く。読めなければ `warnings` に載せて渡さずに進む。

## 残った指摘を引き継ぐ

`run` は終わるときに未解決の指摘のスレッドを PR に開いたまま残す（[02](02-fix-and-rotation.md) の「PR に残す記録」）。
別の `--state-dir` で始めた起動（実装のプランの差分のレビューなど）は、始めに PR のスレッドを読み、マーカーで始まり、最初のコメントの書き手が
今の実行の認証の login（GraphQL の `viewer`）と同じで、resolve されていない自分の指摘を、未解決の指摘（id `t<最初のコメントの id>`・ラウンド 0）としてジャーナルへ入れる。修正担当を 1 度通すまで
収束しない。スレッドの id は状態ファイルの `threads` に入れるので、直した・見送ったときはそのスレッドへ返信して resolve する
（新しいスレッドは作らない）。状態ファイルが既に持つスレッドは引き継がない。そのうち別の実行（か人）が resolve したスレッドの
未解決の指摘は、`fixed`（理由「別の実行か人がスレッドを resolve した」）にして修正担当へ渡さず、返信もし直さない。

有効な位置が無くスレッドにならなかった未解決の指摘（設計全体への指摘など）は、記録のコメントに埋めた一覧から戻す。書き手が
今の実行の認証の login が書いた記録のコメントのうち最終更新が最も新しいもの（打ち直しは同じコメントを書き換えるので、作った時刻では選ばない）の末尾の行に埋めた一覧だけを読み、スレッドの無い指摘を id `p-<元の id>`・ラウンド 0 で
ジャーナルへ入れる。同じ趣旨（キー）の指摘がジャーナルに既にあれば入れず、MVV の判定だけを重ねる（必ず人の承認が要る操作に当たると
初めて分かった指摘は、閉じていても未解決へ戻す）。その記録のコメントを今の保存先が書いていれば、状態ファイルが持つ指摘は戻さない
（コメントの本文は伏せてあり、本文では同じ指摘と分からない）。

PR が足した MVV の根拠の記述の誤り（NDF が機械で確かめて作った指摘。`by` が `ndf`）は、スレッドが resolve されていても、
この一覧から戻す。直ったかを決めるのは、次の確かめだけである。

指摘がプロジェクト MVV に反するという判定（反する項目・固定する前の重さ・必ず人の承認が要る操作の番号・判定したときの MVV の識別子）も、
この一覧が持つ。スレッドから引き継ぐ指摘には、同じスレッドの判定を重ねる。戻すのは今と同じ MVV での判定だけで、別の MVV での判定は
外して `mvv_history` に残し、固定した重さを固定する前へ戻す。

## 範囲

1 ラウンド目は全差分（`--base...HEAD`）を渡す。2 ラウンド目からは、相手役の全員が読めた最後のラウンド（`incomplete_reviewers` の
ラウンドを飛ばす）の head からの差分へ絞る。そのラウンドが無い・その比較基点（`--base` と HEAD の merge-base の SHA）が今回と違う・
そのラウンドを読んでいない相手役が今回いる・そのラウンドの重点（`focus`）かプロジェクト MVV（`mvv`）が今回と違えば全差分を渡す。設計の PR（`--purpose` が設計のプランのテンプレートの purpose）は、変わった Markdown のセクションが詳細レビューを通るまで
全差分を渡す。詳細レビューを通ったセクションは状態ファイルの `reviewed_sections` に残り、MVV が変われば通し直す。範囲だけを読むときは
`ndf cross-review review-scope <worktree> --purpose <P> --base <B> --state-dir <D> --pr <N> [--reviewer <R> ...]` を打つ（読むだけ）。
`--reviewer` は `run` へ渡すものと同じにする（省けば `run` と同じ既定の相手役で決める）。このコマンドは GitHub にもリモートにも
問い合わせず、取得済みのベースブランチの MVV を読む。MVV か変わったセクションを手元のオブジェクトだけで
確かめられなければ全差分を返し、理由を `warnings` に載せる。

## 判定

| ラウンドの状態 | 判定 | 次 |
| --- | --- | --- |
| 収束の妨げになる未解決の指摘（重さが `severities.json` の `blocking` の `critical`・`major` の行と、前の実行から引き継いだ行・前のバージョンの状態ファイルの行のうち重要度の無いもの。必ず人の承認が要る操作に当たる指摘は数えない）も、まだ決めていない足すべき内容（`--findings`）も無い | `converged` | 終わる。`minor`・`nit` の指摘は修正担当へ渡さず、ジャーナルと記録のコメントの表に「軽い」で残る |
| 前々ラウンドの指摘が前ラウンドで消えて戻った | `oscillating` | 終わる |
| それ以外 | 修正が要る | 修正担当を起動し、送れたら次のラウンドへ |

上限まで回って修正が要るまま残れば `max_rounds` で終わる。終わり方と結果 JSON の対応は [02](02-fix-and-rotation.md) の「終わり方」にある。

## 状態ファイル

状態ファイルは `{"pr": 元の番号, "current_pr": 今の番号, "target_repo": "<所有者>/<リポジトリ>", "rounds": [...],
"reviewed_sections": [...], "findings": [...]}` の形で、ラウンドごとに書き足す。

| キー | 中身 |
| --- | --- |
| `rounds[]` | `round`・`head`（レビューした head）・`base`（比較基点。`--base` と HEAD の merge-base の SHA）・`reviewers`（そのラウンドの相手役）・`focus`（そのラウンドで渡した重点）・`mvv`（レビューに使ったプロジェクト MVV。`id` は承認の状態・バージョン・本文と共通原則の sha256 から作る値、`mvv_branch` は MVV を読んだブランチ）・`mvv_checked`（その head の MVV の根拠の記述を確かめ終えたか。承認済みの MVV が無ければ真）・`scope`・`verdict`・`fix`（修正の記録: `commit`・`reported`・`fixed`・送れたら `pushed`） |
| `findings[]` | ジャーナル。指摘ごとの `id`（`r<ラウンド>-<通し番号>`。引き継いだ指摘は `t<コメントの id>`、記録のコメントから戻した指摘は `p-<元の id>`、NDF が見つけた MVV の根拠の記述の誤りは `r<ラウンド>-n<通し番号>`）・`key`・`text`・`section`・`round`・`outcome`（`fixed` / `deferred` / `unresolved`）・`reason`・`by`。相手役が返したときだけ `path`・`line`。相手役が返した指摘の行は `severity`（ジャーナルへ入れるときに下げた後の値）・`raised_severity`（相手役が付けた元の重要度。尺度に無い・無いときは null）と、1 文があれば `impact` を持つ。引き継いだ指摘の行は記録された `severity` だけを持つ。MVV に反する指摘の行は `mvv`（反する項目）・`judged_mvv`（判定したときの MVV）と、重さを固定したなら `mvv_pinned`・`unpinned_severity`、必ず人の承認が要る操作に当たれば `redline`・`redline_items` も持つ |
| `reviewed_sections` | 詳細レビューを通ったセクション（`<パス>#<見出し>`） |
| `reviewed_mvv` | `reviewed_sections` のセクションを読んだときの `mvv` の `id` |
| `unsent_fix` | 修正担当が作り、PR に届いていないコミットの範囲（`base`・`head`）。次の起動の同期で載せ直すと、載せ直した後の範囲へ移る。範囲の後に別のコミットが足されていれば消す。修正担当が新しいコミットを作らなかったときは、この範囲だけを送る |
| `unsent_citations` | 最後に残った手元のコミットが PR に届いていないときだけ、そのコミット（`head`）で見つけた MVV の根拠の記述の誤り（`errors`。確かめられなければ null と `detail` の原因）。PR の記録と結果 JSON には載せず、件数だけを判定に使う。状態ファイルは所有者だけが読める権限で置く |
| `mvv_record_error` | MVV の記録を書けなかった原因（保存先のパスを含む）。書けたら消す。PR の記録と結果 JSON の注意には、書けなかったことだけを載せる。前に載せた失敗の注意と今回の注意が違う起動は、指摘が同じでも PR の記録を書き直す |
| `threads` | 指摘の番号ごとに、PR に作ったスレッドの最初のコメントの id（`comment`）と、返信・resolve を済ませたか（`replied`・`resolved`）。打ち直しても二重に書かない（#3939） |
| `report_comment` | PR へ書いた記録のコメントの URL。次からは同じコメントを書き換える（#3939） |
| `report_published` | 記録のコメントへ公開できた状態（PR の番号・終わり方・ラウンド・指摘・スレッドと、コメントに載せた MVV の記録の失敗の注意）の要約。スレッドを書き切れなかったときは残さない |
| `report_pr` | `threads`・`report_comment`・`report_published` が属する PR の番号。今の番号と違えば（巻き直しの後）、その 3 つを `report_earlier` の旧 PR の番号の下へ移し、今の PR へ記録とスレッドを書き直す（旧 PR のコメントを書き換えず、旧スレッドの id を使わない） |
| `report_earlier` | 巻き直しの前の PR の番号ごとの `threads`・`report_comment`・`report_published` |

状態ファイルが JSON の辞書として読めなければ、既定へ倒さずに止まる。PR を巻き直したときの番号の引き方は
[02](02-fix-and-rotation.md) の「PR を巻き直す」にある。

## ラウンドを足す

**同じコマンドを打ち直すと、状態ファイルの最後のラウンドの続きから回す。** 前のラウンドは消さず、次の番号のラウンドから
`--max-rounds` の数だけ回す。差分を足した PR にもう一度回すときも、同じコマンドを打ち直すだけである。状態ファイルを
開かない・`mv` しない・書き換えない。最後のラウンドが `converged` で head も `--base` も MVV も変わっていなければ、相手役を起動せずに
前回の結果を返す（`process` に「前回の結果（converged）を返した」と載る）。

## 部分の命令

`run` が中で行う確かめを、1 つだけ打つ命令である。止まった後に原因を確かめるときに使う。引数は
[commands.md](../../../docs/contracts/commands.md) の `ndf cross-review` にある。

| 命令 | すること |
| --- | --- |
| `ndf cross-review state-file --state-dir <D> --pr <N>` | 状態ファイルと修正の結果ファイルのパス（読むだけ） |
| `ndf cross-review fix-gate --state-dir <D> --pr <N>` | 次のラウンドへ進める前に、修正の記録が要るか（結果ファイルが残っていれば `next` に `merge-fix` を返す） |
| `ndf cross-review review-scope <worktree> ...` | 次のラウンドの範囲（読むだけ） |
| `ndf cross-review check-worktree <worktree>` | worktree の管理情報の確かめ |
| `ndf cross-review target-repo [--repo R]` | レビューの対象のリポジトリ（`--repo`・状態ファイル・origin の順で決める） |
| `ndf cross-review head --pr <N>` | PR の head |
