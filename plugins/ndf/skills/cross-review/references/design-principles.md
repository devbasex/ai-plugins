# 設計方針

長丁場のため、**メイン（収束ループを打っている層）の文脈の消費を最小にする。** メインが打つのは `ndf cross-review run` の
1 行で、読むのは最後の行の結果 JSON だけである。3 層で通すときにメインに当たるのは設計と検査のフェーズのプラン（または
supervisor）で、人間と対話しているセッション（conductor）は当たらない（`development-workflow` の `references/agent-layers.md`）。

| 観点 | 方針 |
|---|---|
| 相手役 | **読むだけで、ファイルを変えない。** 指摘は最後の行の 1 行の JSON で返し、差分と出力は `--state-dir` のファイルに置く。メインの応答には載らない |
| 修正 | **修正担当（claude）を `run` が起動する。** メインは修正コードを書かない。担当はコミットまでで、送るのは `run` である |
| 送る | 拒まれたら origin をマージして 1 回だけ送り直す。送れなければ、直したとした指摘を未解決へ戻す（PR に届いていない修正を直したと数えない） |
| 指摘のジャーナル | 同じ趣旨の指摘はキーで重ねない。理由を添えて見送った指摘は出し直されても扱わない。直した指摘が戻れば未解決へ戻す |
| 終わり方 | 未解決の指摘も足すべき内容も無くなれば収束。上限・振動・誤りで終わっても、欠けが 0 件なら `ok` で次の工程へ進み、理由を `decisions` に残す |
| 状態の永続化 | `--state-dir` の状態ファイルへラウンドごとに書く。修正の結果は状態ファイルへ書いてから結果ファイルを移すため、途中で止まっても同じコマンドで続けられる |
| 巻き直し | `run` は PR を巻き直さない。状態ファイルは元の番号のまま残り、今の番号は `state-file --current` で記録する |
