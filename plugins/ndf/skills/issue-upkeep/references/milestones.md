# マイルストーンを決める

**マイルストーンは「いつ着手するか」を表す。** 決める軸は 2 つある。

| 軸 | 何を決めるか | 材料の在り処 |
| --- | --- | --- |
| **重要度** | **どのくらい先のまとまりか** | ラベルの説明 |
| 主題 | どの課題と一緒に直すか | マイルストーンの説明 |

**重要度が先に効く。** 主題だけで決めると、実害のある課題が「合うまとまりが無い」という
理由で後回しになる。主題は、重要度が決めた範囲の中でどれと束ねるかを決める。

**重要度は先に見直す。** 起票の時点の値のまま振り分けると、着手の時期が古い値で決まる
（見直しの基準は `SKILL.md` の「重要度と問いの形を変えるときの基準」）。

**マイルストーンを使っていないリポジトリでは、この文書ごと飛ばす。**

## 設定されていない課題を割り当てる

**起票の直後は設定されていなくてよい。** `out-of-scope` は見つけたその場で起票するため、
一覧の全体を見る立場に無い。どのまとまりで直すかは、他の課題と並べて初めて決まる。

| 重要度 | 入れる先 | 主題の合うものが無いとき |
| --- | --- | --- |
| **高い**（実害・安全機構の欠落） | 直近のまとまりのうち主題の合うもの | **直近のまとまりへ、主題によらず入れる** |
| 中くらい（保守性・設計一貫性） | 主題の合うもの | 末尾に新しく作る（下記） |
| 低い（余力があれば） | 主題の合うもの | 未設定のまま残す |

**直近のまとまりは、open のマイルストーンのうち版数が最も小さいものである。** 主題の外から
入れたときは、そのマイルストーンの説明へ課題の番号を足す。主題が複数に当てはまるときは
**要判断**へ倒す。

## 既に設定されているものを振り直す

**重要度とマイルストーンの位置が食い違っていれば振り直す。** 重要度は棚卸のたびに見直される
ため、設定した時点と現在で食い違う。

| 状況 | 対応 |
| --- | --- |
| 重要度が高いのに、直近でないまとまりにある | **直近へ移す** |
| 重要度が低いのに、直近のまとまりにある | **要判断。** 後ろへ移すと着手が遅れる |
| 重要度と位置が合っている | 何もしない |

**早める方向だけを自動で反映する。** 早める判断は実害の記述が根拠になる。遅らせる判断は
「今やらなくてよい」という価値の判断であり、それは「やらない」の 2 つの必要条件で決める
（[no-work.md](no-work.md)）。後ろへ動かして着手を先送りする形は、判断の根拠を残さない。

## 新しく作るとき

**末尾に置く。** 既存のマイルストーンの順序を動かさないため、版数は現在の最大の次にする。
既存の間へ差し込むことは、他の課題の着手の順序を早めるか遅らせるかの判断にあたるため、
**要判断**へ倒す。

| 決めること | 決め方 |
| --- | --- |
| 版数 | 既存の最大の次。`v10.9.0` があれば `v10.10.0` |
| 説明 | **残った課題群から導く。** 既存の説明と同じ形にし、主題と対象の課題番号を書く |
| 入れる課題 | その主題を持つものだけ。残りは未設定のまま残す |

**1 件しか残らないときは作らない。** マイルストーンは着手のまとまりを表すため、1 件のために
作ると、まとまりとしての意味を持たない。未設定のまま残し、次の棚卸で他の課題と合わさるのを
待つ。

## 順序を直すとき

**依存の記述が版数の順序と食い違うときだけ直す。** 説明が「A の後に着手する」と書いているのに
A が後の版にあるなら、どちらかが古い。**依存の記述が無いものの順序は変えない。** 早く出したい
という判断が入るため、返す。

## 報告へ残す

**未設定の件数と理由を残す。** 残った件数と理由（主題が合わず重要度も低い / 1 件しか残らない /
複数に当てはまる）が、次の棚卸の材料になる。
