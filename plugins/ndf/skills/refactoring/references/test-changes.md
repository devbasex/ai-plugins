# テストをどこまで変えてよいか

**「テストを変えない」を絶対の条件にしない。** テストが構造に依存している場合、構造を変え
ればテストも変わる。そこで固執すると、実装に歪みが入るか、構造が形だけ分かれる。

**実測がある。** 3706 行の 1 ファイルを 13 モジュールへ分けたとき、既存のテストを変えない
条件で進めた結果、入口が全モジュールを再エクスポートし、**外から見た名前空間は 1 つの
まま**になった。差し替えを届かせるための仕掛け（`__setattr__` による書き戻し）も、テストを
変えないためだけに入った。

**「テストが変わらない」は「振る舞いが変わっていない」の証拠であると同時に、「構造が改善
していない」の証拠でもある。**

## 変更を 3 つに分ける

| 変更 | リファクタリングとして | 見分け方 |
| --- | --- | --- |
| **期待する振る舞いを変える** | **してはいけない** | 同じ入力に対する期待出力が変わる |
| **読み込みの経路を変える** | **してよい** | 何を取り込むか、何を差し替えるかだけが変わる |
| **内部の詳細への依存を減らす** | **推奨する** | 差し替えの対象が公開 API へ寄る |

**1 つ目だけが振る舞いの変更である。** 残る 2 つは、構造が変われば当然変わるものである。

## 判定は 3 段で行う

**機械で判定できないものを、そのまま人へ回さない。**

| 段 | 誰が判定するか | 何を見るか |
| --- | --- | --- |
| 1 | 機械 | 接頭辞を伏せた `assert` 行の集合が、前後で一致するか |
| 2 | AI エージェント | 段 1 で判定できない差分について、同じ入力に対する期待出力が変わったか |
| 3 | 人 | AI が「判定できない」と答えたものだけ |

### 段 1: `assert` 行の集合を突き合わせる

```bash
norm() {
  grep -hE '^\s*assert |^\s+assert ' "$@" \
    | sed -E 's/^[[:space:]]+//; s/\b(<モジュール名を並べる>)\./MOD./g' \
    | sort
}
git archive <起点> <テストのパス> | tar -x -C <退避先>
diff <(norm <退避先>/<テストのパス>/*.py) <(norm <テストのパス>/*.py)
```

**接頭辞を伏せた `assert` 行の集合が一致すれば、期待値は変わっていない。**

**差分から追加と削除の対を数える形は採らない。** 同じ内容の `assert` 行が複数の箇所に
あると対応が取れず、変わっていない行が残って見える（実測で 2 行が残った）。

### 段 1 で判定できない形

**この手は振る舞い不変の証明にならない。** 期待値が `assert` の行の外にあると、変えても
集合は一致する。

```python
assert price(order) == (
    270,          # ← 300 へ変えても `assert` 行は変わらない
    "JPY",
)
```

| 形 | 集合の一致で判定できるか |
| --- | --- |
| 期待値が `assert` の行にある | **できる** |
| 複数行にまたがる式 | **できない** |
| パラメータ化の値 | **できない** |
| フィクスチャが返す値 | **できない** |

### 段 2: AI エージェントへ渡す

**渡すのは差分と、上の 3 分類である。** 答えは 3 択にする。

| 答え | 意味 |
| --- | --- |
| 期待する振る舞いを変えた | 落とす |
| 読み込みの経路を変えただけ | 通す |
| **判定できない** | 段 3 へ回す |

**2 択にしない。** 迷ったものが片方へ倒れる。

### 段 3: 人が見る

**AI が「判定できない」と答えたものだけが残る。** 通ったものとして扱わない。

## 現状固定テストは、この 3 分類の外にある

**現状固定テストであることは、期待出力を変えてよい理由にならない。** 置き換えを 2 つに
分ける。

| 置き換え | 同じ入力に対する期待出力 | 扱い |
| --- | --- | --- |
| 根拠を「いまの出力」から**仕様**へ置き換える | **変わらない** | 役目を終えた置き換え。印と理由を残す |
| **期待出力そのものを変える** | **変わる** | **振る舞いの変更である。別の変更に分ける** |

**不具合を含む現状を固定した場合も同じである。** `SKILL.md` は「不具合として別に扱う
（固定テストにコメントで印を付け、修正は別の変更で行う）」と定めている。**印は、修正を
同じ変更へ混ぜてよいという意味ではない。**

**印の無いテストを現状固定として扱わない。** 印の付け方は
[characterization-tests.md](characterization-tests.md) にある。

## 段階を分ける

**1 回で終わらせようとすると、振る舞いの固定と構造の改善のどちらかが犠牲になる。**

| 段階 | 何をするか | 何が保証されるか | テスト |
| --- | --- | --- | --- |
| 1 | 移送（再エクスポートなどで振る舞いを固定する） | **振る舞いが変わっていない** | 変えない |
| 2 | テストを新しい構造へ寄せる | **境界がテストで検証される** | 変える（実装は変えない） |
| 3 | 移送のための仕掛けを外す | **公開 API が確定する** | 変えない |

**各段階で保証するものが違うため、混ぜられない。** 段階 2 と 3 を同じ差分で行うと、
テストが落ちたときに原因が実装の変更か読み込みの経路の変更かを分けられない。

**段階は開発の工程ではない。** 1 つの構造改善の中の進め方であり、工程表の行にはしない。

## テストの側の兆候

**テストが構造を固定していることは、それ自体が手を付ける対象である。** 兆候として
[vocabulary.md](vocabulary.md) に 3 つ置いてある。

| 識別子 | 日本語の名前 | 主な手法 |
| --- | --- | --- |
| `test_coupled_to_internals` | テストが内部の詳細に依存している | 依存の向きを整える |
| `test_bypasses_module_boundary` | テストが 1 つの入口から全部を引く | 責務の移動 |
| `mock_targets_implementation_detail` | モックの対象が実装の詳細 | 依存の向きを整える |

説明は [code-smells.md](code-smells.md) にある。
