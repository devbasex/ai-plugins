# 画面

**画面を追加・変更する変更でだけ読む。**

## 画面の仕様を表と図で書く

画面要素の構造・レイアウト・振る舞いを記述する標準は策定の途中にある。**確定した標準が無い
ため、当面は表と図で書く。**

| 項目 | 書くこと |
| --- | --- |
| 画面の一覧 | 画面の名前と、それぞれが何をする場所か |
| 遷移 | どの操作でどこへ移るか（図 1 枚） |
| 状態 | 初期・読み込み中・空・エラー・権限なしのそれぞれで何を出すか |
| 入力規則 | 各入力の必須・型・上限・満たさないときの表示 |
| 権限 | 誰に何が見えるか。見えない要素は隠すのか無効にするのか |

**状態を省かない。** 正常に表示できたときだけを書くと、空とエラーの扱いが実装の時点で決まる。

## 見た目の値

色・寸法・字面などの値には記述の標準がある（Design Tokens Format Module）。JSON 形式で、
値・型・説明の 3 項目を持つ。設計ツール・生成ツール・各実装先の間で持ち運べる。

| 対象 | 扱い |
| --- | --- |
| 値を持つリポジトリ | 記述の標準に従って書き、そこから各実装先の形式へ変換する |
| 値を持たないリポジトリ | 求めない。画面の一覧と遷移だけを書く |

## 設計文書に書くこと

| 項目 | 内容 |
| --- | --- |
| 画面の一覧と遷移 | 上の表と図 |
| 変わる画面 | 追加・変更・削除する画面と、その理由 |
| 見た目の値 | 値の記述を置く場所（持つリポジトリのみ） |
| 検査の手段 | 値の記述が読み込めることを、どのコマンドで確かめるか |

## 部品の扱い

画面部品そのものの記述に定まった標準は無い。部品ごとの表示と操作を機械で実行して確かめる
仕組み（Storybook など）を持つリポジトリでは、設計文書から部品の一覧を指す。

**この Skill は部品の作り方を定めない。** 画面の一覧・遷移・状態・入力規則までを設計の対象と
する。
