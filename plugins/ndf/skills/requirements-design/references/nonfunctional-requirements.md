# 非機能の条件

**業務処理が何をするかとは別に、どう動いていなければならないかを書く。** 条件を書かないと、
実装が終わった後に基準が作られる。

軸は 6 大項目である。可用性・性能拡張性・運用保守性・移行性・セキュリティ・システム環境で、
IPA「非機能要求グレード」の大項目に対応する。

## 該当しない項目は書かない

**すべての変更へ 6 項目を必須にしない。** 変更が触らない項目へ条件を求めると、空欄か
「特になし」で埋まり、**書き忘れと意図的な省略を読み手が区別できなくなる**。

該当は変更の性質から決める。

| 大項目 | 条件を書く場面 |
| --- | --- |
| 可用性 | 常時稼働する経路を追加・変更する。停止を伴う作業が入る |
| 性能・拡張性 | 応答時間・処理量・データ量が変わる。利用者数の想定が変わる |
| 運用・保守性 | 監視・記録・バックアップの対象が変わる。障害時の手順が変わる |
| 移行性 | 既存データを移す。旧版と新版が並走する |
| セキュリティ | 認証認可・通信の保護・秘密情報の扱いが変わる |
| システム環境 | 動作環境・依存する実行基盤・資源の制約が変わる |

**1 つも当たらない変更がある。** 文言の修正や書式の変更がこれにあたる。そのときは非機能の節を
作らない。

## 大項目ごとの書き方

**どの項目も、観測できる量か、観測できる手順で書く。** 「安定して動く」は条件ではない。

### 可用性

| 種類 | 書き方 | 例 |
| --- | --- | --- |
| 運転時間 | いつからいつまで動くか | 平日 8 時から 22 時まで。休止は日曜 2 時から 4 時 |
| 復旧の時間 | 停止からどれだけで戻すか | 障害の検知から 30 分以内に代替の経路へ切り替わる |
| 停止の許容 | 止まってよい時間と、止まったときの見え方 | 月あたり 43 分まで。停止中は 503 と再開の見込み時刻を返す |
| 冗長化 | 何を二重に持つか | 記録の保存先を 2 つの区画へ複製する |

### 性能・拡張性

| 種類 | 書き方 | 例 |
| --- | --- | --- |
| 性能 | 対象操作・データ量・上限値 | 1 万件で一覧の初期表示が 2 秒以内 |
| 容量 | 上限と超えたときの挙動 | 添付は 10 MB まで。超過は 413 と上限値を返す |
| 処理量 | 単位時間あたりの件数 | 1 分あたり 600 件の取り込みを取りこぼさない |
| 増加への備え | どこまで増えることを見込むか | 利用者が 10 倍になっても、追加するのは処理の台数だけである |

**性能と容量は、これまで 4 種として書いてきたものである。** 書き方と例は変わらない。

### 運用・保守性

| 種類 | 書き方 | 例 |
| --- | --- | --- |
| 記録 | 何を残し、何を残さないか | 失敗時に操作者 ID と対象 ID を残す。トークンは残さない |
| 監視 | 何を見て、どこへ知らせるか | 取り込みの失敗が 5 分で 3 件を超えたら運用の連絡先へ通知する |
| 保存 | いつまで残すか | 記録は 90 日保持し、以後は削除する |
| 切り分け | 障害のときに何をたどるか | 1 つの要求を、記録の中の識別子で入口から出口までたどれる |

**記録は、これまで 4 種として書いてきたものである。** 書き方と例は変わらない。

### 移行性

| 種類 | 書き方 | 例 |
| --- | --- | --- |
| 移す対象 | 何を移すか。移さないものは何か | 過去 2 年の注文を移す。それ以前は移さず、参照用の控えに残す |
| 順序 | どの順で移すか | 読み取りを先に新しい側へ向け、書き込みは 1 週間の並走の後に切り替える |
| 切り戻し | 戻せるか。戻す手順 | 切り替えから 24 時間は旧側を残し、設定 1 つで戻せる |
| 並走 | 旧版と新版が同時に動く期間の扱い | 並走中は両方へ書き、差分を日次で突き合わせる |

### セキュリティ

| 種類 | 書き方 | 例 |
| --- | --- | --- |
| 権限 | 誰が何をできるか、できないとどうなるか | 一般利用者は他人の下書きを取得できず 403 になる |
| 認証 | 何をもって本人とするか | 期限切れのトークンでは 401 を返し、再発行の経路を案内する |
| 保護 | 通信と保存で何を守るか | 個人を特定できる項目は保存の時点で暗号化する |
| 秘密情報 | どこに置き、どう渡すか | 認証情報は環境変数で渡し、記録にも応答にも出さない |

**権限は、これまで 4 種として書いてきたものである。** 書き方と例は変わらない。

### システム環境

| 種類 | 書き方 | 例 |
| --- | --- | --- |
| 動作環境 | どこで動くか | Python 3.11 以上。利用者の端末は求めない |
| 依存 | 何の上で動くか | 取り込みは対象の API の版 2 に依存する |
| 資源 | 使ってよい量 | 1 つの処理あたり記憶領域 512 MB 以内 |

## 書き方の共通の決まり

- **上限を書いたら、超えたときの挙動も書く。** 上限だけでは、超えたときに何が起きるかが
  実装の判断になる
- **数字を書くときは、測る条件を添える。** 「2 秒以内」は、何件のデータで、どの操作を
  測るのかが決まってはじめて判定できる
- **満たさないことを条件にしてよい。** 「個人情報が記録へ出ない」は退行を防ぐ条件になる

## 現行 4 種からの移り先

これまで性能・容量・権限・記録の 4 種で書いてきたものは、**書き方と例をそのままに、親を
付け替える**。既にある仕様文書を書き直す必要はない。

| これまでの種類 | 移り先の大項目 |
| --- | --- |
| 性能 | 性能・拡張性 |
| 容量 | 性能・拡張性 |
| 権限 | セキュリティ |
| 記録 | 運用・保守性 |

## 設計側との対応

**要求側で書いた項目だけが、設計側で実現方式を求められる。** 書かなかった項目について、
設計が構成を決める根拠は無い。実現方式の書き方は `design` の
`references/nonfunctional.md` が持つ。
