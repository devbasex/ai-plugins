# リポジトリ自身

**生成物を git のリポジトリへ置く形である。** HTML / PDF / Markdown が対象になる。

**このリポジトリに前例が 1 つある。** `docs/presentations/` は `.md` から `build.sh` で
`.pdf` と `.html` を生成し、両方をコミットしている。**ただし標準ではなく 1 つの実例である**
（README が「発表日時点の記録で、以後の構成変更には追随しない」と明記している）。

## 認証

**要らない。** git の書き込み権限だけで足りる。

## 取り込みの手段と取れないもの

**取り込みを省けるのは、正本と生成物を同じ内容として直接比較できるときだけである。** 正本が
Markdown で生成物も Markdown なら、両方が同じリポジトリにあるため差分はそのまま git で読める。

**HTML / PDF を生成する形では省けない。** git の差分は PDF の本文を読めず、HTML は体裁の
記述が本文に混ざる。**生成で変わった数値や欠落した本文が、制作物承認の前に表へ出ない。**
同じリポジトリに置いてあることは、内容を比べられることを意味しない。

| 生成物 | 内容照合の手段 |
| --- | --- |
| Markdown | git の差分をそのまま読む。取り込みは要らない |
| HTML | 本文を抽出して正規化し、正本と突き合わせる |
| PDF | テキストを抽出して正規化し、正本と突き合わせる |

**抽出したものは正本と別のファイルへ置く。** 正規化の規則と格納先は
[import.md](import.md) にある（用途 1）。

**取れないものは版面である。** 枠からの文字あふれ・図の重なり・改ページの位置は、抽出した
本文には残らない。そちらは描画して見る（`layout-review`）。

## 投稿の手段

`git add` と `git push`。**Pull Request の工程に乗る。**

## 本文の表現

Markdown / HTML / PDF。**正本の Markdown はそのまま置ける。**

## 版の扱い

**git の履歴が版を持つ。** 前の版へ戻せる。5 つのシステムのうち、**取り消しが確実に効く
唯一の形である**（読んだ人には効かないという限界は同じ）。

## 図の扱い

生成の経路が決める。**GitHub で読ませるなら Mermaid をそのまま書ける。** 版面を持つ出力
（PDF / スライド）へ変換する経路では、描画できる形式を生成の側へ確かめる。

## 描画して見る手段

| 生成物 | 手段 |
| --- | --- |
| HTML | `playwright-kit` の `playwright-evidence`（スクリーンショット） |
| PDF | ページを画像へ変換する |
| Markdown | **版面を持たないため、体裁レビューの対象にならない** |

## 既知の失敗

| 事象 | 対処 |
| --- | --- |
| 生成物だけをコミットして正本を置き忘れる | 正本と生成物を同じコミットに載せる |
| 画像を生成物だけコミットする | 図の元（`.mmd` など）も一緒に置く |
