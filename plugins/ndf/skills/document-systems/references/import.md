# 外部の文書を取り込む

**取り込むのは、内容のレビューを git の差分に載せるためである。** テキストが取れれば、事実・
数値・出典・表現・構成のレビューは差分で行える。

**版面は取れない。** 枠からの文字あふれ・図の重なり・改ページの位置は、取り込みでは分からない。
そちらは生成物を描画して見る（`layout-review`）。**この 2 つは重なる観点を持たない。**

## 3 つの用途

**用途が違うと、取り込みの向きと時期が変わる。**

| # | 用途 | 向き | いつ |
| --- | --- | --- | --- |
| 1 | 生成物の検証 | 生成した外部の文書 → リポジトリ | **配布（生成）の後、制作物承認の前** |
| 2 | 既存文書の取り込み | 既にある外部の文書 → 正本の Markdown | Markdown を正本にする最初の 1 回 |
| 3 | 外部で編集されたものの追従 | 外部で直された文書 → リポジトリ | 変更に気づいたとき |

**用途 1 は工程の一部である。** 生成した結果と正本を突き合わせ、数値の変化や本文の欠落を
見つける。**非決定的な生成（AI エージェントが組む経路）では、描画を見るだけでは表に出ない。**

**用途 2 が無いと、既にある文書がこのワークフローに乗らない。** 実在する文書はすべて外部の
システムにあり、新規の文書にしか使えないなら改訂が対象外になる。

**用途 3 は人が気づいたときに実行する。** 更新の時刻を比べて自動で検知する形は採らない。
**取り込みが決定的であることを確かめる前に検知を回すと、変更が無くても差分が出続ける。**

## 正規化

**同じ対象を 2 回取り込んだら、同じ結果になること。** 差分が毎回出ると、レビューできない。

| 直すもの | なぜ |
| --- | --- |
| 区切りを復元する | スライドの区切りが失われ、全枚数が 1 続きになる |
| 文の単位で改行する | 改行が失われ、全体がほぼ 1 行になる。1 行の巨大な差分はレビューできない |
| ページ番号の連結を外す | 本文の末尾へページ番号が連結する（`… Confidential2` のような形） |
| 空白の連なりを 1 つにする | 取得のたびに揺れる |

**取り込むたびに変わる値を残さない。** 取得の日時をファイルの中へ書くと、内容が同じでも
毎回差分が出る。**取得の日時は出典の節（`document-sources` が扱う）へ書く。**

### 正規化しない選び方もある

**以前投稿した内容をそのまま控え、次に取得した内容と比べる形**が Confluence の既存実装に
ある。正規化を挟まないため、変換の揺れが差分に出ない。

| 選び方 | 向く場面 |
| --- | --- |
| 正規化して Markdown へ寄せる | **正本と突き合わせるとき**（用途 1・用途 2） |
| 投稿した内容をそのまま控えて比べる | **外部側の変化だけを見たいとき**（用途 3） |

**どちらを採るかはシステムごとに決める。** 取れる形式が違うためである（Notion は Markdown が
返り、Confluence は XHTML が返る）。

## 格納先

**正本の Markdown と、取り込んだ Markdown を同じファイルにしない。** どちらが正本か分からなく
なる。

```text
docs/documents/<文書名>/
├── index.md          ← 正本。執筆はここへ行う
└── imported/
    └── <提出先の名前>.md   ← 取り込んだもの。差分を読むためだけに置く
```

- **取り込んだファイルを編集しない。** 直すのは正本の側である
- 用途 1 では、取り込んだ結果と正本を比べ、**不一致なら正本を直さず生成をやり直す**
  （正本が誤っていたと分かったときだけ執筆へ戻る）

## 画像の扱い

**取り込みでは図そのものを取らない。参照だけを残す。** 内容のレビューは差分に載ればよく、
図は体裁レビューが描画して見る。**別に取得する手段を作らない**（この Skill は取得の手段を
持たない、という決めと食い違う）。

## システムごとに取れるものが違う

**取れるものと取れないものは各システムの参照が持つ。** ここでは繰り返さない。

| システム | 参照 |
| --- | --- |
| Google Drive | [system-gdrive.md](system-gdrive.md) |
| Notion | [system-notion.md](system-notion.md) |
| Confluence | [system-confluence.md](system-confluence.md) |
| SharePoint | [system-sharepoint.md](system-sharepoint.md) |
| リポジトリ自身 | [system-repo.md](system-repo.md)（生成物が Markdown のときだけ要らない） |

## 継続的統合で動かすか

**動かさない。** 取り込みは工程の中で人が起動する。

**理由は認証である。** 5 つのシステムのうち 4 つが利用者の資格情報を要り、継続的統合で
動かすには秘密情報を渡すことになる。**取り込みは提出の前後にしか要らない**ため、渡す理由が
釣り合わない。

**MCP の経路は対話セッションでしか動かない。** 継続的統合で動かすなら、スクリプトの経路と
その認証を先に用意する。

## 往復で保たれるもの

**外部 → Markdown → 生成 → 外部の 1 周は、まだ実測していない。**

| 段階 | 実測 |
| --- | --- |
| 外部 → Markdown | **動く**（Google スライドと Notion で確認） |
| Markdown → 生成 | **手段がまだ無い。** 生成の経路は `release` の `form-<出力の形>.md` が決める |
| 生成 → 外部 | 同上 |

**1 周を実測してから移行の手順を書く。** 保たれるものと失われるものの一覧が無いまま用途 2 を
回すと、既存の文書を Markdown へ移した時点で内容が減る。

**実測できるまでは、用途 2 の適用を 1 件で止める。** 1 件目の往復で失われたものを記録して
から、残りへ広げる。
