# SharePoint

**このリポジトリでは実行して確かめていない。** 別のリポジトリにある実装の知識から書いた。
手順どおりに動かないときは、実測した結果でこのファイルを直す。

## 認証

| 項目 | 内容 |
| --- | --- |
| 方式 | クライアントの資格情報による認可（client credentials flow） |
| 出所 | `.ndf/document.json` の `auth` が指す環境変数、または秘密情報の管理系の識別子 |

**秘密の値をコードへ書かない。** 実行時に管理系から取得する。

**テナントと組織の識別子はリポジトリごとに違う。** 宣言が持つ。この Skill には書かない。

## 取り込みの手段と取れないもの

**Microsoft Graph を使う。** 到達までに 4 段（サイト → ドライブ → 子の一覧 → 中身）ある。

| 対象 | 手段 |
| --- | --- |
| ファイルの中身 | `GET /v1.0/drives/{id}/root:/{path}:/content` |

**ブラウザの共有 URL をそのまま取得しても、認証を通らないため中身は取れない。**
必ず Graph の経路を使う。

**取れないもの。**

| 取れないもの | 影響 |
| --- | --- |
| 版面 | **体裁は取れない。** 描画して見る |
| Office 形式の内部構造をそのまま Markdown へ | 変換が要る |

## 投稿の手段

同じ Graph の経路で書き込む（`PUT` で中身を置く）。

## 本文の表現

ファイルそのもの（`.docx` / `.xlsx` / `.pdf` など）である。**Markdown をそのまま置いても、
読み手はファイルとして開く。** 変換した結果を上げる。

**表計算（`.xlsx`）は zip である。** 標準ライブラリだけで読める。追加の依存は要らない。

## 版の扱い

**SharePoint は版を保持する。** 前の版へ戻せる。**「その状態を見た人」は戻らない。**

## 図の扱い

ファイルの形式が決める。**Office 形式では画像として貼る。**

## 描画して見る手段

**未確認である。** 取得したファイルを PDF へ変換してからページを画像にする案がある。
手段が無いときの倒し方は `layout-review` が持つ。

## 既知の失敗

| 事象 | 対処 |
| --- | --- |
| 共有 URL を取得しても認証で弾かれる | Graph の経路を使う |
| パスに空白・矢印・隅付き括弧があると失敗する | **そのまま符号化する。** 手で取り除かない |
| 表計算を読むのに追加の依存を入れてしまう | zip として標準ライブラリで読む |
