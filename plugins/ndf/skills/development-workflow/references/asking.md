# 人へ問うか、AI が決めるか（問い合わせの区分）

この文書が、`AskUserQuestion` で人へ問ってよい場面と、問いに付ける区分の正本である。承認資料の中身は `approval-request.md`、判断を求めるときの材料の示し方は `decision-request` の Skill が持つ。どちらも区分の表を写さずにここを指す。

## 例

設計の途中で「ライブラリ A と B のどちらを使うか」を問おうとした。これは下の「区分」のどれにも当たらない。問わずに、根拠を集めて推奨の案を選び、次のコマンドで記録して進む。

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/ask.py" decide \
  --question "ライブラリ A と B のどちらを使うか" --answer "A" --reason "既存の依存に入っていて、B は保守が止まっている"
```

設計 Pull Request のマージの承認は設計承認ゲートである。`AskUserQuestion` の入力に `"metadata": {"source": "ndf-gate:1"}` を付けて問う。

## 原則: AI が自分で決める

人へ回すのは、AI が決めてよい範囲の外にある問いだけにする。**迷った・情報が足りない・好みが分かれるは、人へ回す理由にならない。** その場合は根拠を集めて推奨の案を選び、理由を記録して進む。

AI が決める例:

- 設計の選択・Tool とライブラリの選択・命名・ファイルの置き場
- テストの方針・範囲・順序、実装の順序、並列の数
- 範囲外の課題の扱い（`out-of-scope` で起票して進む）、課題を分ける・まとめる
- レビューの指摘を直すか退けるか（理由を記録する）
- 曖昧な依頼の解釈（最も筋の通る解釈を選び、選んだ理由を記録する）

## 区分

`AskUserQuestion` の `metadata.source` に、問いの区分を 1 つ付ける。区分の無い問いは hook が止める。

| 区分（`metadata.source`） | 当たるもの | 宣言で外せるか |
| --- | --- | --- |
| `ndf-gate:1` | 設計承認ゲート（設計 Pull Request のマージ。設計承認ゲートの委任の承認を含む） | 外せない |
| `ndf-gate:2` | リリース承認ゲート（本番系へ届く操作・制作物承認） | 外せない |
| `ndf-ask:redline:<番号>` | 共通原則の C1〜C8・プロジェクトの P・スプリントの R に当たる操作の承認。`<番号>` は `C4`・`P1`・`R2` の形 | 外せない |
| `ndf-ask:cost` | お金が出ていく: 有料の資源の起動・有料の外部 API・購入・プランの変更。`cost.threshold_usd` 以下は AI が決める | 外せる |
| `ndf-ask:irreversible` | 取り消せない操作のうちレッドラインに当たらないもの: 外部の人への送信（メール・チャット・Issue での言及）・外部の系のデータの削除・公開範囲を広げる操作 | 外せる |
| `ndf-ask:human-action` | 人にしかできない操作: 対話のログイン・二要素認証・権限の付与・秘密の発行と登録 | 外せる |
| `ndf-ask:legal` | 規約・契約・ライセンス・個人情報の扱いへの同意 | 外せる |
| `ndf-ask:<名前>` | プロジェクトが `.ndf/ask.json` の `extra` に書いた区分 | — |

**レッドラインに当たる操作は、`irreversible`・`human-action` より先に `ndf-ask:redline:<番号>` を使う。** 例: 強制 push や `-D` の削除は `redline:C4`、秘密の登録は `redline:C1`、他のリポジトリへの起票は `redline:C5`、`.ndf/` の書き換えは `redline:C7`。

1 つの問いに複数の区分が当たるときは、表の上にあるものを付ける。どれに当たるかが中身で変わる手順では、区分ごとに場合を分け、どれにも当たらなければ AI が決める。

## 止められたとき

hook が問いを止めると、理由に止めた理由と記録の手段（`ask.py decide --ref <id>`）が載る。まず、問いが上の表のどれかに当たるかを見直す。当たるのに区分を付け忘れていた（特にレッドラインの操作の承認）ときは、当たる区分を付けて出し直す。当たらないのに区分を付けて出し直さない。当たらなければ自分で決め、載っているコマンドで記録して続ける。

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/ask.py" decide --ref <id> --answer "<選んだ答え>" --reason "<理由>"
```

手順が「AI が決める」とした場面（hook に止められる前に決めた場面）は、`--ref` の代わりに `--question` で問いを書く。

## 並列の計画のレーン

並列の計画（[parallel.md](parallel.md)）の下で区分つきの問いを出すのはオーガナイザーだけである。レーン（`NDF_RELAY_NAME` が計画のレーンにある）
と一時レーン（作業ディレクトリの役割のファイルが `helper`）が、hook の通す問い（承認ゲート・レッドライン・許された区分）を出すと、
hook が `parallel.py request-ask` でオーガナイザーへ送り、問いを止めて保留の手順を返す。止める問い（区分が無い・許されていない）は今どおり止まり、送らない。
送れないとき（計画が動いていない・送り手でない・上限を越えた）は今どおり問いを通す。

送られたら、その作業を保留して別の作業へ進む。答えはオーガナイザーが送り、持ち主が読んで続ける。答えていない依頼が閾値を超えると、
レーンは区切りで止まり、閾値以下へ戻ると起きる（[parallel.md](parallel.md) の「答え待ちの停止」）。依頼そのものは止めない。

| 送り手 | 保留の仕方 | 答えが届いたとき |
| --- | --- | --- |
| 開発ループのレーン | `sprint-state.py loop hold-question <ループ> --ref <依頼> --plan <止まったプラン> --step <続きのステップ>` でループの 1 回を「質問待ち」で締め、ループの次の 1 回へ進む（[loop.md](loop.md)） | ループの 1 回の境で、止まったプランを続きのステップから流す |
| 1 スプリントのレーン・一時レーン | 引継ぎ文書の「次にやること」に続きのコマンドと依頼の id を書き、`ndf-next` を出さずに、最後に `relay.py stop "$NDF_RELAY_NAME"` で自分のラッパーを止めてセッションを終える（1 行は保留の手順が返す） | 耐久ワークフローが `relay.py restart <レーン>` で再起動する（オーガナイザーは起こさない）。`parallel.py await --from` か答えのイベントを読み、続きから進む |

設計の承認（設計承認ゲート）は、レーンが依頼として送るため問わない。ループのレーンは設計承認ゲートで課題を人の判断待ちへ移すときに
設計の承認の依頼を送る。本番のリリースは、テンプレートで出すリポジトリではリリースの依頼のプランが依頼として送るため問わない。
リリースの Pull Request で届く経路ではレーンが本番チャネルへ入れるリリースプランをそのまま流し、`pace: normal` のリリース承認ゲートは上の表の問いとしてオーガナイザーへ送られる
（経路ごとの表は [parallel.md](parallel.md) の「レーンの側」）。

## 人のいない実行

Factory の実行ジョブ（環境変数 `NDF_FACTORY_RUN` が空でない `claude -p`）は人のいない実行である。`AskUserQuestion` は使えず、応答を人が読まない。conductor は人へ問わずに工程を進め、区間を終える最後の応答の末尾に**区間の報告**を置く。Factory のランナーは報告の結果の行の値で区間の結果を決める。

例: 標準のモードの課題 #12 を流し、設計 Pull Request を作ったところで設計承認ゲートに着いた。承認資料の中身を本文の「## 判断の材料」の節に書き、その後ろに区間の報告を置いて応答を終える。

```markdown
## 区間の報告

- 結果: 判断が要る
- 課題: #12
- 区分: ndf-gate:1
- 承認ゲート: 設計 Pull Request のマージ
- 問い: 設計 Pull Request をマージしてよいか
- Pull Request: https://github.com/<所有者>/<リポジトリ>/pull/<番号>
- 材料: 本文
- 人に頼むこと: 無し
- 理由: 無し
```

報告の形（結果の値・項目・値ごとに要る項目・材料の書き方）の正本は契約のファイル [unattended-report.json](../../../contracts/forms/unattended-report.json) である。結果の行の読み方は `ndf-next` のブロックの規則と同じで、応答の文の最後の `- 結果:` の行の値を読む。

区分ごとの扱い:

| 場面 | 区間 | 結果の値と添えるもの |
| --- | --- | --- |
| 区分の無い問い（`.ndf/` をコミットするか・次のコマンドを流してよいか など） | 終えない | 自分で決め、`ask.py decide --question` で記録して続ける |
| 承認ゲート（pace が MVV 判定で通さないとき） | 終える | `判断が要る`。区分 `ndf-gate:<番号>`・承認ゲート・Pull Request・材料 |
| 承認を求める区分の問い（`redline`・`cost`・`irreversible`・`legal`・`extra` の区分） | 終える | `判断が要る`。区分・問い・材料 |
| 人の操作が要る問い（`ndf-ask:human-action`） | 終える | `できなかった`。区分・人に頼むこと・理由 |
| 工程を最後まで通した・カットポイント | 終える | `完了`。カットポイントでは `ndf-next` のブロックを添える |
| 続けられない（スクリプトの失敗・権限の不足） | 終える | `できなかった`。理由 |

- `.ndf/ask.json` の `allow` と `mode` は人のいない実行に当てない。外した区分を AI が決めると、人のいない所でレッドライン・費用・取り消せない操作・規約への同意を AI が承認し、人の操作を「決めて続ける」ことになるため、区分のある問いは設定に関わらず区間を終える
- 人の判断の材料は、ランナーのコンテナの外から読める形で渡す。中身は同じ応答の「## 判断の材料」の節に書き（材料の値は `本文`）、コンテナの中のファイルのパスは値にしない
- pace が MVV 判定で承認ゲートを通すときは今どおり通し、区間の報告は次の承認ゲートか終わりで書く
- 区間の報告を書かずに応答を終えようとすると、Stop の hook（`hook.py unattended-stop`）が形の誤りの一覧を添えて差し戻す。形に合わない Stop が続く間の差し戻しは上限の宣言 `hook.unattended-pushback` の回数までで、背景の作業か予定が残る Stop は差し戻さない
- hook が働くのは、プロンプトの 1 行目が `/ndf:development-workflow`（前に `/goal ` を許す）のセッションだけである。worker やレビューの `claude -p` は対象にならない

## 問い合わせの宣言 `.ndf/ask.json`

プロジェクトごとに hook の働き方と人へ回す区分を変える。NDF はこのファイルを読むだけで、書かない。

```json
{
  "version": 1,
  "mode": "enforce",
  "allow": ["cost", "irreversible", "human-action", "legal"],
  "cost": {"threshold_usd": 0},
  "extra": [
    {"name": "customer-contact", "description": "顧客の担当者へ連絡するかどうか"}
  ]
}
```

| 項目 | 無いとき | 意味 |
| --- | --- | --- |
| `version` | 読めない扱い | `1` |
| `mode` | `enforce` | `enforce`（止める）/ `advise`（止めずに案内だけ出す）/ `off`（hook を働かせない） |
| `allow` | 4 つすべて | 人へ回してよい組み込みの区分。空配列は「1 つも許さない」。承認ゲートとレッドラインは書かなくても通る。人のいない実行には当てない（「人のいない実行」） |
| `cost.threshold_usd` | `0` | これ以下の費用は AI が決める（hook は額を比べない） |
| `extra` | 無し | プロジェクトが足す区分。`name` は小文字・数字・`-` で、組み込みの名前と `redline` に重ねない |

- ファイルが無いリポジトリでも `enforce` で働く。止めたくないリポジトリは `"mode": "off"` を書く
- 1 か所でも形が誤っていれば宣言全体を既定（`enforce`・4 区分・しきい値 `0`）で扱い、誤った箇所を止めた理由と案内に出す
- 置き場は、作業ディレクトリから親へ辿って `.git` を持つ最初のディレクトリの `.ndf/ask.json`（worktree では worktree の中）

## 記録

hook の判定と代わりの判断は `${NDF_MVV_STATE_DIR:-~/.claude/ndf/state}/ask.jsonl` へ 1 行ずつ追記する。振り返りでは次で数える。

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/ask.py" summary [--since <ISO 8601>] [--cwd <パス>]
```

区分ごと・判定ごとの件数と、止めたのに代わりの判断が無い問いの件数が出る。区分を広く付けて人へ回し続けていないかを、ここで見直す。

## ランタイムごとの扱い

hook で止めるのは Claude Code だけである。Codex CLI・agy・Kiro CLI では、この文書の規則（区分に当たらない問いは出さず、決めて `ask.py decide --question` で記録する）だけで守る。区分に当たる問いは本文か各ランタイムの問い合わせの Tool で出し、区分の名前を問いの先頭に書く。確かめた結果は `docs/ndf-plugin-reference.md` の hook の節にある。
