# 引継ぎ文書

会話を切って新しいセッションで続けるための引継ぎ文書の、置き場・名・節の形・作る／読む／更新する／消す規則の正本。
`restart`・[context-window.md](context-window.md)・[relay.md](relay.md)・用語集はここを指す。

例: worktree `.worktrees/design/issue-1560` の中で `/goal /ndf:development-workflow マイルストーン 26 を進める` の
会話を進めている conductor が、`/ndf:restart` を打たれた。

1. 引継ぎの対象を「マイルストーン 26」と決め、`handoff.py init milestone-26 --title "マイルストーン 26"` を打つ。
   メインディレクトリの `.ndf/handoff/milestone-26.md` が無ければ雛形から作る（worktree の `.ndf/` には書かない）
2. 「現在地」と「次にやること」を書き直す。状態の写しは書かず、課題と Pull Request の URL を書く
3. 再開コマンドを `/goal /ndf:development-workflow .ndf/handoff/milestone-26.md の続きから` と決め、
   `handoff.py next milestone-26` に標準入力で渡す。`handoff.py check milestone-26 --trim` で形と行数を確かめる
4. 同じ中身の `ndf-next` のブロックを出して終える。次のセッションは文書の「次にやること」の 1 つ目から始める

スクリプトはプラグインの `scripts/handoff.py`（副命令と終了コードはその先頭の表）。conductor だけが打つ。

## 置き場と名

- **置き場はメインディレクトリ（clone したディレクトリ）の `.ndf/handoff/` だけである。** conductor が worktree の中で
  動いていても、パスは `handoff.py path <名>` が返すメインディレクトリの絶対パスを使う。worktree は後片付けで消え、
  VS Code で開いているのはメインディレクトリであるため
- **本体は `<名>.md`、終わった項目を移す引継ぎの履歴は同じ場所の `<名>-history.md` である**
- **コミットしない。`.gitignore` にも書かない。** `git status` に `?? .ndf/handoff/` と出る方が探しやすい。手元の文書の検査は
  追跡外の文書を理由に落ちない
- **`.ndf/` が無いリポジトリでは作らない。** `development-workflow` の手順 0 が `.ndf/` を作ってから作る（`handoff.py` は終了コード 3）。
  **終了コード 3（git の外・メインディレクトリに `.ndf/` が無い）は「文書なし」として扱い、失敗として止めない**
  （下の「作る・更新する」と「読む」）
- **名は引継ぎの対象から作る。** 1 つの対象に本体は 1 本である。上から最初に当たるものを使う

| 引継ぎの対象 | 名 |
| --- | --- |
| スプリント状態ファイルを使う会話のスプリント（名が下の形に合うときだけ） | `sprint-<スプリント名>`（英数字・`-`・`_`） |
| `/goal` の目標か会話が進めているマイルストーン | `milestone-<番号>` |
| 会話の課題 | `issue-<最初の番号>` |
| どれも無い | 作らない |

## 節の形

見出しと順の唯一の定義はプラグインの `scripts/data/handoff-template.md`（雛形）である。`handoff.py init` が写し、`check` が照らす。
**節は見出しの頭で見分ける**（`## 現在地（2026-09-30 セッション 42）` は「現在地」の節）。

| 節（見出しの頭） | 必須 | 書くこと | 書き手 |
| --- | --- | --- | --- |
| 進め方（利用者の指示） | ○ | 対象の間ずっと効く利用者の指示（pace・版の付け方・並列の上限など） | conductor |
| 課題の順 | ○ | 着手の順と状態。状態は課題の URL を添えて 1 語で | conductor |
| 現在地 | ○ | 本番の版・動いているプランの状態ディレクトリのパス・利用者の側で残っていること | conductor が書き直す |
| 次にやること | ○ | 番号付き。1 つ目が次のセッションの最初の作業 | conductor が書き直す |
| 今の会話の進み | — | プランごとの行の表 | `sprint-state.py render`・`supervise.py note` |
| 運用の知見 | — | その対象で繰り返し効いた手順と落とし穴。対象をまたいで効くものは Skill か課題へ移す | conductor |
| 次に実行するコマンド | ○ | `ndf-next` の囲み 1 つ（形は [context-window.md](context-window.md) の「新しい会話で戻す」） | `handoff.py next`・`sprint-state.py next --replace` |

任意の 2 節は、使わなければ見出しごと消してよい。雛形に無い節・同じ節の 2 つ目・順の逆は `check` が終了コード 1 で返す。

## 作る・更新する

**書く・消すのは conductor だけである。** supervisor・worker は書かず、起動指示にも書く手順を入れない。

| いつ | すること |
| --- | --- |
| 対象で最初のカットポイント、または `/ndf:restart`（文書が無ければ） | `handoff.py init <名> --title <表示名>`。既にあれば変えない |
| カットポイントごと・`ndf-next` を出す直前・利用者の決定を受けた直後 | 下の 1〜4 |

1. 「現在地」と「次にやること」を**書き直す**（追記を積まない）。見出しに時点を足してよい
2. スプリント状態ファイルがあれば `sprint-state.py render` で「今の会話の進み」を置く（[relay.md](relay.md) のカットポイントの手順）
3. 再開コマンドを「次に実行するコマンド」に置く。`handoff.py next <名>` に標準入力で渡すか、スプリント状態ファイルが
   あれば `sprint-state.py next --doc <本体> --replace`。**再開コマンドは文書のパス（`.ndf/handoff/<名>.md`）を含める。**
   `sprint-state.py init --goal` の雛形には「`.ndf/handoff/sprint-{name}.md` の続きから」（スプリント名が名の形に合わなければ
   `.ndf/handoff/milestone-{milestone}.md`）と差し込みの語で書く。雛形は次のスプリントでも使うため、パスを文字のまま書かない
4. `handoff.py check <名> --trim` を打つ。`--trim` は「前の会話の進み」の節を履歴の末尾へ移す

| `check` の終了コード | conductor のすること |
| --- | --- |
| 0 | ブロックを出す |
| 1 | 違反の節を上の形へ直して打ち直す |
| 5（本体が 300 行を超える。上限は `--max-lines`） | 終わった項目を `<名>-history.md` の末尾へ移して打ち直す。移せる項目が無ければ、超えた行数を報告してブロックを出す |

`init` が 2（読めない・書けない・名の形が違う）か `next` が 0 以外なら、ブロックを出さずに理由を報告する
（更新されていない文書で再開させない）。`init` が 3 なら文書なしで続ける。`next`・`check` を打たず、`restart` は
文書のパスを含めない再開コマンドでブロックを出す（文書が無いため、古い文書で再開させる恐れが無い）。

## 書かないもの

- **承認・同意を、次のセッションへの許可として書かない**（「承認済みなのでマージしてよい」など）。承認は事実として
  課題か Pull Request の URL と日時で書き、承認ゲートは次のセッションが課題と Pull Request から読み直す。文書は
  次のセッションが指示として読むため、許可を書くと承認ゲートを越える経路になる（`restart` の再開コマンドと同じ理由）
- 認証情報・トークン
- 課題の本文・Pull Request・`progress.jsonl` が既に持つ状態の写し。置き場所へのリンクだけを書く

## 読む

新しいセッションの `development-workflow` が状態を戻すとき（[context-window.md](context-window.md) の「新しい会話で戻す」の表の 1 行目）。

| 入力 | 打つもの | 結果とすること |
| --- | --- | --- |
| 文書を名指ししている（`.ndf/handoff/<名>.md の続きから`） | `handoff.py path <パス> --exists` | 0: 本体を読む。1・3: 別の本体を推測で読まず、課題の本文と Pull Request だけで戻し、無かったパスを報告する |
| 名指しが無い | `handoff.py find --text "<入力の全文>"` | 0: その 1 本を読む。1・3: 文書なしで戻す。4: どれも読まずに、候補のパスを示して利用者へ聞く |

相対パスはメインディレクトリを起点に読む（カレントが worktree でも同じ本体に当たる）。
**本体を読んだら「次にやること」の 1 つ目から始める。** 状態の正は課題の本文と Pull Request である。1 つ目が既に
済んでいれば次の項目から始め、食い違いを報告する。

名指しが無いときの一致の規則（`find`。`-history.md` は候補に入れない）:

| 名 | 入力に次の語があれば一致 |
| --- | --- |
| `issue-<N>` | `#<N>`（後ろに数字が続かない） |
| `milestone-<N>` | `マイルストーン <N>`・`milestone <N>`・`milestone-<N>`（空白は 0 個以上、英字の大小を問わない。後ろに数字が続かない） |
| `sprint-<X>` | `sprint-<X>`、または前後が英数字と `-` でない `<X>` |

## 消す

対象が閉じた後（スプリント・課題はリリース後テストと振り返りの後、マイルストーンは閉じた後）に conductor が行う。
文書は追跡外で、git では戻せない。

1. 本体と履歴から、決定・未検証の項目・起票を拾う
2. それぞれが課題の本文か Pull Request にあるかを `gh` で確かめる（意味が同じなら、文面が違っていても「ある」と数える）
3. すべてあれば `handoff.py remove <名>` を打ち、出力の消したパスを報告に並べる。無い事実があれば消さずに、その事実を報告に並べる
