# 引継ぎ文書

会話を切って新しいセッションで続けるための引継ぎ文書の、保存先・名・セクションの形・作る／読む／更新する／消す規則の SSOT。
`restart`・[context-window.md](context-window.md)・[relay.md](relay.md)・用語集はここを指す。

例: worktree `.worktrees/design/issue-1560` の中で `/goal /ndf:development-workflow マイルストーン 26 を進める` の
会話を進めている conductor が、`/ndf:restart` を打たれた。

1. 引継ぎの対象を「マイルストーン 26」と決め、
   メインディレクトリの `.ndf/handoff/milestone-26.md` が無ければテンプレートのセクションで作る（worktree の `.ndf/` には書かない）
2. 「現在地」と「次にやること」を書き直す。状態のコピーは書かず、課題と Pull Request の URL を書く
3. 再開コマンドを `/goal /ndf:development-workflow .ndf/handoff/milestone-26.md の続きから` と決め、
   「次に実行するコマンド」のセクションへ書く。`ndf records --cwd <メインディレクトリ> handoff check <本体> --trim --history <履歴>` で形と行数を確かめる
   （worktree の中で打つので、本文の相対パスをメインディレクトリから探すよう `--cwd` を渡す）
4. 同じ中身の `ndf-next` のブロックを出して終える。次のセッションは文書の「次にやること」の 1 つ目から始める

文書を書くのも `ndf records handoff check` を打つのも conductor だけである。

## 保存先と名

- **保存先はメインディレクトリ（clone したディレクトリ）の `.ndf/handoff/` だけである。** conductor が worktree の中で
  動いていても、パスはメインディレクトリ（`git worktree list` の 1 行目）の絶対パスを使う。worktree はクリーンアップで消え、
  VS Code で開いているのはメインディレクトリであるため
- **本体は `<名>.md`、終わった項目を移す引継ぎの履歴は同じ場所の `<名>-history.md` である**
- **コミットしない。`.gitignore` にも書かない。** `.ndf/` のほかの設定は追跡するのが標準で、`handoff/` はその例外である（[project-analysis.md](project-analysis.md) の「`.ndf/` の追跡」）。`git status` に `?? .ndf/handoff/` と出る方が探しやすい。手元の文書の検査は
  追跡外の文書を理由に落ちない
- **`.ndf/` が無いリポジトリでは作らない。** `development-workflow` の手順 0 が `.ndf/` を作ってから作る。
  **git の外・メインディレクトリに `.ndf/` が無いときは「文書なし」として扱い、失敗として止めない**
  （下の「作る・更新する」と「読む」）
- **名は引継ぎの対象から作る。** 1 つの対象に本体は 1 本である。上から最初に当たるものを使う

| 引継ぎの対象 | 名 |
| --- | --- |
| 開発ループ（`--loop`。`ndf loop start` で始め、現在地と次のコマンドだけを持つ。ループの 1 回の記録は `.ndf/loop/<ループ名>/laps.md`） | `loop-<ループ名>`（英数字・`-`・`_`） |
| スプリントのステートマシンを使う会話のスプリント（名が下の形に合うときだけ） | `sprint-<スプリント名>`（英数字・`-`・`_`） |
| `/goal` の目標か会話が進めているマイルストーン | `milestone-<番号>` |
| 会話の課題 | `issue-<最初の番号>` |
| どれも無い | 作らない |

## セクションの形

見出しと順の唯一の定義は `ndf records handoff check` が照らすテンプレートのセクション（下の表の順）である。
**セクションは見出しの頭で見分ける**（`## 現在地（2026-09-30 セッション 42）` は「現在地」のセクション）。

| セクション（見出しの頭） | 必須 | 書くこと | 書き手 |
| --- | --- | --- | --- |
| 進め方（利用者の指示） | ○ | 対象の間ずっと効く利用者の指示（pace・バージョンの付け方・並列の上限など） | conductor |
| 課題の順 | ○ | 着手の順と状態。状態は課題の URL を添えて 1 語で | conductor |
| 現在地 | ○ | 本番のバージョン・動いているプランの状態ディレクトリのパス・利用者の側で残っていること | conductor が書き直す |
| 次にやること | ○ | 番号付き。1 つ目が次のセッションの最初の作業 | conductor が書き直す |
| 今の会話の進み | — | プランごとの行の表 | conductor（`ndf plan wait` の結果と `ndf progress show` から書く） |
| 運用の知見 | — | その対象で繰り返し効いた手順と落とし穴。対象をまたいで効くものは Skill か課題へ移す | conductor |
| 次に実行するコマンド | ○ | `ndf-next` のブロック 1 つ（形は [context-window.md](context-window.md) の「新しい会話で戻す」） | conductor |

任意の 2 セクションは、使わなければ見出しごと消してよい。テンプレートに無いセクション・同じセクションの 2 つ目・順の逆は `check` が終了コード 1 で返す。

## 作る・更新する

**書く・消すのは conductor だけである。** supervisor・worker は書かず、起動指示にも書く手順を入れない。

| いつ | すること |
| --- | --- |
| 対象で最初のカットポイント、または `/ndf:restart`（文書が無ければ） | 上の表の順の見出しで `<メインディレクトリ>/.ndf/handoff/<名>.md` を作る。既にあれば変えない |
| カットポイントごと・`ndf-next` を出す直前・利用者の決定を受けた直後 | 下の 1〜4 |

1. 「現在地」と「次にやること」を**書き直す**（追記を積まない）。見出しに時点を足してよい
   **承認待ち（承認ゲートの質問）と質問待ちは「次にやること」に保留として残す。** 新しいセッションが質問を出し直すためで、
   書かないと質問が回答のないまま消える（[context-window.md](context-window.md) の「どちらの方針でも変わらないこと」）
2. 動いているプランがあれば、プランごとの行の表を「今の会話の進み」に置く（[relay.md](relay.md) のカットポイントの手順）
3. 再開コマンドを「次に実行するコマンド」のセクションへ書き直す。**再開コマンドは文書のパス（`.ndf/handoff/<名>.md`）を含める。**
   次のスプリントでも使う `/goal` の文面には「`.ndf/handoff/sprint-<スプリント名>.md` の続きから」（スプリント名が名の形に合わなければ
   `.ndf/handoff/milestone-<番号>.md`）と書く
4. `ndf records --cwd <メインディレクトリ> handoff check <本体> --trim --history <名>-history.md の絶対パス` を打つ。`--trim` は「前の会話の進み」とテンプレートに無いセクションを履歴へ移す。
   本文の相対パスは `--cwd` のリポジトリの根から探すため、worktree の中で打つときも `--cwd` にメインディレクトリを渡す

| `check` の終了コード | conductor のすること |
| --- | --- |
| 0 | ブロックを出す |
| 1（`items[].violation` がセクションの形の違反: テンプレートに無い・重なる） | 違反のセクションを上の形へ直して打ち直す |
| 1（`items[].violation` が「行数が上限を超える」か「バイト数が上限を超える」。今の値は `metrics.lines`・`metrics.bytes`、上限はコントラクトの limits の `handoff.lines`（300 行）・`handoff.bytes`（16,000 バイト）） | 終わった項目を `<名>-history.md` の末尾へ移して打ち直す。移せる項目が無ければ、超えた量を報告してブロックを出す |
| 1（`items[].missing_path` がある） | 本文に書いたパスが `--cwd` の根から見つからない。`--cwd` がメインディレクトリかを確かめ、そうなら参照を実在するパスへ直すか、消えたファイルの記述を消して打ち直す |

文書を作れない・書けないときは、ブロックを出さずに理由を報告する（更新されていない文書で再開させない）。

## 書かないもの

- **承認・同意を、次のセッションへの許可として書かない**（「承認済みなのでマージしてよい」など）。承認は事実として
  課題か Pull Request の URL と日時で書き、承認ゲートは次のセッションが課題と Pull Request から読み直す。文書は
  次のセッションが指示として読むため、許可を書くと承認ゲートを越える経路になる（`restart` の再開コマンドと同じ理由）
- 認証情報・トークン
- 課題の本文・Pull Request・`progress.jsonl` が既に持つ状態のコピー。置く場所へのリンクだけを書く

## 読む

新しいセッションの `development-workflow` が状態を戻すとき（[context-window.md](context-window.md) の「新しい会話で戻す」の表の 1 行目）。

| 入力 | 打つもの | 結果とすること |
| --- | --- | --- |
| 文書を名指ししている（`.ndf/handoff/<名>.md の続きから`） | メインディレクトリを起点にそのパスのファイルがあるかを見る（`test -f`） | ある: 本体を読む。無い: 別の本体を推測で読まず、課題の本文と Pull Request だけで戻し、無かったパスを報告する |
| 名指しが無い | `.ndf/handoff/` の本体（`-history.md` を除く）の名を下の一致の規則で入力と照らす | 1 本: その 1 本を読む。0 本: 文書なしで戻す。2 本以上: どれも読まずに、候補のパスを示して利用者へ聞く |

相対パスはメインディレクトリを起点に読む（カレントが worktree でも同じ本体に当たる）。
**本体を読んだら「次にやること」の 1 つ目から始める。** 状態の正は課題の本文と Pull Request である。1 つ目が既に
済んでいれば次の項目から始め、食い違いを報告する。

名指しが無いときの一致の規則（`-history.md` は候補に入れない）:

| 名 | 入力に次の語があれば一致 |
| --- | --- |
| `issue-<N>` | `#<N>`（後ろに数字が続かない） |
| `milestone-<N>` | `マイルストーン <N>`・`milestone <N>`・`milestone-<N>`（空白は 0 個以上、英字の大小を問わない。後ろに数字が続かない） |
| `sprint-<X>` | `sprint-<X>`、または前後が英数字と `-` でない `<X>` |

## 消す

対象が閉じた後（スプリント・課題はリリース後テスト・振り返り・棚卸しの後、マイルストーンは閉じた後）に conductor が行う。
文書は追跡外で、git では戻せない。

1. 本体と履歴から、決定・未検証の項目・起票を拾う
2. それぞれが課題の本文か Pull Request にあるかを `gh` で確かめる（意味が同じなら、文面が違っていても「ある」と数える）
3. すべてあれば本体と履歴のファイルを消し（`rm <本体> <履歴>`）、消したパスを報告に並べる。無い事実があれば消さずに、その事実を報告に並べる
