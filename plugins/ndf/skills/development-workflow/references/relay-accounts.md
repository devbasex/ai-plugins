# 利用上限でアカウントを替えて続ける

[relay.md](relay.md)（ラッパーでカットポイントを自動にする）から分けた、利用上限でラッパーが claude のアカウントを替えて続ける規約である。

**claude のアカウントを 2 つ以上登録しておくと、利用上限で止まらずに別のアカウントで同じ会話が続く。** 例えば `work1` と
`work2` を登録し、`work1` で動いているレーンが 5 時間の上限の手前（85%）に来ると、ラッパーは止めてよい時点を待って子を止め、
同じ会話を `work2` で `--resume` する。`work2` も尽きれば、設定してある従量の接続（Bedrock）か登録簿の API キーで続く。

登録は 2 回に分かれる（1 回目が認可の URL を出し、2 回目で認可コードを渡す。下の「AI が代わりに打つとき」）。
**Linux（コンテナを含む）だけで使える。** macOS の claude はログインの資格情報を Keychain に置き、設定ディレクトリの
`.credentials.json` を書かないため、macOS の `account add` は登録の前に止まる。1 つのメールアドレスで複数の組織（個人と
Team など）に属していれば、組織ごとに別のアカウントとして登録できる（ログインのときに組織を選ぶ。同じメールアドレスと
組織の 2 つ目は拒む）。

```bash
ndf relay account add work1   # 専用の設定ディレクトリで claude auth login が動き、認可の URL を出す
ndf relay account list        # 推論を呼ばずに、登録と使用率のキャッシュを出す
ndf relay account use work1   # 次のセグメントの起動から使うアカウントを指定する
ndf relay account show        # 今選ばれるアカウント（環境変数 NDF_CLAUDE_ACCOUNT → 指定）を出す
ndf relay account clear       # 指定を消す
ndf relay account remove work2
```

**`account` のサブコマンドはどれも結果 JSON を 1 行で返し、入力を待たない。** 値（名前・プロファイル・地域・モデル・確認）は
引数で渡す。足りない値があれば、その名前と候補を `summary` に書いて終了コード 3（停止理由 `input_missing`）で終わる。
使い方の誤りは終了コード 2（`invalid`）、登録が無い・確かめに落ちた・断ったときは終了コード 1（`refused`）で終わる。
排他を待ちきれないときは何も書かずに停止理由 `store_in_use`（終了コード 3）で終わるので、打ち直さずに人へ戻す。
そのアカウントで子か `ndf plan` の `claude -p` が動いている間は、その名前の登録・削除が `refused` で止まる（子を終えてから打ち直す）。
引数と結果の形は [サブコマンドの引数と結果](../../../docs/contracts/commands.md) にある。

## AI が代わりに打つとき

conductor・worker も人も同じ 2 回で打つ。人が要るのは、ブラウザでの認可と、画面に出た認可コードを AI へ返すことだけである。

```bash
ndf relay account add work2
# → {"status": "stopped", "cause": {"kind": "input_missing", …}, "items": [{"url": "https://…", "expires_at": "…"}]}（終了コード 3）。URL を利用者へ渡す
printf '%s\n' '<認可コード>' | ndf relay account add work2 --code -
# → {"status": "ok", "items": [{"name": "work2", "email": "…", "org_name": "…"}]}
```

1 回目は `claude auth login` を待たせたまま（待機中のログイン）認可の URL を返す。登録の途中の状態は保存先の
`.pending-<名前>/` に残り、10 分を過ぎると次の `account add` で捨てる（2 回目は終了コード 3 で、1 回目からやり直す）。
認可コードは `--code -`（標準入力の 1 行）で渡す。引数に載せると `ps` と打った側の記録に残る。

## 一覧と指定

`account list` の項目は登録 1 件ずつである。アカウントの項目は `email`・`org_name`・`pinned`（指定したアカウントなら真）・
`percent`（使用率のキャッシュのうち、リセットの時刻を過ぎていない窓の最大。読めていなければ null）・`capacity_declared`・`state` を持つ。
`state` は `使える`・`上限`・`残量不明`・`再登録が要る`・`broken`（`account.json` を読めない。`warnings` に 1 行）のどれかである。
`再登録が要る` は同じ名前で `account add` し直す。アカウントの後に、従量の接続の設定があれば `metered` の項目（`source` は `saved` か
`env`。保存した設定は `provider` と `details`、環境変数の設定は変数の名前だけを `keys` に持つ）を、登録した API キーがあれば
キーごとの項目（`account`・`monthly_usd`・`state`。値は持たない）を並べる。

`account list` は認証ファイルを確かめないので、リフレッシュトークンが空のアカウントも、ラッパーが起動の前の用意で見つけるまでは
`使える` と出る。用意で見つけると `再登録が要る` になる（下の「アカウントの設定ディレクトリ」）。

`account capacity work2 210 900` は 5 時間と週のクォータの大きさ（USD）を定義する（スロットを `-` にするとその定義を外す）。
定義は一覧の `capacity_declared` に出るだけで、替え先の選び方には使わない。

**`account use <名前>` は、動いているラッパーにも次のセグメントの起動から効く。** 指定は状態の保存先の
`relay/accounts/pinned.json` に書き、ラッパーはセグメントを起動するたびに読む。同じ状態の保存先を使うラッパーすべてに効く。
指定したアカウントは、下の「替え先の選び方」の並びで同じ側（閾値の内側か外側）の先頭に置く。閾値の外側の指定は内側の候補より後になり、
上限の指定は並びに入らない。動いているアカウントを指定のために替えることはしない（替えるのは続けられないときだけ）。`account use` は、そのアカウントの外した間も解く（直してから指定したアカウントを 1 時間待たせない）。
`account clear` で消すと、判断の結果だけで選ぶ。

`account show` は、子が最初に選ぶ名前（環境変数 `NDF_CLAUDE_ACCOUNT` があればその名前、無ければ指定）を出す。使えるかは確かめない。
指定のファイルが壊れていれば、ラッパーは理由を出して止まる（`account clear` で消してから指定し直す）。

## アカウントの設定ディレクトリ

**アカウントの設定ディレクトリが、そのアカウントで起動する claude の `CLAUDE_CONFIG_DIR` になる。** 保存先は
`${CLAUDE_CONFIG_DIR:-~/.claude}/ndf/accounts/`（`NDF_ACCOUNTS_DIR` で替えられる）で、アカウントごとの `<名前>/` に
認証ファイル（`.credentials.json`）・`.claude.json`・NDF の記録を実体で持ち、ほかの項目は共有の設定ディレクトリ（`~/.claude`）の
直下への symlink にする。会話の記録（`projects`）・設定（`settings.json`）・プラグインは共有側の 1 か所に入るので、アカウントを
替えても `--resume` と設定がそのまま効く。子へはトークンもスコープも渡さず、claude が自分の認証ファイルでトークンを更新する。
`/status`・statusline・`claude auth status` には、そのアカウントの email とコントラクトの種類が出る。共有の
`~/.claude/.credentials.json` は読み書きしないので、素の claude で `/login` を打っても、ラッパーの下の claude のアカウントは替わらない。

| 子の環境の変数 | 登録済みアカウントの子 | 従量の接続と API キーの子 |
| --- | --- | --- |
| `CLAUDE_CONFIG_DIR` | アカウントの設定ディレクトリ（`<保存先>/<名前>`） | 共有の設定ディレクトリ（元の値） |
| `NDF_CLAUDE_ACCOUNT` | アカウントの名前 | `metered`・`key:<キーの名前>` |
| `NDF_SHARED_CONFIG_DIR` | 元の `CLAUDE_CONFIG_DIR`（無ければ空文字）。子の中の `ndf` が共有の設定ディレクトリを求める | 渡さない |
| `CLAUDE_CODE_PLUGIN_CACHE_DIR` | `<共有>/plugins`（元にあればその値） | 元のまま |
| `NDF_ACCOUNT_GENERATION` | 起動を確かめた登録の世代（子の `ndf plan` がリースと上限の後の替え先の判断に使う） | 渡さない |
| 認証の変数（`ANTHROPIC_API_KEY`・`ANTHROPIC_AUTH_TOKEN`・`CLAUDE_CODE_OAUTH_TOKEN`・`CLAUDE_CODE_OAUTH_SCOPES`）と提供元の選択（`CLAUDE_CODE_USE_BEDROCK` など） | 渡さない（元の環境にあっても外す） | 渡さない。従量の接続は設定の変数だけを重ねる |

起動の前に、ラッパーと `ndf plan` はアカウントの設定ディレクトリを用意する（起動の前の用意）。共有側に増えた項目の symlink を足し、
共有の `~/.claude.json` の `projects`（プロジェクトの信頼・MCP サーバーの許可）と `mcpServers` を、共有側・アカウント側・
前の同期のバックアップの 3 つで突き合わせて両側へそろえる（片側だけが変えた値を採り、両側で変えたら共有側を採る。`oauthAccount` は
アカウントごとのまま）。ラッパーは、子が終わったセグメントの終わりとラッパーの終わりに、アカウント側で変わった分を共有側へ書き戻す。
書き戻せなければ `ndf-relay: アカウント <名前> の設定を共有側へ書き戻せない（…）` を 1 行出し、次の起動の前の同期でそろえる。

次の表に当たるアカウントでは claude を起動せず、`ndf-relay: アカウント <名前> で起動しない（<理由>）。次の候補で起動する` を出して次の候補へ移る。

| 理由 | 直し方 |
| --- | --- |
| 認証ファイルが無い・読めない・リフレッシュトークンが空（claude がトークンの更新を断られると空にする） | `account add <名前>` で登録し直す |
| アカウント側の `.claude.json` の本人が登録と違う（アカウントの claude の中で `/login` を打った）・旧形式の `.config.json` が残っている | `account add <名前>` で登録し直す |
| アカウント側の `.claude.json` が無いか壊れている | 下の段落の 2 つのどちらか |
| 会話の記録の保存先 `projects` が共有の `projects` でない実体 | アカウントの設定ディレクトリの `projects` の中身を共有の `~/.claude/projects/` へ移し、`projects` を消す（次の起動で symlink になる） |
| 設定ディレクトリか認証・設定のファイルがアカウントの外を指すか、ほかの名前と同じ実体 | 独立したファイルに戻す |
| 設定か環境に、登録先の OAuth より上に来る認証（`apiKeyHelper`・`ANTHROPIC_API_KEY` など）か既定でない `ANTHROPIC_BASE_URL` がある | その項目を外す |
| 上限・再登録が要る・外した間・再起動ループの検出に当たる | 待つか、登録し直す |

リフレッシュトークンが空・本人の食い違い・旧形式の設定ファイルのときは、そのアカウントを `再登録が要る` にする。ラッパーは起動のたびに、
`再登録が要る` アカウントを 1 つにつき 1 行（`ndf-relay: アカウント <名前> は再登録が要る。ndf relay account add <名前> で登録し直す`）で
知らせる。同じアカウントを既定のログイン（`~/.claude`）と登録済みアカウントの両方で別々にログインしない（1 アカウント = 1 ログイン）。
別々のログインは別々のリフレッシュトークンを持ち、片方の更新が断られると、そちらだけが使えなくなる。

アカウント側の `.claude.json` が JSON として読めないときは、NDF は直さない。`account add <名前>` で登録し直すか、アカウントの設定ディレクトリの
`backups/.claude.json.backup.<ミリ秒>` のうち JSON として読める新しいものを `.claude.json` へ `cp` する。どちらの後も、次の起動で
共有側の `projects` と `mcpServers` にそろう。

**`/mcp` で OAuth 認証した MCP サーバー（claude.ai のコネクタでないもの）は、アカウントごとに認証が要る。** そのトークンは
認証ファイルに入るため、共有側で済ませた認証はアカウントの子に届かない。アカウントごとに 1 度、そのアカウントの対話の
セッションで `/mcp` から認証する。対話を持たない `claude -p` の worker は認証し直せないので、認証の済んでいないアカウントで
動く worker はそのサーバーの Tool を使えない。登録し直すと、そのアカウントでもう 1 度認証が要る。

同じ名前で登録し直すと新しい登録の世代になり、前の世代の使用率・外した間の記録は消える。アカウントの設定ディレクトリの
symlink と、claude がアカウント側に作った項目（`plans` など）は残る。共有側に無くアカウント側にだけある項目は、アカウントを替えた先から
見えない（ラッパーは名前だけを `log.jsonl` の `account_dir` の行の `local_only` に残す）。共有したいものは共有の `~/.claude/` へ移す
（次の起動で symlink になる）。登録を外しても（`account remove`）共有側は消えない。

## 使用率の記録

替え先の選び方は、登録済みアカウントごとの 5 時間と 7 日の使用率で決まる。使用率は、使用率の API の最後に成功した取得の値だけを使う。

- **使用率の API**: ラッパーは、動いていないアカウントを含むすべての登録済みアカウントの使用率を、`GET https://api.anthropic.com/api/oauth/usage`
  （アカウントの認証ファイルのアクセストークン）で取る。取り直すのは、そのアカウントを最後に試してから 300 秒（`relay.usage-fetch`）を
  過ぎたときと、記録した窓のリセットの時刻を過ぎたとき、子の画面に上限の行が出たとき（間隔を待たない）である。取得はラッパーの別の
  スレッドで 1 本ずつ行い、端末の中継を止めない。結果は登録簿の側の `<保存先>/.usage-fetch/<名前>/<登録の世代>.json` に書き、成功する
  たびに窓を丸ごと置き換える。同じ登録簿を使うラッパーどうしはこの記録で取り直しを判定するので、同じアカウントを 300 秒に 1 回より多く
  呼ばない（上限の行を見たときを除く）

**トークンの更新**: アクセストークンの残りが 60 秒（`relay.token-margin`）以下か、使用率の API が 401 を返したときだけ、NDF が
そのアカウントのトークンを更新する。更新するのは、そのアカウントで claude が動いておらず（使用の届けが無い）、claude と同じ更新の
排他（設定ディレクトリの `.oauth_refresh.lock`）を待たずに取れたときだけである。動いているアカウントのトークンは claude が更新する。
更新の要求が 400・401・403 で断られたら、そのアカウントを `再登録が要る` にする。

**応答の形の変化**: 使用率の API の応答の形が変わると、ラッパーは `ndf-relay: 使用率の API の応答の形が変わった。最後に取れた値で続ける`
を 1 回出し、`log.jsonl` に `usage_shape` の行（アカウントの名前と読めなかった項目の名前）を残す。形が戻って取れた後の次の変化で、また出す。

リセットの時刻を過ぎた窓は 0% として読む。7 日の使用率は、7 日の窓とモデル別の週の窓（`limits[]` の `weekly_scoped`）のうち
大きいほうである。過ぎていない窓のどれかが 100% 以上か、使用率の API が支出上限への到達（`extra_usage.spend_limit_reached`）を
返したら、そのアカウントを上限として扱う。**上限かどうかは使用率の API の結果だけで決める（#4404）。** 子の画面に上限の行が出たら、今のアカウントの使用率をすぐ取り直す。取り直した結果が上限でなければ、その行は前の起動の描き直し（`--resume` で開き直した会話に残った行）として、そのセグメントでは見ない。使用率を取れない既定のログインと従量の接続だけは、画面の上限の行で決める。

## 替え先の選び方

**基準は「できるだけ長く続けられる」で、無駄な切り替えをしない。** どの場面も `account_decide.choose` の 1 つの判断で選ぶ（#4404・#4527）。

閾値は 2 つで、`contracts/limits/` が持つ。5 時間か 7 日のどちらかが閾値以上なら**閾値の外側**、どちらも下なら**閾値の内側**と呼ぶ。

| 閾値 | 値 | 意味 |
| --- | --- | --- |
| A（`relay.five-hour-guard`） | 85% | 5 時間の使用率がこれ以上なら閾値の外側 |
| C（`relay.weekly-guard`） | 90% | 7 日の使用率がこれ以上なら閾値の外側 |

例: main（7 日 79%）・gmail（7 日 32%）・team（7 日 100%、上限）が登録されているとき、並びは gmail → main で、team は入らない。
`ndf relay account use main` で指定していれば main → gmail になる。

上限でない登録済みアカウントを、次の順に並べる。

1. 閾値の内側を外側より先にする
2. 同じ側では、明示した名前（環境変数 `NDF_CLAUDE_ACCOUNT` → `ndf relay account use` の指定）を先にする
3. 残りは余裕（100 − 窓の使用率の最大）の大きい順 → 名前の順。使用率の分からない（取得の記録の無い）ものは同じ側の最後

候補から外すのは、上限のアカウント・起動の前の確かめに落ちるアカウント・`再登録が要る` アカウント・外した間のアカウントである。
**替えるのは今のアカウントで続けられないとき（閾値の外側・上限・認証の失敗）と、従量の接続から登録済みアカウントへ戻れるときだけである。**

## いつ替えるか

| いつ | ラッパーの振る舞い | 子へ送る 1 行 |
| --- | --- | --- |
| 最初のセグメント | 上の並びの先頭で起動する（落ちれば並びの次）。上限でない登録済みアカウントが無ければ既定のログインで起動する | 起動の引数のまま |
| カットポイント（`ndf-next` のブロック・`/ndf:restart`） | 今のアカウントが閾値の内側なら替えない。外側なら内側の候補の先頭へ替える（無ければ替えない）。既定のログインは替えない。従量の接続で動いていれば、上限でない登録済みアカウントへ戻す | `ndf-next` のブロック（新しい会話） |
| 見回り（0.5 秒ごと） | 今のアカウントが閾値の外側に出て、内側の候補があれば、止めてよい時点を待って子を止め、同じ会話を候補で `--resume` する。バックグラウンドの作業が残る間は替えずに待つ（[relay-background.md](relay-background.md)） | `利用上限の手前でアカウントを替えた。中断したところから続ける。` の後に、監視を始め直すよう伝える文が続く |
| 見回り（従量の接続で動いている間） | 上限でない登録済みアカウントが現れたら、止めてよい時点を待って子を止め、そのアカウントへ戻す（利用料を止める）。バックグラウンドの作業が残る間は同じく待つ | `利用上限が解けたアカウントへ戻した。中断したところから続ける。` の後に、監視を始め直すよう伝える文が続く |
| 利用上限（5 時間・7 日・支出上限） | 使用率の API の結果で今のアカウントが上限（窓が 100% 以上か支出上限の到達）になり、子が静かな時間（5 秒）止まったか画面に上限の行があれば替える。替え先の順は、上限でない登録済みアカウント（上の並び。閾値の外側も入れる）→ 保存した従量の接続か環境変数の設定 → 登録簿の API キー（名前の順。下の「API キーを復帰先にする」）。どれも無ければ子を残して待ち、上限が解けたアカウント（最も早く解けるもの）で同じ会話を続ける。バックグラウンドの処理が残っていても替え、会話の記録に残った待ちは再開した先が受け取る | `利用上限でアカウントを替えた。中断したところから続ける` |
| 認証の失敗（401） | 子の画面の引き金の行（`Failed to authenticate`・`Invalid API key` など）を、会話の記録の最後の API の失敗の記録で確かめたときだけ替える。登録済みアカウントなら 1 時間（`relay.auth-hold`）候補と指定から外し（外した間。状態の保存先の `relay/accounts/held.json`）、上限のときと同じ順で替える。既定のログインでも替える。替え先が無ければ、ログインの形に合う直し方を 1 行出して子を残す（1 つのセグメントで 1 回だけ） | `認証の失敗でアカウントを替えた。中断したところから続ける` |

**止めてよい時点**は、子の出力が静かな時間（`relay.quiet`、5 秒）止まり、回答待ちの質問が無く、会話の記録の最後が終わった応答（`end_turn`。
結果を待つ Tool の呼び出しが無い）で、その応答がラッパーの最後の入力より後の時点である。Tool の実行の間は画面がスピナーで書き換わり続け、
会話の記録の最後が `tool_use` のままなので、止めてよい時点にならない。来るまで子を止めない。見回りで決めたアカウントの切り替えは、止めてよい時点であっても、
バックグラウンドの作業が残っている間と、それを確かめられない間は待つ。監視だけが残るなら待たずに切り替える（カットポイントの切り替えと同じく、監視は子と一緒に終わる）。

認証の失敗で替え先が無いときの直し方は次のとおりである。

| 今のログイン | 直し方 |
| --- | --- |
| 既定のログイン | claude の中で `/login` を打つ |
| 登録済みアカウント | この子を `/exit` で終えてから `ndf relay account add <名前>` で登録し直す（子が動いている間は登録のコマンドが止まる）。登録し直すと外した間も解ける |
| 従量の接続 | `ndf relay account check metered` で設定を確かめる |

従量の接続と API キーの認証の失敗は外した間に記録しない。代わりに、続けて替える間は失敗した接続先を候補から除き、替えた先で応答が 1 つ
返ったら除くのをやめる（失効したキーが 2 本あっても交互に起動し続けない）。

替える回数に上限は無い。替えた元は閾値の外側に入るか、上限・外した間で除かれるので、窓がリセットされるまで同じ元へは戻らない。
起動から間もないセグメントが続いたときは、再起動ループの検出が次のセグメントを起動しない。続きの中で初めて使う起動先への替えは数えないので、
次々にアカウントを替える正しい替えでは当たらない（値と数え方は [relay.md の「上限」](relay.md#上限)。1 日の起動の回数の上限は持たない）。
替え先も今の起動先も用意できなければ、会話を送らずに `account_unavailable` で終わる（直してから `ndf relay run` で続ける）。

**登録済みアカウントも従量の接続の設定も無ければ、ラッパーはアカウントを替えない。** 上限では子を残して待ち、認証の失敗では直し方の 1 行を出す。
切り替えに LLM は使わない。

## 従量の接続（Bedrock・環境変数の設定）

**従量の接続（Bedrock）は `account add-bedrock` で登録する。** AWS のプロファイルは先に `aws configure sso` などで
作っておく。`--profile` を省くと候補（`aws configure list-profiles`）を、`--model` を省くと Bedrock の推論プロファイルの
うち Claude のものを出して止まる。地域は省けばプロファイルの `region` を使う。保存の前に `aws sts get-caller-identity` と
`aws bedrock-runtime converse`（最大 1 トークン。1 回分の費用が掛かる）で呼べるかを確かめ、呼べなければ理由（`認証切れ`・
`権限が無い`・`地域で使えない`・`モデルが有効でない`）と AWS のエラーの種類の名前を出して保存しない。macOS でも使える。

```bash
ndf relay account add-bedrock        # プロファイルの候補を出して止まる（終了コード 3）
ndf relay account add-bedrock --profile bedrock-dev --model <モデルの ID> --yes
ndf relay account check metered      # 今の設定で呼べるかを確かめる
ndf relay account remove metered     # 保存した設定を外す
```

設定はアカウントの保存先の `metered.json`（0600）に保存し、次の起動から効く。シェルの設定ファイルは書き換えない。
保存するのは変数の名前と値（`CLAUDE_CODE_USE_BEDROCK`・`AWS_PROFILE`・`AWS_REGION`・`ANTHROPIC_MODEL`）だけで、AWS のキーは
`~/.aws/` に残る。保存した設定で起動する子からは、親の環境の AWS のキーと接続先・資格情報の選択の変数を外す。設定は 1 つだけで、
置き換えは確認（`--yes`）が要る。

**環境変数で上書きする場合は `NDF_SUPERVISE_CLAUDE_FALLBACK` を定義する**（`KEY=VALUE` を空白区切り。値はリポジトリに
書かない）。定義されていれば（空でも）保存した設定は読まない。

```bash
export NDF_SUPERVISE_CLAUDE_FALLBACK='CLAUDE_CODE_USE_BEDROCK=1 AWS_PROFILE=<名前> AWS_REGION=us-east-1'
```

ラッパーは起動のたびに、次のときに 1 行を出し、従量の接続の設定なしとして扱う（登録済みアカウントで起動していても先に知らせる）。

- 保存した設定が読めないか壊れている
- 環境変数が空
- 環境変数がラッパーの決める変数（`CLAUDE_CONFIG_DIR`・`NDF_` で始まる変数など）を持つ
- 提供元を 1 つに決められない（Bedrock と API キーの併用など）か、`ANTHROPIC_API_KEY` と `ANTHROPIC_CUSTOM_HEADERS` を併せて持つ

環境変数の設定に `ANTHROPIC_API_KEY` を書いたとき（API キーの設定）は、キーを子の環境へ入れず、下の API キーの子と同じく
`apiKeyHelper` で渡し、同じ確かめと停止を当てる。書けるのはキーと接続先の変数だけである。

従量の接続で起動する子にはアカウントの設定ディレクトリを渡さず、アカウントで起動する子には設定の変数を渡さない（混ぜない）。記録と画面に
出るのは変数の名前だけである。従量の接続へ替えるたびに、`log.jsonl` に `account` の行が残る。

## API キーを復帰先にする

**サブスクリプション（Max・Ultra・Team）にリンクした Console 組織の API キーを登録すると、登録済みアカウントがすべて上限か認証の失敗で
使えず、従量の接続の設定も使えない間、中継の子が登録簿の API キーで同じ会話を続ける。** Console 組織の作成・リンク・キーの発行は
利用者が Console で行う。cross-review の担当の CLI には使わない。

```bash
printf '%s\n' "$KEY" | ndf relay account add-api-key key-main --account main   # 確かめてから保存する
ndf relay account add-api-key key-gmail --account gmail --key-file ~/gmail.key
ndf relay account api-key-use always   # 使い方（off・always・near-limit）。省くと今の値を出す
ndf relay account check key-main       # 確かめ直す（状態は記録しない）
ndf relay account remove key-gmail
```

- **キーの値は標準入力の 1 行目か `--key-file` で渡す。** 引数では受けない（`ps` とシェルの履歴に残るため）。値はアカウントの保存先の
  `api-keys.json`（0600）にだけ置き、子の環境・起動引数・画面・`log.jsonl`・`account list` には出さない
- **登録の前に Messages API へ `max_tokens` 1 の要求を 1 回打って確かめる。** 認証の失敗・残高切れ・通信の失敗なら、理由
  （項目の `reason` は `auth_failed`・`credit_low`・`network`・`unclassified`）を出して終了コード 1 で終わり、何も保存しない
- **1 つの登録済みアカウントに結び付けられるキーは 1 本である。** 名前を変えれば 2 本以上を登録でき、同じ名前で登録し直すと
  置き換わる。登録済みアカウントの名前・`metered` と重なる名前は終了コード 2、登録に無いアカウントと、別のキーが
  結び付いたアカウントは終了コード 1 で断る
- **このバージョンより前に登録したキー（登録の世代を持たない行）は復帰先にならない。** 同じ名前で `add-api-key` し直す
- `--monthly`・`api-key-monthly`（月の額）と `api-key-use --weekly-at`（閾値）は登録簿に保存して一覧に出すだけで、このバージョンの振る舞いには
  効かない。使い方の `always` と `near-limit` はこのバージョンでは区別せず、どちらも `off` でなければ復帰先にキーを使う（次の「課金が始まる時点」）
- 組織に買ったクレジットか自動チャージがあると、月の API クレジットを使い切った後もそちらから払われる。NDF は検出しない
  ので、費用の上限は Console の workspace の spend limit で決める（登録のときにも 1 行出る）

**課金が始まる時点**: 使い方が `always` か `near-limit` のとき、登録済みアカウントがすべて上限か認証の失敗で使えず、従量の接続の設定も
使えない間は、登録簿のキー（`key:<名前>`。名前の順）で子を起動する。**このときから API の利用料が掛かる。** 既存の `always`・`near-limit`
の設定のままでも、追加の操作なしに課金が始まる。使わないなら `ndf relay account api-key-use off` を打つ（既定は `off`）。

**`off` は動いているキーの子にも効く。** ラッパーは見回りで登録簿の変化を見つけ、止めてよい時点か 60 秒（`relay.end-wait`）の早い方で
子を止め、替え先へ移る。キーを消したとき（`account remove`）と同じ名前で登録し直したときも同じである。替え先が無ければ子を残さず、
会話を送らずに `account_unavailable` で終わる。止める必要が立った後の入力は子へ送らない（`ndf-relay: API キーの設定が変わったので
入力を子へ送らない…` が出る。替えた後に打ち直す）。

**キーの子の起動の形**: 子は共有の設定ディレクトリで起動し、認証の変数と提供元の秘密の変数を外す。キーは起動引数の `--settings` に足した
`apiKeyHelper`（`ndf relay account api-key-helper <キーの名前> --generation <世代>`）で渡し、同じ `--settings` に設定の変更を反映の前に
拒む `ConfigChange` の hook（`ndf relay account config-gate`）を足す。キーは既定の接続先（`https://api.anthropic.com`）にだけ送る。
次のときはそのキーで起動せず、次の候補へ移る。

- 親の環境か設定が既定でない `ANTHROPIC_BASE_URL`・`ANTHROPIC_CUSTOM_HEADERS`・別の `apiKeyHelper`・資格情報・提供元の選択を入れる
- Claude Code が 2.1.295 より古いか、`--bare`・`--safe-mode`・hook の無効化・簡易の起動で、設定の変更を拒む hook が働かない
- 起動引数の `--settings` が読めないか 2 つ以上ある

**キーの子が動いている間の守り**:

- 最初の入力は、helper がキーを出したのを見届けてから子の端末へ送る。起動から 30 秒（`relay.key-helper` の `first`）たっても出なければ子を止める
- helper がキーを出すのは 1 つの起動につき 60 秒に 3 回までで、一度拒んだ後と 401 を確かめた後は出さない
- 起動のときに確かめた接続先・ヘッダー・資格情報・`apiKeyHelper` が設定ファイルか環境で変わったら、止めてよい時点を待たずにその見回りで子を止める
  （`ndf-relay: API キーの子の送信先・認証の設定（…）が起動のときと変わったので止めた…`）。替え先が無ければ `account_unavailable` で終わる
- 401 を受けたときと helper が拒んだときも、その見回りで子を止める。替え先が無ければ、失敗したキーの名前と直し方
  （`ndf relay account add-api-key <キーの名前> で登録し直す`。API キーの設定の従量の接続は `ndf relay account check metered`）を並べた
  1 行を出し、`account_unavailable` で終わる（子を残して待たない）

`api-keys.json` が壊れていれば、キーを使わずに動く（`account list` の `warnings` に 1 行）。

## `ndf plan` の `claude -p`

`ndf plan` が起動する `claude -p`（work・worker・判定・Pull Request）は、起動したセッションの環境（`NDF_CLAUDE_ACCOUNT`・
`CLAUDE_CONFIG_DIR`）をそのまま継ぎ、同じ起動先で動く。呼び出しごとには選び直さない。中継の子の環境（`NDF_RELAY_DIR` がある）に
`NDF_CLAUDE_ACCOUNT` があれば、先に起動先の確かめを当て、通った後に、確かめが確定した環境と実行ファイルで起動の前置き（学習に使わない設定の確かめ・重い起動のスロット・Claude Code の下限）を打つ。
中継の外の端末で `NDF_CLAUDE_ACCOUNT` を export しただけなら、利用者の指定として扱い、既定のログインと同じく確かめずに起動する。
相対パスの `CLAUDE_CONFIG_DIR` は、確かめでも起動した claude と同じく子の作業ディレクトリから解く。
起動しないときの理由の 1 行には、キー・トークン・接続先の値を入れない。

| 親の起動先 | 起動の前 | 利用上限に当たったとき |
| --- | --- | --- |
| 既定のログイン | 確かめない | 計画の上限の待ち（`supervise.limit-wait-max`、最長 3 時間）へ進む |
| 登録済みアカウント | 認証の上書き（`apiKeyHelper`・`ANTHROPIC_API_KEY`・既定でない `ANTHROPIC_BASE_URL` など）が無いかを確かめ、worker 自身の使用の届けを取る。スロットを取った後の起動の直前にも認証の上書きを確かめ直し（スロットを待つ間に足された設定を拾う）、関所で起動する。上書きがあれば起動せず `refused` で終わる。関所の子が claude になれなければ `launch` で終わる（理由に errno の名前が出る） | 最初の起動で確かめた登録の世代へ上限の観測を書き（期限は 5 時間の窓のリセットの時刻、分からなければ 5 時間後）、ラッパーの上限の後と同じ順（上限でない登録済みアカウント → 従量の接続）の替え先で同じ呼び出しを 1 回だけ打ち直す（標準エラーに `ndf plan: アカウント <名前> が利用上限に当たった。<替え先> で打ち直す`）。替え先が登録済みアカウントなら、打ち直しの起動の直前にも認証の上書きを確かめ直す。替え先が従量の接続なら、打ち直しの起動の直前にも実効の設定を確かめ直し、外れれば `refused` で終わる。替え先が無いか、打ち直しも上限なら計画の上限の待ちへ進む。API キーの子は替え先にしない（確かめる前に候補から外す） |
| 従量の接続（保存した設定・環境変数の Bedrock など） | 設定が親の起動のときから変わっていないときだけ起動する。変わっていれば `metered_changed` で起動しない。スロットを取った後の起動の直前にも実効の設定を確かめ直し、スロットを待つ間に利用者・プロジェクトの設定が接続先や認証を替えていれば `metered_overridden` などで起動せず `refused` で終わる | 打ち直さずに計画の上限の待ちへ進む |
| API キーの子（`key:<名前>` と、API キーの設定の従量の接続） | **起動しない**（`key_gate`。起動の前置きより先に断り、`refused` で終わる。上限の待ちへは進まない）。Claude Code 2.1.330 の `claude -p` は、どの起動の形でも標準入力を読み終えるまで helper を呼ばず、最初のキーの払い出しを見届けてから入力を送る守りが成り立たないためである | — |

キーの子のレーンで計画を進めると、`ndf plan` のステップが `refused` で止まる。登録済みアカウントが上限から戻るか、レーンをアカウントへ
替えてから進める。

## 記録の読み方

ラッパーがアカウントを替えると、`log.jsonl` に `account` の行が残る。行の種類とキーの一覧は [relay.md の「記録の読み方」](relay.md#記録の読み方)
にある。アカウントに固有の行は次のとおりである。

| `kind` | いつ | ほかのキー |
| --- | --- | --- |
| `account`（`from` のある行） | セグメントの claude を起動した | `from`（前のセグメントの起動先）・`account`（起動した起動先。既定のログインは null）・`reason`（起動の理由。`first`・`cut`・`limit`・`guard`・`auth`・`revoked`）・`skipped`（飛ばした名前） |
| `account`（`reason` だけの行） | 替える判断をした | `reason`（替えた理由の文。例: `work1（91%・閾値の外側） から work2（32%） へ替える`） |
| `account_choice` | 最初のセグメントの起動先を選んだ | `scene`（`start`）・`account`（並びの先頭。既定のログインは null）・`reason` |
| `limit_refuted` | 画面の上限の行を見て取り直した使用率が上限でなかった（前の起動の描き直しとして、このセグメントでは画面の行を見ない） | `account`・`reason` |
| `account_dir` | 起動の前の用意・書き戻しの結果か、飛ばした理由 | `account`・`reason`（理由の符号）・`local_only`・`skipped`・`added` |
| `usage_shape` | 使用率の API の応答の形が変わった | `account`・`items`（読めなかった項目の名前） |
| `usage_fetch_failed` | 使用率の取得が例外で終わった | `count`・`sample` |
| `auth_hold` | 外した間を書けなかった | `account`・`reason` |
| `stop`（`cause` が `spin`） | 再起動ループの検出に当たった | `reason` |

```bash
state="${NDF_STATE_HOME:-${XDG_STATE_HOME:-$HOME/.local/state}}/ndf"
cat "$state"/relay/wrappers/*/log.jsonl | jq -c 'select(.kind == "account") | {at, section, from, account, reason, skipped}'
```
