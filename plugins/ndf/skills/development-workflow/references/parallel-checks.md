# 並列の計画のマシン全体の本数と課題の見込みの重なり

[parallel.md](parallel.md) の続き。マシン全体のプランの本数（起動の待ち。理由 `machine-plans`）と、計画の検査（`ndf lanes init`・`start`）が断る
レーンの間の重なり（`I19`・`I13`）の決まりを置く。

## マシン全体のプランの本数

プランの本数の上限（既定 6）は、同じマシンで動いている並列の計画の合計で数える。別のリポジトリの計画も、計画の所在の一覧
（`<状態の根>/parallel/homes/`）から読んで数える。

- 計画の検査（`ndf lanes init`・`start`）は設定の合計を数えない。終わったレーンとまだ始まらないレーンは同時に動かないため、合計は同時に動く数を表さない。
  断るのは 1 本で上限を超えるレーン（`I2` の誤り）だけである
- 耐久ワークフローは、依存のそろったレーンを起動する前に、マシンで動いているレーン（`running`・`awaiting_approval`）と、承認の回答を
  待って止まった設定のレーンの `plans` を数える。その合計にこのレーンの本数を足して上限を超えるなら起動せず、起動の待ちに置く。
  空きができた後の見回りで起動する。マシンで動いているレーンが 1 本も無ければ、上限を超える 1 本でも起動する
- 数えてから起動するまでは、マシンで 1 つの起動の排他（`<状態の根>/parallel/admit.lock`）の中で行う。10 秒で取れなければ、
  その見回りでは起動せず待ちに置く。レーンの状態の一覧（`ndf relay ls`）を読めず、他に動いている計画があるときも待ちに置く
- 起動の待ちは起動の断りに数えず、質問を出さない。待ちは `ndf lanes status` の行の `waiting` と `plan.md` の進行の表の
  「起動」の欄（`起動待ち（マシン 5 + このレーン 2 > 上限 6）`）で読む
- 回答を当てるための再起動・止まったレーンの再起動・一時レーンの起動は待たせない

上限の値は `NDF_RELAY_MAX_NAMED` → 上限の設定 `relay.max-named`（`contracts/limits.json`。既定 6）の順で決まり、
どのリポジトリから読んでも同じ値になる。人の指示を受けて変えるときは、`ndf lanes start` を打つ環境で `NDF_RELAY_MAX_NAMED` を渡す（切り離した `ndf lanes run` が引き継ぐ。値を書き込むサブコマンドは持たない）。`ndf lanes limits <計画> --max-plans <n>` は
1 つの計画のレーンごとのプランの本数の上限で、このマシン全体の値を変えない。

## レーンの間の重なり（`I19`・`I13`）

計画の検査（`ndf lanes init <plan.json>`・`ndf lanes start <plan.json>`）は、同じリポジトリの 2 つのレーンの重なりを誤りとして返し、
計画を作らない。直すかは計画を組む conductor が決め、直してから打ち直す。

| 規則 | 当たるもの | 誤りの文 |
| --- | --- | --- |
| `I19` | 終わっていない 2 つのレーンの行が同じ課題を持つ | `レーン <a> と <b> の間で課題が重なる（I19）: #<番号>…` |
| `I13` | 前後の鎖（`after`）の無い別のレーンの行どうしで、`touches` の触る場所が重なる | `同時に動き得る行 <行>… の触る場所が重なる（I13）: <場所>…` |
| `I21` | `after` が輪になる | `after が輪になる（I21）: <レーン> → …` |

| 直し方 | すること |
| --- | --- |
| 移す | 後ろのレーンの課題を前のレーンへ移す（`ndf lanes move <計画> <元のレーン> <行> <先のレーン> --reason <理由>`） |
| 順にする | 後ろのレーンの `after` に前のレーンを足す（`ndf lanes set <計画> <レーン> --after <前のレーン> --reason <理由>`） |

課題のまとまりは計画には書かず、レーンのスプリントの実行計画のバンドルとして置く
（[parallel-plan.md](../../issue-plan-strategy/references/parallel-plan.md)）。同じレーンの中のバンドルどうしの重なりは計画の検査が見ない。
