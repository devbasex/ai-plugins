# 並列の計画のマシン全体の稼働中の数と課題の見込みの重なり

[parallel.md](parallel.md) の続き。マシン全体の稼働中のレーンの数（起動の待ち。理由 `machine-lanes`）と、計画の検査（`ndf lanes init`・`start`）が断る
レーンの間の重なり（`I19`・`I13`）の決まりを置く。

## マシン全体の稼働中の数

**同時実行の制御は 2 つの層である。** 計画とレーンは同時実行の値を持たない。`after` で直列にした未着手のレーンを何本書いても、
計画の作成とレーンの追加は数で断られない。

| 層 | 何を絞るか | 仕組み |
| --- | --- | --- |
| セッションの数 | マシン全体の稼働中のレーンと名前つきのラッパー | 耐久ワークフローの起動の許可（下の決まり）。上限は `relay.max-named`（既定 6） |
| 重い処理 | テスト・LLM の CLI | テストのスロット（`ndf.testing.slots`）。重みを数え、メモリが下限を割れば待たせるか止める |

- 耐久ワークフローは、行を始める起動の前に 2 つを 1 本ずつ数える。マシンの計画の稼働中のレーン（実行中の行を持つ。承認ゲートや
  質問の回答を待つ行を含む）と、ラッパーの一覧（`ndf relay ls`）で動いているラッパー（オーガナイザーのように計画に無いものと、
  登録簿に無く錠だけを持つものを含む）である。同じラッパーは 1 回、起動するレーン自身は数えない。数 + 1 が上限を超えるなら起動せず、
  起動の待ちに置く。空きができた後の周に、計画のレーンの並び順に起動する
- マシンの計画は、自分の計画・一覧に conductor の役で載る計画・マシンの計画の索引（`<状態の保存先>/parallel/plans/`）の計画である。
  ラッパーがすべて止まった計画も、実行中の行を持つ間は索引から見つかる
- 数える集まりはリレーハブが数えるラッパーを含むので、許可を通った起動をハブが上限で断らない。許可とハブの判定の隙間で
  ほかの起動が空きを使ったときは、ハブが元のラッパーを止めずに断り、耐久ワークフローは待ちに戻す
- 数えてから起動するまでは、マシンで 1 つの起動の排他（`<状態の保存先>/parallel/admit.lock`）の中で行う。`parallel-machine.admit-lock` の秒で
  取れなければ、その周では起動せず待ちに置く。ラッパーの一覧を読めなければ、自分の計画の実行中の行だけで決める
- 起動の待ちは起動の失敗に数えず、`launch_failed` の知らせを出さない
- 中止・回答の後の next・`/goal` の入れ直しは、行を始めた起動の席を使うので待たせない（上限を下げた直後は一時的に上限を超え得る）

**待ちは `ndf lanes status` で読む。** 起動できる行を持つのに待つレーンの行に `machine_wait`、計画の集計に `metrics.machine` が載る。

| `machine_wait.reason` | 意味 | オーガナイザーの動き |
| --- | --- | --- |
| `machine-lanes` | 稼働中の数（`machine_lanes`）+ 1 が上限（`cap`）を超える | 空きを待つ。急ぐなら人の指示を受けて上限を上げる |
| `lock` | 起動の排他を別の計画が持っている（`machine_lanes`・`cap` は null） | その瞬間だけの値なので、`status` を打ち直して読む |
| `observe` | ラッパーの一覧を読めず、自分の計画の稼働中の数で上限を超える | `ndf relay ls` が読めるかを確かめる |

`metrics.machine` は `lanes`（マシンの稼働中の数）・`cap`（上限。読めなければ null）・`unreadable`（読めない計画）・`others`（ほかの計画の
ステートマシンを読んだか）・`error`（上限を読めないときの文）である。起動できるレーンが無い `status` はほかの計画を読まず、`others` が偽になる。

**上限の値は判定のたびに、マシンの設定 → `NDF_RELAY_MAX_NAMED` → 上限の設定 `relay.max-named`（`contracts/limits.json`）の順で読む。**
どれも 1 以上の整数だけを受ける。人の指示を受けて変えるときは `ndf relay cap --named <数>` で書き、`ndf relay cap --clear` で消す
（引数なしで今の値と出所を出す）。動いている耐久ワークフローとリレーハブも次の判定から新しい値を使う。下げても稼働中のレーンは止めない。

## レーンの間の重なり（`I19`・`I13`）

計画の検査（`ndf lanes init <plan.json>`・`ndf lanes start <plan.json>`）は、同じリポジトリの 2 つのレーンの重なりを誤りとして返し、
計画を作らない。直すかは計画を組む conductor が決め、直してから打ち直す。

| 規則 | 当たるもの | 誤りの文 |
| --- | --- | --- |
| `I19` | 終わっていない 2 つのレーンの行が同じ課題を持つ | `レーン <a> と <b> の間で課題が重なる（I19）: #<番号>…` |
| `I13` | 前後の鎖（`after`）の無い別のレーンの行どうしで、`touches` の触る場所が重なる | `同時に動き得る行 <行>… の触る場所が重なる（I13）: <場所>…` |
| `I21` | `after` が輪になる | `after が輪になる（I21）: <レーン> → …` |

| 直し方 | すること |
| --- | --- |
| 移す | 後ろのレーンの課題を前のレーンへ移す（`ndf lanes move <計画> <元のレーン> <行> <先のレーン> --reason <理由>`） |
| 順にする | 後ろのレーンの `after` に前のレーンを足す（`ndf lanes set <計画> <レーン> --after <前のレーン> --reason <理由>`） |

課題のまとまりは計画には書かず、レーンのスプリントの実行計画のバンドルとして置く
（[parallel-plan.md](../../issue-plan-strategy/references/parallel-plan.md)）。同じレーンの中のバンドルどうしの重なりは計画の検査が見ない。
