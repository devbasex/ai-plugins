# バックグラウンドの作業が残る子を止めずに待つ（Claude Code だけ）

**ラッパーは、バックグラウンドの作業が残る子の claude を、引継ぎ・止まりの起動し直し・利用上限の手前の替えで止めずに待つ。**
子を止めると、supervisor やプランのキューも子とともに終わり、そのフェーズの成果が失われるためである。

例: レーンの conductor が supervisor（Agent）を 1 つ起動して応答を終え、会話の文脈の量が運用上限（既定 500,000）を超えている。

1. Agent を呼ぶ直前に、hook（`relay-busy`）が今の起動の記録へ「1 件以上」を書く。応答を終えると、hook（`relay-marker`）が件数を 1 件に書き直す
2. 子の出力が静かになっても、ラッパーは引継ぎを求めずに待つ。`ndf relay ls` の状態は `waiting`、理由は次のようになる

   ```text
   バックグラウンドの作業 1 件の終わりを待つ（監視 0 件は数えない。記録 2026-11-24T02:16:05+00:00）。子を止めず、引継ぎ・起動し直し・利用上限の手前の替えもしない
   ```

3. supervisor が終わると、Claude Code がその報告を子へ知らせ、子が応答する。その応答の終わりに件数が 0 件になり、次に静かになった見回りでラッパーが引継ぎを求める

判定の順は [relay.md](relay.md#承認ゲートを越えない守り) の表にある。この文書は表の 5〜7 の待ちを説明する。

## 作業と監視を見分ける

バックグラウンドの作業は、Claude Code が会話の外で動かし、終わると会話へ知らせるものである（Agent・`run_in_background` の Bash・Monitor など）。
NDF はこれを、止めると成果を失う**作業**と、待つだけなので止めてよい**監視**に分ける。

| 種類 | 当てはまるもの | 例 |
| --- | --- | --- |
| 監視 | 待つだけのコマンド（`ndf lanes wait`・`ndf plan wait`・`ndf ci watch`）だけでできた、Monitor とバックグラウンドの Bash。`;`・`&&`・`\|\|` でつないでも、`timeout` を前に置いても、ファイルへリダイレクトしてもよい | `ndf lanes wait p1 --after 3`、`timeout 590 ndf plan wait plan.json > wait.log 2>&1` |
| 作業 | 上に当てはまらないものすべて | Agent、`ndf plan queue plan.json`、`cd <場所> && ndf lanes wait p1`、`ndf lanes wait p1 \| tail -1`、`until` や `for` のループ、`npm run build \| grep warn` を打つ Monitor |

**監視だと確かめられないものは作業として扱う。** 作業を監視と取り違えると成果を失い、逆の取り違えは待ちが延びるだけで済むためである。
オーガナイザーとレーンの conductor は、`ndf lanes wait`・`ndf plan wait`・`ndf ci watch` をほかのコマンドやパイプとつながずに打つ。
つなぐと作業に数えられ、終わるまで引継ぎへ進まない。待つだけのコマンドの一覧は `contracts/hooks/guards.json` の `relay-busy` の `params` が持つ。

## 何を待つか

件数は今の起動の記録から読む。「確かめられない」は、記録が無い・読めない・形が違うときである（更新前の hook の子、`NDF_HOOK_OFF` で `relay-busy` を止めた子）。

| ラッパーの手 | 作業も監視も無い | 監視だけが残る | 作業が残る | 確かめられない |
| --- | --- | --- | --- | --- |
| 利用上限の手前の替え（表の 5） | 替える | 替える | 待つ | 待つ。止まりの秒に達していれば起動し直す |
| 文脈の上限の引継ぎ（表の 6） | 引継ぎを求める | 引継ぎを求める | 待つ | 待つ。止まりの秒に達していれば起動し直す |
| 止まりの起動し直し（表の 7） | 起動し直す | 待つ | 待つ | 起動し直す |
| 次のセグメントのマーカー（`relay-marker`） | 書く | 書く | 書かずに変更を要求する | 起動ごとの記録でなく、その Stop の入力の一覧で決める |

- **止まりでは監視だけの子も待つ。** 止まりの起動し直しは最初の入力を持たないので、監視を失った会話が入力を待つだけになるためである
- **利用上限の手前の替えでは、監視の張り直しを伝える。** 替えで監視も終わるので、子へ送る 1 行に、直前に受けたカーソル（`ndf lanes wait` の `--after` など）から張り直すことを足す
- **次の手は待たない。** 上限に達した後と認証の失敗の替え・次のセグメントへの切り替え・子が終わった後の起動し直し・API キーの子の停止
- 子を止める直前に、質問の hook と同じロックの中で記録を読み直す。判定の後に作業が始まっていれば止めず、次の見回りで決め直す

## 起動ごとの記録

記録はラッパーの作業ディレクトリの `busy-<起動の ID>.json` である。**書くのは子の会話の hook だけで、ラッパーは読むだけである**
（子を起動するときに、ほかの起動の記録を消す）。子のシェルから起動した claude は会話の ID（`NDF_RELAY_SESSION`）が違うので書かない。

| hook | いつ | 書くもの |
| --- | --- | --- |
| `relay-busy`（SessionStart） | 会話の起動（`startup`・`resume`） | 0 件 |
| `relay-busy`（PreToolUse） | 作業を始める呼び出し（Agent と、作業に当たる Monitor・バックグラウンドの Bash）の前 | 1 件以上。監視を始める呼び出しでは書かない |
| `relay-marker`（Stop） | 応答の終わり | Stop の入力の `background_tasks` を分けた、作業と監視の件数。一覧が無いか `relay-busy` を止めた環境では書かず、前の記録が残る |

**記録を書けないときは、作業の開始を拒否する**（`relay-busy` は失敗を止める側へ倒す）。監視の開始とほかの呼び出しは拒否しない。理由の文は次のとおりである。

```text
バックグラウンドの作業の開始を中継へ記録できなかったので、始めない。もう一度呼ぶ（中継のラッパーは記録の無いバックグラウンドの作業を守れない）
```

| 拒否された理由 | 直し方 |
| --- | --- |
| ロックの取り合いや hook の時間切れ | 同じ呼び出しをもう一度打つ |
| ラッパーが子を止めている | 何もしない。子は止まり、起動し直した会話が続ける |
| 作業ディレクトリが消えた・書けない（ディスクの空きなど） | 保存先を直すか、`/exit` して `claude` を打ち直す |

ラッパーの下でないセッションと Codex では、この hook は何もしない。

## 待ち続ける子を見つけて起動し直す

**作業が戻らない子を、ラッパーは待ち続ける。** 待つ時間の上限は無い。監視が戻らない子も、止まりの起動し直しでは救われない。
待ちは `ndf relay ls` の `state` と `reason` で見る。

```bash
ndf relay ls | jq -c '.items[] | select(.state == "waiting") | {name, reason}'
```

| `reason` の始まり | 意味 |
| --- | --- |
| `バックグラウンドの作業 N 件の終わりを待つ` | 最後の応答の終わりに作業が N 件残っていた。`記録` は件数を書いた時刻（UTC） |
| `バックグラウンドの作業 1 件以上の終わりを待つ` | 作業を始めた後、まだ応答が終わっていない |
| `監視 M 件の終わりを待つ` | 作業は無く、監視だけが残ったまま子の出力が止まりの秒に達した |
| `バックグラウンドの作業を確かめられないので` | 今の起動の記録を読めない |

`reason` がほかの文なら、別の待ち（回答待ちの質問・利用上限のリセットなど）である。子が動き出すと、状態は `running` に戻る。

待ちが長いと思ったら、次の順で確かめる。**起動し直すと、残っている作業は失われる。**

1. 子の画面（名前つきのラッパーは `tmux -L ndf-lanes attach -t <名前>`）で、作業が進んでいるかを見る
2. 進んでいれば待つ
3. 戻らない作業だけを止めたいときは、その会話に `TaskStop <task id>` で止めさせる（運用上限を超えた会話でも通る）。応答の終わりに件数が書き直され、0 件なら待ちが解ける
4. 会話ごと応答しないときは `ndf relay restart <名前>` で起動し直す。新しい会話が、そのラッパーを起動したときの最初の入力から始まる。
   端末で打ったラッパー（`ndf relay ls` の `registered` が偽）は対象にならないので、`/exit` か Ctrl-C を 2 回打って終え、`claude` を打ち直す
