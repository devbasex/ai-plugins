# 形: ページ

**システムの中のページとして読ませる形である。** 運用マニュアル・稟議のページがこれに当たる。

**置き場所と投稿の手順はここに書かない。** `document-systems` の `system-<名前>.md` が持つ。

## 起点の決め方

**正本の Markdown の直前の版。** git の履歴が持つ。

## 生成の経路

**2 つあり、どちらも既定にしない。**

| 経路 | 何が起きるか |
| --- | --- |
| 変換器を使う | 決定的。同じソースから同じものが出る。既知の失敗を列挙できる |
| AI エージェントが組む | **非決定的。** 同じソースから同じものが出ない。見栄えのよい資料になることが増えている |

**どちらを使うかは体裁設計が決める**（`design` の `layout-page.md`）。**選んだ経路が
「生成物を保存するか」の答えを決める。**

| 経路 | 生成物 |
| --- | --- |
| 決定的 | 保存は任意。ソースと設定から同じものが出る |
| **非決定的** | **保存する。** ソースから復元できないため、生成物が成果物になる |

**変換器を使う経路では、対象リポジトリの仕組みを先に探す。** 生成の手順を新しく作る前に、
既にある仕組み（ビルドの定義・スクリプト）を探して従う。

## 区切り

**区切りは見出しの階層が表す。** ページを分けるかどうかはシステムの慣行に従う。
**特定の変換器の記法を正本へ書かない**（書くと、その変換器を使わない経路で読めなくなる）。

## 検証への配布

**対になる下書き先へ生成する。** 本番の提出先へは、承認した生成物だけが届く。
下書き先は `.ndf/document.json` の `draft` が指す（`development-workflow` の
`references/document-destinations.md`）。

## 本番への配布

**承認を得てから、下書き先の生成物を本番の提出先へ移す。** 作り直さない。
**作り直すと、承認したものと届くものが別になる。**

順序は次のとおり。

1. 下書き先で生成する
2. 生成物を取り込み、正本と内容を照合する（`document-systems` の `import.md`、用途 1）
3. 描画して版面を見る（`layout-review`）
4. **制作物承認を得る**
5. 本番の提出先へ移す
6. 公開範囲を設定し、**設定した後に読み直して確かめる**
7. 索引へ登録する（宣言に `index` があるとき）

## 置き場所と命名

**新しい規約を作らない。対象の置き場所を探して従う。** 実在する文書には既に命名の形が
あり、そこへ別の形を持ち込むと、並べたときに揃わない。

| 決めること | 決め方 |
| --- | --- |
| 置き場所 | 宣言の `location` が指す先。その中の階層は既存の並びに合わせる |
| 命名 | **同じ場所にある既存の文書の題名から形を読む**（年月・相手先・対象期間の付け方） |
| 公開範囲 | 宣言の `visibility` を期待値にする |
| 索引への登録 | 宣言に `index` があれば登録する。無ければ飛ばす |

## 完了の確かめ方

- **完了の事実**: 提出先を照会し、対象のページが存在して開けること。**版が増えたか（または上書きされたか）を
  システムの版の扱いに照らして確かめる。** あわせて公開範囲を取得し直し、宣言の `visibility` と突き合わせる

| 確かめること | 手段 |
| --- | --- |
| 提出できたか | 提出先を照会し、対象が存在すること |
| 公開範囲が意図どおりか | **設定した後に取得し直して突き合わせる** |
| 索引から辿れるか | 索引の側から対象への参照が引けること |

## 取り消し

| 手段 | 限界 |
| --- | --- |
| 共有を解除する | **既に見た人には効かない** |
| 前の版へ戻す | 同上。版の扱いはシステムごとに違う |

**完了報告には手段と限界の両方を書く。**
