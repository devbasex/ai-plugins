# 形: スライド

**版面を持ち、1 枚ずつ読ませる形である。** 提案資料・月次の報告・操作マニュアル・説明資料が
これに当たる。

**置き場所と投稿の手順はここに書かない。** `document-systems` の `system-<名前>.md` が持つ。

## 起点の決め方

**生成スクリプト・台本・トーン＆マナーのファイルの直前の版。** git の履歴が持つ。

## 生成の経路

**生成スクリプトを書く（pptxgenjs）の 1 つだけである。** 変換器（Markdown からスライドを作るもの）・python-pptx・
AI エージェントがその場で組む経路は使わない。変換器の出力は開いた後に文字と図形を直せず、ほかの 2 つは同じ台本から
同じ資料が出ない。

| 経路 | 何が起きるか | 生成物 |
| --- | --- | --- |
| 生成スクリプトを書く | 決定的。同じ生成スクリプト・台本・`theme.json` から同じ pptx が出る。Google Slides と PowerPoint で開いて直せる | 保存は任意。正本は生成スクリプトと台本である |

**対象リポジトリの仕組みを先に探す。** プロジェクトに生成スクリプト（`slides/build-deck.js`）が既にあれば、汎用
テンプレートを写さずにそれに従う。既存の .pptx を読む・直すだけの依頼は、この経路ではなく公式の `pptx` Skill
（`official-skills-autoloader`）が受ける。

## 1 ページの区切り

**台本の `## <番号>. <見出し>` の 1 つが 1 ページに対応する。** 生成スクリプトはページを作るたびに同じ番号の
読み上げをスピーカーノートへ入れ、保存の前に台本のページ数と作ったページ数を照合する。

## 生成スクリプトの経路

汎用テンプレートはこの Skill の [assets/slides/](../assets/slides/) にある。版面は 16:9（10 × 5.625 インチ）、
ページの枠組みの関数は `cover` / `page` / `section` / `box` / `note` / `tbl` / `callout`（図の部品の `chip` / `arrow` /
`text`、表のセルの `H` / `C` / `B`）である。

### 資料のファイルの並び

```text
<資料>/
├── README.md        # 成果物・トーン＆マナー・写した時点の lib/ の内容のハッシュ・生成と確認の手順
├── notes.md         # 構成メモ
├── script.md        # 台本（スピーカーノートの正本）
└── slides/
    ├── build-deck.js    # 生成スクリプト（スライドの正本）
    ├── theme.json       # トーン＆マナーのファイル
    ├── package.json・package-lock.json
    └── lib/             # 汎用テンプレートの枠組みの写し。書き換えない
```

### 汎用テンプレートを写す

`$SKILL_DIR` はこの Skill のディレクトリである。

```bash
mkdir -p <資料>/slides
cp -r "$SKILL_DIR/assets/slides/lib" "$SKILL_DIR/assets/slides/build-deck.js" \
  "$SKILL_DIR/assets/slides/package.json" "$SKILL_DIR/assets/slides/package-lock.json" <資料>/slides/
cp "$SKILL_DIR/assets/slides/script.md" <資料>/script.md
(cd <資料>/slides && npm ci)
cat <資料>/slides/lib/*.js | sha256sum
```

- `build-deck.js` の `SCRIPT` を `path.join(__dirname, "..", "script.md")` に直し、ページの中身を書き換える
- 最後のコマンドの値を、写した時点の `lib/` の内容のハッシュとして `README.md` に書く
- **`lib/` を書き換えない。** 汎用テンプレートの更新を取り込むときは `lib/` を写し直し、`README.md` のハッシュを
  写し直した値へ書き換える。`lib/` のハッシュが `README.md` の値と違えば書き換えた資料であり、プロジェクトの値を
  `theme.json` へ移してから写し直す
- 生成スクリプトと `lib/` に書体名と色の値を書かない。色は `theme.json` の `colors` の項目名（`accent`・`ink`・`panel1`
  など）で指す。値を直接渡すと生成が終了コード 1 で止まる
- Node.js と npm が無ければ、導入の手順を示して止まる

### トーン＆マナーを差し替える

**変える項目だけを `slides/theme.json` に書く。** 書かない項目は汎用テンプレートの既定値（会社色を持たない値）になる。
項目名と既定値の正本は `lib/deck-frame.js` の `DEFAULT_THEME` である。

| 項目 | 書き方 |
| --- | --- |
| `font` | 書体名。**Google Slides と配布先の環境にある書体を選ぶ** |
| `colors` | 項目名ごとに 6 桁の 16 進（`#` なし）。項目ごとに既定値へ重なる |
| `sizes` | 項目名ごとに pt。項目ごとに既定値へ重なる |
| `copyright` | 著作権表示の文言。空なら描かない |
| `logo` | ロゴの PNG の、`theme.json` からの相対パス。`null` なら描かない |

知らない項目名と、形の違う値は終了コード 1 で止まる。座標は `theme.json` に書けない（枠組みが固定する）。

### 構成メモを書く

`notes.md` の `## 構成` の節に、構成の考え方（何から逆算し、何を載せず、どこへ回したか）と次の表を置く。
表の行数はページ数と等しい。

```markdown
| # | 見出し | 役割 | 根拠 |
| ---: | --- | --- | --- |
| 1 | 表紙 | — | — |
| 2 | <台本の見出し> | <このページで聞き手に何を渡すか。載せる図・表・箇条書き> | <数値と主張の出所> |
```

ページに収まらない読み上げの扱いと、尺を超えたときに削るページは同じ文書の節に書く。

### 台本を書き、尺を測る

| 規則 | 内容 |
| --- | --- |
| ページの区切り | `## <番号>. <見出し>`。番号は 1 から欠けずに続く。見出しの末尾の `（<秒>秒）` は配分秒数（任意） |
| 読み上げ | 区切りの中の `>` で始まる行。`>` だけの行は段落の区切り |
| ほかの行 | ページに載せる要素の覚え書き。ノートにも字数にも入らない |
| 最初の区切りより前 | 題・想定・構成の表。読まない |

```bash
node <資料>/slides/lib/script-time.js <資料>/script.md --limit <持ち時間の分>
```

ページごとと合計の字数・尺（350 字/分）・配分秒数の表を出す。出力を構成メモか `README.md` に載せる。合計が
`--limit` を超えたら終了コード 1 で、構成メモで削るページを決めて台本を直す。台本の番号が欠ける・重なると終了コード 2。

### 生成する

```bash
node <資料>/slides/build-deck.js <出力>.pptx [<theme.json>]
```

終了コード 0 で pptx が出る。1 は引数・`theme.json`・ページ数の照合の失敗、2 は台本の形の失敗である。pptx は
作り直せるためコミットしない。

### 変換と確認

1. pptx を Google Slides へ変換する。新しく作るときは pptx を上げて `mimeType` を指定して複製し、既にある
   Google Slides は同じ URL のまま差し替える（置き場所と手段は `document-systems` の `system-gdrive.md`）
2. ページごとのサムネイルを取り、全ページを見る（`layout-review`）
3. 文字あふれ・重なりは `layout-review` の差し戻し先へ戻し、作り直してから 1. の差し替えで同じ URL に上げ直す

## 検証リリース

**対になる下書き先へ生成する。** 本番の提出先へは、承認した生成物だけが届く。
下書き先は `.ndf/document.json` の `draft` が指す（`development-workflow` の
`references/document-destinations.md`）。

## 本番リリース

**承認を得てから、下書き先の生成物を本番の提出先へ移す。** 作り直さない。
**作り直すと、承認したものと届くものが別になる。**

順序は次のとおり。

1. 下書き先で生成する
2. 生成物を取り込み、正本と内容を照合する（`document-systems` の `import.md`、用途 1）
3. 描画して版面を見る（`layout-review`）
4. **制作物承認を得る**
5. 本番の提出先へ移す
6. 公開範囲を設定し、**設定した後に読み直して確かめる**
7. 索引へ登録する（ドキュメントの設定に `index` があるとき）

## 置き場所と命名

**新しい規約を作らない。対象の置き場所を探して従う。** 実在する文書には既に命名の形が
あり、そこへ別の形を持ち込むと、並べたときに揃わない。

| 決めること | 決め方 |
| --- | --- |
| 置き場所 | 設定の `location` が指す先。その中の階層は既存の並びに合わせる |
| 命名 | **同じ場所にある既存の文書の題名から形を読む**（年月・相手先・対象期間の付け方） |
| 公開範囲 | 設定の `visibility` を期待値にする |
| 索引への登録 | 設定に `index` があれば登録する。無ければ飛ばす |

## 完了の確かめ方

- **リリース完了の確認**: 提出先を照会し、対象のスライドが存在して開けること。**ログや操作の成功の表示で済まさない。**
  あわせて公開範囲を取得し直し、設定の `visibility` と突き合わせる

| 確かめること | 手段 |
| --- | --- |
| 提出できたか | 提出先を照会し、対象が存在すること |
| 公開範囲が意図どおりか | **設定した後に取得し直して突き合わせる** |
| 索引から辿れるか | 索引の側から対象への参照が引けること |
