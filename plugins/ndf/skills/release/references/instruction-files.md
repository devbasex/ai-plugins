# 指示書を適切に保つ検査

エージェント向けの指示書（既定では `AGENTS.md` / `CLAUDE.md` / `KIRO.md`）は、**根に置いたものを
そのランタイムの全セッションと全サブエージェントが毎回読む**。何を書いてもよい場所ではなく、
**毎回の読み込みの量をそのまま増やす場所**である。

この文書は 3 つを持つ。**何を見るか。宣言をどう書くか。落ちたときにどう直すか。**

## 実行する

```bash
python3 "$SCRIPTS/instructions-check.py" --root .
rc=$?
echo "exit=$rc"
(exit "$rc")   # このブロックの終了コードを検査の値へ戻す
```

`$SCRIPTS` の決め方は [scripts-lookup.md](../../development-workflow/references/scripts-lookup.md) にある。

**終了コードを潰さない。** `コマンド; echo "exit=$?"` と書くと、その複合コマンド自身の終了
コードは `echo` の 0 になり、**自動で実行する側が 1 / 2 / 3 を成功として通す**。値を変数へ
受けてから表示し、末尾で検査の値へ戻す。

| 終了コード | 意味 |
| --- | --- |
| 0 | 指摘が無い（対象が 1 本も無いときも 0） |
| 1 | 指摘がある |
| 2 | 確かめられなかった（宣言の不正・観点のデータを読めない・版を取れない・`git` が無い） |
| 3 | 呼び出しの誤り（知らない引数） |

**2 を 0 へ畳まない。** 確かめられなかったことを、通ったと報告しない。

| 引数 | 何をするか |
| --- | --- |
| `--root <パス>` | リポジトリの根（既定は現在地） |
| `--scope project\|user\|plugins` | 走査するスコープ。**重ねて指定できる**（既定は `project`） |
| `--report` | 読み込みの量の内訳（たどった先）を足す |
| `--refresh` | 観点の出典を取得して提示する。**通信するのはこの経路だけ** |
| `--refresh-timeout <秒>` | 出典 1 件あたりの待ち |

## 何を見るか

**観点は外部の一次情報から導く。** 一覧・強さ・出典は配布物の
`scripts/data/instruction-criteria.json` が持ち、リポジトリごとの違いは宣言が持つ。

| 観点の id | 何を見るか | 要る宣言 |
| --- | --- | --- |
| `broken-import` | 即時読み込み（`@<パス>`）の参照先が無い | 無し（常に動く） |
| `unlisted-import` | 許可していない即時読み込みと、陳腐化した許可 | `imports` |
| `released-version-paragraph` | 出た版の版数で書き出した段落・見出し | `released` |
| `read-size` | 根の指示書ごとの読み込みの量（**報告のみ**） | 無し |
| `read-size-budget` | 読み込みの量が上限を超えた | `budget` |
| `instruction-count` | 箇条書きと段落の文の数（**報告のみ**） | 無し |

**閾値は配布物に持たない。** ランタイムごとに助言の値が違い（200 行 / 500 行 / 2 ページ /
32 KiB）、版が変わると動く。量と指示の数は常に報告し、**落とすのは宣言に上限を書いたときだけ**である。

### 即時読み込みの一致範囲

**判定するのは、その記法を解釈するランタイムの指示書だけである**（既定は `CLAUDE.md`。
宣言の `import_syntax` で足す）。解釈しない指示書へ掛けると、書いてよい文字列で落ちる。

| 書き方 | 参照として見るか |
| --- | --- |
| 行頭・空白の直後 `@b.md` | 見る |
| 強調の中 `**@a.md**` | 見る（名前は `a.md`） |
| コードスパン `` `@c.md` `` / コードブロックの中 | 見ない |
| 括弧の直後 `(@g.md)` / `（@d.md）` | 見ない |
| 日本語の直後 `直後@f.md` / メール風 `user@h.md` | 見ない |

**参照先は、その参照を書いた指示書のディレクトリから解決する。** `@~/x.md` と、作業ツリーの
外へ出る参照は**存在を判定しない**（許可の判定には掛ける）。追跡された symlink が根の外を
指すときも、読まず・存在を見ず・量に入れない。

### 読み込みの量

**1 セッションが読むのは、根の指示書 1 本とその参照先である。** 3 本を合算した値は、どの
セッションでも読まれない量になるため、**根の指示書ごとに 1 つの数**を出す。

- 同じ参照先を 2 回引いても 1 回だけ数える。循環する参照でも止まる
- たどる深さの上限は既定 4 階層（宣言の `import_depth`）
- `budget.bytes` は**根の指示書ごとに**掛ける。1 本でも超えれば指摘する

## 宣言の書き方

置き場所はリポジトリの `.ndf/instructions.json` である。**無ければ静かに既定へ倒れる。**

```json
{
  "$schema": "https://raw.githubusercontent.com/<所有者>/<リポジトリ>/<タグ>/plugins/ndf/skills/release/schemas/instructions.schema.json",
  "version": 1,
  "files": ["AGENTS.md", "CLAUDE.md", "KIRO.md"],
  "imports": {
    "CLAUDE.md": {"AGENTS.md": "現行の規約そのもので、毎回要る"}
  },
  "released": {"source": "changelog", "path": "CHANGELOG.md",
               "pattern": "^## \\[(?P<version>\\d+\\.\\d+\\.\\d+(?:-[0-9A-Za-z.-]+)?)\\]"},
  "decisions": "docs/version-decisions.md",
  "pending_marker": "の次の版で",
  "budget": {"bytes": 24000}
}
```

**`$schema` には版を固定した公開の URL を書く。** プラグインの導入先は 4 ランタイムで違い、
`.ndf/` から相対で辿れる保証が無い。版を固定するのは、定義が変わっても手元の宣言の意味が
変わらないようにするためである。**この値は検査の動きを変えない**（読み取り側は参照しない）。

| 項目 | 既定 | 何を決めるか |
| --- | --- | --- |
| `version` | 必須 | 宣言の形の版 |
| `files` | `["AGENTS.md", "CLAUDE.md", "KIRO.md"]` | 走査する指示書の名前。**書くと既定を置き換える**（足し込みではない） |
| `imports` | 未指定 | 許可する即時読み込み。**`{}` は「許可が 1 つも無い」**で、未指定とは別の値 |
| `released` | 無し | 出た版の取り出し方（`changelog` / `tags`） |
| `decisions` | 無し | 退避先の文書。指摘の文面に出す |
| `pending_marker` | 無し | 版が決まる前の段落の目印。**空文字列は宣言の不正** |
| `budget` | 無し | `{"bytes": <整数>}`。根の指示書 1 本あたりの上限 |
| `scopes` | 無し | `--scope user` / `--scope plugins` で見に行く位置 |
| `import_syntax` | `["CLAUDE.md"]` | 即時読み込みを解釈する指示書 |
| `import_depth` | `4` | たどる深さの上限 |
| `refresh_timeout_seconds` | `10` | `--refresh` の出典 1 件あたりの待ち |
| `review_interval_days` | `90` | 観点の一覧が古いと知らせるまでの日数 |
| `reviewed_at` | 無し | 観点の一覧を最後に見直した日。書けば日数の起点がこちらになる |

**数の項目（`import_depth` / `refresh_timeout_seconds` / `review_interval_days` /
`budget.bytes`）は 1 以上である。** 0 や負の値を「制限なし」と読むか「すべて落とす」と読むかは
実装で分かれるため、範囲の外は宣言の不正として止める。

### 出た版の取り出し方

| 形 | 何を読むか | 向く相手 |
| --- | --- | --- |
| `changelog` | 変更履歴の文書の、宣言した形の行 | 変更履歴を持つリポジトリ。**配布の Pull Request の中で落ちる** |
| `tags` | 宣言した形のタグの最大値 | 変更履歴を持たないリポジトリ |

**`tags` を選ぶなら、継続的統合の取得の設定も直す。** 浅い clone の既定はタグを取らないため、
`git tag` が空になり「版を 1 つも取れない」（終了コード 2）で必ず落ちる。取得の深さを無制限にするか、
タグだけを取る設定を足す。

- **`pattern` は名前付きの捕捉 `(?P<version>…)` を 1 つ持つ。** 無ければ終了コード 2
- 捕捉した値が版数の形（数字 3 つと、semver に沿った任意の接尾辞）でなければ終了コード 2
- 最大値は**数字 3 つの組と接尾辞の有無**で決まる。`10.9.0` と `10.10.0` では `10.10.0`、
  `10.15.0-dev.1` と `10.15.0` では `10.15.0` が最新になる
- **版を 1 つも取れないときは、走査の前に終了コード 2 で止まる**

### 走査の範囲と、指摘の扱い

**既定はプロジェクトのスコープだけである。** 主な実行先は継続的統合で、そこには利用者の
home もプラグインの取得先も無い。手元で広げるときだけ `--scope` を足す。

| 実行しているリポジトリ | 対象 | 扱い |
| --- | --- | --- |
| NDF の開発リポジトリ | すべて | `直す` |
| それ以外 | プロジェクト / ユーザー | `直す` |
| それ以外 | NDF が配るもの（`scopes.plugins` の `ndf: true`） | `起票` |
| それ以外 | 他のプラグインが配るもの | `報告` |

**NDF の開発リポジトリかは、実行しているスクリプトの実体が `--root` の下にあるかで判定する**
（取得元の名前・リポジトリ名・リモートの URL は fork と移設で変わる）。

**検査は扱いを判定して出力へ載せるだけで、直しも起票もしない。** 書き込みと投稿は呼び出し側が行う。

```json
"scopes": {
  "user": [
    {"path": "~/.claude/CLAUDE.md",
     "imports": {"CLAUDE.md": {"memo.md": "利用者が毎回読ませているメモ"}}}
  ],
  "plugins": [
    {"path": "~/.claude/plugins/cache/<取得元>/ndf/<版>",
     "name": "ndf", "version": "<版>", "origin": "<所有者>/<リポジトリ>",
     "update": "<取得元を更新するコマンド>", "ndf": true}
  ]
}
```

**許可はスコープの根ごとに持つ。** 宣言の直下の `imports` はプロジェクトの許可で、
`scopes` の各要素の `imports` はその位置の許可である。**同じ名前の指示書が 2 つの根に
あっても混ざらない。**

## 落ちたときに何をするか

| 指摘 | 直し方 |
| --- | --- |
| 参照先の無い即時読み込み | 参照を消すか、実在するパスへ直す |
| 許可していない即時読み込み | `@` を外す（リンクかコードスパンにする）。毎回読ませる必要があるなら、宣言の `imports` へ**理由とともに**足す |
| 効かない許可・許可の指し先が無い | 宣言の `imports` からその行を外す（`import_syntax` へ足す） |
| 出た版の段落が指示書に残っている | その段落から次の見出しまでを、宣言の `decisions` が指す退避先へ移す |
| 版が決まる前の段落が、配布を越えて残っている | 書き出しを出す版の版数へ直し、同じく退避先へ移す |
| 読み込みの量が上限を超えた | 現行でない記述を退避先へ移す。上限そのものを変えるなら宣言を直す |

**版が決まる前の段落は、宣言した目印（既定は無し）で書き出す。** 版数はミッションをマージするまで
決まらないため、書く時点では直前の正式版しか書けない。目印を宣言したリポジトリでは、配布で
新しい版が出た時点で検査が拾う。

## 観点を調べ直す

**指示書の「適切」は動く。** 1 年以内に、形式の統治の移管・読むファイルの追加・強調語の助言の
反転・自己検証の指示の削除が起きている。**観点の一覧をデータとして持ち、引き金を決めて調べ直す。**

| 引き金 | 何が起きるか |
| --- | --- |
| 日数（既定 90 日。宣言の `review_interval_days`） | 検査が `NOTE:` を 1 行出す。**落とさない** |
| 配布の工程 | この手順が同じ `NOTE:` を読んで調べ直しを促す |
| 手で起動する | `--refresh` を実行する |

```bash
python3 "$SCRIPTS/instructions-check.py" --refresh
```

出典ごとに 1 行（名前・前回の参照日・取得の成否・前回と内容が変わったか・その出典から取った
主張）が出る。**機械が判定するのは、取得できたかと、前回取得した本文の指紋と一致するかの
2 つだけである。主張が今も成り立つかは人が読む。**

- **`--refresh` はどのファイルも書き換えない。** 観点のデータを直すのは人である
- **取れなかった URL を黙って落とさない。** 1 件でも取得に失敗すれば終了コード 2 で、
  一覧は全件を出す（成功した分を理由に 0 にしない）
- 待ちの決まる順は `--refresh-timeout` > 宣言の `refresh_timeout_seconds` > 既定 10 秒で、
  **1 件あたりの総経過時間**である
