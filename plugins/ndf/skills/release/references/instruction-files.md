# 指示書を適切に保つチェック

エージェント向けの指示書（既定では `AGENTS.md` / `CLAUDE.md` / `KIRO.md`）は、**ルートに置いたものを
そのランタイムの全セッションと全サブエージェントが毎回読む**。何を書いてもよい場所ではなく、
**毎回の読み込み量をそのまま増やす場所**である。

この文書は 3 つを持つ。**何を見るか。設定をどう書くか。落ちたときにどう直すか。**

## 確かめる

**NDF には指示書のチェックを打つサブコマンドがまだ無い（`ndf` へ移すのは #3791）。** それまでは、下の「何を見るか」の観点を
手で確かめ、確かめたことと結果を完了報告へ残す。指示書の一覧は設定の `files`（無ければ `AGENTS.md` / `CLAUDE.md` / `KIRO.md`）である。

| 観点 | 確かめ方 |
| --- | --- |
| @インポートの参照先と許可 | `grep -n '@' <指示書>` で候補を挙げ、下の「@インポートの一致範囲」で参照に当たるものだけを残す。参照先の有無と、設定の `imports` の許可を照らす |
| リリース済みバージョンの段落 | 設定の `released` が指す変更履歴かタグから最新のリリース済みバージョンを読み、指示書にその版数以下で書き出した段落・見出しが無いかを `grep -n` で探す。設定の `pending_marker` で書き出した段落がリリースを越えて残っていないかも見る |
| 読み込み量 | ルート指示書ごとに、そのファイルとたどった参照先の大きさを `wc -c` で足す。設定の `budget.bytes` があれば上限と比べる |

**確かめられなかった観点を、通ったと報告しない。** 読めなかったファイル・決められなかった版数は、そのまま完了報告へ書く。

## 何を見るか

**観点は外部の一次情報から導く。** 一覧は下の表が持ち、リポジトリごとの違いは指示書チェックの設定が持つ。

| 観点の id | 何を見るか | 要る設定 |
| --- | --- | --- |
| `broken-import` | @インポート（`@<パス>`）の参照先が無い | 無し（常に動く） |
| `unlisted-import` | 許可していない@インポートと、陳腐化した許可 | `imports` |
| `released-version-paragraph` | リリース済みバージョンの版数で書き出した段落・見出し | `released` |
| `read-size` | ルート指示書ごとの読み込み量（**報告のみ**） | 無し |
| `read-size-budget` | 読み込み量が上限を超えた | `budget` |
| `instruction-count` | 箇条書きと段落の文の数（**報告のみ**） | 無し |

**閾値はリリース対象に持たない。** ランタイムごとに助言の値が違い（200 行 / 500 行 / 2 ページ /
32 KiB）、バージョンが変わると動く。量と指示の数は常に報告し、**落とすのは設定に上限を書いたときだけ**である。

### @インポートの一致範囲

**判定するのは、その記法を解釈するランタイムの指示書だけである**（既定は `CLAUDE.md`。
設定の `import_syntax` で足す）。解釈しない指示書へ掛けると、書いてよい文字列で落ちる。

| 書き方 | 参照として見るか |
| --- | --- |
| 行頭・空白の直後 `@b.md` | 見る |
| 強調の中 `**@a.md**` | 見る（名前は `a.md`） |
| コードスパン `` `@c.md` `` / コードブロックの中 | 見ない |
| 括弧の直後 `(@g.md)` / `（@d.md）` | 見ない |
| 日本語の直後 `直後@f.md` / メール風 `user@h.md` | 見ない |

**参照先は、その参照を書いた指示書のディレクトリから解決する。** `@~/x.md` と、worktree の
外へ出る参照は**存在を判定しない**（許可の判定には掛ける）。追跡された symlink がルートの外を
指すときも、読まず・存在を見ず・量に入れない。

### 読み込み量

**1 セッションが読むのは、ルート指示書 1 本とその参照先である。** 3 本を合算した値は、どの
セッションでも読まれない量になるため、**ルート指示書ごとに 1 つの数**を出す。

- 同じ参照先を 2 回引いても 1 回だけ数える。循環する参照でも止まる
- たどる深さの上限は既定 4 階層（設定の `import_depth`）
- `budget.bytes` は**ルート指示書ごとに**掛ける。1 本でも超えれば指摘する
- デプロイの工程で書き換わる値（版数など）を指示書に置かない。置くと、Pull Request で上限に収まった
  指示書が、デプロイで版数を `-dev.<連番>` 付きへ上げた時点で伸びて落ちる。版数は定義ファイル
  （`plugin.json` など）を SSOT にして、指示書からは指す

## 設定の書き方

置く場所はリポジトリの `.ndf/instructions.json` である。**無ければ静かに既定へ倒れる。**

下の終了コード・`--scope`・`--refresh` の記述は、10 系の NDF の指示書チェックの振る舞いである。`ndf` へ移すとき（#3791）に決め直す。
手で確かめるときは、設定の値の意味だけを使う。

```json
{
  "$schema": "https://raw.githubusercontent.com/<所有者>/<リポジトリ>/<タグ>/plugins/ndf/skills/release/schemas/instructions.schema.json",
  "version": 1,
  "files": ["AGENTS.md", "CLAUDE.md", "KIRO.md"],
  "imports": {
    "CLAUDE.md": {"AGENTS.md": "現行の規約そのもので、毎回要る"}
  },
  "released": {"source": "changelog", "path": "CHANGELOG.md",
               "pattern": "^## \\[(?P<version>\\d+\\.\\d+\\.\\d+(?:-[0-9A-Za-z.-]+)?)\\]"},
  "decisions": "docs/version-decisions.md",
  "pending_marker": "の次のバージョンで",
  "budget": {"bytes": 24000}
}
```

**`$schema` にはバージョンを固定した公開の URL を書く。** プラグインの導入先は 4 ランタイムで違い、
`.ndf/` から相対で辿れる保証が無い。バージョンを固定するのは、定義が変わっても手元の設定の意味が
変わらないようにするためである。**この値はチェックの動きを変えない**（読み取り側は参照しない）。

| 項目 | 既定 | 何を決めるか |
| --- | --- | --- |
| `version` | 必須 | 設定の形のバージョン |
| `files` | `["AGENTS.md", "CLAUDE.md", "KIRO.md"]` | 走査する指示書の名前。**書くと既定を置き換える**（足し込みではない） |
| `imports` | 未指定 | 許可する@インポート。**`{}` は「許可が 1 つも無い」**で、未指定とは別の値 |
| `released` | 無し | リリース済みバージョンの取り出し方（`changelog` / `tags`） |
| `decisions` | 無し | 退避先の文書。指摘の文面に出す |
| `pending_marker` | 無し | バージョンが決まる前の段落のマーカー。**空文字列は設定の不正** |
| `budget` | 無し | `{"bytes": <整数>}`。ルート指示書 1 本あたりの上限 |
| `scopes` | 無し | `--scope user` / `--scope plugins` で見に行く位置 |
| `import_syntax` | `["CLAUDE.md"]` | @インポートを解釈する指示書 |
| `import_depth` | `4` | たどる深さの上限 |
| `refresh_timeout_seconds` | `10` | `--refresh` の出典 1 件あたりの待ち |
| `review_interval_days` | `90` | 観点の一覧が古いと知らせるまでの日数 |
| `reviewed_at` | 無し | 観点の一覧を最後に見直した日。書けば日数の起点がこちらになる |

**数の項目（`import_depth` / `refresh_timeout_seconds` / `review_interval_days` /
`budget.bytes`）は 1 以上である。** 0 や負の値を「制限なし」と読むか「すべて落とす」と読むかは
実装で分かれるため、範囲の外は設定の不正として止める。

### リリース済みバージョンの取り出し方

| 形 | 何を読むか | 向く相手 |
| --- | --- | --- |
| `changelog` | 変更履歴の文書の、設定した形の行 | 変更履歴を持つリポジトリ。**リリースの Pull Request の中で落ちる** |
| `tags` | 設定した形のタグの最大値 | 変更履歴を持たないリポジトリ |

**`tags` を選ぶなら、CIの取得の設定も直す。** 浅い clone の既定はタグを取らないため、
`git tag` が空になり「バージョンを 1 つも取れない」（終了コード 2）で必ず落ちる。取得の深さを無制限にするか、
タグだけを取る設定を足す。

- **`pattern` は名前付きの捕捉 `(?P<version>…)` を 1 つ持つ。** 無ければ終了コード 2
- 捕捉した値が版数の形（数字 3 つと、semver に沿った任意の接尾辞）でなければ終了コード 2
- 最大値は**数字 3 つの組と接尾辞の有無**で決まる。`10.9.0` と `10.10.0` では `10.10.0`、
  `10.15.0-dev.1` と `10.15.0` では `10.15.0` が最新になる
- **バージョンを 1 つも取れないときは、走査の前に終了コード 2 で止まる**

### 走査の範囲と、指摘の扱い

**既定の指示書スコープはプロジェクトだけである。** 主な実行先はCIで、そこには利用者の
home もプラグインの取得先も無い。手元で広げるときだけ `--scope` を足す。

| 実行しているリポジトリ | 対象 | 扱い |
| --- | --- | --- |
| NDF の開発リポジトリ | すべて | `直す` |
| それ以外 | プロジェクト / ユーザー | `直す` |
| それ以外 | NDF が配るもの（`scopes.plugins` の `ndf: true`） | `起票` |
| それ以外 | 他のプラグインが配るもの | `報告` |

**NDF の開発リポジトリかは、実行しているスクリプトの実体が `--root` の下にあるかで判定する**
（取得元の名前・リポジトリ名・リモートの URL は fork と移設で変わる）。

**チェックは扱いを判定して出力へ載せるだけで、直しも起票もしない。** 書き込みと投稿は呼び出し側が行う。

```json
"scopes": {
  "user": [
    {"path": "~/.claude/CLAUDE.md",
     "imports": {"CLAUDE.md": {"memo.md": "利用者が毎回読ませているメモ"}}}
  ],
  "plugins": [
    {"path": "~/.claude/plugins/cache/<取得元>/ndf/<バージョン>",
     "name": "ndf", "version": "<バージョン>", "origin": "<所有者>/<リポジトリ>",
     "update": "<取得元を更新するコマンド>", "ndf": true}
  ]
}
```

**許可は指示書スコープのルートごとに持つ。** 設定の直下の `imports` はプロジェクトの許可で、
`scopes` の各要素の `imports` はその位置の許可である。**同じ名前の指示書が 2 つのルートに
あっても混ざらない。**

## 落ちたときに何をするか

| 指摘 | 直し方 |
| --- | --- |
| 参照先の無い@インポート | 参照を消すか、実在するパスへ直す |
| 許可していない@インポート | `@` を外す（リンクかコードスパンにする）。毎回読ませる必要があるなら、設定の `imports` へ**理由とともに**足す |
| 効かない許可・許可の指し先が無い | 設定の `imports` からその行を外す（`import_syntax` へ足す） |
| リリース済みバージョンの段落が指示書に残っている | その段落から次の見出しまでを、設定の `decisions` が指す退避先へ移す |
| バージョンが決まる前の段落が、リリースを越えて残っている | 書き出しを出すバージョンの版数へ直し、同じく退避先へ移す |
| 読み込み量が上限を超えた | 現行でない記述を退避先へ移す。上限そのものを変えるなら設定を直す |

**バージョンが決まる前の段落は、設定したマーカー（既定は無し）で書き出す。** 版数はスプリントをマージするまで
決まらないため、書く時点では直前の正式版しか書けない。マーカーを設定したリポジトリでは、リリースで
新しいバージョンが出た時点でチェックが拾う。

## 観点を調べ直す

**指示書の「適切」は動く。** 1 年以内に、形式の統治の移管・読むファイルの追加・強調語の助言の
反転・自己検証の指示の削除が起きている。**観点の一覧をデータとして持ち、引き金を決めて調べ直す。**

| 引き金 | 何をするか |
| --- | --- |
| 日数（既定 90 日。設定の `review_interval_days`。起点は `reviewed_at`） | 日数を過ぎていれば、リリースの工程で調べ直しを完了報告へ載せる。**工程を止めない** |
| 手で起動する | 下の手順で調べ直す |

調べ直すときは、各ランタイムの指示書の公式の説明（読み込むファイル・@インポートの記法・量の助言）を開き、上の観点の表と比べる。
**機械が判定できるのは取得できたかだけで、主張が今も成り立つかは人が読む。** 取れなかった出典を黙って落とさず、
取れなかったことを完了報告へ書く。観点の表を直すのは人であり、直したら設定の `reviewed_at` を書き換える。
