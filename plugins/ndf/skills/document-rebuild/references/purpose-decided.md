# 文書の目的: 確定事項を伝える文書

**結論が既に決まっていて、読み手にそれを渡す文書に当たる。** 確定した設計・確定仕様・説明・研修・指標定義・報告書。

## 見分ける手がかり

- 本文が「〜する」「〜とした」の断定で書かれ、読み手に採否を問う節が無い
- 確定仕様（`docs/specifications/`）・説明文書・研修資料・指標の定義
- 文書タイプが説明・研修、または定義を変えない指標定義

## 構成

| 順 | 読み手の問い | 章の例 |
| --- | --- | --- |
| 1 | 何が決まったのか。何を作るのか | 作るもの / 結論 |
| 2 | なぜそれが要るのか | なぜ必要か |
| 3 | その判断は何に基づくのか | 枠組み / 実測 |
| 4 | 中身はどうなっているのか | 定義 / 設計 |
| 5 | どう進めるのか | 手順 |
| 6 | 何をもって終わりとするのか | 受け入れ条件 |

**調査の順序と逆になる。** 調査は 3 から始まり 1 で終わるが、文書は 1 から始める。

**この構成は章の中の段落にも同じ形で当てはまる。** 章の最初の段落がその章の要点を述べ、段落の最初の文がその段落の主張を述べる。読み手はどこで読むのをやめても要点を得られる。

## 文章量

形式別ガイドの目安に従う。この目的が足す目安は無い。

## 結論の位置

**結論・成果物が定義される位置は最初の章である。** 根拠は重要な順に並べる書き方（BLUF）と、設計文書 3 本の実測（組み直しの後に 1〜5 行目へ移った）。

## 文書タイプとの対応

説明・研修と指標定義では、最初の章に `document-drafting` の `type-briefing.md`・`type-metrics.md` の「読み手が最初に問うこと」の答えを置く。
