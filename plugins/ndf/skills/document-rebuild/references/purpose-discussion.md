# 文書の目的: 議論用の文書

**まだ決まっていないことを、読み手と決めるための文書に当たる。** 仕様案・論点の整理・確認待ちの問いを含む提案。

実例: 外部の取引先への確認待ちの論点を含む仕様案を、確定事項を伝える文書の構成で組み直すと、提案が「方針」として最初の章に置かれた。利用者は「議論用なので、結論から書く書き方は不自然」と指摘し、下の構成へ並べ直した。

## 見分ける手がかり

- 本文か Pull Request に「議論用」「案」「提案」「確認したいこと」とある
- 確認待ちの問い（外部への確認・未決の問い）を含む
- 読み手が採否だけでなく、論点の立て方そのものに意見を返す

**「案」「提案」の語は確定事項を伝える文書にも出る。** 語だけで決めず、確認待ちの問いの有無と合わせて見る。決まらなければ呼び出し元へ確かめる。

## 構成

| 順 | 章 | 読み手の問い |
| --- | --- | --- |
| 1 | 決めたいこと（論点） | 何を決めるための文書か |
| 2 | 事実 | 前提になる外部の仕様・要件・実測は何か |
| 3 | 事実の解釈 | その制約は何を意図しているか |
| 4 | 提案 | 書き手はどうしたいか |
| 5 | 提案の中身 | 提案を採るとどうなるか |
| 6 | 確認すること（未決の問い） | 読み手は何に答えればよいか |
| 7 | 未確定・残リスク | まだ分からないことは何か |

**読み手が事実と解釈を確かめてから提案を読む順にする。** 提案を最初の章に置かない。

## 提案の言い回し

**提案の章は、決定と区別できる言い回しで書く。** 「〜する案とする」「次の扱いを提案する」で書き、「〜する」「方針: 〜」の断定で書かない。断定で書くと、議論の参加者が「もう決まった」と読み、反論や確認が出にくくなる。

この決まりは議論用の文書にだけ当たる。確定事項を伝える文書では断定が正しい。

## 判断を求める前に示すもの

確認すること（6 の章）の前に、`decision-request` の 5 項目が 2〜5 の章にそろっているかを見る。

## 文章量

形式別ガイドの目安に従う。この目的が足す目安は無い。

## 結論の位置

**指標「結論・成果物が定義される位置」は、「論点が最初の章」に読み替える。** 提案が最初の章に「方針」として置かれていたら、論点の章を最初へ戻す。

## 文書タイプとの対応

未決の問いを含む提案・企画は、この目的別ガイドに当たる。最初の章に置くのは論点で、`type-proposal.md` の「読み手が最初に問うこと」（何をするのか、いくらか、いつまでか）の答えは 4・5 の章に置く。
