# キーワードの確かめ方

**読み手が、題・見出し・繰り返し出る語を、知っている語として受け取れる状態にする。** 訳語・造語・表記の揺れが題に残ると、読み手は主題を取り違えるか、定義を覚え直す。この手順は、どの文書形式・文書の目的でも手順 3 で通す。

実例: 社外向けの発表資料の題「独自スキルプラグイン開発の薦め」は、要求・設計・実装・2 回のレビューを通り、リリースの直前に作り直した。Anthropic と OpenAI の公式ドキュメントは、スキル（作る単位）とプラグイン（配る単位）を呼び分けていて、「スキルプラグイン」という語を使わない（#2080）。

## 確かめる語の選び方

| 選ぶ語 | 例 |
| --- | --- |
| 題と見出しの語 | 題の名詞、章の見出しの名詞 |
| 用語として立てた語 | 用語の表に載せた語、太字で定義した語 |
| 本文で 3 回以上出る語 | 主題として繰り返す名詞 |

**選んだ語を 1 つずつ、表記の揺れも合わせて見る。** 英語とカタカナの混在（Skill とスキル）・送り仮名・略記の揺れを、1 つの表記にそろえる。

## 突き合わせる相手

| 読み手 | 突き合わせる相手 | 当たらないときの扱い |
| --- | --- | --- |
| 社外（発表資料・記事・提案書など、読み手がリポジトリの外にいる文書） | その語を定めている公式ドキュメントの語と表記。URL を残す | 公式の語へ置き換える。公式の出所が見つからない語は「確かめられなかった」と残し、語を変えない |
| 社内・リポジトリ | プロジェクトの用語集の語と、読み手の業界で流通している語（`document-style` のルール 11） | 訳語・造語は流通している語へ置き換える。置き換える語が無いときだけ、用語集へ定義を足す |

**訳語・造語を作らない。** 英語の語を和語へ直訳した語（key term を「鍵の語」）や、その場で組み合わせた語（「形の参照」）は、読み手の知らない語である。

## 残し方

**手順 4 の報告に、確かめた語ごとに 1 行を残す。** 確かめられなかった語も残す。「キーワードの確認: 無し」とは書かない。

```text
| 語 | 突き合わせた相手 | 判定 |
| --- | --- | --- |
| スキル | https://code.claude.com/docs/en/skills | 公式の語 |
| スキルプラグイン | https://code.claude.com/docs/en/plugins | 公式に無い。「スキル」と「プラグイン」へ分けた |
| 鍵の語 | 用語集・業界の語 | 造語。「キーワード」へ置き換えた |
| 構成メモ | 公式の出所が見つからない | 確かめられなかった（語は変えない） |
```
