# 文書形式: リポジトリの Markdown

**この形式別ガイドは、リポジトリに置く Markdown（`docs/`・Issue と Pull Request の本文・設計文書・README）に当たる。** 他の文書形式は `format-<形式>.md` が持つ。

## 文章量の単位と目安

| 指標 | 目安 | 根拠 |
| --- | ---: | --- |
| 平均文長 | 40 字以下 | 再構成後の実測 30.4 / 31.0 / 33.4 字（設計文書 3 本） |
| 最長文 | 100 字以下 | 再構成後の実測 73 / 75 / 105 字（同じ 3 本） |
| 章あたりの行数 | 40 行以下 | 超える章は分割の候補（同じ 3 本の組み直しで分けた章の長さ） |
| ファイルの長さ | `document-style` のルール 9 | ルール 9 が正本。章と文の長さはこのファイルが持つ |

**文の区切り方と字数の数え方は `lang-<言語>.md` が持つ。**

## 題と見出し

**題は `<対象>: <何ができるようになるか>` の短い 1 文にする。** Issue・Pull Request・設計文書の題の付け方の正本はこの節である。

| 項目 | 決まり |
| --- | --- |
| 形 | `<対象>: <何ができるようになるか>（#<課題番号>[ #<番号>...]）`。対象は Skill 名か領域で、省いてよい |
| 長さ | 1 文で、目安 60 字以内（根拠: 未実測。#2086 の設計の題を 145 字から 60 字にした 1 本） |
| 今の状態（不具合の現象・まだできないこと） | 題に入れない。設計文書では H1 の直後の「目的」の章の「今どうなっているか」に置く |
| 仕組みの語 | 関数・ステップ・ファイルの名前を題に入れない。本文へ回す |
| 見出し | 章の見出しは、その章が答える問いの答えを名詞句か短い文で書く |

実例: `document-rebuild: 文書形式と目的に合わせて組み直し、読み手が理解し納得できるかを確かめる`

## 測らない指標

無し（文長・章の行数・結論の位置のすべてを測る）。
