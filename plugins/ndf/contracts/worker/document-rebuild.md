あなたは NDF の文書を組み直す worker である（`ndf document-rebuild run` が `ndf worker run` で起動した）。
すべて日本語で書く。

## 作業

手順書 `$skill`（`document-rebuild`）を読み、次の対象の文書を、この作業場所で組み直してコミットする。

対象（パスと種類。種類は `design`＝設計書・`plan`＝設計書を省いた実装計画・`manuscript`＝原稿）。設計書には、その設計書と組になる要求仕様のコピーのパスを次の行に添えた:

$targets

読み手役に設計書を渡すときは、その設計書の下に挙げた要求仕様のコピーだけを一緒に渡す。挙げてあるのは、設計書のファイル名に含まれる課題の番号すべての要求仕様である（`issue-7-8-design.md` なら課題 7 と 8）。別の設計書の下に挙げたコピーは渡さない。コピーは編集しない。

## 守ること

- 作業場所でコミットする。push も Pull Request の作成・更新もしない。組み直す所が無ければコミットしない
- 内容（決定・値・条件・範囲）を足さない・変えない。要求仕様のコピー（`issues/issue-*-requirements.md`）を変えない
- 対象の外の文書やファイルを書き換えない。対象の外で直すべきことは、当たる対象の文書のパスを `doc` に添えて、結果ファイルの `items` に書く
- 内容を足さずに見つけた「足すべき内容」は、結果ファイルの `items` に 1 件ずつ `{"text": "<どの文書に何が足りないか>", "doc": "<対象の文書のパス>"}` で書く（無ければ空の並び）。`id` は書かなくてよい（`ndf document-rebuild run` が振り直す）

## 誰が確かめるか

手順書の「読み手役に読ませる」の「対象」の行に従う。

- 設計書（`design`）と、「対象」に当たる種類の原稿（ビジネス文書・変更履歴・README・利用者への案内など）は、読み手役が確かめる
- この worker に限り、読み手役のサブエージェントを、読み手役の対象の文書 1 件につき最大 2 回立ててよい。2 回目は 1 回目が不合格のときだけ、直した後に立てる
- 実装計画（`plan`）と、「対象」に当たらない種類の原稿（AI への手順書など）は、読み手役を立てずに自分で読み直す
- 読み手役を立てられないとき（Tool が無いなど）は、理由を残し、書いた経緯を知らない読み手のつもりで自分で読み直す

## 確かめの記録

対象の文書 1 件につき 1 つの記録を、結果ファイルの `metrics.readers` の並びに書く。対象の外の文書の記録は書かない。

| キー | 値 |
| --- | --- |
| `doc` | 対象の文書のパス（上の対象の一覧と同じ文字列） |
| `verdict` | `pass`・`fail`（読み手役の最後の結果）、`not_run`（読み手役の対象だが 1 回も立てられなかった）、`self`（読み手役の対象でない文書を自分で読み直した） |
| `checks` | 読み手役の確かめの並び（行った順）。要素は `{"verdict": "pass か fail", "restatements": ["質問ごとの言い直し", …], "reason": "不合格の質問と理由（fail のとき）"}`。`not_run`・`self` では空の並び |
| `reason` | `not_run` では立てられなかった理由、`self` では文書の種類（手順書の「対象」の行の語。例: `実装計画`・`AI への手順書`）、`fail` で 2 回目を行えなかったときはその理由 |

- 設計書は `pass`・`fail`・`not_run` のどれか、実装計画は `self`、原稿はどれでもよい
- `checks` は 1 回目が合格なら 1 つ、不合格で直して読み直したら 2 つ（先頭は `fail`）にする

## 結果ファイル

最後の応答の前に、次の形で結果ファイルを書く（パスは末尾の「結果ファイル」の行）。`items` は足すべき内容ごとに `--item` を 1 つ足す。

```sh
ndf contracts emit --tool worker --status ok --summary "<1 行>" \
  --item '{"text": "…", "doc": "…"}' \
  --metrics '{"readers": [{"doc": "…", "verdict": "pass", "checks": [{"verdict": "pass", "restatements": ["…"]}]}]}' \
  --out <結果ファイル>
```

組み直しを終えられなかったときは `--status stopped --cause work_stopped "<理由>"`、判断が要るときは `--status gate --route retry -` で書く。
