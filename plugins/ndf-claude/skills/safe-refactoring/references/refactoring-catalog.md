# 構造改善の手法と適用条件

各手法は **1 手で完結し、テストで安全を確認できる**単位に分けてある。適用条件を満たさない
場合は、その手法を選ばない。

## メソッドの抽出

| 項目 | 内容 |
| --- | --- |
| 適用条件 | 1 つの関数が複数の段階を通しで行っており、段階に名前が付けられる |
| 手順 | 1. 抽出する範囲を決める 2. 使っている変数を引数に、返す値を戻り値にする 3. 呼び出しに置き換える 4. テスト |
| やめる条件 | 抽出しても引数が 5 個以上になる（範囲の切り方が間違っている） |

抽出後の名前は「何をするか」であって「どうやるか」ではない。`calculateAndSave` のような
名前になったら、2 つに分ける。

## 変数・関数・クラスの改名

| 項目 | 内容 |
| --- | --- |
| 適用条件 | 名前と実態がずれている、同じ概念に複数の呼び名がある |
| 手順 | 参照をすべて洗い出して一括で変える。中身は同時に変えない |
| やめる条件 | 公開インタフェースの場合。互換性の扱いを決めるまで行わない |

## 引数オブジェクトの導入

| 項目 | 内容 |
| --- | --- |
| 適用条件 | 同じ引数の組が複数の関数へ渡り回っている |
| 手順 | 組をまとめた型を作り、呼び出し側から順に置き換える |
| やめる条件 | 引数が 2 個で、まとめる意味のある名前が付かない |

## 値オブジェクトの導入（型による安全化）

| 項目 | 内容 |
| --- | --- |
| 適用条件 | ID・金額・単位・期間などを文字列や数値のまま渡しており、取り違えが起こりうる |
| 手順 | 型を定義し、生成時に検証を寄せる。境界（入出力）で変換する |
| やめる条件 | その値に不変条件がなく、単なる別名になるだけ |

## 条件分岐の平坦化

| 項目 | 内容 |
| --- | --- |
| 適用条件 | 入れ子が深く、正常系が末尾に埋もれている |
| 手順 | 例外的な条件を先に判定して早期に抜ける。正常系を最後に残す |
| やめる条件 | 早期リターンの数が分岐の数と同じで、読みやすさが変わらない |

## 多態による分岐の置き換え

| 項目 | 内容 |
| --- | --- |
| 適用条件 | 同じ種類分けの分岐が**複数箇所**で繰り返されている |
| 手順 | 種類ごとの振る舞いをそれぞれの型へ移し、分岐を 1 箇所（生成部分）に寄せる |
| やめる条件 | 分岐が 1 箇所しかない。種類が増える見込みがない |

分岐が 1 箇所なら分岐のままが読みやすい。**種類が増えるたびに複数箇所を直している**という
事実が、この手法の適用条件である。

## 戦略の切り出し

| 項目 | 内容 |
| --- | --- |
| 適用条件 | 差異が**2 種類以上実在**し、呼び出し側が選択する必要がある |
| 手順 | 共通の入出力を決め、種類ごとの実装に分ける。選択を境界へ寄せる |
| やめる条件 | 差異が 1 種類しかない。将来増えるという予測だけを根拠にしている |

## 責務の移動

| 項目 | 内容 |
| --- | --- |
| 適用条件 | ある処理が、扱うデータを持たないクラスに置かれている |
| 手順 | データを持つ側へ処理を移す。移した先のテストを追加する |
| やめる条件 | 移すと循環参照になる（先に依存の向きを整える） |

## 依存の向きを整える

| 項目 | 内容 |
| --- | --- |
| 適用条件 | 双方向参照・循環依存がある、業務ロジックが外部の仕組みに直接依存している |
| 手順 | 呼ばれる側に入出力の定義を置き、呼ぶ側がそれに合わせる。実体は境界で注入する |
| やめる条件 | 依存が 1 方向で、置き換えの必要がない（間接参照だけが増える） |

## 処理の連鎖への分解

| 項目 | 内容 |
| --- | --- |
| 適用条件 | 1 つの処理が「入力の検証 → 変換 → 判定 → 出力」と直列に進む |
| 手順 | 各段を独立した関数にし、前段の出力を次段の入力にする |
| やめる条件 | 段の間で状態を共有しなければならない |

## 死んだコードの削除

| 項目 | 内容 |
| --- | --- |
| 適用条件 | 参照がないことを検索で確認できた |
| 手順 | 参照検索（動的呼び出し・設定ファイル・外部からの呼び出しも確認）→ 削除 → テスト |
| やめる条件 | 外部の利用者から呼ばれる可能性がある（公開インタフェース） |

削除は履歴に残るため、コメントアウトで残さない。

## 1 手ごとの確認

どの手法でも、適用後に次を確認してからコミットする。

- 対象を通るテストが通る
- 公開インタフェースの入出力が変わっていない
- 差分が意図した範囲だけに収まっている（整形の巻き込みがない）
