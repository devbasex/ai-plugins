# PR Test Plan実行

`/ndf:pr`で作成されたPRのTest Plan（チェックリスト形式）を読み取り、各テスト項目を自動実行する。

**制約**: テスト実行と結果報告のみ。コード修正・git操作・ファイル編集は行わない。

## 引数

- PR番号（オプション）: 省略時は現在ブランチから自動検出

## 手順

1. **PR情報取得**: PR本文からTest Planセクションの`- [ ]`項目をパース
2. **テスト実行計画**: テスト種類の判定、実行順序の決定、自動/手動の分類
3. **テスト実行**: 各項目を順次実行し成功/失敗を記録
4. **結果反映**:
   - 成功: PR本文の`- [ ]`を`- [x]`に更新
   - 失敗: PRにコメント追加（問題点・対策案・エラー詳細）
5. **最終報告**: テスト結果サマリーをPRにコメント（総テスト数、成功/失敗/スキップ数、成功率）

## 限定的な検証と全体テストを区別する

Test Plan の項目を実行したことは、**全体が通ったことを意味しない**。両者を分けて報告する。

| 区分 | 内容 | 報告の書き方 |
| --- | --- | --- |
| 限定的な検証 | Test Plan の項目に対応する絞り込み実行 | 絞り込み条件を明記する（`pytest -k orders` など） |
| 全体テスト | 変更範囲外を含む全実行 | 実行したなら結果を、していないなら**未実行と明記** |

Test Plan に全体テストの項目がない場合、勝手に「全体も通った」と書かない。実行していない
なら未実行と書く。完了判定の段階分けは `quality-gates`（未導入なら対象プロジェクトの
手順）に従う。

## 証跡として残すもの

各項目について次の 4 つを記録する。1 つでも欠けたら、その項目は「実行した」と言えない。

| 記録 | 例 |
| --- | --- |
| 実行コマンド | `pytest tests/orders -q` |
| 終了コード | `exit=0` |
| 実行時刻 | `2026-08-13 10:21` |
| 対象範囲 | 絞り込み条件、または「全体」 |

```markdown
## テスト結果

| # | 項目 | コマンド | 対象範囲 | 実行時刻 | 終了コード | 結果 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 一覧が降順で並ぶ | `pytest -k order_desc` | 限定 | 2026-08-13 10:21 | 0 | 成功 |
| 2 | 全体テスト | `pytest` | 全体 | 2026-08-13 10:25 | 1 | **失敗**（下記） |
| 3 | 手動確認: 画面表示 | — | 限定 | 2026-08-13 10:30 | — | 成功（確認者と確認内容を記載） |

未実行: なし
```

- 出力は要約せず、失敗部分と集計行をそのまま貼る
- **実行していない項目を成功にしない。** 実行できなかった項目は理由を書いて未実行とする
- 手動確認の項目は、誰が何を見て判定したかを書く（コマンドがないため終了コードは省く）
