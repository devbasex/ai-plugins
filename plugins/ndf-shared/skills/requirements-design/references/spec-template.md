# 仕様の雛形

「何を満たすか」だけを書く。タスク分解・対象ファイル・実装順序は書かない（それらは
`implementation-plan` の担当）。同じ変更で計画も作る場合は、同一ファイルの別の節にする。

不要な節は削る。空の見出しを残さない。

```markdown
## 依頼（原文）

> （依頼された文をそのまま引用する。要約しない）

## 目的

- 何のための変更か。達成したい状態

## 前提

- 前提 1: （決められない点を、後から成否を判定できる文で書く）
- 前提 2:

## 対象範囲

含む:
- （この変更で扱うもの）

含まない:
- （扱わないもの。「今回はやらない」と決めたもの）

## 用語

| 用語 | 意味 |
| --- | --- |
| （依頼文と実装で呼び方が違うもの、業務上の固有語） | |

## 受け入れ条件

- [ ] （観測可能・一意・テスト可能な条件。形式は acceptance-criteria.md）
- [ ] 
- [ ] （起きてはいけないこと・退行しないこと）

## 非機能の条件

| 種類 | 条件 |
| --- | --- |
| 性能 | |
| 容量 | |
| 権限 | |
| 記録 | |

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | （変わる / 変わらない。変わる場合は互換性の扱い） |
| データ | （スキーマ変更・移行の有無） |
| 既存の振る舞い | （変わる場所） |

## 検証手段

| 項目 | 手段 |
| --- | --- |
| 起動 | （コマンド） |
| テスト | （コマンド） |
| 静的解析・型検査 | （コマンド） |
| 手動確認 | （誰が何を見て判定するか。自動化できない条件のみ） |

## 前提とする取り決め

対象プロジェクトの記録（`AGENTS.md` / `README` / 設定ファイル）から読み取れるものは参照先を、
読み取れないものは新たに決めた内容を書く。守るべき規則だけを書き、個別の対象ファイルは
列挙しない（列挙は `implementation-plan` の担当）。

| 項目 | 参照先 / 決めたこと |
| --- | --- |
| プロジェクト構造 | （変更を置く場所と、置いてはいけない場所） |
| コーディング規約 | （準拠する規約と、その確認手段） |
| テスト戦略 | （どの階層のテストで何を担保するか） |

## 境界

| 区分 | 内容 |
| --- | --- |
| 常に行う | |
| 確認してから行う | |
| 行わない | |

## 未決

| 項目 | 誰が決めるか | 期限 |
| --- | --- | --- |
```

## 書くときの注意

- **原文の引用を省かない。** 要約だけを残すと、解釈のずれに後から気づけない
- **受け入れ条件を仕様の中心に置く。** 目的や背景を長く書いても完了判定には使えない
- **未決を空欄で放置しない。** 決まっていないこと自体を書き、誰が決めるかを添える
- 実装中に条件が変わったら、消さずに変更履歴として残す（`SKILL.md` の該当節を参照）
