# `ndf` を確かめ、`$SCRIPTS` を空にする

> 次のスクリプトのサブコマンドは新しいエントリポイント `bin/ndf` にまだ無いため、今の名前のまま残した: `projects-sync.sh`（M7）・`worktree-localenv.sh`（M8）・`worktree-setup.sh`（M8）・`worktree-testenv.sh`（M8）。移行先は[機能の対応表](../../../src/ndf/parity/features.json)の行で、入れ替えの前の試走（T2 #3411）が行ごとに確かめる。

新しいプラグインの機能は `bin/ndf` のサブコマンドである。Skill とエージェントの本文は `ndf` を名前で呼び、プラグインの保存先を探さない。

- Claude Code は、有効なプラグインの `bin/` を Bash の `PATH` へ足す
- Codex と端末は、`PATH` 上に置いた `bin/ndf` へのシンボリックリンクで呼ぶ（`bin/ndf` の冒頭の注記）

## 確かめる 1 行

手順の先頭で次を打つ。`ndf` が見つからなければ、理由を標準エラーへ書いて終了コード 3 で止まる。旧いプラグイン（`plugins/ndf`）へは倒れない。

```bash
command -v ndf >/dev/null 2>&1 || { echo "ndf が PATH に無い: 新しいプラグインを有効にするか、bin/ndf へのシンボリックリンクを PATH に置く" >&2; exit 3; }
SCRIPTS=
```

この 1 行は `tests/skills/test_scripts_lookup.py` が取り出し、`ndf` を含まない `PATH` で打って終了コード 3 を確かめる。

## `$SCRIPTS` が空のとき

`$SCRIPTS` は、まだサブコマンドの無い旧いスクリプト（開いている子が持つもの）の保存先を指す名前である。新しいプラグインだけの起動では、いつも空にする。

旧いスクリプトを呼ぶ行は、それぞれの子がサブコマンドへ置き換えるまで本文に残る。その行は次の 2 つの形のどちらかで書く。

| 形 | 使う場面 | 書き方 |
| --- | --- | --- |
| 飛ばす（既定） | 後の手順がその出力を入力にしない | `[ -n "${SCRIPTS:-}" ] \|\| echo "<スクリプト名> は <子の記号> #<番号> がサブコマンドに置き換えるまで新しいプラグインだけでは打てない。飛ばした"` の後に、`[ -n "${SCRIPTS:-}" ] &&` を付けて打つ |
| 止まる | 後の手順がその出力（書くファイル・終了コード）を入力にしていて、飛ばすと誤った入力で進む | `[ -n "${SCRIPTS:-}" ] \|\| { echo "<スクリプト名> は <子の記号> #<番号> がサブコマンドに置き換えるまで新しいプラグインだけでは打てない" >&2; exit 3; }` |

どちらの形でも本文に旧いスクリプトの名前が残るため、その行は機能の対応表の判定で `failed` として見える。

## シェルが変わったら決め直す

**この値はシェルをまたいで持ち越されない。** コマンドの実行ごとにシェルが分かれる環境では、決めた値は次の実行に残らない。続けて実行するときは 1 つのブロックへまとめ、分かれるならその先頭で決め直す。

手順書がこの値を受け取る場合は、「この文書が受け取る値」の表で定義する（`worktree` の `SKILL.md` がその形である）。

conductor が直に打つサブコマンドは [conductor-entrypoints.md](conductor-entrypoints.md) にある。
