# NDF の版ごとの決定と理由（v10.17.0〜v10.17.48）

`CLAUDE.md` から移した、出た版の記録である。**その版で何を決め、なぜそう決めたか**を残す。
変更点の列挙は `CHANGELOG.md` にあり、こちらは判断の理由を持つ。**`CLAUDE.md` へ書くのは
現行版で決めたことだけで、版を配布した時点でこちらへ移す。** そのため `CLAUDE.md` に版の段落が
1 つも無いことがある（配布の直後がその状態で、現行版で新しく決めたときに書き足される）。

**v10.6.0 から v10.11.0 の判断はここにも `CLAUDE.md` にも無い。** この 8 版は退避の手順を決める
より前、または `CLAUDE.md` へ段落を書かないまま配布された。変更点は `CHANGELOG.md` にある。
退避が働いたのは v10.12.0 の配布からで、**記録の最初の段落が v10.12.0 なのはそのためである。**

**v10.17.9 から v10.17.40 の判断もここにも `CLAUDE.md` にも無い。** この間の版は `CLAUDE.md` へ段落を
書かないまま配布された。変更点は `CHANGELOG.md` にある。

**v6.1.0 から v10.5.1 までの記録は [ndf-version-decisions-v6-v10.5.md](ndf-version-decisions-v6-v10.5.md) に
ある。** v10.15.0 の配布でこの文書が分割の基準（500 行）を超えたため、古い側を分けた。

**v10.12.0 から v10.14.0 までの記録は [ndf-version-decisions-v10.12-v10.14.md](ndf-version-decisions-v10.12-v10.14.md) に
ある。** v10.17.42 の配布で同じ基準を超えたため、同じく古い側を分けた。

**v10.15.0 から v10.16.1 までの記録は [ndf-version-decisions-v10.15-v10.16.md](ndf-version-decisions-v10.15-v10.16.md) に
ある。** v10.17.45 の配布で同じ基準を超えたため、同じく古い側を分けた。

v10.17.0 で待つ間の問い合わせと、長い conductor の会話を止めた（マイルストーン 26「17 トークン消費の
削減」のまとまり 1、#829 #830）。確定仕様は
[ndf-token-waits-and-context-cut.md](specifications/ndf-token-waits-and-context-cut.md) にある。

**規定を書くだけでは守られなかったため、hook で止める**（#829 #830）。`context-window.md` は以前から
「遅くとも 20 万で切る」と定めていたが、#827 の実測で守られていなかった。Claude Code 本体の前景の
`sleep` の制限もサブエージェントには掛からない。**止めるのはループの本体の `sleep` と 5 秒を超える
`sleep` だけにする** ── 前景の `sleep` の費用の 87% がループの中にあり、ループの外の短い間と `for` の
照会の間隔には代わりの手段が無い。**連続 Read は「空」ではなく「変わっていない」で見る** ── hook は
実行の前に呼ばれ、読んだ中身を知らない。

**文脈量の拒否は起動ごとに 1 度にし、同じ起動の 2 回目を通す**（#830）。毎回拒否すると続けると
決めた利用者が同じ工程をやり直せず、会話ごとに 1 度にすると以後のカットポイントで止まらない。案内だけを
足す形は、規定が読み流された実測があるため採らない。**引継ぎの 1 行は `development-workflow` を
起動する形にする** ── 工程 Skill はモード・作業ツリー・承認の状態を戻す手順を持たない。

**hook は Claude Code にだけ置く**（#829 #830）。代わりの待ち方（`run_in_background` の通知と
`Monitor`）と文脈量を読む記録を持つのが Claude Code だけで、#827 の実測も Claude Code の記録だけで
ある。Codex / Kiro / agy は規約と引継ぎの 1 行で守り、CLI 側の消費を測った後に改めて決める。

v10.17.1 で全体テストの待ちを縮めた（マイルストーン 26「17 トークン消費の削減」の 2'、#882 #884）。
計画と実測は `issues/issue-882-884-test-speedup.md` と PR #891 にある。

**継続的統合はファイル単位で 2 つのジョブへ分け、まとめジョブの名前を `pytest` にする**（#882）。
`-n auto` だけではジョブが 2 分を超えた。まとめジョブが必須のチェックの名前を引き継ぐため、ruleset を
変えずに済む。**分け方が項目を落としても各ジョブは成功しうるため、分割の漏れと重なりは継続的統合の
外のテストで見る**（`scripts/tests/test_root_conftest.py`）。**本番のスクリプトを変える高速化は
この版で行わない** ── `bg-wait.sh` の間隔とロックの上限の注入は振る舞いの変更で、`light` の範囲を
超える。#884 は開いたまま残す。

v10.17.2 でサブエージェントに Skill の本文を読ませないようにした（マイルストーン 26「17 トークン消費の
削減」、#828 #680）。確定仕様は
[ndf-worker-agent-and-skill-excerpts.md](specifications/ndf-worker-agent-and-skill-excerpts.md) にある。

**記録の入口は `projects-sync.sh` のまま、issue の本文も同じ 1 行で書く**。通過記録が
このコマンドを観測するため、入口を変えなければ hook の照合を変えずに 3 か所へ残せる。**worker の規則は
文面だけにせず定義で塞ぐ** ── `disallowedTools: Skill, Agent` の拒否の一覧で書く。許可の一覧では書いた
道具が子に現れず、Skill だけを外すと Agent で起こした孫が Skill を使えた。**抜粋は Skill ごとに
`references/excerpt.md` の 1 ファイルに置き、割らない** ── 本文の近くに置けば直す人の目に入り、割ると
本文との対応のチェックが 1 対 1 で結べない。**小さな作業の線引きは固定費との比で書く** ── 閾値の
数で書くと、書いたリポジトリの値が別の環境の値として読まれる。

v10.17.3 で cross-review の席の埋め方と supervisor の待ち方を直した（マイルストーン 26「17 トークン消費の
削減」、#892 #901）。確定仕様は
[cross-review-participants-and-seats.md](specifications/cross-review-participants-and-seats.md) と
[ndf-token-waits-and-context-cut.md](specifications/ndf-token-waits-and-context-cut.md) にある。

**cross-review の母集合にホストを入れ、ホストを別に確かめて埋め合わせに使わない**（#892）。レビュー担当は
CLI プロセスとして起動するため、ホストと同じランタイムでもホストの会話の作業文脈は持ち込まれない。
ホストが使える者に居ないのは確認を通らなかったか外す指定で外したかのどちらかで、前者は確かめ直しても
通らず、後者で席へ戻すと利用者の指定に反する。**状態ファイルに版を持たせない** ── ホストだけを持つ
状態の再開の分岐 1 つにだけ変更の前の母集合を式で置けば足り、版を持たせると書く側と読む側の両方に
扱いが要る。**supervisor は完了の目印の出現を自分の背景の処理として待つ**（#901）── worker は
supervisor の背景の子に数えられず、応答を終えた supervisor は worker が終わっても起こされない。待つのを
待つ対象を `置き場所` の中身にせず別ファイルの目印にしたのは、書きかけの複製や長い出力に反応しないためで、
起動の前に目印を消すのは前の worker の目印で即座に終わらないためである。

v10.17.4 でカットポイントの再起動と次のコマンドの入力を前景のラッパーに任せた（マイルストーン 26「17 トークン
消費の削減」、#895）。確定仕様は
[ndf-relay-segment-restart.md](specifications/ndf-relay-segment-restart.md) にある。

**ラッパーは端末の前景に常駐し、claude を擬似端末の子として起動する形だけにする** ── 前提が端末と
Python 3 だけになり、tmux の有無を確かめる処理が要らない。2 つの形を持つと使われない側が古くなる。
**区間の終わりは最後の応答の `ndf-next` のブロック 1 つで決め、関門は区間の中で `AskUserQuestion` の
まま受ける** ── 画面の文言から関門を読むと、Claude Code の版で文言が変わったときに関門の前で切る。
**始められない・止まると決めたときは今までどおりの手動の運用へ落ちる** ── 止めると、前提をそろえる
まで claude を起動できない。**alias はシェルの設定へ目印のついた囲みで 1 度だけ足し、消されたら足し
直さない** ── 利用者が明示に自動を求めた。囲みの外は書き換えず、消したのは利用者の判断である。
**背景の処理が動いている Stop では合図を書かない** ── 切ると supervisor が子の claude と一緒に終わる。

同じ v10.17.4 で、`.md` の文言を照合するテストを削り、書かない方針をテストの規約へ入れた（#885）。
設計は `issues/issue-880-885-design.md` の「テストと規約（F10・F11）」と「#885 の棚卸」にある。

**文書の文言を固定するテストを書かない** ── 文書の振る舞いは文言そのもので、同じ文面を渡しても同じ
結果が返るわけではない。固定しても振る舞いは保証されず、文書を整えるたびに期待値を書き換える手間と、
構造改善が文書の整理を「振る舞いの変更」として取り消す副作用だけが残る。**残すかどうかは「その `.md` を
スクリプトが実行時に読むか、テストがその中のコードを実行するか」の 1 問で決める** ── どちらでもなければ
削る。埋め込んだ bash を実行するテストと、スクリプトが実行時に読むプロンプト・表を通すテストは機械が
読む契約を見ているため残す。**工程表とシェルの定数の一致を見ていたテストもチェックスクリプトへ寄せずに
削った** ── 工程表を実行時に読むスクリプトは無く、食い違いはレビューで見る。**受け入れ条件の検証手段にも
しない** ── 文書の変更を求める条件は、該当の節を読んで証跡に書く。

v10.17.5 で cross-refactoring を是正した（マイルストーン 26「17 トークン消費の削減」、#880 #883 #494 #723）。
確定仕様は
[cross-refactoring-round-tests-and-assess.md](specifications/cross-refactoring-round-tests-and-assess.md) にある。

**群と修正コミットの検証はラウンドのテストで行い、全体のテストは `init` と最終ゲートの 2 回に限る**──
範囲の外を触ったコミットは範囲のチェックで落ちるため、群ごとに全体を走らせてもラウンドのテストより多くは
分からない。範囲の外への波及は最終ゲートの 1 回で見る。**ラウンドのテストは明示の引数にし、`--scope` から
組み立てない** ── テストのコマンドの形はリポジトリごとに違い、範囲を決めた起動する側がラウンドのテストも
決める。**省けば前と同じ検証をし、範囲より広い全体のテストには案内だけを出す** ── 互換を保ち、広いことは
誤りではなく時間がかかるだけである。**単独の起動でも 2 つのテストが違えば最終ゲートで全体のテストを
1 回走らせる** ── 単独の起動では範囲の外への波及を見る機会がほかに無い。**最終ゲートの修正のコミットは
テストを走らせない** ── `--ci-check` の実行で手元のテストを走らせない排他（#436）と衝突せず、全体のテストの
失敗を直す修正はラウンドのテストでは直ったか分からない。**打ち切りは親シェルを回収してからグループの存否を
見る**（#883）── 親の終了だけで打ち切ると、SIGTERM を無視する子がグループに残って作業ディレクトリを
書き換え続ける。**飛ばす条件は「本番コードの差分が無い、または変更が 10 行以下」とし、差分から機械で
判定する**（#494）── 「改善の対象になる構造を持たない」は機械で決まらないため行数で近似した。判定は
`refactor.py` に置き（テストの置き場所の知識を cross-refactoring が持つ）、飛ばしたときも工程「構造改善」を
記録して区別は Pull Request の本文の 1 行に持たせる（工程の値を増やすとボードの単一選択と hook の観測の形に
響く）。**文言固定テストは提案の取り込みと適用の検証の 2 か所で弾き、誤検知は群の取り消しの側に倒す**
（#723）── 提案の基準だけでは担当が書いたテストに混じったときに止まらない。追跡している `.md` との一致で
判定すれば、一時ファイルの `.md` を入力に渡すチェックスクリプトのテストは弾かない。

v10.17.6 で cross-review のラウンドを減らした（マイルストーン 26「17 トークン消費の削減」、#542 #786）。
確定仕様は [cross-review-round-inputs.md](specifications/cross-review-round-inputs.md) と
[cross-review-participants-and-seats.md](specifications/cross-review-participants-and-seats.md) にある。

**既定の母集合から agy を外し、claude / codex / kiro とホストにする**（#786）── agy はテストを背景で
起動して結果を残さずに終わることがあり、起動し直しても残らなければ収束が止まる。実運用は既に毎回
`--exclude agy` を渡していた。プロンプトの指示だけで直す案は採らなかった ── 担当が従うかを確かめる
手段が無く、従わなかったときの損失（収束の停止）が大きい。**母集合に無い者の `--exclude` は止めずに
無視して 1 行で知らせる** ── `--exclude agy` を書いた既存の手順が止まらずに通る。無視した名前は外した者と
分けて記録し（同じ記録にすると後から母集合を読み違える）、判定は共通層に置いて cross-refactoring も
同じにする（同じ引数の意味を Skill で変えない）。**`--only` で名指しした者は母集合に無くても参加者に
する** ── 名指しした時点で意図は明らかで、2 つの引数で書かせない。**1 ラウンド目から出し切りを求め、
出す対象は修正アクションのある指摘に限る**（#542）── 出し切らない指摘は修正の後のラウンドで新しい
指摘として数えられてラウンドを 1 つ増やし、nit は収束を止めないため網羅させてもラウンドは減らない。
**既存コメントのスナップショットをラウンドの開始ごとに取り直し、失敗しても止めない** ── 前のラウンドの指摘と返信を
知らない担当が同じ場所を再び指摘すると振動の検知に当たる。前のスナップショットでも今と同じ条件でレビューできる。
**取り直しは 1 つの取得元でも失敗したら前のスナップショットを残す（`--strict`）** ── 一部だけのスナップショットで上書きすると、
前のラウンドの指摘が重複の検出から消える。**取り直しは round エントリの保存の前に行う** ── 保存の後だと
割り込まれたときに結果の無い round が残り、再実行が止まる。**レビュー担当にはテストも背景の処理も
起動させず、cross-refactoring の適用担当にはテストを前景で待たせる** ── 実行の確かめは進行側の
`verify-findings` が行い、背景の起動は結果を書かずに終わる経路になる。適用担当はラウンドごとに 1 回
テストを実行する設計である。**設計 Pull Request はファイル名の規約で見分け、観点テンプレートを足す** ──
設計の文書に特有の穴（3 文書の食い違い・状態の書き手の衝突・外部ツールの挙動の事実誤認）は今の観点に
無く、成果物を増やすとすべての設計の手間が増える。観点を組む入力は変更ファイルでありブランチ名ではない。
**収束の判定・振動の検知・`max_rounds`・起動し直しは変えず、#631（母集合の全員が見るまで収束しない）は
採らない** ── 同時に変えるとどれが効いたかを分けられず、#631 はラウンドを増やす方向である。**前の
ラウンドからの変更の節は #934 へ移した** ── 出し切りとスナップショットの取り直しの効果を先に測る。

`CLAUDE.md` の cross-review の節の「ndf 10.17.5 の次の版で」の目印は、この版で外して現行の使い方として
残した。段落の途中の目印は `instructions-check.py` が拾わないが、目印が指す版がこの版であるため、
v10.17.5 の cross-refactoring の箇条と同じ扱いにした。

v10.17.7 でラッパーの導入を利用者の明示の操作にし、再起動のコマンドと関門を越えない守りを足した（マイルストーン 26、
#928 #936）。確定仕様は [ndf-relay-install-and-restart.md](specifications/ndf-relay-install-and-restart.md) にある。

**SessionStart hook はシェルの設定を書かず、導入は明示指示専用の `/ndf:install-wrapper` だけにする** ──
利用者のシェル設定を黙って書き換えない。書く前にバックアップを取り `uninstall` で戻せるので、実行前の
確認は置かない。**導入・取り外し・状態の表示は 1 つの Skill の引数で分ける** ── 別の Skill にすると
同じ囲みと記録を 2 つの本文が説明し、片方だけが古くなる。**10.17.4〜10.17.6 の自動の囲みは残し、1 度だけ知らせる**
── hook が消すのはまた黙った書き換えになり、リリースノートだけでは読まない利用者が知る手段が無い。
**複製とラッパーの rc は Claude Code の設定の親（`~/.claude/ndf/`）に置き、シェルの設定には読む 1 行だけを
置く** ── devbase で永続化されるのは設定の親だけで、定義の形が変わっても書き換えるのは ndf の持つ
ファイルだけで済む。**定義は `function claude { ... }` の関数にし、呼んだ時点で複製が無ければ素の
`claude` を起こす** ── alias は複製の有無を起動時にしか見ず、先の `alias claude=...` があると `claude()`
の形は展開されて壊れる。**devbase では `DEVBASE_SHELLRC_DIR` の `ndf-relay.sh` に置く**（devbasex/devbase#253）
── devbase の `~/.bashrc` はイメージの層にあり作り直しで消える。**複製の横に版を書き、新しい版の複製を
古い版の `startup` は置き直さない** ── 複製の親はコンテナの間で共有され、古い版が守りの無い複製へ戻す。
明示の `install` は版を比べずに置き、過去の版へ戻す手段にする。

**再起動は `ndf-next` のブロックと既存のラッパーの経路で行う** ── 答え待ち・背景の処理・静止・上限・
空回りと守りがそのまま効く。ラッパーの下かは `NDF_RELAY_DIR` の有無でなく `relay.py is-child` で決める
（Bash から起こした `claude -p` も変数を継ぐ）。ラッパーの外では、シェルの 1 行でなく貼り付ける中身を示す
（引用が壊れて別のコマンドが動きうる）。**再開用のコマンドに承認・同意・判断の結果を書かない** ──
次の区間の claude が人の入力として読み、関門を越える経路になる。

**関門を越えない守り（G1〜G3）は送り込み（#931）を待たずに既存の `/exit` に入れる** ── 質問の表示中に
ラッパーが書いた `\r` が選択肢 1 を決めると実測で分かった。質問は画面の文言でなく `PreToolUse` の hook の
