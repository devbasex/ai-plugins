# ndf の版ごとのトークン消費と所要時間（2026-09-24 集計）

**10.17.0〜10.17.7 の版ごとの差を、cache read の換算をモデル別に直した値で記録する**（#893 の受け入れ条件 4・5）。
あわせて、起動ごとの固定費 P・呼び出し回数 k・全体の書き直しの回数と直前の間隔・書き込みの 5 分 / 1 時間の
内訳を、版・持ち場・CLI の席ごとに載せる。生の記録・会話の本文・リポジトリ名・会話の ID は残していない。
**集計した日時点の記録で、以後の記録の増減には追随しない。**

## 作り方

```bash
python3 scripts/token-usage.py --min-version 10.14.0 --by version                 # 末尾の「集計の出力」
python3 scripts/token-usage.py --min-version 10.14.0 \
  --by version,mode,model,cc,reviewers --format json                              # 2026-09-24.json
```

「10.17.x の版ごとの差」と「版と層ごとの呼び出しとキャッシュ」の 2 つの表は、`--by version --format json` の
`per_pr` と `per_role` を版（と層）でまとめ直したものである。

## 前の基準（2026-09-23）からの変更

- **cache read の換算をモデル別にした。** 倍率は `scripts/token-usage.py` の `READ_RATES` が正本で、
  claude-opus-5-5 は 0.05・claude-fable-5-1 は 0.025・他は 0.1（公式の料金表、2026-09-24 に確認）。
  呼び出しごとに `message.model` で引く。**10.16 以降の Opus 5.5 の換算は、前の基準より 2〜3 割小さい**
  （10.16.0 の PR 1 本あたり supervisor 5.12M → 3.85M）。10.14.0 は claude-opus-5 だけのため変わらない
- **P・k・書き直し・書き込みの内訳を足した。** 定義は「集計の出力」の表の前の説明にある。書き直しは
  2 回目以降の呼び出しだけを数える（最初の呼び出しは P に入る）。間隔は記録の行の時刻の差で、応答が
  書かれた時刻どうしの差である

## 比べるときの注意

- **10.17.x は版ごとの件数が少ない。** PR を作った会話が 1〜3 件で、作業の中身の違いが版の違いより大きい。
  10.17.2 は conductor だけで進めた会話 1 件（PR 2 本）で、他の版と形が違う
- **10.17.4 は表に出ない。** その版で始めた会話が無い（会話の版は最初に読んだ版で決まる）
- **10.17.7 は集計の時点で進行中の会話を含む。** 値は途中までの分である
- **モデルは 10.16.0 以降 claude-opus-5-5 だけである。** 換算の差はモデルの差を含まない
- **conductor の書き込みは 1 時間、サブエージェント（supervisor・worker）は 5 分である。** 書き直しの
  ほとんどが supervisor にあり、その多くは直前の間隔が 5 分を超えている（待ちの後にキャッシュが切れた）
- **外部 CLI の席の P・k は「集計の出力」の最後の表にある。** codex は input のうち cached に当たらなかった
  分を書き込みとみなす。kiro は記録にトークン数が無いため、呼び出し回数（ターン数）だけを載せる
