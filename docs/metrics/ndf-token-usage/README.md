# ndf の版ごとのトークン消費の記録

**正式版を出すたびに、版ごとのトークン消費と所要時間の記録を 1 組（`<集計日>.md` / `.json`）残す。**
手元の記録（`~/.claude/projects` など）は 90 日で消えるため、版ごとの差をあとから比べられるように
配布の Pull Request へ含めてコミットする。生の記録は残さない。

## 例: 10.17.9 を正式版として出すとき

`/ndf:release` の手順 3 で `.ndf/release.json` の段が走り、次を実行する。

```bash
python3 scripts/token-usage-snapshot.py --released 10.17.9
```

出力の例:

```text
書き出した: 2026-09-30.md / 2026-09-30.json（表は 10.17.7 から）
差の大きい版: 10.17.8（+45%）
```

表・比べるときの注意・作り直すためのコマンドはスクリプトが書く。**エージェントが書くのは、
「差の大きい版」に挙がった版の読み取りだけである**（下の手引き）。挙がった版が無ければ
何も書かない。

## 記録の中身

| 節 | 中身 | 書き手 |
| --- | --- | --- |
| 作り方 | 同じ値を作り直すコマンド（打ち切りの時刻つき） | スクリプト |
| 比べるときの注意 | PR を作った会話が 2 件以下の版・`CHANGELOG.md` にあって表に出ない版・打ち切りの 30 分前以降にも行がある会話を含む版 | スクリプト |
| 版ごとの差（PR 1 本あたり） | 前の記録の最後の版から今までの版。各行に 1 つ上の行との比 | スクリプト |
| 版と層ごとの呼び出しとキャッシュ | P・k・書き込み・書き直し | スクリプト |
| 読み取り | 差の大きい版ごとに 1〜3 行 | **エージェント** |
| 集計の出力 | `token-usage.py --by version` の Markdown | スクリプト |

- **表の最初の行は前の記録の最後の版である。** 記録どうしが 1 行ずつ重なり、差が途切れずにつながる
- **ファイル名は打ち切りの時刻の UTC の日付である。** 同じ日に別の版の記録があれば `-2`・`-3` を付ける。
  同じ版で走らせ直すと同じファイルへ書き直す（このとき、書き足した読み取りも消えるため書き直す）
- `.json` の形は `token-usage.py --by version,mode,model,cc,reviewers --format json` と同じで、`meta` に
  `released`（配った版）と `previous`（前の記録のファイル名）を足してある

## 読み取りの手引き

**「読み取り」の節の 1 行（差の大きい版の一覧）を、版ごとの 1〜3 行へ置き換える。** 差の大きい版とは、
「版ごとの差」の表で前の行との比が ±30% を超えた版である。内に入る差は作業の大きさのばらつきと
区別できないため、読み取りを求めない。

書くのは、**その差が作業の中身の違いか、版の変更の効果か**である。値の上下はスクリプトが表に
書いているため、繰り返さない。

| 見るもの | 何が分かるか |
| --- | --- |
| 「比べるときの注意」にその版が挙がっているか | 件数が少ない・進行中を含むなら、作業の中身の違いである見込みが高い |
| conductor / supervisor / worker のどれが動いたか | 1 つの層だけが動いたなら、その層に効く変更か、その層だけで進めた作業の形の違い |
| 「版と層ごとの呼び出しとキャッシュ」の P・k・書き直し | P が動けば起動ごとの固定費（読み込む文書）の変化、k が動けば作業の長さ、書き直しが動けば待ちとキャッシュの切れ方 |
| `CHANGELOG.md` のその版の節 | 変わった振る舞いが、動いた層と値に結び付くか |

書き方の例（10.17.2 のように conductor だけで進めた会話の版）:

```markdown
- **10.17.2（-17%）**: conductor だけで進めた会話 1 件で、supervisor・worker の換算がほぼ 0。
  作業の形の違いで、版の変更の効果ではない
```

**会話の本文・ファイルのパス・リポジトリ名・会話の ID を書かない。** 記録はコミットされる。
結び付けられないときは「作業の中身の違いと版の効果を読み分けられない」と書き、推測で理由を作らない。
