# NDF の開発の費用と速さ（2026-11-10 時点）

**token の消費と開発時間を抑えるために、何が問題なのかを洗い出した記録である。** 2026-11-10 時点の値で、以後の記録の増減には追随しない。
集計値は同じ名前のディレクトリ [2026-11-10/](2026-11-10/) に CSV で置く。

## 具体例: cross-refactoring の 1 回

PR #2889（スプリント lcore-12）の cross-refactoring は、60 分の時間枠を次のように使った。

| 段階 | 秒 |
| --- | --- |
| 着手前のテスト | 699 |
| 提案（各 CLI） | 814 |
| 実装 | **61** |
| その後の CI の待ち | 約 900 |

提案は出たが、実装に回せた時間はほとんど無く、提案の大半が「時間」を理由に見送られた。10 月以降に件数を数えられる 72 回の合計では、
提案 1,297 件のうち採用は 234 件（18%）で、見送りの 72% が時間を理由にしている。この 1 回に、下で述べる問題のうち 3 つ
（テストの肥大・cross-refactoring の時間配分・同じ課題への個別の修正の繰り返し）が重なっている。

## 結論

**4 つの仮説はつながっている。根はテストの肥大である。** テストが重くなり、その時間が cross-refactoring の時間枠を食って空振りが増えた。
空振りへ個別の修正を重ね、同じ課題の起票が続いている。費用の最大の要因は、仮説とは別の「大きな文脈の読み直し」だった。

| 仮説 | 判定 | 主な根拠 |
| --- | --- | --- |
| 1. cross-refactoring が機能していない | **支持** | 採用率 18%（11 月は 10.7%）。見送り 960 件の 72% が時間を理由にする。採用 0 件の回が 21 回 |
| 2. テストに時間が掛かりすぎる | **支持** | テスト関数は 1,041（09-01）→ 8,772（11-10）。CI の pytest の中央値は 2.3 分 → 14.6 分。手元の全体テストは 96 秒 → 671 秒。文書だけの設計 PR でも全体の pytest が走る |
| 3. 根本原因を直せず個別の対処が続く | **部分的に支持** | cross-refactoring の時間配分だけで 12 件を個別に直し、根本の見直し #2457 は open のまま。`parallel_run.py` は 7 日で Fix が 34 件。一方で #724・#734 のように根本で直して再発していない例もある |
| 4. スクリプトにできる所を AI に任せている | **部分的に支持** | 機械的なターンは全期間で約 $3.0k（18%）。9 月に `merge-when-green` と `supervise.py wait` を入れて減ったが、11 月に `python -c` での JSON の読み解き（700 回/週）と `tmux capture-pane` がまた増えた |

## 費用（token）

全期間（2026-08-08〜11-10）の費用は約 $17.2k（token から換算。換算表は「作り方」）。

### 層と起動の形

| 層 | 全期間 | 直近 4 週（10-12 以降） | 1 回の呼び出しの平均文脈 |
| --- | --- | --- | --- |
| conductor | 39% | 27% | 25 万 token |
| supervisor（`ndf:supervisor` と旧形式の general-purpose のサブエージェント） | 9% | 3% | 18 万 token |
| worker（サブエージェントと、supervise.py のプランが出す `claude -p`） | 42% | 57% | 15 万 token |
| 相手役（cross 系の `claude -p`） | 9% | 12% | 6 万 token |

層は 3 層の正本（`plugins/ndf/skills/development-workflow/references/agent-layers.md`）に合わせた。supervise.py はプランを流すスクリプトで、
supervisor の役割を担うが、各ステップの作業は worker（毎回新しい `claude -p`）が行う。そのため supervise.py が起こす `claude -p` の費用は worker に数える。
平均文脈は（入力 + cache 作成 + cache 読み込み）÷ 呼び出し数である。

- **conductor の費用の 71% は、文脈が 20 万 token を超える呼び出しである。** 長い `/goal` のセッションが毎回の呼び出しで大きな文脈を読み直している
- **worker・相手役の費用の 49〜62% は cache の作成である。** `claude -p` とサブエージェントを起動するたびに、文脈の書き込みが発生する
- 上位 20 セッション（いずれも 9 月のマイルストーン単位の `/goal`、最大は 93 時間・$934）で費用の 38%、上位 100 で 60% を占める

### supervisor のサブエージェントと supervise.py

supervisor の役割は、Agent で起動するサブエージェント（`ndf:supervisor` と旧形式の general-purpose）か、supervise.py のプランが担う。
サブエージェントの形では費用が supervisor の層に、supervise.py の形では各ステップの worker（`claude -p`）の層に付く。
下の表は、フェーズを通すための費用を 2 つの形で比べる（サブエージェントの形が起動した worker の費用は含めない）。

| 方式 | 起動数 | 費用 | 2 つの形の合計の中の比率 |
| --- | --- | --- | --- |
| サブエージェント | 169 回（フェーズ単位） | $1,527 | 37% |
| supervise.py | 2,333 回（ステップ単位） | $2,622 | 63% |

09-21 の週を境に入れ替わり、11-02 の週以降はほぼすべてが supervise.py である。フェーズ 1 回の費用の中央値を Opus 5.5 の単価にそろえて比べると、次のとおりである。

| フェーズ | サブエージェント | supervise.py（プラン 1 本、帳簿の 10-25 以降） |
| --- | --- | --- |
| 設計 | $11.0 | $7.1 |
| 実装 | $6.4 | $2.2（平均 $4.3） |
| 検査 | $7.5 | $8.1 |
| 仕上げ（close） | $2.9 | **$8.2** |

- 設計と実装は supervise.py のほうが 3〜6 割安い。サブエージェントは報告の本文を conductor の文脈へ返すため、その読み直しの費用（表に含めていない）も加わる
- 仕上げのプランだけが約 3 倍に上がった（34 本で $295）。原因は #2914 で調べる
- 単位は完全にはそろわない。supervise.py のプランは課題ごとで、9 月のサブエージェントのフェーズは複数の課題を扱った回を含む可能性がある

## データの欠けと不確かさ

- 会話を残さない `claude -p` は transcript が無い。10-25 以降は使用量の帳簿から補った（$890）が、それ以前は数えられず、supervise.py の worker の費用は少なめに出ている
- token から換算した額は、transcript の cost-state の合計（$14.9k）より 8% 高い。Opus 5 と Fable の単価は推定である
- Skill への帰属は 37% だけが記録（`attributionSkill`）によるもので、残りは直前に起動した Skill へ寄せた。conductor のターンの 27〜39% は工程を判別できない
- GitHub の実行の一覧は 09-25 以降の 22,700 件で止めた（API の 502）。pytest のワークフローは全 4,897 件を取れている
- 課題と PR はブランチ名の `issue-N` で結んだため、リードタイムが出たのは 372 件である。不具合の部位は題のキーワードによる近似である

## 作り方

- **費用**: `/persistent/group/.claude/projects/` の transcript のうち ai-plugins に関わる 1,037 ディレクトリ（12,118 ファイル）を読み、assistant の行の `message.usage` を `message.id` ごとに 1 回だけ数えた。使用量の帳簿（`plugins/ndf/scripts/usage-report.py --ledger claude|codex|kiro`）で突き合わせた
- **層**: 対話の main ファイルを conductor、subagents の `agentType` が `ndf:supervisor*` のもの（と旧形式の general-purpose の supervisor）を supervisor、cross-review・cross-refactoring の相手役の `claude -p` を相手役、supervise.py などのスクリプトが起こす `claude -p` と残りのサブエージェントを worker とした。起動の形は `entrypoint`（`cli` / `sdk-cli` / `sdk-py`）で分けた
- **層の数え直し（2026-11-12）**: 初版は supervise.py が起こす `claude -p` を supervisor に数えていた。`usage/total_by_layer.csv`・`usage/last4w_by_layer.csv`・`usage/week_by_layer.csv` は役割別の集計（`*_by_role.csv`）から 3 層の正本どおりに組み直した（試験の行の割り当ての違いで conductor が $0.5 動く）。`usage/*_by_layer_launch.csv`・`usage/mechanical_turns_by_layer.csv`・`usage/tool_wait_by_layer.csv` は生データが無く組み直せないため、初版の割り当て（`supervisor` に supervise.py の `claude -p` を含む）のまま置く
- **工程**: 帳簿のプラン名とステップ名を工程表の行へ写し、無いものは Skill 名か worker の説明の語から割り当てた
- **換算表**（100 万 token あたり。入力 / 出力 / cache 作成 5 分 / 1 時間 / cache 読み込み）: Opus 5.5 は 4 / 20 / 5 / 8 / 0.2（帳簿の 2,841 行に誤差 0 で一致）、Opus 5 は 5 / 25 / 6.25 / 10 / 0.5（推定）、Fable 5.1 は 8 / 40 / 10 / 16 / 0.4（推定）
- **成果**: `gh issue list`・`gh pr list`・`gh run list`・`git tag --contains`・PR の「改修計画」コメント（cross-refactoring の 146 件）・cross-review の投稿（707 PR、4,192 件）・`.ndf/loop/*/laps.md`
- **置かなかったもの**: セッションごとの一覧（会話の ID と最初の入力を含む）、取得した生データ、集計のスクリプト（パスがこのホストに固定されている）
