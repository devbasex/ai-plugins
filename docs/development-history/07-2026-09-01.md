# 開発履歴と知見 (2026-09-01)

**期間**: 2026-09-01
**対象**: [#161](https://github.com/devbasex/ai-plugins/issues/161)（設計工程の Skill）と、
その配布（v9.6.0）

設計工程の Skill（`design`）を新設し、あわせて「設計レビュー」の工程を工程表へ足した。
**新しく足した設計レビューの工程を、それを定義する変更自身で通した。** 要求仕様と設計だけを
載せた Pull Request（#212）を先にマージし、その後で実装（#218）を出している。

## 何が起きたか

### 設計を先にレビューへ通すと、実装の指摘の質が変わった

2 本の Pull Request のレビューの内訳を数えた。どちらも `cross-review`（codex + gemini）で
収束させている。

| Pull Request | 内容 | ラウンド | 指摘 | 内訳 |
| --- | --- | --- | --- | --- |
| #212 | 要求仕様と設計 | 6 | 12 件 | critical 2 / major 8 / minor 2 |
| #218 | 実装 | 3 | 6 件 | critical 0 / major 2 / minor 4 |

**設計の段階で出た critical 2 件は、実装まで進んでいれば文書とコードの両方を書き直すことに
なる内容だった。**

- 設計 Pull Request が課題を自動で閉じる語を含むと、実装が残っている段階で課題が閉じる
- 設計をマージした後、実装用の作業ツリーを作り直す手順が抜けていた（`merged` が設計の
  ブランチと作業ツリーを消すため、そのままでは実装を続けられない）

どちらも工程の設計そのものの抜けで、実装の後では手順を書き直すことになる。

実装の段階で出た 6 件は、表の項目の漏れと語の揺れが中心だった（critical 0 件）。

### レビュー用の作業ツリーが、ラウンド開始時に同期されない

`cross-review` のラウンド 5 で、ラウンド 4 と同一の指摘が 2 件再掲された。原因は、レビュー用の
作業ツリーが 1 コミット古い状態で読まれたことである。

```console
$ git -C /tmp/ndf-worktrees/devbasex--ai-plugins/pr212 rev-parse --short HEAD
2066e91
$ git -C /work/ai-plugins rev-parse --short origin/feature/issue-161-design-phase-skill
2a03298
```

同期は作業ツリーの作成時と再開時にあり、`start-round` には無い。**修正をレビュー用の作業ツリーの
中で行う前提の設計**であるため、開発の作業ツリー側で直して push すると取り残される。

振動検知は働かなかった（`overlap=0/2 (0%)`）。同じ趣旨の指摘でも、文字列の重なりでは拾えない
場合がある。

実装の Pull Request（#218）では、ラウンド開始前に `git fetch` と head への同期を挟んで回避した。
3 ラウンドとも再掲は出ていない。

### 確定仕様化の工程を飛ばしかけた

`architecture` モードでは確定仕様化（`plan-to-spec`）が必須だが、Pull Request のマージから
後片付け・配布へ直接進みかけた。振り返りの手前で気づいて実施している。

盤面（GitHub Projects）へ記録していた `stage` は `Pull Request` の次が `後片付け` になっており、
**工程表にある `確定仕様化` を経由していない**ことが記録の側にも残っていた。

## 次に変えること

| 変えること | 落とし先 | 状態 |
| --- | --- | --- |
| `cross-review` がラウンド開始時にレビュー用の作業ツリーを Pull Request の head へ同期する | `cross-review` の `start-round` | [#217](https://github.com/devbasex/ai-plugins/issues/217) として起票 |
| 工程を飛ばしたことに気づける手立てを持つ（盤面の `stage` の遷移が工程表の並びと合っているかを見る） | `development-workflow` または `merged` の手順 | [#221](https://github.com/devbasex/ai-plugins/issues/221) として起票 |

**設計レビューの工程そのものは変えない。** 上の実測のとおり、設計の段階で工程の抜けが 2 件
出ており、この 1 周分のレビューが実装の書き直しを防いでいる。
