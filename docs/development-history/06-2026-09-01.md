## 何が起きたか

### 新しい工程は、最初に実行したときに手順の誤りを出す

`release` の手順 3（版と説明文書を更新する）を実行して、**手順そのものの誤りが 3 件**出た。
どれも書く時点では気づけず、実行して初めて分かった。

| 誤り | どう分かったか |
| --- | --- |
| 「版数は 4 箇所」が誤りで、実際は 6 箇所（2 つの `plugin.json` は `version` と `description` の両方に版数を持つ） | 検査が push を止めた |
| 検査に載らない版数が 7 箇所ある。うち 3 箇所は書かれたとおり実行すると失敗する（存在しないキャッシュパスなど） | レビューが指摘した |
| 「タグはまだ 1 つもありません」がマージ後に嘘になる | レビューが指摘した |

2 つ目は**「6 箇所」と断言したこと自体が原因**である。断言を読んだ側は 6 箇所を直して終わりに
する。実際にそうなり、レビューで指摘された。断言を「検査が見る 6 箇所」と「手で直す 7 箇所」へ
分けた。

### 文書の Pull Request で手戻りが最も多かった

このセッションで回した cross-review は 5 本・14 ラウンドで、1 本あたり 2.8 ラウンドだった。
[#156](https://github.com/devbasex/ai-plugins/issues/156) に記録した導入前の基準値
（17 本・平均 4.1 ラウンド）より少ない。

| Pull Request | ラウンド | 内容 |
| --- | ---: | --- |
| [#205](https://github.com/devbasex/ai-plugins/pull/205) | **7** | リリースタグと取り消し手段、形ごとの分割 |
| [#208](https://github.com/devbasex/ai-plugins/pull/208) | 3 | v9.5.0 の配布 |
| [#204](https://github.com/devbasex/ai-plugins/pull/204) | 2 | cross-review の作業ツリー同期 |
| [#192](https://github.com/devbasex/ai-plugins/pull/192) | 1 | 配布の工程 |
| [#200](https://github.com/devbasex/ai-plugins/pull/200) | 1 | Kiro の文脈量 |

**#205 の 7 ラウンドは、すべて「書いたとおり実行すると失敗する記述」だった。** 存在しない
タグを例に出す、片方の文書だけ直してもう片方に古い例が残る、固定した定義の読み込み方が
書かれていない、といったものである。コードではなく**利用者が実行する手順**を書いた変更で
起きた。

### レビュー用の作業ツリーが同期されていなかった

#192 のレビューを回そうとしたとき、レビュー用の作業ツリーが **8 コミット古い**まま流用され
ていた。そのまま回すと、現在の Pull Request に無い行への指摘や、直したはずの箇所への指摘が
投稿される。どちらも通常のレビューとして出るため、受け取った側から見分けが付かない。

`cross-refactoring` は v8.5.0 で同じ問題を解いていたが、`cross-review` には入っていなかった。
[#203](https://github.com/devbasex/ai-plugins/issues/203) として起票し、
[#204](https://github.com/devbasex/ai-plugins/pull/204) で直した。

### まだ存在しないものを指示する記述

#192 で `AGENTS.md` へ「Pull Request の宛先は `develop`」と書いたが、**`develop` はまだ
存在しない**。#205 のレビューで codex が規則どおり「宛先を `develop` に変更せよ」と指摘し、
そこで気づいた。指示どおり動くと存在しないブランチを指す。

規則を決めることと、それが効き始めることは別である。移行までの扱いを 3 箇所
（`AGENTS.md` の Git 運用ルールと `--base` の説明、`README.md` の開発者向け）へ書いた。

### 前提が 2 つ覆った

配布チャネルの設計中に、実機で確かめて前提が覆った。

| 当初の前提 | 事実 |
| --- | --- |
| 正式版を新しい名前のブランチ（`stable`）へ置けば手順を変えずに済む | **済まない。** 取得元の登録に ref は保存されないが、clone は登録時点の既定ブランチに固定される（fetch の refspec が `refs/heads/main` だけになる）。既定ブランチを移しても既存の利用者は追随しない |
| ローカルのディレクトリを同じ名前で追加したときの上書きは想定外の挙動 | **仕様である。** 名前ごとに 1 つしか登録できない |

前者が分かったため、**正式版を既定ブランチ（`main`）へ置く**形にした。利用者の取得手順が
1 文字も変わらない唯一の形である。

## 次に変えること

| 変えること | 落とし先 | 状態 |
| --- | --- | --- |
| 版数を持つ箇所を「検査が見る分」と「手で直す分」に分けて書く | `AGENTS.md` の記述 | この変更で反映済み |
| 説明文書の本文に書かれた版数を検査の対象へ広げる | `scripts/check-doc-staleness.py` | [#209](https://github.com/devbasex/ai-plugins/issues/209) として起票 |
| `cross-review` が既存の作業ツリーを Pull Request の head へ同期する | `cross-review` の手順とスクリプト | [#204](https://github.com/devbasex/ai-plugins/pull/204) で反映済み |
| まだ存在しないものを前提にする規則には、いつから効くかを併記する | `AGENTS.md` の記述 | この変更で反映済み |
| 開発の起点ブランチが既定ブランチと異なる構成へ NDF を対応させる | `worktree` / `ndf-policies` / `cherry-pick-pr` / `deploy` | [#202](https://github.com/devbasex/ai-plugins/issues/202) として起票。`develop` を作る前に片付ける |

**変えないと判断したもの**が 1 つある。修正をメインセッションで行うと `merge-fix` を通し忘れ、
次のラウンドが `exit 5` で止まる事象が 2 回起きた。これは v9.4.0 で入れた停止条件
（[#33](https://github.com/devbasex/ai-plugins/issues/33) /
[#37](https://github.com/devbasex/ai-plugins/issues/37)）が正しく働いた結果であり、出力に
復帰の手順も書かれていた。手順の側は変えない。
