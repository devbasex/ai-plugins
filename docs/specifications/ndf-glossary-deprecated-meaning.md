# 用語集の意味の説明の廃止した語: 構造の検査が用語集自身の意味の説明を照らし、1 文字の語と語の一部に現れる語を単独で照合する廃止した語として登録する

## 概要

**用語チェック（`glossary.py check`）の構造の検査は、用語集の意味の説明に廃止した語が現れると、規則
`deprecated_meaning` で 1 件ずつ当てて終了コード 1 で止まる。** 意味の説明は、語の項目の意味の欄（`terms[].meaning`）と
コンテキストの意味の欄（`contexts[].meaning`）を指す。構造の検査は CI ですべての Pull Request に走るため、用語集を
変えた変更のどれもが照らされる。

あわせて、用語集の語の項目は省略できる欄 `deprecated_standalone`（単独で照合する廃止した語）を持てる。この欄の語は、
先頭が漢字なら直前が漢字の出現に、末尾が漢字なら直後が漢字の出現に当てない。1 文字の `段` や、`文字で持つ` の一部に
現れる `字で持` を、`段階`・`手段`・`文字で持つ` に当てずに廃止した語として登録できる。

この文書は、その形に**なぜしたか**（背景・決定と理由・常に成り立つ条件・照合の例・テスト観点）を残す。
**規則の契約と用語集の形の正は次の文書にある。**

| 何を | 正本 |
| --- | --- |
| 用語チェックの規則の一覧（`deprecated_meaning` と `schema` の条件）・用語集の欄の表・人が読む文書の形 | [ndf-ubiquitous-language.md](ndf-ubiquitous-language.md) の「用語チェックの規則」「用語集（`source`）」「人が読む文書」 |
| 用語集の形と規則の表（用語集の持ち主が読む参照） | `requirements-design` の [references/glossary-format.md](../../plugins/ndf/skills/requirements-design/references/glossary-format.md) |
| 照合の正規表現と漢字の範囲 | [`scripts/lib/glossary_words.py`](../../plugins/ndf/scripts/lib/glossary_words.py) |

決定の番号は #3190 の設計の番号である。

## 用語

「廃止した語」「単独で照合する廃止した語」「用語チェック」「CI」「文字列」の定義は用語集（[docs/glossary.md](../glossary.md)）が正である。
この文書で使う「避ける語」は、ai-plugins の用語集が廃止した語として登録した古い語・直訳調の語 4 つ（`継続的統合`・`入口`・`段`・`字で持`）を指す。

## 背景

用語チェックは、設計の文書の追加した行の廃止した語を落とすが、用語集自身の意味の説明は見ていなかった（意味の説明で見るのは
禁止語だけだった）。語を改名しても意味の説明に古い語が残り、用語集を読んで設計の文書を書く AI と人が、そこから新しい文書へ
古い語を写した。#1142 の設計文書（PR #3179）に `継続的統合` が 31 か所、直訳調の `字で持ち`（文字列で持ち）が残ったのも
同じ流れである。

2026-11-13 に `develop`（25f96ab28）の用語集（1,063 項目・20 コンテキスト）を照らすと、意味の説明に用語集自身の廃止した語が
7 か所、`入口` が 11 か所、ステップ・ステージの意味の単独の `段` が 3 か所あった。`段` と `字で持` は、部分一致で照合する
`deprecated` の欄へは登録できなかった（1 文字の語は `schema` に当たり、`字で持` は `文字で持つ` に当たる）。

## 決定と理由

| # | 決定 | 理由 | 採らなかった案 |
| ---: | --- | --- | --- |
| 1 | 意味の説明の廃止した語の規則（`deprecated_meaning`）を、`--rules all` ではなく構造の検査に置く | 古い語は意味の説明から新しい文書へ写る。CI は設計のブランチ以外で構造の検査だけを走らせるため、`--rules all` だけに置くと用語集だけを直す Pull Request が照らされない | `--rules all` だけに置く |
| 1 | 意味の説明の照合は、文書の照合と同じ正規表現の組と除き方（どこかのコンテキストの生きた語と同じ語・生きた語の出現の内側・インラインコードの中は当てない）を使う | 2 つの規則で当たり方が食い違わない | — |
| 2 | 1 文字の語と語の一部に現れる語のために、前後が漢字の出現を除いて照合する欄 `deprecated_standalone` を足す。既存の `deprecated` の欄の照合は変えない | 誤った当たりはどれも「登録した語の前か後ろが漢字」の形をしている。語の境界を文書の全体に引かず（日本語の語の境界は辞書を引かないと決まらない。Unicode Standard Annex #29）、登録した語の前後の 1 文字だけを見る。照合の条件を語の側に置く形は prh・Vale の置き換えの規則に先例がある。既存の欄すべてに漢字の境界を掛けると、`共通層` のように前後へ漢字が続く書き方で当たっていた出現が当たらなくなる | 語ごとに正規表現を書かせる（用語集の持ち主の手間が増え、要る条件は 1 種類で足りる）。形態素解析のライブラリ（SudachiPy・fugashi。辞書のパッケージが要り、NDF のスクリプトが標準ライブラリで動く前提が崩れる）。PyPI の regex の `\p{Han}`（範囲を書けば標準ライブラリで足りる） |
| 2 | 漢字の判定は、標準ライブラリの `re` に CJK 統合漢字・拡張 A・互換漢字・繰り返しの記号（`々`）の範囲を書いて行い、範囲は `lib/glossary_words.py` の `KANJI` だけに置く | 漢字の範囲の置き場を 1 つにする | — |
| 3 | `段` をステップとステージの両方の単独で照合する廃止した語にし、2 語の意味は広げない | 両方に登録すると `detail` が `ステップ / ステージ と書く` になり、書き手が文脈で選べる。2 語は「プランの steps の 1 要素」「パイプラインの中のプランのグループ」の意味で他の文書が使っており、広げると 1 語 1 意味が崩れる | 片方だけに登録する（もう片方の意味の行に誤った言い換え先を示す）。2 語の意味を「工程の 1 つ分」「パイプラインの 1 つ分」へ広げる |
| 4 | `インライン` の内側の `ライン` は言い換えも規則の追加もしない | 廃止した語の照合は、カタカナだけの語の前後がカタカナのときに当てない。意味の説明の `ライン` 12 回の出現（`インライン`・`パイプライン` など）の当たりは 0 件だった | 意味の説明を言い換える・除外の規則を足す |
| 5 | 置き換え先の語の意味が合わない箇所は、置き換え先へ写さず中身で書く | `仕様適合` の「レビューの第 1 段」「段 spec」と `進行表` の「3 段」は、ステップとステージのどちらの意味にも当たらない。1 語を 2 つの意味に使わない | 項目ごとに照合から除く欄を足す（古い語が残る原因を残す） |
| 8 | `deprecated_meaning` は既定で掛け、止める設定を持たない | 意味の説明だけを照合から外していたことが、古い語の残った原因である。止める設定があると、古い語を残したまま検査を通す道が残る。用語チェックは当たった規則を止める項目を持たない | 規則を止める設定を足す |

## 仕様

### 構成要素と責務

| 要素 | 責務 |
| --- | --- |
| `plugins/ndf/scripts/lib/glossary_words.py` | 漢字の範囲（`KANJI`）を持つ。`is_kanji_edged` が語の先頭か末尾が漢字かを返し、`standalone_part` が単独で照合する語 1 つの正規表現の断片を作り、`word_pattern` が `deprecated` の語と単独で照合する語を合わせた 1 つの正規表現を長い語から当てる順で作る。同じ語が両方にあれば `deprecated` の側で組む |
| `plugins/ndf/scripts/lib/glossary_fields.py` | 語の項目の欄を読む。`deprecated_standalone_of` が単独で照合する廃止した語を、`all_deprecated_of` が 2 つの欄を合わせた廃止した語（重なりは先に出た方を残す）を返す。`standalone_findings` が欄の形を確かめて `schema` の当たりを足す |
| `plugins/ndf/scripts/glossary.py` の `structure_findings` | 用語集の形・重なり・禁止語に加えて、`_meaning_findings` で意味の説明を照らす。正規表現の組（引数 `words`）を省いて呼ばれたら自分で作る（`plan-to-spec-steps.py` はこの形で呼ぶ） |
| `plugins/ndf/scripts/glossary.py` の `_meaning_findings` | 語の項目とコンテキストの意味の説明を、インラインコードを空白で埋めてから照らし、生きた語の出現の内側を除いた一致 1 つにつき `deprecated_meaning` を 1 件当てる。意味の説明が文字列でない項目は飛ばす |
| `plugins/ndf/scripts/glossary.py` の `cmd_check` | 正規表現の組を構造の検査の前に 1 回だけ作り、構造の検査と文書の照合の両方へ渡す |
| `render_text`・`replacement`・`diff_items`・`_build_word_patterns` | `all_deprecated_of` を読み、単独で照合する廃止した語も人が読む文書・置き換え先・差分・照合に含める |

依存の向きは `glossary.py` → `lib/glossary_fields.py` → `lib/glossary_words.py` の一方向である。

### 常に成り立つ条件

| # | 条件 | 破れたときの扱い |
| --- | --- | --- |
| I1 | 語の項目とコンテキストの意味の説明に、どれかの項目の廃止した語（2 つの欄のどちらでも）が現れない。どこかのコンテキストの生きた語と同じ語・生きた語の出現の内側の出現・インラインコードの中の出現は数えない。項目自身の廃止した語も当てる | 構造の検査が `deprecated_meaning` で当て、終了コード 1 で止まる |
| I2 | 単独で照合する廃止した語は、漢字で始まる語なら直前が漢字の出現に、漢字で終わる語なら直後が漢字の出現に当たらない | 照合の規則が持つ（テストが縛る） |
| I3 | 単独で照合する廃止した語の欄は空でない文字列の配列で、各語の先頭か末尾が漢字であり、同じコンテキストの生きた語と重ならない | 構造の検査が `schema` で当てる |
| I4 | 人が読む文書は、用語集から `render` した内容と一致する | `stale_document` で当てる |

### 照合の例

| 書いた行 | `段` に当たるか | `字で持` に当たるか |
| --- | --- | --- |
| `第 1 段`・`3 段` | 当たる | — |
| `段階`・`手段` | 当たらない（後ろか前が漢字） | — |
| `字で持ち`・`字で持つ` | — | 当たる |
| `文字で持つ`・`数字で持つ` | — | 当たらない（前が漢字） |
| `文字`・`字数`・`1 字` | — | 当たらない（語の形が違う） |

### 当たりの形

当たりは既存の構造の当たりと同じ形で出し、新しい項目を足さない。`line` は 0、`term` は項目の語（コンテキストのときは `id`）、
`detail` は見つけた語と置き換え先を示す。置き換え先は、その語を廃止した語に持つ項目の語を ` / ` で並べたものである。

```text
ERROR: docs/glossary/glossary.json:0: deprecated_meaning: 登録簿
{"rule": "deprecated_meaning", "path": "docs/glossary/glossary.json", "line": 0, "term": "登録簿", "detail": "意味の欄に廃止した語「起動元」がある。親エージェント と書く"}
```

人が読む文書は、「廃止した語」の列に `deprecated` の語の後に単独で照合する廃止した語を `段（単独）` の形で並べる。列の数は 6 のままである。

## データ・設定

ai-plugins の用語集（`docs/glossary/glossary.json`）は、避ける語 4 つを次のとおり登録する。

| 避ける語 | 登録した欄 | 置き換え先の語（コンテキスト `ndf-workflow`） |
| --- | --- | --- |
| `継続的統合` | `deprecated` | CI |
| `入口` | `deprecated` | エントリポイント |
| `段` | `deprecated_standalone` | ステップ・ステージ |
| `字で持` | `deprecated_standalone` | 文字列 |

語は各プロジェクトの用語集のデータで受け、NDF のコードに語を書かない。

## 運用

- 規則は、用語集の設定（`.ndf/glossary.json`）を持つすべてのリポジトリで既定で働く。意味の説明に廃止した語を持つ用語集は、
  この規則を含む NDF の版を入れた後の構造の検査で落ちる。直し方は、当たりの `detail` が示す置き換え先で意味の説明を言い換え、
  `glossary.py render` で文書を作り直すことである
- 置き換え先のどの語の意味にも当たらない出現は、置き換え先へ写さず中身で書く（決定 5）
- `deprecated_standalone` を持たない用語集の文書の照合は変わらない
- 避ける語を廃止した語にしても、用語集の外の既存の文書（確定仕様・Skill の本文）は追加した行だけが照らされるため、既存の出現では落ちない
- 構造の検査の時間は、ai-plugins の用語集（1,063 項目・20 コンテキスト）で正規表現の組の作成と意味の説明の照合を合わせて約 0.28 秒である（2026-11-13、手元で 1 回）

## テスト観点

検査の振る舞いは [`plugins/ndf/scripts/tests/test_glossary.py`](../../plugins/ndf/scripts/tests/test_glossary.py) が一時の用語集を入力にして縛る。

- 語の項目の意味の説明に別の項目の廃止した語を書くと、`check --rules structure` が項目の語・見つけた語・置き換え先を持つ `deprecated_meaning` を出して終了コード 1 で終わること。コンテキストの意味の説明でも当たり、`term` が `id` になること
- どこかのコンテキストの生きた語と同じ廃止した語・生きた語の出現の内側・インラインコードの中の出現は当てないこと
- `deprecated_standalone` に `段` を登録すると `第 1 段`・`3 段` が当たり `段階`・`手段` は当たらず、`字で持` を登録すると `字で持ち` が当たり `文字で持つ` は当たらないこと。文書の追加した行でも意味の説明でも同じであること
- `deprecated_standalone` が配列でない・空の文字列を含む・先頭も末尾も漢字でない語を含む・同じコンテキストの生きた語と重なる、がそれぞれ `schema` で当たること
- `render` が単独で照合する廃止した語を `（単独）` を付けて「廃止した語」の列に並べ、列の数が 6 のままであること
- ai-plugins の用語集で `python3 plugins/ndf/scripts/glossary.py check --rules structure` が当たり 0 件・終了コード 0 で終わること
