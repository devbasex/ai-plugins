# 設計レビューの項目の行き先: 規則 review-items が読む 182 項目の表

#1142（NDF の作り直し）の設計レビュー 4 巡で見つかった項目 182 件に、行き先の子・順番・新設か追補か・要求の行・版を 1 行ずつ割り当てた表（振り分け表）である。規則 `review-items` の入力で、`plugins/ndf/src/ndf/checks/rules.json` の `spec.review_items_source` がこの文書を指す。

- **読み方**: `ndf check --write-spec` が「行き先の表」から `plugins/ndf/src/ndf/checks/children.json` の `review_items` を生成する（手で写さない）。形と違反にするものは [ndf-contract-fact-checks.md](ndf-contract-fact-checks.md) の「設計レビューの指摘の対応先（`review-items`）」にある。版が `11.x` の行の 11.x での行き先は [ndf-review-items-11x.md](ndf-review-items-11x.md) だけが持つ。子の記号と Issue の番号は [ndf-rebuild.md](ndf-rebuild.md) の「子の記号」にある
- **出所**: #3395 の設計で作った振り分け表（ファイル名は #1142 の設計文書の名前で始まる。[消す前のコミットの `issues/` の一覧](https://github.com/devbasex/ai-plugins/tree/eb4d652deeb08105ef65a4353aa3c58a6c92e289/issues) にある）の「列の読み方」と「行き先の表」を、セルを変えずに移した（#3960）。変えたのはリンク先の文書の名前だけである。下の文の「設計」は #3395 の設計を指し、その決定（決定 123・125 など）と版の基準は [ndf-rebuild-review-scope.md](ndf-rebuild-review-scope.md) にある
- 抜き出しのコマンドと突き合わせ・件数・決定 127 で戻した行・要求の受け入れ条件の持ち主・作らない要求の行は移していない

## 列の読み方

| 列 | 何を書くか |
| --- | --- |
| 項目 | `<Issue 番号>-<連番>`。連番は 2026-11-14 に、その Issue の本文（`## 進行` より前）にある取り消し線の無いチェックボックスの行を、上から数えた順で振った。以後は番号を引き継ぐ。項目の同一性は番号で決め、要旨が変わったかは要旨のセルの sha256 の先頭 12 文字（`text_sha`。`children.json` の `review_items` が持つ）で見分ける。取り消した項目の番号は欠番にして使い直さず、新しい項目にはその Issue の既存の最大の連番 + 1 を振る。#3395 だけは本文が要求に書き直されたため、「依頼（原文）」の引用の中の 10 行を数える |
| 要旨 | 項目の要旨。`text_sha` の原文である |
| 行き先の子 | 項目を解く子の記号。2 つ以上を `・` で並べたときは、先頭の子が項目を閉じる持ち主である。この設計の差分で解くものは `#3395 の設計`、承認済みの設計の差分で解いたものは `済み（PR <番号>）` と書く。版が `11.x` の行は、Issue の番号を書かず [11.x の対応表](ndf-review-items-11x.md) を指す。11.x での行き先は対応表だけが持つ |
| 順番 | 行き先の子の流す順番（先に要るものの順番の最大 + 1）。`0` はこの設計の差分か承認済みの設計の差分で解き、子を流さないことを表す。`—` は版が `11.x` の行（11.x での順番は [#3388 の設計の 11.x の子の表](https://github.com/devbasex/ai-plugins/tree/784110e5461b3f856ba18f3c8ea7e995a06c8b0d/issues) （コミット `784110e5` の `issues/` の一覧にある）が持つ）。数の直後に全角の括弧で注記を添えてよい（例: `2（比較の結論まで着手しない）`）。注記は人が読むためのもので、規則 `review-items` は数だけを読む |
| 新設か追補か | `新設`（この設計で足す・分ける子）・`追補`（閉じた子への追補の単位）・`既存`（開いている子の受け入れ条件へ足す。分類 D・E・G は承認済みの設計で既に足した）・`#3395 の設計`・`済み` のどれか。版が `11.x` の行は `—` |
| 要求の行 | #1142 の要求仕様のコピー（[コミット `4e1f1f1ca` の `issues/` の一覧](https://github.com/devbasex/ai-plugins/tree/4e1f1f1caa7c022cd4807d56df2706e095776adb/issues) にある）の行番号（コミット `4e1f1f1ca` の時点）。項目の根拠になる要求の文が無い行は `無し` と書き、設計の「範囲を広げるか 11.x へ回すか」の一覧に載せる |
| 版 | `11.0.0`（入れ替えの前に解く）か `11.x`（11.0.0 を出した後に解く）。当て方は次の段落、決めた理由は設計の決定 123・125 にある |

**要求の行の当て方。** 今の NDF にある機能を作り直しで保つための項目は、対象範囲の「含む」の 239 行（`plugins/ndf/scripts/` のすべて）か、より細かな行を当てる。今の NDF に無い機能を足す項目には、その機能を名指す行が無い限り `無し` を当てる。

**版の当て方。** 基準は「今の `plugins/ndf/` にある機能を同等に担うか」である（決定 123）。次のどれかに当たる項目は `11.0.0`、ほかは `11.x` にする。

- 今の NDF にある機能を、作り直しで落とさず同等に担う（持ち主の無い今の機能・今より後退する箇所）
- 正しさと安全に要る（分類 A #3341・E #3345・H #3364・N #3378・X #3394 と、分類 M #3377 の異常系のうち今の水準まで。#3388 へ回した行を除く）
- 入れ替え（S2）と 11.0.0 の受け入れ条件（決定 124）に要る（対応表・試走・退行させないもの・S2 の判定）

今の NDF にも無い機能と改善は `11.x` である。11.x の行の行き先（11.x の新しい子・開いている既存の Issue・作らない理由）は [11.x の対応表](ndf-review-items-11x.md)（#3388 の設計）が持ち、この表の行き先の子の列は対応表を指す。オーガナイザーの振り分けの案から直した行と理由は決定 125 にある。
