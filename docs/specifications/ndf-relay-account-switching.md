# 中継のアカウントの切り替え: 利用上限で停めず、避けられなければ使い切ってから同じ会話へ自動で戻す

中継のラッパー（`ndf relay`）は、利用上限で子の claude を停めないことを最優先にして、子のアカウントを替える。使用率は
使用率の API ですべての登録済みアカウントから取り、今のアカウントは NDF の status line も記録する。見回りでは、
今のアカウントが閾値の手前を越え、閾値の内側の替え先があれば、セグメントの途中でも止めてよい時点で子を止めて、
同じ会話を替え先で `--resume` する（守り 1）。替え先が無ければ今のアカウントを上限まで使う（守り 2）。上限で停まったら、
人の入力無しで、上限でない登録済みアカウント → 従量の接続 → 最も早く上限が解けるアカウントの順に同じ会話へ戻す
（守り 3・最後の砦）。認証の失敗（401）では、そのアカウントを 1 時間外して替える。起動の回数には上限を置かず、
暴走は再起動ループの検出（短いセグメントが 3 つ続く）だけで止める。Claude Code だけが対象である。

例: 登録済みアカウントが `work1`・`work2`・`work3` で、`work1` で動くレーンのとき（閾値は既定の A 85%・B 70%・C 90%）。

| 順 | 観測 | 起きること |
| --- | --- | --- |
| 1 | `work1` 5 時間 40%・7 日 30%、`work2` 7 日 10% | 替えない（`work1` は余裕の組で、最良の候補と同じ組。切り替えの余裕） |
| 2 | セグメントの途中で `work1` の 5 時間が 86% | 見回りが閾値 A を越えたと読む。止めてよい時点（応答が終わり、5 秒静か）を待って子を止め、`work2` で同じ会話を `--resume` する。子へ「利用上限の手前でアカウントを替えた。中断したところから続ける」を送る |
| 3 | `work2` も `work3` も使い切りの組（7 日 92%・95%） | 替えずに `work2` を上限まで使う（守り 2） |
| 4 | `work2` が上限に当たり、子の画面に上限の行が出る | `limited.json` に上限の観測を書き、使い切りの組の `work3` で同じ会話を続ける（守り 3） |
| 5 | `work3` も上限。従量の接続（Bedrock）の設定がある | `metered` で同じ会話を続ける。利用料が掛かる |
| 6 | 使用率の API の取り直しで `work1` の 5 時間の窓がリセットされたと分かる | カットポイントを待たずに、止めてよい時点で `work1` へ戻す（「利用上限が解けたアカウントへ戻した。中断したところから続ける」） |

この文書は、その形の構成要素・常に成り立つ条件・データの形・決定と理由・テスト観点を残す。子をアカウントの設定
ディレクトリで起動する仕組みは [ndf-relay-account-config-dir.md](ndf-relay-account-config-dir.md)、従量の接続と API キーの子は
[ndf-relay-metered-and-api-keys.md](ndf-relay-metered-and-api-keys.md)、`ndf plan` の `claude -p` は
[ndf-relay-plan-claude-accounts.md](ndf-relay-plan-claude-accounts.md) にある。

## 背景

- 11.0.0 の作り直し（#3304）で、替えるかの判断の純粋な関数だけを移し、判断へ入る観測（使用率・認証の状態）を移さなかった。
  使用率のキャッシュに書き手が無く、判断はいつも「替えない」か同じアカウントのリセットを待つだけだった（#3864）
- 2026-11-21 の設計承認ゲートで、利用者が「利用上限で停まったセッションは人が起動し直すまで何もできない。停めないことを
  最優先にする。避けられなければ使い切り、停まった後は人の入力無しで別のアカウントか API・Bedrock で自動で復帰する」と
  指示した。閾値 A・B・C と選ぶ順の組は、そのとき利用者が出したたたき台を骨組みにしている
- 2026-11-22 の設計承認ゲートで、1 日の起動の上限（`relay.max-starts`、20 回）と替えた回数の上限の撤廃を指示した。10 系でも
  #2505 で同じ上限を撤廃していた（壊れていなくても 1 日に 4 回止まった）
- 使用率は 10 系と同じく使用率の API（`GET /api/oauth/usage`）で取ると、2026-11-22 に利用者が決めた（「公式に無くても
  使えるものは使う。仕様が変わったらまたそこから考える」）。公開の文書にある契約は status line へ渡る `rate_limits` だけで、
  届くのは動いている子のアカウントの値だけである

### 使用率の取得

ラッパーは見回りで判断の入力を読む前に、取り直す登録済みアカウント（`due` が真）を別のスレッドへ積み、1 本ずつ取る。
見回りと端末の中継は止めない。今のアカウントも、動いていないアカウントも取る。

- **取り直す条件（`due`）**: 最後に試した時刻（取得の記録の `at` と、このラッパーが最後に積んだ時刻の大きいほう）が無いか、
  `relay.usage-fetch`（300 秒）を過ぎたか、最後に試した後にキャッシュと取得の記録の窓・モデル別の枠の `resets_at` か
  上限の観測の `until` を過ぎたとき。試した後は、取得が失敗しても、同じリセットでは取り直さない
- **排他**: 取得の排他は `<登録簿>/.fetch-locks/<名前>.lock` の `flock` で、待たずに取る。取れなければ呼ばない。錠は状態の
  保存先でなく登録簿の側にあるので、`NDF_STATE_HOME` の違うラッパーと登録・削除のコマンドも同じ錠を引く。登録の排他は
  確かめと書き込みの間だけ持ち、HTTP の往復の間は持たない。順は 取得の排他 → 登録の排他 → 窓の錠 に固定する
- **手順（`fetch_usage`）**: 取得の排他の中で `due` を読み直す → 登録の排他の中で世代（違えば `reregistered` で資格情報を
  読まない）・`needs_relogin`・実体を確かめ、保留の更新を当て、認証ファイルの写しを取る → 取得の記録の `at` を書く（書けなければ
  呼ばない）→ 残りが `relay.token-margin`（60 秒）以下ならトークンを更新する → GET → 世代を確かめ直して書く
- **呼び方（`get_usage`）**: `GET https://api.anthropic.com/api/oauth/usage` を `Authorization: Bearer <アクセストークン>` と
  `anthropic-beta: oauth-2025-04-20` で 1 回送る。転送は追わない（転送先へトークンを送らない）。上限は `relay.usage-http`
  （10 秒）で、名前解決から受信の終わりまでの往復全体の期限である。`user:profile` のスコープが無いトークン（`scope`）と、
  送る直前の時計で期限を過ぎたトークン（`token`）は送らない
- **応答の読み（`parse_usage`）**: `five_hour`・`seven_day` の `{utilization, resets_at}` を読む。どちらのキーも無いか、形が違えば
  `error: shape` で窓を変えない。`utilization` が 0 で `resets_at` が null の窓は使用の無い窓として返さない。`limits[]` の
  `kind: weekly_scoped` はモデルの識別ごとに、`extra_usage.spend_limit_reached` は真偽のときだけ読み、崩れていればその項目だけを
  読めなかったとする
- **失敗**: `network`・`http-<状態>`・`token`・`scope`・`shape`・`not_account_local`・`reregistered` のときは窓を変えず、取得の
  記録の `error` だけを書く。判断は status line の記録で続く
- **形の変化**: `shape` のとき、画面に `ndf-relay: 使用率の API の応答の形が変わった。status line の記録で続ける` を 1 回、
  `log.jsonl` に `{"kind": "usage_shape", "account", "items"}`（読めなかった項目の名前。値と本文は出さない）を出す。1 つの
  ラッパーで 1 回だけで、形が戻って取れたら次の変化でまた出す。取得の例外は `usage_fetch_failed` の 1 行にまとめる

**トークンの更新（`_refresh`）**: アクセストークンの残りが `relay.token-margin` 以下のときと、GET が 401 を返したときだけ
更新する（1 回の取得で多くても 1 回。更新の後の 401 では更新し直さない）。更新するのは、使用の届けが無く（動いている claude が
無い）、`<設定ディレクトリ>/.oauth_refresh.lock` を `os.mkdir` で待たずに取れたときだけである。排他の中で認証ファイルを
読み直し、別の期限内のトークンに替わっていれば宛先を呼ばずにそれを使う（`fresh`）。宛先 `https://platform.claude.com/v1/oauth/token`
へ Claude Code と同じ形（`grant_type: refresh_token`・`refresh_token`・`client_id`・`scope`）で POST し（上限は
`relay.oauth-refresh` の 3 秒）、`claudeAiOauth` の項目だけを書き換える。

| 応答 | 扱い |
| --- | --- |
| 200 で、`access_token` が空でなく `expires_in` が有限の正の数 | 登録の排他の中で、登録の世代が POST の前と同じで、POST に使った資格情報の組（アクセストークンとリフレッシュトークン）が認証ファイルで今も同じなら書く（`ok`）。世代が違えば `reregistered`、組が替わっていれば適用しない。登録の排他を取れなければ、認証ファイルを変えずに保留の更新（`.ndf-oauth-pending.json`）へ、応答と一緒に登録の世代と POST に使った組のハッシュを控える。保留は次に登録の排他を取る手順が、更新の排他の中で当てる（`account_files.apply_pending`）。当てる時も世代と、今の認証ファイルの組のハッシュを控えと照らし、どちらも同じときだけ書く。どちらかが違えば（POST の後の再登録・`/login`・claude 自身の更新）書かずに保留を捨てる |
| （POST の前）リフレッシュトークンの期限切れ | 更新の排他の中で読み直した認証ファイルの `refreshTokenExpiresAt` が今以前なら、POST せずに `needs_relogin` を立てる（`rejected`）。この判断は最初の登録の排他の中で、登録の世代が今と同じで、使用の届けが無く、読み直したトークンが別の期限内のトークンに替わっていない（替わっていれば `fresh`）と確かめた後に行う。POST していないので資格情報の組の照合は無い |
| 400・401・403 | 成功と同じく、登録の排他の中で世代と POST に使った資格情報の組を照らし、どちらも同じときだけ取り消しとして `needs_relogin` を立てる（`rejected`）。世代が違う・組が替わっていれば立てない（POST の間に利用者がログインし直し、古いトークンへの拒否が遅れて届いても、新しい資格情報のアカウントを候補から外さない）。POST の間に子が起動していれば立てない（`rejected_in_use`） |
| 429・408・5xx・通信の失敗・必須の条件に外れた 200 | 一時的な失敗。認証ファイルを書かず、次の間隔で試す |

ラッパーの通常の終了は、始まった更新が認証ファイル（か保留）を書いて排他を放すまで待ち、新しい取得と更新を始めない
（`FetchGate`）。送り始めた GET も往復が終わるまで待つ。

### 使用率のキャッシュの読み方

窓の書き手は 2 つで、書く先が違い、読む側（`usages`）が窓ごとに同じ規則で合わせる。

| 書き手 | 書く先 | 中身 |
| --- | --- | --- |
| ラッパーの使用率の取得 | 登録簿の側の取得の記録（`<登録簿>/.usage-fetch/<名前>/<世代>.json`）。取得の排他の中で書く | `at`・`error`・`spend_limit_reached`・`windows`（`five_hour`・`seven_day`・`seven_day_scoped.<識別>`） |
| NDF の status line | 状態の保存先のキャッシュ（`<状態の保存先>/relay/accounts/usage/<名前>/<世代>.json`）。`<ファイル>.lock` の `flock`（待たない）の中で書く | 入力の `rate_limits.five_hour`・`seven_day` の `used_percentage`・`resets_at`。`NDF_ACCOUNT_USAGE_FILE` のある子（登録済みアカウントの子）だけが書く |

- 窓ごとに「`resets_at` の新しいほう、同じなら使用率の大きいほう」を残す。前後して届いた古い入力で値を下げない。入力に無い
  窓は前の値を残す。合わせた中身が前と同じなら書かない
- 有効な窓が 1 つも無い入力では書かない。`spend_limit`（Claude apps gateway の支出の上限）は利用上限の窓として読まない
- 読む側は、窓ごとに `resets_at` を過ぎていれば 0% にし、5 時間と 7 日の使用率と 7 日のリセットの時刻を返す（`Usage(name,
  percent, five, seven, seven_resets_at, limited)`）。7 日は `seven_day` と、リセットを過ぎていないモデル別の枠の最大の、大きい
  ほうで読む。`percent`（一覧の表示）は窓の最大である
- 上限は、過ぎていない窓のどれかが 100 以上か、取得の記録の `spend_limit_reached` が真か、上限の観測が続いているとき。
  窓を持たないアカウントでも、後の 2 つなら使用率は分からないが上限の行（`percent` が None）にする
- 窓を 1 つも持たない記録・読めない記録は返さず、そのアカウントは使用率の分からない候補になる（0% と読まない）。窓を持つ
  記録は、窓がすべてリセットを過ぎていても観測済みとして返し、過ぎた窓は 0% である
- 今の登録の世代と違うファイル・項目は読まない

今のアカウントでは、status line の記録が使用率の API より早く届く。status line は会話の更新のたびに呼ばれ、
`rate_limits` はモデルの呼び出しごとに新しくなる。ラッパーは見回りのたびにファイルの印を `stat` で比べ、変わったときだけ
読む。そのため、閾値を越えたモデルの呼び出しの後 0.5 秒以内に見回りへ届く。

### 選ぶ順の組と替え先

上限でない登録済みアカウントを 4 つの組に分ける（`account_decide.group`。番号はコードの値）。上限のもの（上限の観測を
含む）はどの組にも入れない。並びは 組の番号 → 7 日の窓のリセットの早い順 → 7 日の使用率の大きい順 → 名前の順 である
（`order`）。組 0〜2 を閾値の内側と呼ぶ。

| 組 | 名前 | 条件 |
| --- | --- | --- |
| 0 | 余裕の組 | 5 時間が A より下（5 時間の窓の無いプランは満たす）で、7 日が B より下か窓が無い |
| 1 | 使用率の分からないもの | 使用率の記録が無い |
| 2 | B 越えの組 | 5 時間が A より下で、7 日が B 以上 C より下 |
| 3 | 使い切りの組 | 5 時間が A 以上か、7 日が C 以上 |

候補は呼ぶ側が渡す起動できる登録済みアカウントで、使えないアカウント・外した間・再登録が要るアカウントは入らない。
判断の関数は候補の外の名前を返さない。

| 場面 | 関数 | 替え先 |
| --- | --- | --- |
| カットポイント | `before_limit` | 今の組より番号の小さい組の候補があれば先頭へ替える。同じ組なら替えない（切り替えの余裕）。今が既定のログインか使用率が分からなければ替えない。今が従量の接続なら、候補の先頭の登録済みアカウントへ戻る |
| 見回り（子が動いている間だけ） | `guard` | 今が使い切りの組で、閾値の内側の候補があれば先頭へ替える（閾値 B は見ない）。今が従量の接続なら、候補があれば戻る |
| 上限の後 | `after_limit` | 上限が解けた今のアカウントが最良の候補より悪い組でなければ同じアカウントで再開する。でなければ候補の先頭（使い切りの組も入れる）→ 退避先の先頭（今と同じ起動先は除く）→ どれも無ければ `wait_reset` |
| 認証の失敗の後 | `after_auth` | 候補の先頭 → 退避先の先頭（今と同じ起動先は除く）→ どれも無ければ `stalled` |

退避先は `account_choice.fallbacks` が作る並びで、従量の接続の `metered` → 登録簿の有効なキー（使い方が `off` でない登録簿の、
起動の前の確かめに通った `key:<名前>`。名前の順）である（`tried` に入った起動先は除く）。`metered` と `key:<名前>` は別の起動先で、
従量の接続の設定が無くても有効な登録キーがあれば `wait_reset`・`stalled` に入らずそのキーへ替える
（[ndf-relay-metered-and-api-keys.md](ndf-relay-metered-and-api-keys.md)）。

`wait_reset` の間は子を残したまま待つ。待つ間も見回りごとに入力を読み直し、取得の間隔と、キャッシュのリセットの時刻・
上限の観測の `until` を過ぎた時点で使用率の API で取り直す。取り直した値で上限でないと確かめたアカウント（今のアカウントに
限らない）が現れた時点で、`after_limit` がそのアカウントを返す。

### 指定と最初のセグメント

- 最初のセグメントは、環境変数 `NDF_CLAUDE_ACCOUNT` の名前 → 指定（`pinned.json`）の名前の順に、使えるものを試す。どちらも
  無いか使えなければ既定のログインで起動する。登録済みアカウントは列挙しない（登録だけして普段は既定のログインを使う利用者の
  認証を替えない）
- 2 つ目以降のセグメントを起動するたび（カットポイント・見回りの替え・上限の後・認証の失敗の後）に指定を読み直す。指定は、
  使えて（起動の前の確かめに通る・上限でない・外した間でない）、閾値の内側にあるか閾値の内側の候補がほかに無いときだけ、
  判断の関数の結果より先に使う。指定が使い切りの組に入り、閾値の内側の候補があれば、停めないことを先にする。ただし見回りの替え・
  認証の失敗の後・キーの子の停止の後（`reason` が `guard`・`auth`・`revoked`）では、指定が今の起動先を指すなら先に使わない
  （`_pinned_or`。今の起動先から離れる判断を指定で打ち消さない。例: 従量の接続から登録済みアカウントへ戻る見回りで、指定が今の
  `metered` を指していても有料の接続を選び直さない）
- 起動の順は 先頭（指定か判断の結果）→ 判断の関数の順 → 尽きたら理由ごとの起動先 である。見回り・上限の後・認証の失敗の後に
  替え先も今のアカウントも用意できなければ、既定のログインへ落とさずに `account_unavailable` で止まる（別の認証で会話を
  送らないことを、停めないことより先にする）。認証の失敗の後に替え先が尽きたときも、今のアカウントにも既定のログインにも
  戻さない（`Choice.last`）
- 起動先を確定した結果だけを、子の環境の `NDF_CLAUDE_ACCOUNT`・セグメントの記録・`log.jsonl` の `account` の行に使う

### 見回りと止めてよい時点

見回りは、今のアカウントの窓を読み、使い切りの組で閾値の内側の候補があれば（`guard` が `switch`）、止めてよい時点を待つ。
止めてよい時点（`_safe_point`）は次がすべてそろった時点で、確かめられない（記録が読めない）ときは止めない。

- 子の出力が静かな時間（`relay.quiet`、5 秒）止まっている
- 回答待ちの質問が無い
- 子の会話の記録の最後が終わった応答（`stop_reason` が `end_turn` か `stop_sequence`）である。結果を待つ Tool の呼び出し
  （`tool_use` に対応する `tool_result` が無い）と、`tool_result` や利用者の入力の後で次の推論を待つ間は当たらない
- その応答の終わりが、ラッパーが子へ最後に入力を送った時刻より後である

止めてよい時点は子の背景の作業（背景の supervisor・`ndf plan queue`・`run_in_background` の Bash など）を見ない。止めた時点で
背景で動いていた処理は子とともに終わる。背景の作業が残る子を止めずに待つ判定は #4049 が担う（`issues/issue-4049-design.md`）。

来たら子を止め、同じ会話を替え先で `--resume` する。送る 1 行は、登録済みアカウントの間は「利用上限の手前でアカウントを替えた。
中断したところから続ける」、従量の接続から戻るときは「利用上限が解けたアカウントへ戻した。中断したところから続ける」である。
待つ間も、文脈の上限の引継ぎと出力の止まりの再起動は先に打つ。替える回数に上限は置かない。替えた元は使い切りの組に入るか、
上限の観測・外した間で除かれるので、窓がリセットされるまで同じ元へは戻らない。

### 上限の後

次のどちらかで上限とし、上限の観測（`see_limit`）を自分の登録の世代の項目へ 1 回書いてから `after_limit` で替え先を選ぶ。

- 子の画面に上限の行が出た（`observe.limit_line`）
- 今の登録済みアカウントの過ぎていない窓が 100 以上か、使用率の API が上限の到達（`spend_limit_reached`）を返し、子が
  静かな時間止まっている（画面の文言が変わっても引き金を見落とさない）

例外として、上限の行も 100 以上の窓も無く、使用率の API の `spend_limit_reached` だけで検出したときは、上限の観測を書かない
（`_limit_pick`）。上限は取得の記録の `spend_limit_reached` で読むので、次の取得で `false` が返れば今のアカウントの行の上限が落ち、
今のアカウントがふたたび選べるようになる（別に書いた観測が推定の `until` まで復帰を遅らせない）。その後は `after_limit` の通常の順で決め、今のアカウントが候補に残り、最良の候補より悪い組にいなければ同じアカウントで再開し、そうでなければ候補の先頭へ替える。

`until`（解除の推定の時刻）は、上限の行のリセットの時刻 → 行の窓の語か使用率 100 以上の窓の `resets_at` → 5 時間の窓の
`resets_at` か見た時刻 + `relay.limit-unknown`（18000 秒）の順に決める（`limit_until`）。窓を特定できたときは、窓の名前と見た
時点のその窓の `resets_at` を `window`・`window_resets_at` に残す。観測は、その窓のキャッシュの `resets_at` が `window_resets_at`
と `until` の大きいほうより後で 100 未満になるか、`until` を過ぎたら解ける。同じ窓の値の変化と書き込みの時刻では解かない。
書けなければ `log.jsonl` に `limit_seen` の 1 行を出し、今のアカウントを上限として判断へ渡す。替えた子へ送る 1 行は
「利用上限でアカウントを替えた。中断したところから続ける」である。

### 認証の失敗

画面の認証の失敗の行（`Failed to authenticate`・`Invalid API key`・`Login expired`・`Not logged in`。`observe.AUTH_FAILED`）は
引き金だけにする。次の 3 つがそろったときだけ、認証の失敗と確かめる（利用者の入力・モデルの応答・古い表示で動かない）。

- 子の会話の記録の会話の行（`assistant`・`user`）の最後が、`isApiErrorMessage` が真の `assistant` の記録で、`error` が
  `authentication_failed` か、そうでなく `apiErrorStatus` が 401 である（`observe.credential_failure`。打ち直しの `system` の
  記録は読まない。429 の `rate_limit`・400 の `billing_error`・403 の `permission_error` は当てない）
- その記録が、セグメントの起動（壁時計の時刻）より後である
- その後に利用者の記録が無い

確かめたら、今が登録済みアカウントなら `relay.auth-hold`（3600 秒）外し、`held.json` の自分の世代の項目へ書く（既定の
ログインは外さない。書けなければ `auth_hold` の 1 行）。`after_auth` の替え先があれば、同じ会話を「認証の失敗でアカウントを
替えた。中断したところから続ける」で続ける。既定のログインの認証の失敗も、登録済みアカウントへ替える。

替え先が無ければ子を残し（`stalled`）、ログインの形に合う直し方を 1 行出す（同じセグメントで 1 回）。この続きで失敗した接続先が
あれば、名前と直し方をすべて並べる。

| 今の形 | 直し方 |
| --- | --- |
| 既定のログイン | claude の中で `/login` |
| 登録済みアカウント | この子を `/exit` で終えてから `ndf relay account add <名前>` |
| 従量の接続 | `ndf relay account check metered` |
| API キー | `ndf relay account add-api-key <キーの名前>`（キーの子は子を残さずに止める。[ndf-relay-metered-and-api-keys.md](ndf-relay-metered-and-api-keys.md)） |

再登録（`account add` の成功）と `ndf relay account use <名前>` は、その名前を `held.json` から消す（直した後に 1 時間待たせない）。
従量の接続と API キーの認証の失敗は外した間に記録せず、続けて復帰する間は試して失敗した接続先を候補から除き（`tried`）、
替えた先で応答が 1 つ返ったら除くのをやめる。

### 再起動ループの検出

1 日の起動の上限（`relay.max-starts`・`NDF_RELAY_MAX_STARTS`）は持たない。`NDF_RELAY_MAX_STARTS` は読まず、設定されていても
誤りにしない。リレーハブの登録簿は起動の回数（`starts`）を持たず、`hub ls` の項目からも外した（`hub.RETIRED_KEYS`）。

セグメントは、子を 1 回起動してから、ラッパーが次のセグメントを起動する手（区切り・落ちた後の起動し直し・引継ぎ・
アカウントを替える手）を決めた時点までである。その長さが `relay.spin` の `seconds`（120）未満なら短いセグメントである。
ラッパーは短いセグメントの続き（`Streak`。数と、続きの中で起動した起動先）をメモリに持ち、次を起動する前に進める（`advance`）。

| 終わったセグメント | 続き |
| --- | --- |
| 短くない | 数を 0 にし、起動先を終わったセグメントと次のセグメントの 2 つにする |
| 短く、アカウントを替える手で、替え先が続きの中でまだ起動していない起動先 | 数を足さず、替え先を起動先に足す |
| それ以外の短いセグメント（区切り・起動し直し・引継ぎ・既に起動した起動先への替え） | 数を 1 足し、次の起動先も足す |

数が `relay.spin` の `count`（3）に達したら、次のセグメントを起動しない（`spin`）。子が動いていれば止めずに中継を続け、
そのセグメントの間は以後の区切り・替えでも起動しない（保持）。画面に理由の 1 行、`log.jsonl` に `stop` の行（理由 `spin`）を
出す。保持はそのセグメントが起動から 120 秒に達したら解け、上限の後の替えを含めて通常どおり続く。子が終わっていれば `end` の
行（理由 `spin`）を書いて終わる（停止理由 `spin`。`contracts/causes.json`）。当たるかは、判断の関数の替え先ではなく実際に
起動する起動先ごとに決める。1 つ目のセグメントも数え、待つ手（`wait_reset`・`stalled`）はセグメントを終えない。

秒は環境変数 `NDF_RELAY_SPIN` で替え、0 で検出を切る。リレーハブの `ndf relay restart` は、対象を止める前に後継へ渡す環境で
`NDF_RELAY_SPIN` を確かめ、数でない・負なら止めずに断る。続きはラッパーのプロセスごとで、起動し直したラッパーは空から始める。
利用者は原因を直してから、端末のラッパーは `ndf relay run`、名前つきのラッパーは tmux の外から `ndf relay restart <名前>` で
起動し直す。

### 次の手の順

`switch_decide.decide` は、上から順に最初に当たった条件で手を決める。

1. API キーの子の停止（`must_end`）
2. 回答待ちの質問（転送か待つ）
3. 再起動ループの保持の間に子が終わった（`spin`）
4. 上限の後（`limit_pick`）か認証の失敗の後（`auth_pick`）の替え・`wait_reset`・`stalled`
5. 次のセグメントのマーカー（区切り）
6. 見回りの替え（止めてよい時点なら `account`、それまでは待つ）
7. 子が終わった（`finish` か起動し直し）
8. 文脈の上限の引継ぎ・出力の止まりの再起動・待つ

次のセグメントを起動する手は、どれも再起動ループの検出（`_spin_or`）を通る。

## データ・設定

| パス | 形 | 書き手 |
| --- | --- | --- |

| `<状態の保存先>/relay/accounts/held.json` | `{"<名前>": {"<世代>": {"until"}}}` | ラッパー（`relay-auth-held`） |
| `<状態の保存先>/relay/accounts/limited.json` | `{"<名前>": {"<世代>": {"seen_at", "until", "window", "window_resets_at"}}}` | ラッパー（`relay-limit-seen`） |

状態の保存先は `NDF_STATE_HOME` → `$XDG_STATE_HOME/ndf` → `~/.local/state/ndf` の順に決まる。`held.json`・`limited.json` の
書き手は自分の世代の項目だけを書き、ほかの世代の項目を上書き・削除しない（再登録の後に旧い世代のラッパーが遅れて書いても
新しい世代の項目は残る）。終わった項目と世代の違う項目は読む側が無いものとし、次に書くときに消す。登録・削除の成功の後に
`forget` が旧い世代の項目・ファイルを消す。

## 決定と理由

- **使用率は使用率の API ですべての登録済みアカウントから取り、status line の `rate_limits` を代わりにする。** status line
  だけでは動いている子のアカウントの値しか届かず、替え先の値が古いか分からないままになる。最後の砦で、最も早く解ける
  アカウントが解けたことを確かめられない。トークンを更新しないと、動いていないアカウントのアクセストークンが期限を過ぎて
  値が取れなくなる
- **記録はアカウントと世代ごとのファイルにする。** 1 つのファイルを排他の中で書き換えると、会話の更新ごとに動く status line の
  すべてのレーンが 1 つの排他を待つ。世代を分けるのは、再登録の前の記録を新しい登録に効かせないためである
- **閾値を 3 つ持ち、同じ組では 7 日の窓のリセットの早いものを先にする。** 1 つの閾値（90%）で最も空いたものへ替えると、
  5 時間と 7 日の窓を区別できず、リセットの近いアカウントの残量を捨てる。直近まで使っていたものを先にすると、リセットの
  早い窓の残量がリセットで消える。替える回数を抑える利点は切り替えの余裕で残す
- **使用率の分からないものは余裕の組の次に置く。** NDF が最近そのアカウントで子を動かしていないためで、最初の応答で使用率が
  分かり、外れていれば次の見回りで並べ直せる
- **見回りで閾値 A・C を見て、止めてよい時点で子を止めて `--resume` する。** たたき台の `/ndf:restart` は、モデルが応答して
  `ndf-next` のブロックを出す必要があり、応答の途中・上限の直前・停まった子では働かず、新しい会話で文脈を捨てる。子の端末へ
  `/exit` を書くことはしない（子の端末へ書くのは利用者の入力を渡すときだけ。#3814）。閾値 B は見回りで見ない（会話の途中で
  替えると文脈の読み直しの費用を払う）
- **直近の消費の速さから替える時点を決めない。** 使用率は応答ごとに届き、同じアカウントの複数のレーンの消費が混ざり、
  次に止めてよい時点までの時間も分からない。固定の閾値で塞げないのは、1 回の呼び出しで閾値の手前から上限まで動く場面と、
  閾値を越えてから止めてよい時点までに上限へ届く場面だけで、どちらも守り 3 が拾う
- **閾値を越えても先に従量の接続へは移らない。** 残量があるのに利用料を払う（Value 2）
- **最後の砦はラッパーに置く。** ラッパーの下のすべての子（オーガナイザー・レーンの conductor）に効く。同じアカウントの
  リセットだけを待つと、ほかのアカウントが先に解けても待ち続ける。従量の接続から戻るのをカットポイントだけにすると、
  解けたアカウントがあっても利用料を払い続ける
- **認証の失敗は 1 時間外して替える。** 子を残して利用者を待つと、2 つ以上のアカウントがあってもレーンが止まる。画面の文字列
  だけで替えると、利用者の入力やモデルの応答の `API Error: 401` で動く
- **1 日の起動の上限を消し、再起動ループの検出だけに戻す。** 回数の上限は、レーンの数と時間に比例して壊れていなくても当たる。
  アカウントを替えた起動をすべて数えると、正しい替えが 3 つ続くだけで止まる。一切数えないと、替え先の除外の記録が書けない
  ときに同じ起動先の間を回り続ける。続きの中で初めての起動先だけを数えなければ、正しい替えは止めず、回り続ける替えは 3 つで
  止まる（systemd の `StartLimitIntervalSec`・`StartLimitBurst` と同じ「短い時間に何回」の形）

## セキュリティ

- 秘密（アクセストークン・リフレッシュトークン）を読んで外の宛先へ送り、認証ファイルを書き換える（レッドラインの C1・C2）。
  送るのは使用率の API と更新の宛先だけで、転送を追わない。値を画面・`log.jsonl`・結果に出さない
- 動いているアカウントのトークンは claude が更新するので、NDF は更新しない（使用の届けで全プロセスを見る）
- 認証ファイルは確かめた実体の記述子からだけ読み書きし、照合から置き換えまでに HTTP の往復も排他の待ちも挟まない
- 脅威の範囲は、うっかりの利用者と権限の無い人だけである（#2773）

## 運用

- 利用者が使用率を見るのは `ndf relay account list`（窓の最大と `state`）と `log.jsonl` の `account` の行である。替わった理由は
  `account` の行の `reason` に、組と閾値と使用率で書かれる
- 状態の保存先の `held.json` は同じマシンのほかのレーンにも効く。直した後は `ndf relay account use <名前>` で外す
- status line の本体（`~/.claude/ndf-statusline.sh`）は SessionStart の `ndf statusline ensure` が置き直すまで古いままで、その間は
  status line の記録が欠ける（使用率の API の値で判断は続く）

### 既知の限界

| 場面 | 停まるか | 扱い |
| --- | --- | --- |
| 止めてよい時点が来ないまま上限に届く（長い 1 回の応答・長い Tool の実行）・1 回の呼び出しで閾値の手前から上限まで動く | 停まる | 守り 3 で戻る。停まった応答の途中の作業は、会話の記録に残った所までになる。閾値は `limits.json` で下げる |
| 既定のログインで起動した最初のセグメント | 守り 1 が効かない（使用率を記録しない） | 守り 3 で登録済みアカウントへ替わった後は効く。`ndf relay account use` で指定すれば最初から効く |
| 使用率の API も `rate_limits` も窓を返さない席（Team・Enterprise の席など。未確認） | 守り 1 が効かない | 使用率の分からない候補として扱い、守り 3 だけが効く |
| 登録済みアカウントがすべて上限で、従量の接続も API キーも無い | 停まる（避けられない） | 最も早く解けるアカウントの時刻まで待ち、人の入力無しで戻る |
| 再起動ループの検出に当たる | 子が動いていれば停まらない（上限に当たると起動から 120 秒まで守り 3 を待つ）。子が終わっていれば停まる | 原因を直して起動し直す |
| 上限か認証の失敗の後に、替え先も今のアカウントも用意できない（`account_unavailable`） | 停まる（会話を送らずに終わる） | 画面に理由の 1 行と「直してから起動し直す」を出す。利用者が直して起動し直し、同じ会話を `--resume` で続ける |
| 認証の失敗の行がネットワークの一時的な失敗でも出るか・403 の記録の形・上限の行のリセットの時刻の形 | 未確認 | 403 は替えない側に置く。リセットの時刻が読めなければ使用率のキャッシュの規則へ倒れる |
| アカウントを替えたときのプロンプトのキャッシュ | 替えるたびに新しいアカウントで文脈を読み直す前提（未確認） | 切り替えの余裕で替える回数を抑える |
| 上限を超えて使える追加の利用を買った利用者 | 使用率 100 以上で静かな子を上限と読むので、早く替わりうる | リリースの後の記録で見る |
| 120 秒以上かかる空回り・`NDF_RELAY_SPIN=0` | 再起動ループの検出を抜ける | 10 系と同じ穴（[ndf-development-loop-limits.md](ndf-development-loop-limits.md)） |
| ラッパーの外で直に打つ `claude` | 守られない | 範囲外 |
