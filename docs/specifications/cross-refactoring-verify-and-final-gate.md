# cross-refactoring: 群の単位で検証し、全体のテストが落ちると原因を見ずに取り消していた → 項目ごとに限ったテストで検証し、全体のテストは危険の印で 1 度だけ走らせ、落ちたら落ちたテストだけで原因を見分ける

## 目的

**改善項目は 1 件ずつ、その項目が触った箇所に限ったテストで検証する。** 検証は HEAD で行い、
同じコマンドになる項目どうしは 1 回だけ走らせて結果を共有する。

**全体のテスト（`--baseline-test`）は、検証の中では危険の印が立ったときに最大 1 回だけ走る。**
ほかに走るのは着手前の 1 回と最終ゲートの 1 回である（最終ゲートは使い回せれば走らせない）。

**全体のテストが落ちても、原因を確かめずに取り消さない。** 落ちたテストだけを今の HEAD と
着手前の HEAD で走らせ直し、揺れ・元からの失敗・変更が原因に分ける。変更が原因なら締め切りまで
直し、直らなければ印の項目を新しい順に絞って取り消す。

**直らない項目は項目の単位で取り消す。** 他の項目のコミットは残る。項目の単位で戻せないときだけ
取り消しを広げる。

**最終ゲートが落ちたら、予算を使い切った後でも必ず 1 度は直しを試みる。**

**取り消し・見送り・絞り込み・揺れの判定・次の試行に進むかは、状態ファイルの値・git・テストの
終了コードだけでスクリプトが決める。** 計画の後に判断のために LLM へ問わない。

例: 危険の印 D3 を持つ項目 I-002 と I-004 を採った実行で、検証の中の全体のテストが 3 件落ちた。

| 落ちたテスト | 今の HEAD で走らせ直す | 着手前の HEAD で走らせる | 分類 |
| --- | --- | --- | --- |
| `tests/test_a.py::test_x` | 通る | — | 揺れ（取り消さない） |
| `tests/test_b.py::test_y` | 落ちる | 落ちる | 元からの失敗（取り消さない） |
| `tests/test_c.py::test_z` | 落ちる | 通る | 変更が原因 → I-002 と I-004 を修正へ回す |

直しの試行の打ち切りまでに `test_z` が通らなければ、I-004 → I-002 の順に 1 件ずつ取り消し、
`test_z` が通った時点で止める。I-004 だけで通れば I-002 は残る。

**手順は
[`cross-refactoring` の `docs/02-plan-and-implement.md`](../../plugins/ndf/skills/cross-refactoring/docs/02-plan-and-implement.md) と
[`docs/04-verify-and-report.md`](../../plugins/ndf/skills/cross-refactoring/docs/04-verify-and-report.md)
が正である。** この文書が扱うのは、そこに書かない決定の理由と、進行の内部の契約である。
時間の決め方・控え・締め切りは [想定最大時間の確定仕様](cross-refactoring-time-budget.md) が持つ。

## 用語

本文は左の業務用語で書く。識別子は表・コードブロック・業務用語の初出の括弧書きにだけ置く。
想定最大時間・実装担当・改善項目・控え・完了の締め切りは
[想定最大時間の確定仕様の用語](cross-refactoring-time-budget.md#用語)と同じ意味で使う。

| 業務用語 | 識別子 | 何を指すか |
| --- | --- | --- |
| 限ったテスト | `items[].command` / `command_source` | 項目ごとの語の並び。シェルを通さずに走らせる |
| 範囲のテスト | `--round-test` / `round_test` | `--scope` のテストの置き場所を走らせるコマンド。限ったテストを組み立てる元で、組み立てられない項目はそのまま使う |
| 全体のテスト | `--baseline-test` / `baseline_test` | リポジトリのテストの全体 |
| 危険の印 | `items[].danger`（D1〜D5） | 限ったテストで覆えない変更を git の事実で表したもの |
| 検証の中の全体のテスト | `whole_test` | 危険の印で走らせた 1 回と、落ちたときの見分けと結末 |
| 揺れ / 元からの失敗 / 変更が原因 | `whole_test.flaky` / `preexisting` / `caused` | 落ちたテストの 3 つの分類 |
| 修正 | `fix` / `merge-fix` | 落ちた項目を実装担当が直す 1 起動と、その取り込み |
| 直しの試行の打ち切り | `budget.fix_end` / `converge._fix_stop` | 修正に使える残りが控えの `fix` より短くなった時点 |
| 取り消し | `undo.drop` / `drops[]` | 範囲を逆再生し、残す項目のコミットを積み直す手順と、その記録 |
| 最終ゲート | `final-gate` / `final_gate` | 全体のテストか継続的統合で合否を見る。単独起動ではその後に `cross-review` |
| 最終ゲートの修正 | `final-fix` / `merge-final-fix` | 最終ゲートの失敗を直す起動と取り込み。項目に属さない |

| 扱う | 扱わない |
| --- | --- |
| テストの追加と実装の取り込みの検査、限ったテストの組み立ての契約 | 計画・見積り・締め切りの決め方（[想定最大時間の確定仕様](cross-refactoring-time-budget.md)） |
| 検証と修正の繰り返し、危険の印、全体のテストの見分け、項目の単位の取り消し | `--scope` の関門・`assess`・文言固定テストの判定（[範囲のテストと assess](cross-refactoring-round-tests-and-assess.md)） |
| 最終ゲートと最終ゲートの修正の打ち切り、履歴へ追記する時点 | 結果なしの取り込みの共通手順と記名の読み方（[取り込みの共通手順](cross-refactoring-apply-intake.md)） |

## 背景

**検証の単位が群だった。** 変更の前は、書き換えるファイルが重ならない項目を群にまとめて
1 コミットで検証した。群は複数の担当と並列を前提にした単位で、1 者が順に適用するなら分ける
理由が無い。

**全体のテストの失敗の原因を確かめていなかった。** PR #951 の実行の報告を見た利用者から、
全体のテストが改善のせいで落ちたのか元から落ちていたのか区別できないと指摘があった
（2026-09-24）。原因を確かめずに印の項目をまとめて取り消すと、揺れや元からの失敗でも採った
項目を失う。利用者の指示は「締め切りが来るまでは修正を試みる」だった。

## 決定と理由

番号は #933 の決定の番号である。コードのコメントの「決定 N」はこの番号を指す。

| # | 決定 | 理由 |
| ---: | --- | --- |
| 13 | テストの追加は計画が項目に紐づけたテストだけにし、足したテストが今のコードで落ちた項目は `test_failed` で見送る。見送った項目と `not_done` の項目のテストのコミットは取り消す | 現状固定テストは今のコードで通って初めて比較の基準になる。落ちるテストを HEAD に残すと、限ったテスト・全体のテスト・最終ゲートがすべて落ちる |
| 14 | 検証は HEAD で項目ごとの限ったテストを走らせ、全体のテストは危険の印が立ったときに 1 度だけ走らせる | 後の項目は前の項目の上に積まれるため、HEAD で通ることが Pull Request に残る条件である |
| 15 | 落ちたテストを取り出せないときは、印の項目をまとめて取り消し、検証の中では走らせ直さない | 走らせ直すと検証の中の全体のテストが 2 回になる。取り消した後の HEAD は最終ゲートが確かめる |
| 16 | 最終ゲートの全体のテストは、検証の中で通った後に取り消しが無く HEAD が進んでいなければ使い回す | 同じ結果になる。着手前の全体のテストは、壊したのか元から壊れていたのかを区別する唯一の材料なので残す |
| 20 | D3 と D4 は名前の一致で判定し、言語ごとの参照の解決を持たない。D4 は示せないときに立て、D3 の見落としは残る危険として受け入れる | 標準ライブラリだけで言語を問わない。D3 を 0 件のときにも立てると、ほぼすべての変更で全体のテストが走る |
| 21 | `--round-test` をそのまま使う項目の D4 は、その対象の語の配下の追跡されたファイルで判定し、対象の語が無ければ立てる | その項目を検証したのは実際にそのコマンドで、覆う範囲を最も正しく表す |
| 22 | 全体のテストが落ちたら落ちたテストだけを走らせ直して見分け、変更が原因なら締め切りまで直し、直らなければ印の項目を新しい順に 1 件ずつ取り消す | 揺れや元からの失敗で採った項目を失わない。二分探索は全体のテストを何度も走らせるので採らない |

実装で決めた細部:

| 決めたこと | 理由 |
| --- | --- |
| 手順を外れたコミットを持つ項目は、そのフェーズのコミットを取り消して `status: reverted`（`failure_reason` に理由）にし、見送りに入れない | 見送りの理由を 8 つに保つ |
| 取り消しは起点から HEAD までを逆再生し、残す項目を積み直す。競合したら同じファイルを触った項目まで広げて 1 度だけやり直し、それも競合したら全件を取り消す | 1 回目の競合で全件を捨てない。半端な履歴より決定的な状態へ落とす |
| 取り込んでいない修正があるまま `verify` を呼ぶと、先に `merge-fix` を行う | 修正のコミットが項目に結ばれないまま HEAD に残るのを防ぐ |
| 危険の印の全体のテストの失敗の取り出しは pytest に限る | pytest は `-q` でも要約に `FAILED <ID>` / `ERROR <ID>` を出す（pytest 9 で実測）。jest / vitest の出力の形は確かめていない |

## 仕様

### 常に成り立つ条件

| 条件 | 破れたときの扱い |
| --- | --- |
| 検証の中の全体のテストは最大 1 回である | `verify` は `whole_test.ran` が真なら走らせない。直しの後は落ちたテストだけを走らせ直す |
| 差し替えずに `--baseline-test` を項目の検証に使わない | 組み立てられない項目は `--round-test` をそのまま使い、無ければ計画で `no_target` にする |
| 担当の申告で検証を減らさない | 所要・コミット・合否は git と実際のテストから取る。D5 の `risk` は印を立てる側にだけ使う |
| 検証を通っていないコミットを Pull Request に残さない | 取り込みと検証が取り消し、公開は進行側だけが行う |
| 取り消しの途中で落ちても再開できる | 取り消しの前に `pending_drop` と `pending_push` を立てて保存し、再開した取り込みと検証の入口でやり直す |
| 最終ゲートは押し出し済みの地点で、打ち切っても採った改善項目を取り消さない | 失敗として報告する |

### テストの追加と実装の取り込み

`merge-tests` と `merge-implement` は、そのフェーズの起点から HEAD までのコミットをトレーラー
`Item-Id` で項目へ振り分ける。**結果ファイルの申告は使わない。** 取り込みの前に実装担当が残した
未コミットの変更を捨てる。

| 見つけたもの | 扱い |
| --- | --- |
| `Item-Id` が無い・計画に無い・テストを足さない項目のコミット | そのコミットだけを取り消す |
| 手順を外れたコミット（範囲の外・トレーラー欠け・1 フェーズで 2 コミット以上・テストの追加がテスト以外を変えた・差分予算の超過・文言固定テスト・期待値の変更） | 項目を取り消す（`status: reverted`） |
| コミットが無い・完了の締め切りを過ぎてコミットした | `not_done` で見送り、項目のコミットを取り消す |
| 足したテストが今のコードで落ちた（その項目の限ったテストで走らせる） | `test_failed` で見送り、テストのコミットを取り消す |

求めるトレーラーは `Item-Id` / `Impl-Runtime` / `Impl-Model`（`vocabulary.REQUIRED_TRAILERS`）で、
読み方は [取り込みの共通手順](cross-refactoring-apply-intake.md#必須の記名の読み方) にある。
**項目の所要はコミットの時刻で測る。** 起点は、そのフェーズで最初の項目ならフェーズの CLI を
起動した時刻、2 件目からは同じフェーズの直前の項目のコミットの時刻である。修正のコミットは
項目の所要に入れない。

**テストの差分の判定は段 1（機械）だけを取り込みで行う。** 値が失われていれば項目を取り消す。
段 1 で決まらない差分は `items[].review_test_judgements` へ残し、改修計画の項目の節に
「レビューで確かめるテストの差分」として載せ、最終ゲートのレビューへ引き継ぐ（決定 25）。
通ったものとしては扱わない。

### 限ったテストの組み立て

`--round-test`（省けば `--baseline-test`）を `shlex.split` で語に分け、対象の語を計画の
`test_targets` へ差し替える（`testcmd.limited_command`）。組み立てた語の並びは
`shell=False` で走らせる。

| 元の実行器（前置きを読み飛ばした後） | 対象の語 | 組み立て |
| --- | --- | --- |
| 既知（`pytest` / `python -m pytest` / `python3 -m pytest` / `jest` / `vitest`） | 1 つ以上 | 対象の語を取り除き、最初の位置へ `test_targets` を並べる |
| 既知 | 0 個 | 末尾へ足す |
| それ以外 | 問わない | 差し替えない（オプションの値を対象と読み違えない。位置引数をパスとして読まない実行器で対象を走らせずに通るのを避ける） |

`test_targets` の各要素は、`--scope` のテストの置き場所の中のパスかそれに `::` で続くノード ID で、
パスの部分が作業ディレクトリに実在し（その項目が足すテストはまだ無くてよい）、シェルの構文の
文字と空白を含まないこと。1 つでも満たさなければ差し替えない。

### 検証と修正の繰り返し（`verify`）

| 順 | すること |
| ---: | --- |
| 1 | 実装済みの項目ごとに、HEAD で限ったテストを走らせる。同じ語の並びは 1 回だけ走らせ、出力を `<TMP_DIR>/verify-<項目>.log` に残す |
| 2 | 直しの試行の打ち切りに達していたら、落ちた項目を取り消す。**回数の上限は持たない**（決定 23） |
| 3 | 落ちた項目が残れば `VERIFY=fix` を返す。修正は落ちた項目のすべてを対象に 1 回起動し、`fix_count` を同じだけ数える |
| 4 | 落ちた項目が無くなったら危険の印を判定する。印があり、まだ走らせていなければ全体のテストを 1 度走らせる |
| 5 | 全体のテストが落ちたら見分ける（下の節） |
| 6 | 公開して `VERIFY=done` を返す |

**同じ語の並びを共有した項目は 1 つの修正の対象としてまとめる。** 取り消すときは新しい項目から
1 件ずつ取り消し、そのたびに共有したコマンドを走らせ直して、通った時点で止める
（`converge._revert_shared`）。通る前に取り消した項目だけが取り消しになる。

**直しの試行の打ち切りは時計で決める。** 修正に使える残り（`budget.fix_time_left`。終わりは
開始 + B − 全体のテストの控え 2 つ − `final_fix`）が控えの `fix` より短ければ打ち切る。
控えの `fix` を終わりから引かないのは、引くと控えた修正 1 回分が使われないためである。
`final_fix` を引くのは、検証の直しに最終ゲートの修正の時間を使わせないためである（決定 26）。

**修正の取り込み（`merge-fix`）** は修正の起点（落ちたときの HEAD。`state["fix"].base_sha`）から
HEAD までを `Item-Id` で読み、対象の項目のものだけを受け取る。1 件でも手順を外れたら修正の範囲
ごと取り消す（どのコミットが安全かを決められないため）。どちらの場合も修正の回数は数える。
所要は `start-phase fix` からの時計で測り、`fix_stats` と配分テーブルの `fix` に使う。

### 危険の印

| 印 | 条件 | 見るもの |
| --- | --- | --- |
| D1 | 項目のコミットが、項目の `path` と `tests` 以外のファイルを触った | `git show --name-only` |
| D2 | ファイルを消した・名前を変えた | `git diff-tree --name-status -M` の `D` / `R` |
| D3 | 触った本番のファイルが `--scope` の外のコードから参照されている | `git grep -lE`。探すのはコードのファイルだけ（`*.md` / `*.rst` / `*.txt` と `docs/` を除く）。語は末尾 2 区切りから作るモジュールの参照の形（`refactor_lib/plan`・`refactor_lib\.plan`・`refactor_lib import .*\bplan\b`）と修飾名の `symbol`。直下のファイルは行頭の `import` / `from`。パッケージの入口（`danger.ENTRY_NAMES`）は探さずに立てる |
| D4 | 限ったテストが触った本番のファイルを覆うと示せない | 限ったテストのファイルに、拡張子を除いたファイル名と `symbol` の名前のどちらも現れない。`--round-test` をそのまま使う項目はその対象の語の配下、対象の語が無ければ立てる |
| D5 | 公開の入出力が変わりうる | 計画が決めた `items[].public_io` を読むだけ（無い旧い状態は `risk`） |

**D3 は当たったときとパッケージの入口のときだけ立てる。** 動的な読み込みや文字列で組み立てた
import は名前が当たらず見落とす。見落としは最終ゲートが拾う。`git grep` 自体が失敗したら立てる。
印は項目ごとに `items[].danger`（当たった語は `danger_hits`）、全体として走らせた理由は
`whole_test.flags` に残る。検証を通った項目にだけ付け、付け済みの項目は見直さない。

### 全体のテストが落ちたときの見分け

`triage.classify` が次の順で分ける。全体のテストは検証の中で走らせ直さない。

1. 出力（`<TMP_DIR>/verify-whole-test.log`）の pytest の要約から落ちたテストの ID を取り出す
   （`testcmd.failed_nodes`）
2. それだけを今の HEAD で走らせ直す（`testcmd.rerun_command`）。通れば揺れ
3. まだ落ちるものを着手前の HEAD（`baseline_test.head`。無い旧い状態は `plan.base_sha`）で
   走らせる。作業ディレクトリは動かさず、一時の detach の作業ツリーで走らせて消す。落ちれば
   元からの失敗
4. 残りは変更が原因

**迷ったら変更が原因の側へ倒す。** 走らせ直しの出力から ID を読めなければ全部がまだ落ちている
とみなし、着手前の HEAD の出力から読めなければ元からの失敗とはみなさない。着手前の作業ツリーに
未追跡の依存が無くて落ちた場合も、読めなければ元からの失敗とはみなさない。

| 結果 | 結末（`whole_test.resolution`） | すること |
| --- | --- | --- |
| 変更が原因が無い | `kept` | 取り消さない。最終ゲートが全体のテストを走らせる |
| 変更が原因があり、締め切りの内 | `fixing` → 通れば `fixed` | 印の項目を `failing` にして修正へ回す。修正担当へ落ちたテストだけを走らせ直すコマンドと出力を渡し、次の `verify` は落ちたテストだけを走らせ直す |
| 締め切りまでに通らない | `narrowed` | 印の項目を新しい順に 1 件ずつ取り消し、落ちたテストが通った時点で止める。`reverted` を真にする |
| 取り出せない（実行器が pytest でない・要約の行が無い・打ち切られた） | `reverted_all` | 見分けも直しもせず、印の項目をまとめて取り消す。理由を `unparsed_reason` に残し、`reverted` を真にする |

### 取り消し

`undo.drop` は、起点（`plan.base_sha`）から HEAD までを新しい順に `git revert` で逆再生し、残す
項目のコミットを古い順に cherry-pick で積み直す。**範囲全体の逆再生は競合しない。** 競合する
のは一部のコミットだけを飛ばして戻すときである。

| 段 | 条件 | 記録（`drops[].mode`） |
| ---: | --- | --- |
| 1 | 指定した項目だけを取り消して積み直せた | `item` |
| 2 | 積み直しが競合し、同じファイルを触った項目まで広げて積み直せた | `widened` |
| 3 | それも競合した | `all`（計画の項目をすべて取り消す） |

- 積み直しで SHA が変わるため、`items[].commits` を新しい SHA へ更新する
- どの項目にも属さないコミット（過去の取り消しのコミット）は積み直さない
- `git push --force` は使わない。revert と cherry-pick による前進だけで行う
- コミットを持たない項目の取り消しは git を触らない
- 巻き込まれた項目の `failure_reason` にもその旨が残る

### 最終ゲート

| 起動のされ方 | 見るもの | 検証の中の全体のテストとの関係 |
| --- | --- | --- |
| `--ci-check` あり（単独・工程の 1 つ） | 継続的統合の結果（`check-runs` を 1 回読む。結果を得られなければ通さない） | 使い回さない |
| 工程の 1 つ・`--ci-check` なし | HEAD で全体のテストを 1 度 | 検証の中で走って通り、`whole_test.reverted` が偽で、HEAD が 1 つも進んでいなければ走らせずに通す（`gate._reusable_whole_test`） |
| 単独・`--ci-check` なし | 全体のテストを 1 度 → 通れば `cross-review`（`FINAL_GATE=cross-review`） | 同上 |

生成物の同期のコミットが積まれていれば HEAD は進んでいるので走らせる。最終ゲートの全体の
テストの所要は `final_gate.whole_test_seconds` に残り、使い回したら `whole_test_reused` が立つ。

| 終了コード | 意味 | 駆動 |
| ---: | --- | --- |
| 0 | 通った | 次へ（単独起動は `cross-review` へ） |
| 2 | 落ちた。`FINAL_GATE=failing`・`FINAL_FIX_IMPL`（実装担当）・`FINAL_FIX_ROUND` を返す | 最終ゲートの修正を起動し、`merge-final-fix` の後に `final-gate` をやり直す |
| 1 | 修正を打ち切った | 取り消さず、失敗として報告する |

**打ち切りは時計で決める**（`gate._final_fix_stop`）。

| 条件 | 打ち切るか |
| --- | --- |
| 起動し直しても解けない結末（利用上限）の印 `no_relaunch` が立っている | 打ち切る（1 回目の前には立っていない） |
| まだ 1 度も修正していない（`final_gate.fix_rounds` が 0） | **打ち切らない**（決定 26） |
| 2 回目から、`limits.final_end_at`（開始 + B）を過ぎた | 打ち切る |

`final-gate` は修正を起動する前に回数を上げるため、打ち切りの判定では 0、`start-phase` では 1 が
1 回目である。回数は上限としては使わない。計画を経ずに最終ゲートへ進んだ実行（`plan.reserve` が
無い）は控えが 0 になり、1 回目の長さの下限も 0 で余裕だけを渡す。**予算を超えうる幅は、最終
ゲートの修正 1 回分の見積り + 余裕に限られる。**

**最終ゲートの修正は項目の修正と別物である。** 直すのは全体のテストの失敗で、どの項目にも
属さない。求めるトレーラーは `Impl-Runtime` / `Impl-Model` の 2 つで `Item-Id` を求めない。
起点は落ちた時点の HEAD（`final_gate.fix_base_sha`）で、コミットごとのテストの合否は見ない
（直後の `final-gate` が 1 度だけ見る）。申告から漏れたコミットと範囲の外を触ったコミットは
修正の範囲ごと取り消す。結果を残さなかったときの扱いは
[取り込みの共通手順](cross-refactoring-apply-intake.md) にある。

### 履歴へ追記する時点

| 起動のされ方 | `finalize` を呼ぶ時点 | 追記する条件 |
| --- | --- | --- |
| 工程の 1 つ | `final-gate` の直後 | 最終ゲートが通った |
| 単独 | `cross-review` の最終スイープと確かめが終わった後。駆動は cross-review の状態ファイルを読み、`final` が `approved`・`sweep.verified` が真・`sweep.remaining_open` が 0・`sweep.commit` が無いときだけ `--review-status approved` を渡す | 最終ゲートの検査が通り、`--review-status` が `approved` |

**単独起動で `final-gate` の直後に追記しない。** その時点では `cross-review` の合否が決まって
おらず、収束しなかった実行が履歴に混ざる。`--review-status` を渡さずに単独起動の状態で
`finalize` を呼ぶと、追記せずに終了コード 0 で知らせる。中断（終了コード 4）した実行と、
最終ゲートが通らなかった実行は追記しない。

## データ・設定

`whole_test`（検証の中の全体のテスト）:

| キー | 中身 |
| --- | --- |
| `ran` / `flags[]` / `status` / `seconds` / `head` | 走らせたか・理由の印・`pass` / `fail`・所要・走らせた HEAD |
| `reverted` | 落ちて印の項目を取り消したら真。最終ゲートはこれが真なら必ず走らせる |
| `items[]` | 印を持っていた項目（新しい順） |
| `failed_tests[]` / `flaky[]` / `preexisting[]` / `caused[]` | 落ちたテストとその分類 |
| `baseline_head` / `rerun_command[]` / `rerun_log` | 見分けに使った着手前の HEAD・走らせ直すコマンド・その出力 |
| `resolution` | `kept` / `fixing` / `fixed` / `narrowed` / `reverted_all` |
| `unparsed_reason` | 取り出せなかった理由 |

そのほかの検証のキー: `verify_stats`（`items` / `seconds`）・`fix_stats`（`launches` / `seconds`）・
`fix`（進行中の修正の `items` / `base_sha` / `attempt`。取り込んだら `null`）・`drops[]`・
`pending_drop`。最終ゲートは `final_gate` に `fix_rounds` / `checks[]` / `impl` / `fix_base_sha` /
`whole_test_seconds` / `whole_test_reused` / `no_relaunch` / `review_status` /
`failed_attempts[]` を持つ。

| 印が立つと全体のテストが 1 度だけ走り、最終ゲートが使い回し、直らないまま取り消すと最終ゲートが走らせ直すこと | 同 `test_phases_git.py` |
