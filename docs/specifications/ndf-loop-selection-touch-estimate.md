# 開発ループの選定と並列の計画の検査: 触る場所の見込みが重なる課題を同じスプリント・同じ時間帯に集めない

## 概要

**開発ループの選定（`loop select`）は、候補の課題ごとに触る場所の見込みを出して記録し、逆転の幅が 1 以上なら、順位の近い
課題の間で見込みが既に選んだ課題と重ならない課題を先に選ぶ。** 並列の計画の検査（`parallel.py check`）は、同じ時間帯に
動くレーンの課題の見込みが重なると、規則 `I21` の警告で重なる組と直し方の案を出す。

例: 残りの枠が 2 件、逆転の幅が 1 で、順位の順に #A・#B・#C が並び、#A と #B の見込みが同じファイルを含み #C は重ならない
とき、選定は #A と #C を選び、記録の `reorders` に `{"later": B, "earlier": C, "with": [A]}` を残す。逆転の幅が 0 なら
#A と #B を選ぶ。

**逆転の幅の既定は 0 で、並べ替えは既定では効かない。** 見込み・出所・重なりの記録と検査の `I21` は、逆転の幅に関わらず
働く。

選定の手順の全体と記録の全項目は [ndf-workflow-development-loop.md](ndf-workflow-development-loop.md) が、並列の計画の検査の
規則の一覧は `plugins/ndf/skills/issue-plan-strategy/references/parallel-plan.md` の「検査」が正本である。この文書は見込みの
出し方・並べ替え・`I21` の契約と、その形にした理由を持つ。

## 用語

「触る場所の見込み」「見込みの出所」「同時に動く本数」「順位の逆転」「逆転の幅」の定義は用語集（[docs/glossary.md](../glossary.md)）の
「NDF の工程（`ndf-workflow`）」が正である。

## 背景

選定が順位と課題数の上限だけで課題を選ぶと、同じ主題の課題が 1 つのスプリントに集まり、実装のキューが重なりの組として
直列に流す。マージキューの製品（Mergify の並列のモード。https://docs.mergify.com/merge-queue/queue-modes.md ）は、触る範囲を
共有しない変更を同時に流し、共有する変更だけ順序を保つ。NDF では実装のキューの判定はそのままにし、選ぶ側で重ならない課題を
同じスプリントに入れて待ちを減らす。

## 仕様

### 常に成り立つ条件

| 条件 | 破れたときの扱い |
| --- | --- |
| 選定の行（選んだ・外した）は、見込みのパスの一覧と出所を持つ。出所は `設計の結果` / `課題グループの表` / `課題の本文` / `見込みなし` のどれか | テストが落とす |
| 選んだ行は、先に選んだ課題との重なり（`あり` / `なし` / `不明`）と相手の番号を持つ。見込みなしの課題との組は `不明` | テストが落とす |
| 先頭に選ぶ課題（承認した設計・直して出し直す課題・デプロイの直し）と品質の枠の課題は、重なりがあっても選ばれる | テストが落とす |
| 順位の逆転は、窓（残りの枠の数＋逆転の幅の件数）の内でだけ起きる | テストが落とす |
| 重なりを理由に選ぶ課題の数は減らない。候補がすべて互いに重なれば、逆転の幅 0 と同じ組になる | テストが落とす |
| 逆転の幅が 0 なら、選ぶ組は並べ替えの無い選び方と同じになる | テストが落とす |
| 見込みの欄と `reorder_width` の無い古い記録を読んでも選定は止まらない。既存のキーの形は変わらない | テストが落とす |
| `after` を推移的にたどって順序の付かない同じリポジトリの 2 レーンで課題の見込みが重なれば、`I21` の警告に組と案が載る。順序の付いたレーンの間では出さない | テストが落とす |
| 見込みの重なりは、実装のキューと同じ関数（`supervise_lib/admission.py` の `overlap_of`）と同じ共有の一覧（`.ndf/supervise.json` の `queue.shared`）で判定する | テストが落とす |
| 見込みのパスは、そのリポジトリの追跡しているファイル（`git ls-files`）と照らして決め、ディレクトリの名前を前提にしない | テストが落とす |

### 構成要素と責務

| 要素 | 責務 |
| --- | --- |
| [`lib/touch_estimate.py`](../../plugins/ndf/scripts/lib/touch_estimate.py) | 見込みの出し方（`from_design`・`from_group_table`・`from_body`・`estimate`）と並べ替え（`spread`）は値を返すだけ。外を読むのは集める関数（`issue_estimate`・`lane_estimates`・`shared_list`・`git_tracked`）だけ。`I21` の組と案は `lane_overlaps` が返す |
| `lib/sprint_loop_select.py` | 候補ごとに見込みを集め、枠の割り当てで `spread` を呼び、選定の行と `reorders` を書く |
| `lib/sprint_loop.py` | 記録を作るときに、進め方の宣言の逆転の幅を `reorder_width` として記録へ写す |
| `lib/pace.py`・`contracts/settings/pace.json.json` | `loop.reorder_width` を読み、形を検査する |
| `lib/parallel_plan.py` の `check_data` | 見込みの表（レーン → 課題 → パス）を任意で受け、`I21` の警告を返す |
| `parallel.py` | `check` のときにレーンの課題の見込みを集めて `check_data` へ渡す |
| [`scripts/experimental/selection-replay.py`](../../plugins/ndf/scripts/experimental/selection-replay.py)（実験版） | スプリントの記録から、並べ替えの有無で実装のステージの同時に動く本数の平均を比べる |

### 見込みの出し方

出所は 設計の結果 → 課題グループの表（マイルストーンの説明の `### 並列の組（見込み）`）→ 課題の本文 の順に見て、見込みが
1 件以上出た最初の出所だけを使う。出所を合わせると、設計の結果がある課題で確定した触るファイルより広くなるためである。

| 出所 | 何を取るか |
| --- | --- |
| 設計の結果 | マージ済みの設計文書の「設計の結果」の表の、その課題の触るファイル |
| 課題グループの表 | その課題の行の「触る場所の見込み」の列の、バッククォートで囲んだパス。パスの包含で読み、ディレクトリも取る。追跡しているファイルに当たらない語（Skill の名前など）は捨てる |
| 課題の本文 | 見出し「目的」「対象範囲」（「含まない」より前）「事象」「原因の見当」の中のバッククォートの語。見出しが 1 つも無ければ全体。追跡しているファイルに完全に一致する・glob が当たる・末尾のパスの要素が 1 つのファイルだけに一致する語だけを残し、ディレクトリは取らない |

本文からディレクトリを取らないのは、親ディレクトリと共通の文書（`AGENTS.md` など）がほぼすべての課題に入り、すべての課題が
互いに重なるためである。切り出しの境界の外の課題は本文を読まない（`note` が `切り出しの境界の外`）。本文を読めない課題は
見込みなし（`note` が `本文を読めない`）にし、選定を止めない。`gh` は候補 1 件あたり本文の 1 回だけで、出所 1・2 で見込みが
出た課題は呼ばない。`git ls-files` は選定 1 回につき 1 回である。

### 並べ替え（`spread`）

1. 枠の順（先頭に選ぶ課題 → 品質の枠 → 残り。業務時間外は先頭に選ぶ課題 → 設計を要る課題 → 設計の要らない課題）の先頭から、
   先頭に選ぶ課題と品質の枠の課題を、重なりを見ずに取る
2. 残りの枠の数を `k` とし、残りの候補の先頭から `k + 逆転の幅` 件を窓にする
3. 窓の中を順に見て、見込みが既に取った課題のどれとも `あり` にならない課題を、枠が埋まるまで取る。見込みなしの課題は `不明` で取る
4. 枠が残れば、取らなかった候補を枠の順に戻して埋める
5. 取った課題のうち、窓の中で自分より前にあって取らなかった課題を、`later` と `earlier` の組にする

重なりの値は、選んだ順で自分より前に選んだ課題だけと比べる。どれかと重なれば `あり`、重ならずに見込みなしの相手が 1 つでも
あれば `不明`、それ以外は `なし` である。自分の見込みが無ければ、相手がいる限り `不明` になる。

### 決定と理由

| 決定 | 理由 |
| --- | --- |
| 逆転の幅は候補の件数で数え、`.ndf/pace.json` の `loop.reorder_width` で受ける。記録を作るときに値を記録へ写し、ループの途中で宣言を変えても同じループの選び方は変えない | 順位の値の差はマイルストーンごとに尺度が違い、同じ幅が別の範囲を指す。上限を設けずにすべての候補を並べ替えると、順位の低い課題が重なりの少なさだけで先に出て、棚卸しの順位を上書きする |
| 逆転の幅の既定は 0 | 選ぶ時点に使える見込み（課題の本文）で模擬すると、並べ替えの有無で同時に動く本数の平均が変わらなかった（「運用」）。効果が測れない並べ替えで順位を変えない |
| 重なる課題は外さず後ろへ回し、空いた枠は順位の順に戻して埋める | 課題を減らすと、同時に動く本数ではなくスプリントの量が減る |
| `I21` は警告にとどめ、案を添える | 見込みは確定ではなく、外れの率は測っていない。外れた見込みで起動を止めると、レーンを組めない計画が出る。レーンの宣言の重なり（規則 `I4`）は変えない |
| 過去の変更で一緒に変わったファイルを見込みに足さない | 模擬で平均が変わらず、選定 1 回ごとに履歴を読む費用だけが増える |
| 課題グループの表を必ず書かせる検査は足さず、列の値の形（リポジトリの根からのパス）だけを決める | 表が無くても本文の出所で見込みが出る。棚卸しの手順を増やさない |
| 重なりの判定は `admission.overlap_of` を使い、グラフのライブラリ（networkx の塗り分け）を使わない | 選定は順位の順に 1 件ずつ取る貪欲法で、塗り分けは順位を保たない。判定の関数を増やさない |

## データ・設定

### 進め方の宣言

| 項目 | 形 | 無いとき | 誤っているとき |
| --- | --- | --- | --- |
| `loop.reorder_width` | 0 以上の整数（bool は不可） | 0 | `PaceError`（`loop start` を断る） |

### 開発ループの記録（`loop.json`）へ足すキー

| 置き場 | キー | 形 |
| --- | --- | --- |
| 記録の根 | `reorder_width` | 0 以上の整数。無い古い記録は進め方の宣言の値（読めなければ 0）で読む |
| 選定の行（すべて） | `touch` | `{"paths": [str], "source": str, "note": str}` |
| 選定の行（選んだ行） | `overlap` / `overlap_with` | `"あり"` / `"なし"` / `"不明"` と、`あり`・`不明` の相手の番号の配列 |
| ループの 1 回 | `reorders` | `[{"later", "earlier", "with"}]`。逆転が起きたループの 1 回だけが持つ。選び直したループの 1 回には前の組を残さない |

`loop select` の結果の JSON は、`items` の選定の行に同じキーを、逆転があれば `reorders` を載せる。既存のキー・`status`・終了コードは変えない。

### 並列の計画の検査の項目（`I21`）

```json
{"level": "warning", "rule": "I21", "at": "lanes",
 "message": "同じ時間帯に動くレーンの課題の見込みが重なる: lflow #2997・lcost #2913（plugins/ndf/scripts/lib/sprint_loop_select.py）",
 "lanes": ["lcost", "lflow"], "issues": [2913, 2997],
 "paths": ["plugins/ndf/scripts/lib/sprint_loop_select.py", "plugins/ndf/scripts/lib/sprint_loop_select.py"],
 "proposals": [{"kind": "after", "lane": "lflow", "after": "lcost"},
               {"kind": "move", "issue": 2997, "from": "lflow", "to": "lcost"}]}
```

| 項目 | 決まり |
| --- | --- |
| 検査の成否 | `level` は `warning` で、終了コードを変えない。計画の書き込みと起動を止めない |
| レーンの課題 | スプリントのレーンは `input.issues`。ループのレーンは `--milestones` のマイルストーンの課題グループの表の課題（`--milestones` が無ければ見ない） |
| 案 `after` | 計画の後ろのレーンの `after` に前のレーンを足す |
| 案 `move` | 2 つともスプリントのレーンのときだけ付ける。ループのレーンの課題は選ぶのがループのため移さない |
| 見込みを集められない | `I21` の警告を 1 つ出し、`message` に理由を書く。検査は続ける |
| 別のリポジトリのレーン | 同じリポジトリのレーンの間だけで判定する |

## 運用

`selection-replay.py` は、スプリントの記録（設計の結果・実装のプランの所要・実装の PR が変えたファイル）を入力に、並べ替えの
有無で同時に動く本数の平均（所要の和 ÷ 経過）を出す。経過は重なりの組を組ごとに直列にし、`--max` 本の枠へ長い組から
割り当てて求める。実装のキューの触るファイルは `--queue-files design`（記録の設計の結果）か `--queue-files changed`
（実装の PR が変えたファイル）で選ぶ。結果は実験版の台帳（[docs/ndf-experiments.md](../ndf-experiments.md)）にあり、lcost-1 の
7 件では、課題の本文を見込みにしたとき並べ替えの有無でどちらも 1.0 本だった。

### 既知の限界

| 項目 | 内容 |
| --- | --- |
| 見込みに出ないファイル | 実装の PR の重なりの多くは、確定仕様・契約の一覧（`plugins/ndf/contracts/index.md`）・実験版の台帳など、課題の本文に出ないファイルで起きる。選ぶ時点の見込みではこれらの重なりを知らない |
| 見込みの外れの率 | 測っていない。記録の `touch` と設計の結果の触るファイルを後から突き合わせて数えられる |

## テスト観点

- 選んだ行と外した行のすべてが `touch` の `paths` と `source` を持ち、本文にパスの無い課題の `source` が `見込みなし` であること
- 選んだ行に `overlap` と `overlap_with` が載り、見込みなしの相手との組が `不明` であること
- 上位から重なる 2 件・重ならない 1 件・上限 2 で、重ならない組が選ばれ `reorders` に組が載ること。窓の外の重ならない課題は先に出ないこと
- 候補がすべて重なると、逆転の幅 0 と同じ組になること
- 先頭に選ぶ課題と品質の枠の課題が、重なりがあっても選ばれること
- 逆転の幅 0 で、並べ替えの無い選び方と同じ組と行を返すこと
- `after` の無い 2 レーンに見込みの重なる課題があると `I21` に組と `after`・`move` の案が載り、推移的に `after` で順序を付けた 2 レーンでは出ないこと
- 追跡しているファイルの一覧を別の形（`src/app/models/user.rb` など）にしても、本文のパスから見込みが出ること
- 見込みの欄と `reorder_width` の無い記録で選定が通ること
- 見込みが共有の一覧に当たる 2 件を `あり` と判定すること
- `loop.reorder_width` の既定が 0 で、負の数・真偽値を断ること
- 模擬の平均の式で経過の代わりに所要の和を使うと値が変わること（小さな入力で値を固定する）

テストは `plugins/ndf/scripts/tests/test_touch_estimate.py`・`test_sprint_loop_touch.py`・`test_parallel_touch_estimate.py`・`test_pace.py` にある。
