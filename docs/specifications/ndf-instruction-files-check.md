# エージェント向け指示書を適切に保つチェック

エージェントが読む指示書（`AGENTS.md` / `CLAUDE.md` / `KIRO.md`）を適切に保つチェックを、NDF の
配布物のスクリプト 1 本（`plugins/ndf/scripts/instructions-check.py`）として配る。落とすのは 4 つ
（参照先の無い即時読み込み / 許可していない即時読み込み / 出た版の段落 / 読み込みの量の上限）、
報告だけが 2 つ（読み込みの量 / 指示の数）で、閾値は配布物に持たず、リポジトリ側の宣言
（`.ndf/instructions.json`）が判定の強さを決める。この文書は、決めたことの理由と、判定と宣言の契約を残す。

**呼び方・宣言の書き方・落ちたときの直し方は `release` の `references/instruction-files.md` が正
である。** チェックを呼ぶ時点（版の判断の退避の直後）は `release/SKILL.md` の「3. 版と説明文書を更新する」
が持つ。

| 何を読むか | 正本 |
| --- | --- |
| 実行の 4 行、引数の一覧、終了コード、宣言の書き方、落ちたときの直し方、観点の調べ直し | `plugins/ndf/skills/release/references/instruction-files.md` |
| 宣言の定義（編集時の補完） | `plugins/ndf/skills/release/schemas/instructions.schema.json` |
| 観点・強さ・要る宣言・出典 | `plugins/ndf/scripts/data/instruction-criteria.json` |
| 判定の手続き | `plugins/ndf/scripts/instructions-check.py` と、この文書の「仕様」 |

## 概要

**同じチェックが、リポジトリ側の宣言の有無で違う強さで働く。** 宣言が無くても動くのは、リポジトリの
性質によらず誤りである「参照先の無い即時読み込み」と、落とさずに数える「読み込みの量」「指示の数」
だけである。宣言を書けば、許可していない即時読み込み・出た版の段落・量の上限で落ちる。

**チェックは判定だけを行い、どのファイルも書き換えず、課題も立てない。** 指摘には扱いの目印
（`直す` / `起票` / `報告`）を付けるが、書き込みと外部への投稿は呼び出し側が行う。

**新しい Skill は無い。** 実行するのは 1 コマンドで、判断が要るのは「どこへ退避するか」であり、それは
`release` の退避の手順が既に持つ。Skill を足すとその説明文が全セッションの固定費に乗る。

**何を見るかは外部の一次情報から導き、データとして持つ。** 出典 23 件から出た 21 の観点のうち、機械で
判定できる 6 つだけを入れ、残る 15 は入れない。観点の一覧は `--refresh` で調べ直せるが、提示するだけで
書き換えない。

## 用語

| 用語 | 意味 |
| --- | --- |
| 指示書 | エージェントが読む規約の文書。既定の名前は `AGENTS.md` / `CLAUDE.md` / `KIRO.md` |
| 根の指示書 | スコープの根に置かれた指示書。セッションのたびに読まれる |
| 配下の指示書 | サブディレクトリに置かれた指示書。その場所で作業したときに読まれる |
| 即時読み込みの参照 | コードの外に書いた `@<パス>`。参照先の内容がそのまま読み込まれる |
| 出た版 | リポジトリが配布済みとして宣言した版。取り出し方（変更履歴の文書・タグ）は宣言が決める |
| 宣言 | リポジトリ側に置く `.ndf/instructions.json`。無ければ既定の判定だけが動く |
| 読み込みの量 | 根の指示書と、そこから即時読み込みでたどった先の合計バイト数 |
| 観点 | 指示書がどうあるべきかの 1 項目。外部の一次情報から導き、`instruction-criteria.json` が一覧を持つ |
| 落とす / 報告する | 観点ごとの強さ。落とすものは終了コード 1、報告するものは数を出すだけ |
| 調べ直し | `--refresh`。観点の出典を読み直し、食い違いを提示する（書き換えない） |
| スコープ | 指示書の置き場所の区分。プロジェクト（`--root` の下）/ ユーザー（利用者の home）/ プラグイン（取得先の配布物） |

## 背景

**「開発の指示書には現行版で決めたことだけを残す」という規則を、機械で見ていなかった（#554）。**
`ai-plugins` の `f56c90d9`（PR #552 の直前）では、`CLAUDE.md` に出た版の段落が 7 件残り、退避先を
`@` で毎回読ませていた。指示書の分量は行数ではなく読み込みの量で見る必要がある（分量の基準は文書の
種類で変わる）。利用者の依頼は、インストールされたスコープ全体の指示書を、配布物の側の機能として
適切に保つことだった。

**指示書が適切であるとは、書いたことが実際に守られる状態を指す。** 長い入力そのものが精度を下げ
（Context Rot）、指示の数が増えると遵守率が落ち（IFScale）、中央に置いた情報が最も使われない
（Lost in the Middle）。ランタイム側の助言はこの土台を各社が数値へ落としたもので、数値は揃っていない
（200 行 / 500 行 / 2 ページ / 32 KiB）。

## 決定と理由

**判定の強さはリポジトリ側の宣言で決め、宣言が無ければ既定の判定だけを動かす。** 利用者は NDF を入れた
任意のリポジトリで、版を持たない・変更履歴を持たない・指示書を 1 本しか持たないリポジトリがある。全部に
同じ判定を掛けると入れた瞬間に落ちる。宣言が無いことを終了コード 2 にしない。

**宣言は `.ndf/instructions.json` に置く。** `worktree.json` / `projects.json` と同じ場所で、NDF に渡して
いる値を 1 つのディレクトリで見渡せる。1 つの大きな宣言へ相乗りしない（読み手が違う）。

**走査は `git` が追跡する既定の 3 つの名前とし、根と配下を区別する。** 追跡していないファイルを入れると
実行した環境で結果が変わる。量の集計は根に限り、判定は両方に掛ける。

**出た版の取り出し方は宣言から受け取り、`changelog` と `tags` の 2 つの形を用意する。** タグは配布の
後に打つため配布の Pull Request の時点では無く、浅い clone でも取得されない。節の一覧との一致ではなく
最大値との大小で見る（一覧で見ると、変更履歴に節を持たない版の段落を取りこぼす）。

**版の段落は段落の先頭と見出しの書き出しで拾い、目印は宣言があるときだけ見る。** 行の途中の版数まで
見ると現行の規約の文が指摘される。段落の途中の行も見ない（折り返した先の行が版数で始まることがあり、
`f56c90d9` では 7 件が 9 件になる）。版が決まる前の段落の目印（`pending_marker`）は言い回しがリポジトリ
ごとに違うため、既定を置かない。

**読み込みの量はバイトで数え、上限は宣言があるときだけ判定する。** トークン数では継続的統合に CLI の
認証と課金が要り、値は読み込む設定で変わる。バイト数は絶対値としては粗いが増減は追える。

**閾値を配布物に持たず、落とすのは宣言に書いたときだけにする。** 4 つのランタイムが別々の値を助言して
おり、どれを既定にしても他の 3 つでは誤りになる。最も厳しい値を既定にすると、利用者が最初に外すチェックになる。

**即時読み込みの一致範囲は実測に合わせる。** Claude Code 2.1.274 で 8 通りを実測し、読み込まれた 2 通り
（行頭・空白の直後、強調の中）を参照として見る。読み込まれない書き方まで指摘すると、囲む必要の無い記載を
直させることになる。

**実体は配布物の中で完結させる。** 利用者のリポジトリの `scripts/` を読まない。調べ直しの部品（取得・
指紋の比較・一覧の提示・待ち）は `plugins/ndf/scripts/lib/refresh.py` へ置き、#743（Skill の陳腐化）と
共有する。

**観点の根拠を出典として残し、値そのものは持たない。** 数値を写すと写した側だけが古くなる。残すのは
出典の名前・URL・参照日・主張である。

**調べ直しは引き金を決めた別の経路にし、自動で書き換えない。** 引き金は日数（既定 90 日）・配布の工程・
手での起動の 3 つで、日数を過ぎても落とさず `NOTE:` を出すだけである。自動で書き換えると、外部の記述の
読み違いがそのままチェックの基準になる。ランタイムの版は引き金にしない（実行している CLI の版を確実には
取れない）。

**走査の既定をプロジェクトに絞り、ユーザーとプラグインは宣言と引数で足す。** 主な実行先は継続的統合で、
そこには利用者の home もプラグインの取得先も無い。位置はランタイムごとに違い版で動くため、配布物に
埋め込まず宣言の `scopes` が持つ。

**指摘には扱いの目印を付けるが、直しも起票もチェックは行わない。** 扱いは実行しているリポジトリと対象の
スコープで決まり、分ける理由は直したものが残るかどうかである（プラグインの配布物は取得元の更新で
上書きされる）。NDF の開発リポジトリかは、実行しているスクリプトの実体が `--root` の下にあるかで判定する
（取得元の名前・リポジトリ名・リモートの URL は fork と移設で変わる）。

**このリポジトリへの適用は、配布物とは別立てである。** `ai-plugins` は利用者の 1 例で、宣言・継続的統合の
ジョブ・必須のチェック・手順の記載は適用の設計である。

## 仕様

### 常に成り立つ条件

- チェックはファイルを書き換えず、課題を立てず、既定では通信しない。通信するのは `--refresh` だけである
- 終了コード 2（確かめられなかった）を 0 へ畳まない。止まるなら何も判定する前に止まる
- 宣言の `imports` の未指定と `{}` は別の値である。未指定なら許可の判定を行わず、`{}` は参照をすべて指摘する
- 版の段落の判定はプロジェクトのスコープだけに掛ける
- 閾値の数値は配布物に無い。量と指示の数は常に報告し、落とすのは `budget` を宣言したときだけである

### 入出力の契約

```text
python3 "$SCRIPTS/instructions-check.py" [--root <根>] [--scope project|user|plugins]... [--report]
                                         [--refresh] [--refresh-timeout <秒>] [--criteria <パス>]
```

| 引数 | 意味 |
| --- | --- |
| `--root` | プロジェクトのスコープの根（既定は現在地） |
| `--scope` | 走査するスコープ。重ねて指定でき、既定は `project` |
| `--report` | 根の指示書ごとに、たどった先の内訳を足す |
| `--refresh` | 観点の出典を取得して提示する |
| `--refresh-timeout` | 出典 1 件あたりの待ち（秒）。優先順位は引数 > 宣言の `refresh_timeout_seconds` > 既定 10 秒 |
| `--criteria` | 観点のデータの置き場所（既定は配布物の `scripts/data/instruction-criteria.json`）。観点のデータを読めない・行を消す・知らない `id`・`enforce` を変える・`checked_at` が古い、を配布物の実体を動かさずに確かめるための引数 |

| 終了コード | いつ |
| ---: | --- |
| 0 | 指摘が無い。指示書が 1 本も無いときも 0 で、その旨を 1 行出す |
| 1 | `enforce` が `error` の指摘が 1 件以上ある |
| 2 | 観点のデータを読めない・宣言の構造が不正（JSON として読めない・`version` が無いか未対応・項目の型が違う・値が範囲の外・`pattern` が名前付きの捕捉を持たない）・`released` から版を 1 つも取れない・捕捉した値が semver でない・`released.path` が根の外・`git` が使えない。`--refresh` は通信できないときと 1 件でも取得に失敗したとき（一覧は全件出したうえで 2） |
| 3 | 知らない引数。標準エラーへ使い方 |

標準出力には本数の行（`指示書 N 本（根 x / 配下 y）`）、根の指示書ごとの読み込みの量と指示の数の行、
`NOTE:` の行（宣言が無いため動かない判定・観点の一覧が古い）が出る。指摘は標準エラーへ 1 件 1 行、
`ERROR: [<扱い>] <位置>: <理由>` の形で出す。`<位置>` は行まで持つものは `<ファイル>:<行>`、ファイル
だけのものは `<ファイル>`、どちらも持たないものは省く。`報告` の指摘には配布元の名前と版・取得元・
更新の手立て・観点の id と出典を、`起票` の指摘には題名の目印 `[instructions] <観点の id> <対象のパス>` と
宛先のリポジトリを添える。

### 指示書を集める

| スコープ | 集め方 | 根 |
| --- | --- | --- |
| プロジェクト | `git ls-files -z` が返す追跡対象から `files` の要素と一致するものを集める。実体（symlink を解決した後）が根の外にあるものは除く | `--root` |
| ユーザー / プラグイン | 宣言の `scopes` が挙げた位置から集める。位置がファイルならそれ 1 本、ディレクトリならその配下を辿り `files` と一致するものを採る。`git` は使わない。位置が無ければそのスコープは走査しない | その位置（ディレクトリならその配下、ファイルならそれを含むディレクトリ） |

`files` の要素に `/` が無ければファイル名の一致（根と配下のどこにあっても対象）、あれば根からの相対パスの
一致（その 1 本だけ）である。`files` を書くと既定の 3 つを置き換える。

| 位置 | 量の集計 | 判定 |
| --- | --- | --- |
| 根 | 入れる | すべて |
| 配下 | 入れない | すべて |
| 根の指示書が `@` でたどる先 | 入れる | 指示書としての判定はしない |

### 読み込みの量と指示の数

**量は根の指示書ごとに 1 つの数を出す。** 本文のバイト数に、`@` でたどった先のバイト数を深さ
`import_depth`（既定 4）階層まで足す。同じ参照先を 2 回引いても 1 回だけ数え、解決しない形（`~` と根の外）は
数に入れない。`import_syntax` に無い指示書では参照をたどらず本文だけを数える。`budget.bytes` は根の
指示書ごとに掛け、1 本でも超えれば指摘する。

**指示の数は、箇条書きの項目・段落の文・見出しの行を数える。** 箇条書きは先行する空白を許し
`- ` / `* ` / `+ ` / `1. ` で始まる行、段落は 1 つへ連結してから句点（`。` `！` `？` `!` `?`）で区切る。
表の行・引用の行・コードブロックの中・HTML の行は数えない。落とさない。

### 即時読み込みを見る

判定するのは `import_syntax`（既定 `["CLAUDE.md"]`）に挙げた指示書だけである。Codex・Kiro・Copilot は
`@` をただの文字列として扱うため、解釈しない指示書へ掛けると書いてよい文字列で落ちる。

**参照は、コードブロックとコードスパンの外で、`@` の直前が行頭・空白・`*`・`_`・`~` のどれかであるもの。**
名前は `@` の直後から続く英数字と `.` `_` `-` `/` `~` の並びで、末尾の `.` `_` `~` は落とし、空なら参照と
しない。参照先は書いた指示書のディレクトリから解決し、`~` で始まるものと根の外へ出るものは存在を判定
しない。読む前に実体のパスが根の中に収まることを確かめる。

| 条件 | 指摘（観点の id） |
| --- | --- |
| 参照先が存在しない | `broken-import`。宣言は要らない |
| `imports` を書いていて、その指示書の許可に無い | `unlisted-import` |
| `imports` の許可が `import_syntax` に無い指示書のもの、または許可の指し先が存在しない（存在を判定するパスに限る） | `unlisted-import`（宣言の陳腐化。行を持たない） |

`imports` のキーは根からの相対パス（`CLAUDE.md` / `docs/AGENTS.md`）で、値は参照先ごとの理由である。
ユーザーとプラグインの許可は `scopes` の各要素の中の `imports` が持つ。根ごとに分けるのは、同じ名前の
指示書が複数の根にあるためである。

### 版の段落を見る

**見るのは書き出しだけである。** 見出しの行はすべて、それ以外は段落の先頭行だけを見る。段落の先頭行は、
ファイルの 1 行目・直前が空行か見出しかフェンスの終わり・箇条書きの項目の始まり（2 件目以降と字下げした
項目を含む）のいずれかで、表の行と引用の行は先頭として扱わない。書き出しは箇条書き記号と強調を読み
飛ばした直後の `v<版数>` または `<版数>` である。

| 形 | 指摘する条件 |
| --- | --- |
| 版数（目印が続かない） | 基底（接尾辞を除いた数字 3 つ）が最新以下 |
| 版数 + `pending_marker` | 基底が最新未満 |

目印を宣言していないリポジトリでは、版数で始まる段落はすべて「以下」で判定する。

**目印だけは段落の途中も見る。** フェンスの外の各行で、`<版数>` の直後に `pending_marker` が続く箇所
（例: 「agy は ndf 10.17.4 の次の版で既定から外し」）を、基底が最新未満なら指摘する。書き出しで既に
指摘した行は重ねて指摘しない。

**最新は `released` から取る。** `changelog` は根の中の文書の各行に `pattern` を当て、`tags` は
`git tag` の各行に当てる。版数として読むのは名前付きの捕捉 `(?P<version>…)` の中だけで、捕捉した値は
semver の形（数字 3 つと任意の接尾辞）でなければ終了コード 2 である。最大値は数字 3 つの組と接尾辞の
有無で比べ、基底が同じなら接尾辞のある版が前、接尾辞どうしは semver の prerelease の規則で比べる
（`10.15.0-dev` < `10.15.0-dev.1` < `10.15.0-dev.10` < `10.15.0-rc` < `10.15.0`）。

### 扱いの判定

| 実行しているリポジトリ | 対象 | 扱い |
| --- | --- | --- |
| NDF の開発リポジトリ（スクリプトの実体が `--root` の下） | すべて | `直す` |
| それ以外 | プロジェクト / ユーザーのスコープ | `直す` |
| それ以外 | プラグインのスコープで `ndf: true` | `起票` |
| それ以外 | プラグインのスコープで `ndf: false` | `報告` |

### 観点の調べ直し

`--refresh` は観点のデータの `sources[]` の URL を順に取得し、出典ごとに 1 行（名前 / 前回の参照日 /
取得の成否 / 前回と内容が変わったか / 主張）を標準出力へ出す。機械が判定するのは取得できたかと、前回
取得した本文の指紋（`sha256`）と一致するかの 2 つだけで、主張が今も成り立つかは人が読む。待ちは 1 件
あたりの総経過時間で、単調に進む時計で期限を持ち、越えたら取得の失敗として一覧へ理由付きで残す。
観点の一覧が古い（`reviewed_at` または `checked_at` から `review_interval_days` を超えた）ときは、
チェックが `NOTE:` を出すだけで落とさない。

## データ・設定

### 宣言（`.ndf/instructions.json`）

| 項目 | 型 | 既定 | 何を決めるか |
| --- | --- | --- | --- |
| `$schema` | 文字列 | 無し | 定義ファイルへの参照。版を固定した公開の URL を書く。読み取り側は参照しない |
| `version` | 整数 | 必須（`1`） | 宣言の形の版 |
| `files` | 文字列の配列 | `["AGENTS.md", "CLAUDE.md", "KIRO.md"]` | 走査する指示書の名前 |
| `imports` | オブジェクト | 未指定 | 許可する即時読み込み `{"<指示書>": {"<参照先>": "<理由>"}}` |
| `released` | オブジェクト | 無し | `{"source": "changelog", "path": "...", "pattern": "..."}` または `{"source": "tags", "pattern": "..."}` |
| `decisions` | 文字列 | 無し | 退避先の文書。指摘の文面に出す |
| `pending_marker` | 文字列 | 無し | 版が決まる前の段落の目印。空文字列は不正 |
| `budget` | オブジェクト | 無し | `{"bytes": N}`。根の指示書 1 本あたりの読み込みの上限（1 以上） |
| `scopes` | オブジェクト | 無し | `user` は `path` と `imports` を持つオブジェクトの配列、`plugins` はそれに `name` / `version` / `origin` / `update` / `ndf` を足した配列。`path` の先頭の `~` は home へ広げ、相対は `--root` からと読む |
| `import_syntax` | 文字列の配列 | `["CLAUDE.md"]` | 即時読み込みの記法を解釈する指示書 |
| `import_depth` | 整数（1 以上） | `4` | 即時読み込みをたどる深さの上限 |
| `refresh_timeout_seconds` | 整数（1 以上） | `10` | `--refresh` の出典 1 件あたりの待ち |
| `review_interval_days` | 整数（1 以上） | `90` | 観点の一覧が古いと知らせるまでの日数 |
| `reviewed_at` | `YYYY-MM-DD` | 無し | そのリポジトリが観点の一覧を最後に見直した日。書けば `checked_at` ではなくこちらを起点にする |

範囲の外は宣言の不正として終了コード 2 で止める。0 や負の値を「制限なし」と読むか「すべて落とす」と読むかは
実装で分かれるためである。

このリポジトリの宣言は `files` の 3 つ・`CLAUDE.md` から `AGENTS.md` への許可・`CHANGELOG.md` の
`## [ndf <版>]` の行を読む `released`・`decisions` に `docs/ndf-version-decisions.md`・`pending_marker` に
`の次の版で`・`budget.bytes` に **24,000** を持つ。現在の最大は `CLAUDE.md` の 19,444 バイトで、
30,000 では増加の合図にならない。`$schema` は配布のタグを打った後に足す（定義ファイルを新設した時点では
版を固定した URL が解決できない）。

### 観点と出典のデータ（`instruction-criteria.json`）

| 項目 | 何を決めるか |
| --- | --- |
| `checked_at` | 最後に調べ直した日 |
| `criteria[].id` | 判定の手続きへ結び付く名前。一覧に無い `id` があれば終了コード 2。行を消せばその判定は動かない |
| `criteria[].enforce` | `error`（落とす）/ `report`（数えて出すだけ） |
| `criteria[].needs` / `aspect` | その観点が要る宣言の項目 / 観点の番号（根拠をたどる入口）。判定の手続きは読まず、人が読む |
| `criteria[].sources` / `sources[]` | 出典の id / 名前・URL・参照日・主張（`claim`）・前回取得した本文の指紋（`fingerprint`） |

観点は 6 件（`broken-import` / `unlisted-import` / `released-version-paragraph` が `error`、`read-size` /
`instruction-count` が `report`、`read-size-budget` が `error` で `budget` を要する）、出典は 14 件である。
量は `report`（常に数える）と `error`（`budget` を宣言したときだけ落とす）を別の行に持つ。利用者がこの
ファイルを書き換える前提は置かず、更新は NDF の側で行う。

## 運用

**即時読み込みの深さ（最大 4 階層）は Claude Code のドキュメントによる。** こちらでは測っていない。
Codex / agy / Kiro が `@<パス>` を読み込むかも測っていないが、読まないランタイムでは許可の一覧に載らない
参照を指摘しても害が無い。

**`pending_marker` を使わずに書いた現行版の段落は検出できない。** 次の配布で漏れが出たら、目印を必須に
するかを別の課題で決める。

**観点の一覧は動く。** 1 年以内に、`AGENTS.md` の統治の移管・Copilot が読むファイルの追加・強調語の
助言の反転・自己検証の指示の削除・置き場所の分割が起きた。`--refresh` で提示された差分は人が読み、
観点のデータと `checked_at` を直す。配布物の `sources[]` はまだ指紋を持たないため、最初の `--refresh` は
すべて「前回の記録が無い」になる。

**`--refresh` でも宣言を先に読む。** 宣言が壊れていれば取得の前に 2 で止まる。
